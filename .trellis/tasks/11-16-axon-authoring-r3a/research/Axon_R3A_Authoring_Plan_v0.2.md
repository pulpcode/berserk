## R3A · 对话辅助能力创建｜方案评审稿

## 一、本轮目标与本次调整

**交付目标：管理员在 Axon 现有对话中创建、修改专家与方法型 Skill；经已有确认交互保存为真实草稿，随后沿用原管理与发布流程。保留手动创建，不新增独立创作对话页面或专用结果卡片体系。**

建设顺序保持 **R3 → R3A → R4**。本稿替代 R3A v0.1 的实施建议；原稿保留，不改变 R3 的历史实施记录。[D1、D2]

### 1.1 本次已确认的交互方向

| 项目 | v0.2 的处理 |
| --- | --- |
| 创建主入口 | 管理员点击“创建专家”后进入现有新建对话；“创建技能”采用同一原则，带入对应创建意图。 |
| 手动创建 | **保留为明确可发现的次要入口。** 直接使用原创建表单／管理流程，不先进入对话，也不调用模型。 |
| 页面与结果 | 复用原聊天、输入区、工具过程、确认交互和历史；不建设创作专页、固定双栏编辑器或新的业务结果卡片。 |
| 已有对话 | 管理员可在本人已有个人对话中明确发起创建／修改；无需为每个目标强制换会话。 |
| 保存后 | 留在原对话，显示真实回执并提供详情／管理入口；不自动跳转，不自动发布或扩大使用范围。 |

“与 WorkBuddy 保持一致”在此指用户描述的“创建按钮 → 新对话 → 对话创作”交互。上传包只支持对话方法与管理脚本的参考，不证明其完整前端行为，也不要求照搬其注册、打包或发布政策。[W1]

### 1.2 本轮范围不扩大

| 必须建设 | 本轮不建设 |
| --- | --- |
| 管理员对话创建／修改专家及方法型 Skill | 普通用户私人创作、连接器／专家团创作、批量自治创作 |
| 受控管理 Skill、目标读取、变更建议、确认保存及回执 | 模型自主发布、授权、改默认、启停、封禁或配置凭证 |
| 指定字段／文本文件修改，必要差异查看 | 自动生成／调试脚本、安装依赖、任意宿主文件操作 |
| 解释已有检查／扫描／试用记录，建议测试输入 | 自动试用、环境前置检测器、风险审批、虚构验证结果 |

Skill 试用仍可选，自动静态扫描仅作报告；专家自身发布条件保持原义。管理员身份、通用助手不进入专业专家列表及不可变修订规则均保持。[D2、S1–S4]

### 2.1 已有能力与本轮新增分开

资产、草稿、发布和使用范围继续以现有管理服务为准；原聊天与工具证据继续以 Pi 历史为准。本轮只新增管理任务关联、待确认建议及保存回执等实际缺口，不建第二套资产库或聊天库。

专家引用新包使用 **skillId＋revisionId＋packageDigest**；旧 skillIds 保持兼容。现有自动调用限制仍生效，例如不能将不允许自动调用的包静默绑定为专家依赖。[S3、S7]

### 2.2 验证与状态边界

仓库记录仍区分技术验证与用户验收；早期全量、后续定向／浏览器及部署记录属于不同时间点，不拼接成“最终全部重验通过”。开工时核对该提交之后的差异与阻断项；历史后置 UI 不自动阻塞本轮，但数据、权限与保存一致性缺口须处理。[S8]

## 三、创建入口与现有对话交互

### 3.1 主入口与手动入口并存

| 入口 | 行为 |
| --- | --- |
| 能力中心 → 专家 → 创建专家 | 进入**现有新建对话**，带入“创建专家”意图和受控管理方法。 |
| 专家页 → 手动创建 | 在主按钮旁的明确次要操作／下拉项中保留；直接沿用原创建表单或管理入口。 |
| 能力中心 → 技能 → 创建技能 | 进入现有新建对话，带入“创建方法型技能”意图。 |
| 技能页 → 手动创建／导入技能 | 保留当前表单和导入路径；两者不依赖模型或对话助手。 |
| 专家／技能详情 → 对话修改 | 带入明确对象和已保存基线，进入同一聊天工作台；普通手动编辑仍保留。 |
| 本人已有个人对话 | 明确提出创建／修改需求后使用相同管理能力；目标不明确时先询问，不猜测写入对象。 |

次要入口必须可发现，不能用一个“创建”按钮根据隐藏条件随机切换表单和聊天。继续采用当前桌面布局、简洁文案与键盘操作，不新增创作导航栏目。

### 3.2 点击主按钮后发生什么

**点击创建 → 沿用现有空间／新对话流程 → 显示原聊天输入区 → 管理员发送需求 → 对话梳理与生成 → 确认保存草稿。**

已存在可用个人空间时沿用既有创建会话规则；需要选择／创建空间时复用原弹窗，取消不创建空间或会话。明确完成“新建对话”动作可创建空会话，但**不创建专家／技能草稿、不调用模型、不自动发送消息**。

创建意图可通过原有方法选择区或简短输入提示呈现；不生成假助手回复，不覆盖输入区已有正文／附件，不修改个人默认专家。该意图是宿主校验的操作上下文，不是浏览器授予的管理员权限。

### 3.3 保留手动方式的完整可用性

手动创建继续能独立完成内容填写、草稿保存、范围配置与发布。技能沿用 R3 的完整原子创建；取消表单不落资产。专家保留当前手动路径，不为本轮顺带重写其全部表单流程。模型服务不可用时，手动创建、编辑和导入仍可用。[S1、S2、S4]

### 3.4 保存后不强制离开对话

助手可继续调整同一草稿。真实保存结果提供“查看专家详情／查看技能详情”或“继续配置”入口；只有管理员点击才打开原管理界面。技能可按真实回执进入“使用范围”，但须核对当前草稿是否已被他人更新；发现变化先回内容核对，不自动更改范围或发布。[S4]

## 四、复用现有组件，不新增结果卡片

### 4.1 每类信息放在已有位置

| 内容 | 呈现方式 |
| --- | --- |
| 需求澄清、专业指令、创作建议 | 原助手消息；必要提问复用已有问答交互。 |
| 修改摘要、完整候选、字段／文件差异 | 原消息／工具详情及现有可展开内容；按需查看，不常驻左右分栏。 |
| 保存授权 | 原输入区的操作确认，明确“保存专家草稿”或“保存技能草稿”，显示目标、变更和基线。 |
| 保存成功／失败／待核对 | 原工具执行结果及确认历史；“已确认”不等于“已保存”。 |
| 资产入口 | 工具回执提供宿主校验的详情定位，复用普通链接／已有动作入口。 |

**不新增 AuthoringResultCard 一类专用消息卡片，不新增创作页面、独立输入器、侧栏会话分组或第二套历史恢复。** 若现有组件缺少差异折叠或详情定位，只做最小兼容扩展；这不意味着无需任何前后端改动。[S6]

### 4.2 确认内容来自宿主，不依赖模型口头承诺

模型先提出结构化候选，宿主校验目标、字段和内容摘要，再把**实际待写入内容**展示到原确认交互。不能只显示模型生成的“修改了三处”，却保存另一份内容；内容较长时提供可展开的完整字段／文件，不静默截断后要求批准。

管理员可以继续说“只保留输出格式的调整”，由助手重组候选；也可按需复用已有选择交互确认字段／文本文件。**默认是一份明确候选、一次保存确认，不要求每次经过新的勾选页面。** 部分采纳的最终范围必须进入候选摘要与确认记录。

### 4.3 修改与拒绝

修改前读取实际草稿；未要求修改的内容保留，删除须明确列出。手动表单有未保存输入时，先保存、放弃或取消进入对话，不能自动舍弃。所选历史修订与当前共享草稿不同，先明确“修改当前草稿”或“复制为新对象”，不覆盖已发布修订。

拒绝／取消只终止该次保存，不删除已存在的草稿。旧确认不再有效时，可在当前对话重新提出保存并生成新确认；不恢复后台执行或偷偷补写。

### 4.4 参考 WorkBuddy，但不照搬其本地写入

上传的 expert-manager 提供“交互收集／资料转化、先读原内容、定向修改、校验与注册”等方法，可用于 Axon 内置管理 Skill 的写作。Axon 仍通过服务端草稿服务保存，不运行参考包的本地注册脚本，不写 marketplace.json，不自动生成头像、专家团或发布包。[W1]

## 五、受控管理 Skill 与可操作范围

### 5.1 管理方法与权限分开

为专家和方法型 Skill 提供系统维护的管理方法，可分别命名为 expert-manager／skill-manager（名称为实现建议），共用相同管理服务原则。不要求用户先导入或安装，不新增“能力配置助手”专家卡片。

它们指导需求梳理、真实目录引用、精确修改及结果说明；**普通上传包即使使用同名，也不能获得管理工具**。内置方法的可信身份由服务端登记，不按文件名、自然语言或模型输出授予权限。

### 5.2 本轮可修改的内容

| 对象 | 可建议并确认保存 | 不由对话工具修改 |
| --- | --- | --- |
| 专家 | 名称、简介、专业指令；真实工具范围及固定技能引用 | 身份 ID、发布版本、系统来源、使用范围、默认、启停或发布状态 |
| 方法型 Skill | SKILL.md、文本参考资料、文本模板；明确的文件增删 | 可执行脚本、安装配置、二进制生成、权限和生命周期字段 |
| 检查／试用报告 | 读取有权限的已有记录，解释发现，建议测试任务 | 改写报告、伪造通过、自动运行试用或替管理员批准发布 |

沿用 v0.1 的首期范围：含脚本／二进制的包仍可手动维护，R3A 暂不提交这类包的对话修改；不能为适配本入口删掉原文件。这是范围建议，保留在整稿审阅项，不扩展成风险分类器。

### 5.3 工具职责

受控工具仅负责读取可引用目录、读取选定目标、提出候选、读取获准报告以及**请求宿主确认保存**。请求保存可以是模型发起的工具步骤，但实际写入必须等待真实管理员确认；不暴露一个可跳过确认的模型保存接口。

写入由宿主在批准后调用原服务。管理请求不注册发布、授权、默认、封禁、业务写入、任意文件写入、Shell、安装、MCP 或子 Agent 委派工具。普通聊天的原有工具不因此被全局删除，只在明确管理请求中限制可用集合。

### 5.4 元数据和引用保真

专家的旧 skillIds 与新 skillRefs 分别处理；新包引用带齐 skillId、revisionId、packageDigest，遵守现有自动调用资格限制。工具名与技能必须来自真实目录。[S3、S7]

只修改 SKILL.md 正文时，不重建或丢弃 license、metadata、compatibility、扩展及注释。未采纳文件和字段保持原内容；无变化不重新序列化。借鉴现有 skill-method 的保真处理，不把前端模块直接当服务端信任边界。[S4]

## 六、确认保存、并发与真实回执

### 6.1 一次操作对应明确目标

每次管理操作关联 ownerUserId、现有 sessionId／requestId、对象类型、目标 ID 或新建标识、来源修订、草稿基线及建议摘要。会话可以顺序处理不同对象；**约束是“一次操作一个目标”，不是“一条会话只能维护一个对象”。**

切换目标后，未确认的旧建议不得借“继续”写入新对象；重新选择旧建议也要核对原目标和当前基线。本轮不做跨对象批量采纳或多目标事务。

### 6.2 批准绑定实际候选

服务端固定 proposalId／proposalDigest、最终候选摘要、选择范围、expectedDraftRevision 和目标。专家基线用 draftDigest，技能基线用 packageDigest。确认记录关联当前用户、会话、请求和保存动作，不接受模型或上传资料提供的“已批准”标志。[S3、S6]

已有问答中的“是”、普通消息中的“确认”和旧历史不能代替操作确认。模型可以据此请求保存，但宿主仍呈现现有确认交互。确认后、提交前再次检查管理员身份、目标权限和版本。

### 6.3 复用与需要补齐的部分

| 保存场景 | 实现要求 |
| --- | --- |
| 首次创建 Skill | 调用现有完整 files＋clientActionId 创建能力；保留原锁、事务、审计和扫描触发。 |
| 首次创建专家 | 增加最小的完整内容创建边界；不能由浏览器先 create 占位再 save，也不破坏原手动创建。 |
| 修改专家／Skill | 在原服务中补确认保存的持久化动作回执；草稿、审计与回执由同一写入事务提交。 |
| 重试与重复确认 | 同一动作同参数返回原结果，异参数冲突；同一已采纳候选不能换动作 ID 再创建一份资产。 |

当前两类草稿保存只有 CAS，不等于幂等采纳；额外写一张前端回执表不能解决“写入已完成、回执未保存”的窗口。[S1、S2]

### 6.4 失败与原子性

技能整包保存保留完整文件清单，不拆成多次可见的单文件替换。沿用各服务实际存储结构；如需暂存内容，先完成受控写入与校验，再提交引用。不能假定不同数据库连接的外层事务天然覆盖内部服务提交。

原生聊天记录引用管理回执，不要求跨 SQLite 与 JSONL 建立新分布式事务。聊天投影暂未写入时，以持久回执核对，不重新执行保存；结果不明显示待核对。并发冲突保留候选，由管理员重新读取比较，不能自动合并覆盖。

## 七、现有会话中的运行与权限

### 7.1 复用聊天，而不是全局开放管理工具

复用当前聊天路由、会话创建、Pi 循环、模型选择、流式、停止与历史。创建按钮的宿主意图、管理员主动选择内置方法，或本人消息中明确的管理请求，可发起受控管理步骤。名称不明先询问；引用资料中出现“创建专家”不视为管理员的操作意图。

**模型可以识别或建议调用管理方法，但不能决定权限。** 服务端复核当前账号、本人空间／会话和选定目标，才启用管理请求白名单。可复用本人已有个人对话；不对业务公共会话、后台或子 Agent 自动注入。管理能力不永久附着于历史，也不改变当前会话的专家修订或用户默认设置。

管理方法按需读取；不把整个管理手册、全部资产或所有工具描述每轮注入模型。不使用被编辑专家的工具范围授予创作执行权限。不得通过 extraTrialTools 注入真实管理服务或将创作标记为试用。[S7]

### 7.2 确认机制的最小适配

当前确认界面与工具历史可复用，但操作工具名、记录结构和解码存在严格限制。实施时为管理保存补受控操作语义及必要参数；需要新增持久字段时进行兼容／版本化处理，不改写旧记录，不以新增专用卡片绕开这些约束。[S6]

优先沿用“等待确认 → 批准后复核 → 执行 → 返回回执”的原请求生命周期。不另建脱离会话的审批待办中心；已结束请求的建议可以继续讨论，但要在新的明确请求中重新发起确认。

### 7.3 历史、停止与恢复

| 信息／事件 | 要求 |
| --- | --- |
| 聊天与工具证据 | 保存在现有本人会话及 Pi 历史；不另设创作聊天列表或完整聊天副本。 |
| 管理操作关联 | 仅补目标、基线、候选、确认及回执的必要关联；服务端投影给前端。 |
| 刷新 | 恢复现有会话和真实操作状态；不自动重发消息、重新生成或重新采纳。 |
| 停止／撤权／重启 | 沿用当前请求取消；未提交不保存，已提交不假称回滚；过期确认不得继续写入。 |

管理员只能读自己的对话、获准管理资产和本人试用资料；共享草稿可管理不等于可看他人完整聊天。管理请求默认以文字、选定目标和已有报告为输入，不新增 URL 抓取或业务数据读取。

## 八、衔接现有管理、扫描与发布

### 8.1 对话不是第二套发布流程

| 环节 | R3A 行为 |
| --- | --- |
| 草稿保存 | 真实调用专家／技能服务，回传实际对象及新草稿修订；不改当前发布指针。 |
| 格式检查 | 候选做必要字段／路径检查，正式格式规则仍调用原服务；不产生“AI 专用格式”。 |
| 静态扫描 | 通过既有保存路径触发适用扫描；复用报告，不重复排队，不伪造方法包的零发现。 |
| 试用 | 助手可建议测试任务、解释可访问的真实记录；管理员在原入口主动运行。 |
| 使用范围／发布 | 保存后只给原管理入口，由管理员显式操作；不自动配置范围、确认试用或发布。 |

保持 Skill 可不试用发布、扫描仅作报告、无额外环境检测器；专家自身校验、试用、确认和发布规则不被绕过。报告只解释实际检查的内容版本，不把旧结果变成新内容的证明。[D2、S1、S2]

### 8.2 接回技能最新流程

管理员主动打开管理时，采用当前“技能内容 → 使用范围 → 检查与发布”。新建完整草稿可在核对回执摘要后进入范围；若首次详情已是别人更新的内容，回内容核对。编辑、导入、复制及历史来源沿用现有审阅路径，不仅凭链接参数跳过步骤。[S4]

扫描轮询、详情 GET 和报告加载不驱动导航，不覆盖本地未保存输入。现有手动创建、导入、复制、源码编辑和文件维护全部保留。

### 8.3 管理员个人使用规则

当前实现已允许管理员在本人个人对话使用已发布、启用的组织技能；业务席位范围与管理员个人使用分别判断，仍遵守封禁、账号限制和工具权限。[S5]

技能发布要求显式设置过使用范围；“明确未开放业务席位”和“尚未设置范围”不同，不能为了个人使用自动开放全部业务席位。对话创建的新资产仍是未发布、尚未配置范围的草稿；创建本身不授予正式使用资格。[S1]

### 8.4 不改变其他轮次

R4 连接器、R5 后台统一、R6 专家团、R7 安全治理和待讨论的技能安全审核专题不提前实现。参考包中的团队、头像、批量转化与本地安装不进入本轮范围。正式 releaseVersion／revisionId 继续在原发布流程形成，旧会话依赖不漂移。
