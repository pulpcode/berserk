# 席位选择登录

## 目标与授权
用户认可此前讨论的席位下拉加密码方案后，明确要求实现并更新线上服务。

## 范围
- 登录页选择启用席位、输入现有密码；不默认选中席位。
- 匿名引导响应只提供席位 ID 和名称，不提供账号标识、职责、权限或密码信息。
- 服务端解析席位对应的启用账号后复用密码校验、限流和会话轮转；保留已有 username 登录 API 兼容脚本。
- 原生下拉框有标签、加载及空状态；失败保留席位，切换席位清空密码。
- 修改 AuthSession、认证路由、Seats 登录组件与相关样式和测试；不修改账号、数据结构、密码或授权规则。
- 备份当前线上代码和构建文件，只部署本任务改动，可回滚。

## 验收
- 下拉仅展示启用账号对应的席位；正确密码进入所选席位；错误密码、未知或停用席位统一拒绝。
- 混合 username 和 seatId 请求拒绝，原账号登录保留，匿名业务和 CSRF 保护保留。
- 登录失败、切换席位、退出及跨标签页同步有测试；空列表不可登录。
- 类型、lint、认证测试和相关浏览器测试通过；线上公网页面显示席位选择及密码。

## 实施记录
界面复用现有登录卡片，原生 select 绑定可见标签；375px 宽度下不溢出。线上补丁预检通过，等待质量检查完成后发布。
