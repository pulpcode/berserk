# 地图关注范围预填方案

2026-11-09 · 已搁置，见SIM-MAP-001

**建议由宿主把来报已有的引用带入创建表单，人员确认后保存。复用现有任务关注范围和地图查询，不增加一轮模型推理。**

## 用户看到的变化

点击“创建公共任务并关联”后，现有表单的“业务关联与关注范围”带出对象和区域；用简短数量摘要提示已填写，展开后可修改、移除或清空。创建后进入任务地图，加载这些对象及关注区域内的态势。

例如，来报对应报告包含“临港三号仓库、V01、滨港路”和“临港区域”：

| 来源引用 | 保存到任务 |
| --- | --- |
| 三个对象的systemId/objectType/objectId | context.businessRefs |
| 临港区域的原始编码 | context.focus.areaIds |

这是关注对象和范围，不自动断言仓库火情已确认、滨港路必经或V01已分派。用途role默认留空，不自动填写实际路线/作业范围等角色。时间、主题不从正文推断或自动填入。

## 数据如何取得

通知本身只有报告线索，不能把subjectId当作地图对象编号。建议增加一个只读“来源关注范围预填”读取能力，按eventId+jobId使用现有来源/结果读取授权，返回默认context和必要的报告标识/修订依据；不创建任务、工作区或模型作业。

- 从所选作业该次请求的已验证、成功来源工具结果中，选择与本条来报明确对应的报告。优先完整报告读取结果；仅有可唯一对应的报告索引时也可使用其引用。
- 固定所选分析实际读取的报告版本；不重新查询最新报告替换旧分析依据，不把该次搜索到的所有报告合并。
- 由宿主确定性提取报告objectRefs/areaIds；不解析Agent正文、不采纳工具调用参数或失败回执中的“引用”。存在多个无法区分的对应报告、引用版本冲突或没有对应结果时不猜测，返回未预填状态。
- 对象按(systemId,objectType,objectId)、区域按原编码去重。保持原系统归属和编号，不凭名称猜坐标、补齐对象或强行转成态势系统引用。若对象名称已在获准证据中可用，可以作为label；否则保留编号。
- 对象/区域超限时简短提示并要求调整到现有20/10上限，不悄悄丢掉超出部分。

建议在挂载创建表单前完成这次只读预填读取，等待时使用现有加载效果；失败则打开可手工填写的表单并提示未预填。切换来报或分析后，旧读取结果作废，避免晚到响应覆盖新表单。

## 保存与地图

创建请求沿用已有context字段，提交人员看到并确认的最终值。修正现有“仅contextDirty才发送”的条件，确保预填但未编辑也能保存；主动清空后按空范围创建，后端不再自动兜底补回。

继续走既有创建事务：任务、来源关联和创建回执一起提交；提交时重新检查权限、选定作业和轮次可写性，幂等重试沿用首次确认的输入。

地图继续按businessRefs对象查询和focus.areaIds区域查询取并集。对象引用未必都有地图几何，关注区域也不等于实际作业范围；不改变地图已有的未知对象、资料权限或来源错误处理。保存引用不赋予其他席位读取原来报、分析正文或附件的权限。

## 本期边界

不扩展Agent新建建议字段，不新增来源字段或数据库表，不自动改变已有任务范围，不回填历史任务，不引入额外模型调用。优先改创建预填链路；如果实施时发现引用证据无法可靠对应，保持空值和手工编辑，不以正文猜测替代。
