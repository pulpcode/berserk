# 从来报创建公共任务时预填地图关注范围

2026-11-09 · 已搁置，见SIM-MAP-001

## 目标

人员从来报的分析结果创建公共任务时，表单自动带入该来报的对象和区域引用；人员确认或调整后保存，新任务地图即可按关注范围查询态势。

## 已核实的现状

- Agent新建建议只有名称、目标、理由。通知元数据主要是systemId/subjectId，本身没有objectRefs/areaIds；引用存在于来源报告及该次分析的查询证据中。
- 现有创建请求已支持context，后端会连同任务及来报关联一起保存。
- TaskPanel仅从已有任务初始化context，新建来源任务时为空；且只有contextDirty才提交context，预填后未手动编辑也必须能够保存。
- 地图已经读取context.businessRefs和context.focus.areaIds并合并查询，无须新增地图范围模型。

## 建议范围

1. 从选定分析的已验证来源查询结果提取本条来报对应报告的对象/区域，作为表单默认值；Agent建议结构保持现状。
2. 沿用现有“业务关联与关注范围”编辑区，可增删、清空；任务名称、目标、理由仍由人员确认。
3. 创建时保存人员最终确认的context，包括未手动修改的预填值；清空后不在后台重新补回。
4. 仅覆盖从来报新建公共任务，兼容无新建建议的人工创建入口。关联已有任务不自动覆盖其范围，历史任务不自动回填；普通新建入口不增加来源要求。
5. 来源权限、公共任务创建权限、轮次归属、幂等及旧轮只读限制继续执行，不向业务席增加轮次选择。

## 验收

- 来源报告有可用对象和区域时，打开表单即可看到默认值；直接确认后刷新任务，引用仍存在，地图查询使用这些值。
- 修改/删减/清空后，保存结果和地图查询以人员最终值为准。
- 无建议也能预填；无引用、无法对应报告或读取失败时明确显示当前未预填，可手工填写或留空创建。
- 去重并保留原系统/对象编号；不同报告、不同作业或不同轮次的引用不混入。超出现有20对象/10区域上限须调整，不静默截断。
- 重复提交返回原任务；丢响应重试、无权限、旧轮结束及已有任务关联均不改变既有保护。
- 地图无法读取的对象保留正常未知/无权限/来源不可用状态，不承诺所有引用都有坐标。

实施与验证待本方案批准；需要运行验证时，在服务器隔离目录执行。
