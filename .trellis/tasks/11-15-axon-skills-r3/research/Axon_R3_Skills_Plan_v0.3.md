## 一、目标、范围与代码基线

**本轮建设技能管理与运行能力，并提供管理员按需使用的隔离试用条件；不把试用成功作为 Skill 发布的必要步骤。**

**相对 v0.2 的两项调整：不建设试用前的额外环境前置检测器；恢复自动静态代码扫描。** 扫描用于报告风险，不恢复“扫描通过／零告警才能发布”的门禁；试用仍由管理员按需发起。Agent Skills 格式基线、原有修订、授权、历史兼容和运行隔离保持不变。

### 1.1 建设顺序与范围

沿用阶段路线图：R1 → R2 → **R3 → R3A** → R4 → R5 → R6 → R7。新增“技能安全审核与发布策略”专题待单独拟制和排期，不自行编号、不默认并入 R7，也不改变 R3A 和原后续轮次。[D1、S1]

| R3 必须交付 | 本轮不做 |
| --- | --- |
| 管理员创建、复制、编辑和导入技能 | 普通用户创作私人技能、专家包或整库安装 |
| Agent Skills 格式、完整性检查和自动静态扫描报告 | 自拟替代格式、通用业务环境前置检测器 |
| 可选隔离试用及真实运行记录 | 按风险强制试用、自动试用或 AI 批准发布 |
| 发布、版本、历史、范围与普通启停 | 漏洞库治理、风险分级、扫描阻断审批和封禁管理 |
| 专家引用、按需读取、受控脚本和资源装载 | R3A 对话创作、MCP、后台迁移、专家团编排 |

### 1.2 代码依据与修订边界

代码依据沿用 v0.1 已核查的 `codex/axon-r2` 提交 **5969069f565d28c753962daca1fe8bf3de17885c**；该时点记录仍保留用户验收 pending。本次重新读取 v0.2 原稿，并补核静态扫描工具的官方说明；未重新拉取分支、运行产品测试、修改代码或迁移数据。[S1、E5]

开工须核对最新提交、遗留问题与用户授权。已获准后置的 R1 UI 不自动阻塞 R3；安全、数据及执行回归问题仍须处理。本文仅修订 R3 技能发布要求，不自动取消 R2 已实现的专家发布条件。

### 2.1 保留已经落地的产品行为

沿用统一登录、Axon 桌面布局、能力中心的专家／技能／连接器标签与卡片。管理员仍是账号级身份，可无业务席位并拥有本人个人空间；专用试用空间与普通个人空间分开，不恢复专用管理员后台。[S6]

通用助手不进入专业专家列表；“与专家协作”、releaseVersion 与 revisionId 的含义不变。不借本轮升级 Pi、重写后台或引入第二套模型循环。[S7]

### 2.2 与 R2 专家试用的明确边界

R3 Skill 可不试用即发布；R2 专家自身的校验、试用及发布规则仍按已有契约执行。专家更新技能依赖时沿用专家流程，但不能额外要求该 Skill 存在成功试用记录。需要调整专家发布政策时另行确认，不由 R3 静默改动。

**复用基础设施，不等于复制全部门禁。** 本轮只做确有需要的技能模型、资源和发布分支，不提前建设通用风险策略引擎。

## 三、产品入口、管理与使用范围

### 3.1 页面安排

| 入口 | 普通用户 | 管理员 |
| --- | --- | --- |
| 能力中心 → 技能 | 查看获准技能、版本和当前使用条件 | 增加创建、复制、导入入口 |
| 技能详情 | 选择“用于当前对话”，不自动发送 | 草稿、文件、格式检查、静态扫描、可选试用、发布历史、操作记录及范围 |
| 专家编辑 → 技能依赖 | 不修改共享专家 | 选择已发布技能修订，查看包内声明及平台支持说明 |
| 输入区方法选择 | 选择本条方法；不覆盖正文和附件 | 普通个人对话不混入管理或试用权限 |

全局选择技能时，先确定可访问的会话／空间。取消不创建请求、不调用模型；不增加用户下载或安装到私人技能库的步骤。

### 3.2 发布、扫描与试用分开

**发布主流程：创建／复制／导入 → 编辑草稿 → 格式与完整性检查 → 管理员确认发布。**

**可选试用：选择草稿或已发布修订 → 输入任务和测试资料 → 启动隔离试用 → 查看结果，按需返回修改。**

**自动扫描独立进行：** 导入完成或保存新包快照后，对含受支持脚本的内容排队扫描；不等待管理员试用，也不执行包内脚本。

发布页面展示当前内容的扫描状态、发现摘要和已有试用情况，不要求“免试申请”、风险等级或例外审批。方法型、脚本型、业务场景型 Skill 均不强制试用；扫描发现、尚未完成或失败不单独阻止发布。基础格式与完整性问题仍须修复。

草稿支持 SKILL.md 和包内文本编辑、资源增删替换，不建设完整 IDE。同名导入不覆盖内置或已发布内容；页面读取不生成草稿。内置技能只读可复制，受控部署维护其原始内容。

### 3.3 管理、授权与普通上传

组织技能沿用 R2 的“未开放／全部业务席位／指定席位”范围，发布前明确选择；账号拒绝仍优先。使用专家不自动授予依赖技能或业务工具权限。

无席位管理员可管理和试用，普通个人会话暂保留既有内置能力；是否增加正式组织技能的账号授权仍属原 Q4 待审阅事项，本次不扩大。普通聊天上传 SKILL.md／ZIP 仍只是资料，不安装、不注册、不改变权限。

发布历史与操作记录放在技能管理详情；不得借此查看其他用户完整会话。普通用户看到发布信息及试用状态摘要，不暴露管理员测试文件、日志或私有数据。

## 四、格式规范与导入适配

### 4.1 采用开放规范，不自拟 Skill 格式

**以 Agent Skills Specification 为格式依据。** 技能是包含 SKILL.md 的目录；文件使用 YAML frontmatter 与 Markdown 指令。name、description 为必需字段；license、compatibility、metadata、allowed-tools 为规范中的可选字段，具体约束按锁定的规范检查。[E1]

scripts、references、assets 是组织惯例，不是目录白名单；templates、自定义子目录和相对资源路径可保留。规范的长度建议不能擅自升级成硬错误，正文非空等额外质量要求应明确标为 Axon 提示。[E1]

R3-0 保存所采用规范的获取日期／快照摘要及校验器版本。优先复用官方参考校验器 skills-ref；若按宿主技术栈实现等价校验，以参考工具和固定样例作对照，并记录差异，不额外发明私有必填字段。[E1]

### 4.2 标准、生态扩展、上传包装分开

| 对象 | 已核实事实与 Axon 处理 |
| --- | --- |
| Codex | 官方说明以 SKILL.md 目录及资源构成技能；agents/openai.yaml 属产品扩展。Axon 保留内容，未实现的扩展明确标记，不自动配置 MCP 或授予权限。[E2] |
| DeepSeek Harness | 官方文件提供器支持目录技能及平铺 `<name>.md`。后者作为导入适配，不称为标准必需形态。[E3] |
| ZIP | 开放规范描述目录，不统一规定上传容器。OpenAI 托管 Skills API 的顶层目录要求是该 API 的上传规则，不代表 Codex 本地发现或通用标准。[E4] |

### 4.3 本轮上传方式（Axon 适配约定）

支持单个 SKILL.md；兼容具有有效元数据的单个 `.md`，经预览确认后保存为 SKILL.md。依据有效 name 建立逻辑技能根目录，不改写正文来伪造兼容。

ZIP 首期接受根目录或单层外包装中的一个技能根；仅去掉外包装，保留包内子目录和相对路径。多技能／更深包装提示拆分或重新打包，不误报为 Agent Skills 格式错误。目录名与 name 不一致时给出明确修正提示，不静默改名。

未知生态字段保留原文并单列扩展报告，不一概当作标准字段。影响调用资格的扩展未适配时，不得忽略限制后静默开放自动调用。allowed-tools 不增加 Axon 权限；所有可调用能力仍由宿主控制。

**格式可兼容，不等于环境已具备或效果已验证。** Axon 的身份、修订与使用范围存于服务端，不要求外部技能携带私有发布字段。

## 五、完整包修订、资源与历史

### 5.1 保留完整技能目录

不以目录名或脚本语言判定是否符合开放格式。普通受管资源原样保存；本轮提供文本、数据、图片及无宏办公模板的基础处理，活动内容不在浏览器执行。对不能安全接收的文件明确报告 Axon 平台限制，不静默删减后发布残缺包。

Python／JavaScript 为本轮必验运行与静态扫描链路；已有 Bash 能力沿用宿主策略。其他解释器、外部命令和系统依赖按包内声明展示，不自动探测业务环境，不因暂不能执行就判定格式错误。未支持的扫描语言明确列为未覆盖。导入不运行安装钩子、不自动安装依赖，不自动激活包内 MCP／网络配置。

| 对象 | 责任 |
| --- | --- |
| SkillAsset | 稳定 skillId、来源及显示信息；与 frontmatter.name 分开 |
| SkillDraft | 文件清单、内容与运行需求；draftRevision 控制并发修改 |
| SkillPackageRevision | revisionId、releaseVersion、packageDigest、规范版本与不可变文件清单 |
| 文件清单 | 相对路径、字节数、类型与内容摘要；不含宿主路径或上传执行权限 |
| 检查／扫描／试用／发布记录 | 分别关联固定包、工具规则及操作者；发布不依赖扫描通过或成功试用引用 |

**完整包摘要覆盖所有文件与平台保存的运行需求。** 改脚本或模板也产生新内容身份；旧扫描和试用只对应旧快照，不迁移成新内容的成功证据。发布号沿用首版 1.0.0、后续 PATCH 递增建议；来源版本单独保留。

### 5.2 修订选择规则不变

专家声明依赖锁定具体修订；用户显式选择在发送前核对修订与包摘要；Agent 按需读取使用本请求固定的候选目录。发布新技能不自动升级旧专家或旧会话。同 ID 不同修订冲突须提示，不能覆盖固定依赖。

专家升级依赖需重新发布专家，遵守 R2 专家流程；技能是否做过试用不成为额外前置条件。

### 5.3 旧格式与当前资料

保留旧 SkillRevision、16 KiB 正文规则、摘要算法和逐版本历史解码。[S4] 新包使用新契约，必要时显式升级相关 schemaVersion，不批量改写旧 Pi JSONL、R2 校验和试用证据。新技能不写进严格旧 workspace-index。

旧修订缺失或摘要错误应阻断相关执行，不替换成最新包。工作区资料和实时授权仍按请求读取，不随技能修订永久冻结。

## 六、格式检查、静态扫描与后置安全专题

### 6.1 分开呈现检查和扫描结果

| 项目 | 本轮责任 | 对发布的影响 |
| --- | --- | --- |
| 规范格式 | 按 Agent Skills 检查元数据与目录；生态扩展和上传适配单列 | 不合规内容可留草稿，修正后发布 |
| 完整性与基础防护 | 路径边界、限额、摘要、文件清单和可确定的包内引用 | 损坏、越界或无法完整保存仍阻断 |
| 源码静态扫描 | 对受支持脚本自动扫描；报告发现、位置及实际覆盖范围 | 提示与留证，不设“零告警／扫描成功”发布条件 |
| 来源声明与支持说明 | 展示 compatibility、依赖说明及平台已支持的工具／解释器范围 | 仅为说明，不推断已具备业务环境，不作环境准入门槛 |

**删除 v0.2 的“环境适配检查”工作项。** 不新增试用前依赖探测、业务连接检查、场景存在性检查或模型驱动的前置条件分析器。包内声明只是来源信息，不能呈现为系统检测结论。

### 6.2 恢复自动静态代码扫描

首选固定版本的本地 **Semgrep CE**，先覆盖 Python／JavaScript，规则集在 R3-0 锁定。优先选取适用的现成规则，记录来源、版本、许可证和实际覆盖；必要的少量补充规则单独留证，不自研扫描引擎。Semgrep 官方支持本地规则，其忽略机制需要在接入时明确控制。[E5]

| 环节 | R3 要求 |
| --- | --- |
| 触发 | 导入完成、保存形成新包快照后自动排队；管理员可主动重扫。打开页面、开始试用或普通聊天不触发重复全量扫描 |
| 输入 | 固定 packageDigest 的只读快照；不边编辑边扫描，不执行脚本、不安装包内依赖、不连接业务系统 |
| 覆盖 | 按文件清单核对目标脚本、已扫描文件及跳过原因；无受支持脚本记“不适用”，其他语言记“未覆盖”，不能当作已检查 |
| 控制 | 固定入口和本地规则；不加载包内扫描配置，不允许其忽略文件／注释静默隐藏发现。原包保持不变，实际覆盖与排除须留证 |
| 资源 | 限时、限并发、限输出；无生产凭证，默认无外网，显式关闭遥测；不接云端扫描平台，不自动修复包内容 |

扫描针对代码，不需要态势框架或其他业务测试环境。结果不能证明自然语言方法正确，也不能证明全部恶意行为已被识别。扫描器与规则的真实部署、覆盖对照和失败处理属于本轮交付，不可只做“扫描按钮”。

### 6.3 报告、内容一致性与发布关系

报告在**管理员技能详情 → 静态扫描**展示：文件／行号、规则标识、发现说明、工具原始严重性、扫描器版本、规则摘要、时间、packageDigest，以及覆盖和跳过情况。工具严重性不是 Axon 的 Skill 风险等级，不触发风险审批。

执行状态区分“待扫描、扫描中、已完成、部分完成、失败、不适用”；发现数量另列。只有覆盖完整且无发现时，才显示“本次规则范围内未发现问题”，不能写“绝对安全”。旧内容／旧规则的记录保留并标明关联，不冒充当前内容的结果。

**自动扫描是必交功能，扫描通过不是发布条件。** 发现问题、尚未完成、工具暂不可用或扫描失败时，展示真实状态，管理员仍可按基础发布条件发布；不要求额外豁免，不由模型批准。扫描暴露出包损坏或非法路径等基础问题时，按基础规则阻断，而非按风险评级阻断。

发布记录保留当时可用的扫描引用／状态；后到报告按相同包摘要关联，不倒填成“发布前已完成扫描”，不改写发布内容、当前版本或使用状态。对扫描结果的阻断、审批和持续监测策略留待专项。

### 6.4 基础处理仍须落实

上传进入不可执行暂存区；按实际字节和解压量限制资源。拒绝目录穿越、绝对路径、符号／硬链接、重复归一化路径及不支持归档；不盲目递归解压。预览不执行宏、HTML 脚本或外部资源，扫描器不能扩大上传权限。

初始限额沿用 v0.2：ZIP 20 MiB、展开 100 MiB、文件 256 个、单资源 20 MiB、SKILL.md 64 KiB、单文本／脚本 2 MiB。实施时验证并配置化；它们是平台约束，不是 Agent Skills 标准。

安全解析不 import 不可信模块、不执行安装脚本。原有沙盒、人工确认、凭证隔离与撤权检查保留；不因扫描只是报告而删除这些边界。

### 6.5 后置专题只承担治理增量

OSV／依赖漏洞库、持续漏洞治理、来源信任、恶意意图分析、Skill 风险分级、强制试用、扫描结果阻断及例外审批仍后置；本轮不建立相应策略引擎。

“技能安全审核与发布策略”继续作为独立待讨论专题；与 R7 的运行期封禁、取消和恢复区分，编号和位置另议。**静态扫描及报告已恢复到 R3，不再列为全部后置。** 发布不构成代码安全或业务正确性认证。

## 七、按需隔离试用与自主发布

### 7.1 提供试用，不新增环境前置检测器

管理员在技能详情点击“试用技能”，选择草稿或发布修订，输入目标、提供测试资料并主动启动。平台准备独立会话、工作区和固定包，复用现有 Pi 循环；上传、打开页面、扫描和发布均不自动试用。

**试用前不额外分析“需要什么业务环境、是否已配置”。** 不根据 SKILL.md 自然语言生成“未配置测试态势环境”等预判，不主动探测正式业务系统，也不要求填写完整环境清单才能开始。

现有身份鉴权、包完整性校验、工具权限、容器启动及参数检查继续执行；这些是原运行流程的基础校验，不是新建一套 Skill 前置检测器。既有试用工具限制与替身标识保留，不为完成试用而开放生产写入。

方法型直接按任务执行；脚本按需使用 Docker；模板只读，输出写入测试工作区。真实调用、退出结果和文件来自执行记录，不采用模型自报。管理员可以停止或自行记录结论，均不形成必填发布批准。

### 7.2 只展示实际试用结果

状态保留“未试用／运行中／已完成／失败／中断”。内容变更后旧记录标明对应旧快照；停止或重启不自动重跑。没有试用时只显示“未试用”，不生成“环境缺口报告”。

| 实际发生的情况 | 展示方式 |
| --- | --- |
| 工具返回权限不足、资源不存在或连接错误 | 展示实际工具、错误码／原因和相关步骤，不推断其他未检测条件 |
| 试用准备时现有运行器无法启动 Docker／模型调用 | 展示实际启动错误，不回退宿主执行，不另做依赖探测 |
| 使用既有合成数据或工具替身 | 标明模拟来源；不称真实业务集成已验证 |
| 仅完成文字回答，未实际调用目标业务工具 | 记录已执行内容及“未取得该操作证据”；不推断环境不存在或操作成功 |

这些是本次执行记录，不是对 Skill 的全局认证。无需建设复杂的根因推断器；错误含敏感信息时按既有规则脱敏。R3 不搭建完整态势测试平台，不自动连接正式环境补齐测试条件。

### 7.3 发布条件与持久化

| 必须满足 | 不作为必要条件 |
| --- | --- |
| 当前管理员有管理权，草稿和发布基线一致 | 已试用、试用成功、人工确认试用通过 |
| 标准格式及基础完整性检查完成，内容可持久化 | 测试环境具备、真实集成验证或试用前环境报告 |
| 发布说明、使用范围及幂等动作有效 | 扫描零告警／扫描成功、风险评级、漏洞审查及安全审批 |

扫描／试用状态如实展示；发布不要求成功 trialId 或 scanId，也不生成免试／免扫成功记录。基础损坏仍须修复。可选证据须与发布包一致，不能用旧草稿的报告证明新包。

文件先落盘校验，事务再写修订、当前指针、发布记录、审计及回执。重试只返回原发布；“已发布、已扫描、已试用”分别表达。

正式使用仍遵守原有工具、权限及执行约束。没有授权或执行时确实缺少依赖，应拒绝对应操作并说明实际原因；不能因为缺少试用／扫描成功记录而增加额外运行门禁。

## 八、运行装载、隔离与普通启停

### 8.1 一条运行链路

**身份与空间校验 → 固定专家依赖／本条技能／候选目录 → 按需读取方法 → 装载获准资源 → 原 Pi 工具执行 → 记录实际证据。**

继续关闭未经平台批准的自动 Skill 发现；先提供目录摘要，再读正文和资源，不把所有技能全文塞入上下文。调用是否可行取决于工具和业务权限，不能因包声明 allowed-tools 或已发布就扩大授权。

新选择参数带修订与完整包摘要；旧 `{id, hash}` 仅按旧内置语义兼容。旧会话、地图引用和子角色历史保持原解释。[S4]

### 8.2 请求级只读资源区

沿用 `/skills/<skillId>/<revisionId>/` 虚拟资源根建议；内部保留规范技能根名与相对目录，不把内部 ID 冒充规范 name。模型得到的是虚拟路径，不是宿主路径。

仅物化当前请求已激活且获准的固定包，Docker 只读挂载；输入和输出仍在 `/workspace`。read／ls／find／grep 识别只读资源区；write／edit 不得修改包，模板复制到工作区后生成成果。禁止挂载全局能力库、可变草稿目录或原始解压目录。

试用使用独立数据目录；模型凭证只供宿主调用，不进入脚本容器。默认不挂生产业务凭证、其他账号资料或管理员普通个人空间。沿用无网络及资源限制，不提供宿主执行回退。[S5]

### 8.3 生命周期与性能

普通停用阻止新的显式选用、首次装载和依赖该技能的新请求；已准入且装载的请求在原快照和有效授权内收尾，不接收追加输入扩大任务。未使用的可选技能停用不取消无关请求。

恢复仅解除 disabled，不清除 banned 或主体拒绝；归档保留受引用版本和历史。既有封禁／撤权检查继续生效，本轮不新增封禁管理入口。

内容缓存有界，不能共享私有上下文或缓存跨用户授权。记录导入、静态扫描、可选试用、冷／热装载和上下文耗时。扫描以内容快照和规则版本去重、限并发，不进入普通模型请求关键路径；不在日常请求中重复扫描整个技能库。

### 9.1 服务分工

| 位置 | 本轮改造 |
| --- | --- |

### 9.2 接口原则

沿用 v0.1 的技能目录、管理员管理、导入和请求选择接口分组，路径由实施时按仓库规范核定。

`validate` 返回规范格式、基础完整性及扩展支持说明，不返回自动业务环境检测结论。扫描独立提供报告查询与重扫接口，由导入／保存流程自动排队；不得执行 Skill 来完成静态检查。

`trials` 仅由管理员显式发起，返回真实执行记录；validate／scans／publish 不隐式触发试用。`publish` 不要求成功 trialId、scanId 或试用／扫描确认，按第七章基础条件执行。

保存草稿使用 expectedDraftRevision；有副作用操作使用 clientActionId。同键同参数重试返回原结果，异参数冲突。检查、扫描与试用均绑定内容摘要；迟到结果只归属原快照。扫描记录包含扫描器／规则版本、覆盖清单、发现、失败原因与时间，不改变技能发布或授权状态。

### 9.3 存储及旧契约

继续使用 capabilities.sqlite 和不可变内容文件，不建第二份聊天历史。能力库、认证库独立迁移；旧 ExpertRevision、资源记录和 Pi JSONL 保留原语义，不批量改写。[S2、S4]

R2 旧草稿、校验和试用记录仍可读取；本轮取消的是新 Skill 发布的强制试用条件，不将旧专家试用记录置为无效或伪造通过。

后台保持既有 Profile／固定技能兼容路径，不自动投放组织技能，R5 再统一。R3A 可复用技能草稿和结构化报告，但本轮不提供管理 Skill、对话创作工具或模型发布权限。
