# 修复方案：任务漏关联与“未记录却声称已记录”

v0.2｜2026-11-06｜**已批准并实施；工程通过，三轮复验的整体关联语义未全部达标，待审阅**

**业务优先级：先保证每条信息正确关联所有需要考虑它的已有任务，再考虑是否有额外独立工作需要新建。** 有依据的潜在影响也应纳入，明确条件和不确定性；真实记录是执行底线，不能用“已保存”代替判断正确。

工程上仍可先补真实记录的完成检查，再调整判断和表达，便于可靠验收；这不改变上述业务优先级。继续使用现有Pi、任务关联服务和人员建任务流程。

## 1. 修复后应有什么变化

| 问题 | 拟调整后的行为 |
| --- | --- |
| 已有部分关联，却遗漏其他需要考虑本信息的任务 | 在当前授权业务范围内逐一核对活动任务，关联所有需要考虑本信息的任务；有依据的潜在影响说明条件，不当作已确认影响 |
| 文字说“已记录”，实际没有保存 | 核验真实记录和回执；漏调时在同一会话提示补做，最多2次。仍失败则显示“任务判断未完成”，不作为成功分析投递 |
| 将火情主任务缩窄为“只管烟情” | 按完整目标判断事实能否支撑任务；关联理由指出支持哪项目标，不要求名称或对象引用完全相同 |
| 想另开工作，于是放弃关联原任务 | 先保留全部应有关联，再判断是否有现有任务不适合承接的额外独立目标；建议新建不替代关联，不自动创建 |

例如，车辆清单能支持火情任务中的资源核实；发现未知项可在该任务内核实，不自然要求另建任务。确有额外独立交付时，也可以保留信息关联后再提出建议。此例仅供审阅，不写入模型运行时答案。

## 2. 原因判断

已确认：完整目标进入请求，漏判时模型仍省略资源核实范围；另一次未调记录工具，却声称已记录。普通初析缺少必要记录的完成检查，持续研判已有检查及有限补做。

三选一契约、任务结构化引用差异等可能影响相关性判断，尚未证明哪项是唯一原因。本期修正表达限制与研判方法，不据此宣布因果已证实或模型普遍可靠。

依据：[本次复验](../11-05-scenario-business-flow/research/full-repeat-results.md)、[历史修复](../10-26-continuous-background-analysis/missing-record-repair-report.md)。当前关键位置（相对 `experiments/harness-lab/`）：`src/pi/lab.ts:816`的持续研判专用接入、`src/background/service.ts:863`起的初析结束处理、`src/pi/task-information-tools.ts:36`与`src/background/task-links.ts:33`的三选一规则。

## 3. 先补真实记录闭环

**谁必须记录。** 在现有Profile增加可选要求，建议字段名 `requireTaskAssessment`，缺省false。配置了工具不等于必须调用；仅做事实核对的旧方案不被一律强制。启用时必须具备任务查询和记录工具，否则拒绝配置。要求随Profile冻结到来报/作业快照，并清楚提供给Agent；场景来报核对Profile拟启用，代码不按场景名或双系统通道硬编码。已有作业不追加要求。

**如何完成：**

1. 首次正常结束时，检查当前作业的持久记录、对应请求的原生成功回执、任务版本及授权。
2. 可补救的漏调/无效提交，或普通初析需重读任务版本时，通过Pi原生follow-up给出缺口反馈，由Agent自行查询、填写并记录；程序不指定关联对象。
3. 最多2次补做。正常路径不增加调用；补做共用原取消与时限，不新建作业、重启分析或重放业务操作。
4. 最终成功前再核验。仍不满足则使用现有 `failed` 状态及明确错误原因；保留原文和工具记录，不生成成功投递或有效新关联，也不清空旧成功结果和人工决定。

两次补做是连续漏记录的失败收敛规则，不是累计token预算，也不限制Pi正常研判的总工具步数；实验继续采用仅记录用量模式。

**复用范围。** 只对 `continuous-completion.ts` 的“结束检查＋原生follow-up”做必要复用/小范围抽取，两条路径各保留业务核验；持续研判原有补做、版本过期重评和暂停行为保持，不再造宿主Agent循环。

**真实性边界。** 回执必须属于本作业/请求，保存内容与成功工具结果一致；不采信正文关键词、旧回执或失败调用。重复相同内容的 `unchanged` 仍可核验；后续提交失败不能被当作新判断已保存。取消、超时、权限失效、演示结束、历史损坏和来源故障不靠补做绕过，最终提交前仍检查竞争。程序验证执行完整性，不证明关联语义或正文每句话正确。

## 4. 先完整核对已有任务，再考虑新增工作

以下方法放在现有记录工具描述及要求归口的Profile说明，不扩大通用system prompt，不新建Skill、任务索引或额外审核Agent：

1. **完整发现候选。** 通过现有任务查询及分页，读取当前授权业务范围内的活动公共任务；不先用来报标题把候选缩成少数同名任务，不以首次命中或任意Top N代表全部。已有返回包含完整目标时不重复读取；不足再按需读取任务。实际检索范围及缺口保留为证据。
2. **逐个判断是否需要考虑。** 对照完整目标、对象、地点、业务时点、资源和约束，检查本信息是否提供核实依据、有效印证、持续限制或有依据的潜在影响。不要求一定出现新变化才关联，也不要求与任务名称或对象引用完全重合。
3. **保留所有应有关联。** 一条信息可关联多条任务，每项理由说明“具体事实→该任务哪项目标/约束→为何需要考虑”。潜在影响标明条件和待核实事项，不写成已确认冲突；不能靠广撒网关联全部任务来避免漏项。
4. **无关与无法判断分开。** 没有实际支持关系可不关联；检索未覆盖、查询失败或事实不足不能当作已确认无关。有依据的潜在影响应关联并注明不确定性；确实无法判断的，明确资料缺口，评审单列未定项。必要任务查询失败仍不能通过本方案的完成检查。
5. **最后独立考虑新建。** 只有额外工作有独立目标、且不适合由现有任务承接，才建议新建；已有目标内的核实、补充资料和未知项不自动另立任务。提出建议时仍须保存全部应有关联，创建由总体席确认。

宿主负责授权范围、真实查询/回执、版本和合法组合，不以“调用过task_search”断言已穷尽或正确理解全部任务，也不通过硬编码替模型指定归属。覆盖是否正确，必须结合实际查询轨迹和业务依据复验。

保留现有字段，拟调整组合校验：

| 保存内容 | 拟允许 |
| --- | --- |
| 一个或多个已查询任务的关联 | 是，应覆盖所有有依据需要考虑本信息的任务 |
| 仅新建建议 | 是，须先核对已有任务，确无应关联对象，且有独立目标和理由 |
| 已有关联＋新建建议 | 是，全部应有关联保留，额外独立目标另写理由；建议不等于已创建 |
| 仅暂不归口原因 | 是，须完成必要查询；已确认无关与资料不足无法判断在理由中区分，后者不记为已证实无关 |
| 暂不归口＋关联/新建；全空 | 否 |

不新增“信息只能关联一个任务”的限制。权限、观察到的任务版本、事件级人员创建去重及人工覆盖继续生效；当前必要查询不能用另一作业的查询充数。

界面沿用现有关联列表和新建建议区域，分别展示；记录状态取自实际API，失败沿用处理详情提示。保留原始模型正文，不静默改写错误措辞，不新增常驻面板。

## 5. 兼容与范围

旧单类判断和无记录作业继续可读，不追改历史。混合结果沿用JSON字段、不新增表，但旧校验器无法接受混合记录，新Profile字段也不兼容旧配置解析。因此发布需配对备份代码/配置/数据；回退保留新证据并恢复配对快照，不能只切旧代码。

只覆盖信息当次普通初析及任务关联展示。任务后续变化沿用既有重新处理与持续研判边界，不增加新任务创建后全库历史消息回溯。无来源创建、历史轮次恢复、自动派工和长期研判质量扩展不纳入；补做受既有轮次隔离和结束门禁约束。

## 6. 顺序与验收

| 阶段 | 内容 | 通过口径 |
| --- | --- | --- |
| A 完成检查 | 显式要求、回执核验、原生补做、失败显示 | 正常无额外调用；遗漏可补做；连续遗漏失败；取消/版本/归属竞争安全；持续研判无回退 |
| B 关联覆盖与补充建议 | 完整候选发现、逐任务核对、有依据的多任务关联；之后再判断新建，兼容组合结果 | 不以首个匹配替代覆盖；潜在影响有依据且不冒充已确认；合理不关联和无法判断可区分；合法组合可存取展示，人员权限不变 |
| C 独立复验 | 同场景、目标、模型ID与参数，新建3轮完整演示 | 全部13条来报按当时任务逐项查漏、查误、查保存；新建建议单独评审，不能抵消漏关联 |

**主要语义验收改为“逐条信息×当时任务”，E05只是已知回归点：**

- 测评前冻结评审口径及核验表，依据原场景事实和任务完整目标列出明确应关联、明确不应关联及资料不足的关系，说明理由，允许合理多解。表只留在测评侧，不注入Profile、Skill、任务说明或模型工作区，也不照搬作者任务编号作为答案。
- 三轮每条来报都核对当次分析时授权范围内的活动任务与版本，记录：信息、当时任务、应否考虑及依据/不确定性、实际关联与回执、漏关联/误关联/无法判断、新建理由。首报时主任务尚未创建，不能用之后创建的任务倒扣漏关联；人员创建后的原信息关联另查回执。
- 修复目标：明确应关联的关系无遗漏、明确不应关联的关系不误关联；有依据的潜在影响被纳入且未提升为确认事实；需要的判断均真实保存，无“未执行却声称完成”。无法判断单列缺口，不混入无关或正确覆盖数量。新增建议不能弥补原任务漏关联，也不能以组合合法掩盖不必要新建。
- E05同时检查所有应考虑资源信息的已有任务，不只盯主任务；E09既查晚到旧信息的时效，也查任务覆盖；E12既查“火势趋稳不等于结束”，也查应考虑该进展的任务。

沿用原样本，不新增无关来报或给模型归属答案。执行完整、关联覆盖、新建合理性分别报告；Agent离线审阅明确标注，不冒称人工独立盲评，争议保留待核对。未达目标保留失败，不择优补测；少量通过不证明普遍可靠。若需证明某项调整的单独因果贡献，另做单因素对照，不用本批冒充。

继续不因累计请求/token/费用或实验总时长截停，记录实际usage并支持人工取消；真实提供方或证据故障保留失败。工程完整性、模型语义和用户最终验收分别报告。
