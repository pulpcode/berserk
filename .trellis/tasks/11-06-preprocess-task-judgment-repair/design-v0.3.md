# v0.3 任务关联研判修复方案（待审阅）

本轮优先让一条来报关联所有需要考虑它的已有任务，再判断是否需要独立立项。v0.2 三轮的 39 条判断均有保存回执。按事前口径，可判定的 84 项关系中有 5 项漏关联、9 项误关联，另有 6 项新建建议与已有目标重叠，立项必要性待审。[三轮复验结果](research/retest-results.md)

## 本轮改动

| 问题 | 拟调整的行为 |
| --- | --- |
| **漏掉资源对其他任务的影响**。5 项漏关联都来自城西救援车辆继续占用的来报。模型收到了主任务完整目标和车辆归属站引用，但车辆所在地被用作排除主任务的理由。 | 在来报核对 Profile 中要求按任务的完整目标判断。资源当前地点和归属可能指向不同任务时，使用现有态势查询核对归属。理由写清这条事实回答了任务中的哪个问题。例如，临港站车辆在外区作业，仍能回答临港火情任务的资源可用性问题。实际调派需求另按来源证据判断。 |
| **误把排除条件或否定理由写成关联**。9 项误关联均指向交通救援任务。8 项与已排除道路有关，另 1 项明确写了“故不关联”却提交了正向关联。 | 对照任务实际使用的资源、依赖的路线和需要核实的事实。若任务明确绕开某路，只有新资料表明路线可能改变或存在其他具体依赖，才把这条路况纳入。记录工具让 Agent 显式选择“关联／排除／依据不足”。有具体依据的潜在影响选“关联”，并写明成立条件。 |
| **把已有目标内的未知项另立任务**。车辆台账、桥梁核查和旧巡查记录时效等建议，与主任务的资源、道路核实目标有交集。 | 先把已有任务能承接的核实项写入相应关联理由。还有独立工作时，通过新建建议现有的“目标、理由”说明额外需要交付什么、已有任务为何无法承接。原有关联一并保存，由总体席决定是否创建。 |

## 工程落点

调整现有场景 Profile 和任务判断记录工具。新版工具一次接收逐项结论、任务编号和理由。宿主校验已查询的任务、版本和授权，拒绝同一任务的矛盾结论，只将选为“关联”的项写入现有关联清单。“排除”和“依据不足”的理由留在本次原生工具记录中，人工保留或移除关联仍按原权限处理。没有正向关联时，按实际情况提交独立新建建议或暂不归口原因。

新版输入由 Profile 选择并随作业冻结。旧快照沿用原工具格式，成功回执、已有任务关联数据和页面继续复用。最终任务清单按保存结果展示。模型对事实的解释及正文与回执是否一致，纳入语义复验。上述车、站、路实例仅供方案审阅，运行时使用通用判断规则。

## 验收

1. **工程回归**覆盖三类结论的写入结果、同一任务结论冲突、关联与新建建议并存、旧作业重处理、权限和轮次隔离。验收时同时检查工具入参、作业回执以及业务席实际可见的关联。
2. **真实模型复验**沿用已冻结的场景、任务目标、模型参数和[逐项评审口径](research/review-rubric.md)，用全新数据从头跑三轮，累计用量只记录。目标为 39 条判断均有真实回执，42 项应关联全部命中，42 项无关联依据零误入，正文与实际关联清单零矛盾。30 项未定关系按依据和条件逐项审阅。
3. **单独评审新建建议**。逐项核对额外交付及已有任务的承接范围，重点复核上轮 6 项重叠风险。首报尚无主任务时，有依据的新建建议仍属合理。保留全部失败和争议项，交由用户审阅。
