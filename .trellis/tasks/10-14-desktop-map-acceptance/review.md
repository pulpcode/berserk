## Findings (not fixed)

这些不是可以在本轮测试任务中静默改掉的机械缺陷，已记录原因与影响：

1. **原始 A01 指令的业务歧义。** 首批 main-3 将「一起」理解为区域边界和车辆，明确说明道路未加入并询问。未达到三对象门槛，但没有虚报。第二、三批预先明确三个对象，属于新输入条件，不能声称原提示稳定性提高。
2. **共享任务当前状态的过期陈述。** 第二批 C01 请求 `44a7ec4b` 说「本任务也仍无当前版本」，实际请求开始前已由总体席 UI 采用 P1、sequence=1。模型只读草稿，没有重新查询任务当前；本次备注保存与未发布声明正确。此为明确的额外状态陈述错误，后一次查询后纠正。第三批没有复现这条陈述，但不能据此视为已修复。若后续改进，应单独验证回答对共享状态的依据，不能为这一观察立即新增状态缓存或校验框架。
3. **无依据的动作归属说明。** 第三批 C02 请求 `59ac6ea3` 将此前采用 P2 说成「会话 B 所属流程」，实际是总体席的管理会话。P2、采用时间和用户 ID 正确，B 归属是额外推断；不影响本次权限拒绝及结果。保留为回答质量问题，没有修改提示词掩盖它。
4. **自然语言地图链接质量。** 第三批 main-3 正文出现 `[href]` 占位链接；主代理已核对实际结构化结果入口可点击并打开固定结果。本期核心路径满足，正文链接问题仍保留，不将结构化入口通过扩大为任意 Markdown 引用均可靠。
5. **冗余业务确认。** 第二批 B01 对已明确的备注修改再次确认；第三批 C02 有一轮含两题的额外问答。后者仅确认原目标和失败后的报告方式，属于已批准的正常业务交互；不能标作无交互完成，也不能混同为提供工具提示或人工修复成果。

本轮没有发现越权写入、错误对象修改、静默覆盖或固定标注漂移；上述额外说明问题没有被归入「错误保存」或借歧义认定虚报。修复产品行为需要另行确定具体目标，不在测试代码中加入隐式纠正模型结果的机制。
