## 1. 验收路线

围绕三组业务流程安排八个用例：

| 组别 | 用例 | 关注结果 |
| --- | --- | --- |
| 地图与对话接续 | A01 选取引用并上图；A02 人工编辑后继续对话；A03 同一草稿保存冲突；A04 歧义目标澄清 | 找对对象、接续手工修改、保存可核对、冲突可恢复 |
| 同任务多会话 | B01 同基线独立草稿；B02 跨会话查看与固定引用 | 讨论不互相覆盖，查看不改变编辑目标 |
| 发布与任务采用 | C01 显式发布与授权采用；C02 权限对照 | 发布与采用分开，已有草稿稳定，权限正确 |

“同任务双会话”指**一个用户账号、一个席位、一个任务，创建 A、B 两个会话并交错操作**，不要求两个模型调用必须同时执行。A03 的两个页面则打开**同一个会话**，操作同一草稿，专门验证冲突。跨席位使用不同账号、不同浏览器身份环境；不等同多个用户同时登录同一席位。

## 2. 环境、身份和数据

### 2.1 环境

- 独立本地验收服务、数据库、数据目录和模拟来源；仅使用虚构数据，不接触线上任务。复用现有 `startMapTrial`、正式登录、地图 fixture 和原生 Pi 执行。
- 桌面主视口 1440×960，补查 1280×900、拖动三栏分隔线、地图放大／还原和窄地图面板。没有手机验收。
- 瓦片使用本地固定测试资源，避免公网瓦片速度影响业务判断；保留地图底层 MapLibre 与实际标注渲染。
- 沿用现有已授权模型配置，记录提供方、模型、实际请求参数、代码／Skill／schema／夹具 hash。真实模型只接收虚构资料和正常业务输入，不接收评分表。
- 浏览器业务步骤走现有界面及真实服务；初始化材料可用现有服务／API。不能通过直接写数据库代替被验收的操作。读取 API 或数据快照只作为独立核对证据。
- 假模型仅用于可控边界与回归；不能据此宣称真实模型完成。已有 Playwright 路由使用 app.inject 的测试也要与真实 HTTP、真实模型桌面走查分开标识。

### 2.2 身份

| 标识 | 身份和权限 | 用途 |
| --- | --- | --- |
| 筹划席账号 | 正常来源读取、自己的任务工作区和会话；无公共任务管理权限 | 主流程、A/B 两会话、发布 |
| 总体席账号 | 具备现有公共任务管理权限及相同来源权限 | 浏览授权发布版、设为任务当前 |
| 私有对照 | 筹划席账号 的个人空间或其他席位私有草稿 | 验证 总体席账号 管理公共任务不等于可读其他私有内容 |

公共任务采用权限按当前 `canSetCurrent` 判定，不按席位名称猜测；测试账号的权限由准备清单核实。跨席位用独立 browser context／浏览器档案，避免共享 cookie 导致串号。来源读取授权对两个正常参与账号保持一致，防止把来源无权限误判为版本功能失败。

### 2.3 材料

- 公共任务 T：“西区现场协调”；对照任务 T2：“东区独立核对”。对象名称、任务和 ID 可辨认。
- 来源数据包含西区区域 Polygon、道路 LineString、车辆 Point；已有可用几何及业务时间。复用已验收数据结构，不由模型估算坐标。
- A01 从没有会话草稿开始；A02 额外手工新增“集合点甲”，位置使用给定坐标。
- B/C 使用明确的共同发布基线 P0，含“集合点甲”“集合点乙”和“现场讨论”层；A/B 首次编辑从 P0 派生。P0 的来源、字段、hash 和创建回执先记录。准备动作不算模型完成的步骤。
- 初始来源 r2 为道路关闭，后续 r3 为恢复通行。业务时间落在本轮合成任务的有效时间窗；绝对日期在启动前固定，避免复用过期日期制造无关歧义。
- 基线及每个结果分别记录：来源实际查询事实、标注持久字段、草稿修订、发布内容和任务当前指针。来源引用不自动等于保存了全部业务属性。

## 3. 场景、步骤和逐项标准

### A01 地图选取 → 引用到对话 → 生成标注

**前置：** 筹划席账号 进入 T 的会话 A，无草稿；来源可用。

1. 在会话中打开态势地图，展开来源态势，在地图上点击西区道路；若对象重叠，使用已有候选列表明确选中道路。
2. 点击引用到对话，检查输入区出现正确来源对象；仅选取或引用，不应产生模型请求或写入。
3. 发送业务指令：“围绕引用的西区道路，查询该区域边界与车辆，一起放到本会话的‘现场讨论’图层。当前没有草稿，请建空白草稿。位置采用已有来源，先不发布。”
4. 等待 Agent 正常完成，点击其工具结果／答复旁的地图入口，查看草稿对象。
5. 切换显隐、展开层与对象、放大／还原地图；刷新页面重新查看。

**通过：** 选择与发送引用一致；三对象属于会话 A 的指定层，几何与实际来源相同；保存的完整来源引用、修订和查询时间正确；无额外发布或采用。入口打开真实固定结果，重新加载仍存在。显隐、折叠和布局操作不新增草稿修订，不改变编辑目标；打开地图与引用不会自动执行模型。

**证据：** 选择和输入区截图、实际发送的 contextRefs、原生消息与工具回执、前后草稿快照、重载截图。contextRefs 与标注 annotationRefs 分开记录。

### A02 人工调整 → Agent 接续编辑

**前置：** A01 完成；“现场讨论”为明确目标层。

1. 使用地图绘制或坐标新增“集合点甲”，保存，记下对象 ID 和位置。
2. 选中该标注，引用到对话；输入“把这个集合点的备注设为‘待核实’，不改变名称、位置和所属图层。”发送并核对保存。
3. 通过地图手工将名称改为“备用集合点”，调整到给定新坐标并保存。记录手工保存修订。
4. 再引用最新标注，发送“以本会话最新草稿为准，只把这个点的备注改成‘已核实’，保留我刚调整的名称、位置和图层。”
5. 检查新对象详情并重载。另在输入区保留一段未发送文字，进行地图放大／还原和分栏调整，确认文字与引用保留。

**通过：** 两次 Agent 编辑均命中同一对象 ID；第二次保留人工修改的名称、坐标和图层，仅备注变化。其他对象不变，模型没有照旧聊天中的坐标覆盖新值。布局切换不发送消息或丢失输入。刷新后的实际字段与明确的完成说明一致。

**证据：** 每次保存前后的字段差异、annotationRefs 的固定版本及 objectIds、实际读取／写入调用、地图详情截图。不能只凭地图位置看似相同判断没有覆盖。

### A03 两个页面编辑同一会话的冲突与恢复

**前置：** 同一 筹划席账号、同一 T、同一会话 A；两个页面操作同一草稿，不新建会话。

1. 页面 1 打开集合点属性表单，将备注输入“人工补充说明”，暂不保存，记录表单起始修订 rN。
2. 页面 2 在会话 A 中发出“将集合点甲〔实际名称〕的备注改为‘Agent 补充说明’，其他字段保持不变。”等待实际保存为新修订。
3. 页面 1 点击保存；观察冲突提示和原输入是否保留。
4. 使用已有“查看最新保存版本”核对，再按已有“已核对最新版本，重新编辑”入口，由操作员明确决定保留并保存“人工补充说明”。
5. 重载两个页面，核对最终字段、修订链和对象数量。

**通过：** 第 3 步旧修订保存被拒绝，无静默覆盖、无重复对象；Agent 已成功的内容仍在已保存版本中，页面 1 输入保留。第 4 步基于用户明确核对后保存才形成新修订。不会自动把“刷新页面”当作允许覆盖。

**执行注意：** 若界面本身阻止并行操作，先记录实际限制；不能直接绕过后宣称桌面路径通过。必要的受控冲突可另用现有测试夹具复现，分别报告。反向“Agent 读后遇到外部写入”继续复用确定性回归，不依靠延时碰运气制造真实模型竞态。

### A04 明确选择与歧义澄清

**前置：** 单独干净会话有两个同名“集合点”的对象，分别位于两个可区分图层；没有待发送引用或唯一目标。

1. 输入：“把‘集合点’的备注改为‘待核实’。”
2. 记录 Agent 是否提出选择问题；在尚未确定对象时检查没有写入。
3. 操作员给出预先定义的正常业务回答：“修改‘现场讨论’图层里的集合点。”若它使用 ask_user，选择对应项；若用正文提问，按正常对话回答。
4. 核对仅指定对象变化。随后直接从地图引用另一个对象并请求改备注，验证唯一引用能解除歧义。

**通过：** 歧义未解除前不猜测修改，也不通过新建图层绕开问题；正常澄清后正确完成。已有唯一引用时不应要求用户再查找内部 ID。澄清本身算正常业务交互，不算人工纠正。

**说明：** 本例只规定确实存在多个候选的情况；不把所有未写图层名的指令一律判为必须提问。用户明确授权自行选择时，应按该授权另评，不能套用本例。

### B01 同一席位两个会话从共同基线独立修改

**前置：** 筹划席账号 在 T 有会话 A、B，均显式选择固定 P0；没有自动采用最新任务版本。

1. 分别在两会话地图确认 P0 基线，完成首次编辑以形成各自草稿；记录两个不同 setId。
2. A：“把本会话集合点甲备注改为‘A 现场讨论’，保留其余内容。”核对 B 草稿没有变化。
3. B：“把本会话集合点乙备注改为‘B 保障讨论’，保留其余内容。”核对 A 草稿没有变化。
4. 在两个会话间交错查看、关闭／打开地图、重新加载页面。
5. C01 采用 A 的发布版之后，再回到 B 继续修改其已有草稿，检查它仍沿自身修订链保存。

**通过：** A/B 可继承相同对象逻辑 ID，但 setId、修改内容和修订链各自独立。切换会话后显示与编辑的是对应草稿；A 的修改、发布、任务采用均不改写 B 的已有草稿或基线。任务当前只是显式采用的发布版，不是两个草稿的合并结果。

### B02 跨会话查看、引用和历史稳定性

**前置：** B01 第 3 步完成；A 保存固定修订 A:rN，B 有自己的可写草稿。

1. 在 B 的版本入口添加 A:rN 为只读参考，并引用其中一个对象到 B 对话；记录完整固定引用。
2. 发送：“比较引用对象与本会话对应对象的备注，只说明差异，不修改。”核对按固定版本读取并解释；两份草稿均不新增修订。
3. 回 A 修改该对象备注形成 A:rN+1；回 B 点击原消息引用和旧地图入口，再重载。
4. 在 B 选回“本会话标注”对象，发送明确编辑指令；核对只写 B，不写 A，也不修改参考。
5. 刷新模拟来源 r2→r3，再查看来源态势和旧标注参考。来源入口若重新查询当前资料，应明确它是当前查询，不宣称加载了来源 r2 的历史几何。

**通过：** 旧标注引用始终指向 A:rN，后续保存或来源刷新不替换它；参考只读状态可辨，不能直接编辑 A 的草稿。看过 A 参考后，B 的可写归属保持不变。没有支持的历史来源不能被说成已重放。

**边界：** 同席位有权限读取固定草稿不等于能经模型工具修改别的会话。跨席位读取私有草稿在 C02 中应被拒绝。

### C01 发布、采用和继续编辑

**前置：** T 是公共任务；筹划席账号 可编辑 A，总体席账号 具备现有任务管理及所需来源权限；B 草稿快照已记录。

1. 筹划席账号 在 A 明确要求：“把本会话当前已保存标注发布为‘西区讨论第一版’，先不要设为任务当前。”记录 P1 和发布修订。
2. 核对任务当前指针未变；总体席账号 使用自己的浏览器身份打开同任务的 P1。
3. 总体席账号 在界面“比较并设为当前”中核对差异，明确点击“设为当前标注”。这里是操作人自己的确认，没有另一个审批人。
4. 检查任务当前指向 P1、选择记录归属 总体席账号；刷新 筹划席账号 页面，确认显示的任务当前更新，但 A/B 草稿未改变。
5. 筹划席账号 在 A 继续编辑形成新草稿修订，不发布；核对 P1 和任务当前保持不变，并执行 B01 第 5 步。
6. 筹划席账号 明确发布第二版 P2，不自动采用；总体席账号 在自己的会话中明确要求“比较目前任务当前与‘西区讨论第二版’，将第二版设为任务当前”，检查真实读取／比较及采用回执。

**通过：** P1/P2 均固定，发布不隐式采用，只有明确授权操作改变任务当前。界面与 Agent 两条采用路径复用相同权限，已有当前版时有实际比较依据。采用不合并或覆盖 A/B 草稿。每次用户动作只产生相应的有效发布／选择效果；无额外通知、审批或外部业务动作。

### C02 权限对照

**前置：** 沿用 C01 身份；筹划席账号 没有公共任务管理权限，总体席账号 不能读 筹划席账号 的私有草稿／个人空间。

1. 筹划席账号 浏览 P1，检查没有可执行的采用入口；在其会话请求将 P1 设为任务当前，核对系统未执行。记录是模型可用工具约束还是实际服务拒绝，不把口头拒绝当作服务权限证据。
2. 通过现有正式认证客户端，以 筹划席账号 对同一真实采用接口提交对照请求；预期拒绝，任务当前不变。该步骤是权限测试，不算用户正常操作路径。
3. 总体席账号 可以打开 T 的 P1，但不能打开 筹划席账号 会话 A 的私有固定修订；再尝试 筹划席账号 私有任务的入口，检查不暴露标题、几何、对象数量或引用内容。
4. 在两个浏览器身份之间复查页面及结果，确认没有共享会话／登录态导致错判。

**通过：** 非管理用户不能改变公共任务当前；管理权限不赋予其他席位私有内容访问权。持有 ID 或历史链接不是访问令牌。不得因用户要求、猜到 ID 或地图引用扩大权限。

## 4. 如何判定结果

### 4.1 每个场景分别给出三项结论

| 维度 | 判据 |
| --- | --- |
| 数据和权限 | 对象、字段、几何、修订、发布、当前指针、访问范围与预期一致；失败无额外效果 |
| 用户操作 | 能通过现有桌面入口完成，能定位结果、辨认版本与编辑目标、处理明确冲突 |
| Agent 行为 | 正确理解明确目标；需要时澄清；可自行恢复普通调用错误；不明确虚报已完成的业务动作 |

最终状态使用：**通过、通过并记录观察项、人工纠正后完成、失败、环境阻塞、未执行**。正常澄清和正常业务核对另标注，不归为人工救场。任何未执行或环境阻塞不算通过。

### 4.2 阻断与观察项

| 情形 | 判定 |
| --- | --- |
| 越权、跨会话写入、改错对象、静默覆盖、历史漂移、重复效果、未经要求发布／采用 | 阻断；停止受影响写入，保存证据 |
| 无法通过现有入口完成核心步骤，或明确完成声明与实际动作结果相反 | 阻断；记录具体步骤与实际结果 |
| 参数不完整被拒绝，Agent 补齐后完成且无额外错误效果 | 可通过，记录恢复成本；不以零工具错误作为门槛 |
| 连续三次相同失败调用，参数未修正、没有取得新信息，也未转入澄清 | 记为恢复停滞，结束该测试步骤；这是验收停止条件，不修改产品重试策略 |
| 能唯一理解的业务澄清或冲突核对 | 正常交互，不扣成模型失败 |
| “旧版引用的道路当时关闭”等可能同时指来源事实和保存内容的文字 | 记录原句及上下文，允许合理解释，不直接算虚报保存 |
| 明确说“已将 passability=closed 写入标注属性”，实际属性没有该字段 | 成果说明不符；如属于用户要求的交付，阻断，否则单列语义问题及影响，不掩盖真实已完成部分 |
| 主观觉得繁琐、略多读取、时间省略到秒、无实际误导的术语 | 观察项；先记录，不预设必须改工具或增加校验机制 |

不通过机械关键词匹配判定自然语言事实。判断“虚报保存”必须同时给出用户要求、Agent 明确声明、实际回执／持久数据和差异；有合理歧义时先澄清，不能用审阅者猜测制造缺陷。

### 4.3 总体通过门槛

- 八个场景均执行，全部必需步骤满足数据、权限和用户操作标准，且无未解决阻断问题。
