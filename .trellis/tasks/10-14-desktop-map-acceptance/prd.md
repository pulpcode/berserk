## 1. 目标

验证用户能在桌面浏览器中，通过地图选取与引用、Agent 对话、人工编辑、多会话讨论、发布和任务采用，完成一套可继续使用的地图标注。观察真实用户操作、模型调用、地图呈现与实际保存结果是否一致，按真实阻碍决定下一步修复。

本阶段以已有能力验收为主，不预设必须新增框架、工具或提示词机制。

## 2. 已有基础与本轮增量

- 上阶段确定性检查 157 项通过，三例真实模型均完成查询上图、发布与刷新；原先因全量遗忘造成的交替补读未复现。证据见 [恢复验证](../10-10-task-plan-validation/agent-map-workflow/recovery-validation.md)。
- 桌面地图已有独立草稿、固定引用、绘制、冲突处理和版本采用测试；其中地图测试使用假模型。参见 `experiments/harness-lab/tests/e2e/annotations.spec.ts` 与 `situation-map.spec.ts`。
- 本轮新增验证组合是“真实浏览器操作＋真实 Agent 多轮执行＋同任务多会话／跨席位”，不把此前分别通过的局部测试相加为完整业务通过。
- 根据本轮讨论，本稿将偶发调用被拒绝后能自行恢复、没有错误写入列为可接受情形，已获用户批准。对“发布版引用的道路当时关闭”等有合理解释的表述，先记为歧义，不直接认定虚报保存或阻断验收。

| ID | 要求 | 对应场景 |
| --- | --- | --- |
| R1 | 地图选择与引用能进入对话，Agent 修改正确对象与图层，成果可打开、可重载 | A01、A02 |
| R2 | 人工编辑后继续对话以明确的当前草稿为准；过期保存不能静默覆盖，未保存输入可恢复 | A02、A03 |

## 4. 通过标准

具体逐步判据见 design.md；以下规则优先于调用效率或措辞评分：

1. 不得出现越权、修改错误对象／会话、静默覆盖并发编辑、固定版本漂移、未要求的发布或采用、重复业务效果。
2. 指令明确的操作必须在目标草稿或发布版中实际落盘，并能从桌面入口核对；任务失败或未执行不能明确声称成功。
3. 用户可理解正在看哪个版本、编辑哪份草稿；页面刷新与布局切换不能悄悄改变编辑归属或丢失本应保留的输入。
4. 工具参数错误后自行纠正不自动判失败；记录次数、耗时与额外读取。没有新增信息而反复执行相同失败调用，应按恢复停滞单独记录。
5. 正常业务澄清不算人工救场；人工补充正确工具、指出遗漏写入或替模型修复结果，计为人工纠正。
6. 单凭措辞存在其他合理理解，不能认定虚报保存。只有能指出“明确承诺保存的具体对象／字段／版本”与实际结果不符，才认定成果说明错误。
7. 同一冻结版本所有必验场景满足标准，才可给出“本轮场景验收通过”；环境未覆盖或仅假模型完成的部分不能算真实使用验收通过。通过也不代表任意任务的普遍可靠性。

## 5. 不在本阶段范围

- 手机端、全新布局、地图视觉风格改造。
- 工作交接、普通文件协作、MCP 迁移、新 Agent 编排器、跨请求读取缓存、审批流或自动采用。
- 多个不同账号共用同一席位的新账号模型；真实多人共席压力测试。
- 空间计算算法、复杂 GIS 推理、真实业务资源调度、模型选型与 Skill 因果效果对照。
- 生产数据、线上服务升级、推送或自动部署。

既有契约内的缺陷可在批准后的执行阶段以最小修复处理并另批复测；若需要改变权限、版本语义或产品能力，先提交变更方案审阅。
