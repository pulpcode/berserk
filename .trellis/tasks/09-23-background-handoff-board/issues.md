# 后续问题

## PERM-001：丰富完善权限体系

记录日期：2026-09-23。状态：后续建设阶段待设计，不阻塞本期；具体范围与实施时点另行审阅。

### 现状与需求

当前已有席位及来源访问权限、业务工具授权与确认、命令检查和 Docker 沙盒。本期修复命令误拦及后台工具反馈，保留这些机制。

命令检查只覆盖已识别的调用形式。Python／Node 文件脚本与可写文件工具可以修改工作区，当前不会完整审计脚本效果；拦截 `rm` 不等于所有删除、覆盖操作都必须审批。Docker 限制可访问的目录、网络和进程权限，但不会阻止获准程序修改可写挂载目录。未知语法进入待审，也不等于已确认该命令危险。

随着席位、自动处理和工具能力扩展，需要明确授权范围与审批要求，并让页面、工具说明和实际执行保持一致。

### 后续需评估

- 席位、任务和服务身份可访问哪些资料、文件及工具；前台、后台和 Agents 如何沿用对应授权范围。
- 哪些操作由工作区权限直接允许，哪些确需逐次确认；删除、覆盖等效果是否需要跨工具统一控制。
- 复杂 shell 语法和脚本的检查边界，是否复用成熟机制，以及无法判断时如何处理。
- 有审批需求时由谁处理、人员不在线时怎么办，以及现有记录和界面是否足以说明授权与执行结果。

上述内容是待评估问题，不预定全量权限平台、脚本审计引擎或后台持久化审批。本期不为其预埋状态、表或接口。

### 完成判据

后续方案明确权限主体、资源范围、确认规则及其能力边界，并在获批后实施；使用真实文件处理与业务协作场景验证前后台及不同工具入口，不以命令名匹配宣称已控制全部同类效果。
