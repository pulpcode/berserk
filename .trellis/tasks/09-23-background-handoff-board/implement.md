## 验证重点

- 共用策略：两条复现命令及相关文件检查场景、普通文件通配、后接命中确认／禁止规则的命令、动态目录、变量和命令替换、重定向、解析器故障。整条命令校验后再执行；前台和后台都验证，未知语法与明确风险的原因不混用。
- 能力边界：回归沙盒内正常 Python／Node 文件脚本与文件工具读写；保留现有容器隔离检查。脚本效果未审计，不把命令规则测试通过写成“所有删除／覆盖均需审批”。
- Pi 反馈：后台 ask → 工具错误 → 获准读取 → 正常答复；后台 deny 仍不执行；普通对话 ask 仍需确认，拒绝后不执行。
- 结束语义：受阻后只有无法完成的最终答复，仍按现有执行完成及投递机制处理；详情保留真实受阻证据。技术失败、取消、中断不被包装成成功，也不因一次 ask 自动判失败。
- 重新处理：新作业关联旧作业，沿用原输入及规则快照；改当前规则不悄悄改变旧快照。仅重试投递不调用模型，旧失败不自动重跑。
- 页面：侧栏常驻，原会话草稿和流式执行保留；看板各列筛选、计数与分页，详情深链、刷新、返回焦点和键盘关闭可用。
- 数据权限：同一信息多次执行的状态与投递按 jobId 展示；来源无权、view-only 管理操作、其他席位私有分析正文及文件均按当前边界拒绝。
