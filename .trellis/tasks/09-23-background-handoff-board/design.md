# 设计：后台工具反馈与信息处理看板

状态：2026-09-23 用户已批准，实施中。范围见 [PRD](prd.md)，执行顺序见 [实施计划](implement.md)。

## 1. 执行方式

Pi 继续负责 Agent 循环、工具消息和压缩；宿主负责命令策略、作业记录、权限及投递。前台和后台使用同一命令判定，只在需要人工确认时采取不同处理方式。

`ask` 包括命中确认规则和暂时无法分析两种原因；后者不等于已知危险。`allow` 表示按当前规则获准执行，不代表没有写入等副作用。

| 判定 | 后台处理 | 普通对话 |
| --- | --- | --- |
| allow | 执行工具，返回结果 | 执行工具，返回结果 |
| ask | 不执行该命令，返回“后台无法审批，本次未执行”及规则原因；Pi 可继续 | 展示现有确认卡并等待决定 |
| deny | 不执行，返回禁止原因 | 沿用现有拒绝机制 |
| 策略解析器或记录存储异常 | 结束请求并记录技术失败 | 沿用现有失败机制 |

后台 ask 分支移除整请求 `stop('failure')` 和 `terminate:true`，复用 Pi 原生工具错误反馈及已有命令策略记录。Agent 可以换用获准方法；宿主继续按现有命令规则和各工具权限校验，不因重试放宽权限。规则拦截的是当前调用，对其他入口产生的同类效果不保证识别，边界见下一节。取消、请求时限和模型错误仍按现有机制收尾。

bash 工具说明按执行模式描述实际能力：前台可以等待确认，后台返回未执行原因。删除后台“网页已展示确认卡／去普通对话即可继续”的错误承诺，不增加通用业务流程提示。

## 2. 共用命令策略

现有权限机制各自负责：

| 机制 | 作用 |
| --- | --- |
| Docker 沙盒 | 限制可访问目录、执行网络、进程权限及资源；`/workspace` 保持可写 |
| 命令检查 | 对已识别的命令与参数决定允许、待审或禁止；不是完整脚本效果审计 |
| 业务授权与确认 | 由服务端校验席位、任务、来源访问及分派、提交等业务操作 |

Python／Node 文件脚本和可写文件工具仍可修改工作区。拦截 `rm` 不等于所有等效删除或覆盖都需确认，沙盒也不会阻止对可写挂载目录的修改。更完整的权限及跨工具效果控制需求在 [PERM-001](issues.md) 中后续评估。

修复范围覆盖前台和后台，保持整个命令链先校验、再执行：

- 初始目录固定为 `/workspace`。支持不改变该目录的字面量 `cd /workspace`、`cd .`；其他目录切换仍待审，不能直接移除全部 cd 检查。
- 支持 `ls`、`md5sum`、`sha256sum`、`wc` 普通文件参数中的简单文件名通配，例如 `*.md`。不通过运行 shell 来推演展开结果，不扩大到变量、命令替换、解释器参数或任意重定向。
- 带目录逃逸、动态目录或未支持组合继续按现有策略处理；后接命中确认／禁止规则的命令不能因为前面的 cd 已获准而跳过检查。保留实际原命令，不为通过检查改写内容。
- 未支持语法说明“无法可靠分析，需要人工检查”，与已命中的风险规则区分。保留现有明确命令规则，不统一放行未知语法，不增加完整 shell 解释器或模型安全判断。

复现命令：

```sh
cd /workspace && ls -la
cd /workspace && ls -la && echo "---HASH---" && md5sum *.md && sha256sum *.md && echo "---WC---" && wc -l -c *.md
```

## 3. 状态、答复与投递

沿用 `queued → running → succeeded / failed / cancelled / interrupted`，不新增执行状态或业务完成度字段。

- `succeeded` 在页面显示“执行完成”：本次 Agent 正常结束，最终答复和已发布文件通过现有核验。答复可能是完整结果、部分结果或无法完成的说明。
- `failed` 是实际执行错误，例如模型调用最终失败、记录写入异常或缺少有效最终答复；不是由“出现过 ask”或正文中的某个词推断。
- 取消、中断和历史记录沿用已有语义。受阻工具只是执行过程中的事实，不是新的作业终态。

正常结束的预处理继续创建现有结果投递；未正常完成的不新增结果投递。Agent 如果只回复“当前条件下无法完成”，这份答复也可能被投递。本期不新增结构化完成报告工具、关键词判断或额外模型验收。

详情分别展示“执行状态”“处理答复”“投递情况”。执行过程展示具体受阻命令、工作目录、规则原因和“未执行”，从既有原生记录读取；必要时在现有详情接口增加只读投影，不建立另一套日志或失败事实表。

一条信息的不同处理作业按 `jobId` 分别展示；每次投递归属具体作业。前一次完成并已送达、后一次失败且未投递，要分成两条经过。投递失败重试只做送达，不再次执行模型。

## 4. 人员如何处理异常

有来源查看权限者可核对获准内容；有来源管理权限者可执行已有取消、重新预处理或投递重试。管理权限不等于命令批准权，也不等于服务器维护权限。

| 情形 | 处理方式 |
| --- | --- |
| 普通列目录被误判待审 | 开发维护人员部署共用策略修复后，来源管理人员明确重新预处理 |
| 模型额度不足或执行环境故障 | 维护人员恢复额度或环境后，管理人员重新预处理 |
| Agent 想用 `sudo apt-get` 安装依赖 | 该命令仍禁止；维护人员可评估并预装沙盒依赖后再处理，不提供网页提权或临时放行按钮 |
| 原始附件缺失、内容需要替换 | 来源按新消息提交修正输入；不修改旧输入或期望重跑后附件自动改变 |
| 工作确实无法在当前权限下完成 | 查看已有答复和原因，保留记录；本期没有批准旧命令或自动转前台的入口 |

**重新预处理沿用原作业的输入和规则快照，创建新的作业与独立目录，并记录 `retryOfJobId`。** 修改当前规则不会改变旧作业重处理使用的快照；需要新规则或新输入时提交新消息。重处理不自动解除任何执行限制，也不会清除旧错误。

已有席位后台分析仍由本人进入关联会话，待本次执行结束后发起新请求；这不是恢复原工具调用。预处理失败不自动转成目标席位的待办或普通会话。

## 5. 信息处理中心前端

沿用一个应用、现有登录和 `/information` 路由，只切换右侧内容，左侧导航保持常驻。取消常驻“返回工作台”按钮。无权限提示也保留导航，切换页面不清空对话草稿或停止执行。

```text
左侧常驻                     右侧：信息处理中心
┌────────────────┬─────────────────────────────────────────────┐
│ Axon           │ 信息记录 | 后台作业 | 处理与投递规则          │
│ 新建对话       │ 来源筛选、搜索、看板／列表                    │
│ 收到的信息     │                                             │
│ 信息处理中心   │ 排队中 | 执行中 | 执行完成 | 异常／已停止     │
│                │  作业卡片       作业卡片                    │
│ 任务与会话列表 │                         ┌─────────────────┐ │
│ ……             │                         │ 作业详情侧栏    │ │
│ 设置／当前席位 │                         │ 状态、答复、过程│ │
│                │                         │ 文件、投递、操作│ │
└────────────────┴─────────────────────────┴─────────────────┘
```

| 栏目 | 本期交互 |
| --- | --- |
| 信息记录 | 保留列表、原始信息和附件；按作业分别展示处理与逐席位投递经过 |
| 后台作业 | 默认看板，可切换列表；一张卡对应一次执行，点击打开详情侧栏 |
| 处理与投递规则 | 保留当前配置入口；不新增审批人、接手人或命令放行规则 |

看板四列：queued、running、succeeded、异常／已停止。最后一列合并 failed／interrupted／cancelled，卡片仍显示“执行失败／执行中断／已取消”具体标签。没有“待批准”或“需人工接手”列，不通过拖拽修改状态。

卡片显示获准的标题、来源、类型、时间与当前阶段；技术错误给出简要原因，预处理另行显示投递情况。“执行完成”卡片不自动代表目标已达成，完整答复在详情核对。

各列使用同一筛选条件，独立分页并显示服务端计数；合并列需一致排序和分页，不能拆分全局第一页充当完整看板。复用现有轮询，仅按需要扩展作业查询的状态筛选和计数。

详情按“本次执行状态及可用操作 → 原始输入／附件 → 处理答复或错误 → 本次投递 → 可展开的执行过程”组织。已有操作：

- queued／running：有权限者取消。
- 已结束的预处理：有管理权限者明确重新预处理；提示沿用原输入与规则快照。
- 投递失败：有权限者重试该次投递。
- 席位分析：本人可进入关联会话，其他查看者不得获得该链接。

进入信息中心默认后台作业看板；显式深链和已有栏目定位优先。关闭详情恢复卡片焦点和滚动位置，Esc 可关闭；刷新、前进后退保留定位，轮询不抢焦点。

来源权限继续由服务端检查。其他席位的 `seat_analysis` 只显示当前已获准的最小状态摘要，不暴露私有目标、会话、文件、具体命令或错误正文。中心管理权不授予这些内容的访问权。“收到的信息”继续接收现有正常结束的预处理答复，不增加接手通知。

## 6. 数据与实施边界

不升级 Pi、不迁移 JSONL、不新增 SQLite 状态、表或投递类型；复用当前作业、投递、原生记录和权限。详情与看板需要的只读查询扩展按当前访问规则实现。

旧 `HUMAN_ACTION_REQUIRED` 失败保留原状，不追改为完成、不自动重试。新行为仅应用于更新后的请求。源码与页面修改完成后再单独发布，使用现有备份与更新方式，不动线上业务数据。

`request_handoff`、`blocked`、接手投递、后台持久化审批和自动转前台流程均后置；本期不为它们预埋接口或数据字段。
