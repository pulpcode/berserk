## 2. 预计影响位置

以下路径相对于 experiments/harness-lab：

- 新增 src/files/：上传、文件元数据、目录浏览、下载副本和受控文件服务；不导入 Pi。
- 新增 src/execution/：请求执行沙盒、当前任务／席位目录挂载、进程／取消／超时和日志映射；按 requestId 管理容器，停止不影响其他会话。
- src/workspaces/store.ts 与资源映射：增加 taskSpaceId／seatId、当前测试席位过滤与旧数据迁移；既有 Session 继续绑定原 workspaceId。
- src/pi/lab.ts 与新文件工具接入模块：公开 Pi 工厂、cwd、主子权限、原生记录、压缩与停止兼容。
- src/pi/roles.ts、subagent-history.ts、history-evidence.ts：新工具目录与记录校验；保留旧历史。
- src/contracts、src/server：新增 DTO、流式上传／下载路由、阶段状态及配置；保持普通 JSON 请求限制与 Host／Origin 检查。
- src/web：附件状态、统一文件面板、输出卡；未发送文字／文件引用及异步结果按工作区／会话归属保存。
- 执行镜像、依赖锁定清单与 README：Python／文档依赖、字体、构建、资源设置与启动检查。
- tests、浏览器用例和 scripts/probe-files.ts：隔离样本、故障与真实模型记录。

现有 .trellis/spec 描述的是已实现状态。落地后更新新增文件工具／路径契约及网页行为；不得提前把待审设计写成现有能力。

## 3. 验证方式

本期将新增的容器集成测试与真实探针入口须在实现中提供，并明确环境不可用是“未验证”，不能作为测试通过或静默跳过。

现有基础命令保持：

```bash
npm --prefix experiments/harness-lab run typecheck
npm --prefix experiments/harness-lab run lint
npm --prefix experiments/harness-lab test
npm --prefix experiments/harness-lab run test:e2e
npm --prefix experiments/harness-lab run build
```

新增测试优先验证真实风险：附件漏发／串席位、目录越界、进程遗留、停止误伤其他会话、上传同名覆盖、移除引用误删文件、旧下载变化、重启重放、命令失败误报成功。同工作区多会话应能并行，不以同文件修改绝不覆盖作为本期验收条件。不为低影响文案变动增加镜像实现的测试。

真实验收复用用户已配置的 API；不读取或展示密钥，不恢复早期 8 次工具／120 秒整轮限制。模型调用费用按现有授权与配置执行，需要额外模型能力或服务器接入时再说明。

## 4. 实施前核对与回退

- 按已确定的同目录并行方式实施方案，不增加工作区队列、同文件冲突保护或 worktree 前置任务；用户已批准按此范围开工。
- 核验 Docker daemon、可用磁盘与镜像构建条件；可使用用户提供的 Ubuntu 服务器。实施时再核对地址、SSH 端口和用户名，通过本地 SSH 配置登录，不在文档／Git 保存凭证。
- 使用服务器验证时，优先同机部署应用服务、持久目录和执行容器，并通过本地转发访问；本期不开放公网多用户服务，也不建设远程执行调度平台。
- 停止服务后备份完整 LAB_DATA_DIR；容器测试使用独立目录，不能处理真实用户文件作破坏性验收。
- 核对新能力开关和运行环境；失败时禁用新增执行能力，保留已有聊天和文件查询。
- 回退使用备份和匹配代码，不删除已上传／生成文件，不自动重放未完成请求，不提交 .env.local 或运行数据。
