# W01-5 审阅入口：Web 通用文件作业

日期：2026-09-18。状态：**已实现并通过 E01～E15 组合验收**。

## 主要设计选择

- **工作区归属**：任务 × 席位；同工作区会话共享文件、各自保留聊天，不同席位／任务目录隔离。文件不随人员交接迁移；本期只做固定测试席位绑定。
- **作业对象**：真实普通文件，包含上传文件、脚本、数据、中间产物和交付文件；不限定 Markdown。
- **Pi 复用**：沿用公开文件／命令工具与既有循环、压缩、会话；只适配 Web 所需的访问范围和运行环境。
- **上传**：两个入口都直接加入本工作区的普通可写目录，完成后即可使用；同名自动生成不重名名称，移除附件引用不删除文件；不强制只读原件。
- **文件交付**：统一文件面板展示当前文件；对话下载卡保存当时内容的副本，无成果状态或版本管理界面。
- **最小沙盒**：本期落地请求级 Linux 容器，预装文件处理依赖、默认关闭执行网络；只挂载本席位获准目录。Pi、模型 API 调用与密钥留在应用服务端；销毁容器保留工作文件。
- **服务器**：可在用户的 Ubuntu 服务器验证，实施时再核对接入条件；不在文档或 Git 保存凭证，不引入公网多用户部署。
- **上下文**：发送消息只引用普通工作文件，Agent 按需读取；上传不是全文注入，不自动成为 AGENTS.md。文件可修改，历史附件不承诺保留上传时原件。
- **多会话并行**：参照 Codex Local 的同目录工作方式，同工作区的不同会话允许并行，不增加整轮排队；同会话仍最多一个活动请求。共享文件可能发生修改冲突，专门保护与合并后置。
- **网页交互**：切会话保留未发送的文字和附件引用；上传不打断输入，保留蓝点与流式回复，失败可重试。“输入草稿”不指成果状态。
- **后置**：成果上报／审批／业务状态机、完整 Run、Git worktree／自动合并、文件版本库、跨会话聊天检索和公网多用户部署。
