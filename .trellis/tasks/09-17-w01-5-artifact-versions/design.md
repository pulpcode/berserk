# W01-5 设计：Web 通用文件作业

日期：2026-09-18。状态：**已实现并通过 E01～E15 组合验收**。范围见 [PRD](prd.md)，依据见 [工程研究](research/implementation-basis.md) 和 [竞品交互](research/upload-ux.md)。

## 1. 作业方式

用户通过网页提供文件和目标。主 Agent 使用 Pi 工具读取、编写、执行、检查和修订，脚本及中间文件可以作为后续工作的输入。用户可以浏览项目文件、下载交付文件，并继续通过对话修改。

例如：上传数据.csv → 编写 analyze.py → 执行 Python → 得到统计.json 和趋势.png → 编制方案.md → 根据用户反馈重算、修改并再次提供下载。没有预设的文稿模板或固定处理流水线。

本期文件就是实际文件，不要求先登记成业务成果。不建立成果状态机、Markdown 版本库或上报工具；“满意”“下载”不触发提交。未来的业务提交可以选取确定的文件内容另行设计，不影响本期处理方式。

## 2. 任务、席位、会话与文件

- 页面中的“项目”对应任务范围；工作区由“任务 × 席位”确定。Workspace 增加 taskSpaceId、seatId 绑定，同一组合对应一个持久工作目录，workspaceId 继续由服务端生成。
- Session 仍固定绑定 workspaceId。同任务同席位的会话共享文件，聊天历史分别保存；不同任务或席位的文件目录隔离，不开放跨会话聊天检索。
- 文件跟随席位，不绑定个人账号；人员交接不新建或清空目录。实际人员授权和交接流程后置，本期使用服务端固定测试席位，不允许浏览器或模型提交 seatId 来改变当前身份。
- 工作目录在服务端管理，浏览器通过上传与下载交换文件。本期不接受任意宿主目录路径，也不把用户电脑的文件路径当成服务器路径。
- 上传完成即成为工作目录中的普通可写文件；Agent 可原地修改，也可按任务另存副本。上传文件、脚本、中间数据和交付文件遵循同一套文件读写规则，不强制只读原件、扩展名或业务目录结构。
- 通用文件区与现有 AGENTS.md、固定资料、Skill、Pi 会话和密钥存储分开。原有指令编辑仍经过 instructions_update，下一请求加载。
- 上传的 AGENTS.md／CLAUDE.md 只是输入文件，不自动成为指令；继续禁用未经配置的扩展、Skill 和上下文文件自动发现。

项目列表、会话查询和文件访问都由服务端按当前测试席位解析工作区；同一项目下其他席位的目录不因同属任务而默认可读。通用只读指令仍按既有显式配置加载，工作区 AGENTS.md 与资源按各自 workspaceId 选择；跨席位共享文件和成果交接以后通过明确接口设计，不挂载整个任务目录。本期不增加业务席位管理界面。

建议存储结构如下；workspaceId、uploadId、downloadId 和 requestId 由宿主绑定／生成：

```text
LAB_DATA_DIR/
  sessions/                              现有 Pi 原生历史
  workspaces/<workspaceId>/
    AGENTS.md                            现有受控指令
    files/                               本任务、本席位的普通工作文件，含上传文件
  file-storage/<workspaceId>/
    staging/<uploadId>/                   传输与落盘临时区，不暴露给 Agent
    uploads/                             上传记录及实际工作文件路径，不另存只读原件
    downloads/<downloadId>/               对话交付时的固定文件副本
    executions/<requestId>/               命令日志与执行环境关联
```

元数据与实际字节分别保存。宿主元数据带 schemaVersion、任务／席位／工作区归属、名称、大小和 hash；正文不存 SQLite。上传完整落盘后才进入普通文件目录，记录完成后返回成功；若文件已落盘但记录未完成，核对已有文件，不盲目重新上传。上传记录中的 hash 表示上传时的内容，普通文件后续可改变，不将其当成永久版本锁。

## 3. Pi 与执行环境的职责

| 部分 | 实现职责 |
| --- | --- |
| Pi 0.85.1 | AgentSession、模型—工具循环、read／edit／write／bash 的公开工具定义与行为、默认压缩、重试、会话历史 |
| 项目 Pi 接入层 | 注册工具、绑定任务／席位／workspace/request、固定虚拟 cwd、主子工具范围、模型输入附件清单、取消和文件事件 |
| 文件与执行服务 | 隔离运行环境、真实字节、上传／下载、文件路径范围和请求级进程生命周期，不依赖 Pi 类型 |
| Web | 附件输入、项目文件浏览、执行反馈、预览／下载及多轮反馈，不推断模型是否已经成功读写 |

主 Agent 注册公开的 createReadToolDefinition、createEditToolDefinition、createWriteToolDefinition、createBashToolDefinition，通过各自 operations 接到执行环境。只读 ls/find 使用公开工厂与受控 operations，主／子 Agent 均可按角色使用；grep 先由主 Agent 通过容器内命令完成。保留现有资源与 subagent 工具；无需修改 Pi 包或重写循环。继续关闭默认宿主工具，只启用已完成路由的定义，不能把仍在宿主 spawn 程序的工具误当成已经隔离。

工具上下文 cwd 固定为虚拟 `/workspace`，与 AgentSession 的 cwd 一致；公开工厂的 cwd 不能被旧 LAB_DATA_DIR 上下文覆盖。受控 ResourceLoader、SettingsManager、SessionManager 和模型服务仍显式传入。具体接口与源码依据见 [Pi 研究](research/pi-file-runtime.md)，虚拟 cwd 与旧会话兼容性在 P0 验证。

### 执行环境

本期建设最小可用执行沙盒，采用请求级 Linux 容器：一次用户请求的工具复用一个环境，请求结束后销毁本次容器，席位工作文件保持在持久目录。同工作区的不同会话可各自运行容器并挂载同一工作目录；容器隔离执行进程，不隔离这份共享文件的修改。工作区长期保存文件，沙盒临时执行脚本，不为每个席位保持一个常驻容器。

Pi AgentSession、模型 API 调用和 API Key 留在应用服务端；容器只执行文件与命令操作，不获得 LLM 密钥。这里的“模型调用留在服务端”不表示把 DeepSeek 等模型部署在该服务器上。Pi 的工具定义与循环继续复用，执行隔离由宿主接入层负责。

- 只挂载当前任务、当前席位的工作目录到 /workspace（可写）及其受控日志到 /logs（只读）；上传文件也在 /workspace。不挂整个任务目录、LAB_DATA_DIR、宿主 home、Docker socket 或其他席位工作区。
- 以非 root 身份运行，采用只读系统镜像、独立临时目录、删除额外 capabilities、禁止提权；进程环境使用允许列表，不继承宿主密钥。Bash 工厂设置 exposeSessionEnvironment:false，后端仍独立过滤 env，不能只关闭 PI_* 元数据就假定密钥已隔离。
- 本期执行网络默认关闭。镜像构建时预装 Python、Shell、Node、检索程序及文件处理依赖；缺包明确失败，不自动绕到宿主安装或任意联网。
- CPU、内存、进程数、文件传输限额集中配置并通过 info 返回必要能力信息。磁盘限额必须说明是硬配额还是监测阈值；不能声称普通目录挂载天然有硬配额。
- Docker 不可用或挂载／清理校验失败时拒绝文件执行，并保留文件与文字草稿；不回退到裸宿主 Shell。没有文件执行环境时，原有普通聊天能力仍可使用。

P0 先验证真实容器执行、文件持久化、停止清理与隔离范围；不建设沙盒集群、跨主机调度或容器池，也不宣称已具备生产多租户隔离。用户可提供 Ubuntu 服务器作为验证环境。实施时核对地址、SSH 端口、用户名、Docker 和磁盘条件；登录通过本地 SSH 配置完成，不将密码或私钥写入文档、对话或 Git。若使用服务器，首期优先将应用服务、持久目录与容器放在同一服务器，通过本地转发访问网页；不额外引入远程文件同步平台或公网多用户部署。

## 4. 上传与上下文

### 网页入口

输入框提供附件按钮和拖放区；项目文件面板另有“上传文件”。两个入口都上传到当前任务、当前席位的同一工作目录。沿用现有项目选择与新会话入口，页面显示文件所属工作区。

- 输入框附件绑定上传发起时的 workspaceId 和输入框，逐文件展示名称、大小、进度、失败重试及移除；切换会话／项目不会把迟到结果挂到新位置。新会话尚未创建时，绑定已选择任务对应的席位工作区。
- 选文件即开始流式传输到临时区，完整落盘后加入普通工作目录；成功后即对本工作区获准会话可用，无需等待发送消息。上传不自动触发模型请求，也不主动插入其他会话上下文。
- 有上传中或失败附件时，发送按钮说明原因；用户可完成重试或移除该项后发送。不能默默丢弃失败附件。
- 移除附件只移除本条未发送消息的引用，不清空文字或删除已落盘文件；界面明确提示“文件仍保留在工作区”。上传未完成时可取消传输并清理临时字节；完成与取消竞争时核对实际结果，已完成文件保留。刷新恢复已完成引用，未完成传输提示重新选择，不声称能恢复本地 File 对象。
- 默认保存到工作目录根；同名时由服务端生成不重名文件名，并在上传结果中显示实际名称和路径，不覆盖已有文件。保留原显示名，拒绝路径分隔符、控制字符和目录穿越。Agent 后续可通过正常工具移动、修改或删除它，上传记录不会因此变成隐藏只读副本。
- 上传只保存字节，不自动运行脚本、安装插件、解压或加载其中的指令。压缩包需要用户任务后由 Agent 在隔离环境内处理。

采用逐文件流式上传，不在聊天 JSON 中传 base64。建议初始单文件上限 100 MiB、每条消息最多 20 个附件，均为可配置传输参数，P0 用边界样本验证；不是模型上下文容量或任务能力上限。超限原样失败，不截短文件。部署容量不足时明确提示，不把容量耗尽表现为“文件已上传”。

### 接入模型

消息提交包含 text、uploadIds 及可选的工作文件引用。服务端从会话解析当前任务与席位工作区，核验上传完成状态、文件当前是否存在和路径范围，再记录输入关联并开始处理。只附文件而没有文字时提示用户填写处理目标。

本轮模型输入包含原始用户文字、附件名称和 /workspace 下的访问路径；引用的作用是告诉 Agent 本轮要处理哪些普通文件，不创建另一份模型附件存储。Agent 按需读取或用脚本解析，结果按 Pi 正常工具结果参与上下文和压缩；用户聊天原文保持不变，不把所有文件正文拼成系统指令。文件实际字节不随压缩删除。

发送消息不是文件生效或发布的边界。文件引用按路径使用执行前核验的当前内容，不是不可变版本；路径缺失时提示重新选择，不按同名搜索替代，也不承诺自动追踪任意脚本的移动或重建。取消回复或消息记录失败均保留已上传文件，不自动再次发送消息。

## 5. 格式与处理能力

上传／保存按字节处理，不用文稿类型白名单限制通用工作文件；文件能被存储与能被解释是两回事。

| 文件类型 | 本期处理与验收范围 | 网页查看 |
| --- | --- | --- |
| UTF-8 文本、Markdown、代码、CSV、JSON | Pi 读取／编辑；脚本可解析、计算、重写；大文本按需分段 | 文本／代码或安全 Markdown；大文件显示预览范围并可下载全文 |
| XLSX、DOCX | 执行环境中的 openpyxl、python-docx 等完成基础读取／生成 | 名称、大小与下载；首期不做完整 Office 渲染 |
| 含文本 PDF | pypdf 等提取文本；reportlab 等生成基础 PDF | 首期下载；不承诺扫描件 OCR 或原版式还原 |
| PNG／JPEG | Pillow／matplotlib 等进行处理及生成图表 | 受控图片预览；是否可交给模型看图取决于已配置模型能力 |
| 其他二进制、压缩包 | 原样保存／下载；是否可处理由环境工具决定，无法处理明确说明 | 不支持预览时提供下载，不伪装成乱码文本 |

镜像固定依赖版本并提供中文字体，至少用实际样本验证以上基础能力。Pi read 不是 Office／PDF 解析器；当前文本模型不能因为上传了图片就被宣称具备视觉能力。图像工具结果在模型不支持时返回明确说明，不把 base64 伪装成文字发送。

沿用 Pi 的工具结果截断与分段读取，不把完整二进制塞进上下文。原生 read 可能先读完整文件再截断，因此文件适配层必须按资源规模选择可处理路径，超大输入引导脚本按块读取，避免以“返回内容有限”冒充“内存占用有限”。

## 6. 文件交付与前端

项目顶部增加“文件”入口，桌面右侧面板统一展示当前席位工作区文件，不再分为“上传文件”和“工作文件”。提供文件夹导航、名称搜索、刷新、预览、引用到输入框及下载；默认不展开整棵目录，不自动打开每个中间文件。修改继续通过对话，本期不做浏览器编辑器。

主 Agent 增加一个薄的 `file_output({path})` 工具，用于把已经存在的普通文件提供给用户：

1. 宿主检查当前任务／席位工作区、可读根、实际文件类型及大小；拒绝不存在文件、目录、符号链接和越界路径。
2. 从受控文件句柄复制实际字节到下载临时文件，完成后保存 hash 与归属并发布 downloadId；复制／记录失败不返回成功卡。
3. 以 sessionId、requestId、toolCallId 关联下载记录，并通过原生 custom entry／SSE 返回“可下载文件”。相同调用重复核对返回已有结果，不重复执行脚本。
4. 文件名、大小和下载按钮来自服务端确认。模型仅声称“已生成”或编造本地链接不能形成成功交付卡。

下载副本只固定一次交付的内容，不维护“草稿 v1/v2”或审批状态。之后修改工作文件不会改变旧卡；再次交付产生新卡。用户仍可直接从项目面板下载当前文件，无需调用 file_output；此时标明是当前内容，不误称历史版本。

预览与下载由文件服务提供受控 ID／路径，不能直接静态托管数据目录。Markdown 关闭原始 HTML，不加载任意外部资源；HTML／SVG 作为源码或下载，不在应用同源执行。图片验证类型与解码规模，其他二进制使用 attachment 和 nosniff。

当前工作文件的预览／下载读取当前内容，不因其他会话执行而锁住工作区。读取或复制失败时明确提示；若其他会话同时修改源文件，本期不保证取得一致快照。已发布的下载副本保持固定，不能把这项保证扩大成源文件并发修改保护。所有读取仍在隔离文件后端内打开实际普通文件，校验路径段、符号链接与最终范围；不能只先 realpath 再在宿主无保护地打开可能被替换的路径。

窄屏使用全屏文件面板，关闭后恢复聊天位置；上传与文件刷新不抢焦点、不触发未读蓝点。拖放有键盘替代，按钮有可访问名称，进度与错误可读。对话仅显示必要的执行反馈和交付卡，不恢复“查看本轮资料”或展示内部 hash／原始 JSON。

## 7. 并发、停止与重启

同一工作区的不同会话允许并行，直接操作同一份当前文件；不同任务／席位工作区也可并行。这是本期采用的 Codex 同目录工作方式，不引入工作区级请求队列、独占执行权或等待状态。

- 同会话仍最多一个活动请求，沿用已有活动标记；每次请求分别加载当前获准指令、绑定工具范围与执行容器，事件和结果按 sessionId／requestId 归属。
- 子 Agent 沿用其所属请求的执行范围及停止信号，只有只读文件工具；不共享其他会话聊天，也不阻塞其他会话工作。
- 上传独立接收临时字节，完整文件通过不覆盖已有目标的落盘操作加入工作目录；若目标已存在则另选名称，不采用“先检查、再无条件覆盖”。上传不等待其他会话整轮结束，也不触发模型请求。
- 重启后不重放模型请求或命令，保留已记录的请求及文件，提示用户核对后继续。
- 重启时清理未完成传输的临时字节；已落盘但完成记录缺失的上传先核对再恢复记录或报告异常，不删除工作文件，也不自动重新传输。
- 停止传播到本次 Pi 请求、子 Agent 与命令执行器，终止本次命令及后代进程；未完成清理前该会话保持“正在停止”，收敛后才能在同会话开始下一请求。按 requestId 清理专属容器，不停止同工作区的其他会话。
- 不允许后台命令脱离管理。命令退出时收敛其遗留子进程，请求结束时仅销毁自己的容器；启动服务时先核对并清理本数据实例的残留执行环境，再开放文件执行。
- write、edit、脚本已经产生的效果不随取消回滚；脚本可能留下半成品，失败时明确说明。原生工具不是通用文件事务，不承诺任意写入原子化、全任务撤销或外部程序并发安全。

保留 Pi 原生文件工具的内部行为及已有 AGENTS.md 受控编辑校验，不扩展为全工作区互斥。多个会话同时修改同一文件可能冲突或覆盖；本期不建设跨会话冲突检测、自动合并或独立工作副本，后续遇到实际需求再设计。

不新增默认整轮工具次数／模型尝试次数上限；沿用已有独立模型超时、可选总时限和 Pi bash 的单命令 timeout 参数。宿主如显式配置工具上限，应说明实际生效值，同一次请求不能借执行阶段切换清零。

## 8. 最小接口与记录

所有新增 DTO 由 src/contracts 定义；旧会话的附件与下载字段可缺省。前端不解析 Pi entries。工作区索引与摘要增加 taskSpaceId、seatId，查询与创建由服务端绑定当前测试席位。workspaceId、请求、容器和访问根均由宿主校验，模型不得指定其他任务／席位或容器。

| 接口／事件 | 作用 |
| --- | --- |
| POST /api/workspaces/:id/uploads | 创建上传记录，核验当前席位与工作区、名称／声明大小；入口只影响网页引用，不影响存储归属；返回 uploadId |
| PUT /api/workspaces/:id/uploads/:uploadId/content | 单文件流式传输；完整文件以不覆盖方式落入工作目录，返回实际名称／相对路径；超限／取消清理尚未落盘的临时字节 |
| GET /api/workspaces/:id/uploads/:uploadId | 核对实际上传状态；失败重试前先查，已成功不重复上传 |
| DELETE /api/workspaces/:id/uploads/:uploadId | 取消未完成上传；若已落盘，返回已完成状态并保留文件，不充当文件删除入口 |
| GET /api/workspaces/:id/files | 统一列当前席位工作区普通文件，目录范围与分页由服务端校验 |
| GET /api/workspaces/:id/files/content | 受控预览／下载当前普通文件，不接受任意宿主绝对路径 |
| POST /api/sessions/:id/messages | 兼容原 text，增加 uploadIds／fileRefs；仍采用 POST SSE，不隐式重发 |
| GET /api/workspaces/:id/downloads/:downloadId | 读取已发布的下载副本，支持刷新后访问 |
| files.output、既有工具／请求事件 | 返回确切归属、下载元数据及执行反馈；不输出宿主路径或密钥 |

上传状态只表示传输、保存、完成、取消或失败，与成果业务状态无关。“输入草稿”只指尚未发送的文字和文件引用，不是文稿状态机。上传 ID 固定绑定 workspaceId 和完成时的实际路径；声明大小不可信，服务端在流中计量。完成后重试须核对已有记录，不重复写文件；本期不做断点续传，失败可重新上传完整文件。

新增输入／交付 custom entries 使用版本化类型（拟 berserk.files-input.v1、berserk.files-output.v1），保存 requestId、toolCallId（交付）、工作区、受控引用、文件名、大小、hash；正文仍在文件存储。输入引用表示当时所用路径与内容标识，不承诺原始字节永久留存；文件变化时提示已变化／不可用，不把当前文件冒充当时原件。交付引用指向固定下载副本。历史解码拒绝错工作区的引用。文件落盘与 Pi JSONL 不宣称跨文件事务；会话记录失败不删除已存在文件，停止并提示核对，不重跑命令。

Bash 全量日志继续复用 Pi 行为，但公开工具把溢出日志写在宿主临时目录：接入层须将其归档到 executions 并映射成 /logs/<requestId>/ 的只读引用。映射覆盖流式 partialResult、成功结果和错误文本，包括非零退出、取消及超时；必须在 Pi 保存工具结果前替换宿主路径。归档日志在新请求中仍可按旧引用读取，销毁容器不删除日志。日志不是交付成果；映射失败明确“全文日志不可用”，不返回宿主路径。大输出与失败路径必须实际验证。

## 9. 兼容、实施条件与后续

保留现有原生历史、模型设置、AGENTS.md 与固定资料。迁移时保留现有 workspaceId、Session 归属和目录，为每个旧工作区建立对应任务范围并绑定默认测试席位；不重写 Pi JSONL，不合并不同旧工作区。其他席位的工作区显式新建，不复制原会话或指令。归属索引带版本，缺失／冲突明确报错，不静默重新归属。

新增目录采用显式初始化与版本检查，不修改或导入用户电脑的任意项目目录。首次实施前停止服务并备份 LAB_DATA_DIR；回退使用匹配的备份与代码，不自动删除已上传或生成的文件。

P0 先验证 Pi operations、虚拟 cwd、执行环境、日志与停止，再开发完整 Web 闭环。P0 不通过时保留原有应用并报告缺口，不以裸宿主执行或假下载卡替代验收。

完整 Run、业务上报与成果状态、多人权限、文件版本／撤销、并行工作副本及跨内核迁移以后分别设计；本期不添加占位审批按钮、状态表或调度接口。具体实施与验收见 [implement.md](implement.md)、[acceptance.md](acceptance.md)。
