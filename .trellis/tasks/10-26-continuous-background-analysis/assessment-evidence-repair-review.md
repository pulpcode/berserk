# 研判依据与条件接续修复方案（待审阅）

日期：2026-10-29。**用户已批准提交方案并实施；先做共享车辆一对回归，通过后才展开。**

当前实现及完整测评已提交：`1e12a94`。本轮以此为修复前基线；更早的 `2321f72` 只作历史参考。

## 1. 本轮要解决什么

让 Agent 根据实际证据判断：哪些条件成立、哪些只是可能性、哪些旧判断应纠正或撤回。避免把检查建议变成“必须满足才能执行”的新限制。

现有工具已经按任务保存条件、前后状态、来源／推断、引文和历史，也能检查编号、引用及记录完整性。**缺口主要在证据解释与旧条件复核，不是缺少数据库。**

共享车辆组旧版24/36、新版15/36；这是整份研判严格评分，不能直接当成条件管理准确率，也不能仅凭这组结果确定某项改动是唯一原因。[完整报告](assessment-quality-report.md)

## 2. 怎么改：先做三项小范围修复

| 修复 | 具体落点 | 应看到的效果 |
| --- | --- | --- |
| **不凭空增加执行限制** | 修改持续分析指引和记录工具说明：新增影响执行的条件，必须说明任务要求／业务规则／事件依据及影响关系；建议单列。仅有“没提供某资料”不能自动判受阻；确有必要条件但依据不足，仍应明确待核实。 | 已确认车辆可用时，不因模型自行提出核载证明就降为不可执行；任务确实要求证明时，缺失也不能被忽略。 |
| **计算前先辨明字段含义** | 在现有计算工具说明及分析指引中明确：计划时间、截止时间和资源占用时间不能互换；算出区间重叠，只证明输入区间重叠。模型需从原文核对字段含义，缺实际占用／周转资料时只说明方案尚不能确定。 | 不再用“出发—截止”窗口断言借用必然冲突；实际占用时段明确冲突时，仍能判冲突。人员、设备同样适用。 |
| **旧条件逐项复核，不机械照抄** | 复用候选工具返回的固定基准、来源索引及原文读取工具。修改接续指引：对旧条件核对依据、适用对象／时段、新消息是否替代依据，再选择保留、更新、纠正或撤回；在现有理由和引用字段说明处理依据。 | 假设调配不变成历史事实；上午限制取消后不继续套用；没有新信息且依据仍成立的条件继续保留。 |

第一版不增加必填字段、数据库表或模型调用阶段。重点重写现有指引中“必要条件未核验”的边界，避免模型把自己提出的所有疑问都升级为必要条件；原有“旧条件不得遗漏”明确允许纠正和撤回，不代表必须继续认可。

这些改动改善模型使用证据的方式，**不是程序已经能自动证明每项业务判断正确**。不能只改措辞后宣称修复完成，必须由下述对照验证。

## 3. 一轮分析实际怎样接续

1. 读取本轮输入、任务当前版本及上次已发布条件；上一轮判断作为待复核观点。
2. 新信息涉及旧条件，或准备新增阻碍／宣布解除时，核查原始依据；300字预览不足就分页读取，不以旧摘要代替原文。
3. 分清已确认事实、条件性方案和普通建议；需要计算时核对字段含义、适用对象及时间，再用已有工具计算。
4. 通过同一个记录工具提交完整条件。发生变化的条件写明依据；确有纠错或失效才纠正／撤回，不因本轮未重复提及就删除。
5. 沿用现有校验、保存、统一展示和重要提醒。程序仍只对可确定的记录错误反馈；不凭关键词拦截业务结论，也不每轮强制另找模型审核。

例如：C的重量一直为2.5吨，原本就低于3吨限重。限重时段改到下午后，应表达“上午不适用此限制，C原先也未因重量受阻”，不能写成“C道路障碍解除”。若此前错误保存为受阻，应明确纠正旧判断。

## 4. 怎么测，避免只适配车辆样本

**先冻结输入和独立预期，预期不进入 Agent 上下文。** 增加双向用例，防止靠一律回答“未知”或一律撤回条件提高得分：

| 用例 | 必须验证 |
| --- | --- |
| 仅知道任务截止／已知真实占用时段 | 前者不能断言必冲突；后者确实重叠且独占时能发现冲突，不重叠且无其他限制时不能虚报。 |
| 普通检查建议／任务明确的必备要求 | 前者不升级为阻碍；后者缺失时正确保留障碍或待核实判断。 |
| 建议调配／正式确认调配 | 前者不改变实际分配；后者重新评估所有受影响任务。 |
| 规则改时段／无关消息／发现历史误判 | 分别验证适用范围更新、有效条件保留、明确纠错；不能把本来未受限说成风险解除。 |
| 剩余时间变短，但无准备耗时／确有准备耗时与未就绪事实 | 前者不凭空新增“来不及”；后者能够识别真实时间不足。 |

获准实施后的顺序：先完成受影响程序检查，再以同一方舟实际模型、配置和冻结输入做新旧对照。先跑共享车辆修复前后各1次，每次12轮，共24轮；仍有同类错误即停止展开并复盘。初步通过后补共享车辆各2次验证稳定性；另外设计人员、设备两组独立短序列，各1对。以上过关后，原文本、空间、时间重量、来源冲突各1对回归。合计最多18次完整序列运行；任何阶段暴露同类问题先复盘，不追加重跑挑选最好结果。

分别报告：记录成功率、每项条件处理是否正确、整份研判正确率、提醒误报／漏报、请求量／耗时／token。单独统计保留、更新、纠正、撤回，避免用发布成功代替判断准确。

建议验收：定向双向用例均正确；共享组3次中不再重复出现本轮所列无据限制、假设事实化、过期限制及倒计时误报，且汇总严格正确率优于本轮基线；回归不得以新增同类错误或漏掉真实风险换取改善。边界争议和全部失败保留。未达到就报告未通过，重新审阅下一步，不自行扩展系统。

## 5. 本轮边界与风险

- 复用Pi原生循环、现有工具／存储／权限／两次补做；不建通用规则引擎、车辆专用检查器、全局事实库或额外审核Agent，不改数据库及界面契约。
- 真实业务规定和字段说明只使用已有获准资料查询；明确缺失，不替业务方编造。本轮不新增规则管理产品。
- 模型仍可能误读证据。若改进指引不足，须带失败证据另行提出最小结构化补充，不能在本轮悄悄加字段或语义拦截器。
- 每轮完整条件列表的增长成本仍存在；本轮记录用量，不承诺解决长期膨胀。现实6—8小时、压缩、生产地图及业务调配执行不在此次验收内。
