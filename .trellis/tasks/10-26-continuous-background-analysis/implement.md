## P4 验证与质量门

先运行受影响测试，之后按项目规范完成一次全量检查；结果未变化不重复跑相同检查。

```sh
cd experiments/harness-lab
npm run typecheck
npm run lint
npm test -- --maxWorkers=2
npm run build
npm run test:e2e -- --workers=2
```

新增行为测试须覆盖：批次输入不丢失、持续高频不饿死、任务修订自动触发且明确目标不可漏评、退役代次不接新输入、任务与未归属重要性无冲突、跨来源权限、静默结果可读而无待办、错版本不发布、缺记录不能当无变化、故障与SIGKILL边界、通知幂等及历史引用。使用确定性模型测试真实SQLite／Pi原生记录，不能只测最后一句文案。

已获准运行真实模型隔离验证。首轮冻结序列与语义判据见 [验证计划](research/validation-plan.md)，其余变体按实际结果分别报告：道路封闭→车辆减少→道路恢复、条件互换、旧通知晚到、未知对象、资料不可用、无任务／多任务、无实质变化、旧推测纠错。不得把预期答案写入Profile、资料或mock接口；保存全部失败、模型用量、调用与任务版本。

语义验收逐场景评审：事实是否有依据、变化比较是否正确、风险是否该保留／解除、重要性是否合理、资料不足是否诚实。机制与语义分别报告；发布阻断的系统性误判需回到方案，不以额外强制模型修复隐藏。
