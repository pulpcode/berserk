# 漏记录补做：实施与复测结论

2026-10-27。方案已提交：`4fd77cb`（文档：提交漏记录补做方案与多任务实测证据）。实现位于 `codex/continuous-background-analysis` 独立 worktree；未替换生产服务。

**结论：漏记录自动补做已实现，定向测试通过。真实模型完成全部12个分析批次，但多轮研判出现偏移，语义验收未通过。执行完整与判断正确是两项结果。**

## 1. 实现效果

程序在正常答复结束时检查：本轮是否有有效变化记录、是否有匹配的真实成功回执、必要重评任务是否完整。缺失时，向同一Pi会话追加明确的补做提示，最多2次；补做与原分析共用请求、超时预算和取消控制。

- 正常完成不增加模型调用；不由程序代写研判。
- 中间答复和补做提示全部保留，仅最终有效结果更新当前研判、按需通知。
- 仍失败则保留旧研判和待处理输入并暂停。取消、超时、权限失效、历史损坏不绕过；任务版本过期沿用自动重评。
- 无新增数据库表、第二套Agent循环、前端交互或业务写入权限。

技术落点：`continuous-completion.ts`使用Pi公开扩展的`agent_end`与`sendUserMessage(..., {deliverAs:'followUp'})`；Pi在原`prompt()`返回前处理接续。宿主通过`checkAnalysisCompletion`提供只读核验，复用发布阶段的版本/必要任务检查。正常发布阶段仍执行完整校验。

## 4. 逐轮判断核验

由本轮主代理依据运行前冻结的[核验标准](research/multi-task-sample.md)，检查最终正文和持久化变化记录；不是人工独立盲评，也不以关键词命中代替正确性判断。以下“核心符合”仅指该轮主要约束，不代表全文无误。

| 轮次 | 核验结果 |
|---|---|
| R0 初始状态 | **不符合。** 三个任务已存在，模型用受限关键词及未提供的区域过滤查询无结果，便称“无活动公共任务”，未建立任务基线。R1才找到任务；不能解释成系统当时没有任务。 |
| R1 东桥封闭 | 核心符合：A受阻、B次日不受本时段影响、C走西桥。但建议中出现“推迟至12:00后，并确认仍能10:00前到达”的矛盾措辞。 |

| R7 旧封路消息晚到 | **不符合。** 识别出旧v1不能覆盖v2，却仍将它升级为新的重要不确定性，提醒A；之后持续把桥况当成未解冲突。 |

**主要风险是“推测逐轮固化”**：R7的旧消息疑点、R9的假设调车进入当前研判后，后续反复引用，逐渐被写成事实或已存在的障碍。限定主结论、保留缺口虽有作用，但也出现过度质疑明确信息、过度提醒的问题。本次不通过增加补做提示修饰这些语义错误；它们是下一步需要单独治理和验证的能力缺口。
