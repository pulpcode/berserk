# 第一轮：让资源统计与结果校验一致

状态：实施依据已获认可，已补入T13、T14审阅边界；尚未实施。依赖代码基线 `99b2caa`。只做产品修复和离线验证，模型调用为0。

## 目标

合法查询应正常返回已知结果与缺口，不因产品内部规则冲突中断；多份汇总可能重叠时，不给没有依据的精确合计。

## 改什么

### 1. 统一实际进入统计的集合

查询保留的全部记录，不一定都参与当前统计。例如有1条关系未确认的资源，但“本任务已关联资源”统计集合为空。

生成结果和校验结果都使用同一份明确的筛选规则，并分别表达：原始记录、符合条件的条目、已确认实体数、不能确认的总量。不要用原始集合非空来推导筛选后总量为零。

- 明确范围、完整覆盖、确实无记录：可以报告该范围0条。
- 关系覆盖不完整、筛选后为空：已知命中0条，但完整任务数量未知。
- 有部分可确认记录：报告已知部分，保留覆盖缺口，不把它叫全量。
- `query`、`summarize`、结果读取和空间续用必须遵守相同规则。保留严格校验，不以删除校验、吞错误或补默认0解决问题。

### 2. 按成员证据处理汇总重叠

“每份清单完整”只说明知道各自成员，不说明两份互不重叠。

先判断是否可比较：可靠身份命名空间、类别、单位、数量含义、统计范围、有效时间及条件均须相容。`available`等数量不自动等于成员总数；完整成员列表也不能证明哪些成员可用。

在数量确指成员实体数、成员列表完整且与声明数量一致时，允许按同一命名空间内的成员并集计数。任何条件不足，就保留各份声明数量，合计未知，并说明缺的是成员、范围、状态还是时间依据。跨来源同名ID不能直接合并。

`knownValue`也不能把疑似重叠的声明简单累加后包装成去重下界。能证明的独立成员贡献可单列；不能证明时保留未知。不要为了输出精确数字擅自改变既有字段含义。

### 3. 保留历史结果

当前校验器会重算数量；直接替换算法可能让旧合法结果失效。实施前检查旧结果读取路径：若新算法改变持久结果的接受条件，新增结果版本和对应校验分支，旧版按冻结语义读取，新查询采用新规则。复用现有原生历史和版本机制，不新增结果库。

旧A06-2的无效结果仍作为失败证据保存，不自动改成合法，也不静默修写旧回执。旧有问题的统计不能当作新规则正确结果，用户要求重算时生成新结果并注明版本差异。

## 实施顺序与完成标准

1. 核对最新代码，保留失败复现，确认汇总问题是否能从真实来源契约进入。
2. 明确统计集合与历史兼容策略，再修改生成、统计和校验。
3. 跑上表独立预期、相关既有回归、类型检查和Lint；不扩大到付费测试。
4. 落盘修复证据和仍存限制，单独提交供审阅；通过后才进入第二轮。

完成要求：T01—T14全部满足，合法结果不被自身拒绝，无无据精确合计；旧固定引用、权限、数据不被改写。若需更改业务含义或扩大到新的跨系统身份服务，停在设计审阅，不自行扩建。

独立验收继续检查本轮工具缺陷是否再现，采用专门门槛，不能靠其他任务通过抵消工具回归；详见[验收标准](03-acceptance.md#验收标准)。
