# 实施与检查清单

本文件描述审阅后的工作，不表示已经开始。

1. 保存用户批准的方案与预算，记录基线、题目/答案、模型与依赖哈希。另建本轮运行目录，旧测评文件只读。
2. 实现单一段落适配：A 不变；B 精确移除自动草稿段。保留原生历史和绑定，记录实际外发差异。拒绝无法定位的格式漂移。
3. 接入 [schedule.json](schedule.json)，每槽独立环境。两组均沿用正常 Skill 发现、真实查询、真实计算和由执行 Agent 按语义判断的澄清接续，不导入上轮对话。
4. 完成下列离线检查，再由独立 Agent 复核。受控 provider 不访问模型，不计业务正确率。
5. 冻结所有直接/间接执行依赖及最高预算。实际发起模型调用前核对配置、已知额度状况和启动条件，不打印 Key。
6. 执行前4项流程检查；流程有效后继续其余28项。正常答错不触发重跑或中止；协议/平台失败停止留档。
7. 根会话处理每次真实结束或追问，独立 Agent 复核完整公开轨迹；评分者不看到分组映射，先按统一规则打分，再揭示分组分析。若从轨迹可推测组别，报告盲化限制，不称双盲或人工标注。
8. 交付配对和重复结果、用量、冻结核验、数据前后状态；停止，不自动修产品或运行保留题。

## 必需的离线检查

| 检查 | 要排除的问题 |
|---|---|
| 完整初始请求差异 | 除声明的自动段落及机械身份映射外，系统指令、用户文字、工具 schema、Skill 目录/正文、参数均相同 |
| 混合 composer 输入 | 自动段落与显式引用/Skill 同时存在时，只移除前者；普通正文、工具结果中相同文字不误删 |
| 原生历史与外发历史 | 原生历史正常重开；B 的后续请求无自动段落重新漏入，真实工具取得的草稿事实仍保留 |
| 无自动 ID 的真实读取 | B 经 annotation_read draft 能取到准确草稿；G01/G02 明确题能完成真实计算，不依赖模型提前知道 ID |
| 两类澄清 | 普通文本、AskUser 的单项/双项问题按既有固定回复继续；未知问题不猜答，局部完成后的选做邀请不补救 |
| 业务状态与隔离 | 每槽数据独立，完整草稿版本/发布/采用/来源快照可比，旧区域/道路无残留 |
| 预算与故障 | 精确上限响应保留；下一请求拒绝；429、网络错误、缺用量、版本漂移无自动重试 |
| 评分与调度 | 32槽无缺重、两次组序相反；分项与strict一致，未执行不算模型失败，不沿用旧分数 |

执行已有任务级 TypeScript、scoped ESLint、相关 Node 离线测试和 diff 检查。具体命令随新运行器落地后写入执行说明；本次不创建可运行代码、不运行这些测试。

如果必须修改产品权限、原生历史或新增提示才能实现 B，应停止并报告偏离，不能悄悄扩大“只移除自动段落”的实验范围。
