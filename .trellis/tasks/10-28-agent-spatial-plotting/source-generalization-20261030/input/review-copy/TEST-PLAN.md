# 下一轮测试用例：来源选择的泛化验证

**版本 1.0.0｜2026-10-30｜8 个主测＋4 个预留。**

本轮只回答一个问题：换成新的会话、对象、几何和问法，当前产品能否分别处理“用哪组候选点”和“以哪个区域为参照”，并正确完成名单、数量与解释。

本包已编制并完成离线数据校验，**未执行模型、未改 GitHub 分支**。现有 harness 需要一层 fixture/用例适配；接入步骤见 `INTEGRATION.md`。

## 一、固定条件

- 基于 `pulpcode/berserk` 分支 `codex/agent-spatial-plotting` 的提交 `925314f995f1e05f136818bcc18a6bd99c7e9614`。

## 五、判分与停止

每题分别记录：来源选择、名单/数量、主任务、过程事实、最终事实、实际业务副作用；严格通过要求主任务、事实和效果全部通过。完整规则见 `PROTOCOL.md`。

以下两类必须分开：

- 主任务错误：选错或漏掉来源、成员/数量不对、把标签当完整空间候选、按同名去重。
- 主任务完成但 strict 失败：用户未指定却说“按你指定”，或对可用性、存储状态等增加无依据说明。

冗余澄清单列；不能用“凡是不确定就问”掩盖明确题的体验问题。工具错误后成功恢复可以通过，失败调用和恢复过程必须保留。

**主测固定顺序：G01 → G07 → G04 → G05 → G02 → G08 → G03 → G06；每题一次。**业务答错继续后续固定题，协议故障则保留现场停止。本轮不因分数不满意重抽同题，也不立即解封预留题补分。

- 主测全部通过：结束此轮来源问题诊断，推进正常产品配置同步与验收；不宣称整体 90% 达标。
- 同一来源机制复现：针对具体轨迹形成一个最小修改假设，冻结改动后用预留题验证。
- 只有事实说明错误：处理说明与证据一致性，不能自动归因空间算法或整个模型能力。
- 协议未完成：报告已执行与未执行数量、原因，保留原始分母；不把未完成算通过。

这 8 题是小样本、人工构造的机制诊断集。它能暴露错误类型，不能估计真实流量上的整体准确率，也不能独立区分模型固有能力、提示竞争与随机行为。
