## 4. 实施时需要调整的评测部分

1. **完整替换模拟场景。** 导入题包中的草稿和来源对象，更新系统目录、任务区域与时间，清除旧场景道路和区域。来源标识如需改名，保存机械映射；坐标、名称、对象关系不改。不能把标准答案中的命中 ID 偷传给模型。
2. **保留真实筛选难点。** 来源查询包含区域、资源和可能的道路。Agent 应通过实际查询识别资源点；草稿资源层里的线也不能计作资源点。不能由评测适配器预先替模型筛出正确候选。尤其 G04，不得自动用区域登记标签缩小“全部资源点”。
3. **修好追问接续。** 区分“问资源来源”和“问边界来源”，只回答实际问到的部分。复用原生交互的文本答复能力；不因选项漏了交叉组合就替用户改选项。规则见下节。
4. **冻结评分并完整留证。** 保留全过程公开说明、工具实参/回执和前后业务状态。把主任务正确与解释正确分开评分；不再仅凭关键词判断澄清或完成。

不使用旧评测脚本额外写入的 `businessContext`。不直接沿用旧脚本归档的旧提交加补丁，运行内容必须与本轮冻结的产品基线一致。实现评测适配后，先做无模型的后端读写初始化、查询、空间计算和交互回放检查。

## 5. Agent 追问时怎么回答

答案事先固定，具体原句在逐题清单中；它们是**评测器持有的用户偏好**，模型没有追问之前不能假定已得到这些指令。

- 只问资源来源，只回答资源来源；只问区域边界，只回答区域边界。未说明的另一项仍需澄清或分别计算。
- 两项一起问，回复两项固定选择。两项都不明确、却笼统问“草稿还是来源”时，也回复两项固定选择，并记录问题没有分清两件事；不单独因此判失败。
- 用户已经说明的内容被再次询问，最多重述一次并记“多余追问”，不单凭这一点判严格失败。有效澄清最多覆盖两个未知项各一次；反复询问仍不能完成，记未完成。
- “如果需要也可以查另一来源”只是附加邀请，不补发答案来挽救遗漏。
- 普通文本追问与交互 API 分别记录。语义由复核者按冻结规则判断，不由问号或关键词直接决定。所有分支选择记录原句、所问内容、答复与依据。
- 遇到规则未覆盖的问题，不临时编回复：先核实是模型偏离任务还是题目材料缺失。前者保留未完成结果；后者记流程问题并暂停受影响执行，不混成模型失败。

若两种资源和两种边界都未确定，本轮允许“澄清后完成”或“清楚标注四种组合后完成”。这依据新题中两套不同几何；**不回头用四组合规则重判旧 T03**。

## 6. 怎样评分

| 指标 | 通过要求 |
|---|---|
| 来源与范围 | 遵守用户已说明的部分；其余经澄清确定，或完整列出相应条件结果 |
| 名单与数量 | 与实际计算一致；不能只看数量相同，不核对对象 ID；零命中也须有证据 |
| 主任务 | 上述两项均正确，完成题目要求的名单和数量 |
| 过程说明 | 查询、追问选项及中途陈述有当时证据支持 |
| 最终说明 | 不编造用户选择、查询经过、对象身份或存储状态；不把点数说成资源容量 |
| 业务状态 | 未擅自修改草稿、来源、发布或采用状态 |
| 严格通过 | 主任务、过程说明、最终说明和业务状态全部通过 |

例如模型自行选了草稿，却说“按你指定的草稿”，即使算数正确，也属于解释错误。真正来自用户题干或澄清回复的选择才可这样描述。条件句“如果按草稿计算”则允许，仍须满足所需结果完整性。

不要求唯一工具路径；修复工具报错后完成可以通过。公开误述后来更正，原误述仍保留并影响本轮严格分，另记恢复成功。实际执行了额外计算不等于编造，但须检查是否掩盖漏答。

Skill 记录是否读取、何时读取、正文哈希及是否遵守；读取率只是诊断指标，不作为正确率或硬性通过门槛。未读取也可能通过；读取后失败也不能只归因为加载问题。

先按隐藏模型标签复核完整公开轨迹，再结合工具与业务状态证据定分；不为评分再调用付费模型。争议保留原句及依据，未定项不硬塞进通过或失败。正式执行前冻结口径，执行后不为提高分数更改。

建议总上限：**96 次模型请求、300 万输入 token、30 万输出 token（含思考）**。这是 8 道完整任务共享的上限，不是每题固定 12 次，也不是要用完。请求输出上限沿用 32768，发起前预留本次输入和最大输出额度；可能因此在达到数字上限前停止。

每题有进展就继续到完成，不设单题 10 次请求或 10 分钟硬切断。澄清后的接续和失败请求都计预算；未知用量不能算零。仅用现有方舟 Agent Plan，不使用百炼现金接口，不自动启用超额付费。AFP 不从 token 擅自换算，记录实际可取得的套餐用量；平台限流时停下留档。

G01 和 G07 作为前两项流程观察，**计入这 8 项，不另加冒烟题**。正常业务答错、解释错误或隔离场景内越权：记失败并继续剩余题。后端串数据、追问答复串题、记录丢失、预算用尽、平台/传输中断或冻结配置漂移：停止并汇报。无新证据、无状态变化却重复相同调用时按无进展循环处理，判定依据留档；不靠总工具调用次数误停正常探索。

**不自动重试，不追加模型/题目，不自动启用保留题。** 本轮方案获批后才实施及调用模型。

## 8. 怎么解读结果、决定下一步

本轮诊断目标为 8/8 主任务通过、8/8 严格通过、业务违规 0 项；流程可用性单独验收，不把流程故障算模型错。未完成或存在争议时同时报告计划数、有效完成数、各指标分子/分母，不能删除失败提高分数。每类仅两题，报告原始“几题/几题”，不过度解释百分比。

- 多道不同题出现同一错误：优先形成针对性修改假设，例如候选筛选、边界选择、追问或解释归因；仍不声称已证明唯一根因。
- 仅个别失败：先复核轨迹，再提出重复验证或局部修改建议，不自动选择有利样本重跑。
- 全部通过：说明在这些新来源场景中可完成任务；不证明生产正确率 100%，也不等于达到总体 90% 验收。

整体 90% 门槛继续留给后续独立、代表性更充分的验收。4 道保留题只有在修改假设和候选版本冻结、另获批准后才考虑启用。若提前读过具体内容，后续就标作已知回归题，不能冒充未见题。
