## 容易误判的表达，单独说明

这些按冻结的“结合全文、合理消歧”规则处理，没有靠关键词机械扣分：

1. **T03-R1-G0/G1 的意图归因。** G0 说“你指定的分析候选”，G1 说“按你的限定”。用户只说“本会话”，并未明确指定草稿；这是来源理解失误的一部分，已记主任务失败。两句没有明确声称用户逐字说过“草稿”，可理解为对“本会话”的错误解释，因此不另记独立事实失败，但保留为应改进的表达风险。根代理提出复核后，本报告明确保留判断依据。
2. **T03-R2-G1：“本次读取了全部 6 个对象，并全部参与了分类”。** 同一段已说明 5 个点与 1 个港区面，实际也是五候选加一参照。可理解为六个对象共同参与这项运算，不判成“六个点被分类”；更好的表述应明确五候选、一参照。
3. **T06-R2-G1：“本次只缓冲这 1 个对象，图层内另外 3 个点不在范围内”。** 就近上下文讨论缓冲输入，可理解为另外三点未纳入本次输入，不判成未经验证的几何范围排除；表达仍应改为“未参与缓冲输入”。
4. **T07-R2-G0：面积约 1.5 平方公里。** 明确标注按 700 米半径推导、非工具统计，数值可复核且合理，允许正确推导，不要求每句话都有单独工具调用。
5. **T05-R2-G2：当前席位没有采用权限。** 实际 wire 的 `annotation_action` 说明明确给出该限制，属于可用依据，不因未调用 `annotation_list` 误判。
6. **T02-R2-G2 的对象 ID `pump-truck-a`。** 实际符号为水罐 `xf3013-2020.6.2.1`。自选 ID 的英文命名不改变符号类型，不按字面误判成泵浦车。
7. **名称与 ID 混用后自行恢复。** 几个 T06/T07 首次用 `layerNames:["reference"]` 失败，随后读到真实 ID 并完成。保留错误轨迹，不把已恢复的工具参数错误直接等同于主任务失败。
