# 实现设计

## 展示数据

现有快照仅返回 lastResult，且 PublicMessage 省略 assistant 的工具调用信息，不能靠最后一条文字推断历史最终答复。新增可选只读 `turns` 字段，类型 `ConversationTurn[]`：`{requestId,status,finalMessageId?}`，status 沿用 RequestResult 的终态。仅从已经校验的原生 request 记录与 message 投影得到；不写新 JSONL 条目。只有成功且本请求最后实际消息是正常结束、有正文、无工具调用的 assistant 才给 finalMessageId。运行中的请求不被标终态；旧快照无字段时全部过程保留展开。

## 聊天展示

继续复用 conversationItems 对工具、Agents、交互的请求内匹配，不重新建立事件源。按原有顺序和 requestId 组织每轮展示。最终答复保留正文渲染；同轮中间说明、普通工具和成功 Agents 使用紧凑过程区域。只有明确成功且 finalMessageId 可见时允许默认收起；不从文本内容猜状态。纯对话不生成空过程控件。

交互卡片、失败／中断／未知结果、下载文件独立于可折叠区域，保留在其原有时序位置；宁可拆成多个相邻过程段，也不重排用户及交互内容。每段按真实工具和 Agents 条目计数，不重复计算映射后的工具调用。未知工具使用通用标题，不能全部叫读取资料；原文可展开。

手动展开选择以席位／会话／请求及稳定段标识区分；流式更新不重置展开。自动折叠不能隐藏键盘焦点或打断向上阅读；优先保留打开状态。手动收起保持触发器焦点。统一 Agents 文案、工具图标和轻量边界；显示实际状态，不构造思维链或额外模型摘要。

## 边界

前端主要改聊天渲染组件、SubagentCard 和相关 CSS；main.tsx 只做接入。服务端仅改快照／历史读取投影和公共类型，已有运行状态、读写权限与工具流程不变。默认面向桌面，不新增手机端专项适配。
