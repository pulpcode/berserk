## 3. 实施约束

- 一套服务、一个数据根；不为席位各起 PiLab 或部署实例。保持 taskSpaceId × seatId 目录关系与原生 Pi 历史。
- 身份来自认证会话，任务授权进入宿主公共入口及资源访问层；模型和页面都不能绕过。测试席位接口只存在于隔离测试模式。
- 复用官方 Fastify 会话机制与 Node 密码派生 API，不自行设计密码学或 token 协议。依赖固定版本并检查 Fastify／Node 24 兼容性。
- 启用正式模式前完成账号初始化；无账号不能静默切回匿名／测试运行。维护命令不在 shell 参数接收明文密码。
- 新数据保持任务／工作／文件 ID 持久稳定；任务状态与工作验收分开。API 兼容入口也要登记任务，不保留旁路。
- 公私互转、组织权限、人员换岗、后台事件／执行／智能分流不混入本期。
- 清单中后端／前端 harness-lab.md 超过自动注入长度，实施前主动分段读取相关规范。

## 4. 验证命令与证据

在 `experiments/harness-lab/` 执行：

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

新增身份／任务／备份初始化／跨标签用例，复用现有资源隔离、文件、HITL、恢复和协作测试。验收固定账号由隔离数据初始化，不使用生产密码。两席位浏览器验收使用独立 browser context，另外专门验证同一 context 切换账号的旧标签行为。

真实模型只用于确认任务上下文、文件与原工具路径仍可正常工作；身份和权限主要用确定性测试验证，避免依赖模型碰巧不越权。若需要新的测试账号配置，由维护命令在实施时提供入口，本轮不向用户索要密码。

## 5. 发布与回退

1. 停服后备份完整数据根；旧实验数据可舍弃，不建设复杂映射。
2. 初始化新数据根、账号与本地签名配置，沿用模型设置。
3. 发布时验证未登录拒绝、两席位隔离、普通处理与文件下载。
4. 回退前保留新数据，以对应旧程序和原备份恢复。

实施前文档基线为 `a4080ea`。本轮实现及验证不自动更新线上服务。提交信息继续以中文为主体。
