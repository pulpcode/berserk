## 已实现

- 独立业务控制席沿用现有登录和协作，通过示例配置明确授权下达。总体、情报、筹划、态势和导演席未获得该下达授权。账号开通复用现有离线管理命令，参见模拟服务 README。
- 方案继续使用普通文档。复用提交、退回、验收、导入固定副本和工作分派，形成业务席提交、总体席认可、控制席接收的软流程。下达接口没有审核状态、交接状态或必带方案附件的门禁。
- 任务内新增指令区，提供车辆、目的地、可选路线、可选固定附件和说明，核对后确认下达。Agent 可准备指令，通过现有 Pi 人员确认发送；页面不能代替对话确认，后台分析不获得下达工具。
- Axon 持久保存指令、固定文件引用、准备和实际下达账户及接收回执。模拟外部 HTTP 服务保存收到的指令和原编号回执。重试、未知结果、重启和换轮均按原指令核对。
- 接口提供无轮次标识的任务入口可用性投影。普通无来源任务的归属仍按 SIM-TASK-002 后续决定。

## 验证结果

| 验证 | 最终结果 |
| --- | --- |
| 冻结候选全量单元回归 | 139 个文件，1,596 项全部通过 |
| 新指令模块真实 HTTP／原生确认 | 11 项全部通过，已计入全量 |
| 原有相关桌面套件 | 63 项按套件复验完成 |
| 新增三席桌面流程 | 3 项全部通过，最终附件句柄修复后再次复验 |
| TypeScript、Lint及依赖边界、生产构建 | 全部通过 |

最终全量单元回归采用 --maxWorkers=4，未修改测试超时，也保留用例内部的并发请求。此前默认并行批次有一个场景驱动超时，另一个旧并发建任务夹具仅等待重新分析成功，未等待该次分析实际投递给 B。B 依赖具体作业的投递取得访问权，因此提前创建被正确拒绝。已补齐投递等待，保留原有并发创建和去重断言，再完整复验。该批失败日志单独保留。

原有桌面套件为 handoff、hitl、access、task-information。首次并行批次通过 39 项、失败 24 项；失败发生在旧 access/task-information 测试转发使用 request.headers()，省略 Cookie 后触发 CSRF 校验。两处改为 allHeaders()，随后这两个文件共 26 项完整串行通过。其余两个文件的 37 项原批次均通过。保留首批失败日志。

新增三席桌面实际操作了筹划文件提交、退回修改、重新提交、总体验收、导入固定副本并转交控制席，随后确认下达并从真实外部 HTTP 取得回执。还验证无审批无附件下达、丢失发送响应后只查回执、准备响应丢失后刷新恢复、取消不发送，并关闭浏览器原生 randomUUID 以核对 HTTP 环境兼容。最终三项通过，用时约 1 分钟。

11 项新模块测试覆盖明确授权与导演拒绝、准备及提交去重、对象校验、24 辆车分批核对、取消、撤权、原生确认及历史状态、旧轮拒绝和旧回执归属、响应丢失、宿主及接收端重启、损坏回执。接收不改变车辆位置、占用或场景时间。单独的接收端重开用例首次遇到原端口旧 keepalive 连接重置，改为同一数据库在新临时端口重开，专门核对持久回执；网络不明结果由独立丢响应测试覆盖。

## 审查修正

独立复核修正了账户权限投影递归、明确拒绝被误作未知、并发查询覆盖已接收结果、缺失或无效回执仍显示成功、大量引用超出单次查询上限，以及原生确认状态和业务错误文案。附件校验复用现有 assertValid，保证验证句柄关闭；修复后定向回归及最终三席桌面复验通过。

## 结果的适用范围

本轮验证采用确定性 Agent 提供方、正式测试登录、真实 SQLite 和本机模拟外部 HTTP 服务。真实模型的文档质量、指令内容正确率以及七车行动效果需要后续单独验收。既有来报关联复验 83/84 保留为先前结果，未据此推算指令正确率。
