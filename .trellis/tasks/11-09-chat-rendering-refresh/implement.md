## 1. A1：统一排版和视觉基线

需求：R01；验收：A01/A02。

- [ ] 用现有主题 token 统一正文起点、字体层级、块间距与过程行尺度，覆盖普通消息、列表、引用、代码块及宽表格。
- [ ] 先用代表性已有聊天样例形成桌面截图，确认正文/过程/交互/文件的视觉层次；不先铺开新的通用设计系统。
- [ ] 如 D4 批准复制入口，先验证本地/公共 HTTP 可用方式再做最小实现；否则本阶段仅排版，不增加高亮依赖。

预计边界：`src/web/styles.css`、`ChatMessage.tsx`；具体组件提取仅在确有第二个消费者时决定。

## 2. A2：过程分组、行摘要与状态呈现

需求：R02/R03；验收：A03–A05/A10。

- [ ] 调整 `chatBlocks`：普通 assistant 正文形成可见边界，工具/Agent/交互/文件沿用 `conversationItems` 的归属和顺序。
- [ ] 只使用已有工具名、阶段和结果状态生成分类摘要；未知/并发证据不足时使用中性表达。
- [ ] 调整过程/工具行布局和展开控件；不新增整轮折叠层、显示模式设置或底部状态条。
- [ ] 逐项复验成功折叠、旧历史回退、同一 host request 内多条用户消息、手动展开、焦点及阅读位置保护。

预计边界：`processGroups.ts`、`ChatPresentation.tsx`、`ChatMessage.tsx`、相关 CSS；必要的活动接入限定在 `main.tsx`，不改 `useChat` 流守卫。

## 8. 代表场景与证据

| 场景 | 应保留的证据 |
| --- | --- |
| 纯文本、Markdown、宽表格、长链接 | 正文对齐、局部滚动、无空过程 |
| 说明与多个工具交替、进行中及成功完成 | 原时序、说明常显、分类摘要及默认收起 |
| 工具失败/中断/未知结果、旧历史缺终态 | 独立可见、无成功误判 |
| 单/多文件、长中英文名、交接附件 | 固定链接、真实附件数量与紧凑布局 |
| 待确认、批准但结果未知、拒绝/失效 | 决定与执行分离、关键内容可审阅 |
| 多题、自由文本、已回答/已跳过 | 草稿、答案匹配及摘要可查 |
| 排队/引导/撤销/取回、会话切换与向上阅读 | 顺序、状态、焦点与阅读位置 |
| 桌面 1440px、960px 及实际聊天/地图分屏 | 由可用面板宽度决定布局，不增加手机端专项验收 |

## 9. 回滚与风险点

- 以 A1/A2/A3 的可审阅边界分批提交。回滚仅撤销该阶段展示修改；不删除历史、固定交付文件或原始结果。
- A2 风险最高：分组边界变化可能引起 remount、展开重置、焦点丢失或阅读位置变化；必须先建立对应回归，再扩展视觉调整。
- A3 保持交互提交锁和不确定结果查询，不为视觉精简改变权限、审批范围或请求身份。
- 如执行中发现 A 需要增加后端投影/依赖或搬动交互位置，先更新方案和范围并回到审阅，不静默扩展。
