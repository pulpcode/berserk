# 聊天页面渲染统一：设计草案

状态：A/C 已实施；B 首批技术设计已批准，见本文末节及 [b-first-batch-review.md](b-first-batch-review.md)。D1–D4 保持原决策；用户于 2026-11-13 批准 B 首批实施。

## 1. 现有结构与改动边界

现有展示路径：

```text
Pi 原生事件/历史
  → 现有宿主校验与公共快照/SSE
  → useChat（所属会话、请求、流与版本保护）
  → conversationItems（工具/交互/Agent 绑定）
  → chatBlocks（相邻过程段与文件去重）
  → ChatPresentation / Message / InteractionCard / Files / SubagentCard
```

A 只调整末端呈现和纯展示分组；继续复用 `conversationItems`、`turns`、文件去重、既有草稿与读状态。`main.tsx` 只在必要时接入活动展示，不另建消息源或执行状态。

B 才允许核实并补充公共投影。原生事件/历史仍是执行与终态依据；展示字段不足时回退，不编造对象、时间或结果。

## 2. 视觉层次

建议以现有主题 token 为基础，不引入另一套主题或 DSH 插件运行时。

| 层次 | 推荐基线 | 内容 |
| --- | --- | --- |
| 回复正文 | 14–15px，约 24–26px 行高；沿用现有 760px 消息列 | 普通说明、最终答复、可阅读 Markdown |
| 过程行 | 约 13px / 24px，行间约 4px，弱化默认边界 | 工具/Agent 执行摘要，展开后就地查看 |
| 待办交互 | 有节制的边界和强调；完整动作可审阅 | 待确认、待回答及需要核对结果的操作 |
| 成果附件 | 内容自适应，最大 480px；与正文对齐 | 交付文件、引用与交接资料 |
| 历史与次要信息 | 同一正文体系的次级颜色，避免重复大外框 | 已处理确认、回答摘要及来源/状态说明 |

正文段落约 12–16px 间距，同轮说明约 12px，不同轮次保留更明确的分隔。数值是待截图审阅的起点；桌面窄面板保留布局弹性，不把固定高度施加给长内容。状态需要可访问文字，不仅依赖颜色或动效。

## 3. 消息与过程组织

按照已确认 D2 保留进度说明，推荐的新顺序：

```text
用户输入
进度说明（可见）
过程段 A（工具/适合收拢的 Agent 记录）
进度说明（可见）
过程段 B
确认/提问/交付/异常（在原位置独立可见）
最终答复（可见）
```

- 所有 `role=assistant` 的普通公开正文都是消息边界，不通过正则、最后一段文字或模型摘要决定它是否值得保留。内部推理不新增投影。
- 工具、Agent、交互、文件仍由既有归属与去重规则定位；用户排队消息消费产生的边界必须保留。不得为了把过程拼成一个大块而重排真实时序。
- 过程摘要是本地纯格式化：按实际工具类别给出简洁概括。运行阶段有可信当前工具名时显示该类别，否则中性“处理中”；`stopping` 优先。
- A 没有工具参数与通用时间，不能显示臆测的文件名、命令、百分比、耗时或并发数量。工具失败/结果未知不计入成功完成的文案。
- 成功终态和有效最终消息 ID 双重证据、手动选择优先、焦点/阅读保护沿用。每个过程段只控制自身的执行记录；不新增默认全轮/组/工具三重折叠和显示模式设置。
- 运行反馈在对应过程/工具位置表达；不恢复输入框底部整行阶段提示，也不增加一份抢占注意力的全局执行说明。

## 4. 工具行与展开内容

A 统一“图标 + 动作 + 有依据的状态 + 展开”及默认次要色。展开箭头靠近动作信息，避免长空白横跨整列。普通结果只在有返回证据时表述为完成；未知工具保持中性标题，原始文本可查。

B 的候选专门视图如下，均以资料完整性为进入条件：

| 类型 | 需要的可验证数据 | 有数据时 | 缺数据时 |
| --- | --- | --- | --- |
| 命令 | 原始命令、工作目录、结果/退出信息 | 命令与输出分区，已知退出结果独立显示 | 保留通用结果，不从文本猜退出成功 |
| 文件读取 | 精确路径、读取窗口/行号及内容 | 文件标题和带行号内容 | 展示原始内容，不伪造行号/路径 |
| 修改 | 原生明确的 diff/修改元数据 | 文件、增删摘要及 diff | 不拼接一次新旧文件读取来反推历史 diff |
| 查询/业务结果 | 已校验的结构化业务结果及授权 | 使用现有结果卡，逐步精简摘要 | 不将普通返回文字解释为结构化结果 |
| 增量输出 | 支持的原生更新事件和结果归属 | 在原工具位置增量更新 | 显示等待结果，不另建执行队列 |
| 耗时 | 同一真实轮次/工具的开始、结束时间 | 展示实际时间差 | 隐去耗时，不使用首次浏览时间计时 |

公共类型本轮不预定字段名或 schema。B 开工前需列出每个字段的生产者、校验位置、权限、历史来源与旧版本回退，再独立审阅。

## 5. 文件呈现

- A 只统一当前已存在的文件卡/附件行：图标、名称、大小、操作位置、长名称换行。普通交付卡可去掉“本次交付的内容”这类重复说明。
- 固定交付、交接副本、当前文件引用和上传中/失败状态维持不同语义。文件名、版本/变化及失败提示不得为视觉精简而消失。
- `downloadId` 与 `fileId` 继续决定固定副本；当前工作区引用沿用显式状态查询，不替换成同名当前文件冒充历史交付。
- 预览属于 B/可选增强。先核实固定下载是否可按授权读取、MIME 与格式限制、blob 生命周期及错误回退；禁止为了预览静默复制文件或生成新版本。现有 `HandoffFiles` 预览逻辑可作为复用证据，不直接扩张支持格式。
- 多文件分组必须保留每个独立的固定下载对象及各自的原始位置；跨越普通消息或交互的文件不为整齐而合并。

## 6. 确认与提问

### A：首轮过渡，先保留消息流位置

待确认卡的主要内容为具体动作、对象/影响、完整可审阅内容与决定。状态条、通用种类标签及规则说明减轻权重；长命令局部滚动且仍可直接核对。命令权限提示与业务交接使用各自语气和颜色。分派真实附件数量/列表仍在决定前可见。

已处理确认以一行或紧凑摘要显示动作、决定和必要执行结论，展开保留原操作与记录；审批决定不等于执行成功，结果未知/失败仍直接可辨。沿用 `submission.busy`、`needsQuery`、查询后再决定是否重试等机制，不新增授权方式、批准范围或快捷键。

待回答卡减少标签与选项留白，长内容限制在可阅读区域；不因限高遮住题目、选项或提交入口。已回答首先显示实际题目和答案，其余选项折叠可查；跳过/取消/失效按实际状态显示。继续按原问题 ID 匹配，保留自由文本/选项互斥、IME 与草稿隔离。

### C：输入区处理当前交互，聊天保留历史

产品行为以已批准的 [C 轮修复 v0.3](c-repair-plan.md) 为最新依据；原 [C 轮审阅稿](c-round-review.md) 中冲突条款按修复方案替代。继续复用现有 `Interaction` 的 `question` / `confirmation` 两类记录、`sessionId + requestId + interactionId` 身份、服务端状态和 `useChat` 提交机制，不新增交互状态源、独立记录或执行接口；回答契约仅补齐显式逐题 skipped 标记，经既有校验、原生历史和工具返回链路传递。

```text
现有快照中的当前待处理交互
→ 输入区只渲染一张当前卡
→ 原消息位置仅保留状态入口，不重复渲染可提交表单
→ 服务端返回已回答/已确认等非待处理状态
→ 当前卡退出并接续下一项；原消息位置显示历史记录
```

- 当前卡只从所属会话、当前可响应请求的待处理交互中选择；出现多项时沿用原记录顺序逐项展示，不建立持久队列或跨卡片轮播。
- 普通 composer 隐藏但不清理其文字、附件和引用；已有输入队列继续显示；卡片期间不显示停止入口，交互结束后普通运行恢复既有停止。提问与确认的内容组件保持各自语义，只共用输入区承载和生命周期。
- 提问卡以本地分页状态支持一张卡内多题切换，回答继续使用现有按交互保存的草稿。收起仅隐藏正文与操作区、保留标题栏，不恢复普通 composer。确认卡不提供收起。
- 提交沿用 `respondInteraction`、`submission.busy` 和 `needsQuery`。只有服务端投影转为非 `pending` 才退出当前卡；网络结果未知时保留查询，不自动重发。
- `approved` 只表示确认已被接收，后续原生工具结果继续更新 `execution`。当前请求仍在对应工具执行阶段时，历史可显示“执行中”；旧历史缺少结果时仍显示结果待确认，不伪造成功或进行中状态。
- 已回答提问使用简洁的问题与实际答案气泡；完整题目和选项可从对应工具记录只读核对。确认历史沿用紧凑可展开结构。两种历史都不渲染可操作表单。
- 输入区卡片采用有界高度和内部滚动，主要动作固定可达。消息列表仅随可用空间调整；用户已在底部时保持跟随，阅读历史时不抢滚动或焦点。若被隐藏的 composer 正持有焦点，焦点需有可见落点；当前卡完成后仅在实际交互路径中恢复输入焦点。

预计改动集中在 `InteractionCard.tsx`、聊天原位置投影、输入区接入及相关 CSS。若实现发现必须修改公共契约或交互语义，先回到审阅，不在 C 中静默扩展。

## 7. 后续 Agent 与业务成果

B 可使用已有 `SubagentSummary` 的角色、描述、任务、状态和结果改善摘要，避免重复状态/任务标题；保持请求内归属与既有取消规则。只从实际记录展示已知执行结果。

资源/地图卡的简洁摘要要保留时间、范围、关键数量及限制入口；对象列表、依据和原始结果可展开。现有结果授权与重新读取语义不改变，聊天链接继续定位到已授权对象/版本。该项不能顺带重做地图画布、右侧业务面板或统计算法。

历史错误需先核实每轮原生终态/原因来源；当前 `ConversationTurn` 没有错误正文，不能把最新一轮错误复制到过去轮次。

## 8. 兼容、性能与回退

- 沿用 `useChat` 的会话/请求/stream token/快照修订守卫，不调整业务写入和重连行为。
- 保留 `requestId + toolCallId` 绑定、稳定段身份、文件去重和当前焦点桥接；新增显示边界不能丢失展开状态或把阅读者拉到底部。
- A 不增加数据库、JSONL 类型、模型提示词、后台执行、显示偏好持久化或新依赖。无额外模型调用。
- 字段缺失、旧历史、未知工具或结构化结果不完整时，回退到可展开原文与中性状态。
- 如果采用复制入口，公共 HTTP 与权限拒绝的处理须先验证；仓库当前没有现成剪贴板工具，不能把“安全上下文才支持”当作当前产品的隐含前提。
- B 的原生事件与读取型投影变更在各自阶段单独设计；不要把 DSH 客户端插件框架作为本项目依赖。
- 回滚按阶段撤回展示变更；不得删除用户历史、固定文件或改变原生工具结果来恢复旧样式。

### 展示与状态归属

- 首批采用固定 DSH Web Detailed 行为，不接入其插件框架或四模式设置。运行中直接渲染过程成员，详情独立收起；完成后新增整轮过程控制，再使用既有相邻过程组与工具详情。
- 思考以原生内容块顺序形成过程节点，不能只附在所有正文末尾；普通正文继续作为过程组边界。预览从已返回文本确定性提取首行/段落，不另调模型生成摘要。已完成消息替换流式节点时保持身份与展开状态，避免重复思考、正文或工具。
- 正常自动收起继续要求可信 succeeded + 可见 finalMessageId；失败、停止、未知结果以及过程后的已消费用户补充不提供整轮隐藏。文件、交互、异常、普通回复永远在整轮隐藏范围之外。
- 终态且无过程内容时，耗时为无展开动作的次要文字。完成时间只由匹配的起止记录计算；不新增全局计时状态条或输入区提示。
- 手动选择、焦点和阅读保护延续现有规则；展开状态按席位/会话/请求/原生块或稳定分组标识隔离。用户主动关闭整轮时可重置其内部披露；流式更新和导航不能无故重置。
- 通用详情继续使用现有安全 Markdown/纯文本展示；diff 用代码样式按增删区分，长命令/输出局部滚动并显示截断。使用语义 button、aria-expanded、可见焦点及现有主题 token，不引入新主题或移动端专项设计。

### 兼容、风险和回滚

思考文本投影和额外整轮折叠是 B 首批新增范围，实施获批后同步更新旧前后端规范中对应禁止条款。模型配置、能力判定、high/off、权限/确认和执行语义保持现有机制；Kimi/Qwen 的真实接入不包含在本批。

主要风险是原生块顺序与流/历史切换重复、工具增量被误作 delta、折叠范围跨越用户消息、公共参数越过现有授权，以及不完整历史误算耗时。对应 B1-01–B1-06 验证；代码审阅前逐项核对。回滚仅撤回新增投影和展示，保留原生历史、固定文件及 A/C 行为；新增公共字段均为兼容可选字段。
