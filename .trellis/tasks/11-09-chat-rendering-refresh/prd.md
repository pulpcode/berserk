# 聊天页面渲染统一与 DSH 对齐：需求草案

版本：v0.2，2026-11-09。状态：待审阅；需求范围尚未批准实施。审阅入口为 [review.md](review.md)。

参考 GitHub 仓库：[https://github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)。Web 应用入口：[apps/web](https://github.com/deepseek-ai/deepseek-harness/tree/master/apps/web)；聊天核心源码：[packages/client/ui-chat](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/client/ui-chat)。

## 目标与价值

统一聊天页面中的正文、处理过程、工具结果、文件与人工交互的展示层次，使用户能顺畅阅读回复、了解正在进行的工作、发现需要自己处理的事项，并按需查阅执行细节。

参考 DeepSeek Harness 的紧凑过程行、活动摘要、就地展开和过程折叠，结合现有任务、席位、文件固定交付及地图业务，不要求复制其全部界面或插件体系。

本文“进度说明”指 Agent 在最终答复前已发给用户的自然语言消息，例如“我先读取资料，再核对差异”。其展示方式已由 D2 确认：仿照 DSH Web 默认 All replies，进度说明和最终答复保持可见，工具过程按规则折叠。具体例子见 [审阅入口](review.md)。

## 已确认事实与约束

- 用户要求“先不进行实施”，当前只维护方案和计划供审阅；此前十项建议不等于全部获准实施。2026-11-09 用户通过批注确认 D2：进度说明仿照 DSH Web 默认行为保持可见；并同意 D3 分开描述首轮暂留原位与最终输入区待办目标。这些决策不构成整体实施批准。
- 范围讨论中的“整个聊天页”指聊天主区域；侧边栏没有获得纳入范围的确认。本方案将侧边栏、地图本体等列为范围外，待用户审阅。
- 当前已存在过程分组、成功终态投影、文件交付去重、交互历史折叠、请求内工具/Agent 归属、阅读位置与焦点保护，需在其上迭代。
- 当前 `PublicMessage` 只有工具名、正文和部分业务结果，公共工具开始/完成事件未携带完整参数、通用增量输出与时间；`ConversationTurn` 只有请求 ID、状态和可选最终消息 ID。证据及源文件锚点见 [research/evidence.md](research/evidence.md)。
- 面向桌面浏览器，包含窗口缩放及分屏。沿用 Pi 原生机制、公开 SDK、历史和现有权限；不为本次展示改造建立第二套执行状态或聊天记录。
- 保留已接受的输入区改动：无底部整行状态/快捷键提示，无独立排队按钮，Enter 在允许时排队，引导只在队列行操作，Ctrl/Cmd+Enter 不提交；文件卡片随内容收拢且最大 480px。

## 候选需求与阶段归属

R02 中进度说明与最终答复保持可见的行为已由 D2 确认；R06/R07 的首轮过渡位置与最终位置方向按 D3 分开记录。其余要求及具体阶段范围仍为草案。A 是推荐首轮范围，B 为后续候选，C 是已确认方向但尚待详细设计的后续交互阶段；B/C 不随“批准 A”自动获准实施。

| ID | 内容 | 推荐阶段 | 可观察目标 |
| --- | --- | --- | --- |
| R01 | 消息正文与 Markdown | A | 普通回复、进度说明和最终答复使用同一正文起点；标题、段落、列表、引用、代码块与表格具有统一层次，宽内容在自己的区域内可读 |
| R02 | 过程组织与折叠 | A | 普通 assistant 正文留在消息流；工具和适合收拢的 Agent 执行记录归入相邻过程段，保留原时序与两层以内的常规披露 |
| R03 | 过程行与活动摘要 | A | 紧凑行统一图标、文字、状态及展开位置；运行中只显示有事件证据的当前活动，结束后按实际类别概括，不以调用次数作为唯一信息 |
| R04 | 工具结果专门视图 | B | 按可验证数据分别显示命令/输出、文件读取、修改 diff、查询结果；缺数据或不支持时仍能展开原始返回内容 |
| R05 | 文件、附件与交付 | A / B | A 统一聊天中的已有文件信息与操作样式，精简无信息增量的说明，保留固定副本、变化及失败信息；B 可增加支持格式的只读预览与多文件增强 |
| R06 | 确认卡及历史回执 | A / C | A 突出具体动作、影响、内容和决定，降低通用标签及历史外框权重；审批决定与执行结果仍分开。C 的目标为输入区当前待办与聊天历史回执 |
| R07 | 提问卡及回答历史 | A / C | A 使待答内容与提交操作易于阅读和到达；已回答记录聚焦题目与实际答案，其他选项可展开查阅；C 的目标为输入区当前待办与聊天历史回执 |
| R08 | Agent 子任务摘要 | B | 利用已有角色、描述、任务和状态呈现具体工作，减少展开后的重复标签与进度文字；不暴露或重建内部层级 |
| R09 | 业务成果摘要 | B | 聊天中的资源/地图结果优先呈现结论、数量、范围/时间和授权入口，名单、依据与限制按需阅读；不改变统计或访问语义 |
| R10 | 错误、中断与阅读稳定性 | A / B | A 保留已有异常可见性、手动选择及阅读保护；B 在原生历史可证明时，将历史终态与原因呈现在所属轮次，不从当前 `lastResult` 套用到旧轮次 |

## 首轮 A 的功能要求

- 已确认的 D3 分阶段方向：A 先保留确认/提问卡在触发它的消息流位置，统一密度和历史摘要；C 最终将当前待办置于输入区附近，服务端确认已处理后在聊天原位置保留结果回执。C 需独立完成交互设计与审阅，不在 A 实现时临时搬动位置。
- 已确认的 D2：每段已有的普通 assistant 正文始终可见，不用措辞判断它是否“重要”；最终答复仍以已验证的终态证据识别。整体方案获准并实施后，需更新旧 W01-10 将部分中间说明放入过程折叠的规则。
- 过程摘要可以来自已有 `toolName` 类别及 `RequestState.phase`，但没有真实活动证据时使用中性表达；不能把一次调用或取消请求表述为成功结果。
- 确认卡在允许前能直接核对操作标题、影响、目标及完整命令/交接文件。次要规则信息可以降低视觉权重，但不能因此隐藏决定所需内容。
- 已回答问题首先展示实际题目与对应答案，未选选项保留可查；“已跳过/已取消/已失效”不能伪装成已回答。
- 交付卡继续使用固定 `downloadId`，文件名完整可读，单文件保持紧凑；合并视觉样式不合并固定交付、当前工作区引用与交接副本的含义。
- 样式调整不触发提交、执行、导入、复制文件或授权；预览和界面复制入口属于未批准的可选增强，见 D4。

## 首轮验收标准

| ID | 对应需求 | 用户可观察的结果 |
| --- | --- | --- |
| A01 | R01 | 纯文本多轮对话有统一正文对齐和留白，不生成空过程标题或额外品牌行 |
| A02 | R01 | 中文段落、列表、引用、代码块、宽表格及长链接在普通桌面与窄聊天面板可读，不造成页面级横向溢出 |
| A03 | R02 | “说明 → 工具 → 说明 → 工具 → 最终答复”的顺序不变；普通说明与最终答复始终可见，过程折叠只影响对应执行记录 |
| A04 | R02/R10 | 有成功终态且最终答复可见时才自动收起；缺终态/最终 ID、失败、中断及未知执行结果仍可见；纯工具返回不被当成最终答复 |
| A05 | R03 | 运行、停止中及结束后的行样式清楚且不重复播报；多工具/并行活动只表达可证明事实，长标题不挤掉状态或展开入口 |
| A06 | R05 | 单/多文件、中文及长英文文件名可读；固定下载内容和所属请求保持一致，刷新后无重复交付卡；上传/引用错误仍可处理 |
| A07 | R06 | 待确认能核对动作、目标、完整命令及实际附件；拒绝、提交中、结果需查询等流程可用，不发生误提交或重复授权 |
| A08 | R06 | 确认历史同时保留决定和执行结果；批准成功、执行失败、未执行和结果未知四种情况可区分 |
| A09 | R07 | 单/多题、自由文本及长选项可作答；已回答摘要准确对应问题与实际答案，刷新/切换后草稿和历史一致 |
| A10 | R02/R10 | 用户向上阅读、聚焦工具详情或手动展开时，流式到达、完成折叠和切换会话不丢焦点、不抢阅读位置、不重置手动选择 |
| A11 | R03/R05 | 排队、行内引导、删除/撤销、取回编辑与停止仍正常；中文输入法、Shift+Enter 及已取消的 Ctrl/Cmd+Enter 行为不回退 |
| A12 | 全部 A | 新旧快照均能显示；渲染、展开、复制文本等本地操作不隐式发送消息或重放工具；关键样例有桌面截图，相关质量检查通过 |

## 后续阶段的进入条件

B 中每一项先形成“已有原生字段 → 授权投影 → 公共类型 → SSE/快照/刷新 → UI”证据，再决定最小改动；不能把暂缺数据的能力塞入 A。C 的最终方向已确认，但具体承载方式、多待办排序/切换、长内容及输入草稿/队列共存仍待设计审阅。A 之后 B/C 分别排期，C 不依赖全部 B 能力完成。后续阶段实施批准前需补齐各自的需求和验收。

## C 阶段的目标验收草案

对应 R06/R07 与已确认 D3 的最终方向，细节需在 C 的独立设计中收敛；本表不构成当前开工授权。

| ID | 预期效果 |
| --- | --- |
| C01 | 当前待确认/待回答在输入区附近可达，用户无需向上翻找；完整命令、实际附件、题目及选项仍可核对 |
| C02 | 每个交互只有一处可操作表单；服务端确认已处理后，当前待办退出操作区域，聊天原位置留下可展开回执 |
| C03 | 正在提交或结果不确定时不提前当作已处理，不自动重发；保留既有锁、查询及核对能力 |
| C04 | 回执按记录显示决定、实际回答与必要执行结论，保留批准/成功/失败/未执行/未知、跳过/取消/失效的区别 |
| C05 | 当前待办、消息流历史和普通输入之间切换时，原输入草稿、附件引用及问题草稿不丢失，且继续按所属会话/请求隔离 |

## 范围外

侧边栏重构、登录/设置、工作总览、地图本体和业务侧栏；手机端专项工作；新思维链或系统提示词展示；执行/权限/模型/工具协议迁移；新执行状态库或持久聊天副本；未经确认的新主题、显示模式设置、批量历史迁移；部署、push 或生产验收。
