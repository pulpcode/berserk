# C 轮独立复核

2026-11-12；复核对象为 `feat/chat-rendering-c` 当前未提交实现，基线 `main@2eee566`。本次由独立检查代理阅读批准方案、代码和现有用例；未在本机运行测试。服务器验证由主会话执行，最终结果另附，不沿用11月10日A轮成绩。

## 发现与修复

1. **待答卡会因查询而跳序（C02/C05）**：`useChat.applyInteraction` 原先删除旧条目再追加；首卡提交结果不确定、查询仍pending时会排到第二张之后。现改为原位置替换，新增“首卡未收到提交→查询→原题/答案不变→提交后才显示第二卡”回归。
2. **同名确认卡误报执行中（C06）**：仅按请求及toolName匹配，不能区分同一请求内多个同名确认。现在存在多个未获得确切执行结果的同名批准记录时保留中性“结果待确认”，不向每张卡套用当前工具阶段。新增双同名确认回归；不为C新增公共执行字段。
3. **旧卡可能抢占另一会话焦点（C07/C08）**：卸载卡片的延迟恢复只看textarea是否存在，可能命中新会话或隐藏视图。现增加席位/视图/会话归属及可见性核验，新增历史导航离开卡片后的焦点回归。
4. **点击输入区外的空白后仍有焦点归属（C08）**：blur.relatedTarget为空时保留dockFocus，会使后续卡片误认为输入区仍持焦点。现以实际输入区外pointer事件清除归属，新增延迟SSE到达后的阅读焦点回归。
5. **普通输入恢复后高度未刷新（C07/C08）**：文本未变化时，替换卡结束后的新textarea不会触发原高度effect。现随当前卡身份变化重算高度，复用原180px上限，不改草稿。

前三项代码归属分别为useChat.ts、ChatPresentation.tsx、InteractionCard.tsx/main.tsx；后两项局限main.tsx。全部修复保持既有API、权限、工具、交接和持久交互数据契约。

## 逐项核对

| 验收 | 静态核对及需要的服务器证据 |
| --- | --- |
| C01 | 普通输入和当前卡互斥；历史pending仅只读指针。浏览器核对唯一表单及停止入口 |
| C02 | first pending按原记录序选择；更新原位替换。多卡、分页与未受理查询回归 |
| C03 | 题卡收起仅隐藏正文；确认无收起控制；均未恢复普通输入 |
| C04 | response/query沿用服务端交互投影，非pending即退出；批准不等待执行成功 |
| C05 | 原锁及needsQuery保留，不自动重发；草稿按session/request/interaction归属 |
| C06 | 回答按questionId匹配且文本转义；未选项只读可查；确认执行状态依证据且歧义回退 |
| C07 | 文本/附件/引用仍归原useChat状态，卡片不清空或消费；队列在条件输入之外保留；切换/刷新/停止回归 |
| C08 | 内容体有界内部滚动、footer常驻；同作用域焦点恢复，外部阅读不抢焦点。桌面宽/窄、地图分屏及截图 |

## 未修复问题与边界

当前未发现需要扩大产品范围或新增公共接口才能修复的阻断项。历史RequestState只有toolName，没有确切当前toolCallId；多次同名确认时故意显示中性结果，不能把它描述为每张卡精确实时进度。该回退已纳入用例和规范，C不扩展B轮投影。

原实施代理的1656项单元、38项交互和81项其它浏览器通过记录为历史证据，不冒充本次最终验证。`implement.md`最终质量门应在服务器对最终源码通过检查后由主会话更新。
