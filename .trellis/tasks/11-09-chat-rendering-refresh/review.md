## 目标

参考 DeepSeek Harness 的聊天呈现，将当前聊天主区域整理为“正文清晰、过程紧凑、待办醒目、历史轻量”。复用现有 Pi 运行机制、历史与权限，只补已证实需要的展示能力。

## 建议的阶段与范围

| 阶段 | 内容 | 边界 |
| --- | --- | --- |
| A：首轮，推荐优先 | 消息与 Markdown 排版；面向用户的进度说明留在消息流；紧凑过程行与分类摘要；文件展示一致性；确认卡、提问卡的密度及历史摘要 | 只消费已有前端契约；没有文件名、命令等证据时不显示对象摘要；不增加服务端接口或持久记录 |
| B：后续，另行审阅 | Agent 子任务摘要；资源/地图成果摘要；历史错误在所属轮次呈现；工具对象摘要、专门结果视图、实时输出与真实耗时 | 逐项核对原生数据、授权、历史恢复和兼容性；可先做已有字段支持的 UI，小步补充已证明必要的投影 |
| C：已确认的最终交互方向，独立设计 | 当前待确认/待回答操作靠近输入区，处理后在聊天原位置保留简洁回执 | 与 A 的首轮过渡效果分开验收；待办排序、长内容、输入草稿/队列共存等细节仍需审阅，不随 A 自动实施 |

左侧项目/会话导航、工作总览、设置/登录、地图本体与业务侧栏不在本方案范围。地图结果在聊天中的摘要、链接可列入 B，地图工作区本身不改。桌面浏览器窗口缩放及分屏在范围内，手机端专项工作不在范围内。

## 已确认决策

### D2：仿照 DSH Web 默认行为，保留进度说明

2026-11-09，用户对“保留进度说明对应 DSH Web 的默认行为”批注明确同意：“可以，仿照 dsh web 的行为来”。此项产品决策已确认，整体方案仍未获实施批准。

采用 DSH Web 默认的 **All replies（所有回复）**行为：Agent 已发给用户的进度说明与最终答复都保持可见，工具过程按既有证据和保护规则折叠。参考：[DSH Replies after collapse](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-chat/src/client/conversation-nodes/README.md#folded-replies)。

“进度说明”例如“我先读取资料，再核对差异”“已找到两处差异，接下来检查影响范围”。只调整已有公开消息的折叠方式，不额外生成说明文字或展示内部推理，也不由此新增显示模式设置。

| 一轮对话中的内容 | 已确认的展示行为 |
| --- | --- |
| Agent 发给用户的进度说明 | 留在原来的聊天位置，随聊天记录正常滚动，不随工具过程收起 |
| 工具调用与原始返回 | 放在可展开的过程区，沿用可靠终态、异常可见与焦点/阅读保护规则 |
| 最终答复 | 保持可见 |

当前代码仍会把部分进度说明与工具一起折叠；D2 的行为改动将在整体方案批准后实施。

### D3：分开说明首轮过渡效果与最终交互目标

2026-11-09，用户批注同意按讨论将“首轮暂留原位”和“最终推荐效果”分开写清楚。方案据此记录分阶段方向；这不构成首轮全部范围、C 的详细交互或整体实施批准。

| 阶段 | 位置与效果 | 如何理解 |
| --- | --- | --- |
| A：首轮过渡 | 确认/提问卡仍在触发它的聊天位置，先做紧凑卡片和历史摘要 | 控制首轮改动范围，保留现有时序；暂留原位不代表最终始终放在消息流 |
| C：最终目标 | 底部输入区附近处理当前待办，聊天记录保留处理结果 | 待处理时不必向上翻找；服务端确认已处理后，当前待办退出操作区域，原位置留下可展开的结果记录 |

最终目标包含：待确认时可完整核对动作、命令和附件；待回答时可查看题目、选项并填写答案；提交结果不确定时保留查询/核对入口；已处理记录区分决定和执行结果；恢复普通输入时保留原有草稿。交互表单只保留一处可操作入口，历史详情不重复发起操作。

C 的具体承载方式（在输入框上方或暂时代替输入表面）、多待办排序/切换、长内容布局及输入草稿/队列共存仍待详细设计。A 完成后，B 与 C 可分别排期，C 不以完成全部 B 能力为前提；每个进入实施的阶段仍需明确批准。

## 关键展示规则

- 正常说明、最终答复、用户消息、确认/提问、交付文件、失败/中断/结果未知条目保持独立可见。
- 只有成功终态与有效 `finalMessageId` 都可证实时，工具过程才允许自动收起。缺字段的旧历史保留可读回退；继续保护手动展开、键盘焦点及向上阅读。
- 摘要来自真实工具类别和原始字段，不调用模型重写过程，不从返回文案猜文件路径、命令、diff 或执行成功。
- “已批准”与“执行已完成/失败/结果未知”仍为不同信息；分派、签收、提交、审核各自保留业务操作语义。
- 保留本次对话已完成的输入区精简、队列行引导、无边框引导按钮与紧凑文件卡。交付文件继续指向固定副本。

## 如何判断首轮完成

代表场景需能看清普通回复、流式工具过程、完成折叠、文件交付、待确认、已确认但结果未知、待回答与已回答摘要。刷新、切换会话、队列消费、桌面分屏及键盘操作不丢内容、位置或草稿；纯对话不出现空过程块；异常和成果不被折叠隐藏。
