# 对话 UI C 轮方案（已批准）

日期：2026-11-12。用户已审阅并批准本方案实施。

## 目标

需要用户回答问题或确认操作时，直接在当前输入框的位置处理，不必向上寻找卡片。处理后，聊天记录仍保留回答、决定和执行结果。

## 1. 当前卡片的位置与顺序

- 提问卡和确认卡都占用普通输入框的位置，同时只显示一张。
- 多张待处理卡片按出现顺序处理，不提供卡片之间的左右切换；当前卡处理完后自动显示下一张，全部处理完后恢复普通输入框。
- 普通输入框暂时隐藏时，已输入的文字、附件和引用选择全部保留。
- 已有排队消息仍可查看和管理，停止当前请求的入口保持可用。
- 卡片出现时，不打断用户阅读历史消息，也不强制滚动聊天列表。

## 2. 提问卡

- 一张提问卡可以包含多个问题，支持在问题页之间切换；切换后保留已填写或选择的答案。
- 所有必答问题完成后，提交整组回答；现有“跳过提问”能力保留。
- 提问卡可以收起为标题栏，但收起后仍占用输入区，不恢复普通输入框；展开后可继续回答。
- 不增加“关闭后恢复输入、再从工具行重新打开”的能力。

## 3. 确认卡

- 普通操作、命令执行、分派、签收、提交和审核共用确认卡类型；分派确认不是另一种独立卡片。
- 确认卡不提供收起或“稍后处理”，用户可确认、拒绝，或使用现有停止入口。
- 确认前可核对完整命令、操作影响、分派内容和实际附件。
- 长内容在卡片内部滚动，主要操作按钮保持可见，不撑破聊天页面。

## 4. 提交与退出

```text
用户提交回答或确认
→ 服务端接收本次回答或决定
→ 当前卡退出，显示下一张卡或恢复普通输入框
→ 聊天原位置保留记录
```

- 确认分派被服务端接收后即可退出，**不等待分派执行成功**。
- 分派随后在原聊天位置显示执行中、成功或失败；批准与执行结果分开呈现。
- 提问被服务端接收后即可退出，不等待 Agent 生成最终答复。
- 提交期间防止重复点击。
- 如果提交后网络中断、无法确定结果，保留卡片和草稿，提供“查询最新状态”；不直接显示成功，也不自动重发。

## 5. 聊天中的历史记录

- 提问回答参照 DSH，显示简洁的“问题 + 实际答案”气泡；跳过、取消和失效按实际状态展示，不伪装成已回答。
- 原题目和完整选项可通过对应工具记录只读查看，不会再次出现可提交表单。
- 确认历史使用紧凑、可展开的结果卡，保留确认或拒绝，以及执行中、成功、失败、未执行或结果未知等真实状态。

## 6. 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| C01 | 当前提问或确认直接出现在输入框位置，同时只有一处可操作表单。 |
| C02 | 卡片按顺序处理并自动接续；没有跨卡片切换，提问卡内部可多题分页。 |
| C03 | 提问卡收起后仍占输入区；确认卡不可收起；普通输入不被误恢复。 |
| C04 | 服务端接收回答或决定后立即退出当前卡，不等待后续答复或业务执行完成。 |
| C05 | 提交中、结果不确定、刷新和查询恢复时不丢草稿、不重复提交、不提前显示成功。 |
| C06 | 提问历史准确显示问题和答案；确认历史准确保留决定及执行结果。 |
| C07 | 普通草稿、附件、引用、已有队列和停止能力不回退；切换会话和地图分屏不串用状态。 |
| C08 | 长内容可核对、页面无横向溢出；阅读位置和键盘焦点不被无故打断，并完成桌面截图审阅。 |

## 7. 本轮不做

- 不做 B 轮的工具结果专门视图、实时输出、耗时或文件预览。
- 不做多卡片轮播、提问卡关闭后重开、确认卡收起或新的持久授权方式。
- 不改变现有权限、工具执行、消息队列和业务交接规则。
- 不新建第二套交互状态或聊天记录，不引入 DSH 插件体系。
- 不做手机端专项设计，不自动部署或发布。
