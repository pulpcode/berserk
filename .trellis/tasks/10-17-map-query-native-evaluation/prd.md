## 1. 目标与用途

从用户真实提问开始，观察 Agent 能否自主取得足够证据并完成回答，定位失误首次出现在哪一步：目标识别、名称到 ID 的发现、范围/分页选择、补查决策，还是最终解释。交付可复查的诊断结果，为下一次具体改动提供依据。

**当前问题没有修复。本轮不是继续验证 readSummary，也不是再确认问题是否存在。** 上轮固定历史错误调用，只检验后续纠错；本轮测量当前产品自然执行时的完整行为。若模型本来能选对查询，上一轮40%/60%不能代表其完整流程成功率；若仍失败，则记录实际断点。该观察本身不能证明唯一根因为模型能力或工具设计，不能自动导出新提示词/宿主机制。

## 4. 验收标准

“测评执行完成”与“模型表现通过”分开：

- 执行完成：预设15条都有明确终态；每条具备输入、工具执行、全部可见回答、独立前后快照和评分；如触发预算/安全/环境停止，必须报告未完成，不能算全批执行完成。
- 单条严格通过：用户要求被完整、正确回答，所有可见事实与实际证据一致，没有错误副作用和阻塞性的多余确认。允许预算内必要补查、自我纠正；但已经展示给用户的明确错误单独保留，不能被最终正确答案抹掉。
- 单条业务成功：最终主问题答对且状态符合要求；与严格通过、首次查询质量、工具错误、自我恢复分别统计。
- 本批模型表现通过：F1/F2/F3各5/5严格通过，查询阶段0写入尝试、0隔离回归。达不到就按场景报告缺陷，不用合计通过率掩盖某例全败。该门槛仅是本批标准，5次重复不证明总体可靠率。
- F2前置编辑失败时，比较阶段不启动；该计划样本计未完成。比较能力的条件成功率另列分母为实际进入比较的次数，不能将其与5次计划分母混用。

## 5. 不在范围内

不改产品接口、模型回执、提示词、Skill、常驻图层上下文、UI、权限、hook、修订校验、数据库结构、交接机制或模型型号。不做对话截图/地图布局验收，不部署，不使用正式任务数据。

本轮无已知ID/未知ID A/B、无第二模型对照、无自动答案裁判、无按用例补丁、无自动全图查询。若完整流程证据仍不能区分原因，明确未决，不自动扩张试验。上一轮冻结错误调用的成绩与本轮自然流程仅并列展示，不计算“修复提升率”。
