# 完整查询流程测评设计

2026-10-17 · 待审阅；以下是拟执行步骤，不是新测评结果。

## 1. 本轮究竟回答什么

上一轮：用户问题 + 已经发生的错误调用 + 真实结果 → 模型能否纠错。

本轮：用户问题 → Agent自主发现图层/对象 → 自主查询或补查 → 最终回答。

本轮不改变产品表达。关注三个可观察的区别：

1. 首次没有ID时，模型是先发现、有效命中，还是把业务范围遗漏后直接作结论？
2. 工具已经返回ID与实际范围后，模型是否正确利用；需要更多证据时是否行动？
3. 已有足够且正确证据时，是否仍发生范围扩大或错误转述？

这能定位具体失误，不能读取模型内部原因。说明冗长、上下文干扰、模型过度自信均只作为待验证假设；不得根据一次失败直接写为已证实根因。

## 2. 产品与运行基线

- 基线：main `8cab905b3f14a201e7b8dadce5a651f115be8cde`。用户批准后重新核对；产品/工具/Skill/运行时若有变更，先展示差异并重新冻结，不悄悄套用本设计。
- 模型固定 `deepseek-flash`，沿用原生 `controlledStream` 的 thinking disabled。测试进程显式使用现有配置项将单次最大输出设2048、单模型请求时限60秒；不写回项目.env或线上模型设置。这是成本边界，与上轮S1相同，不冒称生产默认输出上限。
- 现有 `PiLab.start` → 工具 → 服务 → hook → 后续推理，继续完整运行；没有新的Agent循环，没有在provider入口重写messages或工具结果。
- 本机独立正式身份环境，复用 `startMapTrial(..., serveWeb=false)`；`LAB_EXECUTION_ENABLED=false`，不需要Docker或生产服务器。原有任务、席位与来源背景仍由夹具产生，不为做题改系统目标；用户问题明确指本会话地图标注。
- Skill目录保留，模型可以自主调用skill_read；不强制加载或禁止加载。记录每次是否实际读取和当时工具定义，不把未读Skill当作唯一失败原因。
- 保留正常原生重试。源码 `lab.ts` 配置Agent级自动重试最多3次，`controlledStream` provider级maxRetries=0；所有HTTP尝试都计预算，单列技术重试，不能谎称整个循环没有重试。测试人员不重新运行失败样本。

## 3. 固定场景：3例各5次，15条完整场景

按repeat=1..5，每次依次F1→F2→F3；每条使用新环境/任务/会话，F2在该条内部共享任务。题目、数据生成规则和评分在第一次付费调用前冻结，UUID、时间及实际模型输出自然变化。不借用前一条模型记忆。

### F1：只知图层名称，查图层内页面（原G02-order）

用户原话不变：

> 请只展示本会话地图“仓储设施”图层按保存顺序的第4～5项摘要，说明这一页有哪些对象。只查看，不修改。

准备：直接复用 `prepareCase(manifest,'G02-order')`，顺序为维修设施2项（机修站、电修站），再仓储设施5项（北仓、南仓、河畔仓、东仓、山脚仓）。自动上下文只含现行草稿元信息；不额外提前告诉模型storage。

步骤：通过现有消息HTTP入口发送一次原话，等待原生循环完成。模型自行选择摘要、字段和分页；不预置offset=3/limit=2，不给模型喂上一轮错误调用或答案。

正确结果：东仓、山脚仓，顺序为仓储图层第4/5项。若附带数量，应为该层5项；不能把南仓、河畔仓说成该层第4/5项。

允许路径：先读全7项摘要，再按真实图层和保存顺序自行筛选；或先从layers识别storage，再筛选分页；或合法精确读取。**不要求一定两次调用或一定带layerIds。** 若猜测ID后实际成功命中并获得足够证据，不直接判失败，但记录“调用前未见ID映射”，不倒推为宿主早已提供。

### F2：引用A的甲，对照B的甲（原B02比较子流程）

比较原话不变：

> 比较引用对象与本会话对应对象的备注，只说明差异，不修改。

准备与真实历史：

1. 通过原服务/HTTP准备共同发布基线P0，含甲、乙，备注均为“基线备注”。A/B属于同一个筹划席账号、同一任务的两个独立会话；不是多个用户共享登录测试。
2. 各自从P0派生独立草稿，沿用原标题和保存步骤。A的甲改为“A 现场讨论”由服务初始化完成，记录真实回执和固定ref；A的乙仍存在。初始化不算Agent完成，A没有伪造对话。
3. 在B通过真实Pi执行前轮原话：“把本会话集合点乙备注改为‘B 保障讨论’，保留其余内容。”只允许该前置阶段的明确编辑。核对B仅乙备注变化、A不变；保留全部原生对话和回执。失败不人工修好后继续。
4. 在同一B会话，通过现有 `annotationRefs:[{...A固定ref,objectIds:['point-a']}]` 发送比较原话。这是正常用户引用入口，宿主按现行规则解析，不预先注入note值或假工具结果。
5. 查询/比较阶段独立核对A固定版本、A/B草稿头/内容、绑定、发布版和任务当前均不变。

正确结果：引用A版本甲为“A 现场讨论”，B甲为“基线备注”；只比较、未修改。不得把A局部读取的total=1说成A整个版本只有甲或不存在乙。模型可自行读两边、使用compare后按需读值、或读取足够摘要；不强制不对称范围或强制对齐。

这是原B02的**模型比较子流程**，保留B实际前轮历史；不声称重跑完整桌面B01→B02，也不执行原B02后面的再次编辑、来源刷新和UI固定引用回看。

### F3：新图层名与ID，目标位于默认首屏以外

用户问题冻结为：

> 请只展示本会话地图“应急补给”图层按保存顺序的第51～52项名称和类型。只查看，不修改。

数据：3层依次为“设备巡检”4项、“应急补给”58项、“观察记录”2项，共64项。目标第51/52项分别为“松林补给点”“湖湾补给点”，均point；其余名称、位置与ID在本任务夹具中冻结。采用无业务语义的合法图层ID，如`lyr-k72`，不沿用storage/repair；模型初始消息不含映射。其他对象名称不得与目标重名。

目的：避免把默认limit=50的首批摘要误认为完整图层；目标不在首次无筛选默认页中。正确结果只可能来自有效追加读取或一次覆盖目标的合法大页读取，不能凭隐藏答案命中。

正确结果：松林补给点、湖湾补给点，类型point/点；若额外报数，目标层58、整图64须分清。可以先查layers后筛选、直接读取limit=100的完整基础摘要后筛选，或其他有完整排序依据的路径；不要求成本更高的固定调用模式，也不为了减少冗余禁止合法全摘要。

## 4. 证据和评分

每条留存：

- 初始化数据/实际回执、独立真值、固定ref，置于模型工作区以外；账号密码和cookies不导出。
- 实际用户请求body、首次及每次provider JSON（无headers/凭据）、工具schema、模型/Skill/产品文件hash；证明没有预置坏调用或新readSummary。
- 全部原生工具请求、返回及isError，助手中途文字与最终文字，模型可见的每个ID映射首次出现在哪一步；原生会话文件、HTTP事件流和脱敏provider响应。
- 每阶段前后快照、业务副作用、引用是否保持固定、调用数、技术重试、模型主动补查/纠错、时延与token用量。

观察路径按事实标记：发现性查询／目标查询／必要补查／重复读取／不必要字段；首次宽查询不自动记错误。只有模型把不足的证据当作满足目标并输出结论，或实际错误参数导致拒绝时，才分别标记推理失败/工具调用错误。

评分至少分列：前置准备、主问题最终正确、完整回答准确、所有中途可见文字准确、有效补查、无必要确认、明确错误、歧义、冗余、工具错误/恢复、技术失败、写入尝试、状态变化。中途有明确错误但最终改正：业务结果可成功，严格通过仍失败，同时记录自我纠正。

同一输出可以“查询正确但解释错误”；服务succeeded、页面有按钮、工具receipt有效都不是语义正确的替代。若没有出现自然错误路径，则“纠错能力未覆盖”，不能用无错误推断能纠错。

分母固定报告：整体严格通过/15、各例/5、业务成功/计划条数、实际进入比较的F2条件结果、技术未完成和未执行数。旧S1是固定错误上下文的续答，本轮是自然路径，不能将本轮得分减去旧40%来宣布产品变好。

至少两份逐条复核（若实际只有一份须声明），先匿名试次ID评分再合并。复核者必须看到用户问题、真实调用/结果和全部可见回答，不能只给“标准答案+最终一句”。分歧保留，不根据得分调题。

## 6. 次数、成本和停止边界

- 固定15条场景；F1/F3各5个用户请求，F2每条前置编辑+比较最多2个请求，共最多20个用户请求。
- 每条最多6次实际provider请求，F2前置+比较合计计算；包括子Agent、压缩、原生技术重试；总上限90次。请求前在测试驱动层计数并拦截超额外发，随后取消现有请求，不向模型补写“成功工具”。
- 单模型请求60秒，每条场景累计360秒。累计输入含缓存200万token、输出6万token；每次外发预留2048输出，不足则停止。输入是实报停止阈值，最后一次可能越过，必须披露；usage缺失不能当0，停止后续外发。
- 已失败试次不重跑/替换，不调整题目、数据或提示直到通过。普通语义失败完成剩余固定独立样本后统一报告；技术错误保留原生有界恢复，最终失败则记技术失败。鉴权/额度故障、证据缺失或持续不可用停止整个批次，不重建成功批次掩盖。
- 发生不在该阶段用户授权范围内的写入尝试、实际副作用或越权，立即取消并停止全批，保存真实回执与状态；取消可能晚于提交，不能声称取消就未写入。查询阶段不删除写工具或修改权限来让“0误写”看起来通过。
- 弹出意外ask_user/确认按现有ask取消；纯文本“需要我再查吗”也计阻塞确认/未完成。不要模拟用户补答。F2前置编辑只准改乙备注，其他变动为副作用。
- 报告停止位置及未执行样本；样本不足不得宣布15条验收完成。预算未用满不是追加实验授权。

## 7. 如何根据结果决定下一步

| 自然流程证据 | 可以提出的下一步 | 不可直接下的结论 |
| --- | --- | --- |
| 多次未取得目标ID便停止/错答 | 单独审视名称发现的操作成本与入口 | 不能认定必须把完整图层目录塞进常驻prompt |
| 已见ID仍未筛选且证据不足 | 分析该次计划、参数和继续执行决策 | 不能再归咎于“模型不知道ID” |
| 查询/证据正确，叙述却范围扩大 | 限定为解释一致性缺陷，讨论必要精确信息的程序展示 | 不能当服务筛选bug，也不自动追加摘要 |
| 必要补查前再次确认 | 分析当时权限/说明和行动选择 | 不直接扩大地图写入授权 |
| 自然流程全通过 | 本批未复现；旧错误恢复问题仍保留 | 不能宣称旧问题消失或整个系统准确率100% |

本轮不自动接续修复或第二模型对照。若证据不足以选择一个具体修改点，直接报告未决；用户再决定是否继续研究。
