- 调度：24 题 × 四组 × 三次 = 288。每组 72 项；四个执行位置各占 18 项。第一轮前 12 项为 Q07、Q08、Q20 各四组，已包含在正式预算内；第二、三轮仍各覆盖完整 24 题。
- 题目：`case-specs.json` 的用户原句从已批准的 `tasks.md` 提取；Q10 按方案沿用 Q09 的问法。所有材料明确标为构造样本，独立答案留在评测端。
- 来源：Q01、Q02、Q03、Q14 通过真实 HTTP 查询，核对返回对象与来源数据快照一致，且来源目录名称一致。
- ID 提示：Q15 在 GT、GST 的真实读取中返回对象 ID 提示；G0、GS 不返回。Q16 的部分名称命中不会触发该提示，四组均核实。
- 分页：Q17 在四组均真实读取 offset 0、2、4、6，每页最多 2 个，共取得 7 个不规则名称；核对无缺页、无依赖名称规律补全。
- 用户编辑：Q22 通过真实用户 API 移动 `origin`，生成后续轮使用的新版本，保持 current 和 publications 不变；重复执行该编辑被拒绝。只豁免预定用户动作，Agent 的其他修改仍判越权。
- 澄清：Q01、Q13、Q20 使用固定选择；已经明确的参数只重述题干，不补充答案。未知问题标为不确定，交给 runner 停批。识别流程不使用正确答案判断是否完成。
