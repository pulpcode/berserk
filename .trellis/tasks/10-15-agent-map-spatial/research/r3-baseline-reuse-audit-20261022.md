# Research: R3 原版组能否复用 R2 记录

- Query: 已测过的原版记录中，哪些可以直接替代当前 R3 原版槽位，减少付费调用？
- Scope: internal
- Date: 2026-10-22

## Findings

**按当前冻结题目和准备配置，精确可替代数是 0 / 48 个 R3 原版槽位。** 不是旧记录丢失，也不是产品代码改了：R2 原版的 493 份索引原始文件均存在且 SHA256 一致；R2 原版 runtime 的 246 个文件与当前产品逐文件相同。不能替代的直接原因是题目/轮次、背景和加载条件改变。

### 核查方法与数量

1. 读取实际 R2 批次 `.local/spatial-r2/live-20261018-r2-01/protocol.json`，确认原版只有 16 项，均为显式选择一个 Skill。
2. 只导入 R3 `cases.ts`、`holdout.ts` 的声明（没有导入运行入口，没有发起 HTTP 或模型请求），将 24 题的完整 `prompts` 数组与实际 R2 protocol 中全部 16 个提示数组逐项比较。**24 题均无完全相同的提示序列**。
3. 核对 R2 `runtime.start` 未传 background 选项，而 R3 `prepare` 明确传 `background:'neutral'`。这改变模型可见的任务标题、目标、席位职责；即使问题文字接近也不是相同上下文。
4. 依据 `research/r2-evidence-index-20261018.json` 检查路径含 `-baseline/` 的 493 个文件：缺失 0、哈希不匹配 0。它们包含 provider 输入/SSE、原生会话、fixture、前后状态等。
5. 将 R2 `runtimes/baseline/runtime-integrity.json` 的 `after` 246 个条目与当前 `experiments/harness-lab` 同路径 SHA256 比较：缺失 0、不同 0。不能把本次需补测归因于不存在的产品代码变化。

| R3 原版槽位 | 数量 | 可直接复用 | 决定性差异 |
| --- | ---: | ---: | --- |
| 开发题 × 显式加载 | 20 | 0 | 所有完整提示序列均有变化，任务背景从 original 改为 neutral；部分题还改变选中的 Skill、轮次或交互 |
| 保留题 × 显式加载 | 4 | 0 | 新坐标、图层、属性和组合目标，旧批次未运行 |
| 开发题 × 原生按需加载 | 20 | 0 | R2 没有对应原生加载组，且提示和背景已变 |
| 保留题 × 原生按需加载 | 4 | 0 | 新题与新加载条件 |
| 合计 | 48 | 0 | 同题族不等于同实验条件 |

### 对执行安排的建议

当前144项方案不能通过把R2成绩粘进48个原版格子来省调用。可以把旧结果作为历史诊断旁证，保留原评分和原口径。若要降低本轮总量，必须在开始付费前明确减少或重设计部分题目/条件；那是缩小研究范围，不是“相同条件下复用”。本审计不擅自改题、改样本或重新评分。

原版工具代码/Skill与R2相同，是有利于历史解释的证据；但不能抵消新提示、背景、加载策略和时间差。模型参数名相同也不能证明服务端版本/随机结果完全相同，不应宣称历史批次是同批随机对照。
