## 三组如何隔离

三组从同一个完整产品 archive 构建：`b56de822cec4ee2519ac8a24eb307a6230cac29d` 的 `experiments/harness-lab/{src,scripts,fixtures,package.json,package-lock.json,tsconfig.json}`。共享同一已安装依赖，要求工作区 lockfile 与该基线字节一致；额外记录安装目录 `.package-lock.json` 的哈希。每组创建新目录，拒绝静默复用部分构建。

| 组 | 相对同一 archive 的唯一变化 |
| --- | --- |
| E0 | 无变化 |
| E1 | 两份 Skill 正文替换成 R5 的 `candidates/E1` |
| E2 | 两份 Skill 正文替换成 R5 的 `candidates/E2`，再复制下列 12 个后端文件 |

E1/E2 的两份方法是 `map-annotations`、`spatial-analysis`。frontmatter 与基线逐字一致，因此方法 ID 和目录简介不变。实际受控加载器校验正文，并核对原始内容 SHA-256；`synthesis/review` 不变。每题显式选择的目标方法仍由任务用例决定。

这是一组最小的后端依赖，不复制当前整个 `src`。不包含 UI 改动。全部文件的新增、删除、内容变化使用 before/after 哈希集合核验，实际差异必须恰好等于上述组别白名单。

三组 `lab.ts`、`resource-tools.ts` 均保持原基线字节；不引入 R5 的 Skill 参数候选。E2 工具导入了 methodAdvice helper，但基线宿主不传 `skillIds`，默认空列表使该提示不生效。离线真实回执已经验证这一点，而不只依赖源代码推断。

**E2 是“新增工具能力与相应用法映射”的组合。** E2 的 Skill 正文需要说明新参数和操作，故 E2−E1 不能称为纯工具因果效果；E1−E0 才只改变方法正文。本运行时不自动扩展试次、改写评分或安排真实调用。

## 供执行器冻结的接口

`r6-20261022/runtime.ts` 导出：

- `buildRuntime(directory, group)`，group 为 `E0 | E1 | E2`；返回原有 `Runtime` 形态：`root/hashes/start/skills`。
- `repo/packageRoot/root/digest/hashes/save/selectionFor/offlineEnvironment/loopbackOnly`。
- `baselineRevision/treatmentPaths/runtimeSourceFreeze()`。

`runtimeSourceFreeze()` 返回基线 commit/tree、12 个输入后端文件哈希、4 份候选正文哈希、基线一致的 lockfile 哈希和安装依赖 lock 哈希。构建前后再核对该对象没有变化。

每组 `runtime-integrity.json` 保存 `archiveHash`、精确 `allowedDiff`、`freeze_inputs`、完整 before/after 文件哈希。返回的运行时哈希还包括此记录，供执行器在每题前后检查运行时漂移。实际执行器另外冻结 R6 驱动及历史依赖文件，不把候选文件送入产品模型工作区。

## 离线验证结果

`runtime.test.ts` 使用真正的隔离服务、认证 HTTP API、原生 Pi 循环和 provider 传输适配。外网 provider 被假 SSE 完全替代；其他网络仅允许 loopback。三个运行时各两个显式选择请求、7 次假 provider 循环，总计 21 次，全部通过。

验证内容：

1. 三组 archive 哈希、lockfile 哈希一致，各自只发生预定白名单变化。
2. 两种目标方法各自显式选择的真实正文进入 provider 输入；实际目录描述和哈希与各组运行时一致。
3. E0/E1 拒绝新的 `objectNames` 参数与 `classify_points` 操作；E2 精确查询返回唯一名称对象，并把独立矩形夹具的内部、边界、外部三点分别正确分类为 1/1/1。
4. 所有组都真实触发 `ANNOTATION_READ_REQUIRED` 和 `SPATIAL_UNSUPPORTED_GEOMETRY`；回执不包含 `methodAdvice`，保留原错误码、outcome 与缺少 draft 的资源信息。
5. E0/E1 provider 工具定义完全相同。E2 的工具名称与数量相同，只有 `annotation_read` 和 `spatial_analyze` 两个定义不同；`skill_read.id` 仍是原始 string schema。
6. 原有测距在三组得到完全相同的数值与单位，仍输出 v1；E2 分类使用新 v2。检查结束草稿仍为 revision 1，失败编辑没有修改数据。
7. API 检查前后运行时文件哈希完全一致。
