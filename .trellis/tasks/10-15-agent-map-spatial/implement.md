### 4.2 三组对照

借鉴 MapLibre Agent Skills 的有无 Skill 对照思想；以下运行时对照及空间结果评分由本项目自行建设，具体参考边界见 [设计第 14 节](design.md#14-参考依据)。

| 组别 | 条件 | 回答的问题 |
| --- | --- | --- |
| A：只有工具 | 提供同一版本的全部空间工具及说明，既有 Skill 正常可用；不注册或加载新增 spatial-analysis | 模型凭工具说明原本能完成多少，哪些错误需要新增指导 |
| B：明确加载 | 通过现有显式 Skill 选择/请求资源机制，确保同一版本 spatial-analysis 正文实际进入模型上下文 | 在加载成功的条件下，Skill 内容能否减少方法选择、步骤和解释错误 |
| C：按需发现 | 注册正常 Skill 目录，不预先选择 spatial-analysis；由 Agent 在正常 Pi 流程中自行发现和加载 | 实际产品入口中是否在需要时加载，是否出现误触发，效果能否保持 |

三组保持相同模型/提供方、生成参数、工具及工具说明、用户问题、身份权限、数据快照、既有 Skill 和执行预算。只改变新增 Skill 的可用性及加载方式；不为 A 组删减工具说明或加入不利提示。B 组不另建系统提示注入通道；C 组保留原有发现机制。

每个试次使用独立会话及隔离数据，避免前次答案或草稿污染。记录实际模型配置、代码/工具/Skill/夹具哈希和全部失败；按预先确定的顺序交错运行三组，降低提供方时段变化的影响。若工具契约改变，重新产生可比较的基线，不把旧 A 组与新 B/C 组直接计算增益。

分别记录 B 组正文是否进入上下文、C 组是否通过原生资源读取加载、何时加载以及实际版本。未加载但答对可记为任务正确，不能记为 Skill 带来的改善；需要加载的规则场景应另记加载失败。负向请求不要求调用空间工具；如加载了 Skill，也单独记录误触发和成本，不混同于计算错误。

### 4.3 样例与独立预期

首批拟定 24 个逻辑用例，每组每例预先安排 3 个独立试次，共 216 个试次；这是已批准的验证预算，按冻结版本执行。每个试次可包含正常工具循环，但不得反复重开直到成功。实施前冻结时间和调用上限；报告所有预定试次的完成、失败及未运行情况。

| 用例集合 | 数量 | 必须覆盖的内容 |
| --- | --- | --- |
| 开发集：基础方法 | 6 | 两点距离、点到线距离、折线长度、面积、关系判断、区域筛选；同时覆盖明确和隐含请求 |
| 开发集：组合方法 | 6 | 缓冲→筛选→统计、属性与空间条件组合、先排除再取最近、同距排序、固定结果续问、预览后保存 |
| 开发集：边界与负向 | 6 | 对象歧义、缺几何/属性、不完整或失败来源、完整但无命中、最近与最快的区别、只改名等非分析请求 |
| 保留集 | 6 | 未参与 Skill 调整的对象名称、位置、几何布局和问法；至少包含组合分析、边界、负向请求；地域覆盖中国与澳大利亚 |

用例可包含多个断言；它们不替代第 4.1 节的确定性、权限、历史和浏览器测试。保留集及评分答案放在模型执行工作区之外；Skill 只能包含一般规则与独立示例，不包含这些用例的答案、对象 ID 或坐标。保留集一旦用于修订 Skill，应归入开发集并补充新的保留用例，原结果仍保留。

每个用例预先记录：用户意图、允许访问的对象和版本、预期对象集合/数值/几何、必要步骤依赖、允许的等价方法、禁止的结论或写入、正确的澄清/停止行为，以及对应 M 规则和 AC。对于边界歧义用例，发出必要澄清即是正确行为，不强制要求完成计算；驱动不得自动替用户回答未定义的问题或批准未授权操作。

预期值由独立已知样例、人工核算或经审阅的另一参考实现生成，记录方法和误差；集合、版本、权限和保存结果使用明确断言。不能用被测函数生成自己的标准答案，也不把另一个模型的评分当作几何正确性的唯一依据。

### 4.4 评分与失败归因

| 评分维度 | 核对的可观察证据 |
| --- | --- |
| 对象与范围 | 查询和计算实际使用的对象身份、候选集合、版本、来源及完整性 |
| 方法与步骤 | 操作是否适用，单位/阈值/关系正确，过滤与排序依赖满足；接受满足契约的等价调用链 |
| 数值与几何 | 数值在独立容差内，对象集合正确，缓冲/显示几何符合契约；有工具成功回执仍需核验 |
| 解释 | 回答是否符合实际范围、时间、单位和缺口；是否把最近误说成最快，或把缺数据误说成零命中 |
| 加载 | 正文进入上下文或实际读取的证据、按需触发覆盖、无关请求误触发 |
| 副作用与展示 | 无保存请求时不写入；保存和预览使用同一结果；业务对象和历史未被意外修改 |

前四项及适用的副作用/展示断言全部满足，才记为一次语义成功；正确的澄清、明确不支持或数据不足提示可按预设标准判为成功。语义成功率按“语义成功试次 / 已执行试次”计算，同时披露预定试次数；存在未运行项时不能声称该组完成验收。权限或数据完整性等关键失误不得被其他分数平均抵消。

另行报告加载率、误触发率、工具调用数、耗时和可取得的 token/费用数据，不预设只有更少调用才正确。区分“Skill 未加载”“方法选择错误”“参数/步骤错误”“工具或数据故障”“解释误报”“保存/界面错误”；不将所有失败归咎于模型。

评审以实际工具轨迹、结构化结果和原始数据为准。模型裁判只能辅助检查文字表达，关键结论需人工核对或程序断言；不采集或依赖私有推理过程。错误报告保留原始请求和失败，不通过隐藏重试提高成功率。

### 4.5 拟定验收门槛与结果报告

以下是本项目提出并随方案批准的门槛，不来自参考项目的成功率，也不是已取得的成绩：

1. **系统正确性**：AC1—AC9 的确定性、契约和相关浏览器检查通过；M1—M11 均有对应规则及用例，参考方法与自行建设部分可追溯。
2. **关键错误**：B/C 组所有已执行试次中，越权、伪造对象/几何、未授权写入、把不完整数据声称为完整结论等关键错误为零；发现即阻止验收，修复后作为新版本重新验证。
3. **任务质量**：B/C 两组各自总体语义成功率至少 90%，保留集分别至少 90%；边界与负向用例的关键行为全部正确。同时报告基础、组合、边界与负向各类分母和失败，不只给总分。
4. **Skill 增益与退化**：逐用例比较 A/B/C；B 应减少被其规则针对的已观测错误，C 应能通过正常发现流程取得效果。对预先标注需要加载规则的用例，C 组在相关分析前读取正确版本的比例至少 90%，与任务成功率分开计算；不要求每个简单问题都加载 Skill。B/C 不应相对 A 出现总体净退步或新增关键错误。若 A 已表现良好或未观察到增益，明确记录“未观察到改善”，精简重复指导，不能宣称 Skill 已提高可靠性；任务正确性仍须达标。
5. **证据完整性**：按预定试次报告成功、失败、超时和未运行；未运行不视为通过。环境/提供方故障单独标识，不静默删除；补跑属于额外记录，不覆盖原失败。小样本结果只支持当前固定条件，不能推断通用可靠性。

实施后在本任务的 `research/` 下保存参考与规则映射、冻结的用例清单和评测报告；运行原始证据沿用既有隔离测试产物机制。它们是测试资料，不是产品的新持久化系统，也不加载到模型工作区。

报告至少列出：代码/模型/工具/Skill/数据版本，预定与实际运行数，三组整体及分类结果，保留集结果，配对改善与退化，实际加载与误触发，关键失败和未通过项，是否有足够证据保留各条 Skill 指导。没有执行结果时填写“未执行”，不得将计划中的门槛写成测试成绩。

## 7. 风险与回退检查点

- **计算精度和性能**：在发布能力前冻结容差与规模上限；超限明确失败。若需要 worker，只隔离纯计算，不新增持久任务队列。
- **历史兼容**：新 Skill 或结果产生后，旧二进制可能不能读取；预先准备兼容读取版本，不能随意降级。
- **复杂面保存**：首版限制需随设计获审；不得靠丢弃内环或面积来“兼容”。
- **权限继承**：派生几何不能脱离来源授权，公开回执不得暴露私有引用。
- **并行冲突**：同步前检查工作树；避免在不同分支同时重构公共模块。
- **自然语言误报**：程序校验无法保证模型解释绝无错误；真实模型验收单独评分。
- **参考迁移与 Skill 无效**：参考项目的模型、数据和加载方式不同；按三组对照及保留集验证。没有增益的指导可精简，不通过加长提示词掩盖工具契约问题。

本期不建设新结果数据库。回退时保留新历史读取和已保存标绘访问能力，可停用新分析/保存入口；数据迁移如在实现中被发现确有必要，须先更新设计和回退计划。
