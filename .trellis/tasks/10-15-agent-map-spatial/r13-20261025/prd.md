# R13 需求与验收

状态：方案待审。用户只授权规划与落盘，未授权实施、真实调用或提交 Git。审阅入口为 [plan.md](plan.md)。

## 目标

判断同一 Flash 模型在关闭推理与请求开启 high 时，从用户任务开始，经真实工具执行到最终答复的正确性和成本差异，解决 R12 单步观察不能判断任务完成效果的问题。

## 要求

- R13-R1：五项去重任务、两个配置、各一次，共十次完整运行；固定正常按需 Skill，不增加 Skill 版本或加载分组。
- R13-R2：有效工具请求继续真实执行；多轮任务覆盖全部预定用户要求，不在第一条工具调用处结束。
- R13-R3：两组独立且业务等价的初始环境；使用同一代码/Skill/权限/工具。旧成绩、历史路径和隐藏预期不作为新模型输入。
- R13-R4：先离线检查实际推理配置、SDK 历史回传、循环与预算；真实调用必须等用户批准本方案。
- R13-R5：保留原失败和完整证据；无自动重跑、追加、改题、付费裁判或用历史通过替换新对照。
- R13-R6：按任务报告必要结果、全文事实、状态边界、未完成原因、Skill 行为和成本；区别技术完成与语义正确。
- R13-R7：不改产品默认行为，不修改 Skill、空间计算和业务权限，不合并或部署。

## 可观察验收

| 验收项 | 可观察证据 |
| --- | --- |
| 工具闭环真实运作 | 模型工具请求、匹配 call ID 的真实回执、随后请求可串联；无伪造输出 |
| 多轮完整覆盖 | F02 三轮、F04 两轮，其余各一轮；没有遗留未回答的工具请求被当作通过 |
| 两组条件有效 | 初态规范化一致、代码/Skill/工具哈希一致，实际请求只有声明的推理配置和自然产生的历史差别 |
| 只读及授权保存正确 | 非保存题业务状态不变；F04 第一轮不写入、第二轮只保存最初固定范围且不发布/采用 |
| 证据与用量完整 | 所有发送先登记，全部模型请求计入同一预算，原始响应、轨迹、状态及未知用量完整保留 |
| 成绩可复核 | 每题原句、当时可见依据、判定和歧义记录；程序与 Agent 复核不冒充人工金标 |
| 停止范围明确 | 不因正常工具调用中断；总预算及技术异常规则生效，无隐含重试或第二轮 |

本轮完成不等于模型效果通过。正式整体及保留集 90% 门槛保持；本轮五类开发题不承担正式验收。是否后续扩大验证，按 plan.md 的配对证据条件报告，不自动执行。

## 范围边界

本轮不做来源指引改写、第二模型、两种 Skill 加载方式的四组实验、旧三份工具请求的单独补跑、新保留集建设、路网/专业决策或线上升级。预算与具体题干在 plan.md、design.md 固定，执行步骤在 implement.md。
