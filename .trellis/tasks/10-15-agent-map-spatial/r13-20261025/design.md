## 1. 固定共同基准

从 `6a631a42b99b01de334cd2017c07bf0d9d58a560` 归档创建两组评测运行时。两组使用该提交的两份 Skill 和工具描述；当前工作区的 R12 三项来源指引候选保留，不拷入新运行时。

相同业务规则、普通原生 Skill 目录与 `skill_read` 入口，不进行预加载。逐次记录目录可见性、实际正文读取及首次关键操作前是否读过。主动读取率不作为单独通过门槛。模型可以按实际需求选择查询、读取或计算，不要求复现 R12 原工具序列。

安装依赖必须匹配固定 lockfile，记录 Pi 版本和相关文件哈希。保留原 HTTP/Pi 执行、权限、标绘/空间工具及状态管理。不得建立另一套工具调度、模型事实状态或伪造服务来让题目通过。

## 3. 业务环境与样本重建

使用现有 `startMapTrial`、准备夹具与真实 API。每个槽位新账号/会话/草稿/来源实例，禁止重用 R11/R12 的活会话或向旧版本写入。不得把旧空间结果缓存导入新会话；F02/F04 的固定 resultRef 必须由该次 Agent 自己产生。

从旧 fixture.json 复用业务数据，不复用模型回复或隐藏 truth 字段作为可见材料。配对准备记录允许归一化的正式身份 ID、服务端口、合成日期/时间戳映射；图层 ID、对象名、几何、属性、权限、可见来源、工具 schema 与初始业务状态必须等价。规范化后的业务快照哈希相同才发请求。统一固定业务日期，不在两组之间自动更新来源。

F03 对应的 `Q05-1-S0-P`、`Q05-2-S1-P` 已离线确认原始 prompts 与完整标绘 document 完全相同，故合并。F05 保留悉尼坐标；其余草稿题保留原中国沿岸坐标。来源系统 F01 保留原合成来源数据，不声称本轮进行了两国底图或显示验证。

## 4. 完成、澄清与中断

原生 Pi 负责工具选择、实际执行、工具错误返回和继续模型调用。驱动只负责初态、预定用户消息、证据及预算，不因看到答案不正确而自动追问或重新提示方法。

某个用户轮次返回最终答复且原生会话无待执行工具/交互，才推进下一条预定用户消息；前序轮次错误保留。前序已越权、服务异常或缺少继续所必需的真实状态时，记录具体原因，不捏造 resultRef 或保存回执。

普通澄清或 ask_user 若只确认题干已明确的来源/对象/是否保存，可仅重述原文一次；允许映射的问题类别和固定答复须在实施离线检查中冻结，未知问题不得由主会话临场代答。权限批准与事实澄清分开，禁止任何任意审批。有效空间/标绘工具返回的参数错误可继续修正；HTTP/网络失败后的自动重发被预算/尝试账本阻止。

状态区分：planned、started、运行已结束待评分、等待用户、协议/工具环境异常、预算耗尽、截断。不得将原 `needs_evidence` 当作完整流程自然终点。`stop` 有正文仍需审查是否完整；length 单列截断，不自动补一句“继续”或算正确。

## 5. 预算与证据

计划额度及完成预留以 plan.md 第6节为唯一数值来源。每个实际付费请求发出前登记，包含父、子、压缩和失败尝试；未知用量保持未知，禁止继续外发。模型的正常下一步请求与网络重试分别标识。

单次发送前，按实际请求体 UTF-8 字节长度加 4096 作为保守输入启动预留，另预留完整 32768 输出；该预留不是实际 token 用量。最终用量以 provider usage 为准，缓存明细不重复相加，reasoning 已包含在输出内。未知用量或实际用量异常超额均停止，不能按预估替代收费记录。

使用 R13 专属 freeze、固定十项 schedule、一次性批次标记和不可覆盖的结果目录；换目录不能重新发送已开始槽位。预算不继承 R12 剩余额度，R13 也不能修改旧 claim。不得输出密钥或鉴权头。

预计产物：冻结代码/参数/题干/初态清单，实际请求与 SSE，原生会话，完整工具调用及真实回执，逐轮前后状态，公开证据评分材料，按任务和组别的用量，逐条复核及总报告。私有思考保留原始技术记录，但不进入公开语义裁判材料。

## 6. 共同限制与回退

本轮样本是已知失败任务家族，每题仅一次，5 对不能证明稳定性；正常 Skill 加载让是否读取成为推理配置可能影响的流程行为，不是另一项独立加载实验。若性能变化发生，先按读取、来源选择、计算、状态与解释定位，不只归因思考长度。

方案待审阶段不创建运行时、不建立线上服务、不修改 Key。实施阶段如适配或离线检查不通过，停在离线；真实失败保留原证据，不恢复到一半继续伪装成同一成功任务。产品始终维持原配置，无产品回滚需求；后续上线另行评估。
