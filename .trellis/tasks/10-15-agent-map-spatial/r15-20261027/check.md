## 已修正的问题

1. **候选 Skill 没把图层筛选讲完整。** `candidate-skills/map-annotations/SKILL.md` 原来只排除了“按对象筛选”，仍可能将单个图层的读取说成全草稿。改为“完整且没有图层或对象筛选”；同步 `skill-candidates.json` 的哈希和长度。没有改旧 Skill。
2. **任务目录的 lint 被遗漏。** 在包目录检查外部路径会出现 ignored 提示。改用仓库根目录、显式指定该包 ESLint 配置后发现 `review-tools.ts` 的兼容参数未使用；以 `void _historicalIds` 保留调用契约，真实检查已通过。
3. **隔离草稿越权后澄清可能误停整批。** 初版要求 nativeCompleted 且无未映射澄清，导致只影响本题草稿的越权升级为批次停止。经主会话确认，由 runner 修正：请求必须已结束、同 requestId 的成功或已知澄清取消终态；来源、指令、绑定、发布状态和草稿身份均通过隔离核对，且没有全局故障，才仅判本题失败。普通澄清仍待定；真实越权原因保留，不用待定覆盖失败。最终 API 回归又发现较早 waiting_user 占用任务 stop 摘要，已改为确认本题隔离越权后用真实违例作为任务 stop，并在 precedingStop 保留原交互取消原因；对应四组通过。
4. **四组工具 schema 校验误把 Skill 目录文字差异当成污染。** 原生 `skill_read` schema 含 Skill 的名称和 description。由 runner 修正为：先核对两个受控 Skill 的目录描述与实际已加载内容完全相符，再仅归一化这两处描述；组内原始 schema 固定，跨组其余字段仍严格一致。原始请求不改写、原始 schema 仍归档。独立测试覆盖额外 schema 差异和错误目录文字。
5. **旧观察脚本漏识别新标绘封装。** `scripts/probe-map-result-projection.ts` 原来只识别 annotation v1，可能漏记 v2 的部分页。改用共享常量识别 v1/v2；新增实际 `annotationToolResult` 生成 v2 的测试及未知格式拒绝检查。它只影响诊断，不加入四组的六文件工具覆盖。

## 产品与实验边界核对

- 名称全不匹配时的 ID 提示只查已授权、固定版本、原图层范围，且只返回 objectId/name/layerId。提示不混进匹配结果、不泄露几何；部分匹配、名称与 ID 相撞、仅分页为空均不扩大范围。
- 标绘 v2、空间 v3 是模型展示封装。原始结果、几何、resultRef、持久化和历史 v1/v2 保持兼容；新封装逐字段验证数据和程序生成说明，未知字段或篡改不能成为可信结果。未知/失败回执不会得到成功说明。
- 数量按实际操作解释；本页、筛选总数、全草稿不混用。说明只描述本次执行/读取及对应结果，不推断内存、作者或全会话保存状态。
- 两个 Skill 的 description 和正文均为独立候选，工具使用方式与实际契约相符；覆盖来源和范围、ID/名称、局部计数、作者、方向和多结果状态，没有强制预加载或新增通用权限状态。
- 四组从同一 `6a631a42b99b01de334cd2017c07bf0d9d58a560` 归档构建。工具组只覆盖指定六文件；Skill 组只覆盖两个候选正文。四组数据规范化后完全相同，评分要求不注入被测 Agent。
- 请求采用原生 Pi 循环；不重写消息、工具历史或思考续传。全组固定 Flash enabled/high，预算共同记账。任务次数/工具次数/持续时间仅提醒；真实故障、无进展、批次预算和隔离边界保留停止条件。唯一批次标记禁止自动重试或恢复。
- 评分保留主任务、解释、严格、待定和未执行；严格必须与分项一致，已证实失败不能被待定遮住。盲评文件打乱且去除组名映射，思考内容不进入公开解释评分；实际 wire 与宿主真值分别说明。
