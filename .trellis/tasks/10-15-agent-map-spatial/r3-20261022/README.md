# R3：已实现的准备与本地验证，真实模型运行待审阅

本目录只用于离线诊断，不替换产品 Skill、目录、后端工具或模型。三组是原版、仅标绘正文调整、仅空间正文调整；每组分别检查显式选择和原生按需加载。两份 Skill 的简介、工具接口、模型参数保持一致。

## 已实现什么

- `cases.ts`：20项开发/回归题。复用已知合成事实，但为新问题独立写真值，不继承旧题的评分行为要求；全部标为开发题。
- `holdout.ts`：候选正文冻结后独立编写的4项新组合题。候选编写者未读取这些题；评测作者未读取新候选正文。代码核对冻结哈希，候选若再调整，本保留集即不能继续当未见新题。它只有4题，不能证明90%的稳定可靠性。
- `runtime.ts`：复制隔离产品运行目录，仅允许目标 Skill 正文变化；保持原生 Pi 和后端。运行时文件哈希、正文哈希和实际目录均可核对。
- `prepare.ts`：**只准备**。为24题×3正文组各建立独立临时账号、任务和会话，验证两种选择配置，共72份夹具；不发送用户模型消息，不调用真实模型。输出的真值只在评测目录，未放进模型工作区。
- `audit.ts`：核对实际 provider 输入的系统目录段、完整正文、请求顺序和关键决定所在请求。记录“已经送达”，不能证明模型理解或遵守。
- `http-probe.ts`、`native.test.ts`：实际 HTTP/Pi 流程接入本地假 provider，检查两种 Skill 的两条加载路径、提问与回答、跳过、取消、未回答、冲突和固定结果保存。假回复只验证程序接线，不能作为模型成绩。
- `scoring.ts`、`review-rubric.md`：独立审阅者判事实，程序检查槽位、汇总严格通过、主任务完成、边界完成、未定、中断和额外麻烦。不存在“调用了工具就通过”的规则。

## 怎么运行本地检查

以下命令从`experiments/harness-lab`目录执行（空间worker按此工作目录解析tsx），不读取`.env`，不需要模型密钥。

```sh
./node_modules/.bin/tsc -p ../../.trellis/tasks/10-15-agent-map-spatial/r3-20261022/tsconfig.json
node --import tsx --test ../../.trellis/tasks/10-15-agent-map-spatial/r3-20261022/scoring.test.ts ../../.trellis/tasks/10-15-agent-map-spatial/r3-20261022/native.test.ts
node --import tsx ../../.trellis/tasks/10-15-agent-map-spatial/r3-20261022/prepare.ts prepare-only /private/tmp/NEW_UNIQUE_R3_DIRECTORY 4528
```

Lint单独从仓库根运行，防止ESLint忽略包目录之外的本任务文件；零警告才算通过：

```sh
./experiments/harness-lab/node_modules/.bin/eslint --max-warnings 0 --config experiments/harness-lab/eslint.config.js .trellis/tasks/10-15-agent-map-spatial/r3-20261022/*.ts
```

预检输出目录必须不存在。所有外部请求被拒绝；本地测试仅在内存中模拟 DeepSeek SSE。真实用户回答通过现有 interaction response API；未注册的意外提问会取消，不自动选第一个。预设“未回答”先核实真实 pending，再为了测试清理而取消；记录同时保留这两个事实。模拟回复不是人类真实参与，也不授权写操作。

准备程序的72份夹具与下述144个拟议模型槽位不同。未来真实运行必须每槽全新隔离实例，不沿用预检会话、前一组模型历史或前一题的发布状态。准备记录使用当前合成日期并留档，没有沿用2026-10-18日期锁。不得跨日运行后宣称时间条件不变；真实协议需冻结或检查同日。

## 还没实现、不能直接开跑的部分

**本目录没有真实模型运行入口。** `contract.json`是待审建议，不是已授权执行清单，也没有由准备程序执行其中预算限制。真实评测前仍需：

1. 用户审阅题数、预算与停止条件，冻结源码/候选/题目/评分规则和具体槽位清单。
2. 接通实际 provider 的保存和预算计数、每槽新实例、原生历史/请求/结果保存，检查每次请求的工具 schema 和模型参数。
3. 按已审阅交互脚本处理真实提问，意外问题先停止；D16要在真实读取和保存之间注入冲突并保留证据，不能随意挑时机帮助模型。
4. 保存实际 provider 输入与输出、所有可见发言、工具错误和最后状态；运行前后核对冻结哈希，输出独立审阅包。当前真值和假模型测试不能替代这个执行器。

旧驱动有固定日期、可变全局预算和遇提问一律取消等限制，本轮不调用旧批量执行入口或Observer；仅复用安全的夹具/隔离启动，并从有CLI导入保护的旧入口导入SSE解析类。没有搭建新的通用评测框架。

## 待审阅的模型测试建议

建议先做**1轮144槽**：20项开发/回归题+4项新保留题，每题3正文组×2加载方式；每个“正文组＋加载方式”条件是24题。六个条件分别比较，不把它们混成产品正确率。开发和保留集也分别报告。不自动追加第二轮或重试失败。
