# R12 B：来源处理对照的执行约定

本文件说明已批准的 12 项 B 对照如何实现。它不扩大任务规模，不授权补测，不把离线假模型结果计入正确率。

## 比较什么

- B0：从 `6a631a4` 归档完整 harness 源码、脚本和夹具；不是 R11 的旧 S0。
- B1：同一归档，仅替换两份地图 Skill 的来源选择段和 `resource-tools.ts` 中 `source_list`、`source_read` 的说明。工具参数、算法、权限、模型和默认推理设置相同。
- 两组均在同一系统消息位置预加载各自两份 Skill 的完整原文。保存 Pi 原始输入、加入正文后的输入、实际发送的 wire payload 和正文检查记录。此对照只衡量指引送达后的执行，不衡量主动读取。
- 归档检查列出 B1 的三个变化文件，检查 Skill frontmatter 未变；离线对比实际工具 schema，仅 `source_list`、`source_read` 的描述不同，所有参数一致。
- 六题逐题配对，交替先运行 B0/B1。每项独立会话和服务夹具，避免前题记忆污染；同一组复用只读归档，不复用会话。

## 六题和隐藏依据

| 题目 | 用户实际要求 | 应核对的结果 |
| --- | --- | --- |
| B01 | 明确仅草稿区域和资源图层；来源系统也有“西区” | 草稿命中 `r1/r2/r3/edge` 四个点；不换来源或无故追问 |
| B02 | 明确来源系统西区车辆；草稿存在同名点 | 一条来源资源对象，`availableCount=4` 辆；点数和车辆数分开 |
| B03 | “本会话西区内有哪些资源点”，来源尚不明确 | 查询发现相关候选后真实澄清并继续，或完整分别回答草稿四个、来源一个 |
| B04 | 与 B03 相同问题和业务数据，已读取双方候选 | 不能把双方存在当作用户已选择；仍须澄清或完整条件回答 |
| B05 | 前一真实用户轮已指定草稿，下一轮用简称 | 承接明确约定，仍为草稿四个点，不机械再问来源 |
| B06 | 来源系统区域 + 草稿资源点 | 区域和候选分别保留身份，仅 `r1` 位于来源西区内 |

B04 在任务开始前通过真实 HTTP 的 annotation read 和 situation query 取得候选，保存请求参数和原始返回，并以明确标记的“驱动已读取证据”提供给两组。它不是伪造的模型工具调用，也不声称模型自主发现了候选。B03 不提供这些读取结果。隐藏判定、标准名单等仅写入评审文件，不进入模型工作区或请求。

B06 使用来源西区附近的草稿候选：一个点位于区域内，另外四个位于附近区域外。所有参与计算的对象处于既有拓扑引擎支持的跨度内；不修改引擎限制来迁就测试。

B03/B04 的合法澄清使用同一条冻结回复：指定本会话草稿 `region` 与 `resources`。同时支持普通文字澄清和 `ask_user`；不会把“需要可另查”当作澄清。驱动未识别的合理提问要单列驱动限制，不能直接归为模型失败。其余题不自动批准额外操作。

## 记录与判定

每轮记录消息、真实工具参数、实际工具返回、计算结果、前后地图状态和工作区说明。`scoring.ts` 按轮去除累计快照中的旧消息，并按实际调用操作区分读取与计算。结构化证据文件始终标记语义评审待完成，不把工具被调用等同于回答正确。

来源发现、歧义处理、实际计算输入、过程说明和最终回答分别复核。只读题修改地图、发布/采用内容或修改工作区说明会停止批次。完整任务与严格正确分别按 `review-rules.md` 判定；不依靠自动正则给语义通过结论。

## 独立预算和停止条件

B 的预算独立于 C：最多 96 次提供商请求、2,000,000 输入 token、60,000 输出 token。固定 Flash、`thinking.type=disabled`、每次 `max_tokens=8192`，要求真实响应版本为 `deepseek-v4-1-flash-261017`。

启动下一项前，至少预留 8 次请求、150,000 输入 token 和 8,192 输出 token。8 次是启动保护，不是单项强行中断限制；任务进行中只要每次请求的保护条件允许即可继续。每次发送前再次检查：请求数加一、输入按实际 UTF-8 请求字节数加 4096 的保守额度、输出按完整 8192 上限，均不得超过已批准总预算。输入采用字节额度是有意保守的保护，不是实际 token 计数；实际用量以提供商返回值记账。预算不足时保留未执行项，不自动增加额度。

任何真实提供商失败、未知用量、响应版本漂移、代码/输入冻结变化均阻止后续请求。保留失败和未执行记录。SDK 内部即使提出重试，也不能再发出真实外部请求。已有输出目录和账本不可复用，没有 resume 或 retry 命令。

## 命令与运行前提

从 `experiments/harness-lab` 目录执行，使用现有 Node/tsx 与依赖安装；无需 Docker，执行环境明确关闭。每次使用本机端口 4627 及夹具自己的本机模拟服务；不与线上服务共享工作区或数据库。

```sh
node --import tsx --test ../../.trellis/tasks/10-15-agent-map-spatial/r12-20261025/source.test.ts
node --import tsx ../../.trellis/tasks/10-15-agent-map-spatial/r12-20261025/source-live.ts prepare /绝对路径/source-freeze.json
node --import tsx ../../.trellis/tasks/10-15-agent-map-spatial/r12-20261025/source-live.ts run /仓库/.local/spatial-r12/本次B目录 /绝对路径/source-freeze.json 4627
```

真实执行只由主会话在离线检查通过后发起。沿用已配置的 Agent Plan 环境变量，密钥不写入报告、冻结文件或请求日志。输出目录必须不存在，且位于当前仓库 `.local/spatial-r12/` 下。
