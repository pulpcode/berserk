# 开发验证：信息处理与席位投递

日期：2026-09-22。设计基线：`9b98c22`。代码已实现，**未部署线上，用户验收尚未进行**。

## 实现范围

- 来源认证、文本／文件接入、消息去重、固定输入、无规则暂存及持久队列。
- 复用 Pi 原生会话与循环执行预处理；独立工作目录、模型并发许可、取消与中断状态。
- 一次预处理向多个席位投递；人员明确选择对话分析或后台分析，资料导入与会话准备可查回。
- 信息处理中心的三栏页面、来源范围授权、规则编辑及开关；普通席位只看自己的收件。
- 原生 JSONL 继续保存聊天内容，SQLite v3 保存后台元数据；现有业务交接机制保持独立。

### 强制退出

`tests/background/crash.test.ts` 在真实子进程中发送 SIGKILL，使用真实 SQLite、BackgroundService 和 Pi 原生历史，仅模型提供方确定化。5 项均通过：

| 终止位置 | 重启后结果 |
| --- | --- |
| 接收事务提交前 | 无接收回执，事件与作业回滚 |
| 已接收、尚在排队 | queued 保留，不丢接收记录 |
| 领取后、开始模型处理前 | 标记 interrupted，不自动重跑 |
| 工作文件及原生答复已写入、终态提交前 | 保留文件与原生历史，作业中断，不猜测成功或重放模型 |
| succeeded 与 pending 投递已提交 | 仅补投递，模型调用数不增加 |

故障测试中的文件效果由测试桩生成，用于验证宿主持久化边界；实际 Python／Docker 执行由下列真实链路验证，两者不混为同一项证据。

## 真实模型与 Docker

环境为 `tencent-server` 的独立代码目录 `/home/ubuntu/axon-background-check.JPIhZC/app`，Node 24、Pi 0.85.1、DeepSeek `deepseek-flash`、Docker 26.1.3。通过服务注入接口运行，不启动生产监听器，不使用线上账号或会话数据。

成功数据目录：`/tmp/axon-background-live-mHv3kJ`。详细回执、原生会话引用、hash 和用量见 [live-validation.json](research/live-validation.json)。

通过链路：

1. 上传 CSV，接入后台并生成独立作业。
2. Pi 编写和执行 Python，核对金额总和为 42，生成固定下载文件。
3. 同一预处理结果分别投递 A／B，无人打开浏览器也可完成。
4. A 选择任务和资料，准备可编辑草稿；发送前没有模型调用，发送后完成对话分析。
5. B 明确提交后台分析，执行脚本并生成文件；结束后在同一会话继续对话。
6. A／B 文件目录隔离；收件不携带服务指令或完整工具过程。

成功链路共 15 次模型请求、14 次工具调用，提供方报告 59,962 token；这不是费用结算。

首轮独立探针在 `/tmp/axon-background-live-26XPWb` 遇到 `cd /workspace && python3 ...` 的现有 Bash 确认规则，作业明确结束为需人工处理，未绕过批准。之后只调整探针目标，说明已处于工作目录并直接运行 Python；未放宽产品命令策略。
