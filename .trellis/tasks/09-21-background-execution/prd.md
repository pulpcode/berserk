# 需求：信息处理与席位投递

更新：2026-09-22。状态：**已实现并部署，待用户验收**。属于任务与后台作业规划的第二增量。

## 1. 目标

服务接收文本和文件，自动完成配置的预处理，将原文与结果投递给一个或多个席位。席位人员确认开始后，可以通过普通对话分析，也可以提交后台分析。获授权人员通过“信息处理中心”观察接收、执行及投递，维护规则。

处理能力通用：资料整理、材料检查、数据计算、文件编制均可使用同一 Pi 执行机制。特情、态势是应用场景，本期不建设外部领域系统，不固化其业务步骤。

## 2. 基础与概念

现有登录、公私任务、席位工作区、Pi 原生会话、AGENTS.md、Skills、Agents、压缩、文件工具、Docker 和正式协作继续复用。

| 对象 | 含义 |
| --- | --- |
| 来源消息 | 某接入来源送来的一条文本／文件消息；同一条重送保留原消息标识 |
| 后台作业 | 一次自动预处理或人员主动提交的后台分析；不是业务任务或人员待办 |
| 席位收件 | 该席位可查看并决定是否处理的一份输入及预处理结果 |
| 业务任务／工作区 | 人员分析时选择的任务及本席位文件目录；公共任务不自动公开各席位的文件与聊天 |
| 信息处理中心 | 受独立权限控制的观察与规则管理页面，不承担全部系统管理 |

席位是接收和办理主体，Agent 提供执行能力；不要求每个席位有永久运行的 Agent 进程。信息送达不代表已读、正式签收或已经开始分析。

## 4. 范围与边界

- 来源消息可以不带业务任务编号。预处理仅使用本次输入和配置允许的服务资源，不自行读取席位目录。
- 本期规则按来源匹配，选择已登记预处理方案和一个／多个获准席位。不以模型判断内容作为首次接入前提。
- 席位工作台使用通用收件／详情组件；信息处理中心独立页面，共用登录和部署，按来源授权展示数据。
- 人员对话与后台分析均沿用任务 × 席位文件归属。两席位收到同一信息，各自的分析互不共享私有目录。
- 框架支持执行不同目标，但本期的后续正式分析由人员发起。明确后台分析请求不属于“结果自动触发下一作业”。

## 5. 本期不包含

- 外部特情／态势系统建设、正式适配、跨系统上下文查询、LLM 智能分流和多任务影响关联。
- 无人确认自动启动下一段正式分析、任意作业级联、定时任务、拖拽编排或多进程消费。
- 自动正式上报、下发、业务验收；不把所有自动结果改成业务待办。
- 后台人工等待的跨重启续接、任意执行断点恢复、全量前台 Run 表或 Pi 历史迁移。
- 手机界面、特情地图等专用业务组件、通用权限管理门户和站外推送。

上述能力按实际需求后续独立设计。本期实现与开发验证见 [验证记录](validation.md)，线上部署与备份记录见 [验证记录](validation.md#上线与验收)。
