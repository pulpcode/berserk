## 验证

在 `experiments/harness-lab` 执行现有 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`、`npm run test:e2e`。新增故障测试覆盖接收、规则保存、投递、导入和执行前后真正的 SQLite／文件边界，不只 mock 成功响应。

新增 `probe:background`：独立数据接入测试材料，预处理并投递 A／B；A 发起对话分析，B 明确提交后台分析，至少一项执行 Python 并交付文件。记录环境、原生历史引用、文件 hash、投递回执和实际调用用量。容量及崩溃测试以确定性模型为主，不扩大真实付费验收来代替故障覆盖。

## 发布与回退

1. 检查通过后记录实现边界与证据，按中文主体约定提交 Git。
2. 用户要求部署时，停止接收／领取，核对在途和投递状态，停服备份整个数据根；保留当前账号、任务和历史。
3. 使用已验证迁移升级，登记来源、处理方案及信息中心权限，验证规则和两席位收件后启用。
4. 回退使用匹配的旧程序与备份，另行保留备份后新增输入、投递、文件和人员分析，逐项核对。

当前未更新线上服务；上线需配置来源、处理方案及权限，并按上述备份步骤执行。
