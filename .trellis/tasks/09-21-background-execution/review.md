# 第二增量：信息处理与席位投递

更新：2026-09-22。状态：**已实现并部署，待用户验收**。

本期打通：**后台预处理 → 投递一个或多个席位 → 人员确认开始 → 对话分析或后台分析**。同时建设受权限控制的“信息处理中心”，查看接收、处理和投递全过程，维护基础规则。

## 使用过程

1. 维护人员登记来源及可用的处理方案；获授权人员在“处理与投递规则”中选择来源、预处理方案和接收席位。
2. 外部系统发送文本／附件及稳定消息标识；无需指定工具或提前关联 Axon 业务任务。
3. 后台按目标使用 Pi 预处理。原文、过程文件、结果及日志保存；可以运行 Python、生成文件或委派只读 Agents。
4. 同一份预处理结果可送达多个席位。人员尚未操作时不会启动正式分析，也不占用执行资源。
5. 席位人员查看内容，选择任务、资料并补充目标：进入普通对话，发送后分析；或明确提交后台分析，稍后查看结果。
6. 获授权人员通过“信息处理中心”查看信息记录、后台作业和规则；正式上报、下发仍沿用现有协作及确认。

例如“特情资料 → 基础整理 → 特情席位和筹划席位分别接收 → 各自决定如何分析”。这是验证场景，执行框架不写死为特情业务。

## 审阅重点

| 内容 | 本方案 |
| --- | --- |
| 路由 | 基础规则决定来源使用的预处理方案和一个／多个接收席位；LLM 智能分流后置 |
| 人员确认 | 收到信息不等于开始分析；用户发送对话或点击“提交后台分析”才发起执行 |
| 工作目录 | 服务预处理每作业独立；人员分析使用其选定任务的席位工作区，支持脚本和过程文件 |
| 页面权限 | 信息处理中心有“查看／管理”两类能力，可授予指定账号或席位；普通席位只看自己的收件 |
| 页面栏目 | 信息记录、后台作业、处理与投递规则；与对话工作台共用登录和部署 |
| 规则编辑 | 本期支持基础规则新建、编辑和启停；只选择已登记处理方案及获准接收席位 |
| 可靠性 | 消息重送不重复预处理，投递重试不重跑模型；中断保留内容，明确重新处理才创建新执行 |
