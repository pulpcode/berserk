# R1.3 资源结果组件化与展示规则

## 目标

用户在聊天正文里先看到资源统计与关键限制，展开后能核对固定结果的来源、明细和依据。Agent 可按问题选用指标、分类柱状图和详情，普通 React 入口也可复用详情组件。

## 需求

- 在现有 `resource-v1` 目录加入 `ResourceResultView`。正文默认显示概览，来源和明细由用户按需展开。组件支持「来源与覆盖」和「完整详情」两种用途。
- 指标、分类柱状图和详情均引用同一份已授权的 `ResourceResult`。区分候选名单与统计范围、记录数与条目数、已知实体与未知总量。保留统计或场景判断时间、任务关系、可用性、空间范围和关键数据缺口。
- 复用资源工具卡的重新读取、每页十项、逐条依据和来源说明。展开或翻页时通过会话接口复查访问权限。保留现有地图入口及其证据规则。
- 正文优先显示必要统计、单位、明确的统计范围和影响解读的缺口。每个结果块保留一个明确入口，避免重复标题、副标题和解释。来源与逐项说明放在详情。
- 补齐资源组件和 R1.2 五类图表的选择指引及样例。视觉使用现有样式变量，覆盖桌面分栏、键盘展开、可读数值和长标签。

## 验收

1. 同一个固定结果可分别呈现「指标＋柱状图＋来源」和「指标＋完整详情」。统计范围、数值、单位、未知状态及来源一致。详情中的未纳入候选有清楚标记。
2. 用超过十项的固定结果验证展开、翻页和逐条依据。刷新、重新进入和服务重启能找回原结果。撤权或读取失败时，触发读取的视图清除旧结果并显示提示。
3. 验证工具过程卡仍可独立使用，已有地图入口仍打开它原来指向的证据。只有资源结果的会话无须额外地图操作。
4. 旧的 R1.1 资源展示块与 R1.2 计算展示块可继续回看。窄桌面聊天栏内，用户可用键盘打开详情、翻页并核对数值。折叠状态下正文只显示一次范围和缺口，详情内容按需出现。

## 范围

本轮改动集中在资源展示组件、组件注册和图型指引。资源查询、聚合、权限和历史数据继续沿用原有契约。新增地图对象定位、图表下载和自由 HTML 制图另行评估。R1.4 汇总真实模型的阶段验收。
