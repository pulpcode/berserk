# 评分、追问与证据规则

状态：随题包待审阅。适用于本轮新题，不回写旧A/P题分数。

## 一题怎样算完成

逐题清单中的用户问题、必要名单/数量/范围/状态以及指定后续轮都完成，才可能主任务通过。正确工具调用、正确卡片或一句“已完成”都不能替代答复。允许等价的正确工具路径，不以调用次数或是否读取Skill判成功。

| 维度 | 判定 |
| --- | --- |
| 主任务 | 用户所问的必要结果齐全且正确；N06还必须先解决真实歧义；N08两轮都正确 |
| 解释 | 所有过程说明、追问中的事实、最终回答均有当时证据；具体事实错误或无据断言判失败 |
| 严格 | 主任务通过、解释通过、四项关键约束均通过 |
| 表达建议 | 措辞可以改进，但结合全文没有确定事实错误，单列建议，不降事实分 |
| 无最终答复 | 产品故障/未完成的主任务及严格失败；解释为N/A，之前的过程误述另记，不能洗掉 |
| 基础设施问题 | 输入、记录、接续或计费证据不可信，单列protocol_failure；计划未完整有效完成不能宣布验收通过 |

数量、成员集合、位置分类和状态变化用独立预期核对。语言判断由两位审阅者分别阅读原始轨迹后作出；第二位先读原证据，不先看第一位结论。原判与裁决均保留。不能用关键词或问号代替语义判断。

工具缺陷专门门槛检查**实际工具返回和产品故障根因**：模型把正确工具数字说错，是模型解释/主任务错误；工具本身重复计数或中断，即使模型自行修正，工具修复仍失败。若任务没有经过有关工具路径，只能说该路径本次未覆盖，不能算该项回归已验证；可等价完成用户任务的路径不因此被硬扣主任务分。P02、N02、N03的调用覆盖需在报告明确列出，缺覆盖时该工具验收门槛标“未充分验证”，不得宣布工具修复验收通过，也不自动追加题目。

## 哪些追问能得到回答

1. 只发送逐题列出的初始问题与显式引用。追问后的冻结事实留在评测器侧。
2. 审阅Agent实际提出的问题，保留其原句、消息/交互ID及匹配理由，使用`reviewedContinuation`匹配本题冻结事实。
3. 询问区域且有对应事实时，回答它实际问的区域；不得提前发送隐藏偏好，也不能用错误字段的答案强行推进。
4. 普通文本追问通过真实下一轮用户消息回复；交互API追问通过真实questionId/optionIds或自由文本响应。分别记业务追问成功与API覆盖，不要求必须采用API才能业务成功。
5. 未追问而已作出单范围结论，不发送补救答案；“若需要可以继续”不是必要澄清。用户原题明确比较时，不强迫选一个。
6. 追问超出冻结事实时不临时编答案。单题记未完成或待审阅；若确为题目资料缺陷，单列fixture_gap并保留记录，不能事后修题后覆盖原执行。

P04、N08的第二轮是预先规定的任务续问，不是错误救场：前一轮已有可用固定结果/正常终答后才按题发送；若产品未生成所需引用，记录失败，不捏造结果继续。题内澄清不额外算新任务。

## 可说与不可说

| 已有依据 | 可说 | 不可说 |
| --- | --- | --- |
| 来源完整，明确范围内0记录 | 本来源本范围未查到记录 | 本任务现实中没有资源 |
| 未收到放行回执 | 是否放行尚未确认 | 已确认未放行 |
| 旧可用依据失效，无其他有效依据 | 统计时点可用性未知 | 当前不可用 |
| 同一实体有效可用/不可用报告冲突 | 冲突，列双方依据 | 选一边或降为普通未知 |
| 平台引用，无分配证据 | 与任务相关，分配未确认 | 引用后就已分配，或只能建立引用才可证明分配 |
| 两份完整同口径成员有交集 | 按并集去重，给依据 | 简单相加，或把汇总缺单体ID说成成员未知 |
| 每组scope不同或筛选集合不同 | 各自范围分别说明 | 所有scope都相同，或同单位误称不同单位 |
| 固定标注版本时间 | 该保存版本的时间 | 本次查询时间或资源状态发生时间 |

后来的工具结果不能为更早的断言补证；最后更正不能抹掉已发出的明确错误。正常换算与有证据的推导可以通过，不要求每句话再调用一次工具。不得靠少答用户必要问题提高解释分。

## 原始证据与最终报告

每槽保留：原用户消息与实际发送引用、来源请求/分页与响应、实际草稿/导入/固定版本、完整公开工具结果、全部助手文本、澄清问题与真实用户续答、原生会话、Skill实际读取、状态差异、提供方请求与usage、冻结文件hash。私有推理不作为用户可见解释评分材料；如提供方返回推理用量仍纳入预算记录。

评分采用`resource-evidence-v2`：`scoreReviewV2`审阅到分数，`aggregateV2`按N01—N08×两遍汇总。其本身不替代逐题业务判定、15/16门槛或工具修复专门门槛。运行前连接并冻结这些模块，不沿用硬编码旧A题号的聚合器。

报告分别给出：4项公开检查；16次正式主任务/严格正确率；有答复解释正确率与N/A数；过程误述；两遍分数与两次都成功题数；Skill读取及实际规则遵守；工具门槛的通过/失败/未充分验证；失败归因与耗时/请求/token。不把旧分数变动或本轮新题成绩直接宣称为某个组件的因果提升。
