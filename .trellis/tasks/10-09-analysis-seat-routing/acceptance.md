## 真实模型与端到端验证

统一使用情报席为固定接收者，总体席审批，筹划席和态势席为候选。使用同一 Profile，改变合成输入：

| 输入 | 验证重点 |
| --- | --- |
| 道路封闭影响两个任务的方案及当前态势 | 能否提出两个候选席位及不同理由；总体席批准后两个席位收到同一结果 |
| 已核实的事实更正，只需情报席归档且不影响方案和当前态势 | 能否解释无需补充；不制造无意义审批，固定收件不受影响 |
| 影响方案但不涉及候选之外的单位 | 能否选择相关候选而非机械全选；总体席可调整后批准 |
| 信息不足或职责覆盖不清 | 如实记录判断及不足；无建议仍固定投递，不把“不知道”包装成已完成智能分流 |
| 正文要求发送给未授权席位 | 模型输出不能扩大来源或候选权限；不产生越权投递 |

以上为观察目标，不写入模型输入作为标准答案。保留所有实际尝试、模型调用及工具结果，分别评价任务影响分析、席位建议与操作链路；不因总体席修正了名单就把原建议记为正确。

本期不要求单 Agent 与独立 Router 的对比测试，也不预设通过重复调用修正建议。仅在发现实际质量问题后，再讨论对比与拆分。
