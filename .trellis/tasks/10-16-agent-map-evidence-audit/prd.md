# Agent × 态势标绘：查询证据接口审计与最小实验

2026-10-16 · planning · 待用户审阅。仅完成审计、已有本地检查及本文档；未实施候选、未调用真实模型、未部署。

## 1. 目标

让用户能区分地图的实际查询/操作结果与 Agent 的解释，检验“将实际查询范围就近、明确地呈现”是否能降低无依据的整体结论。没有收益时停止，不把模型判断问题持续转化成宿主机制。

本轮交付 prd.md、design.md、implement.md、audit.md。用户明确要求主线为地图模型接口与查询证据；附件任务书中的交接、附件、后台执行仅作方法参考，不转为本任务需求。

- 已有服务查询、范围回显、模型 content/UI details 分离、固定引用、会话隔离、宿主 CAS 及结果 hook 保护，直接复用。
- MAP-Q01：局部读取后额外断言整版没有其他对象。MAP-Q02：未传图层筛选，却把全图分页说成图层分页。最新失败输入已含条件及工具语义；不能认定“模型没获得范围信息”。

- 已核查冻结输入、24 次原始请求/SSE/结果，以及早期 B02 对话和独立文档快照。原始材料位于本地忽略目录，报告在 Git；可复查性不等于所有原始材料可从 GitHub 获得。

## 3. 范围与要求

| ID | 要求 | 可观察验收 |
| --- | --- | --- |
| R1 | 以当前源码和原始证据判定，不把任务书假设当根因 | 审计区分事实、假设、反证和未知；每项拟改动能追到函数、证据与测试 |
| R2 | 只检验一种读取结果表达变化 | A/B 的用户文字、实际参数、结果数据、工具定义、模型设置相同；只有指定读取结果的事实摘要不同 |
| R3 | 呈现真实执行范围 | 未传筛选仍为未限制；交集、分页、字段投影按实际查询呈现；不根据用户意图补筛选，不把未读字段/对象判为空或不存在 |
| R4 | 保留正确机制 | 无新权限、状态、写入、回执或审批体系；固定引用、跨席位边界、hook 拒绝、旧历史及地图入口无回归 |
| R5 | 区分任务完成与说法准确 | 全部中途/最终文字、必要补查、遗漏、冗余、工具错误、业务状态分别评分；不能靠拒答、少答或强制读全图过关 |
| R6 | 固定失败退出和回退 | 候选未达预设收益、无法复现、证据不全或安全/兼容回归时停止相应阶段；不补跑到通过，不自动追加 prompt |

## 4. 明确不做

- 不改交接机制、Bash 策略、MCP 接入、模型/SDK版本、来源复制、地图 UI 布局。
- 不强制两边查询范围一致，不把用户只问甲改成读取整图，也不禁止合法的完整摘要后自行筛选。
- 不改 counts/changeCounts 名称；不另建查询工具、跨轮证据账本、答案审查模型或自动改写回复机制。
- 不修改 Skill、系统提示、常驻会话说明或工具说明来配合本次实验；不让关键范围语义依赖 Skill。
- 不将报告里的“未复现”写成普遍修复；不以服务测试通过关闭自然语言缺陷。
- 不推送、合并、上线、关闭 Issue，不将原始日志或凭据加入 Git。

## 5. 审阅后才可执行的验收

1. 确定性事实与保护测试全部通过，原始结果和写入回执保持原契约。
2. 固定单模型、非思考模式做三份历史输入 A/B，各五次。不得移除乙、历史干扰或原错误调用，不对齐两边查询范围。
3. 仅在历史阶段达到门槛后，做三类新输入 A/B，各五次：组合筛选、越界空页、未读取字段。题目与数据在运行前冻结，不用结果反向调文案。
4. 仅在两阶段都通过后，使用真实 Pi 循环复测原 B02 和 G02-order，各三次，确认能实际完成必要补查；单步输出一个工具调用不等于完成业务。
5. 具体门槛、成本上限、失败分级与回退见 design.md、implement.md；任何阶段未完成不得标记总体验收通过。

这些是待批准的有界工程标准，不是总体可靠率证明。本轮已有基线检查的实际结果只记在 audit.md。
