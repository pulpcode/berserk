## 已修复

- `BackgroundService.inboxItems` 新策略字段解析曾对无 sourceId 的持续研判投递抛错，导致原逐条收件入口失败。先区分投递类型，再读取原策略；增加已投递持续研判的实际服务回归。
- 接收开关曾分别存于连接器配置和原 background_controls，旧工作总览暂停与能力中心显示会矛盾。经主代理确认，`bindInboundControl` 仅桥接宿主现有 BackgroundService；原控制表继续是唯一状态，管理员权限在调用时校验，保留 CAS 与操作者记录。没有新增接收状态字段。
- 连接器写原控制后发生审计写入失败，保持真实状态并返回失败；相同旧修订再次操作冲突，用户可读取最新配置核对。故障注入验证不重写或自动重放。
- 已退役来源的旧接收开关 API 明确拒绝；原策略规则仍按授权可编辑，但不能重新开放旧来源。
- 通知接收详情补充可复制的实际接收地址；审批历史筛选与其他历史一样按业务归类，授权仍按原策略验证。
- 增加浏览器回归：账号仅有自由调试原策略管理权、规范来源仅查看权，仍能选择“情报接入 · 自由调试”创建规则；收件席位严格限于该策略。

在既有 fixture 测试中实际将 backup/data 复制到另一隔离根并打开连接器服务，验证原四来源配置和凭证可读、历史业务数据库与 native 文件一致、无半迁移 marker。该测试验证 host 备份恢复；外部 source 数据根和旧程序需按发布 runbook 独立完整备份，CLI 不涵盖未传入的 source 根。
