# 修复跨席位文件交接与确认展示

状态：**已审范围内的代码修改完成，自然多轮验收未通过，待审后续处理。** 详见 [实施与验收记录](verification.md)。

## 目标

Agent 应理解工作区的共享范围和跨席位文件交接方式。用户说“把这项工作和资料交给 B”时，应交出实际文件；确认页面应显示真正附带的资料，用户无需了解工具字段。

## 问题依据

2026-09-22 的线上测试中，A 已读取初稿和修订要求，也表示会附上两份文件，但实际调用只在工作目标中写了路径，没有选择交接附件。B 收到的工作没有文件，确认界面也未明确显示零附件。

代码核查发现，宿主没有直接说明同任务不同席位的目录独立，分派工具也未解释工作说明中的路径不会自动传送文件。这是已确认的说明缺口；日志不能证明模型当时是误解了共享关系，还是生成参数时遗漏。[核查记录](research/evidence.md)

## 需求

| 编号 | 要求 |
| --- | --- |
| R1 | 向 Agent 说明：同一任务、同一席位的会话共享工作区；不同席位的目录独立，即使都显示为 `/workspace`，也不能直接访问对方文件。 |
| R2 | 明确分派中的文字要求与实际文件交接。Agent 按用户意图和已有上下文选择资料，核对准备结果，再进入现有人工确认；资料明确时不要求用户重新提供文件名或技术参数。 |
| R3 | 先修正说明，用原自然多轮场景验证。是否需要增加参数约束，以验证结果决定；参数必填不作为本次修复前提。 |
| R4 | 聊天确认卡片和页面分派确认独立展示实际附件数量、名称、大小及查看入口；零附件时明确显示“本次未附文件”。 |
| R5 | B 的工作详情显示实际输入资料，包括零附件状态；保留工作区隔离、固定文件副本、现有 HITL 和历史记录。 |
| R6 | 工具说明表达通用的用途、参数和结果关系，信息各有明确位置；测试口语和内部恢复细节留在验收与开发设计中。 |

## 验收

| 编号 | 可观察结果 |
| --- | --- |
| A1 | 核对实际发送给模型的工作区说明和工具说明，能够直接得知共享范围、发送文件的方式及接收后导入的方式；不依赖模型自行推测。 |
| A2 | A 首轮读两份相关文件，下一轮仅说“直接全部分派给 B 去执行”；实际交接两份文件，B 导入后的字节与确认副本一致。工作区中的无关文件不被附带。 |
| A3 | 用户明确要求只交一份文件时只交该文件；纯文字任务可不附文件，不因这次修复被强制要求提供附件。 |
| A4 | 工作说明即使写着“随附两份文件”，实际附件为空时，两种确认入口和 B 的工作详情仍如实显示零附件。 |
| A5 | 指定文件不存在或不可交接时沿用现有错误处理，不以成功的空附件分派替代失败的文件交接；准备、确认和导入仍执行既有权限检查。 |
| A6 | 旧缺省附件参数、已提交工作及确认历史继续可读；签收、提交、验收、拒绝和取消的原有行为保持，A 仍能导入 B 提交的成果。历史空附件不会自动补齐或重新交接。 |

## 范围与限制

先修改模型可见的工作区及工具说明，并验证自然多轮行为；保留实际附件展示的必要改进。沿用 Pi 原生工具循环和现有参数结构，不新增专用参数拦截、状态机、意图复核模型或自动收集整个目录的能力。

若补清说明后仍出现遗漏，应记录失败并据此提出最小补充方案供审阅，不直接扩大实现。有限场景通过不保证模型永远不会少选或错选文件。当前已提交的测试坏单保留，复测使用隔离数据中的新分派。

详细行为见 [设计方案](design.md)，执行与检查安排见 [实施计划](implement.md)。
