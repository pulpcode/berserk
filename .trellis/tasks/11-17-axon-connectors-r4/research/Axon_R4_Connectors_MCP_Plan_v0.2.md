## 一、本轮目标与范围

**连接器定位：组织统一管理的外部系统接入能力。管理员统一配置，用户按权使用，Agent 按需调用；原业务模块继续负责信息研判、任务关联和席位分派。**

本轮交付两条主线：**既有特情／情报、态势及相关控制接入保持原单实例关系并规范化纳管；通用远程 MCP 支持多个具名连接的独立调用。** 不因支持多连接，就提前建设多来源业务路由。

| 本轮必须交付 | 本轮不建设 |
| --- | --- |
| 管理员统一配置、凭证引用、使用授权、状态及记录 | 普通用户自行登记任意地址、公开市场、任意适配器安装 |
| 既有业务单实例纳管及服务端约束，原业务行为不变 | 特情／态势第二实例、业务实例切换、多演练平台 |
| 标准 MCP 工具发现、实际调用、通用服务多实例隔离 | 通用 CLI 执行接入、任意 stdio 安装、MCP 全能力平台 |
| 原会话内按需调用、来源可见、歧义询问 | 新聊天页、专用结果卡片、独立作用域管理中心 |
| 既有入站链路兼容、基本权限与取消边界 | 新业务通知订阅、多来源路由、后台重构、统一紧急停止 |

路线保持 **R3A → R4 → R5 后台统一 → R6 专家团 → R7 运行期安全治理**。多业务实例及信息路由作为后续待讨论需求，不自动塞入 R5；技能安全审核专题仍按原记录待排期。[D0、S1]

将原稿“信息／态势查询也验收多实例”改为“既有业务单实例＋通用 MCP 多实例”。移除新建任务—连接绑定接口、个人／席位默认继承链和独立实例策略管理。保留原任务、席位、来源、场景权限，不将其删除或放宽。

### 1.2 证据与评审边界

代码依据沿用原稿已核查的固定提交 `a3b9b887ab7cb26a1212d7b8bd543fb0d83b02f0`，**不声明其仍是当前分支头**。本次重读 R4 v0.1，依据后续讨论修订，并重新查阅 MCP 官方规范／SDK；未重新拉取最新代码、运行产品测试、访问部署或修改仓库。[D0、E1–E6]

## 二、当前实现与 R4 增量

以下事实来自原稿及本会话已核查的固定提交；右列是本轮设计要求，不代表已经实现。实施前需核对新提交差异。[D0、S1–S11]

| 基线事实 | 本轮处理 |
| --- | --- |
| 能力中心已有连接器标签，尚为空状态。[S4] | 沿用目录及详情组件；管理员管理，普通用户查看获准能力。 |
| `ContextSystemConfig` 是系统数组，保存 adapter、地址和 tokenEnv；演练／控制另有固定来源约束。[S5] | 复用通用连接记录；既有业务各固定一个连接，不把“数组可存多个”当成业务已支持多实例。 |

| 专家已有工具／技能限制；R3A 管理 Skill 只能读取、建议及确认保存。[S3、S10] | 补必要连接依赖和真实目录；不向创作请求开放远程执行、凭证或连接管理。 |

### 2.1 不是重新开发业务集成

保留 `information_search`、`information_read`、`situation_query`、`simulation_command_send` 的既有语义。页面、Agent 与后台仍经过原领域服务；连接模块只统一必要的接入配置、认证解析、传输和调用关联。[S6–S8、S11]

Axon 内部的任务、交接、标绘和空间分析，不因提供工具就全部归为外部连接器。地图底图／瓦片、模型供应商连接不纳入本轮。也不为了统一名称，把原 HTTP API 全部包装成 MCP。

### 2.2 当前认证与验收状态

基线的外部查询和入站接收使用服务端固定凭证，并非“没有认证”；已核查链路没有完整 OAuth 授权流程。R4 不为模拟系统专门建设 OAuth 授权服务器。[S5、S7、S9]

原合并记录为 89 项定向单测、10 个浏览器场景及静态／构建检查，用户阶段验收仍待反馈。它们不是本次重跑，也不是当前所有功能的一次全量验证。原历史恢复警告等遗留必须保留真实状态。[S2]

## 三、产品定位与用户入口

### 3.1 产品概念与技术方式分开

| 概念 | 本稿含义 |
| --- | --- |
| 连接器 | 对某个外部系统的受控接入；管理配置、身份、可用操作及来源。 |
| 连接 | 一条具体地址／外部账号的具名配置，具有稳定身份和独立凭证引用。 |
| MCP | 已公开维护的标准协议；本轮新增远程 MCP 客户端路径，不自拟发现／调用协议。 |
| 原生 HTTP／CLI | HTTP 保留原业务适配；CLI 是未来按需采用的调用方式，不是本轮通用安装能力。 |

内部可保留 ConnectorDefinition／适配器注册信息和 Connection 的区别，但**不要求用户依次创建“定义、实例、作用域”三个对象**。通用 MCP 直接添加具名连接，必要的内部类型和标识由系统维护；同类分组不等于共享凭证或共享工具目录。[D0、E1–E3]

### 3.2 管理员入口

能力中心沿用“连接器”标签。既有业务连接提供“查看配置／管理”，不提供新增同类实例。通用服务提供“添加 MCP 连接”，直接填写名称、地址、认证及开放工具。展示具体连接，可按服务类型分组，不强制进入定义详情再添加实例。

详情沿用现有面板，包含配置、开放工具、使用范围及操作记录。凭证仅可写入／替换，不回显秘密。配置保存、授权状态和最近调用结果分别展示；不以一个“已连接”代表全部业务可用。

### 3.3 普通业务席位入口

**连接管理无感，业务能力可感知，数据来源可追溯。** 普通用户可以不打开目录，直接在原专家、对话和任务流程中工作；目录仅展示其获准的外部能力及按需选用入口，不提供任意 URL 登记。

既有特情、态势沿用原来源，不新增选择步骤。新增服务在目标唯一且已获准时可直接按需使用；多个候选有歧义时再询问。手动选择、必要的个人认证和错误提示均复用原对话／管理组件；不建专用聊天或结果卡片。

选择连接不自动发送、不调用模型、不更换专家、不覆盖正文或附件。来源标签、实际失败和未完整查询须可见；不能把连接失败解释为“没有特情”或“没有异常”。

## 四、既有业务单实例与规范化纳管

### 4.1 “单实例”按既有业务接入逐项约束

本阶段特情／情报、态势各维持原来的一条接入关系；演练／控制保持原拓扑。**不是整个 Axon 只有一个连接，也不是所有 HTTP 或同类业务永远只能单实例。** 原 `systemId／sourceId` 与连接 ID 显式映射；单连接仍可服务多个原有任务和场景。[S5–S9]

| 场景 | 本轮规则 |
| --- | --- |
| 迁移原业务配置 | 每个既有接入映射到固定连接；重复执行迁移不产生第二条。 |
| 新增／复制／导入第二个既有业务连接 | 前端不提供入口；服务端写入与配置装配均拒绝，不能靠改显示名绕过。 |
| 停用、更新或恢复既有连接 | 操作原记录，保留来源和历史；停用不释放一个可另建替代品的“名额”。 |
| 通用 MCP | 允许多个具名连接；不受既有业务单实例约束，但不能据此获得其来源、路由或业务权限。 |

约束归属于受控的既有业务接入标识／映射，由服务端确定，不能相信客户端传来的类型。创建与绑定在原锁／事务边界内校验唯一性，持久层保证不出现两个并发有效绑定；启动对导入配置也校验。**不只隐藏按钮，也不要求建设通用 `instancePolicy`／数量配额管理平台。**

若实际部署已有不符合本次假设的额外配置，迁移报告冲突并停止相关 apply，先明确处理；不得静默删除、取第一条或覆盖用户数据。未来开放业务多实例仍需业务设计，不能仅改一个开关。

### 4.2 必须保留的业务语义

特情保留报告 ID／修订、正文／索引、分页和来源；态势保留完整对象引用、场景时间、固定读取及地图引用；控制保留原确认、发送意图和回执。`connectionId` 不替代 `scenarioInstanceId`。[S6–S8]

查询、地图、任务资料、后台和入站等路径使用唯一有效配置来源。已迁移配置不被旧文件重新覆盖；凭证和地址修改留修订。同一系统维护不改来源身份；实质更换外部系统不能只改 URL 后让旧记录冒充新系统资料。

### 4.3 入站与后台只做兼容纳管

原 `sourceId` 关联既有连接，继续原认证、去重、Profile、队列、任务关联和席位投递；接收事件与允许调用分别控制。会话选择哪个连接，不改变收到哪些通知，也不改变原路由。

不新增业务通知订阅、第二来源、自动分派或后台 MCP 工具；不把个人凭证借给服务身份。普通接收暂停遵循原回执语义，保留已收数据，不静默成功后丢弃。R5 再讨论后台专家统一；多来源路由另行评审。[S9]

## 五、管理员配置、个人身份与使用流程

### 5.1 两类管理流程

**既有业务：读取原配置 → 核对来源映射 → 规范化纳管 → 维护配置与状态。** 不要求用户重建任务绑定，不引入业务来源选择器。

**新增 MCP：添加具名连接 → 保存未开放配置 → 主动发现工具 → 选择开放动作／使用对象 → 明确启用。** 普通保存不调用模型或业务工具；打开页面不探测全部连接。内置动作来自受控代码，不伪造发现。

可以保存尚未发现成功的 MCP 配置；没有真实目录时不能编造工具供调用。“测试连接／刷新工具”是管理员主动操作，只报告协议和目录结果，不证明业务正确，也不是 Skill 环境前置检测。

### 5.2 统一配置，不等于共享管理员账号

| 模式 | 管理员负责 | 用户负责 |
| --- | --- | --- |
| 组织连接 | 服务、地址、服务凭证、动作及使用资格 | 按业务权限使用，无需重复配置。 |
| 已开放服务＋本人凭证 | 获准目标、认证方式和能力边界 | 仅为该服务配置／替换本人凭证，不修改目标地址。 |
| 个人任意添加服务 | 本轮不提供 | 不开放任意 MCP URL、CLI 安装或自建连接类型。 |

首期建议保留原稿的无认证、服务明确支持的 Bearer／API Key，以及对应的组织／个人凭证隔离。API Key 头名受控。对知识库等敏感来源，不使用管理员高权限凭证无差别向所有用户开放；无法落实数据使用边界时不扩大授权。

### 5.3 OAuth 支持边界（待确认项 Q2）

OAuth 是取得／维护外部授权的流程，Bearer 是令牌使用方式，不能把“粘贴 Token”称为完成 OAuth。当前模拟链路不需要为此自建授权服务器；OAuth 也不要求全组织先统一身份系统。[S5、S7、E4]

完整浏览器授权、回调、刷新及撤销不列为通用首批必交。若选定目标只支持 OAuth，先单列该目标及完整验收再纳入；不以管理员账号代替个人授权。未实现 OAuth 的版本不展示无效“连接我的账号”入口，只展示实际支持的认证方式。

### 5.4 配置生效不自动进入全部请求

管理员启用代表连接可供获准主体使用，不代表所有任务、专家或后台自动加载。新工具经过请求级权限与目标解析进入原工具链；用户不必每次人工安装，但能查看实际可用连接及调用来源。来源切换与停用规则见第六、九章。

## 六、多实例使用与 Agent 决策

### 6.1 分工：系统限范围，Agent 选工具，目标不明先问

系统根据当前账号、空间、专家能力和连接授权生成候选；Agent 理解需求并选择获准工具；宿主解析真实 ID、固定连接／账号并检查后执行。**模型不能新建连接、选择隐藏账号、改 URL、取得凭证或声明自己已经获权。**

| 情况 | 使用规则 |
| --- | --- |
| 特情／态势等既有业务 | 原领域服务确定固定连接，不由 Agent 重新挑选实例。 |
| 会话已有有效选择，或资料带明确来源 | 使用该选择／原来源；不把引用 B 的资料改到 A 查询。 |
| 用户明确指定一个获准服务 | 解析到真实连接后使用；名称重复／目标无法确定则询问。 |
| 对所需能力只有一个获准候选 | 可自动确定目标，不再单独问“用哪个连接”；调用确认仍按政策执行。 |
| 多个候选均可能适用、目标未定 | 复用原提问／选择交互；形成有效选择前不向任何候选发送业务参数。 |
| 用户明确要求比较多个获准来源 | 分别查询，保留各自来源；可顺序完成，不要求新增并行编排。 |

明确选择可以来自现有界面、原提问回答或本次具体目标确认。**不能仅凭模型自报“用户已选择”就取得执行资格。** 自然语言解析只生成目标候选；多义情况下须形成宿主可核对的选择，再开放对应调用。

### 6.2 只保留必要的会话选择

取消原稿“会话 → 任务 → 个人 → 席位”的新默认继承链，不新建任务—连接绑定接口。已有可信业务来源继续有效；新增通用连接以本会话的显式选择或本次唯一目标为准。

显式选择可在当前会话保留，刷新后可恢复，但不升级为全账号／公共任务／后台默认。自动判定的唯一目标只代表本次使用，不替用户创建永久偏好；新增候选后不得暗中扩大原选择。请求执行中不改连接，完成／停止后再更换。

同一会话可选多个连接，但“允许使用多个”不等于“每个问题都查询全部”。跨源只读比较需明确意图；写入逐个确定目标，不默认广播。A 不可用不切到 B，部分失败如实显示，不把来源对象 ID 相同当成同一对象。

### 6.3 用户可见与后台不可越界

调用过程显示具体系统／账号说明及来源；回读一条既有信息始终沿原来源，不自动改掉会话选择。更换连接只影响后续调用，历史消息仍在模型上下文中，不能宣称已清除先前数据。

聊天选用不改变信息接收、通知投递或队列。所选实例也不自动进入后台、创作、试用或子任务。新 MCP 的多实例验收仅覆盖获准的普通交互调用，不承担业务信息路由。

## 七、授权、凭证及调用确认

### 7.1 权限独立于连接是否可用

有效调用范围为：**主体／原空间权限 ∩ 专家能力限制 ∩ 连接开放工具 ∩ 组织或个人使用资格 ∩ 原领域规则。** 取消独立作用域管理，不等于取消已有权限。Skill、Prompt、MCP 注解及连接健康状态均不授予权限。

管理员可维护连接，但不自动拥有特情、态势等业务访问权。管理员个人使用组织 MCP 需明确开放；个人凭证默认仅本人个人空间使用，不供公共任务或后台共享。已有来源 ACL 不能被组织高权限账号绕过；本轮不另建通用文档级 ACL 同步引擎。

### 7.2 凭证与网络底线

连接只存 secretRef、认证模式及归属；新秘密服务端加密，主密钥外置。旧环境变量保留引用，不复制明文。表单只写不回读，秘密不进模型、浏览器持久化、脚本沙盒、参数和日志；无密钥不降级明文。已有无连接模块业务不因此无法启动。

同账号轮换记录非秘密版本，失效对应认证缓存。不同用户／实例／认证主体的客户端、目录及结果不得串用；个人凭证发现的工具不能冒作组织通用目录。

只连接获准 HTTP(S) 地址；生产优先 HTTPS，旧内网 HTTP 显式保留允许目标。限制 DNS／IP、重定向、端口、响应体、Schema 及耗时；防止目标切换和秘密转发。远端描述／结果是外部资料，不自动下载 URL、执行 HTML 或安装程序。[E5]

### 7.3 选实例与批准调用是两个动作（Q4 尚待审阅）

选定连接只明确访问目标，不表示批准之后所有外发或写操作。**本稿暂保留 v0.1 的建议：新增通用 MCP 逐次通过原确认交互展示目标、账号说明、工具及实际外发参数，再调用。** 已有内置读写工具保持原政策，不统一增加确认。

因此，“唯一目标可自动用”只是不再额外询问实例，**不等于取消调用确认**。逐次确认是否过重仍列为 Q4；本次讨论未明确通过免确认规则，不把远端 `readOnlyHint` 当作免审或无副作用证明。[E3]

确认绑定用户、请求、连接修订、动作和参数摘要；批准后再次检查权限与停止状态。实例歧义询问可与目标确认衔接，但问答回复不能自动充当操作批准。复用现有交互，不新增风险审批链或专用卡片。

## 八、MCP 协议、工具目录与专家衔接

### 8.1 采用公开规范，不自拟协议

MCP 的消息、版本处理、工具发现与调用遵循项目维护的正式规范，采用官方 TypeScript SDK。**2026-11-17 本次重查：当前规范为 2026-07-28，SDK v2 文档标为稳定线。** R4-0 锁定确切包版本和依赖文件，并验证 Node／Pi 兼容；不顺带升级 Pi。[E1、E2]

首期为远程 Streamable HTTP，按 SDK 支持实测 2026-07-28 与 2025-11-25 两代。不同版本的协商、会话和取消语义不能混写，外部目标记录真实协商结果。不自行发明协议，也不承诺所有 MCP 服务原样可用。

只承诺本轮工具能力子集。暂不接任意 stdio／CLI、旧独立 SSE 自动降级、远端采样、根目录、远端交互续接、MCP Apps／Tasks、远端 Skill 安装及业务事件订阅。协议需要但本端未支持的能力如实拒绝，不伪造完整结果。

### 8.2 工具按实例发现、授权与映射

真实 `tools/list` 支持分页及限额，保留名称、描述、输入／适用输出 Schema 和注解；不能只取简单字段。不可支持的 Schema 单独标明，该工具不开放。管理员选择开放项，新工具和重大契约变更不得静默获权。[E3]

宿主依据稳定连接 ID 与动作生成消歧工具名，保留原工具映射；同名 `search` 不能跨实例串调用。内部 connectorId／actionId 是 Axon 管理模型，不是要求服务实现的私有 MCP 字段。通用 MCP 无需先手工创建定义；同名服务也不自动被判为契约一致。

目录快照及缓存按实际认证主体、连接修订隔离；不每轮全库联网发现。调用结果区分协议错误、`isError`、超时、未完整结果和业务回执；正文／结构化结果有界处理，不自动解释为 Axon 原业务动作已完成。

### 8.3 复用 Pi、专家和 R3A

连接模块不依赖 Pi 原生类型，由 `src/pi` 适配获准工具、原确认、流式、取消与历史。新通用连接经独立准入解析装配；**原 `allowedTools:null` 不能被直接扩义为“所有新 MCP 都允许”。**

专业专家增加必要的连接能力引用／动作契约约束（如 `connectorRequirements`，最终 DTO 在 R4-0 映射），不保存个人凭证、不要求新建任务绑定。固定业务依赖走原映射；通用依赖走第六章规则。旧专家不自动扩大，变更依赖走原草稿和发布流程。

R3A 的表单和管理 Skill 只扩充真实目录、依赖建议与字段保存；不开放连接登记、认证、远程调用或发布权限。专家／Skill 试用均可选，连接引用校验不新增联网业务试用门槛。[S3、S10]

## 九、配置修订、普通启停与效果不明

### 9.1 保留什么，实时核验什么

| 内容 | 本轮规则 |
| --- | --- |
| 稳定身份 | 连接 ID 与旧来源映射不因改名变化；不能用显示名恢复目标。 |
| 请求配置 | 固定连接修订、实际认证主体的非秘密引用、目录摘要和动作参数；执行中不切换。 |
| 地址／外部账号变化 | 留新修订，影响现有选择时提示重新确认；实质更换业务系统需迁移判断，不冒用旧历史。 |
| 同账号凭证轮换 | 使用现行有效凭证，记录版本并失效缓存；不将旧秘密冻结进历史。 |
| 授权及状态 | 准入、调用和确认后重新检查；内容缓存不能缓存授权结论。 |
| 历史结果 | 保留当时来源与时间，读取历史不自动发起外部请求。 |

锁定配置与契约不等于锁定远端程序或数据；不能承诺旧会话能复现远端服务历史行为。切换连接也不删除已进入会话的旧内容。

### 9.2 普通停用不等于安全封禁

普通停用拒绝新的准入；已准入且明确持有该连接执行范围的请求按原快照收尾，不借继续输入扩大工作。普通恢复不重放任务，不清除既有 `banned` 或账号拒绝。管理、入站接收与出站调用按各自状态明确处理。

撤权、账号失效或凭证失效应阻止后续调用并尽力取消受影响执行；这属于新增链路基本守卫。全局紧急停止、统一封禁／解除和跨实例处置平台继续留在 R7，不因本轮增加连接而提前建设。

### 9.3 不让重试产生重复业务效果

安全读取、发现和连接重建可有限重试；语义未知或有副作用的调用默认不自动重试。写操作发送前持久化最小意图：请求、连接修订、动作、参数摘要和上游关联标识；重启不重放。

发出后取消／断网且结果无法核实时显示“结果待核对”，不是“未执行”。有回查接口则查询原操作，无接口则保留未知。SDK 重连和 MCP 请求 ID 不构成业务幂等保证，既有指令继续由原 CommandService 核对回执。[S8]

授权撤销不应顺带取消其他用户／其他连接的无关请求。调用参数和结果按原拥有者权限读取，普通目录不公开私有参数。

## 十、技术落点、存储与迁移

### 10.1 最小分工（路径是建议）

| 位置 | 本轮职责 |
| --- | --- |
| `contracts/connectors.ts` | 连接、动作、认证模式、选择及调用摘要；不含 SDK／Pi 原生类型。 |
| `connectors/` | 具名配置、受控适配器注册、原业务固定映射约束、秘密引用、授权、MCP 客户端和传输。 |
| 原 context／commands／入站模块 | 通过统一接入解析访问原服务；继续拥有业务权限、时钟、回执、队列及投递。 |
| `pi/` | 获准目录、目标解析／原生提问、工具映射、调用确认、取消及新旧历史兼容。 |
| 专家管理／authoring | 共用连接能力引用与目录，保存草稿，不增加远程管理执行权。 |
| 原能力中心／会话 | 管理配置、获准目录、轻量选用与来源／错误展示；不增加页面体系。 |

继续单服务进程，不新增微服务、消息总线、通用路由器或第二 Agent 循环。不为此次范围限制强制引入统一 `single/multiple/maxInstances` 管理模型；在已有业务注册和服务端提交边界落实必要约束即可。

### 10.2 必要记录与接口

连接修订、动作快照、原来源固定映射、管理审计和动作回执优先扩展原能力库；会话选择与实际执行清单关联原会话，不复制聊天库。**不新增任务—连接绑定表／接口，不新增个人—席位—任务默认继承配置。** 原 contextScope、任务和场景权限保留。

可沿用原稿拟议的 `/api/capabilities/connectors`、`/api/admin/connections/*`。个人接口仅管理本人对已开放服务的凭证／认证状态，不允许创建任意目标。实际路由和表结构在 R4-0 对照实现确定，不提供任意 URL／任意 MCP 方法代理。

管理写入用 CAS 和持久动作 ID；并发创建、重复迁移及响应丢失不产生重复连接或绑定。秘密先受控持久化再提交引用，失败可核对，不假定跨库天然原子。原生历史为聊天事实来源，最小调用意图仅用于核对外部效果。

### 10.3 迁移与回退

先在数据副本 dry-run，盘点系统／来源／场景／指令／Profile／凭证引用，输出固定映射与冲突。停服全备份后显式 apply，不重写业务对象、旧 ID 或历史字节。旧配置只保留明确的兼容读源或历史输入，不双写、不自动覆盖已迁移对象。

回退配对原程序、全量数据／配置及可用密钥版本，保留 R4 新数据供核对。新增严格历史格式也可能影响回退，不能因没有业务表迁移就直接使用旧程序打开活动根。部署、生产迁移及提交推送仍需单独授权。

### 11.2 多实例与单实例分开验收

**单实例线：** 验证当前特情／态势正常使用和消息投递不退化，第二业务实例的管理请求、并发创建及配置导入被明确拒绝；不要求连接两个真实特情系统。

**多实例线：** 至少两条同类通用 MCP 连接，覆盖不同地址及同地址不同认证主体；真实目录、目标选择、调用和记录互不混淆。使用受控服务测试凭证、Schema 变化、写入和取消，不把模拟业务说成真实第三方业务。

建议 Microsoft Learn MCP 为公开只读真实目标，官方提供远程 Streamable HTTP 且无需认证；实施时实测版本及工具，不根据文档造结果。该目标验证接入能力，不代表要把微软技术文档列为业务必需知识库。[E6]

### 11.3 验证纪律

运行实际仓库 typecheck、lint／边界、build、单元／集成及相关 1060／1440 桌面浏览器回归。真实模型、真实网络、合成服务和用户验收分别留证；保留失败及准确复测范围，不复用历史“通过”冒称本轮实测。

量测目录／上下文大小、冷热装配、首次调用及取消耗时，记录样本，不承诺未经测量的毫秒目标。网络或凭证缺失时列明未验证项，不用替身掩盖真实接入未完成。
