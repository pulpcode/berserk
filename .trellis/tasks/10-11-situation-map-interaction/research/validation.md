# 本轮实施与验证记录

日期：2026-10-11。仅本机独立数据验证，未发布线上，未自动批准业务投递。

## 实现范围

- MapLibre 6.4、在线 OSM 栅格底图配置，统一全局/任务/对话侧栏地图；实际 OSM 道路节点、模拟态势叠加。
- 现有 ContextService 权限下的地图查询、实际查询依据定位、正文 Markdown 对象链接校验；旧依据与当前状态分开。
- `contextRefs` 最多 20 个，宿主在发送时加载当前对象，复用 Pi 原生 custom message 和历史投影。无 Pi 内核修改。
- 独立模拟源 SQLite 快照、受控状态/报告修改、保存与通知分离、稳定操作编号和接入回执。
- 设置中的模拟控制页，仅配置获准的总体席可用。其他席位仍通过现有资料权限查询。
- 新测试驱动建立独立目录、三个新任务和四个席位，不覆盖既有实例。

- 自动化瓦片全部使用本地替身，未扫描公共 OSM。实际在线服务连通和人工视觉对齐仍待人工验收。

本机默认 5187 端口已有另一工作区的 Vite；首次浏览器运行误复用旧页面。添加可选 `AXON_E2E_PORT` 后改用 5198，保留默认端口，不停止其他工作区服务。最初受本机监听沙盒限制的测试经授权重跑，不计为功能失败。

完整 Playwright 首轮为 155/160 通过，五项失败已定位：

- 两项普通链接焦点回归：Markdown anchor 的内联组件每次更新重新挂载，导致流式过程丢失焦点、提前折叠。改为稳定组件类型，通过 Context 传依据，不放宽原断言。
- 一项测试替身遗漏：旧聊天 mock 未处理新增地图目录/配置 GET，误当会话读取，解析 undefined 报错。补显式空目录及未配置响应。
- 两项模型选择测试使用过时导航：此前已合并 UI 中，点击任务标题进入任务详情；测试仍假设直接进入聊天。已核对实施前 HEAD 同样行为，测试改为进入任务下已有会话，业务断言保持。

最终 TypeScript、ESLint/依赖边界与生产构建均通过；地图渲染器分包约 942 KiB（gzip 248 KiB），仍有构建体积提示，不阻止构建。

新增空白对话“引用地图对象”入口，允许首次发送前连续选择道路和车辆池；浏览器用例覆盖两对象及草稿重开。视觉核对还修正了模拟保存反馈中会过期的“尚未发送”文字，发送状态以下方操作记录为准。

## 真实模型验证

模型：本机既有配置 `deepseek-flash`。测试使用合成资料，执行容器关闭，仅调用资料查询与已有业务记录工具。

### 首次对象引用

独立批次 `map-18669d87`，一次显式提问，宿主加载两个对象，处理成功。道路初始 open、车辆 4、任务要求至少 3，模型正确比较数量及时间。实际回答输出了裸 `/situation?...` 地址，未满足 Markdown 正文可点击形式；保留此记录，不能称本次正文定位已验证。

发现工具说明未明确链接语法后，补充通用规则“使用 Markdown `[对象名称](href)`，原样复制 mapReferences.href”，没有追加场景答案、强制调用或自动重试。首次回答另有“未提供停放位置”的笼统说法，虽然已提供车辆池位置；车辆池位置与每辆车具体位置应区别理解，此处仍属于回答措辞问题。

### 状态变化与接续提问

全新批次 `map-c2521246`，独立进行下列三次模型请求，不沿用首次失败回答：

1. 保存车辆 4→2、道路 open→closed（09:30–10:10）；保存后作业列表仍空。发送道路通知后，后台作业 `610c56e2-a320-45c0-9b9d-296f811c50b4` 成功。

3. 保存道路 10:10 恢复 open 并发送新通知，后台作业 `d502f6f8-09e4-4deb-96a7-8b255ebc9f7f` 成功；道路第 3 版 open、车辆第 2 版仍为 2。逐字比较旧作业 snapshot 保持相等。

两次后台结果均固定投递情报席，均建议筹划席/态势席并停在总体席待批准；没有代替人员批准。两个西区任务被关联，东区对照任务未被机械关联。

仍有问题：

- 恢复分析生成了产品不存在的 `/task-read?taskId=...` 链接。地图链接本身正确；不支持的任务链接不是本期新增能力，不把模型生成当成真实入口。

- 有“需查询合成演练正式通告”等不必要核实，以及普通问答结束时再问是否继续查询的保守行为。没有因此追加专用提示或审批流程。
