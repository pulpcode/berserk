# 态势地图人工测试指南

线上已于 2026-10-11 更新，详见 [线上测试指南](server-test-guide.md)。以下命令在 `experiments/harness-lab/` 执行，创建全新本机实例，不混用旧任务。

```bash
npm run build
npm run probe:situation-map -- serve --port 4321
```

打开 `http://127.0.0.1:4321`。终端只打印 URL、测试目录、manifest 和账号文件位置；账号密码在该目录的 `credentials.json`，文件权限为 0600，不提交 Git。用户名为 `overall`、`intelligence`、`planning`、`situation`，密码每轮随机生成。主要使用总体席与筹划席。Ctrl+C 停止本轮 Axon 和模拟进程；重新运行创建新批次，保留此前测试目录供核对。

## 1. 地图与引用

1. 总体席登录后打开左栏“态势地图”，应见西区、东区道路、车辆池和区域。实际地理背景为新加坡 Orchard Road 附近，业务状态均为模拟。
2. 核对 OpenStreetMap 署名、模拟标识和道路线与底图道路的对齐。在线瓦片需要浏览器联网；此项人工验证与自动化替身测试分开。
3. 打开本轮“西区补给任务”的态势页；选择西区道路或车辆池查看来源、修订、业务时间。初始道路 open、车辆 4 辆。
4. 在该任务新建对话，点击输入框工具栏“引用地图对象”，在侧面板依次引用道路及车辆池。输入“请结合本任务目标，说明这两个对象的状态及影响，列出依据版本”，明确发送。
5. 应看到可移除的对象标签；发送前不会调用模型。模型实际收到宿主查询的对象资料，历史重开仍保留当次版本。有效正文链接可在侧栏地图定位；若模型未输出链接，可使用查询依据的地图入口。

## 2. 模拟变化、通知与分析

1. 总体席在设置中进入“模拟验证”，核对实例编号与本轮任务标题一致。
2. 保存西区车辆池为 2 辆；保存西区道路为 closed，生效时间本轮日期 09:30、有效期至 10:10。仅保存后地图刷新可见新修订，信息中心不应凭空出现作业。
3. 对道路操作点击“发送通知”，核对保存的通知与接入回执。信息中心应出现后台分析；重送同一操作应沿用同一接入记录，不新增分析。
4. 固定接收席为情报席；如果 Agent 建议补充投递，需总体席审批，系统不会自动替你批准。批准给筹划席后，以筹划席在工作台查看。
5. 分析应区分：09:40 补给任务处于关闭窗口且 2<3；10:20 转移任务晚于关闭窗口、单独需求为 1 辆，不能机械判定相同影响。东区对照任务不能仅因地图距离近而被判定受影响。
6. 再保存道路 open、生效 10:10，发送新的通知。地图应是道路新修订、车辆仍 2；旧分析及其查询依据仍保留旧版本。注意临时关闭和恢复通知的事实依据是模拟有效时间，不是实际查询时刻。

## 3. 权限与异常

- 筹划席可查询获准态势，但看不到模拟控制入口，直接请求控制接口也被拒绝。
- 在两个任务间切换、打开/关闭地图，不应清掉现有对话草稿，或把旧响应写入另一个任务。
- 底图断网与模拟源离线应分别提示；已有适用资料保留并说明更新失败，不显示成“无风险”。
- 不要用本次地图数据推导路线可达、行程时长或真实调度结论，本期没有路网拓扑。

真实模型单次引用测试可运行 `npm run probe:situation-map -- verify --port 4324`；它会调用当前配置模型，保存原始 SSE 和会话快照。它不会替人员批准任何交接或投递。
