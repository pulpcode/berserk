# 设计：态势模拟与地图交互接入

状态：已审阅，获准实施。接口细节以 [integration-contract.md](integration-contract.md) 为准。

## 1. 系统职责

| 部分 | 负责什么 | 保存什么 |
| --- | --- | --- |
| 独立模拟服务 | 维护合成报告、态势状态与空间位置；供查询；按测试人员指令发通知 | 本实例的对象、报告修订、变化和发送记录；使用自己的测试数据目录 |
| Axon 宿主 | 登录、权限检查、查询适配、通知接入、后台执行与席位投递 | 现有 SQLite 元数据和业务回执；不建立完整外部态势镜像 |
| Pi 会话 | 根据用户或 Profile 目标，按需查询、分析、生成文件 | 原生 JSONL 保存模型上下文、已加载对象及实际工具结果 |
| 地图组件 | 呈现授权查询结果，选择和引用对象 | 页面内缓存及视图状态，不作为业务事实来源 |

模拟服务继续为独立 Node.js/TypeScript 进程，沿用现有 HTTP 适配方式；Axon 仍为 React/TypeScript、Fastify 和 Pi。地图引入 MapLibre GL JS，不引入第二个 Agent 内核。

本期测试控制页复用 Axon 页面框架与登录，建议路径 `/simulation`，入口在设置中的“模拟验证”。它是开发验证入口，不是日常业务席位的态势编辑功能。宿主只能转发配置中指定的模拟控制接口，不能接收任意 URL；模拟控制接口不加入 Agent 工具列表。

## 2. 地图入口和页面

### 2.1 全局“态势地图”

左侧与“工作待办”“工作总览”并列，具备态势查询范围时显示；建议路径 `/situation`。无须先选任务即可浏览。

页面结构：顶部为来源、区域、对象类型筛选和刷新；中央为地图；右侧为选中对象详情；紧凑对象列表可展开，与地图选择联动。保留应用侧边栏，不使用遮住整页的模态弹窗。

对象详情显示名称、类型、状态、源系统、修订、业务生效时间、有效时段；“本次查询时间”与源数据截止时间分开。资源池标为“可用车辆 2 辆”，不能画成两辆实时定位车辆。

从这里“引用并提问”时才选择可见任务或个人空间，创建普通会话草稿；已从某个对话打开地图则返回该对话。保存位置选择不创建任务关联、不分派工作。

### 2.2 任务内“态势”页签

在现有“相关信息 / 任务说明”旁增加“态势”。标题保留任务名称，默认突出任务 `businessRefs` 与 `focus.areaIds` 对应的对象。

默认展示集合为“显式引用对象 ∪ 关注区域内对象”，分别查询后按完整引用去重；不能把两类条件放入现有 AND 查询而漏掉对象。外部报告引用可读出其中的对象引用，再定位获准态势对象；不是自动关联整个来源系统。

若没有结构化条件，显示“尚未设置态势范围”，可选择区域或切换“全部获准态势”；不从任务标题猜测范围，不把空筛选呈现为没有相关情况。区域条件沿既有可查询系统解释；多系统区域编号冲突时显示系统名称，不静默跨系统合并。

“任务关注”只是视图，不等于模型确认的任务影响；任务的时间条件也不把当前态势转换成历史快照。点击对象进入详情；不自动修改任务元数据。

### 2.3 对话和信息详情内查看

Agent 回答正文支持可点击的对象名称，例如“[西区通道]仍有限制，[西区车辆池]可用 2 辆”。点击名称，在右侧地图定位并高亮对象；现有“查询依据”旁同时提供“在地图查看”。前台对话及获准读取的后台分析正文共用这一交互。

宿主从成功查询或发送时加载的结构化资料生成对象链接，随资料提供给模型；模型可在回答中使用这些 Markdown 链接。前端核对完整对象引用与已保存依据后展示定位入口，不通过正则猜测自由文本中的地名。报告仅使用它实际返回的对象引用。具体契约见接口文档第 3.2 节。

无对应依据的链接显示为普通文字；对象缺少位置时说明“暂无位置”，不猜坐标。模型未使用链接时仍可从查询依据查看，不追加模型调用来强制补链接。点击时重新检查资料权限，链接本身不授予读取权。

打开右侧非模态地图面板，保留对话、流式输出和输入草稿。侧面板内的对象详情放在地图下方，不再嵌套另一列。面板可收起，提供“展开地图”打开完整地图页；返回时恢复会话位置。桌面空间不足时收起辅助列表，仍可通过对象详情操作；不新增手机布局。

来自旧查询的入口显示“依据版本 N；地图显示当前态势”，当修订不同则同时列出当前版本。仅有报告对象引用而未查到对象修订时，显示“报告关联对象；地图显示当前态势”，不把报告修订当成对象修订。地图当前结果不写回旧消息，不伪装成历史地图回放。

### 2.4 共同交互

- 缩放、平移、图层开关、对象列表选择和刷新直接查询或改变视图，不启动模型。
- 道路状态使用线型/标签及颜色共同表达；未知状态不按可通行着色。缺少位置的对象列在“未定位对象”中。
- 支持键盘操作对象列表、详情、引用和关闭；无需精确点击线条才能使用功能。继续使用现有图标、颜色和焦点样式。
- 首次加载和手动刷新查询当前数据；页面可见时每 15 秒刷新已选范围，隐藏/离开即停止，不做 WebSocket 或每次地图拖动查询。
- 不重叠刷新；新筛选取消旧请求。分页收齐后整体替换显示；更新中仍保留上一幅画面。来源变化导致游标过期时重取第一页一次，再失败则保留旧画面并提示手动刷新。
- 多来源分别显示更新时间和错误；某来源失败不能把它的对象全部画成消失。地图能力包按需加载，普通聊天不加载地图渲染器。

## 3. 模拟资料与底图

### 3.1 对象与来源

继续使用 `(systemId, objectType, objectId)` 引用。态势对象增加可选 `geometry`，支持 GeoJSON Point、LineString、Polygon；道路补充结构化通行状态。完整约束见接口文档。

态势系统拥有区域边界、道路形状与通行状态、资源池驻点和数量。特情系统拥有报告正文、观测时间、修订与所引用对象；本期通过对象引用定位报告，不自动从报告文本提取坐标。

道路限制既可能来自报告，也可能来自态势记录。准备脚本可分别更新两者，再按场景选择发送通知；二者仍有独立修订，不承诺跨来源原子更新。这只是测试人员安排的合成事实。正常接口仍允许二者不一致，地图呈现态势记录，报告作为独立来源供核对，不能把 Agent 的推断写成道路状态。

### 3.2 底图选择

选用 **MapLibre GL JS + 在线 OpenStreetMap Standard 栅格底图**。MapLibre 是开源渲染框架，OSM 提供开放地理数据和在线底图；底图由浏览器直接读取，无须商业地图密钥、本地瓦片部署或服务器代理。它与模拟服务提供的态势图层分别加载。

坐标仍采用 WGS84 经度、纬度顺序。测试准备选择小范围真实区域，道路线与选定底图道路对齐；道路限制、资源池状态及任务数据仍为模拟。页面持续标明“模拟态势”，并显示链接到 OSM 版权页的 `© OpenStreetMap contributors`。态势标签和图标随应用提供，不依赖外部字体服务；底图地名由在线瓦片提供。

本期按小规模人工验证使用公共瓦片：采用官方 HTTPS 地址，保留浏览器正常缓存及 Referer，不提供离线下载或批量预取；自动化测试使用瓦片替身。底图服务没有可用性承诺，配置保留替换服务地址与署名的入口，不建设供应商管理后台。依据：[OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。

瓦片不可用时显示“底图加载失败”，保留可加载的态势图层、对象列表与重试入口，不能呈现为态势源故障。每 15 秒刷新只更新态势数据，不重建底图或绕过瓦片缓存。发布前从实际测试浏览器验证联网可用性。

MapLibre 负责空间展示，不提供道路拓扑、地名解析或路线求解。拟真底图不代表模拟限制是真实通报，也不证明线路互通或可以按图调度。本期不建设路网服务。

### 3.3 修改、通知与复现

控制页展示当前模拟实例、对象状态、报告修订及最近通知。人员可修改道路状态、资源数量与生效时间，或发布报告新修订；坐标和基础对象由受控场景文件预置，本期不做绘图编辑器。

“保存变化”先持久保存新修订；“发送通知”另行调用既有接入接口。每次保存产生稳定的操作编号，重试不重复加版本。通知也使用稳定 `sourceMessageId`，接收超时先查回执，可明确重送同一内容，不自动启动第二次分析。

模拟数据建议采用独立 SQLite 文件，保存有界场景快照和操作/发送记录，源变化与待发送通知在同一事务写入。需求是服务重启后继续当前测试、明确已保存和已发送的区别；不建设通用消息中间件或跨系统事务。通知失败不撤销源数据变化。

新一轮测试由准备脚本建立新模拟数据目录和新任务，实例标识进入对象、区域、报告及通知编号；旧编号不会重新代表新事实。重启同一实例保留原状态。创建新实例不自动删除 Axon 旧任务、文件或会话；本期控制页不提供一键清空 Axon 数据。

## 4. 地图如何参与 Agent 上下文

点击“引用到对话”添加可移除的对象标签，不粘贴整张地图或自动发送。发送请求增加可选 `contextRefs`，只接受完整对象引用；按完整引用去重，本期最多 20 个，与文件附件分别计数。

宿主按当前席位权限查询所选对象的当前状态，加载对象名称、修订、状态、时间和来源查询记录。浏览器传来的标签或地图颜色不作为事实。引用表达“发送时读取这些对象”；如果选择后源数据更新，则加载新版本，并在消息资料标签中显示实际加载版本。

加载内容沿用 Pi 公开 custom-message 机制与原生历史，作为本次用户选择的资料；扩展现有 composer input 的可选字段并保持旧记录解码，不建立第二份可修改的聊天历史。不伪造 `situation_query` 工具调用记录；界面区分“发送时加载”与“Agent 查询”。

Agent 可继续用既有 `situation_query`、`information_search/read`、任务查询和文件工具完成工作。无需新建 `map_read` 工具，无需截图视觉能力；本期不支持空间距离、连通性、可达路线推理工具。只读 Agents 不因地图引用而自动获得更多工具权限。

所选对象不存在、无权限、查询失败或总加载内容超过限制时，在模型启动前返回明确错误并保留草稿，由人员刷新或移除引用；不静默丢失引用。对话仍须遵守当前请求/HITL 等待规则。

## 5. 权限与隔离

- 普通地图和模型查询复用 `ContextService` 与当前席位/后台服务身份；浏览器不能选择服务身份、扩展 scope 或传入外部访问凭证。
- 本期仍是既有系统级资料范围。不同任务可查看同一获准道路，任务筛选不构成数据隔离；任务 × 席位的文件、对话和交接隔离继续保持。
- 模拟控制须显式启用测试配置，且当前席位拥有对应模拟来源的管理授权及资料读取权限；预置只授权总体席。管理其他来源不自动获得此权限。
- 模拟查询、控制、通知接入使用分离的服务端凭证。Agent 无控制工具，普通地图也无写接口权限。
- 在线底图请求仅用于读取视野内瓦片，不携带 Axon 登录令牌、任务内容或态势对象属性；服务可看到请求的地理视野。采用 `strict-origin-when-cross-origin`，保留来源站点而不传会话路径；不复用携带认证和 no-store 的业务 API 客户端。
- 换席位、任务或来源时取消请求并清空不适用缓存；所有迟到响应按身份和视图版本校验，不写入新视图或新草稿。历史资料沿既有权限读取；不在本期追加撤权追溯收回体系。

## 6. 兼容、部署与回退

空间字段可选，旧对象没有坐标仍可查询；道路旧 `properties:{}` 解释为状态未提供。历史 JSONL 不重写。原有 sourceId、Profile、审批与事件契约保持不变。

测试服务器仍部署一个 Axon 实例、一个模拟进程；地图是浏览器组件，底图来自在线服务，无需单独地图服务器或容器。模拟持久数据目录与 Axon 目录分离，凭证保留在服务端。

发布时一起更新源契约与宿主校验；先备份模拟数据、应用数据和构建产物。回退应恢复匹配的源/宿主版本与测试配置，不能将新格式强塞给旧严格校验器。关闭地图入口及模拟控制不会改变已完成投递和文件交接。
