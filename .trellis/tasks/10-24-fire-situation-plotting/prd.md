# 消防专业标号与单地图态势标绘方案

版本：V1.1 已批准实施｜日期：2026-10-25

用户已确认交互方向：**实时态势和标绘共用一张地图，需要时展开标绘工具，首期不拆成两个页面。** 用户已于 2026-10-25 明确要求“提交方案git，然后开始实施”。

## 1. 方案摘要

在现有任务地图内叠加来源态势、指挥部署和分析结果。日常查看时收起标绘工具；需要表达现场情况、研判或计划时，在原地图展开工具并编辑有权限的草稿。查看态势和进行标绘可以同时发生。

| 事项 | 本版方案 |
| --- | --- |
| 页面组织 | 单地图工作区；取消“事件作业 / 指挥总览”双入口及“态势 / 标绘”顶层模式切换 |
| 编辑入口 | 地图内提供“标绘工具”，按需展开、收起；打开面板本身不创建会话、文档或版本 |
| 同图内容 | 来源态势只读；当前部署、我的草稿、参考版本和分析结果分层显示 |
| 更新与保存 | 来源按既有机制刷新；标绘独立保存、发布、设为任务当前，彼此不覆盖 |
| 首期范围 | 22 个专业点标号条目、基础线面文字工具、属性编辑、共享渲染及现有 Agent 工具适配 |
| 实时能力边界 | 首期保证查看与标绘并行且不打断现有来源刷新；真实 GPS/AIS 接入、推送和轨迹回放仍延后 |

技术上复用 MapLibre、Terra Draw 和现有草稿、版本、权限机制。单地图是界面组织决定，不意味着把来源、草稿和发布版本合并为一份可写数据。

## 2. 用户方向与本轮变化

已确认：使用独立 worktree；专业、非卡通风格；需要消防车、救护车、消防艇、冲锋舟及救援舰船；仅面向桌面浏览器，同时适配桌面窄面板；采用单地图、按需展开标绘工具；先审方案和符号样张，再实施；现已收到明确实施指令。

本版替代 V1.0 中“两种工作模式”和后续预览中的“事件作业 / 指挥总览”页面划分。独立指挥大屏、只读总览或岗位工作区不作为首期交付，也不预建空入口；未来出现实际岗位或部署需求时再评估。

最新交互方向见本对话的单地图效果图。预览采用模拟位置和示意图标，用于审阅交互，不代表已接入真实定位或已完成标准图形核验。[旧预览留档](research/approved-preview.html) 仅作历史参考，不能继续作为双模式实现依据。产品范本及决策记录见 [工作区调研](research/workspace-patterns.md)。

## 3. 概念与数据边界

| 概念 | 含义与边界 |
| --- | --- |
| 标号 | 消防车、消防艇、人员等对象的图形及注记表达规则 |
| 标绘 | 编辑地图信息的能力，可表达现场记录、研判或拟定方案；人和 Agent 均可使用 |
| 态势 | 汇集授权来源、标绘及分析结果，理解当前情况与变化；可包含人工现场记录 |
| 实际位置与计划位置 | 前者来自明确观测，后者表达拟部署地点；可以关联并同图出现，不能互相替代 |
| 信息性质 | 现场记录、研判、拟定方案；历史缺省显示“未注明” |
| 文档生命周期 | 本会话草稿、已发布版本、任务当前版本；沿用现有机制 |

信息性质、来源与生命周期独立。已采用的方案仍然是计划，不代表车辆已到场或任务已完成；手工现场记录也不因人工绘制而自动归为计划。来源查询时间、业务生效时间、观测时间和标绘保存时间不能互相替代。

## 4. 现状与缺口

| 已有能力 | 本期补齐 |
| --- | --- |
| 来源态势、会话草稿、只读参考版本、分析结果 | 单地图内清楚的分层、按需标绘和属性操作 |
| 点、线、面、文字与 Terra Draw | 专业点标号、方向、尺寸及常用线面模板 |
| 固定修订、发布、任务当前、来源引用、冲突处理 | 新样式和信息性质跨网页、服务、Agent 一致保存与读取 |
| 来源业务时间、查询时间及既有定时刷新 | 标绘时刷新连续，保持输入与地图上下文 |
| 路网、影像、混合底图 | 专业符号的可读性、命中与重叠消歧 |

当前点标绘主要是圆、方、三角；来源点使用通用表达。当前来源契约是道路、车辆数量汇总和区域；一条“可用车辆数量”不能解释成一辆消防车或实时船舶。现有页面约每 15 秒重新查询来源，不等于提供单车 GPS 数据。证据及原始文件行号见 [调研记录](research/evidence.md)。

## 5. 首期功能要求

### R1 统一专业符号目录

以 XF/T 3013—2020《国家综合性消防救援队伍常用标号》为主要依据，首批建议 22 个条目：20 个有明确标准索引的符号，以及 2 个需核对适用范围的水域救援扩展需求。

| 类别 | 首批条目 | 数量 |
| --- | --- | ---: |
| 灭火及高空作业车辆 | 水罐、泡沫、干粉、泵浦、云梯、登高平台、举高喷射消防车 | 7 |
| 救援及保障车辆 | 抢险救援、化学事故抢险救援、化学洗消、照明、通信指挥、排烟、供水消防车 | 7 |
| 医疗、水空救援 | 救护车、消防直升机、消防无人机、消防艇 | 4 |
| 人员及集结 | 战斗员、集结地 | 2 |
| 应用扩展需求 | 冲锋舟、救援舰船 | 2 |

- 每项记录中文名、稳定 ID、类别、标准条目或扩展来源、尺寸和方向规则；实施时先完成整套样张及小尺寸核验。
- “消防车”是分类，不把类型未知的车辆自动当作水罐车；救援舰船也不直接等同消防艇。
- 冲锋舟、救援舰船先核对标准适用范围；无明确对应的独立子类标记“应用扩展”，采用一致的线性、几何化风格，不冒称标准原图。
- 来源与标绘共用目录及渲染规则，但保留各自身份、权限和版本。

### R2 单地图与按需工具

**默认查看**：原地图展示获准来源、任务当前部署及已有可见图层。提供选择、定位、显隐和引用到对话；标绘面板默认收起，没有第二个“指挥总览”页面。

**展开标绘**：点击“标绘工具”，展示符号目录、点线面文字工具、明确的目标草稿/图层及属性。打开面板只是界面动作，不自动创建新草稿、会话或持久版本。实际编辑沿用本会话可写、任务未归档等限制；无可写上下文时展示原因和现有打开/新建会话入口，不能借工具展开获得写权限。

**边看边画**：来源按原机制继续刷新；选择来源对象查看详情不改变草稿编辑目标、不清空输入。地图不因刷新自动定位或跟随移动对象，工具与未完成输入不被刷新重置。

**收起工具**：停止当前绘制/拖动交互，回到地图浏览；保留当前上下文内的草稿、属性输入与未完成绘制缓冲。收起不等于保存、取消、发布或采用，不要求每次收起都弹确认。再次展开恢复原目标与输入。未完成几何不冒充已保存对象；需要继续绘制时显式恢复工具。

**图层与上下文**：有效的草稿预览独立标记“草稿/未保存”，收起后按原显隐状态保留，可单独隐藏；不自动成为任务当前成果。展开、收起和来源刷新保留地理中心、缩放、已有图层显隐和合法选择，不重建地图。切换任务、身份、会话、目标文档或真正离开编辑上下文时，才沿用保存、放弃、取消及晚响应防护；本期不承诺新增跨刷新恢复机制。

### R3 标绘、属性与版本操作

- 点：选标号、放置、设置名称/方向/尺寸，保存到明确目标图层。
- 线：普通路线及方向箭头，复用折线编辑，不做自动寻路。
- 面：搜救区、警戒区等应用模板，不宣称实现全部消防战斗行动标号。
- 文字：点锚定注记，支持内容及位置编辑。
- 可写草稿支持修改几何、标号、注记及信息性质；来源和固定参考版本只能查看，需沿用现有派生流程才可形成可写副本。
- 保存草稿、取消本次编辑、发布、设为任务当前分别有明确操作；完成绘制不自动发布，发布不自动采用。采用后只更新当前部署叠加层，不改动来源位置或业务行动状态。

### R4 信息性质与来源关联

新建普通标绘默认“拟定方案”，可显式改为“现场记录”或“研判”。这是用途声明，不代表已核实。历史无字段对象显示“未注明”，不批量猜测或重写。

来源身份由 `systemId / objectType / objectId` 共同确定。关联资源的计划通过现有 `sourceRefs` 表达，保留独立标绘 ID、几何与版本，显示关联关系；不加入来源可用数量统计。复制来源得到的是快照，不自动随来源移动。

实际位置与计划位置可同时显示，分别标明信息性质、名称与来源组；不按同名合并，也不因存在来源引用就断言几何仍与来源一致。

### R5 专业符号与界面状态

- 专业标号保留标准的主体形状、颜色和方向语义，不将整个图形随待命、作业或离线状态改成红黄绿。
- 业务状态使用来源原值的文字或独立标签；没有数据则显示“来源未提供”。
- 草稿、发布、任务当前以分组标题、版本和详情表达；计划使用明确“拟定”标记，适用的行动线依规范采用虚线。
- 预览的蓝、橙、紫只是辅助区分实际位置、当前部署和草稿；正式符号遵守目录规范，不能照搬为整套消防标号配色。
- 选中衬圈、控制点、草稿辅助显示仅属于交互状态，不写入发布内容。
- 允许规范内的显示尺寸、衬底/描边以适配底图；标签避让不能悄悄隐藏实际资源，重叠对象必须可选择。

### R6 来源刷新、时间与实时接入边界

首期保留并复用现有来源查询/刷新机制。标绘面板展开、表单输入、保存和发布不暂停来源刷新，也不把一次来源刷新当作草稿修改；不能因此产生新修订、冲突或覆盖正在编辑的几何。

展示来源业务生效时间、有效期、查询时间和资料截止时间；如果没有真实观测时间则显示缺失，不用当前时钟伪造“刚刚定位”。来源刷新失败时保留仍获授权的适用数据，标明失败/可能过时；权限撤销沿用既有清理规则。明确有效期结束时提示失效，不新增通用于所有资源的“超过 N 分钟失联”判定。

真实单车/单艇定位后续若接入，也按相同只读来源层展示；需要另行明确个体身份、定位时间、坐标系、更新质量和过期规则。本期不扩展当前汇总来源协议、不新增 GPS/AIS、推送、跟随或回放功能。预览的模拟移动仅证明交互可以并行。

### R7 既有入口、桌面布局与 Agent

- 全局、任务、对话地图入口复用同一套单地图能力；既有只读上下文按权限显示，不为本期新建独立展示页。
- 宽窗口采用图层/资源区、主地图及按需停靠的工具/属性区；工具收起后释放地图空间。窄桌面窗口在地图下方或既有折叠区呈现工具，避免遮住主要对象和输入，不强塞三栏。
- 地图容器调整只触发尺寸适配，不重置地理视角；工具展开、对象查看与底图切换遵守相同状态保留规则。
- Agent 沿用现有写入工具、符号 ID、字段校验和保存服务；不增加第二套写通道或自动发布。面板开关不改变 Agent 权限。
- 保留固定引用、来源复制、冲突草稿、幂等回执及旧对话历史读取。

## 6. 首期不包含

独立指挥总览/大屏页面、岗位工作区或第二套业务系统；真实 GPS/AIS、推送、轨迹回放及对象自动跟随；新的资源台账/调度执行系统；多人即时协同编辑；自动寻路/灾害预测；完整军标及全部消防战术符号引擎；任意上传 SVG；移动端；重做工作台/对话整体布局；新的发布审批规则；全量历史数据重写或新增草稿持久恢复机制。

| A3 | 工具收起/展开及底图切换不重建地图或重置地理视角；收起不写入，重新展开恢复目标、输入和未完成缓冲；真正切换上下文才处理脏数据 | R2、R7 |
| A4 | 消防车、救护车、消防艇、冲锋舟均能新增、调整、保存和重新读取 | R3 |

| A9 | 旧圆方三角、固定修订和发布内容可读；保存失败、并发冲突及晚响应不丢输入或串任务 | R2、R7 |
| A10 | 网页与 Agent 对同字段执行一致校验；非法符号、方向或越权写入无部分保存 | R7 |

| A12 | 火灾、水域救援完成“同图查看→展开标绘→收起并继续查看→恢复→保存→发布→采用”闭环；无第二页面，来源不受版本操作影响 | 全部 |
| A13 | 草稿收起后仍按原图层状态显示并可独立隐藏；保存/发布均不替换任务当前版本，采用才更新当前部署 | R2、R3 |
| A14 | 打开工具本身不创建文档/会话或改变权限；无可写上下文时不能编辑来源或固定参考版本 | R2、R7 |

定位并行测试使用明确标为测试的数据更新，不能将其验收结果表述为已完成生产 GPS 接入。

## 8. 交付、风险与审阅状态

交付：受控符号目录和素材来源记录、共享渲染、单地图按需标绘与属性编辑、跨层契约/Agent 适配、相关验证及两个演示案例。技术方案见 [design.md](design.md)，后续执行清单见 [implement.md](implement.md)。

主要风险：标准样张的比例/方向需逐项核验；扩展图形不能冒称标准；现有来源粒度限制实际态势内容；工具折叠与来源刷新需保护编辑缓冲；共享地图文件可能与其他 worktree 重叠。兼容、素材回退和并行整合措施已写入设计与实施清单。

**审阅重点**：本版的 22 个首批符号及扩展处理；单地图中“收起保留、显隐独立、采用才更新当前部署”的操作规则；首期聚焦地图表达与编辑，真实定位接入另行规划。工作区是否拆分已解决，不再作为未决问题反复询问。

**状态**：2026-10-25 用户明确要求先提交方案，再开始实施；此前“暂不改代码”的限制已由该指令解除。已审阅的 [22 个符号样张](research/fire-rescue-symbols-22.pdf) 和 [素材来源清单](research/symbol-source-manifest.json) 留档，标准符号 20 个、应用扩展 2 个。
