# 交付入口：信息自动归口与任务内接续处理

日期：2026-10-09。状态：**已实现并完成工程验证，待用户验收；未更新线上服务**。

## 实现内容

后台 Agent 查询信息与已有任务后，可以记录已有任务关联，也可以建议新建公共任务。新建建议包含名称、目标和理由，由有工作任务管理权限的人员审阅、编辑并创建；系统同时关联原信息与所选分析结果。

没有匹配任务不等于应当新建任务：仅供参考、依据不足或查询失败时，不强行建立任务。信息可关联多个已有任务，任务中展示同一来源的引用，人员从任务进入本席位工作区继续处理。

## 示例场景

道路限制可能关联“西区补给”和“西区设备转移”，一次分析可记录两个关联；收到一项已有任务未覆盖的独立文件编制需求时，可以建议新建公共任务。实际工程和模型测试结果分别记录，不用示例代替验证。

## 重点取舍

1. 自动关联直接可见并标明理由，人员按需纠正；不逐条发起审批。
2. 自动关联只涉及活动公共任务；个人空间仅由所属席位手动收录。公共关联纠正复用现有工作任务管理权限，同时要求可读来源内容。
3. 信息和分析保留一份，任务展示引用；只有开展文件处理时导入本席位工作副本。
4. 重新分析不改历史结果；自动结果随对应分析版本更新，人工保留／移除优先于自动建议。
5. 关联不授予内容访问权；原投递规则不变。因此有权看任务但没有获准信息的人不会看到该条目。
6. 新建建议不自动创建任务、不阻塞投递；本期每次分析最多提出一个新建建议。人员可创建并关联，也可改选已有任务收录或暂不采纳，不新增审批队列。

## 交付规模与限制

一次增量，按数据与权限、Pi 工具、查询与接续、页面、验证五步实施。复用现有 Pi 循环、历史、SQLite、队列、文件导入与侧边栏，不建设新总线或多 Agent 编排平台。

关联质量继续单独评估：工具调用成功只能证明建议已保存，不能证明判断正确。旧消息无关联时仍可使用收件和人工选择工作区的原有路径；不会后台自动重跑历史消息。

当前代码保留在工作区，尚未提交或部署。部署需停服务备份现有数据后升级 SQLite 至 v4；既有任务、历史、消息与附件保留，不自动重跑旧消息。
