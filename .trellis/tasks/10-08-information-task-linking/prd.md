# 信息自动归口与任务内接续处理

日期：2026-10-09。状态：**已实现并完成工程验证，待用户验收；未部署**。交付入口见 [review.md](review.md)。

## 1. 目标

信息经过后台分析后，能归入零个、一个或多个相关任务。人员在任务中查看来源和分析理由，继续提问或处理文件；从任务进入时不必再次选择会话保存位置。

如果 Agent 判断信息需要独立开展工作，而已有公共任务不能承接，应提出新建公共任务建议，说明建议名称、目标与理由。由有权限人员决定是否创建，创建后关联原信息和本次分析；没有关联任务本身不是新建理由。

“归口”指建立可查询的信息与任务关联，不表示已经证实任务受影响，不改变席位分派关系。当前阶段仍是能力验证，具体领域的数据与研判规则不固化为通用框架。

## 2. 实施前的基础与缺口

已实现来源接入、Pi 后台分析、多源与任务查询、固定多席位投递、人员后续对话／后台分析，以及任务 × 席位的文件隔离。当前分析正文中提到的任务尚未成为系统关联；任务内没有相关信息列表，也不能按任务查询这些结果。

已有人工创建公共任务的能力；尚无结构化的新建任务建议，以及从建议创建并关联原信息的入口。

实测已发现时间重叠和缺失信息推断偏差。因此自动关联需要展示理由和来源，允许纠正；不能把成功执行作为关联正确的证明。代码依据见 [research/current-state.md](research/current-state.md)。

## 3. 本期要求

| 编号 | 要求 |
| --- | --- |
| TL01 | 一条信息可关联多个任务，每项都有独立理由；原始信息、附件、分析结果保留原有记录 |
| TL02 | 后台 Agent 在现有分析中查询任务并记录判断，不从自由文本猜任务 ID，不额外启动分类模型；一次分析可关联多个任务，不按任务数量重复处理 |
| TL03 | 自动关联限获准的活动公共任务；区分未记录判断、关联已有任务、建议新建、暂不归口及处理失败，不把查询失败解释为没有相关任务 |
| TL04 | 自动关联可直接展示；获准人员可保留、补充、移除或恢复自动判断，重新分析不覆盖人员纠正 |
| TL05 | 同一消息重送不重复处理；同一信息重新分析保留各次结果和依据，任务列表不因多次处理重复出现同一信息 |
| TL06 | 工作任务及个人空间有“相关信息”入口；显示标题、来源、业务／接收时间、关联理由及分析版本，按现有权限过滤 |
| TL07 | 收件详情展示关联任务；从任务进入默认在当前任务处理，从收件进入优先列相关任务，多个关联不随意预选一个 |
| TL08 | 查看、关联及查询不复制附件、不创建工作区或启动模型；明确开展处理时才按需导入文件、创建会话 |
| TL09 | 席位主 Agent 能按任务查询已关联信息并按需读取原文／分析；不把全部相关信息自动放入每轮上下文 |
| TL10 | 任务关联不扩大来源或结果权限，不暴露其他席位会话／文件／私有任务；多任务关联不自动修改接收席位 |
| TL11 | 有独立工作目标且已查询任务仍无合适承接对象时，Agent 可提出新建公共任务建议；本期一次分析最多一个建议，包含名称、目标及理由，不自动创建 |
| TL12 | 有工作任务管理权限且可读该信息／结果的人员，可编辑建议后“创建公共任务并关联”；也可选择已有任务收录或暂不采纳，建议不阻塞后台完成与投递 |
| TL13 | 创建成功后原信息与所选分析版本出现在新任务中；重复提交同一建议不重复建任务，不自动创建工作区、复制附件、分派工作或启动新分析 |

## 4. 产品规则

以下规则已纳入本期实现范围。

公共任务对应页面中的“工作任务”，其名称、目标等任务说明沿用现有公共可见范围；个人空间属于某个席位，用于独立工作。两者的会话与工作文件都仍按任务 × 席位隔离，公共任务不等于共享所有文件或对话。

- 公共任务的关联由现有“工作任务管理”权限人员纠正；个人空间由所属席位维护。两者还必须有原信息和所选分析结果的读取权限。
- 自动关联只进入公共任务。个人空间可以由人员手动收录获准信息，其存在及关联不对其他席位公开。
- 人工保留／补充会固定所选分析版本，避免后续自动结果覆盖确认依据；人员可明确选择更新版本或恢复自动判断。
- 未记录任务判断时，原分析仍可投递，界面如实说明。不开启强制模型补调用、自动重跑或审批流程。
- 新建建议是分析意见；查询无匹配但无需独立工作、证据不足或查询失败时，应说明原因，不自动建议新建。已有任务能够承接时优先关联；本期不在同一次判断中同时关联已有任务和提出新建建议。
- 创建入口复用现有任务表单和权限，人员确认的是任务名称、目标及关联依据。任务说明会按现有规则公开，原信息、分析正文及附件仍按各自权限读取，不整段复制到公共任务说明。

## 5. 本期边界

本期不建设动态席位路由、全目录文件同步、每个任务自动启动分析、自动改写任务方案、自动建任务、完整权限管理后台或建议审批状态机。现有受控业务操作的人工确认保持不变。

本期不改入站 REST 契约，不把旧 `publicTaskId` 的展示归属自动解释为相关性；来源显式传入多任务关联的接口扩展后置。不将道路和车辆样例答案写入提示词，不承诺本增量解决全部模型推理质量问题。

## 6. 验收与审阅

以同一条道路消息关联两个西区任务、排除东区任务为主例；增加独立需求建议新建、无匹配但不应建任务、人工创建并关联、误关联纠正、重新处理、席位权限及文件接续场景。验收清单见 [acceptance.md](acceptance.md)。

用户已于 2026-10-09 批准实施；实际验证结果另行记录，不将需求示例当作已通过的测试。
