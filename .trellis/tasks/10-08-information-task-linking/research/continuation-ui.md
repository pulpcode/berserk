# 接续处理界面优化

2026-10-09：用户批准将现有长表单改为紧凑接续输入区，并将工作任务的新建按钮改为悬浮／键盘聚焦时显示。本文件为本期交互实施补充，替代旧方案中“进入对话后再发送”的交互。

## 行为边界

- 从任务信息页进入时固定当前任务；收件页单个相关任务默认选中，多个相关任务直接展示供选择，其他任务和个人空间通过次级选择入口选择。选择位置不修改信息关联。
- “继续处理”以输入要求为主体；默认带入本次分析，资料选择和更多选项按需展开。保留 Skill、Agents 和可查询系统信息，不展示目录复制等实现说明。
- 用户明确点击“发送并进入对话”后，沿用现有幂等准备，再向该次准备的确切会话发送首条消息并进入对话。发送复用 useChat 的附件、能力选择、模型校验和流式处理。不能向此前选中的会话发送。
- 查询准备结果、打开关联对话、刷新和迟到响应不自动发送。已保存的对话或草稿不能被再次覆盖或发送；准备结果不确定时保留输入，查询后由用户在对话中明确发送。不新增服务端重试、运行状态或消息幂等协议。
- “后台处理”仍需现有确认后提交；“后续处理”没有记录时不占区域。
- 已确认成功创建会话或后台作业后，自动解除本次提交锁，保留任务和资料选择，可直接选择另一任务处理同一信息；既有处理从后续记录打开，无需“再次处理”解锁。后台提交成功或问题已带入对话后清空已提交的问题；响应丢失后的只读核对保留尚未带入对话的输入。
- 提交中、准备未完成或响应不确定时保留本次提交标识和输入，避免重复建立会话／作业。重新打开页面自动只读核对遗留提交：完成则解锁，未找到则保留文字并允许编辑，仍准备中或查询失败时保留恢复入口；核对不发送消息、不自动跳转或重试。
- 侧栏工作任务的新建按钮仅在所属栏／行悬浮或包含键盘焦点时显示；保留无悬浮设备和折叠侧栏可达性。

## 文件与验证

- InformationContinuation / Inbox / TaskInformation 负责紧凑布局、选择、恢复入口及空态。
- main / useChat 负责明确目标会话的首条发送，保留原对话发送路径和迟到响应隔离。
- WorkspaceNavigation / styles 负责按钮显示和布局；无新增 UI 框架。
- 针对接续、任务信息、模型／附件及侧栏做浏览器回归，验证一次发送、正确任务、原草稿保护、查询不重发、后台确认及键盘焦点。执行 lint、typecheck、build 和相关测试。
- 表单解锁调整以 InformationContinuation 为主，main 的准备回调仅在本次问题实际带入对话时返回 true，导航失效或对话已有独立草稿时返回 false，Inbox / TaskInformation 同步回调类型；补验同条信息先后在两个任务处理、后台入队即可继续、刷新核对和结果不明保护。既有后端幂等、关联与权限保持不变。

本次不改后端存储、权限、任务关联和业务流程，不更新线上服务，不提交 Git。
