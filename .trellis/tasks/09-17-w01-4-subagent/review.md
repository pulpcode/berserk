## 重点审阅

- **复用方式**：Pi 提供官方 Subagent 扩展示例；本项目沿用其委派模式，用公共 SDK 的独立 AgentSession 执行，避免另建循环和压缩机制。
- **角色配置**：通过受控 Markdown 文件定义名称、职责、系统提示和工具集合；预置 analyst、reviewer，添加合法角色文件即可扩展，主 Agent 按任务选择。
- **委派方式**：采用 single，一次调用委派一个任务，可以先后选择不同角色；角色数量与并发模式分别管理。
- **配置生效**：角色目录在父请求准备时加载并固定，文件改动在下一请求生效；子只注册角色获准的只读工具。
- **上下文**：子 Agent 看到显式任务和本项目获准资源，不自动复制父会话全文；AGENTS.md 沿用父请求固定的版本。
- **交互**：原对话中展开子任务卡查看进度和结果；主 Agent 负责最终回答，“停止”结束整次处理。
- **历史**：父子原文分别保存在 Pi 原生文件，父会话保留关联和最终结果；重启不自动重做未完成任务。
- **运行控制**：不新增默认次数或整轮时长上限；如显式配置父截止时间，子任务共同受其约束，用量分别记录后汇总。

网页角色管理和独立角色模型配置后置，本期通过文件配置角色，模型继承父请求。并行、chain、递归、与子 Agent 单独对话和脱离父请求后台运行仍后置。

公开 SDK 独立会话不等于进程沙箱。官方示例的 CLI 子进程和本项目的 SDK 嵌入方式差异，见 [能力核对](research/pi-subagent.md)。本期不涉及任意代码执行或外部调度。

实现与验证见 [验收记录](research/validation-results.md)。本期使用现有 DeepSeek API，本地开发无需服务器凭证。
