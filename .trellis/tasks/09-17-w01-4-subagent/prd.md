# W01-4：子 Agent 委派与协作（S2c）

日期：2026-09-17。状态：**已实现，D01～D13 组合验收通过**。

## 1. 目标

主 Agent 可以根据任务选择不同职责的子 Agent，委派其在独立上下文中工作，取得结果后继续回答用户。优先复用当前 Pi 0.85.1 的公共 SDK 和官方 Subagent 示例思路，保持内核稳定，不另写模型／工具循环、压缩或重试引擎。

本期实现单层、只读的基础多角色支持，预置 `analyst`（资料分析）和 `reviewer`（内容检查）作为通用验收配置。例如，主 Agent 按任务先委派资料分析，再综合形成建议；需要独立检查时，另行选择 reviewer。角色和处理顺序不写死为唯一脚本。

## 2. 范围

- 通过受控 Markdown 文件定义角色名称、职责、提示词和工具集合；支持加载多个角色，添加合法角色文件无需修改委派代码。
- 提供 `subagent({agent: "角色名", task: "…"})` 工具；向主 Agent 提供角色目录，由其按任务选择，不要求每轮调用。
- 每次委派创建独立 Pi 会话，复用父请求的模型配置、获准指令和资料快照，工具限制为只读。
- 同一父请求一次执行一个子任务，可以先后多次委派；不同普通会话仍可独立工作。
- 展示子任务进度、结果或失败原因；用户通过当前“停止”结束整次处理。
- 保存父子关联和原始历史，关联用量；刷新和正常重启可查看已完成结果。

官方示例还支持并行和链式模式；本期只接入 single 模式，即一次调用委派一个角色执行一个任务，不限制角色目录只能有一个角色。网页角色管理、独立角色模型配置、并行编排、chain 模式、递归、与子 Agent 单独对话及后台脱离父请求运行后置。本期实现范围以验收记录为准，以上后置能力尚未实现。

## 3. 需求与验收

| 编号 | 要求 | 验收 |
| --- | --- | --- |
| N01 委派与综合 | 自然语言触发，子结果作为工具结果交回，主 Agent 可继续查询、修改和回答 | D01、D02 |
| N02 复用内核 | 父子均使用公开 AgentSession；默认压缩、原生重试和完整取消复用现有接入 | D01、D06、D07 |
| N03 独立上下文 | 子会话只获得显式任务、角色说明及获准资源；不自动复制父历史或访问其他会话 | D03 |
| N04 只读与单层 | 子 Agent 不注册写入、Shell、委派或业务操作工具；权限由代码约束 | D03、D04 |
| N05 停止与失败 | 停止传播到子模型／工具／压缩和重试；子失败明确回传，不能伪装检查成功 | D05、D06 |
| N06 历史保存 | 父子原始历史分开保存；父会话显示子结果，重启不自动重做未完成委派 | D08、D09 |
| N07 持续工作与用量 | 不新增默认调用次数或整轮时长上限；可选父请求截止时间覆盖子工作，用量不漏记、不重复累加 | D07、D10 |
| N08 网页交互 | 原对话内查看进度和结果；切换、刷新、未读、草稿及停止行为保持一致 | D09、D11 |
| N09 工程边界 | Pi 类型和原生记录解释继续限于 src/pi，旧会话兼容，不修改用户凭证 | D08、D12 |
| N10 基础多角色 | 从受控文件加载角色目录，主 Agent 按职责选择，子按选定提示词和工具集合执行；配置版本在父请求内固定 | D01、D04、D13 |

## 4. 阶段边界

W01-3 的默认压缩、AGENTS.md 独立加载和现有运行控制作为基础。本期不增加压缩提示词、跨会话检索或关键业务数据管理。

正式 Run、数据库、可靠事件回放、崩溃自动续作、费用预算账本在 S3／后续阶段设计。子任务用量关联不等于已经实现平台预算。业务工作分派、外部调度、Ubuntu 部署和样板业务不进入本期。
