# W01-4 设计：基于 Pi 的子 Agent 委派

日期：2026-09-17。状态：**已实现，D01～D13 组合验收通过**。范围见 [PRD](prd.md)，版本与源码依据见 [Pi 能力核对](research/pi-subagent.md)。

## 1. 技术路线

Pi 0.85.1 没有内置 Subagent 调度器；官方提供扩展示例，通过 `subagent` 工具启动独立 Pi CLI 进程。本项目采用其单任务委派方式，使用公开 SDK 创建独立 `AgentSession`，嵌入现有服务进程。

| 层次 | 本期使用方式 |
| --- | --- |
| Pi 原生能力 | AgentSession、工具循环、事件、SessionManager、默认自动压缩、原生重试、abort／dispose |
| 官方示例模式 | `subagent` 工具、显式 task、独立上下文、Markdown 角色定义与选择、进度回传和最终结果交回主 Agent |
| 项目补齐 | 父子关联、受控资源与只读工具、Web 状态、用量归属、停止联动和历史投影 |

SDK 方式可直接复用当前模型配置、凭证、资源工具和受控模型流，不需要再维护 CLI 参数、子进程通信和另一套资源发现。独立 AgentSession 隔离对话上下文，**不提供操作系统进程隔离或沙箱**。本期只运行项目固定的只读工具；未来加入任意代码或 Shell 时，另行设计执行隔离。

不修改 Pi 内部源码，不升级依赖，不新增通用编排框架。父子使用同一套会话构建逻辑；角色、工具集合、历史管理器和执行上下文分别传入，不通过调用公开 `PiLab.start()` 嵌套出用户会话。

## 2. 委派流程

```text
用户提出任务
  → 主 Agent 根据角色目录选择角色，按需调用 subagent
  → 宿主固定父请求、项目、配置和资源范围
  → 独立子 AgentSession 按角色说明执行，可以调用获准的只读工具
  → 子结果作为本次 subagent 工具结果返回
  → 主 Agent 综合后继续工作，最终回答用户
```

公开工具／wire 名均为 `subagent`，参数为 `{agent: string, task: string}`。agent 必须属于本次父请求加载的角色目录；例如 `{agent: "reviewer", task: "检查以下内容……"}`。task 应包含目标、必要输入、资料标识和用户约束；子 Agent 不会自动看到父会话全文。参数拒绝未知字段，不接受 cwd、文件路径、模型、权限或父请求 ID。

工具描述包含本轮全部可用角色的名称和职责，主 Agent 按任务判断是否委派以及选择哪个角色；角色系统提示只加载到对应子会话。简单问答可直接回答，无需用户每轮先选 Agent，也不固定执行“分析→生成→检查”脚本。

每次调用新建子会话；结果回传后结束，不保持常驻。主 Agent 可以先后调用同一角色或不同角色，每次显式传入必要信息。本期沿用父工具串行执行，每个父请求最多一个活动子任务；这是并发约束，不是累计调用次数上限。single 只限制一次委派的任务数量，与可配置角色数量无关。

## 3. 角色配置、子会话上下文与工具

### 角色定义与加载

角色文件放在 `experiments/harness-lab/fixtures/agents/*.md`，由项目维护。沿用官方示例的 Markdown frontmatter 形式，复用 Pi 公开的 `parseFrontmatter`；name 为唯一角色名，description 说明适用职责，tools 显式列出可用工具，Markdown 正文为角色系统提示。不将角色名写死在分支逻辑中，也不要求固定 JSON 输出。

```markdown
---
name: reviewer
description: 检查给定内容的资料依据、矛盾和遗漏，提出修改建议
tools: source_list, source_read, instructions_read, skill_read
---
根据传入的目标和内容进行检查，区分已核实事实、推测和资料不足。
说明发现、依据和建议；没有读取资料时，不声称已经核实。
```

预置两个通用角色用于验证，增加合法配置文件即可扩展，不需要增加新的工具实现：

| 角色 | 职责 | 默认工具 |
| --- | --- | --- |
| analyst | 提取资料事实、差异和缺失信息，供主 Agent 综合 | source_list、source_read、instructions_read |
| reviewer | 核对传入内容的依据、矛盾与遗漏，可参考检查 Skill | 上述工具及 skill_read |

每次父请求准备时加载并固定角色目录、正文、工具集合及内容 hash；本轮所有委派使用该版本。新增、修改或删除文件在下一次用户请求生效，不在启动子任务时重新读取。角色配置供各工作区复用，但不包含具体工作区资料；子任务的数据范围仍取自父请求。

只读取上述工程目录，不扫描用户主目录或任意工作区路径。名称重复、缺少必填项、工具未声明、未知／越权工具及非法格式均在准备阶段明确报配置错误；不静默跳过或回退为全量工具。`tools: []` 可以表示无工具角色。目录为空时明确提示配置缺失。每个角色文件最多 64 KiB，拒绝符号链接和无效 UTF-8。角色名只能从本轮已验证目录解析，不能拼接模型提供的路径。

本期角色统一继承父请求模型和 thinking，不开放配置中的模型覆盖；填写未支持的 model 字段明确提示，不静默忽略。基础文件配置属于本期；网页新增／编辑角色、独立角色模型与凭证管理后置。

### 上下文与工具范围

子会话输入由三部分组成：宿主系统规则和选定角色说明、父请求已固定的通用／工作区 AGENTS.md、显式 task。子历史从空开始；只回传最终结果，不把子会话的整段原始历史拼入父上下文。

AGENTS.md 的装配和请求内固定语义与主 Agent 一致。父请求期间保存的新指令，下个用户请求才生效，不因中途创建子 Agent 而提前加载。子会话独立进行默认压缩，摘要不代替当前指令。

| 可供角色声明的只读工具 | 数据范围 |
| --- | --- |
| source_list、source_read | 父请求固定的本工作区资料清单和正文 |
| instructions_read | 读取父请求指令快照，返回 `editable: false`；用于核对已加载规则 |
| skill_read | 父请求固定的 Skill 清单与正文，读取记录归属子会话 |

子实际工具集合为“角色声明工具 ∩ 父请求获准工具 ∩ 宿主只读工具目录”。超出范围的角色配置明确拒绝，不静默扩大或删减其声明。本期通过这些工具可以访问该工作区已获准的只读快照；task 中列出的资料是任务要求，不额外建立逐资料授权机制。子 `instructions_read` 读取快照，区别于主 Agent 为保存冲突检查而读取当前磁盘；两者在工具描述中说明。

只注册选定角色获准的工具，关闭内置工具与外部扩展发现；不注册 instructions_update、subagent、Shell、任意文件工具和业务写操作。仅靠“请勿写入”的提示词不构成限制。ModelRuntime 可复用，父子 AgentSession、SessionManager、活动标记、压缩标记和用量计数分别独立。

## 4. 模型、压缩与运行控制

子会话继承父请求固定的模型／端点、thinking、容量、输出能力和压缩参数；不增加单独模型设置。沿用 W01-3 的受控模型流、HTTP 空闲计时、可选单次模型超时和原生重试；摘要保留 Pi 默认提示和输出额度。

- 主、子分别让 Pi 判断压缩时机和保留范围。子压缩事件不能改变父会话的摘要记录或状态归属。
- subagent 是等待子任务完成的工具，不套用一个新增的固定工具时长上限。子工具仍按各自定义处理超时。
- 不新增默认模型／工具调用次数、委派次数或整轮分钟数上限。
- 显式配置 `AGENT_RUN_TIMEOUT_MS` 时，父请求接受时产生唯一截止时间，覆盖子会话创建、模型、工具、压缩及重试；委派不重新计时。
- 接受取消后立即禁止新的父子调用。任何 await 之后开始模型或工具工作前，仍检查所属请求是否有效。

每个执行上下文记录自身回复／摘要尝试、工具调用和已知实际 usage。父级原有 `usageSummary` 保持“主 Agent 自身”的口径；新增子任务独立汇总，诊断时显式计算整次请求合计。主 Agent 的一次 subagent 调用计一个父工具调用，子内部工具计在子项，子 token 不重复计入父项。缺失 usage 标未知，不能按 0 计算或声称精确费用。

## 5. 停止与失败

子任务内部状态为 `running → succeeded / failed / cancelled`，重启发现未完成记录时投影为 `interrupted`。取消尚未收敛时显示“正在停止”；这些是子调用状态，不引入正式 Run 状态机。

| 情况 | 行为 |
| --- | --- |
| 子正常完成 | 保存结果，作为工具结果交回主 Agent；主 Agent 继续综合 |
| 子最终模型／压缩失败、输出截断或无有效最终正文 | 返回明确 failed 和清洗后的原因；部分内容不能标为完整检查结论 |
| 子只读工具失败 | 沿用 Pi 工具错误回传，子 Agent 可调整；不可伪称读取成功 |
| 用户停止／父截止时间到达 | 先关闭父子工作入口，传播 abort，等待子 prompt、工具及原生 abort 收敛后再结束父请求 |
| 历史保存失败或父资源状态失效 | 停止整次请求，保留已有记录并提示恢复问题，不继续综合成成功结果 |
| 服务异常重启 | 保留已保存记录，标识未完成调用；不重新发起委派或自动续跑 |

工具回传正文明确携带成功／失败语义，details 中保存结构化状态；通过公开 afterToolCall 将该工具的失败状态映射为原生工具错误标记，不能只看 promise 是否 resolve 或是否有文本来判成功。失败后主 Agent 可以说明局限、自己检查，或根据新信息重新委派；宿主不自动重试整个子任务。

取消处理通过外层执行控制器协调；Pi 事件回调只设停止标记和发送信号，不能在子事件回调中等待正在等自己的父 `abort()`。子执行结束后解除监听并 dispose，父 active 保留到全部子执行收敛。迟到事件只属于原 parentRequestId／subagentId，不能写入后续请求。

## 6. 历史与关联

继续使用 Pi 原生 JSONL，不引入数据库或另一套消息存储。

| 记录 | 保存位置与作用 |
| --- | --- |
| 父会话 | 既有 `LAB_DATA_DIR/sessions/`；保留用户输入、subagent 调用／结果和主回答 |
| 子会话原文 | `LAB_DATA_DIR/subagents/<parentSessionId>/<subagentId>/` 内由 SessionManager 生成原生文件；保存 task、回复、工具结果及压缩记录 |
| 父子关联 | 父原生文件的版本化 custom entry；关联 parentRequestId、toolCallId、subagentId、childSessionId、workspaceId、角色／配置版本和起止结果 |

子来源元数据保存实际角色名、description、完整角色正文、声明及有效工具集合、内容 hash；历史按当时保存内容解释，不用当前角色文件覆盖旧记录。角色更新／删除不影响已完成结果读取。

目录 ID 由宿主生成或取自已验证的会话绑定；模型及客户端不能提供路径。子会话不加入 workspace-index 的普通会话列表，访问范围由父会话绑定确定。

先在父文件保存开始关联，再开始子模型调用。子原文及终态可保存后，在父文件追加结束记录，随后向 Pi 返回工具结果。跨文件没有原子事务：如果子已完成而父结果尚未保存就中断，保留子原文，父显示该调用结果未完整提交；不得自动补发模型调用或伪造父回答。出现孤立子文件保留供诊断，不自动挂到其他会话。父记录有效但子文件缺失、损坏或结果不一致时，保留父对话供查看，标记相关子任务中断并隐藏无法核实的结果，提示恢复问题、禁止续跑。

新增记录使用 `berserk.subagent-start.v1`／`berserk.subagent-result.v1`，子文件使用单独校验的来源元数据。复用资源快照内容时，显式记录 readonly 能力，不能套用现有记录中的 `editableFileIds: ["workspace"]`。旧记录缺少 subagent 字段视为没有该能力的历史，不补造子任务。

父结束记录保存最终公开结果和独立 usage，供正常历史投影读取；子完整原文保留在子文件，本期不开放子历史检索工具或独立聊天页面。主上下文只接收最终工具结果；与官方 single 示例一致，不新增宿主摘要模型或静默截短最终结果。过长结果仍可能使父上下文超限，沿用 Pi 压缩／恢复及明确失败机制，D06 验证该边界。

## 7. 网页交互

沿用当前消息内的工具展示，在委派位置显示可展开的子任务卡，标题使用实际角色名。例如：

```text
▸ reviewer · 正在核对资料
  展开后：角色职责、本次任务、当前公开步骤

▸ reviewer · 已完成
  展开后：角色职责、本次任务、执行结果

主 Agent：综合子结果后的回答……
```

执行中展示实际阶段，例如“正在分析”“正在读取资料”“正在压缩上下文”；不显示虚构百分比。失败／取消／中断显示对应原因。子任务完成只更新卡片，父请求继续处理中；仅父回答完成触发现有未读蓝点。

当前“停止”停止整次处理；本期不增加单独停止子 Agent、直接回复子 Agent 或开新会话的按钮。切会话不取消，刷新查询当前父快照恢复卡片，不重发请求。下一条草稿和阅读位置保留，卡片变化不抢焦点、不强制滚动。

卡片默认折叠，使用原生可键盘操作的展开控件，状态带文字并通过现有 status 区播报；窄屏纵向排布。只展示任务、公开工具步骤和最终结果，不展示内部推理、凭证、路径、hash 或运行 JSON，也不恢复“查看本轮资料”入口。

## 8. 接入位置与契约

- `src/pi`：增加受控角色文件加载／校验和本轮目录，提取现有会话创建和受控执行的共享部分，按角色注册工具并执行 subagent；不用重写工具循环。通过工具 `onUpdate` 和 Pi `tool_execution_update` 转发子公开进度。
- `src/contracts`：新增不依赖 Pi 的 `SubagentSummary`，包含 ID 关联、实际角色名与职责、任务、状态、公开阶段、结果／错误和时间；SessionSnapshot 增加可选子任务列表。
- SSE 增加 `subagent.updated`，保留 sessionId／requestId，并携带 subagentId／toolCallId。终态以父快照为准；历史与实时卡片按 subagentId 合并，不重复渲染同一个工具结果。
- `GET /api/sessions/:id` 投影已保存结果及活动子任务；`/api/activity` 仅返回原父会话元数据，可使用“子任务处理中”阶段，不读取所有子历史。继续使用既有 cancel API。
- 服务端只暴露白名单 DTO；新增 custom entry、tool details 和 usage 扩展需要显式验证，不能把原生 child messages 直接传给浏览器。

本期不增加独立子任务提交接口、全局子任务列表或 Worker 队列。稳定性验证覆盖停止竞争、保存失败、重启识别和双会话隔离，见 [验收清单](acceptance.md)。
