# 第二轮方案 · 外部模拟执行与反馈集成

v0.2 · 2026-11-08 · 用户要求完善后提交并实施

## 1. 本轮目标

让控制席下达的安排在模拟外部系统中形成车辆行动，Axon 能查到真实模拟进展、收到变化反馈，再由人员决定是否调整安排。

延续第一轮的普通文档软流程。总体席认可后交给控制席，控制席确认下达；指挥权限和人员确认继续适用。方案文档无需增加专用审批状态。

## 2. 完成后能看到什么

| 节点 | 外部模拟系统发生什么 | Axon 中看到什么 |
| --- | --- | --- |
| 控制席下达 | 接收指令，核对车辆、目的地、路线和当前占用；允许执行后登记占用 | 接收结果，以及另列的执行受理或拒绝原因 |
| 导演推进 | 按场景时间生成出发、途中位置和到场记录 | 指令详情更新，地图位置变化 |
| 中轴桥封闭 | 尚未通过的车辆停在受阻位置，生成反馈 | 收到受阻来报，可查询涉及车辆和原指令 |
| 人员调整 | 总体席组织复核并交控制席，控制席确认新的绕行指令 | 保留原指令、调整指令和实际执行记录 |
| 支援到齐 | 按逐车到场回报核对数量 | 可确认“支援到齐”；火情是否结束继续看后续来源报告 |

推荐演示仍为本地三车先到、跨站四车受阻后绕行。可分两条指令下达，分别指定车辆组及路线，复用现有“一条指令一组车辆”的形式。支持本轮数据中明确配置的路线和行程，未覆盖的安排如实反馈条件不足。

## 3. 谁负责什么

| 组件 | 本轮职责 |
| --- | --- |
| 模拟外部系统 | 核验执行条件，维护车辆占用、行动、位置、轨迹、受阻和到场，产生可查询记录和反馈通知 |
| Axon | 提交人员确认的指令，通过接口查询执行结果、接收反馈、提供研判和展示；保存必要引用及操作记录 |
| 控制席 | 核对指令，确认下达、取消或调整，查询结果不明的操作 |
| 总体及其他业务席 | 依靠普通文档和既有工作交接开展复核，提出后续安排 |
| 导演席 | 按时机推进来源事件和模拟行动，结束并重新演示 |

本轮模拟执行可与现有模拟服务共用部署，责任属于外部系统。沿用特情、态势两个信息来源，执行进展由态势系统发布。外部服务接口和 Axon 集成分别实现、分别验证。

## 4. 执行规则

**接收与执行分别记录。** 第一轮“已接收”继续表示收到了指令。本轮新增逐车执行状态，展示待出发、途中、受阻、到场、取消或失败，以及对应时间和依据。到场后仍处于任务占用，不能自动算作可再次调派。

**先核对再占用。** 外部系统核对当前状态、占用、有效期、路线和支持的模拟行程。未知、检修中或被其他业务占用的车辆，不能直接视作可出动。建议一条新派遣指令整批受理或整批拒绝，并逐项说明原因，避免人员以为七辆均已出发。不同车辆组可分条下达。

**有据地移动。** 行动采用预先配置、可追溯的模拟路径和耗时，地图显示外部提供的位置与轨迹。没有路线依据时反馈缺口；真实导航、火势模型及通用调度算法留待后续。原指令路线为空时仍可收到接收回执，执行阶段需要补齐可支持的路线；不擅自代选并发车。

**修订只改变未完成行动。** 追加调整指令，明确引用原指令和待调整车辆。已到场的三辆保留事实，四辆受阻车辆从实际位置继续绕行。调整前再次核验占用、当前执行版本和路线，旧版本、错车辆或其他任务的调整被拒绝。新旧操作、理由和回执均可追溯。取消同样要由控制席确认，已发生的出发和到场记录保留。

## 4.1 如何推演不同指令

模拟服务预制基础数据、动作及规则，运行时读取实际指令计算。基础数据包括车辆当前位置、道路连线、路段长度、模拟速度和出发准备耗时。动作包括派遣、出发、行进、受阻等待、改道、到场及取消。同样的初始数据、指令和推进次序应产生一致的业务结果。

首期支持当前世界中已明确配置的起点、目的地与道路连线组合。每次按所选车辆的实际位置和所选路线生成路径，行驶耗时按各路段长度除以配置速度、加上准备和已知等待计算；使用明确的单位和固定取整规则。路径连接与车辆接入点要有数据依据，不用跨越未连接道路的直线代替真实通道。所需数据缺失则反馈无法执行的原因，不能替换成作者预设的七辆车或默认路线。

车辆位置按已经过的场景时长在已保存路径上插值，轨迹保留业务时间和来源修订。道路条件变化时逐车核对所处路段和是否已通过，未通过车辆等待；改道从当前点继续，剩余距离重新计算。迟发或迟改道自然延后到场。本地三车与跨站四车只是演示推荐组合，实际结果必须遵守本次指令。

## 4.2 LLM 与展示边界

外部模拟的状态转换、占用核验、路径行进、耗时和受阻判断采用确定性程序，无需 LLM 调用。Axon 的 LLM 可以帮助整理结构化指令、解释反馈和提出调整建议，改变车辆安排仍由控制席人员确认。

Axon 消费外部记录，在现有态势地图展示车辆位置、轨迹、道路及状态变化，在指令详情展示逐车进展。推演规则和执行事实由外部模拟系统维护；Axon 的本地展示或语言模型回复不会修改车辆状态。

## 5. 时间和导演操作

继续使用现有手动场景时钟，真实时间流逝不推动车辆。建议导演台仍以事件列表和一个推进按钮为主，将预设来报与实际指令产生的行动节点按场景时间合并显示。悬停展开必要信息，按钮提示下一步事件或行动反馈。

例如，09:21道路巡查之后，下一步可为09:22三辆车到场，然后是09:23桥梁封闭。没有下达指令时不会生成车辆到场节点，预设业务来报仍可继续推进。浏览页面和查询回执都不推进时间。

一次推进要按先后处理所跨越的节点。同一时刻先处理道路、资源条件变化，再处理依赖这些条件的车辆行动，避免先到场、后补封路。预设主线的09:22、09:34是按时下达、按时绕行时的示例；迟下达或迟调整时，以实际场景时点和剩余行程计算，不回填到更早时刻。

新增版本需要扩展完整演示中的决策后行动段。旧版“主线五事件结束”的定义保留为旧演示行为；新版事件投送完、车辆支援到齐和火情结束分别展示。

## 6. 反馈如何回到 Axon

外部系统先持久保存执行变化，再通过现有态势来源发送业务通知，例如“V07因中轴桥封闭受阻，当前位置……”。通知包含合法的指令引用、车辆、业务发生时间、观测时间和修订，正文不夹带导演术语或预设关联答案。

内部保留可信的演示归属。Axon 核验指令和任务归属，执行详情关联原指令对应任务；普通来报研判继续按原规则判断对一个或多个任务的影响。执行详情关联不冒充 Agent 已完成研判，也不触发自动改派。

先复用当前向总体席投递初析的规则；控制席可直接查询自己下达的执行进度，总体席按既有工作交接协调。来源身份跨场景复用，反馈不默认向所有席位广播。新反馈同样受来源、资料和席位权限约束。总体及后台沿既有授权读取报告和态势事实，控制席的原指令详情按现有下达记录权限查询。

通知丢失可重试投送同一消息编号；接收去重、分析、投递和人员操作分别核验。查到执行结果不代表通知已经投递，消息送完也不代表任务完成。

## 7. 一致性、重启与重演

- 外部接收受理、车辆占用、执行记录、来源事实及待发通知在同一个来源事务中保存。Axon 与外部 HTTP 各自提交，接收不明先查原编号，不能自动重新发车。
- 同一指令编号和内容重试返回原结果；改变内容使用新指令。受理时原子争用车辆，同车并发指令只有一条能成功占用。调整、取消也有稳定编号和明确结果。
- 预设来报和动态行动共同更新当前事实。旧车辆清单不能把已出发车辆刷回车库，原观测与报告版本照常保留。需调整现有整对象覆盖和固定修订前置，按当前事实修订记录变化。
- 重启从已保存的执行位置、占用和待发通知恢复，场景时间不跳到现实时间。缺失或损坏的已初始化执行数据要明确报错。
- 结束演示时停止旧轮后续推进与调度，保留旧占用和行动历史。新轮有自己的世界和指令，晚到反馈仍归旧轮只读，不能影响新轮。原轮业务未完成的车辆不能标作到场或自然释放。
- 新建场景定义和执行协议版本；旧演示、旧接收回执继续可读。升级不自动执行第一轮历史已接收指令，存量指令保留原有接收含义。首次测试通过新演示使用新规则。

## 8. 本轮界面和验收

在既有指令详情增加逐车进展与查询，提供明确的调整、取消入口，沿用原生人员确认；已有地图接入来源位置和有限轨迹展示。导演台只扩展必要的行动节点，不增加另一块常驻控制面板。任务综合页的大幅整合安排在第三轮。

工程验收覆盖三条实际业务链。

1. 正常下达，来源受理与占用，逐车出发、途中、到场，Axon查询与地图对上来源记录。
2. 桥梁封闭、旧正常报告晚到，四车受阻；人员复核后控制席下达绕行，三车到场事实保留，四车继续行进。没有新指令时保持受阻。
3. 资源冲突、未知状态、重复发送、取消、响应丢失、通知重试、两端重启和中途重演，结果可核查且不串轮。

同时验证没有审核记录或附件的授权指令仍能办理，未授权席位仍不能下达。真实模型另做受控的完整主线验证，记录资料是否查全、是否正确解释占用、受阻和到场；程序链通过与模型内容质量分别审阅。建议沿用现有模型与参数，从新数据完整复验三轮，累计用量只记录，保留全部失败，不择优补跑。不把原98.8%的关联结果当作本轮执行正确率。

## 9. 审阅范围

本版已按讨论明确确定性动作规则、不同指令推演、导演手动控制进展及 Axon 展示边界，用户要求提交后实施。独立方案实体、硬审批流程、七系统拆域、真实车辆接入及历史轮次恢复执行后延。
