# 本轮问题修复方案

2026-11-08 · v0.1 · 待审阅，先不实施

**优先修复反馈信息和历史查询；Agent只做必要的小幅调整。到场超时按业务结果处理，漏关联继续保持较低优先级。**

## 1. 补全外部反馈

由模拟外部系统根据实际指令、逐车执行记录生成，仍通过现有态势来源发送。补充：

- 派往哪里：指令目的地名称及对象引用；不把派往某点当作该点事件已核实的证据。
- 当前怎么走：实际生效的路线；部分车辆改道时分别说明。
- 当前在哪里、什么状态：逐车位置、业务时刻和来源修订。
- 为什么受阻：具体受影响路段及执行记录确认的原因；与车辆当前所在位置分别表达。
- 后续进度：可计算时提供预计到场，分批到场只报告已到车辆，到场后仍说明本次指令占用。

例如：

> V07、V08、V11、V13 正按指令前往临港三号仓库，计划经中轴桥、滨港路。因中轴桥封闭，四车在各自当前位置等待调整。观测时间09:23。各车位置及指令引用见详情。

路线依赖及受阻原因由执行记录给出，不能要求 Agent 凭“车离桥多远”猜因果。通知正文、报告正文和目的地/道路/车辆引用保持一致。不同测试下按实际指令生成，不写死车辆组合或桥名。

这项修复在来源生成端完成。保持现有指令读取权限，向 Agent 提供业务事实，不在来报中写“应该关联哪个任务”或“应该新建任务”。

## 2. 历史查询减少重复数据

**历史列表保留状态和位置前后值；完整轨迹继续通过现有当前对象和指令详情读取。**

变化记录保留车辆引用、修订、业务时间、归属、可用性、执行状态及位置的前后值，不再每条附带整段累计轨迹。状态未变的确认记录也保留。响应明确标识这是不含完整累计轨迹的历史视图；类型、接口校验和工具说明同步适配。

完整轨迹和原始历史仍由来源保留；本期先修读取投影，不拆数据库或新建通用轨迹服务。地图当前对象与控制席指令详情的完整轨迹功能保持。

分页同时受两项约束：请求条数是上限，完整来源响应暂以200 KiB为页预算，为现有256 KiB宿主保护留出余量。超出时返回较少条数及有效续页游标，游标按实际已返回条数前移。原有limit含义、时间边界、快照修订校验和末页nextAfter语义保留；不静默丢记录。

单条记录仍过大时明确失败，不返回假完整结果或循环空页。Agent按有效游标补查；失败须区分“未核完”和“没有变化”。两个已知超限回归范围必须能实际读到末页，不能只把报错改成文字解释。

## 3. Agent调整保持小范围

| 问题 | 调整原则 |
| --- | --- |
| 归属、所在地、占用混淆 | 分别引用来源字段；本次任务占用说明不可另派，不据此说本任务无法使用已到场车辆 |
| “一直开放”写成“恢复开放” | 对照前后状态，只有有依据的受限/封闭→开放才称恢复；正常→正常称确认延续 |
| 方位、日期和时刻写错 | 时间引用原值；不做无必要的方位、日期换写和实时日志说明，缺少确定依据时保留来源坐标与时间 |
| 新建建议与原目标重叠 | 先覆盖已有任务的核实项；只有说清额外独立交付及原目标为何不能承接时再建议新建，仍由人员确认 |
| 记录参数错误 | 统一现有工具字段说明和通用调用示例；保持严格校验，错误由Pi原生回合更正，不静默删除参数或伪造成功 |

调整限于现有初析配置、工具说明及必要的类型/解码适配。简短输出本条事实、影响和缺口，不新增长报告框架、宿主二次LLM审核或业务硬门禁。

3处漏关联继续单列观察；不添加针对V02、T01等对象的规则，也不把“零漏关联”设为本补修的阻塞门槛。正文关键事实错误与关联统计分别验收，不用记录成功替代内容正确。

## 4. 09:35未达标单独处理

现有按距离、速度和准备时间计算的结果保留。当前安排末车09:46:42到场，应报告“未满足09:35”，不把脚本执行结束写成业务达标。

原核实任务目标与基准评测保持；另外增加一项带明确期限的执行评估用例，由控制席已有前台会话读取交接的普通业务文档，明确“七车09:35前到齐”，再查询已有执行进度核对预计到场；受阻时旧预计时刻不能作为承诺，绕行后采用新的预计。验证能否识别迟到风险，由业务人员决定是否调整车辆或路线，控制席确认；导演不替业务席选方案。未取得该文档的后台初析不承担期限比较，不为此扩展其指令读取权限。本期不自动优化调度，也不承诺现有组合可按时到齐。

## 5. 顺序与兼容

1. 先补来源反馈、历史视图和字节分页，完成真实HTTP、分页及地图回归。
2. 再对初析与工具说明做小幅调整，补事实解释和期限评估用例。
3. 固定候选与评审口径，沿用现有模型参数，从新数据完整复验三轮；累计用量只记录，所有失败保留。

新演示采用可识别的修订版本（拟v6），保留v4/v5历史读取；更新涉及定义指纹、执行版本判断和响应校验。旧通知不重生成、旧回执不改写，旧数据不回填缺失字段。需要补报时生成新的来源记录及消息编号。既有轨迹和原三轮证据保持。

不新增页面或常驻说明。必要字段进入现有通知详情、指令详情及地图；界面保持简洁。此次仅形成方案，实施和上线另待授权。

## 验收结果怎样看

分别列出反馈是否完整、历史是否查全、物理结果是否一致、Agent正文是否有依据，以及关联/新建建议表现。原13条来报与新增执行反馈分开统计。三轮中仍出现的错误原样列出，不能挑最好的一轮，也不能把未达时限标成通过。
