## 2. 任务说明面板

入口继续使用侧栏任务行的“任务说明”和对话页的同名入口（`experiments/harness-lab/src/web/main.tsx:289`，`:302`，`:368`），不增加独立任务管理页。

面板顺序：任务名称 → 目标与说明 → “业务关联与关注范围（可选）” → 负责席位与状态 → 保存。可选区默认在无值时折叠，摘要为“未设置，普通任务可留空”；已有值时显示引用数量、区域、时间窗和主题摘要，可展开编辑。字段有错误时自动展开，错误定位到具体字段。

| 字段 | 控件与填写方式 | 含义与边界 |
| --- | --- | --- |
| 业务引用 | 可添加/删除的简单行：外部系统下拉、对象类型下拉、对象编号文本框；可选显示名称 | 使用配置提供的系统/对象类型标识，编号保留字符串和前导零；不要求将外部对象复制成 Axon 任务，不强制建设外部对象搜索器 |
| 区域编码 | 区域编码输入和“添加”，下方可删除条目；有字典名称则同时显示名称 | 保存约定编码，不从名称猜编码；本期不提供地图选区或空间编辑 |
| 时间窗 | 开始、结束两个日期时间输入，旁边固定显示当前录入时区 | 两端都空即未设置，允许只填一端表示开放区间；两端都有值时必须开始早于结束，使用半开区间 `[from,to)`；提交与返回统一时间表示，界面明确时区，不静默偏移 |
| 主题 | 简单多值文本输入和可删除条目 | 按契约修剪首尾空白、去重；不提供主题体系管理或自动扩展同义词 |

推荐帮助文案：“用于查找相关业务资料和判断任务影响，不改变文件与会话的访问权限。”公共任务同时说明：“这些内容与任务说明一样，对可查看本任务的席位可见。”这里只保存标识与关注范围，不粘贴外部业务全文或凭据。

空行不写入；用户开始填写的一行业务引用必须完整，否则在系统、类型或编号下指出缺项。字段条数、长度、编码约束由后端契约和能力目录提供，前后端一致；前端不要自设另一套限制。外部记录是否存在与字段格式分开：能够保存格式有效的引用，不因远端暂不可用阻止普通任务保存，显示“尚未核验”而非“已关联成功”。

普通任务的新建和编辑流程不增加必填项。关注范围全空表示“没有显式关注条件”，不代表全部区域、全部历史或所有外部数据的访问权；后台是否能查询仍取决于获准能力，分析中说明实际使用的匹配依据。保存元数据不会追溯重跑已完成分析。

所有者控制与公共/私有可见性沿用现有任务规则。非所有者可阅读获准元数据，表单显示只读；公开任务的引用不是访问其他席位文件、会话或远端对象详情的凭证。已经删除或不可选择的系统/类型，不自动抹掉已有引用；保留原标识并提示“当前不可用”，允许所有者明确移除或更正。

### 保存与冲突

全部字段使用同一个任务 revision 原子保存，避免目标与引用分别保存后形成混合版本。沿用“你的编辑仍保留 → 查看最新说明 → 核对后继续合并编辑 → 明确保存”流程；比较区必须展示名称、目标以及全部新增字段，不能只比较文字说明。

“已核对”只更新后续保存使用的基线版本，不自动覆盖用户草稿；若提供“使用最新内容”，应明确替换整个当前草稿且不发起写请求。发生再次冲突或保存结果未知时，必须重新读取后才能重试，不能自动重放旧 PUT。新建结果未知仍按现有 `clientActionId` 查询结果，不能再次建任务。

## 3. 来源与处理投递规则

沿用“信息中心 → 处理与投递规则”。将“预处理方案”面向用户解释为“分析方案（Profile）”，保留内部已有预处理阶段与作业类型，不为了改名重建后台流程。

选择一个方案后，在下拉控件附近展示只读说明并保留现有投递控件：

1. **分析目标**：现有 Profile goal，说明此来源更新后要形成什么结果。
2. **允许查询的内容**：后端提供的系统名称、对象类别/查询能力、允许的范围摘要，以及是否支持当前记录、历史/变化查询；用短列表，长内容折叠展开。只呈现可信配置的安全投影，不返回服务端地址、密钥、内部提示词或资源正文。
3. **投递到**：仍是现有固定接收席位复选框。说明“分析会列出相关任务；结果按这里选择的席位投递”。不增加“按影响任务自动选席位”开关。

“方案允许查询的内容”来自服务启动时加载的固定部署配置。后台作业保存当次 Profile 资料范围标记，供结果鉴权和溯源；席位前台和人员提交的后台分析按真实席位及固定 `contextScope` 校验，不继承服务身份的权限。界面范围由服务端投影，前端不把来源管理权限或复选框转换成查询授权。只有 view 权限可查看获准的安全投影，不能改 Profile 或接收席位。本期不增加资料范围热更新、动态撤权或权限版本管理界面。

现有“公共任务展示归属（可选）”保留并补充说明：“仅用于展示分类；不是唯一影响任务，也不建立任务工作区。”不要把它改成影响任务多选框，不强制没有 Axon 任务编号的事件先建立任务。

保存规则继续采用现有 revision、创建回执与比较方式（`InformationRules.tsx:32`）。保存提示保持“新消息使用此版本，历史记录使用原快照”。已完成作业显示当次采用的方案名称与版本；查看规则当前配置不能伪装为该作业的历史配置。

## 4. 信息中心：让人看懂一次综合分析

保留来源筛选、信息记录/后台作业/规则栏目、四列看板、独立列计数与分页、列表切换，以及侧边栏任务导航。无需另建态势驾驶舱。

### 卡片与列表

保留后台作业卡片和列表已有标题、来源、时间、执行状态与本次投递。详情和收件的结果区统一称“处理结果”，同时展示当次 Profile 名称，不增加生成分析标题的状态或存储。卡片不增加影响数量、影响状态或候选任务标记；前端不解析最终 Markdown 生成业务关系。

仍把“执行完成”与分析结论区分：作业正常结束不等于目标实现、所有资料齐备或确认无影响。部分资料无法取得时，执行状态可为完成，结果正文应明确“依据不完整”和具体缺口；不要发明一套与后台状态冲突的前端成功/失败状态。

### 详情顺序

在现有 `InformationDrawer` 内按以下顺序展示：

1. **处理结果**：显示 Profile 名称并保留最终 Markdown 正文，由正文说明变化、主要判断、可能影响的任务、关联理由及待核实项，不拆成新的业务状态。原始消息没有业务发生时间时显示“未提供”，不把接收时间当发生时间。
2. **查询依据**：从当前作业获准的原生查询工具结果派生可折叠列表，以 `toolCallId + 记录引用` 定位，显示来源、对象/记录标识、版本/业务时间及查询时间，展开可看实际返回内容。工具结果中的任务候选不是“已受影响任务”，不自动形成可点击关系或任务导航。
3. **缺口与冲突**：由最终 Markdown 正文明确表达资料缺失和冲突，区分显式引用、范围关联与研判推断；前端不据措辞推导完整性或风险状态。来源未返回版本或时间时如实显示缺失，不编造数值。
4. **原始输入、附件与本次投递**：复用现有区块与下载接口。
5. **执行过程**：继续保留已有折叠内容及命令策略证据，作为需要追查时的入口，不在每条聊天消息下新增 debug 按钮。

查询依据和人可读正文必须同属一个 `jobId` 的执行。重处理产生新作业，旧结论保留在各次执行中；不能把新结果与旧依据、旧成功投递拼在一起。列表由后端从获准的原生工具结果投影，不新建证据库或第二份历史。已有 `InformationText` 会禁用模型正文中的外链（`experiments/harness-lab/src/web/information-ui.tsx:42`），继续保持现有安全 Markdown，不为来源引用整体开启任意链接或 HTML。

分析正文应区分“在本次范围内未发现相关任务”和“没有足够资料判断”，不能统一写成“无影响”；没有完成结果时仍使用既有作业状态。综合结果按主设计中的完整资料范围检查，无权时服务端只返回允许的最小元数据，不发送整份受限结果再依赖前端隐藏，也不裁剪 Markdown 猜测安全。另一席位后续私有分析仍只显示现有最小状态摘要，不额外显示其目标、任务、依据正文或对话链接。

## 5. Inbox 与继续对话

Inbox 仍以一次已送达的信息为入口。“处理结果”区展示 Profile 名称、原有 Markdown 正文及可折叠查询依据；任务影响和缺口保留在正文，不提取结构化数组。仅展示对当前席位获准的内容。原文与附件仍可折叠，打开页面不会重新查询业务系统或调用模型。

“开始分析”区建议改为“继续分析”，仍保留现有任务单选、分析目标、资料勾选、可选 Skills/Agents、“进入对话分析”和“提交后台分析”。任务选择标签可解释为“本次分析所属任务”，辅助文案为：“结果可涉及多个任务；本次对话和所选文件保存在当前席位的这个任务工作区。”

任务选择器保留现有获准活动任务单选，不根据正文推荐、排序或自动选中任务。目标任务为空时禁用两种提交操作，提示先选任务；没有可选任务时沿用“先建立任务”引导。查看收件和分析概要无需先选任务。

在现有能力选项区显示只读“可查询系统”，来自服务端按真实席位及启动加载的固定 `contextScope` 计算的能力投影；不新增与原分析比较能力差异的界面。目标任务的业务引用只提供查询线索，不扩大授权。

首次发送、后续追问、刷新后恢复和普通新对话均可使用同一套主 Agent 查询工具。每次调用沿用既有身份校验，并检查服务启动时加载的固定资料范围，不增加会话能力快照、持久引用或恢复状态机。新回答中的资料标注本次查询时间，与之前结论的历史依据分开，不改写旧回答。

“进入对话分析”继续只准备独立对话、获准资料副本和未发送草稿，用户发送后才执行；“提交后台分析”沿用现有确认面板和其中的单一目标任务、目标及资料说明。该确认是现有产品交互，不增加每次查询审批弹窗。文件仅导入选定任务 × 当前席位目录；其他影响任务的目录与会话不合并、不挂载、不批量复制。

进入对话后沿用现有工具执行呈现，不新增来源设置门户、会话说明入口或每条回复下的技术按钮。查询失败应通过普通工具结果与最终答复说明缺口，不能通过凭空伪造查询结果补齐。

已合法导入席位工作区和普通对话的资料沿现有文件/会话权限处理。动态权限变更与存量治理后置，本期不设计运行中收紧/扩大资料范围、撤权或副本处置流程。

## 6. 异常、空值与迟到响应

| 情形 | 用户可见反馈 | 状态与动作约束 |
| --- | --- | --- |
| 任务业务字段全空 | “未设置，普通任务可留空” | 不阻止保存；不解释成全域查询权限 |
| 业务引用缺项、非法区域码、时间值无效或两端相等/倒置 | 对应字段下说明具体问题，提交时聚焦错误摘要 | 单端开放时间窗合法；草稿完整保留；错误摘要链接到字段；不只吐司提示 |
| 来源目录暂不可用 | “业务系统列表暂不可用”，可重试 | 保留已有引用和输入；普通任务仍可保存其他合法内容；不能清空数据伪装成功 |
| 远端没有相应对象或查询结果为空 | “未找到该对象”或“本次查询无记录”，保留查询范围与时间 | 不等同于无影响或无权限，不自动扩大范围再查 |
| 查询超时、部分来源不可用 | 结果显示“依据不完整”及缺少哪些判断依据 | 保留已有证据；人工可继续追问；不暗示后台必定无限重试 |
| 同一对象多源内容冲突 | 展示两方来源、时间/版本及冲突点 | 保留待核实项；不以较晚到达的消息自动覆盖较新业务事实 |
| 固定配置中无资料范围权限 | 显示一般性的不可访问提示，不能查询、读取或导入受限内容 | 服务端检查真实身份与固定资料范围，不返回受限正文；前端不以隐藏按钮替代后端校验 |
| 任务已归档 | 正文中的历史判断按原结果权限可读，继续分析目标不可选 | 已选择但提交前归档时保留草稿，提示重选或由有权者重开；不偷偷转入别的任务 |
| metadata/rule revision 冲突 | “你的编辑已保留；查看最新内容后合并” | 展示所有新增字段的最新版本；显式合并保存，不自动覆盖 |
| 新建或提交网络失败，结果未知 | “提交结果尚需核对”，保留目标与选择 | 使用同一 `clientActionId` 查结果后继续原操作；不重复建立任务/作业 |
| 切换任务、来源、Profile、Inbox 信息时旧请求返回 | 当前选择仍显示自己的加载/结果状态 | 数据和错误同时按身份、选择键及请求版本绑定；A 的成功或失败均不能进入 B |
| 保存时继续编辑，保存回包迟到 | 显示已保存版本，同时保留保存后新增的草稿 | 捕获发起时 payload、revision 和编辑代次；回包不能覆盖后续输入 |
| 离开 Inbox 后准备对话才完成 | 在原收件记录保留准备结果 | 不抢导航、不将草稿写入当前另一个任务；回到原条目可继续 |
| 退出或切换登录后旧请求返回 | 新身份只看到自己的页面 | 沿用 viewId 隔离与卸载；不把旧查询范围、证据或错误挂到新身份 |
| 列表暂时刷新失败 | 显示“刷新失败，以下为上次结果”与重试 | 普通网络失败可保留同一身份与范围的最后结果；无权限响应显示访问错误，不用旧内容替代；轮询不抢焦点 |

现有 `TaskPanel` 的比较区只处理名称和目标；扩展字段时必须补完整比较。现有 Inbox 能力数据使用 `selected:taskSpaceId` 作为范围，错误状态也应与同一范围绑定；不能原样复制一个全局 `optionsError` 给新的查询能力摘要。以上是新增界面实现时的必要处理，本文未修改现有代码。

## 7. 样式与可访问性

沿用现有 React、原生表单控件、Lucide 图标、`Panel`/`InformationDrawer`，以及 `styles.css` 的 `--surface`、`--text`、`--muted`、`--line`、`--accent`。不新增 UI 框架、全局字体/配色或图标体系。参考 `experiments/harness-lab/src/web/Resources.tsx:7` 和 `experiments/harness-lab/src/web/styles.css:678`。

可选字段用渐进展开，阅读摘要优先于技术配置。表单有可见标签；增删行按钮说明所操作对象；移除行后焦点落到合理的相邻控件。错误与状态同时提供文字，不能只用颜色。长对象编号、任务名、来源名称可换行，完整内容可通过键盘访问，不依赖 hover。抽屉 Escape、关闭后的焦点返回、页面侧栏和原对话草稿保持现有行为；轮询更新只宣布简短状态，不强制滚动或聚焦。

已使用 `.agents/skills/ui-ux-pro-max/SKILL.md` 的桌面 Web 适用规则。针对性检索 `error summary validation --domain ux` 命中 Forms / Accessibility 的 Focusable Error Summary，适用于本次新增复合表单。React 检索只采用适用的一般 effect 清理原则；迟到响应方案以本仓库已有 path、generation、navigation、viewId 契约为依据，不引入 React Actions 重构。本期不做移动端产品或地图交互。

## 8. 实施时应验证的交互样例

- 普通任务所有新增字段为空，仍能创建、编辑、开启对话；只看元数据不建立工作区。
- 公共任务跨席位可看业务引用与关注范围；服务自动分析看不到私有任务，私有任务不出现在其他席位的查询依据或任务选择器；两个席位的文件与会话仍独立。
- 两个窗口分别编辑目标和关注范围触发冲突，双方字段可比较，草稿不丢失，没有隐式覆盖。
- 无 Axon 任务编号的特情和态势更新均展示当次 Profile 名称、带时间的多源查询依据及含任务影响的分析正文；不生成结构化影响状态、数量或候选排序，没有足够依据时正文明确缺口。
- 一个结果影响两个任务；固定接收席位不变。选其中一个任务继续分析，只有该任务 × 当前席位接收资料与新对话。
- 查看 Inbox 不调用模型；准备对话不自动发送；发送、后续追问、刷新和普通对话均按真实席位与启动加载的固定资料范围查询；未获准席位不能从详情、工具过程、附件或导入入口绕过权限。
- 切换来源/Profile/任务/收件时人为延迟旧 GET，旧成功和旧失败均不污染新选择；后台准备迟到不抢导航；切换信息中心时当前对话继续运行且下一条草稿不丢失。
- 详情中旧作业的依据与投递不因后来失败重跑而被替换；无权限、无结果、依据不足、执行失败有不同文案。
- 保留桌面侧栏、独立看板列计数/分页、深链接、返回前进、Escape 与焦点恢复。通过现有桌面 Playwright 入口扩展验证，无需真实 LLM API。

优先扩展 `experiments/harness-lab/tests/e2e/access.spec.ts` 和 `experiments/harness-lab/tests/e2e/information.spec.ts` 的现有样例；后端负责权限、查询证据真实性和结构投影验证，前端不从自然语言或原生 JSONL 猜测成功、权限与任务关系。
