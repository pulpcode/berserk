## 建议操作

1. 登录a，点击三个任务的“任务说明”，查看业务关联与关注范围。核对西区两个任务引用同一道路和车辆池，东区任务不同。
2. 打开“收到的信息”，依次查看上述两条消息，展开“查询依据”。道路消息应分析两个西区任务的时间关系；车辆消息应分别比较2<3与2≥1，不能把东区任务机械关联。
3. 在车辆结果下“提问与处理”选择“【多源验证】西区补给方案”，输入：`请重新查询当前模拟资料。以2026-10-01的业务时间核对：补给方案与设备转移方案分别有哪些道路和车辆约束？逐项区分来源事实、推断和资料缺口，不修改任务。` 点击“进入对话”，检查草稿后发送。查看结果，再追问“如果补给需求假设改为1辆，结论怎样变化？不要修改已保存的任务要求。”
4. 回到车辆收件，选择保存位置，填写：`根据这份分析整理一份待核实事项清单，区分道路、车辆与任务条件；不执行分派。` 点击“提交后台分析”并确认。离开页面再回来，查看状态，通过关联对话读取结果、继续交流。该结果属于发起席位，不会再自动投递其他席位。
5. 用另一浏览器配置或隐身窗口登录b，查看同样两条收件。其后续分析独立保存，不共享a的聊天。a可进入“信息处理中心”核对两个来源、作业和投递规则。

执行完成只说明运行正常。当前真实结果仍有把“未报告限制”说成“无限制”、将空道路属性误判为系统不一致等问题；验收时请对照查询原文，反馈具体结论与依据的差异。
