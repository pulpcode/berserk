## 3. 有意义的验证

| 层面 | 验证重点 |
| --- | --- |
| 目录 | ID 唯一；标准/扩展来源可追溯；全部素材可解析；方向和类型约束一致 |
| 校验 | 非法 symbolId、非有限方向、尺寸超限、错误 geometry 配对、未知 role 拒绝且不部分提交 |
| 保存 | 新字段跨 apply / read / copy / publish / derive / refresh 保留，旧快照不变 |
| 权限与冲突 | 来源只读、固定版本不可写、过期 expectedRevision 保留本地输入、未知写入结果按原回执恢复 |
| Agent | 真实导出的 schema、工具执行与结果读取一致；既有主会话/只读子会话边界不变 |
| 浏览器 | 图标可见、命中正确；单地图工具开合、缓冲恢复、草稿显隐；尺寸适配保留地理视角，各底图可读 |
| 刷新隔离 | 标绘和表单输入期间推进既有刷新，来源层更新但草稿几何/修订不变；失败与撤权按原规则处理 |
| 无隐式写入 | 打开/收起工具没有创建或保存请求；只读对象和不可写入口无法借面板状态越权 |

基于 `experiments/harness-lab/package.json` 的验证命令，在该目录执行：

```sh
npm run typecheck
npm run lint
npm run build
npm test -- tests/annotations.test.ts tests/annotations-acceptance.test.ts tests/annotation-from-source.test.ts tests/annotation-results.test.ts tests/pi/annotations.test.ts tests/pi/annotation-source-history.test.ts tests/situation-map-ui.test.ts tests/map-basemaps.test.ts
npm run test:e2e -- tests/e2e/annotations.spec.ts tests/e2e/situation-map.spec.ts
```

目录/专业符号新增的测试文件应加入对应命令；若地图运行时公共逻辑实际影响空间分析，再加入相关空间地图回归。自动浏览器测试使用既有本地瓦片夹具，不扫描公网瓦片。真实模型/来源联调按实施时已有授权运行并单独报告，确定性测试不能代替模型语义验收。

2. 在可写会话新增水罐车、云梯车、救护车的计划部署，清楚区别来源数据。

5. 保存草稿、发布，再显式设为任务当前；保存/发布均不替换当前部署，采用后计划仍不等于已执行。
6. 在既有只读入口验证同一固定版本；不新增独立总览页面。

### 水域救援

1. 打开已有来源区域与授权记录；缺失来源边界时不自动估算成事实。
2. 放置消防艇、冲锋舟、救援舰船标号并展示它们的差异和来源类别。
3. 绘制接近路线与搜救区域，设置拟定信息性质；适用时关联确切来源资源。
4. 分别显示来源对象和计划对象，验证不重算来源资源数量、不覆盖当前来源位置。
5. 保持工具展开和属性输入，使用符合既有契约的测试来源触发刷新：来源变化可见，草稿与修订不变；不以模拟轨迹宣称已接入单艇 GPS。
6. 收起后验证草稿仍可独立显隐，点选来源不丢输入；恢复、保存、发布、采用在同一地图完成。
7. 模拟无时间、来源刷新失败、撤销授权、重叠标号和草稿并发冲突，确认提示、清理、选择及输入保护。
