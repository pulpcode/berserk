# 消防专业标号与单地图态势标绘技术设计

状态：V1.1 已批准实施（2026-10-25）。基线：`codex/frontend-plotting`，提交 `6ce86513022350fb752eaa3dc04a96a5d2d82a6e`。

**已确认的交互方向**：实时态势与标绘共用一张地图，按需展开标绘工具；首期不建设“指挥总览 / 事件作业”两个页面。本设计与 [V1.1 需求](prd.md) 对齐，保留原符号、契约及版本边界；实际 GPS/AIS 接入仍延后。用户已明确要求提交方案后开始实施。

## 1. 复用边界

```text
授权来源查询 ─────── 来源只读对象 ───────────────┐
现有标绘服务 ────── 草稿 / 固定参考版本 ────────┼─ 共享符号解析与渲染 ─ 同一 MapLibre 地图
现有空间分析 ────── 独立分析结果 ───────────────┘
                                      ↑
                     按需标绘面板 + Terra Draw + 属性表单
                                      ↓
                         现有 actions / 固定修订 / 发布服务
```

统一的是符号语义、素材和显示规则；不是把三类业务数据合并成一份可写集合。来源态势仍只读，草稿仍由会话拥有，参考版本仍固定且只读，空间分析继续独立。

前端沿用 `AnnotationWorkspace`、`SituationView`、`MapCanvas`，在现有结构中增加工具展开状态与符号选择。保持同一 MapLibre 实例和 `business:anchor`；工具开关不调用 `setStyle`、不重新挂载地图，不另建只读总览路由。

## 2. 符号目录

建议新增纯数据目录 `src/contracts/map-symbols.ts` 与受控素材目录 `src/web/map-symbols/`。共用基础目录不依赖 React、DOM、MapLibre 或数据库。

每项记录：

- 稳定 `id`：标准示例 `xf3013-2020.6.2.1`；应用扩展示例 `app.rescue-inflatable-boat`。
- `name`、`category`、有限别名；别名只用于目录检索，不用于推测来源对象类型。
- `sourceKind: standard | extension`，标准名称/版本/条目，素材来源与归属说明。
- `geometryKind`、`defaultIconSize`、`anchor`、`orientation: heading | upright`、素材固有朝向。
- 图形资源的固定键；不会接受远程 URL、脚本、任意 SVG 或 MapLibre 表达式。

目录 ID 一经写入保存版本就保持含义稳定。替换一个条目的业务含义需要新 ID；标签可以修正，但不能把消防艇 ID 改为冲锋舟。

标准源文件保留 SVG 以便审查比例与线条。地图渲染时将受控素材转换为 MapLibre 可注册的图像；一次加载、缓存复用。使用标准浏览器/MapLibre 能力，不引入独立绘图引擎。小尺寸人工核验后再确定像素尺寸，预设为 32 px，允许 20–64 px。

## 3. 最小契约扩展

以下为拟采用的字段；实现前与最终代码基线核对命名，不改变本方案的用户行为。

```ts
interface AnnotationStyle {
  // 既有字段全部保留，包括 symbol: circle | square | triangle。
  symbolId?: string;       // 仅受控目录 ID，首期用于 point
  iconSize?: number;       // 图形显示尺寸，20–64 px；不复用旧 size 的半径含义
  heading?: number;        // 真北为 0，顺时针，[0, 360)；与素材固有朝向分开
  lineEnd?: 'none' | 'arrow'; // 只用于 line
}

interface AnnotationFeature {
  // 保留 objectId、geometry、sourceRefs 等既有字段。
  informationRole?: 'observation' | 'assessment' | 'plan';
}
```

新增字段是已确认缺口所必需：专业图形、方向、尺寸、方向路线和信息性质。业务状态、单位、装备参数继续通过已有 `attributes`、名称及注记表达，本期不创建通用资源台账或状态机。

约束：

1. `symbolId` 只接受目录内值并验证 point 适用性；`iconSize`、`heading` 不得包含非有限值。固定直立标号拒绝不适用的旋转设置。
2. 专业符号的默认标准颜色不随状态或生命周期改写；旧 `color` 继续用于旧形状和普通几何。编辑专业符号时禁用会破坏该条目规范的任意改色。
3. 缺少 `heading` 时使用目录默认图面方向，详情显示“方向未设置”，不得表述为设备真实航向。
4. `informationRole` 是对象用途声明；`observation` 在 UI 显示“现场记录”，不等同来源已核实或实时观测。
5. 新建 UI 普通标绘显式写入 `plan`；旧数据缺省仍保持缺省。Agent 根据用户意图显式写入，不由服务把所有无字段输入补为计划。
6. 扩展 `AnnotationReadField` 以支持请求 `informationRole`，保留基本读结果既有字段行为。渲染完整文档可直接读取该可选值；查询省略它不能被解释为其为空。

同步更新契约、服务严格白名单/合并校验、Pi TypeBox schema、前端表单及实际查询结果。新字段进入现有快照、哈希、差异比较和幂等输入，不仅停留在页面局部状态。

文档继续使用当前 schemaVersion 1 的可选字段扩展，新增服务读取旧文档时不补字段、不重写 JSON，不改变旧固定版本的哈希。旧程序版本的严格白名单不能读取新字段，因此这是“新版本兼容旧数据”，不是“旧程序可任意回滚读取新数据”；回滚策略见第 9 节。

## 4. 三种来源路径

### 4.1 来源态势

使用现有 `SituationObject` 和查询权限，不新增 `mapSymbol` 字段或改造外部服务协议。本期来源仍是 road / resource / area：车辆数量汇总使用通用资源表达，保留数量和单位；不能从名称、数量 1、坐标点或 Agent 判断推断具体车型。

共享解析入口接受明确类型与标绘 `symbolId`。来源缺乏明确细分类型时走通用回退；未来来源适配器得到可信、明确的类型后再接入同一目录，不需要重建地图符号系统。

因此首期专业消防艇/冲锋舟等可以在草稿、发布版本和任务当前标绘的态势查看中完整显示；不承诺当前来源服务直接提供这些装备的实时对象。

现有 `SituationView.tsx:68` 约每 15 秒重新查询来源，并处理页面可见性和请求取消。该刷新所有者应与标绘面板生命周期独立；面板开关不重启查询、清空来源或改变授权范围。数据变化只更新既有来源层，不触发 annotation action、草稿修订或 Agent 消息。来源刷新失败时保留仍获授权的已有数据并提示；401/403/404 等沿用原清理规则。

### 4.2 从来源复制

保留 `annotation_from_source` 的精确几何、完整 sourceRef、修订与查询时间流程。复制出的对象是标绘快照，不会自动跟随来源移动；刷新仍为显式动作。

本期不从普通 `sourceRefs` 推导“已核实现场事实”或“当前与来源一致”，也不默认写入 `informationRole=observation`。用户可以在属性中明确其用途；未标明时保持“未注明”。刷新继续只更新当前约定的几何与来源修订/查询时间，保留名称、样式、信息性质和其他属性。

### 4.3 自定义方案与研判

点、线、面、文字使用现有 `annotation_action`；关联既有资源时复用完整 `sourceRefs`，先查询确切资源并获得引用依据，不新建“资源与标绘关联表”。对象 ID 与来源完整 ref 属于不同命名空间。

绘制方案不改来源数量或位置，发布不执行调度。原有来源权限的继承和发布投影保持不变。

## 5. 渲染方案

专业点采用 MapLibre `symbol` 图层及注册图像，来源点和标绘点共用素材解析器。旧形状继续支持，文字注记可沿用当前稳定路径，避免顺带重构全部点/线/面运行时。

- 专业点几何仍为 GeoJSON Point；显示尺寸、旋转不改变经纬度。
- 车辆/艇旋转以真北方位和素材固有方向换算；名称保持屏幕可读方向，专业参数按条目规则定位。
- 主符号保持可见；名称标签可以采用碰撞避让。不得通过消失整个资源图形来“解决重叠”。
- 点击命中同步加入新 symbol 图层；重叠对象继续用现有候选消歧。图层 ID 包含业务组身份，不只使用 objectId。
- 普通线段、区域沿用现有运行时。末端箭头是派生显示标记，不能将箭头三角形追加到保存几何。
- 选中衬圈、控制点属于临时交互图层；发布文档不保存这些状态。
- 显隐、次序、符号素材注册由明确运行时所有者维护；底图重试仅处理 `basemap:*`，不移除业务素材或重建 Terra Draw。
- 对意外缺失素材，显示中性回退及明确错误；写入未知 symbolId 则直接拒绝。不得把缺失消防艇素材回退为看似正确的另一种消防车。

当前已有每文档 500 个对象、2 MiB 及几何容量限制，本期保留。浏览器验证覆盖接近 500 个对象的选择与编辑，不将此功能扩大为无限量态势渲染工程。

## 6. 单地图内的工具状态

不增加顶层 `view | edit` 路由或业务模式。工具展开是本地界面状态，具体绘制/选择状态继续由 Terra Draw 和现有编辑流程拥有；复用 picked / target / edit / form / buffer / visible / references，不复制地图文档、不新建持久草稿恢复记录。

| 行为 | 规则 |
| --- | --- |
| 初次进入 | 工具收起；读取当前入口获准来源、当前部署及已有可见图层 |
| 展开工具 | 仅展示工具、符号目录和目标信息；不自动创建文档、会话或修订 |
| 缺少可写目标 | 使用既有打开/新建会话、创建图层入口；没有可写上下文不能激活写工具 |
| 选择来源/参考对象 | 只读查看，不把它变成编辑目标；保留原草稿、表单及缓冲，必要时提供返回草稿属性入口 |
| 来源定时刷新 | 局部更新来源数据和详情；不清空 Terra Draw、不改变目标、表单、相机或草稿修订 |
| 收起工具 | 暂停绘制与拖动；保留同一上下文的 form / buffer / target；不自动完成、保存、取消、发布或采用 |
| 再次展开 | 恢复目标及输入；未完成绘制可显式继续，不因开面板自动捕获地图点击 |
| 隐藏草稿层 | 只改显隐，不丢数据、不改当前部署；隐藏正在绘制的目标时暂停该工具，缓冲保留，重新显示后显式继续 |
| 保存/发布/采用 | 复用现有服务与权限；采用指定版本时只替换当前部署引用，来源与分析层保持独立 |
| 切换任务/身份/会话/目标或离开上下文 | 走已有脏数据决策、权限清理及晚响应防护；无权保留的来源不得残留 |

### 6.1 地图、布局与选择

- 左侧保留图层/资源内容；按需停靠的工具区提供目录、点线面文字、目标图层和属性。工具打开不替换整个来源树。
- 宽窗口关闭工具后释放地图空间；窄桌面窗口复用已有折叠区域或将属性置于地图下方，不以遮盖主要对象的浮层硬塞三栏。没有手机端交付。
- 容器变化调用既有尺寸适配路径，保持地理中心与 zoom / bearing / pitch；不调用 fitBounds 自动重新框选所有对象，不重新挂载 MapLibre 或 Terra Draw。
- 查看对象与可写目标是不同概念。先复用现有 target/edit 与来源选择状态，不能把一次只读点选当作切换编辑文档；表单区域暂被详情替代时仍保留缓冲并能返回。
- 选择态、图层显隐、已有参考引用与当前部署不由面板开关重置。关闭按钮支持键盘，关闭后焦点回到“标绘工具”。

### 6.2 草稿与未完成输入

草稿文档、未保存表单和未完成几何是三个状态。前者走现有服务，后两者保留在已有编辑缓冲中；收起工具不是网络写入动作。若运行时关闭工具会销毁临时几何，先在现有 buffer 中保留坐标及操作上下文，再停用交互，恢复时验证目标仍合法。不引入第二套文档或持久恢复机制。

已形成合法几何的草稿预览可在收起后继续显示，带“草稿/未保存”身份，图层独立显隐；未满足最小点数的几何仅属于待继续的输入，不作为已保存图层对象、发布成果或资源统计。控制点只在主动编辑时显示。

工具展开不自动生成一个新版本。用户主动创建/派生目标或完成明确写入时才沿用既有版本规则。保存失败、冲突和未知写入结果按既有机制处理；本方案不把“收起后保留”扩大为浏览器刷新后自动恢复未保存内容。

### 6.3 预览与生产实现

最新预览确认的是单地图与按需工具，以及“实际位置 / 当前部署 / 草稿”并置。预览使用模拟轨迹、示意图标和简化版本按钮；生产实现必须复用真实底图、严格标准素材、既有权限及服务。尤其不能照搬预览中打开工具即生成演示草稿、显隐重置或演示时钟等便捷逻辑。

## 7. Agent 适配

使用既有工具和服务边界，保持主会话可写、子 Agent/后台不新增写能力。

- `annotation_action` 支持新样式字段和信息性质；`annotation_read` 按需返回它们。
- 常用符号 ID 从同一受控目录生成有界 schema 或工具说明，避免手工维护两套枚举。
- 不把整张图、完整符号素材或全部目录描述附加到每条自动上下文；基本上下文大小仍独立于对象数量。
- 不改 Pi 内核、请求级编辑基准、原始回执恢复机制和旧历史文本生成器。
- `annotation_from_source` 的刷新保存新字段，不能因重复构造对象而丢失 symbolId 或 informationRole。

## 9. 兼容与回滚

- 旧圆/方/三角继续按原 size 语义渲染；新增 iconSize 只作用于专业图标。
- 老文档、历史发布、对话引用不批量迁移，不将缺省信息性质补成事实或计划。
- 新增字段在更新、复制、从发布派生、来源刷新和快照读取中均应保留；不能在旧式表单保存时悄悄丢失。
- 前后端及 Agent schema 同批发布；不让新客户端向旧严格校验服务发送新字段。
- 若需要回退 UI，保留支持新字段的契约、校验及读取能力；不能直接回退到无法读取已保存新文档的旧二进制。
- 若渲染出现问题，优先回退专业符号渲染路径并给出通用回退提示，保留保存数据和固定引用。
- 本设计不增加 SQL 表、外部服务凭证或环境变量。

## 10. 已明确延后

独立指挥总览/大屏页面、岗位工作区和第二套系统；真实定位与船舶资源业务模型；推送与自动跟随；统一资源状态机；自动过期阈值；完整军标/消防战术组合引擎；协同多人即时编辑；轨迹回放。后续实施不得以这些能力缺失为由扩大本期数据协议。
