# 会话追加消息与简洁输入交互

状态：用户于 2026-10-12 明确批准开始实施。

## 目标与价值

让单个操作者在同一会话中持续指导 Agent、安排后续处理，无需等待回复结束。采用接近 Codex 的紧凑输入交互，不增加处理卡片、队列管理面板或新的业务任务模型。

## 确认的事实与约束

- 用户已完成交互与原理审阅并明确要求开始实施；本轮未要求部署或 Git 提交。
- UI 要简单；前期 agent-message-flow 原型中的处理卡片、独立队列区及暂停恢复操作已被否定。用户随后提供 Codex Queue 截图，要求输入框上沿的紧凑队列组件，逐条提供“引导”、删除、更多操作。该截图优先于此前“仅取回全部”的建议。
- Pi 0.85.1 原生支持 steer / followUp；优先复用原生机制。
- 多用户身份、消息归属和协作权限以后再建，本期不定义多人操作规则。
- 当前前端忙碌禁发：src/web/main.tsx:172；useChat.ts:412 起阻止 active/stream 请求。
- 当前后端每请求创建并销毁 AgentSession：src/pi/lab.ts:947、1010、1067、1097；一个 requestId 固定模型、资源和执行环境。追加消息不能假装自动获得新请求快照。

## 已批准需求

### R1 输入交互

保留现有输入框、模型选择与附件展示。空闲时 Enter / 箭头正常发送。前台 Agent 运行时仍可编辑、发送纯文本；默认“排队发送”（Follow-up），已由用户确认，与本次 Queue 组件配合；紧邻发送按钮的小菜单可为这一条选择“引导”（Steer），发送后恢复默认。Shift+Enter 换行；Ctrl/Cmd+Enter 为忙碌时“引导”的快捷方式；不占用 Tab，不在中文输入法组合期间发送。

用户已确认默认与快捷键，并要求所有面向用户的 Steer 文案使用“引导”；SDK/API 内部仍使用 steer。用户已随后批准整体实施。

### R2 极简待发送展示

只在输入框上方显示无卡片、无独立面板的紧凑文字行：正文与行尾动作；转为补充后行尾显示“等待引导”，不重复增加状态标签。最多默认展开三行，其余通过一行“展开其余消息”查看。空列表不显示空状态、计数仪表或说明区。

队列像截图一样贴合输入框上沿；每条 Follow-up 右侧依次为“引导”、删除图标、更多菜单。Steer 将该条移入原生补充队列，标签改成“等待引导”，不会立刻宣称生效；更多菜单提供“取回编辑”。删除只影响未消费消息，并给出短暂“撤销”操作；撤销恢复为待发送内容，目标已结束时恢复草稿，不自动启动执行。取回时退出队列，原输入草稿非空则分隔合并，不能覆盖。暂不做排序、拖拽和批量管理。

消息交给 Pi 处理后进入普通对话记录，待发送行消失，不新增“已处理”卡片。不得把入队成功显示为“Agent 已理解”。

### R3 停止与失败

运行时保留独立停止图标，不能因输入框有文字而失去停止入口。停止先阻止新接收和继续消费，等待工具/Agent 终止；未消费消息取回到草稿，不自动继续。已有草稿不能被覆盖；不能撤销已提交的文件或工具效果。

发送被明确拒绝时保留文字；接收结果不确定时保留原发送标识并核对，不能盲目重发。停止、失败、接近结束的竞态中，未消费消息要可见、可取回。消费后取消的消息留在历史，不自动重发。

### R4 首期范围

仅普通前台会话的纯文本追加。忙碌时不改变模型、Skill、子 Agent 选择、文件或对象引用；含这些内容的草稿保留，提示“带附件或引用的消息请在回复结束后发送”，不静默去掉附件。

准备初始化、压缩、等待人工回答/确认、后台作业及停止收尾阶段，追加入口暂不可用并显示简短原因。已有人工问答/确认卡片保留：本次移除的是新增消息处理卡片，不是现有审批交互。

### R5 执行语义与可靠性

Steer 与 Follow-up 均交给同一 Pi 执行循环，逐条投递。Follow-up 是当前前台运行中的原生后续处理，继续使用已捕获的模型、资源和工具权限；并不创建新的 requestId 或业务任务。

每条提交有唯一标识用于防重；执行标识用于避免补充误入另一次前台执行，不假称实现 Codex 每个 turn 的严格绑定。请求临近结束时不自动把 Steer 改投新执行。

同一服务进程存活期间，页面刷新/切换后可读回待发送状态；服务进程重启后的待发送恢复不在本期保证内，不能把这种内存消息展示为已持久保存。

## 验收标准

- AC1/R1：忙碌可纯文本追加，Enter 默认 Follow-up，快捷键/menu Steer；中文输入与 Tab 导航正常。
- AC2/R2：无处理卡片或独立面板，最多三行轻量待发送；375px 可操作、无横向溢出；键盘与触屏均可切换模式。
- AC3/R2/R5：同文重复发送仍是不同消息；同一提交重试不重复执行；Pi 消费后按真实时序进入对话，连续助手回复不错误拼接。
- AC4/R3：停止、取回与模型消费并发时，同一条消息不能既已消费又恢复自动重发；原草稿完整保留。
- AC5/R3/R5：接收前结束则明确拒绝；接收后未消费就结束则可取回；丢失 HTTP 回执可核对，不因盲目重试再执行。
- AC6/R4：后台、人工确认、压缩等暂不支持状态清楚反馈；附件/引用不会被静默丢弃，普通空闲发送无回归。
- AC7/R5：现有文件执行、资源快照、取消、历史和 SSE 行为无回归；浏览器刷新不重复启动 Agent。

## 不在本期范围

多人协同、独立用户与队列归属、永久消息队列、进程重启自动恢复、队列排序/拖拽、排队模型切换、后台消息注入、推翻现有 SSE 为 WebSocket、业务任务/轮次管理重建。
