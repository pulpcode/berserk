# 席位工作双视图：UI 与技术设计

状态：用户已批准 D 席位泳道，待实施。需求与验收编号以 [PRD](prd.md) 为准。原型是独立审阅文件，不属于实际服务页面。

## 1. 页面结构

沿用已精简的桌面应用壳、工作总览标题与六类栏目。标题行不再承载席位工作的局部操作。视图切换与刷新位于席位工作筛选工具区末尾，和搜索相邻，随整个工具组换行；刷新仅针对当前席位工作结果。当前版按钮位置替代首版“页头右侧”建议。

```text
工作总览
研判记录  席位工作  信息流转  处理运行  处理与投递规则  补充投递审批
任务 [全部]  席位 [全部]  状态 [全部]  搜索 [   ]  [刷新图标] [列表 | 泳道图]
                                当前结果
```

不再显示独立总数或常驻箭头／点击操作说明。切换器使用“列表／泳道图”文字。保留原列表分页必要的分页反馈，不新增常驻图总数或图例。

标题继续 24px、36px 行高及既有 22px／26px 页边距，不恢复菜单、标题装饰图标或说明段落。筛选控件使用现有 40px 高度、组内 8px、组间 24px；空间不足时整个字段组换行，不做手机端布局。

## 2. 列表视图

保持当前五列及业务含义，减少学习成本：

| 工作 | 分派双方 | 当前状态 | 下一步 | 更新时间 |
|---|---|---|---|---|
| 完善备用路线方案／道路通行保障 | 总体席 → 筹划席 | 办理中 | 筹划席办理 | 实际业务更新时间 |
| 更新现场道路态势／道路通行保障 | 总体席 → 态势席 | 待验收 | 总体席验收 | 实际业务更新时间 |

- 一工作 ID 一行，任务名称是标题下方次级信息。点击工作名称进入现有只读摘要，不把整行变成难以键盘定位的隐式点击区。
- 保留每页 25 项及现有更新时间倒序、ID 次序打破并列规则，不新增排序模式。
- 标题／分派双方保持合理列宽；窄桌面时表格局部横向滚动，页头和筛选不出现页面级横向溢出。时间、状态保持可读，不将标题挤成单字列。
- 状态沿用 `assigned/working/submitted/returned/completed` 原文映射；下一步责任方复用现有 WorkOverview 规则，两视图不得各维护一套。

## 3. 已选定的席位泳道图

[泳道效果原型](prototype/swimlane.html)为视觉依据，真实页面采用获授权接口结果，不能写死示例。旧 A/B/C 备选只保存在 alternatives.md，不进入产品。

- 每条横向泳道对应一个席位，按席位 ID 保持确定顺序；同名不同 ID 独立。左侧显示席位名称，长名保持可查看。
- 每项工作有独立分派起点（发起行）、工作节点（承办行）与折线箭头。工作节点直接显示标题、任务和原状态，点击复用摘要。已有任务筛选时可避免重复任务文字。
- 按工作 ID 保持确定、稳定的槽位，独立联系错列路由，避免节点与连线重叠。同方向及反向工作分别展示，不聚合丢失工作；自分派有明确本行连接。
- 分派方向固定发起→承办，提交／退回不反转。水平方向仅为排布，不表示时间或不同工作之间的依赖；不新增 BPMN 网关或办理阶段。
- 白色／极浅灰泳道、细绿色箭头、短状态标签，状态始终有文字。保留已批准的简洁页头和筛选布局。

画布内右上角悬浮三个 32px 图标：缩小、放大、适应视图。保留 title、aria-label、禁用状态与焦点。普通滚轮在画布内平移泳道内容，垂直 deltaY 上下移动、deltaX 左右移动，Shift＋滚轮横向移动；Ctrl／⌘＋滚轮才以指针为中心缩放。缩放后释放修饰键仍可滚动，当前比例不变。空白拖动和键盘平移继续可用。画布外及悬浮控制区保留原生滚动，其他浏览器键盘快捷键不拦截。刷新不重置相机；筛选改变时重置图上下文；适应视图由用户显式触发。

多工作画布可超出可视区域，默认以可读比例呈现，平移／缩放可查看完整内容；不隐藏节点或用极小字体假装可读。显式适应视图按全部节点边界计算，用户仍可放大阅读。相机仅保存于当前页面会话，摘要返回时保留；刷新整页不承诺恢复精确坐标。

## 4. 两视图共用的状态

| 用户动作 | 预期 |
|---|---|
| 列表切换泳道图 | 保留四项筛选；列表页码在返回列表时恢复；图使用完整的有界查询而非当前页 |
| 改变筛选 | 重置列表 offset 为 0，清除旧选择与选择，图按新结果适应视图；旧请求不得覆盖新结果 |
| 打开摘要／返回 | 复用当前摘要页；返回按钮按来源标注“返回列表”或“返回泳道图”，恢复位置、选择及触发元素焦点 |
| 从原工作详情返回 | 保持原有导航语义，不创建新的工作副本或修改会话归属 |
| 自动刷新 | 沿用可见页面 10 秒轮询与回焦刷新；保留已选节点／选择／相机；更新不抢焦点 |
| 离开席位工作 | 停止非活动视图查询，其他栏目继续使用原控制与路由 |

仅使用 URL 保存展示与筛选状态，不新增跨用户持久化服务或 localStorage 偏好。相机和临时选择保留在当前页面会话内，刷新页面可恢复视图与筛选，但不承诺恢复相机坐标。

## 5. 数据与权限边界

### 5.1 复用接口

复用 `GET /api/work-overview/items` 和 `/:id`，字段足以构建图：工作 ID、任务、发起／承办席位 ID 与名称、原状态、更新时间、提交摘要和 participant。过滤、授权、排序和总数继续由服务端完成。前端不通过席位名称推导权限，不拉取全部私有工作再自行过滤。

默认列表仍 `limit=25`；图查询使用同一筛选、`offset=0&limit=200`。成功且 `total<=200`、`items.length===total`、ID 无重复时才作为完整图渲染。若超限，不渲染截断图，提示“工作较多，请缩小筛选范围，或切换列表查看全部”，提供现成的切换按钮。若返回数量与总数异常、不完整，不补造节点或数量，显示读取失败并允许重试。

**取舍**：单次有界读取避免多页查询期间工作状态／排序变化造成漏项或混页，复用当前接口。任意规模图明确延后；不能把两次 total 相同视为同一快照。这比早期草稿的无界逐页抓取更收敛。

普通读取错误可保留上一批同筛选数据并标明过期，重试只发 GET。401/403/404 立即清除旧结果、选中详情与聚合清单。切换身份、筛选、视图或离页后忽略旧请求结果。图中只读摘要不扩大正文、附件、验收或代办权限。

### 5.2 路由兼容

新增独立的 `workView=list|flow`：

- `/overview?tab=work` → 默认列表。
- `/overview?tab=work&workView=flow&taskId=...` → 指定任务流转图。
- 原 `view=board|list` 继续仅服务后台作业栏目；旧 `view=board` 不会被解释为席位图。
- 非法 workView 回落列表。切换视图用 pushState，文字筛选保留当前 replaceState 语义；popstate 读取完整展示状态。
- 图忽略列表 offset，但不抹掉它；返回列表恢复页码。改变筛选仍归零。选中详情沿用 id，直接打开详情后返回所带 workView 指定的视图。

## 6. 前端职责与变更边界

- `InformationCenter.tsx`：解析／序列化独立 workView，维护独立视图历史导航；局部操作放在 WorkOverview 工具区。不能将图状态塞入后台作业的 view。
- `WorkOverview.tsx`：公共筛选、业务状态／下一步映射、按活动视图查询、原摘要详情与返回上下文。
- 独立 `WorkOverviewSwimlane.tsx` 与小型纯布局函数：只接收已授权 WorkOverviewItem，不发业务写入、不读私有记录。用 SVG 画连接线、原生 HTML 按钮承接工作操作，减少复杂 SVG 焦点管理。
- `styles.css`：新增总览局部视图／画布样式，复用已提交页头与筛选 tokens；不改其他栏目表单。
- 不新增数据库、后端接口、工作流引擎、图编辑器或动画物理布局依赖。布局函数按输入排序确定结果，便于测试。

## 7. 空态与异常文案

| 状态 | 页面反馈 |
|---|---|
| 首次读取 | 正在读取工作… |
| 无匹配结果 | 暂无符合条件的工作。 |
| 图超过 200 项 | 工作较多，请缩小筛选范围，或切换列表查看全部。 |
| 同筛选刷新失败 | 刷新失败，当前显示上次结果。并提供重试 |
| 缺少总览能力 | 沿用现有权限提示，清除旧结果 |
| 原选中工作已不可读 | 沿用读取错误，返回视图后不显示旧摘要 |

业务正文、文件与操作提示继续由现有组件负责；不再增加常驻的功能介绍段落。

## 8. 验证与回滚

验收矩阵见 [实施计划](implement.md)。上线前仍先本地真实组件验收，确认后才能另行提交／发布。回滚只撤销视图渲染与 workView 路由解析；已有工作、任务、提交、会话和权限数据不发生迁移或回放。历史 query 参数可安全忽略。
