# 第二轮：方案版本、比较与人员批准

2026-11-06 · v0.1 · planning，待审阅。本文为建议需求，不表示已经取得实施授权。

## 目标与用户价值

在现有火情任务中，让人员能提出、比较并批准一个明确版本的方案；新事实出现后，看清此前批准的方案哪些条件仍成立、哪些需要复核，再批准修订版。演示终点为“人员批准及变化后复核”，车辆实际调派属于第三轮。

## 背景与确认约束

- 用户要求从 `codex/scenario-demo` 新建 worktree 并行进行第二轮方案设计，待审阅。基线为 `5e88ca8`，分支为 `codex/scenario-plans-design`。
- 已有任务、来源查询、工作交接、逐条初析、人员从来报建任务、导演时钟及可信来源链的轮次隔离。原生 Pi 拥有会话/文件/工具历史，SQLite 拥有业务记录和回执。
- 当前缺少共享方案实体、固定版本决定、方案依赖核对，以及后台共享方案读取与发布时版本保护；证据见 [research/basis.md](research/basis.md)。
- 当前双系统演示采用逐条初析；持续服务已经存在，但并未完成场景方案接入。完整复验物理流程已完成，模型语义和用户业务验收仍未通过，见第一轮 `research/full-repeat-results.md`。
- 仅面向桌面浏览器，复用现有任务页和 Pi 公开机制；新增记录只服务于固定方案、人员决定、条件依据和必要幂等性。
- “席位工作区”指同一公共任务下各席位自己的工作区/会话，不指个人空间；共享任务不会自动共享各席位的全部会话和文件。
- 2026-11-06 权限审阅：用户提出多筹划席 A→B/C 的分工及审核。现有机制为接收方提交、派工方审核最新提交；原稿“仅总体席批准方案”是新增建议，待 D02 决定，不能描述为既有权限。

## 建议业务规则

- 原稿建议筹划席、总体席可提交共享版本，由总体席批准、退回与撤销；该新增角色限制、自行提交批准规则以及与既有审核的关系均待 D02 确认，不能据此收窄现有工作分派/提交/审核权限。
- 分工作业沿用接收方提交、派工方审核；筹划 A 分派给 B/C 的作业由 A 验收或退回。接受工作成果与选用其中某个候选含义分别明确；若一次操作兼具两种含义，须明确采用的方案版本，避免重复审批。本轮不据此增加通用父子工作或逐级审批引擎。
- 新版本不继承旧版本的批准。批准修订版时明确替换当前批准；原决定保留。新候选提交本身不会撤销既有批准。
- 方案条件状态与人员决定分别表达。新事实使条件不成立时，不改写人员历史决定，也不自动批准替代方案。
- 只能批准当前候选头版本，且任务版本、共享方案集合和核对依据未变化。退回后用新版本回应，不修改原内容。
- 必要条件未知或不成立时先补证/修订；允许保留不完整候选供讨论。有限条件核对通过不代表车辆已获全面出动资格。
- 到达时间是标明依据与假设的筹划估计；不伪装成交通来源预报。方案中不得省略已知必要约束以绕过批准门禁，必要性由人员核对任务需求，宿主不自称能够认证所有业务约束完整性。
- 共享是人员显式发布的业务摘要。原私有文件/对话不自动公开；原资料按当前权限读取，任务可见不扩权。

## 验收标准

| 编号 | 场景与可核对结果 |
| --- | --- |
| A01 | 筹划席在私有工作区准备 A，其他席位/后台无结果；显式提交 A-v1 后可按授权读取，刷新/重启仍为同一版本/hash；编辑形成 A-v2，A-v1 字节及决定不变 |
| A02 | 人员比较 A-v1/B-v1/C-v1，看到车辆/车型/数量、路线、最晚预计到达、必要条件、风险与依据；C 的检修/等待缺口如实存在；后台新版本不打断选择和编辑 |
| A03 | 总体席批准 A-v1，记录明确版本/hash、批准人和时间；A-v2 不继承；批准 B-v1 明确替换 A-v1；两个并发批准仅一个成功；批准不改变车辆来源状态 |
| A04 | 重复车辆不重复计数，类型/身份未知、占用/检修、路段状态未知或缺乏必要核实均显示具体问题；必要条件未满足时不能批准；不以预计释放时间推断已释放 |
| A05 | 当前批准依赖 R01；E08 后条件变为不成立并保留旧决定；E09 的 09:11 观测不覆盖 09:23 封闭；背景 R04 变化不被错误核成 R01 封闭或 A 的确定阻断 |
| A06 | 后台成功读取 A 的确切版本，研判引用这一版本；读取后发生修订/替换或任务需求改变，旧研判不可发布为当前；保留输入等待既有重新研判机制，无第二套模型循环 |
| A07 | 读取/比较均校验任务及全部依赖来源权限，未授权者不能读取，数量和标题亦不泄漏；导演/后台/子 Agent 不能提交或批准；共享记录不暴露私有会话/路径 |
| A08 | 提交/决定响应丢失后按原 action 查得唯一回执；同 action 改内容冲突；旧表单和旧核对结果被拒绝但保留草稿；服务重启不重放批准或模型调用 |
| A09 | 持续首报已有固定已发布结果时，总体席选定一条实际来报并确认主任务；无模型建任务建议也可填写；同来报在另一批次或旧逐条路径重试仍只有一个任务；多消息批次不擅自选择第一条 |
| A10 | 同一来源仅有逐条或持续一种启用模式；结束 A 轮后，旧方案/建任务/批准提交均拒绝，新 B 轮没有 A 的候选和当前批准；历史仍按授权可读，未恢复执行 |

以上工程验收使用确定性模型及真实服务路径；真实模型能否正确识别 R01 影响、说明缺口和实际保存元数据，另行有界测评并保留失败。故事车组/时刻用于验收输入，不能注入工具或宿主选择逻辑作为答案。

## 不在本轮范围

模拟执行命令/回执、实际占用、车辆位置/轨迹/朝向、任务综合首页大改；多人会签、通用规则/流程引擎、自动批准、强行批准；七系统或管理域拆分、无来源任务归属、额外抗干扰样例、历史恢复执行、第一轮模型漏关联的专项治理。私有空间不支持本轮共享方案审批。
