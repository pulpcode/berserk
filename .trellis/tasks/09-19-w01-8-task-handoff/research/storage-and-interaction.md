# 存储与交互依据

日期：2026-09-19。只记录设计依据，不是实现验收。

## 为什么增加少量业务存储

Pi JSONL 保存模型和工具交互。新增需求则要让另一个席位在没有打开源会话时查到分派、固定提交和退回意见，并让一次提交的状态与回执同时保存。为这些业务对象使用独立存储有明确需求，不要求迁移 Pi 会话。

建议 SQLite 只保存元数据，副本先落盘；同一个短事务写工作状态、提交记录和回执。SQLite 提供事务原子性，但它不会把事务外的普通文件复制也变成原子操作，因此设计仍需明确先保存副本、再提交引用。[SQLite 官方事务说明](https://www.sqlite.org/transactional.html)

本机已核对 Node v24.14.0，`DatabaseSync` 可导入；未创建项目数据库。该版本 node:sqlite 仍为实验 API，并且操作同步；仅用于短小元数据事务，不把模型调用或大文件复制放在数据库操作期间，也不为了本期升级运行时。[Node 24.14.0 官方文档](https://nodejs.org/download/release/v24.14.0/docs/api/sqlite.html)

单个 JSON 文件加原子替换也可构成小型原型，但多项工作、提交、回执及查询需由项目自己维护整文件更新和一致性规则。本设计推荐 SQLite 的具体业务存储，不增加通用 ORM 或远程数据库；实际事务与恢复须在 P1 验证。

## 网页设计依据

延续本项目已有侧栏、项目选择、原生弹窗、文件预览、会话草稿、未读蓝点及 InteractionCard。新增业务待办独立展示，不复用助手未读标记；任务详情按当前状态提供动作，阅读不等于签收或验收。

已阅读 ui-ux-pro-max 的交互／无障碍规则，并用其本地 UX 检索核对状态反馈、可取消的界面切换和信息层级。用于检查方案一致性，不把通用风格建议当作已验证产品需求。
