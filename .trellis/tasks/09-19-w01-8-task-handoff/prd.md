# W01-8 任务分派与成果交接

日期：2026-09-19。阶段：S3d。状态：**方案待审，尚未实施**。

## 目标

两个测试席位通过同一个 Axon 完成“分派 → 办理 → 提交文件 → 验收／退回 → 修改后再提交”。继续以多轮对话处理工作，页面提供待办、文件查看及明确的操作入口。

例如：席位 A 将“依据两份资料编制方案”交给 B。B 在自己的目录里编写脚本、生成中间文件、完善方案，再说“上报方案.md”。确认后，A 收到该次提交的固定文件版本；退回时填写意见，B 修改并再次提交。

## 已确认约束

- 用户选择本期**在页面切换两个测试席位**，后续按产品形态完善身份入口。本期不建设人员登录，不宣称具备防冒充的真实多用户认证。
- 工作目录归任务 × 席位。同席位同任务多会话共享文件；不同席位目录、AGENTS.md 和聊天分别隔离。
- 文件处理继续复用 Pi。普通文件不加草稿状态机；提交结果和分派工作由宿主保存。
- 既有 Pi JSONL、压缩、AskUser、操作确认、Subagent 和中断后新请求续聊继续使用。真实业务调度后置。

## 本期需求

| 编号 | 用户可观察的要求 |
| --- | --- |
| K01 | 在单一页面入口切换两个测试席位；各自项目、会话、文件、草稿和待办分别显示；运行中的请求不因切席改变归属 |
| K02 | 在已有项目内分派一项工作，指定另一席位、目标及可选输入文件；接收方获得同一任务下自己的工作区，不能浏览发送方整个目录 |
| K03 | 接收方看到待签收工作，明确开始办理；通过普通对话处理，分派本身不自动启动 Agent，也不创建后台作业 |
| K04 | 一项工作可关联本席位多段会话，关联由页面／服务端明确指定；另一席位的对话原文不会自动进入上下文 |
| K05 | 页面操作与自然语言工具都可发起分派、签收、提交、验收及退回；展示确定的操作对象后再确认，普通聊天文字不直接改变状态 |
| K06 | 每次提交一份普通文件。确认时可查看已固定的待提交副本；确认后接收方看到的正是该副本，原文件后续变化不影响它 |
| K07 | 提交方在详情查看第 1 次、第 2 次等提交及处理结果；接收方只能验收或退回当前提交，退回必须有意见，旧提交仍可查 |
| K08 | 输入资料及已提交成果只能经明确交接读取、下载或复制到自己的目录；复制不覆盖已有文件；不能借文件引用读取未交接内容 |
| K09 | 刷新后可查询原准备单和有效确认，不自动重发；重复点击或响应丢失不重复提交同一次操作。服务重启使未提交准备单失效，Agent 原请求结束或取消也使其准备单失效；已成功的结果仍可查询 |
| K10 | 多会话仍可并行处理普通文件；冲突校验只针对同一分派工作的状态变化和提交，不锁住整个工作区或所有对话 |
| K11 | 原有会话、指令、上传、下载、子任务、停止和压缩行为兼容；旧数据不迁移到新的对话存储 |
| K12 | 待办可以刷新和重新打开查看；进入详情不等于签收，阅读成果不等于验收，不因聊天回复结束而自动完成工作 |

## 范围

- 使用固定两个测试席位，双方均可分派；一项工作只有一名接收席位，提交回到分派方。
- 使用已有项目／任务空间，新增一层“分派工作”；本期不管理整个项目的完成状态。
- 可选多份分派输入资料，沿用现有附件数量及文件大小配置；每次成果提交先支持一份文件。
- 页面待办和明确交接构成本期闭环；不新增独立消息推送系统。

## 后置

输入框键入 `@` 后选择文件的交互，按用户要求留到后续阶段；本期继续使用现有文件面板引用、上传附件和提交表单手动选文件。

人员登录与交接、组织权限、多级审批、转派／撤回／删除工作、多人共同验收、多文件成果包、成果模板、自动差异对比、全文跨会话检索、任意文件修改版本库、后台自动处理、完整 Run／Worker 队列、外部上报／下发接口、消防样板及调度。

通用文件读写仍不提供多会话同文件的强制并发保护；用户确认的是服务已保存的副本，不承诺工作目录的事务快照。
