# 导演台查看与控场边界调整方案

用户已于2026-11-05批准实施，并要求依次提交本方案、合并main、合并codex/scenario-grounded-map、实施及上线待审阅。

## 目标

让“查看记录”“控制当前演示”“重新开始演示”有清楚的入口。最终产品保留切回历史轮次继续演练的方向，具体恢复状态与后台隔离规则在后续轮次隔离方案中定义。

## 本次调整

| 入口 | 行为 |
| --- | --- |
| 当前导演台 | 固定控制服务器当前活动演示，显示场景名、创建时间和状态 |
| 演示记录 | 点击记录打开独立只读详情，查看事件、消息、操作记录和数据概况，关闭后返回当前控场 |
| 重新演示 | 选择场景及模式，集中确认将结束的当前演示与将创建的新演示，再执行现有可恢复准备流程 |
| 待完成准备 | 独立恢复入口，明确准备目标和对当前演示的影响，保留原操作回执及请求编号 |

历史详情提供必要的只读证据入口。“继续准备”移出历史详情。已有准备记录通过明确的准备恢复入口处理，防止点击历史记录就进入可操作的导演台。

演示名称相同时，以实际创建时间及状态辅助辨认。技术编号按需披露。历史详情和主控页面分别读取各自实例，查看历史时主控对象保持明确。

## 现状与后续范围

已有独立对象编号、消息去重、旧任务归档、单活动演示和未确认回执检查。当前场景来源尚未启用自动处理规则。完整轮次隔离涉及消息、任务、来源查询和Agent上下文，属于后续方案与验收范围。

本次先实现独立只读历史查看。隔离完成后，可在详情另设明确的“切换并继续”操作。该能力与挂起、恢复规则另行设计实施。

## 验收

1. 点击任何演示记录只打开详情，主页面的活动实例和投放目标一致。
2. 历史详情只展示资料，任务初始化、启用、投放、锁定和恢复准备均从明确的控场或准备入口发起。
3. 核对或恢复中断操作前，可辨认其目标和影响；刷新后保留既有恢复机制。
4. 只有确认重新演示并成功启用后，活动实例才切换。
5. 保留未确认通知、未投放通知确认、后台作业、未完成工作、权限与场景时钟检查。
6. 合并实际地理数据后验证旧实例可读和定义变化处理，部署有可核对的版本及回退路径。
