# P01 浏览器辅助流程的离线记录

这里记录开发辅助脚本时的首次失败和后续修正。全部连接本地隔离产品，真实模型调用为零。它们不是计划中的 P01 公开真实模型执行，也不进入正式 16 次分母；不能把后续通过覆盖首次失败。

1. `/tmp/task-resource-browser-offline-1`：首次启动被沙箱拒绝本地监听，原错误为 `listen EPERM: operation not permitted 127.0.0.1`。尚未浏览器发送。此目录保留已构建的冻结产品。后续本地服务器/浏览器执行使用获批的 sandbox escalation。
2. `/tmp/task-resource-browser-offline-2/P01-offline/browser/failure.json` 和 `failure.png`：真实登录按钮在“正在登录”期间名称改变，原脚本误以为登录按钮消失就已完成，提前导航。断言在找“发送消息”时发现仍是登录页。改为等待已登录界面的“设置”按钮后导航，不改产品。
3. `/tmp/task-resource-browser-offline-3/P01-offline/browser/failure.json` 和 `failure.png`：脚本将始终存在的空引用容器误当成一条引用，期待容器数量为 0，实际为 1。改为检查容器内引用条目 `:scope > span` 的数量，不削弱“未自动引用”要求。

另一个实际来源集成检查发现区域记录需有 `properties.memberRefs`，而最初样本只有空 `properties`。已为区域补上空数组，保持无隐式资源关联；`fixtures.test.ts` 新增实际 `situationObject` 完整边界解码。修正后 11 项样本检查通过。该问题属于离线夹具准备错误，尚未消耗真实模型请求。

4. `/tmp/task-resource-browser-offline-4/P01-offline/browser/failure.json` 和 `failure.png`：UI 已真实发送且获得确定性回复，发送载荷校验通过；收尾断言误用了页面不存在的“本条消息引用的地图对象”容器名称。改为检查真实用户消息下的“在地图查看 · p01-quay · 证据版本 1”按钮。

最终完整通过：`/tmp/task-resource-browser-offline-5/offline-browser-result.json`。真实浏览器登录、选择区域（无自动引用）、显式引用区域与固定图层、填写 P01 精确原文、点击发送、原生回复及消息引用展示均通过。保留 4 张截图、来源 UI 响应、真实消息载荷、SSE 响应和原生快照；浏览器 pageerror 为零。

本次确定性提供方只返回收件确认，验证 UI 和消息输入路径，不验证资源工具调用、结果卡或模型业务正确性。真实模型调用为 0，确定性提供方请求为 1。正式 P01 仍需按批准计划真实执行并检查这些业务部分。

辅助函数 `driveP01Browser(trial)` 不自行设置提供方；真实运行由 root 明确安排后，运行器可与其现有交互处理并行调用。命令行只提供 `offline` 模式。网页 API 未替换；公共瓦片请求被阻断，避免离线检查访问外部。源对象与固定图层仍真实加载，底图不可用提示保留在截图中。正常运行等待模型完成没有辅助脚本另加的任务时限；离线调用显式使用 60 秒防止测试卡死。

冻结前提示检查：删除 `cases.ts` 的通用任务目标中枚举发现路径的方法清单，改为自然业务目标“核对澄湾演练的资源情况，为值班人员提供有据可查的清单”，保留只读要求。用户题干原本明确给出的范围不变，`oracle.json` 不变。上述离线浏览器记录来自此次任务目标修正前，只作为点击、引用和消息路径证据，不用于宣称模型业务能力或最终提示效果。修正后重新运行样本检查。
