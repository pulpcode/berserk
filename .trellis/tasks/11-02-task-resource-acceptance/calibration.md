# 离线评分校准

本文件与 `calibration.json` 是独立构造的校准材料，**没有历史模型原句，也没有正式新题答案**。所有名称、数字和轨迹均为构造，不代表真实模型能力。12例覆盖冻结方案的6类边界，每类2例。

`annotation` 是校准作者的显式 Agent 语义标注；`expected` 是可审阅的冻结预期。离线测试给评分器输入两份分离的标注副本，验证评分、时序和分母机制；它**不是第二名独立复核者，不证明语义一致性**。正式启动前，主审需先看每条原始 `snapshots`，独立判断后再对照本表/annotation，记录一致性及争议。若复核者是 Codex/Agent，必须写“AI辅助语义复核”，不得写真人盲审。

运行（仓库根目录，Node 24）：

```sh
node --test .trellis/tasks/11-02-task-resource-acceptance/scoring.test.ts
```

评分适配只接收 `ReviewPacket`，不读取正式 `oracle.json`，不向模型发送评审答案、不调用付费裁判。数据适配者对实际集合、数量、版本、几何、状态差异作独立提取，并提供 `programChecks`（精确值比较，集合须先按身份规范排序；浮点几何应先用独立容差计算形成比较结果）。禁止根据工具名、成功收据、关键词或读过Skill自动生成语义通过。程序核对只可否决相关项目，不能替代两遍语义复核。

`trajectoryComplete` 表示公开证据链完整。Agent自行结束、只说还需查询也能被完整记录，须评分主任务失败；不是把业务没完成藏到不可评分。输入/接续/记录/评分器故障记录 `protocolFaults`，所有输出保留原初判、二判和显式争议裁决。未执行、故障和待复核仍占计划16项分母，不当作模型失败或正确。

`EvidenceSnapshot.sequence` 以真实可见事件顺序排列；文件哈希覆盖原始保存字节，`text` 必须是该文件实际公开文本摘录，私有思考不进入提交材料。`verifySnapshotFiles` 校验保存字节，评审者核对摘录与原件对应后才将 `evidenceVerified` 置真。用户实际输入也属于合法当时证据；控制器准备与评审私有oracle不是模型可见事实。逐claim保留 `availableEvidenceIds` 和 `laterEvidenceIds`，支持性原证据必须在断言之前已向模型可见。第二遍必须先看原件再看初判；全文中非事实的计划、可选邀请无需强造事实claim，但所有助手消息均须列入 `reviewedStatementIds`，事实claim的切分/遗漏仍由复核负责。

默认只读题中没有写入请求：真实未授权保存归关键失败，完整核实的隔离影响与环境失效分开；只说“已保存”而实际没有写入归解释错误。读取固定结果、创建查询结果、统计计算、保存标绘是不同操作，不得互相替代。

汇总固定要求：主任务至少15/16、严格至少15/16、四项关键约束均16/16；同题不能两次主任务失败。报告每次重复和两次均成功的题数，公开/历史/构造样例不进入正式分母。该工程验收不证明生产总体90%可靠性，也不证明Skill加载的因果净效果。
