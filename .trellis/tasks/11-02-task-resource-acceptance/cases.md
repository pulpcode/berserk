# 第四批验收题目与准备清单

本批包含 4 道公开流程题和 8 道正式题。正式题各执行两次：先 A01 至 A08，再 A08 至 A01。每次使用新任务、新会话和新标绘版本；同题的业务事实与用户原文不变。

这些实例在产品版本 `12e1cc9` 冻结后独立制作。出题 Agent 未参与资源产品实现；名称、坐标、身份、数量和证据原文均为本批新编，未把旧题改名复用。已有测试只用于查明接口和字段契约。独立预期没有调用产品的空间计算、资源整理或统计函数生成。这里是 Agent 独立出题，不宣称人工出题或人工评分。

`cases.ts` 保存用户原文及仅供控制器使用的澄清事实；`fixtures.ts` 保存业务数据；`oracle.json` 单独封存具体答案。运行器不能导入答案、把答案复制进工作区，或把整个 case 对象发给模型；否则会把尚未追问的事实提前泄漏。每轮只发送正常用户原文和真实产品引用。

## 业务资料放在哪里

- 来源资料通过本地 HTTP 模拟系统提供，Agent 用真实 `ContextService` 查询。模拟系统实际执行对象、类型、区域、关键词及已声明的任务/关系/类别过滤，再分页；不直接返回评测答案。
- 草稿、受控导入和发布版通过真实 `AnnotationService` 建立。受控导入必须调用 `fromSource`，不能直接填写 `resourceAssociation`。导入后的状态冲突通过普通资源编辑写入。
- 任务采用版由独立的作者会话建图、发布，再通过 `setCurrent` 采用。需要草稿和采用版同时存在的题目，分别建立两份资料，不能用其中一份替代另一份。
- A02 的电话补充先作为真实用户消息发送，附实际来源对象引用，再在同会话发送正式问题。原文留在原生历史里；不伪造历史消息 ID。这个前置轮次仍属于同一道题，模型请求照常记账。

每次重复只映射新的实际 task ID，其余业务事实不变。业务参考时间为 `2026-11-02T06:00:00Z`。普通证据在此之前生效且不自动过期；A04 的过期证据明确在此之前失效。因此两次执行不会因跨越有效期而改变答案。**服务系统时钟没有被冻结**；报告应称“固定业务事实”，不能称“冻结运行时钟”。

## 正式题

| 题号 | 用户原文 | 资料准备位置 | 追问或后续安排 | 验收重点 |
| --- | --- | --- | --- | --- |
| A01 | 查一下本任务有哪些资源，任务相关和有依据的支援分开列；已分配、可用情况按证据说。 | 澄湾物资簿中的任务明确引用；邻站协作登记中的支援证据；另有无关可访问记录。主来源没有任务查询接口 | 数据已足够，无预设答复；发现出题遗漏则暂停核题 | 无任务接口仍能按对象读；不把可访问当任务相关，不把支援当已分配 |
| A02 | 把本任务已知的实际资源列出来，草稿和任务采用版本也考虑；计划位置、不能确认的对象和状态另外说明。 | 堤口设备簿、当前草稿、独立采用版；此前带来源引用的真实用户电话报告 | 未知对象单列即可；不为补全未知而阻断已知结论 | 实际资源、计划位置、普通图形和旧图标分开；电话报告不能说成系统确认 |
| A03 | 整理这批资源的名单和数量，同一资源的副本不要重复算；身份不能确认的单列。 | 联运车辆源；经 `fromSource` 导入的副本；另有手工绘制的近似记录 | 无预设身份补充；既有材料足以给有限结论 | 只凭可靠身份去重；同名不同实体保留；未确认贡献不能并入精确总数 |
| A04 | 哪些已分配给本任务而且目前可用？有条件支援、不可用和待核实的也分别列出。 | 东埠班次登记；受控导入后的另一份状态声明；明确的时间、条件和冲突证据 | 没有预设事实可以满足条件或消除冲突；先回答已知部分 | 分别判断任务关系和可用状态，再求交集；保留条件、过期、未知和冲突 |

| A06 | 查清澜登记源和白榆巡查源在榆岸区的资源，有没有资源、查全没有、任务关系是否明确，分别说明。 | 清澜完整范围来源；白榆明确 partial 的有限来源，部分关系字段缺失 | 无预设补充；完全不可用路径只做离线检查 | 真零、部分结果和关系未知分开；分页结束不能抹掉来源覆盖缺口 |
| A07 | 第一轮：只统计我引用图层中的实际资源，区域内和边界分开，不分析任务关系。第二轮：再看同一图层里的全部点图形，包括普通点和计划点，分别有多少在区域内、边界和区域外？ | 桦堤固定发布图层及区域；另有无关可访问来源 | 第一轮正常结束后发送固定第二轮，不按答对答错改题 | 两轮都要完成；第二轮切换全部点图形口径；不扫描无关来源、不强加任务关系门槛 |

A08 的两个可见名称是“北区（山麓侧）”和“北区（港口侧）”，初始问题只说“北区”。目录平等列出两者，任务标题、目标、初始引用和此前消息均不暗示用户选哪一侧。完整名称用于发现后区分候选；它本身不能证明用户意图。任务资源默认范围已在业务背景中明确，不再增加隐藏的来源选择题。

全部题目对 Agent 都是只读任务。控制器预先建图、导入、采用发布版，以及 P04 更新来源，分别记录为控制器准备动作，不能误判为 Agent 写入。

## 如何处理真实追问

只有 P03、A08 有冻结的澄清事实。查看实际问题全文，确认它确实在问区域选择，再使用完整名称、可见 ID 或正常地图引用回复。API 追问使用实际 question ID，并按选项含义匹配；普通文本追问通过正常用户消息回复。不能预设“第一项就是正确项”，也不能按问号判断是否需要回答。

若问到了事实表之外的内容，保留现场并暂停该题核题，不现场编答案。完成任务后可选的后续邀请，不属于阻断任务的澄清。P04、A07 的第二轮是事先固定的用户请求，不受第一轮正确与否影响；A07 第二轮沿用原固定图层，不更换版本。

## 离线核查与封存

`fixtures.test.ts` 用实际字段解码器检查来源、标绘和能力声明；用独立的矩形坐标比较、集合与数量断言核对静态答案，不导入产品空间或统计函数。检查还覆盖稳定重复、身份关联、资源组成员不重叠、真实区域歧义、用户原文来源以及来源更新隔离。

运行器另行验证真实 HTTP 过滤、完整/部分/不可用响应、原生用户历史、受控导入、采用版和任务范围。字段校验通过不代表这些运行路径已通过；离线替身回复也不代表真实模型验收通过。

正式运行前冻结 `cases.ts`、`fixtures.ts`、`oracle.json`、`fixtures.test.ts`、本清单及浏览器辅助脚本的 SHA-256。先提供 hash、制作来源和覆盖说明；产品及评测器冻结后才解封具体正式答案用于复核，不用它调整产品或提示词。
