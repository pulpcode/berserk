# W09-A 审阅入口：事件驱动的后台作业与管理台

日期：2026-09-21。状态：**设计待审，未开始实现**。

本阶段让 Axon 在事件触发后，按目标使用 Agent 与工具完成后台工作，保存执行过程和结果，并按要求交付或转交人员。继续复用 Pi 和现有文件、Agents、席位交接能力。

## 本期交付

| 能力 | 用户可观察的行为 |
| --- | --- |
| 可靠接入 | 浏览器都关闭后，信息仍可接收、排队、处理；重复消息不会重复启动工作 |
| 通用执行 | 同一机制能查询资料、分析、写文件、执行脚本及委派 Agents；不限定摘要或固定工具步骤 |
| 按需判断 | 已知目标直接执行；不明确时查询上下文，判断关联任务、处理方式和接收方；也可直接送达而不调用模型 |
| 结果交付 | 结果可以只保存、关联零到多个任务、送达获准席位或提示人员跟进；不自动等同于正式提交 |
| 查看与继续 | 席位查看业务结果，选择资料继续对话；管理台查看事件、执行、问题和重新处理记录 |

来源系统负责自己的领域信息和历史；Axon 可按需查询，并保存收到的消息和分析实际使用的依据。本期不复制完整来源系统。特情关联分析是验证场景之一，不是所有作业的必经流程。

## 请重点审阅

1. **通用能力与验证场景**：用上下文关联分析、脚本文件处理验证同一执行机制，辅以已有提交的材料检查；不先建设完整领域模拟系统。
2. **任务目录**：建议本期使用 Axon 项目与 WorkItem，补充可查询的目标描述；不要求来源消息先携带任务编号。业务任务最终是否由 Axon 维护，仍需确认。
3. **上下文权限**：建议后台仅查询明确开放的任务描述、来源接口和资料。关联某任务不代表能读取该任务所有席位文件，更不共享聊天历史。
4. **结果与待办**：建议工作台新增“信息与结果”；需要跟进的信息在此提示，正式分派、提交、验收仍在现有工作待办中进行。
5. **人员接手**：选定资料进入新建或已有空闲会话，发送后才启动模型。需要补充条件时也可明确发起新的后台尝试，不保持 Agent 长期等待人员。
6. **运行边界**：保留持久化队列、独立服务身份、模型并发、取消与中断核对；不建设任意断点恢复或自动重放脚本。

其中第 2～4 项是待确认的产品选择，推荐方案及取舍见 [需求](prd.md#5-待审选择)。本稿供审阅，不代表已具备实施批准。
