# W09-A 需求：事件驱动的后台作业与管理台

日期：2026-09-21。状态：**设计待审，未开始实现**。

## 1. 目标

让 Axon 在事件触发后，根据工作目标和获准上下文，使用 Agent 与工具完成工作，保存执行过程和结果，并按要求交付或转交人员。无人打开浏览器时，服务仍可接收和处理；人员回来后可查看结果、问题和执行状态。

这是通用后台作业能力。摘要、任务影响分析、文件编制、脚本计算和材料检查都是可承载的工作，不规定统一的“预处理 → 关联任务 → 席位验收”流程。特情／态势作为后续应用场景，不决定所有作业的处理步骤。

## 2. 已有基础与概念

现有多轮对话、Pi 原生历史、AGENTS.md、Skill、Agents、文件工具、Docker 沙盒、HITL 和双席位交接继续复用。

| 对象 | 含义 |
| --- | --- |
| 来源消息 | 本次收到的一条信息或业务操作成功通知 |
| 来源事项 | 外部系统中的事件／对象，可有多次消息更新 |
| 业务任务 | 业务上要完成的工作；当前项目空间与其中的 WorkItem 分别表达任务范围和具体分派工作 |
| 后台作业 Job | 系统为一个目标执行的处理；不等同于业务任务或人员待办 |
| 自动结果 | 分析正文、文件、关联建议、检查意见等；生成结果不等于正式上报 |
| Submission | 对既有 WorkItem 正式提交的成果版本，沿用现有确认及验收流程 |

## 3. 要求

| 编号 | 要求 |
| --- | --- |
| R01 | 先保存来源消息、附件和待处理记录，再确认接收；浏览器离线不影响处理，服务重启后记录仍在 |
| R02 | 同来源消息重送不重复办理；同事项的新消息独立保留，记录来源关联及输入依据，不按接收先后推断业务真伪或覆盖旧分析 |
| R03 | 目标明确时直接执行或送达；需要判断时，Agent 可查询上下文、选择获准 Agents、判断关联及接收方；无法判断时保留问题，供人员处理 |
| R04 | 复用通用工具完成不同目标，可生成中间文件、脚本和交付文件；自动结果独立保存，不强制创建 WorkItem 或 Submission |
| R05 | 一条信息可不关联任务，也可关联一个或多个任务；来源关联、Agent 判断和人员修正可区分，关联不自动扩大访问权限或启动更多作业 |
| R06 | 按需查询来源历史、获准任务目标和资料；保留实际使用的重要依据，不要求先复制整个来源系统或建立知识库 |
| R07 | 结果按指定接收范围出现在席位可用入口；查看、已读、需要跟进和正式业务验收分开。人员可带入选定资料继续对话；上报、下发仍按既有权限和确认办理 |
| R08 | 停止、失败或重启后保留已有文件、日志和回执，说明状态；重新处理保留前次关联，不自动重放结果不明的脚本 |
| R09 | 工作台呈现业务信息与结果，管理台呈现事件、后台执行及失败原因；可查询、暂停领取、停用触发、取消和人工重新处理 |
| R10 | 后台作业并发与模型调用并发分开控制；前后台及父子调用共享模型容量，人工等待不长期占用执行资源 |
| R11 | 后台使用固定服务身份，只访问获准来源、任务及资料；结果接收范围不能超出资料交付权限，不能借任务关联读取其他席位的私有目录或会话 |

## 4. 本期建议范围

- 应用内持久化事件接入、作业队列、执行记录、结果及站内送达；复用 Pi，不另写 Agent 循环。
- 文本／文件测试接入；现有任务分派、成果提交成功事件。分派默认只关联已有工作；提交可配置辅助检查，检查不代替验收。
- 按目标执行、按需语义判断，以及无需模型的直接送达。配置明确目标、工具／资料范围和可交付对象，不固化工具步骤。
- 最小来源详情／历史查询、任务目标／获准资料查询。使用可复现测试数据验证，不前置完整特情、态势模拟服务。
- 两类自动作业验证：上下文关联分析；脚本与文件处理。另验证已有提交的辅助检查和人员继续对话。
- 席位业务结果入口与独立管理导航；继续桌面使用、同一应用和部署。

正式上报、下发及外部写操作不由后台自动批准。补资料、人工修正或正式提交由人员明确发起；不为所有结果建设验收状态机。

## 5. 待审选择

| 决策 | 建议 | 影响 |
| --- | --- | --- |
| 业务任务的维护方 | 本期使用 Axon 既有项目／WorkItem 作为任务目录，补充可供分析的目标描述；外部系统维护自身领域信息 | 若任务实际由外部平台统一维护，需改用其目录接口，不同时维护两套任务事实 |
| 后台资料范围 | 配置明确允许查询的任务描述、来源接口和固定资料；席位私有会话与目录默认不开放 | 资料不足时允许给出无法判断及待核实问题；更广的读取范围须有明确授权方式 |
| 席位结果入口 | 工作台增加“信息与结果”，按项目／来源筛选；与现有业务待办分开 | 无需为每条信息创建待办；未来专业席位可在此基础上呈现领域信息 |

以上为待审建议，不视为已经批准的产品选择；实施前需确认。

## 6. 后置与通过条件

后置真实用户登录、真实特情／态势接入、来源全量同步、语义知识库、领域数据模型、定时任务产品、DAG／任意递归调度、独立消息中间件、全部前台 Run 账本、全量会话迁移和任意断点恢复。需要正式验收的业务工作继续使用现有机制，不新增服务承办的自动提交／退回工作流。

通过条件：不同目标共用后台执行机制；无任务编号、一对多关联、无相关任务、来源补充信息均可表达；结果与业务提交不混淆；离线、去重、权限、取消、强制重启和旧功能回归通过 [BG01～BG22](acceptance.md)。
