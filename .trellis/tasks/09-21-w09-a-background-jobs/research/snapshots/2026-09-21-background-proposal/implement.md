## 2. 开发顺序

路径相对 `experiments/harness-lab/`。先完成一条真实执行路径，再完善按需判断和页面。

| 步骤 | 工作与主要位置 | 验证 |
| --- | --- | --- |
| P1 接入与存储 | `contracts/` 定义事件、作业、尝试、结果和接收范围；复用 `collaboration/service.ts` 的同连接事务，增加表及固定文件来源；内部业务成功事件同事务记录 | BG01～BG03、BG21 |
| P2 通用后台执行 | 新增 `background/` 接入、触发及队列；在调用现有 Pi 前预登记尝试；服务目录、文件／脚本、Agents、停止和结果发布；`controlled-stream.ts` 增加共享模型并发 | BG04、BG05、BG09、BG12～BG16 |
| P3 上下文与判断 | 来源详情／历史测试适配器；当前项目／WorkItem 目录及受控任务说明；资料查询、结构化结果登记、零到多任务关联、交付校验 | BG04、BG06、BG10、BG11、BG17 |
| P4 结果与人员衔接 | 信息直接送达、结果与未读记录、关联修正、材料检查关联原 Submission、导入资料继续对话；保留原业务状态和 HITL | BG07～BG11、BG19 |
| P5 页面与管理 | 工作台“信息与结果”和获准后台动态；`/admin` 事件／作业／触发配置，启停、暂停、取消、补充要求及重新处理 | BG08、BG18～BG20 |
| P6 集成验收 | 故障注入、迁移恢复、真实模型／Docker、桌面浏览器和旧功能回归；记录证据，按实际实现补规范 | BG01～BG22 |

P2 首先验证“持久化事件 → Pi 按目标生成文件 → 保存结果 → 离线后仍可查看”。P3 再用无任务编号输入，验证按需查询、多任务影响和无相关任务。两类目标复用同一执行机制，不各写一条业务流水线。

## 3. 实施约束

- 复用公开 Pi SDK、默认压缩和既有 Agents。已安装版本为 0.85.1；用确定性模型先验证服务执行范围，不使用私有字段、不另写 ReAct 循环。
- 上下文清单中的后端／前端 `harness-lab.md` 超过当前自动注入长度；实施时主动分段读完相关规范，不能依赖被截断的注入内容。
- 新增后台身份、结果和查询能力只补明确缺口。旧 WorkItem 不改成服务承办，不扩建自动提交、退回、复核状态机。
- 数据库保存执行和交付元数据，聊天正文仍以 Pi JSONL 为准；结果正文引用原生消息或固定文件。
- 任务关联与授权分开；模型不能通过任务 ID、接收席位或正文扩大资料范围。登记结果不立即送达，也不成为正式业务提交。
- 共享模型名额只覆盖实际调用，等待工具、Agents 和退避不占名额；默认不增加固定工具／模型次数上限。
- 同事项更新不强制串行、不自动合并；不以新的接收时间替代来源版本或事实判断。
- 未确认的领域、身份、成果流程需求不在本期顺带实现。公共 SDK 若存在能力缺口，记录影响并重新审阅方案。

## 4. 检查与证据

在 `experiments/harness-lab/` 运行：

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

新增针对事件／队列、查询与交付权限、结果归属、共享并发和 SIGKILL 的有效测试；回归旧对话、压缩、Agents、文件、HITL、会话恢复及双席位交接。不用模型固定调用顺序证明通用能力，不用 mock 成功代替真实处理质量。

新增隔离数据的 `probe:background` 真实验收入口：源消息／历史和三份候选任务说明用于关联分析，另一组数据文件用于脚本生成与执行；另测已有提交的辅助检查。使用已配置模型与服务器，记录真实调用、产物、用量、已知限制和人工逐例评价；不操作正式业务数据。

网页只验收桌面、键盘、焦点、独立草稿、未读及异步结果归属。没有页面在线时接收并执行；重新打开只查询结果，不重新调用模型。真实 API、自动化、浏览器和上线分别记录。

## 5. 迁移与发布

1. 在数据副本验证新增表、固定文件归属和事件事务；原工作／提交／回执可读写，旧会话和文件字节保持。
2. 正式更新前停服备份完整数据根；迁移预检后启动唯一服务，初始关闭新事件触发。
3. 配置来源、目标、任务及资料范围、交付对象、管理凭证和并发；受控事件验证后启用。凭证不进仓库。
4. 回退恢复对应程序与备份；单独保留并核对升级后的新增记录，不用旧程序直接打开新版数据库。
