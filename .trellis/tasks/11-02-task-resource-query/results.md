## 这批改了什么

1. 新增 `task_resource_query`，能查询资源、读回固定结果、统计数量。继续使用现有后端、权限和 Pi 对话记录，不另建服务或结果库。
2. 把“查到什么数据”和“与任务有什么关系”分开。来源没有任务字段也能按对象、区域等条件读取；平台引用只能证明相关，不能直接证明已分配、可用或已查全。
3. 资源清单区分可靠的同一实体、可能重复、可用/故障/未知状态以及不同数量单位。可按关系和可用状态筛选统计；没有依据的数量不当零。
4. 资源结果可以继续做空间计算。实际位置用于内/边界/外判断；计划、估计、站点、缺失和冲突位置单列。后续读取、统计和保存保留原来的缺口与权限。

例如：来源没有任务接口，但本平台引用了 R1，工具可以查 R1 并标为“任务相关”；如果明确查询某来源区域，则关系未知的 R2 也可以参与普通位置分析，不能因此被说成“已分配”。D15 的五种情况都纳入实际服务检查。

## 审查中修正的问题

- 生成的缓冲区再次作为几何使用时，应正常工作；但不能把缓冲区当成原资源的实际位置来统计。
- 点分析遇到非点几何应报错，不能悄悄记作位置未知。
- 数量不仅校验格式，还要根据固定记录复核；同时改写正文与结构化数字也不能冒充合法结果。
- 后续统计沿用原查询时刻，不能因为时间经过而改变旧结果的数量解释。
- “3 辆可用量”和“1 辆实体量”保留各自含义，不合计为 4，也不删除后一条事实。只有含义、单位、范围、时间等可比且有有效覆盖证据时才去重。
- 来源可以明确声明“只覆盖部分数据”及原因；没有下一页不等于覆盖完整。
- 空间统计保留未分类对象及原因。资源缺位置时，即使已知命中为空，也不能写成确定的实际零资源。

这些是已批准第二批验收要求内的修复。首次失败、测试断言纠正及复验记录分别保留，没有改掉记录后宣称从未失败。
