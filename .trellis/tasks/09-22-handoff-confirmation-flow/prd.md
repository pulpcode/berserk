# 工作交接与确认衔接修复

状态：2026-09-22 已实施，本地检查通过，真实模型验收待完成。业务流程补充提示后置。

## 目标

用户要求分派、签收、提交或验收时，Agent 发起一次完整业务调用，系统展示实际内容供确认，批准后返回真实执行结果。无需用户提醒 Agent 再调用第二个工具。

## 已确认问题

线上测试中，Agent 准备了两份附件后漏调确认工具，却宣称已有卡片；下一轮补调旧操作时，用户批准后才收到失败。事实与请求编号见父任务 [BUG-003](../09-22-handoff-attachment-integrity/bugs.md#bug-003分派准备与确认跨轮衔接失败)。

- 两次模型调用的衔接依赖模型自行完成：[工具定义](../../../experiments/harness-lab/src/pi/collaboration-tools.ts:51)。
- 当前已有同一工具调用内等待批准的机制，但有效性检查晚于卡片展示：[执行前回调](../../../experiments/harness-lab/src/pi/lab.ts:634)。
- 系统提示和工具说明已交代流程；不是简单缺少一段操作指南：[上下文](../../../experiments/harness-lab/src/pi/lab.ts:568)。

## 边界

本次不调整后台 bash 命令策略（BUG-002），不建设跨重启恢复、跨轮分派草稿、自动替用户批准或自动重试。沿用现有 WorkItem 状态，不新增 Run 或审批状态机，不升级 Pi、不迁移聊天历史。

文件选择仍由 Agent 根据用户意图完成；合并工具不能保证模型永远选对文件。父任务 BUG-001 的自然多轮验收继续独立记录。本次不修改旧坏单、不自动补附件、不清空线上测试数据。

审阅重点：统一交接工具、宿主填入当前范围、保留现有确认与失效边界。用户已批准实施。
