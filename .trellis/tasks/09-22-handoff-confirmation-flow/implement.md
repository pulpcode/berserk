## 顺序

1. **锁定复现与兼容。** 将父任务 BUG-003 固定为测试；保留旧 prepare／commit、旧确认记录样本，验证新旧混合历史可读。先落历史读取兼容，作为可回退基点。
2. **调整 Agent 输入边界。** 增加 `work_item_action` 输入，宿主填入当前项目／工作区；复用原服务输入及页面 API。新会话与续聊只注册新交接工具，删除旧流程提示。
3. **串联准备与确认。** 在现有工具执行链中完成准备、卡片前预检、等待和批准后提交；按实际调用关联原生记录，保留原服务授权与事务。
4. **修正错误处理。** 业务校验失败返回具体工具错误；内部故障仍停止。回执可查，取消／拒绝不产生新的工作。
5. **接好现有页面。** 新工具名加入聊天过程标签和交互历史解析；复用当前卡片和实际附件展示，不新增页面或成功状态。
6. **完成回归与真实验证。** 下列检查通过后再运行隔离真实模型评测，保留全部结果。同步实际契约到 spec，记录发布／回退条件，实施完成不等于已部署。

## 验证方式

在 `experiments/harness-lab` 执行：

```bash
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

确定性测试覆盖 [A1—A7](prd.md#验收)：一次模型调用进入卡片；批准前无正式效果；双附件与纯文字；参数错误无卡片；等待中版本变化；拒绝／停止／重复回应；原回执可查；重启不重放；旧历史继续展示；页面入口及其他工具回归。

取消覆盖文件准备尚未返回、等待批准、收到批准立即停止三个时刻；使用可控屏障验证，不靠短暂 sleep 猜时序。历史测试分别保留新旧参数结构，旧会话续聊时真实旧调用仍在上下文中，但可用工具只有新交接入口。

更新 `probe:handoff` 后，在独立数据目录验证 A8：A 读取两份材料，下一轮自然要求全部分派 B，核对卡片、回执和 B 导入字节，再完成提交和验收。三次独立自然分派保留失败，不追加内部工具名或 ID 引导来替代自然验收；成功次数与未完成原因分别报告。使用已配置模型与现有测试授权，不把密钥或原始生产对话写入报告。

真实验证先直接准备隔离工作区材料，不依赖仍未修复的后台命令问题，不清理或复用线上同名旧任务。若观察到模型选错附件／多余提问，记录到父任务，按是否影响本次验收如实判断，不静默扩大修复范围。

验收记录分别保存确定性检查、真实模型表现、数据兼容和发布结果。仅文档阶段不运行上述产品检查、不改业务数据。
