# PRD：多对话模型选择与默认模型机制优化

> 状态：方案已获用户审阅批准（2026-11-27），可进入实施阶段。实施完成后需进行复核检查与前端细节优化。

## 1. 目标与用户价值

优化多对话场景下的默认模型管理与模型选择体验，解决以下真实痛点：

1. **默认模型欠费或停用时反复手动切换**：当前所有新建对话始终硬回退到系统默认槽位 `'default'`，一旦默认模型余额不足、不可访问或已停用，用户在频繁新建对话时必须每次重新下拉选择替代模型。
2. **管理员无法一键切换系统默认模型**：当前“系统默认”死绑在 `id === 'default'` 这条记录上（[model-settings.ts](../../../experiments/harness-lab/src/server/model-settings.ts#L198)、[ModelCatalogSettings.tsx](../../../experiments/harness-lab/src/web/ModelCatalogSettings.tsx#L220)），更换系统默认只能手动覆盖编辑 `default` 配置，运维繁琐且易造成同平台重复模型。
3. **多入口新建对话的默认语义不一致**：工作待办（[WorkInbox.tsx](../../../experiments/harness-lab/src/web/WorkInbox.tsx#L174)）和态势地图引用（[main.tsx](../../../experiments/harness-lab/src/web/main.tsx#L527-L553)）新建会话时会误消费聊天页残余草稿模型，而能力中心与标注派生固定走 `'default'`。
4. **多平台多模型下选择器信息不足**：当前原生 `<select>`（[ModelPicker.tsx](../../../experiments/harness-lab/src/web/ModelPicker.tsx#L4-L18)）未标出系统默认/个人默认、不支持多模型检索与行内设为默认，历史会话模型失效时也缺少一键切换快捷入口。

**核心产品原则**：
* **临时切换与修改默认严格解耦**：在对话中切换模型永远只作用于当前对话，绝不静默改写个人默认或系统默认。
* **系统默认与用户默认优先级清晰闭环**：前台新建尊重个人偏好，后台任务与既有历史会话受硬边界保护，管理员停用/删除权限始终最高。
* **仅面向桌面浏览器**（遵循项目产品平台约定），不引入移动端专项改造。

## 2. 已确认事实（代码锚点）

* 模型目录持久化于 `model-settings.json`（当前 schema 7，见 [model-settings.ts](../../../experiments/harness-lab/src/server/model-settings.ts#L119-L170)），`GET /api/models` 返回 `{ defaultModelId, models }`。
* 会话模型选择持久化于 Pi 原生会话 jsonl 的 `berserk.model-selection.v1` 条目（[model-selection.ts](../../../experiments/harness-lab/src/pi/model-selection.ts#L6-L22)）；会话空记录时回退为 `'default'`。
* 前台执行读取 `selectedModelId`，Subagent 继承父请求模型；后台作业（`internal?.background`）与预处理（`startPreprocess`）强制使用系统默认模型（[lab.ts](../../../experiments/harness-lab/src/pi/lab.ts#L673)、[L1700](../../../experiments/harness-lab/src/pi/lab.ts#L1700)、[L1866](../../../experiments/harness-lab/src/pi/lab.ts#L1866)）。
* 「设置 → 个人偏好」已具备个人默认专家（[Settings.tsx](../../../experiments/harness-lab/src/web/Settings.tsx#L63-L73)、[ExpertDefaults.tsx](../../../experiments/harness-lab/src/web/ExpertDefaults.tsx#L60)）与 `/api/me/preferences/expert` 后端持久化范式。

## 3. 功能需求

### R1：管理员一键切换「系统默认模型」
* 管理员在「设置 → 模型管理」的任意平台模型列表中，可以对任意**可用**（已启用、已确认用途、平台已配置 Key 且参数完整）的非默认模型执行 **「设为系统默认」**。
* 切换后，全局 `defaultModelId` 指向该模型 ID：
  * 立即作为系统级新建对话默认模型、后台作业与预处理模型生效（进行中的请求保持其准入时捕获的模型快照，不受打断）。
  * **不影响已有历史对话**的模型归属。
  * 原默认模型所在平台在不再持有当前系统默认模型后，允许按既有规则删除。
* 不可用模型（未启用、未确认用途、缺 Key、缺容量参数）不允许设为系统默认。

### R2：用户级「新对话默认模型」偏好
* 每个账号拥有独立的个人默认模型设置，初始态为 **「跟随系统默认」**：
  * **正式登录模式**：持久化于后端 SQLite（`GET/PUT /api/me/preferences/model`，按 `userId` 隔离，换浏览器或重新登录不丢失，与现有 `/api/me/preferences/expert` 一致）。
  * **无登录测试席位模式**：自动回退为浏览器 `localStorage`（按当前 `storageKey` 隔离）。
* 用户可在两处管理该设置（状态实时同步）：
  1. **对话/任务首页的模型选择器 Popover 内**：每条可用模型右侧提供轻量的「设为默认 / 取消默认」操作，顶部显示当前生效的「跟随系统默认（当前：平台－模型）」入口。
  2. **「设置 → 个人偏好」页签内**：提供「个人默认模型」配置区（与现有「个人默认专家」风格一致），可在「跟随系统默认」与各可用模型间选择并保存。
* 明确隔离边界：
  * 点击模型主体仅切换当前对话或当前草稿，**绝不**修改个人默认。
  * 修改个人默认**只影响后续新建对话**，不改变已有历史对话，也**不影响后台作业或预处理**。

### R3：全入口统一的新建对话默认解析与优先级
所有新建会话入口统一遵循以下从高到低的解析顺序：

1. **当前草稿的本次手动选择**（仅适用于带模型选择器的聊天页新对话草稿 `workspace:<id>` 和任务首页草稿 `task-home:<id>`，创建会话后消费并清除该草稿选择）。
2. **用户个人默认模型**（前提：用户设置为具体模型，且该模型当前依然存在且可用）。
3. **系统默认模型**（`models.defaultModelId`，前提：当前可用）。
4. **兜底预选：模型列表中第一个可用模型**（仅针对新建对话草稿在默认模型不可用、但目录中仍存在其他可用模型时触发；同时展示温和提示，告知用户原默认暂不可用、已为其预选替代模型）。
5. **全部不可用**：不自动切换，阻止发送并沿用现有配置指引。

**全入口一致性要求**：
* 聊天页新建对话、任务详情页新建对话、能力中心「与专家协作」、工作待办「新建对话办理」、态势地图「引用并提问」、标注派生新会话，均使用上述同一套解析逻辑。
* 无独立模型选择器的入口（工作待办、态势地图引用、能力中心、标注派生）**禁止读取或消费**聊天页 `workspace:<id>` 的未发送草稿模型选择。
* 新会话落盘时，服务端将实际确定的 `modelId` 显式写入会话的 `berserk.model-selection.v1`，确保未来系统默认再次变更时该会话模型不会发生漂移。

**边界互动规则**：
* 用户处于「跟随系统默认」时，管理员切换系统默认 → 用户下次新建对话立即跟随生效。
* 用户已设个人默认 = B 且 B 仍可用，管理员将系统默认从 A 切到 C → 用户新建对话保持 B，且在选择器中清晰可见 `系统默认` 已更新为 C，用户可一键切回「跟随系统默认」。
* 用户已设个人默认 = B，但 B 后续被管理员停用、删除或配置失效 → **系统级管控权限高于个人默认**；新建对话自动降级回退到当前系统默认（系统默认也不可用时走第 4 步兜底），并显示清晰的降级提示（不静默清除原偏好记录，也不卡死在不可用项）。

### R4：桌面端模型选择器与失效恢复交互升级
* 将 [ModelPicker.tsx](../../../experiments/harness-lab/src/web/ModelPicker.tsx) 从原生 `<select>` 升级为桌面端 Popover 菜单（保持输入框底部工具栏紧凑占位与完整键盘无障碍操作）：
  * 清晰展示当前选中模型的 `平台－模型名`。
  * 菜单内按平台分组（或带平台标签）展示模型，标明 `系统默认`、`我的默认` 徽标及不可用原因（未配置 / 待补齐参数 / 不可用）。
  * 当模型总数 ≥ 6 时提供关键词即时过滤。
  * 行内点击模型切换当前会话/草稿；行尾提供显式「设为默认 / 取消默认」按钮（不可用模型不显示）。
* **历史会话所选模型失效时的防呆与快捷恢复**：
  * 保持既有原则：已创建的历史对话所绑定的模型若被删除或停用，**绝不静默切换**，保留输入草稿并阻止发送。
  * 在原有警告提示条中新增快捷按钮 **「改用默认模型」**（仅当当前存在可用默认/兜底模型且会话空闲时可用），点击后一键为该对话切换模型，免去手动下拉查找。

## 4. 验收标准

1. **管理员切换系统默认**：
   * 管理员可将平台 B 下的可用模型 B1 一键设为系统默认；重启服务后系统默认仍为 B1；`GET /api/models` 返回 `defaultModelId === B1.id`。
   * 不可用模型调用设为系统默认接口返回明确错误（400/409/503），不修改磁盘配置。
   * 原默认模型所在平台在迁出默认后可正常删除；当前持有系统默认模型的平台仍拒绝删除（`DEFAULT_MODEL_PLATFORM`）。
   * 业务席位调用系统默认修改接口返回 `403`。
2. **历史会话与后台任务隔离**：
   * 切换系统默认前已创建的旧对话（含未显式写 `MODEL_SELECTION` 的历史对话）在切换后仍保持原模型归属，不会静默变成新默认。
   * 后台作业与预处理在系统默认切换后使用新的系统默认模型，且完全不受任何用户的个人默认模型影响。
3. **用户个人默认与优先级**：
   * 正式登录模式下，用户在模型选择器或「设置 → 个人偏好」中将 B1 设为个人默认后，跨刷新、跨标签页、重新登录后依然生效；随后从聊天页、任务首页、工作待办、能力中心、地图引用、标注派生新建的对话初始模型均为 B1。
   * 无登录测试模式下，个人默认按测试席位隔离保存在 `localStorage` 中并正常工作。
   * 用户在某条已有对话中临时切换到 B2，仅影响该对话，不会改变个人默认（下次新建对话仍为 B1）。
   * 用户点击「跟随系统默认」后，新建对话立即跟随管理员设置的系统默认。
   * 当个人默认 B1 被管理员停用或删除后，用户新建对话自动降级到当前系统默认（并展示温和提示），不会卡死在不可用项上。
   * 当系统默认本身停用/未配置、但目录存在其他可用模型时，新建对话草稿自动预选首个可用模型并给出温和提示。
4. **草稿隔离与防串味**：
   * 在聊天页新对话草稿中选择 B2 但不发送，转去工作待办或态势地图新建对话，新建的对话使用解析默认（个人默认/系统默认），不偷吃聊天页草稿里的 B2，且回到聊天页草稿时 B2 仍保留。
5. **交互与回归**：
   * 桌面端键盘操作（Tab / Enter / Arrow / Escape）及窗口窄面板下 `ModelPicker` Popover 定位与截断正常。
   * 历史对话所选模型失效时，点「改用默认模型」可一键切换并恢复发送。
   * 既有 `typecheck`、`lint`、Vitest 单元/集成测试与 Playwright 桌面端 E2E 回归全部通过。

## 5. 不在本次范围

* 模型余额探测 / 自动故障转移（如按上游 402/429 响应自动切模型）。
* 专家级 / 任务级独立默认模型绑定（本次仅覆盖系统默认与用户级默认，专家仍走既有 `ExpertDefaults`）。
* 手机端布局与触控适配。
* Pi SDK 升级或引入第二套模型配置/运行时体系。
