## 确认的问题：B02 继承关系被说成巧合

- **位置：** `collaboration/B02-request-4d2adc2a-1016-4ab5-b3b7-994e5eb119c4.json`，最终答复。
- **原句：**“两者是不同集合（不同 setId），仅对象 ID 巧合一致，不能据此认定是同一对象的同一版本。”
- **断言范围：** 不只是说两个快照版本不同，而是确定性解释相同 ID 的原因是巧合。
- **模型本轮证据：** 两次 annotation_read 只读取 A:r3 与 B:r3 的 point-a note，以及名称/类型/图层摘要；provider 输入 index 9 起包含 B 的共同基线 baseRef 和 A 固定引用，但没有给出 A 的完整派生链。模型未查询双方共同基线，不能得出“巧合”。
- **独立真实状态：** `P0-preparation.json` 的 startA/startB 均基于 publication `b7ca1dba-17e0-47b5-bd43-fa8b0d7503d4`；P0 已有 point-a，两草稿继承该逻辑对象。并非在两个无关草稿中独立创建同名 ID。
- **判定：已证实错误。** “不是同一版本”这一部分可以成立；错误是前半句把共同继承说成巧合。正确业务解释应是同一基线对象在两个独立草稿中的不同状态。本次并没有因此错写或合并对象。

同段还说“名称、类型、所属图层均一致，无其他差异”。名称/类型/图层都有读取依据，但“无其他差异”若扩展到几何、样式等全部字段，超出本轮 note-only 读取范围。独立完整快照确认这两个 point-a 的确只差备注，因此不另判一个与数据冲突的错误；记录为**比较范围表述过宽**。不应把这一观察转化为每次备注比较必须读取整图的要求，直接限定为“已读取字段”即可。

**判为标题范围不清。** 正文明确 passability/车辆数等是“来源中…事实（非本标注保存字段）”，但该声明具体指后列的两条业务事实，没有明确澄清前表的时间保存位置。前表数据本身正确，也可能是在说明保存时查询到的来源元信息；不能直接认定它明确声称 sourceRefs 存了那些字段。应记录为仍可能误导用户的措辞，不隐去，也不把它当作来源时间写错。
