# 验证页面交互依据

日期：2026-09-16。应用 ui-ux-pro-max 技能，目标是桌面 Web 多轮作业验证页；此处记录设计，不表示已实现界面。

## 检索与取舍

- `agent conversation workspace --design-system` 返回营销页结构；重试 `productivity workspace dashboard --design-system` 仍返回营销演示结构，未找到经核验的工作台布局匹配，因此不采用其 Hero／CTA／营销页信息架构，也不保存为项目设计系统。
- `chat streaming status focus --domain ux` 的前三项为上下文状态播报、流式内容、提交反馈，适合本页。采用可见运行反馈、连贯文本增量和不抢焦点的状态更新；逐 token 更新视觉文本不等于逐 token 向读屏器播报。
- 以下布局来自当前产品目标的设计判断，不冒称检索数据给出了该布局。

## S1 首增量交互

| 区域 | 行为 |
| --- | --- |
| 会话列表 | 新建／切换会话，显示当前是否有请求；不要求任务树或席位选择 |
| 对话 | 文本与流式回复，支持连续追问和纠正；只读资料工具记录可折叠并查看来源 |
| 输入 | 中文输入法 composition 时不发送；Enter 发送、Shift+Enter 换行；处理中保留草稿，先停止再提交 |
| 状态 | 可输入、回复中、正在停止；请求结束显示成功／失败／已停止，无 queued 或 waiting_confirmation |
| 停止／异常 | 针对 requestId 停止，收敛后允许继续；迟到事件不能进入新请求；保留已显示内容和输入草稿 |
| 刷新／断线 | 重新查询历史及活动状态，必要时轮询会话快照；不自动重发消息，不要求事件游标回放 |

首步用会话列表＋对话区，资料详情按需展开；不要求三栏工作台、成果版本、确认卡或运行审计页。切换会话不取消服务端请求，但事件必须绑定原会话；返回时重新查询状态。

## S2～S4 后续面板

S2a 的工作区选择、指令编辑／保存结果、Skill 查看与已加载内容详情，以 [W01-2 设计第 3 节](../../09-16-w01-2-workspace-memory/design.md#3-页面与用户操作) 为准（待审阅）。S2b／S2c 再加入压缩和子 Agent 结果。S3 在任务、成果版本、持久化 Run、人工确认与可靠事件落地后，再增加任务树、成果预览、确认卡和运行详情；三栏仅作为此阶段的信息组织建议。S4 的本地导出检查不要求新增产品页面。

后续确认卡须显示具体动作、目标版本和参数摘要；批准／拒绝／取消分别处理，版本变化显示失效。原文和详情返回时保持会话、滚动位置与输入，不将调试字段堆到聊天正文。

## 通用交互要求

仅在用户接近底部时跟随新内容滚动，上翻阅读时提示“有新内容”；窄屏优先保留对话，其余面板收起。按钮有文本或可访问名称、键盘顺序与焦点合理、状态不只依赖颜色、普通文字对比度至少 4.5:1、动态内容不抢焦点。页面展示公开结果，不展示模型内部推理。W01 不建设完整品牌设计系统、复杂拖拽或移动端专版。
