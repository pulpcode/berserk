# Pi 中断后续聊验证

日期：2026-09-19。版本：Pi SDK 0.85.1、Node 24.14.0；真实模型 DeepSeek Flash。范围为独立技术验证，未改变 Axon 产品代码、配置、用户数据或 4315／4316 服务。

## 结论

Pi 可以加载这些中断会话，并接受用户的新消息；“发现未结束请求就要求新建会话”是当前 Axon 的额外限制，不是本次验证中 Pi 的必然要求。

缺失工具结果由 Pi 的模型协议适配层补成 `No result provided`，不修改原 JSONL。这解决消息配对问题，不证明工具未执行。重开会话不会自动执行旧工具，但模型重新提出的调用仍会执行；没有因此获得操作去重或恰好执行一次的保证。

因此，可以继续设计“原会话中开始新请求”的小范围改进，尚不能直接删除全部恢复保护或宣称完整断点续跑已实现。

## 方法与证据

[独立脚本](../../../../experiments/harness-lab/scripts/probe-pi-recovery.ts) 直接调用 Pi 公开 SDK，关闭资源自动发现，使用临时目录和最小测试工具，不经过 Axon 的恢复阻止逻辑。

- 每个场景先实际完成一轮基线对话，再开始下一轮；在指定位置对脚本自身创建的子进程发送 SIGKILL。不是优雅取消，也不是手工编造中断消息。
- 重新启动子进程，打开原生文件副本。先验证没有模型调用，再显式发送新用户消息；核对模型 HTTP 载荷、调用数量和真实文件字节效果。
- 本机 OpenAI 兼容 SSE 服务控制响应时刻，Pi 模型适配、工具循环、JSONL 写入与协议转换均使用真实实现。确定性服务不冒充真实大模型。
- “等待问题／确认”使用最小测试工具和公开 beforeToolCall 模拟等待，保存独立探针记录；不替代 Axon 网页交互恢复测试。
- DeepSeek 另使用三份中断文件副本验证实际服务接受请求并调用只读状态工具。中断历史由确定性模型产生，真实续聊切换为 DeepSeek；不是在真实 DeepSeek 调用期间制造崩溃。
- 恢复时保留原历史字节前缀，不删除或修改旧消息；新增用户消息和回复正常追加。文件副本只在临时目录中使用。

结果、样例载荷和真实模型回答见 [机器可读证据](pi-recovery-evidence.json)。原始文件留在证据中的临时目录，长期结论以仓库内记录为准。

## 中断场景

| 中断位置 | 磁盘状态 | 用户发新消息后的结果 |
| --- | --- | --- |
| 等待模型回答 | 原用户消息已存，尚无本轮助手回复 | 能续聊，原用户消息没有重复注入 |
| 流式文本输出一半 | 本例片段已通过事件输出，但尚未落入原生文件 | 能续聊；不能恢复这一段未落盘文本 |
| 工具执行前 | 有 toolCall、无 toolResult，文件效果 0 次 | 适配层补缺失结果；旧工具未自动执行 |
| 文件已写、工具还没返回 | 有 toolCall、无 toolResult，文件效果 1 次 | 同样补缺失结果，文件保留 1 次效果 |
| 工具结果已存、等待下次模型回答 | 有真实 toolResult，文件效果 1 次 | 真实结果进入后续输入，无须补位 |
| 等待用户回答 | 有工具调用及待答探针记录，无答案结果 | 能接受新消息；不自动恢复旧等待，也不生成答案 |
| 等待操作确认 | 有工具调用及待确认探针记录，未执行 | 能接受新消息；不会因加载历史自动批准或执行 |

七种情况下，打开会话均为零模型请求、零新增工具效果；显式新消息触发一次确定性模型回复。缺失结果补位只出现在发送载荷里，不会回写为“真实工具结果”。

另外，在“已写文件、结果未保存”的副本上，让模型用新的 toolCallId 再次提出相同写操作，文件效果从 1 次变成 2 次。该对照证明：没有旧调用自动重放，不等于模型不会重复操作，也不等于 Pi 自动识别了已完成效果。

## 真实模型结果

三个场景分别为：工具执行前、文件已写但结果未存、等待用户回答。每个场景 2 次 DeepSeek Flash 请求，共 6 次。三次都正常结束并实际调用只读 `probe_status`，返回的标记数分别为 0、1、0；文件未被修改，首个发送载荷均包含缺失工具结果补位。

模型能说明“没有回执不能证明没有执行”。本验证只开放只读状态工具，不能将未发生写操作归功于模型自律或 Pi 去重。提问场景的回复也出现了不够准确的历史概述（将基线记忆和标记保存混述），所以这不是完整的恢复摘要质量验收，更不是自然语言提示能够保证操作安全的证据。

## 对 Axon 的直接含义

1. 有依据缩小当前一律阻止原会话续聊的范围，优先允许历史可校验的普通中断会话开始新请求。
2. 保留损坏历史、持久化失败、归属错误、子记录不一致和沙盒清理不明等独立保护；本次结果不能用于解除它们。
3. 新请求应明确获知上次中断及哪些效果尚不确定。补位文本不是成功记录，不能按缺失结果自动重做写操作。
4. 旧提问／确认可以继续标记失效，由新请求重新提问／确认；恢复原 Promise、跨重启沿用批准或执行到一半的程序均未验证。
5. 不需要为了这些结果先替换 Pi 原生历史或引入整套 Run 数据库；是否需要新增最小中断标记及宿主校验，留到产品设计中明确。

Axon 原有的 3 项针对性测试也通过：未完成历史仍被阻止、待确认项重启失效／缺结果显示未知、待答项重启失效且不伪造回答。它们证明产品行为没有被本探针修改，不是新恢复能力已接入的证据。

## 复现

在 `experiments/harness-lab` 目录运行：

```bash
node --import tsx scripts/probe-pi-recovery.ts
# 将下面路径替换为上一条命令输出的证据目录；只使用探针生成的数据。
node --env-file-if-exists=.env.local --import tsx scripts/probe-pi-recovery.ts --live /absolute/probe-evidence-directory
```

默认模式不访问外部模型；`--live` 使用现有本地配置，不打印凭证。30 秒子进程时限、真实场景 120 秒时限与 6 次尝试上限仅用于探针故障收敛，不改变产品默认配置。

质量检查：TypeScript、Lint、依赖边界及空白检查通过；原有 3 项针对性测试通过。没有修改界面或产品构建入口，因此未重复全量浏览器测试。

## 验证边界

本次是进程强制退出后的、新用户消息驱动的续聊验证。未验证断电／磁盘损坏、未完成的首次会话持久化、真实容器命令接管、子 Agent／压缩过程中中断、旧确认恢复、任意文件操作去重、外部业务提交、模型切换的全部兼容性或 Axon 全链路恢复。已完成基线轮次保证探针历史文件存在，不能从这些场景推断所有崩溃位置都可恢复。
