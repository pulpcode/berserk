# W01 通用 Harness 协议与技术路线验证

日期：2026-09-16。基线：MVP v0.7。状态：2026-09-16 用户授权实施 W01-1，任务 in_progress；S0／S1 已实现并完成 C01～C06 真实／本地组合验收；W01-2（S2a）也已完成 A01～A12 组合验收，其余后续阶段尚未开始。结果见 [验证记录](research/validation-results.md)。

## 目标

先交付基于 Pi 的真实多轮对话与最小工具入口，再逐步完善成熟 Harness 能力、运行管理与可替换边界，为 M1 提供能力证据和技术选型依据。首增量有独立的验收范围，完整 W01 仍覆盖下列 H01～H08。

## 背景与已确认约束

- 产品面向垂直业务场景，以成熟 Harness Agent 的处理能力和多轮交互为参照；领域业务通过工具、Skill、资料和角色接入。
- 用户明确 Memory 指 AGENTS.md／CLAUDE.md 式指令文件；不要求结构化记忆条目、自动抽取与召回服务。
- 当前路线须兼容后续全部自研 Agent／Harness 并最终移除 Pi 等内核依赖；模型仍可使用外部 API。用户未选择本期自研，也未确定长期采用 Pi。
- 用户要求第一步以 Pi 内核的多轮对话为主体；完整 Run 状态机、确认恢复和数据迁移检查后移。Pi 用于首轮落地验证，不等于长期选型已通过。
- 框架先行，样板业务和模拟业务服务后接入；调度操作后延。
- 用户已有 DeepSeek、Kimi 等 API 和 Ubuntu 服务器，后续需要时再配置凭证。
- W01-1 已在 experiments/harness-lab 建立首个应用工程；本地验证和真实模型验收分别记录，已有规范初始化任务独立保留。

## 首增量 W01-1 范围

第一步只建设本地 Web、多轮消息与流式回复、独立会话、基本停止／错误处理、一个读取固定资料的工具，以及复用 Pi 原生机制的历史保存读取。单一本地测试主体，不要求任务空间、双身份权限矩阵、成果版本或复杂运行控制。

仅保留 Pi 接入模块与平台页面接口分离的代码边界。SQLite、平台 Run／快照／操作账本、确认恢复、可靠事件回放、导出迁移检查和完整 HarnessAdapter 不作为第一步前置条件。Memory、Skill、压缩和 Subagent 在 S2；完整运行与成果在 S3；T13 数据／契约检查在 S4，MVP 总体要求保留。
