# 实施边界

完整产品契约以 `../11-03-scenario-demo/run-isolation-design.md` v0.4 为准。本文件只记录实现组织。

当前缺口是已有独立编号与归档没有形成跨层强制边界；修改点必须位于接收去重、任务权限、作业调度、原生上下文和来源查询本身。

- 来源端：通知结构化携带 scenarioInstanceId；提供从完整持久记录核验通知的接口；内部查询使用固定的 x-axon-scenario-instance 头，不依赖模型选择。
- 宿主：对已确认来源／任务归属保存可核验元数据和结束写入门禁；导演切换复用原激活操作账本与回执，不绕过未完成工作检查、不伪造完成。
- 执行链路：事件、作业、任务、工具和连续分析继承确定归属；无绑定普通业务保持原语义。后台与前台原生历史仍由 Pi 管理。
- 不做：SIM-TASK-002 的无来源手动创建关联选择；不新增通用工作流或另一套聊天记录。

跨层约定：内部头 x-axon-scenario-instance；结构化字段 scenarioInstanceId，均不得从模型输入或消息文本推断。每层拒绝不一致引用。状态切换必须持久、幂等，并在明确终态后放行 B。

## 实际补齐的边界

- 宿主不保存另一份活动指针：从受认证来源同步，已有 pending 激活账本恢复门禁。来源不可用时启动失败，保持关闭，部署需先启动来源。
- 原生任务信息与工作详情工具也检查捕获的父归属，异步读取后复查；当前工作区、会话动态、工作列表共同过滤。
- 历史任务地图通过现有 taskId 授权继承归属，只读查固定历史；全局地图保留当前浏览。无归属父任务不回退读取场景事实，普通来源兼容；不改变手动创建入口。
- 连续分析配置保持原编辑版本，通过固定 execution 编号与版本展示/恢复当前失败处理，无业务席场景选择器。
- 操作先持久确认，再开放目标门禁；等待取消确认及真实终态共用15秒截止，未核清保留原请求。
- 未完成工作保留真实状态，任务及工作详情提供只读投影，禁止办理、导入和新建处理。
