## 需求

- 管理员集中维护平台、协议、端点、凭证引用、模型能力和启用状态；业务席位在会话选用平台－模型。
- 首批 Kimi 官方 coding 端点采用 Anthropic Messages，服务端环境 KIMI_API_KEY。凭证稍后提供，缺凭证不进入可用列表。容量与用途确认后才能启用。
- 兼容旧配置与历史 profile ID，默认会话和后台作业继续原 DeepSeek。无第二配置体系、无 Pi 升级、无自建 agent loop。
- Kimi 原生上下文，保留连接器必需指引；DS 重复指令仅明确已验证模型/端点/API。宿主请求快照、压缩、子任务、权限边界保持。

## 验收

- 管理员前端与 API 可管理，所有业务席位含旧 manage-model 授权不可管理，选模归属与忙态校验保持。
- 配置旧版读取、持久化/CAS/重启、凭证脱敏及端点绑定正确；同名模型跨平台独立。
- 两种真实 Pi 适配器的离线捕获覆盖 endpoint、messages、tools、thinking。Kimi 不生成 disabled 或重复 host_request_instructions。
- DS 例外范围、规则替换/清空/续轮/追加输入快照、压缩隔离、R4 指引及所有辅助调用正确。
- 类型检查、lint、针对性与完整回归通过；真实 Kimi 验收待 key，不能记为已通过。
