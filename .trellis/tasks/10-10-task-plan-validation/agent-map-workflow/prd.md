# 地图 Agent 工作流：读取依据与失败恢复修订

日期：2026-10-14。状态：**本修订已实施并完成原场景复测，保留模型质量问题。** 结果见 [恢复验证报告](recovery-validation.md)。

所属任务：`10-10-task-plan-validation`。上一阶段代码、设计和验收已提交为 `e9a01b4`。原 [验收报告](validation.md)、[审阅](review.md) 与 [来源标注验证](../agent-tool-improvements/validation.md) 保持原貌；历史报告中的“未提交”描述的是当时状态，不代表本次修订已经完成。

## 目标

让 Agent 在创建、编辑和导入来源标注时，从普通调用错误或真实冲突中准确恢复，消除“补读来源后忘了草稿、补读草稿后忘了来源”的循环，同时保留保存一致性和权限隔离。沿用已完成的领域 Skill、批量来源导入及结构化地图入口。

用户明确认可：程序已经知道的参数，尽量不要再要求模型填写，确定性工作优先交给代码。此原则不意味着保存时直接使用数据库最新版本，也不取消冲突检测。

## 保留的基线需求

R1～R7 继续作为回归边界；旧报告是旧实现结果，不是下列 RC 修订的验收证明。

| ID | 需求 | 可观察的验收 |
| --- | --- | --- |
| R1 | 模型不再填写本会话编辑的机械 expectedRevision；宿主维护有依据的写前条件 | 三个来源对象一次上图，无模型递增修订；用户在读取后保存改动会产生冲突，绝不自动覆盖 |
| R2 | 明确区分业务版本选择与机械校验 | 引用旧发布版、读取其他会话、比较版本不会改变当前编辑依据；发布指定保存版本仍需明确选择 |
| R3 | 同一业务批量导入有明确原子语义 | 一批最多 20 个来源对象，成功只产生一个草稿修订；任一对象缺几何、失权或来源过期，整批不写入 |
| R4 | 模型获得稳定、通用的地图概念与操作方法 | 指定已有图层时正确归属；明确新建图层时能创建；同名/多个候选能澄清；不把 source/draft 分组当作业务图层 |
| R5 | 常用地图入口由结构化结果生成 | 即使正文没有链接或写错 Markdown，成功读写仍提供有依据的地图入口；打开标注指向固定保存修订，不冒充当前外部来源是历史快照 |
| R6 | 兼容既有历史、隔离和 Pi 原生行为 | 旧会话可重开；Skill 扩展不改旧记录；请求结束/重启不恢复易失编辑依据；跨用户/席位/任务/会话不能继承写能力 |
| R7 | 验证可迁移的行为，不训练测试答案 | 改图层名、顺序、对象类型、指令措辞后仍评分；Skill 缺席/有 Skill 的对照保留相同底层工具；所有失败留存 |

## 本次需求与验收

| ID | 需求 | 可观察的验收 |
| --- | --- | --- |
| RC1 | 区分创建和修改；创建不强制预读 empty | 未调用 draft read 也能按明确基线创建；并发创建或绑定变化只允许正确的一方提交，不能覆盖或转成追加；创建回执建立新草稿依据 |
| RC2 | 按资源保留读取记录，普通失败不全量清空 | 参数错误后不用重读；缺草稿只补草稿，缺某个来源只补该来源；过期草稿不能静默使用最新 head |
| RC3 | 错误准确区分未读、过期及执行结果未知 | 已知缺项一次列全；来源冲突指明输入项/授权资源；明确未提交与未知不同，错误不泄露未授权内容 |
| RC4 | 批次暂停与依据生命周期分开 | 同输出第二次写失败后第三次不执行，第一次已提交保留；下一次推理可在修正参数后使用保留依据，不受全局 blocked 反复拒绝 |
| RC5 | 不可信工具结果不能建立新依据 | 后置钩子标错/改写读取结果时不提升该次观察，其他确认记录保留；已提交后钩子异常不谎称未保存 |
| RC6 | 生命周期处理按真实原因区分 | 同请求普通补充输入不抹除记录；新请求/重启、成功压缩后缺少原始读取上下文需重新读取；取消后无新写入 |
| RC7 | 结果不确定先核对原操作 | 查原回执后确认实际保存，重复结果不推进旧版本、不重复创建；未找到回执不能自动当成未执行 |
| RC8 | 固定场景复测不掩盖质量问题 | main-3 无草稿路径及措辞变体不再出现由全量清空导致的交替拒绝；实际几何、来源时间、图层、旧发布和隔离仍正确，所有普通模型错误另行如实统计 |

## 范围

包含：Pi 标注工具前置条件、请求内依据与批次暂停分离、服务创建条件和明确错误反馈、相关 hooks 生命周期、必要工具说明/Skill 文字同步、确定性与固定真实模型复测。

沿用但不扩建：批量来源复制、领域 Skill 目录与发现、结构化地图入口。当前修订不处理已有图层歧义、Skill 触发率、正文空间尺度及已保存字段误述的全部问题；相关旧失败仍单列，不能因恢复机制修好就宣布全面业务验收通过。

不包含：新 edit/write 工具拆分、整图覆盖入口、对象级自动合并、数据库新表、跨请求/持久状态缓存、第二份历史、通用 agent 编排器、MCP 迁移、工作交接改造、来源自动同步、GIS 计算、手机适配、线上部署。模型的任意正文事实正确性不作系统保证。

保持：底层 HTTP/AnnotationService 的显式 CAS、桌面手工编辑的起始修订、每会话独立草稿、发布与设为当前分离、现有授权与撤权检查。

## 决策与限制

- 自动机械状态仅在一个已认证请求内存在，不从旧聊天内容重建写入凭据。
- 新读取必须先进入模型推理；本执行链成功写入可立即推进机械条件，旧回执不能推进；看到版本摘要不等于读过对象内容。
- 同一输出允许普通草稿写入顺序执行并沿本链成功提交推进条件；发生失败、冲突或不确定后停止后续写入。外部 head 不能吸收；依赖实际结果的新决策等待下一次推理。
- 普通失败的批次暂停到下一次正常推理为止，不删除无关已读记录；结果不确定则需先核对原动作。补充用户文字不能提前解除批次暂停。
- 创建条件由服务检查，模型仍明确选择空白或固定基线；不把“取消 empty 预读”扩大为所有写入免读或任意创建时覆盖已有草稿。
- 第一阶段不把浏览器本地“当前绘制图层”自动当成模型选择。用户文字指定仍由 Agent 对照实际层结构解析；没有唯一目标时澄清。
- Skill 是方法说明，不拥有权限，也不承载实时图层、版本号、坐标和测试答案。
- 文件中的引用时间表达、任意历史外部来源读取、完整旧业务交接流程保持未覆盖。

用户已明确批准本次 [设计](design.md) 和 [实施清单](implement.md)，要求完成后用原场景复测并展示结果。当前不提交新实现、不部署；验收结果据实更新。
