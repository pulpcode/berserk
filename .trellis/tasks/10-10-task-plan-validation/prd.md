# 任务内综合研判与方案修订验证

日期：2026-10-10。状态：**已批准，实施与验证中。**

## 1. 目标

验证席位人员能否使用当前 Axon，结合任务目标、多条关联信息、外部资料和已有文件，形成方案，再依据后续变化修订并完成交接。

这是现有能力的应用验证阶段。交付可复现的测试材料、实际过程与结论，以及验证发现的必要修复；不预设必须增加产品功能。合成场景不定义后续真实业务的模型、职责或标准流程。

## 2. 当前基础

以已合并 UI 的 main `f40bf3a` 为核对基线：工作待办、工作总览、任务相关信息查询、外部资料查询、文件处理、分派与成果验收均已存在；席位职责也已进入普通对话的席位目录。详见 [现状依据](research/current-state.md)。

已有组件及分段测试不等于本次完整流程已通过；本阶段按下述流程验证，实际覆盖情况单独记录；用户已追加批准更新线上测试服务，保留旧数据并切换到独立验证数据。

## 3. 范围与验收

| 编号 | 要求 | 可观察的通过标准 |
| --- | --- | --- |
| V01 | 从合并后的界面完成办理 | 从工作待办进入收件、工作交接和待批准事项；刷新或返回仍定位正确对象，当前任务和会话不串位 |
| V02 | 结合多条信息和任务条件编制方案 | 方案使用道路、车辆两项资料和本任务约束；有实际读取依据，不遗漏车辆缺口，不把东区独立任务混入 |
| V03 | 用已有文件能力形成成果 | 读取交接初稿并生成普通 Markdown 文件，初稿不被覆盖；下载内容与工作区文件对应 |
| V04 | 在变化发生后进行有依据的修订 | 读取新的道路报告并与旧依据比较；明确道路条件变化而车辆缺口仍在；形成新文件并保留旧稿 |
| V05 | 通过已有交接完成协作 | 总体席分派、筹划席签收和提交、总体席退回、筹划席再次提交、总体席验收均有真实回执；两次提交副本可查 |
| V06 | 统一待办准确反映责任 | 提交后筹划席进入跟进、总体席待验收；退回后筹划席待办理；验收后工作已办。外部信息由本席位显式标记处理，不随 AI 答复或工作验收自动结清 |
| V07 | 权限与数据归属保持一致 | 席位只读获准信息；双方通过交接附件交换文件，不依赖共享工作目录；总体席总览权限不变成其他席位私有文件权限 |
| V08 | 结果可信且可复现 | 保存模型／配置版本、实际查询和交接记录、各版文件及失败情况；预期结果不注入 Agent 指令；人工纠正、重跑和最终通过分别记录 |

主验收只要求总体席、筹划席两个账号操作；情报席、态势席保留现有职责与投递设置，可补充检查收件和处理状态互相独立。

## 4. 本期不增加的机制

- 不新增 Run、方案版本库、业务状态机或审批引擎，继续复用 Pi、工作目录和现有交接记录。
- 不新增席位专属 Agent、固定办理 Skill、必经工具链或业务流程系统提示词。
- 不自动替用户修订文件、批准投递、验收成果或将信息标记已处理。
- 不引入路网、资源调度算法、真实外部系统和模型架构对比。

## 5. 修复范围

能够复现的既有契约错误，例如遗漏已授权资料、进入错误会话、附件未交接、状态展示不同步，可在本期定位并最小修复。模型漏读或判断不准须先核对实际上下文、工具返回与业务材料，不能直接归因于缺少提示词。

若验证表明必须增加产品能力、改变权限或工作流程，先提交缺口和方案供用户审阅，再确定是否建设。一次场景通过只证明该次流程可用，不代表稳定完成任意业务任务。
