# 本轮测试指南

本期是现有能力的应用验证，不定义后续真实业务流程。新版已在原 4315 入口运行；旧数据保留，本轮展示独立合成数据。

## 1. 登录与当前进度

打开 `http://127.0.0.1:4315/`，退出旧登录后重新登录。用总体席和筹划席两个账号，建议不同浏览器配置或无痕窗口，避免同一浏览器登录互相替换。

新账号凭据在本机被 Git 忽略的 `experiments/harness-lab/.local/task-plan-validation/accounts.json`：`overall` 对应 `seat-overall`，`planning` 对应 `seat-planning`。本轮不是原账号或原数据目录。

道路 E1、车辆 E2 已接入、分析成功并归口“西区补给方案”；固定情报席已收到，总体席有两条补充投递审批。恢复 E4 尚未发送。

## 2. 总体席批准并分派

1. 打开“工作待办”，核对道路、车辆两条补充投递建议；批准筹划席，态势席按建议保留即可。
2. 打开“西区补给方案”任务，新建对话。总体席工作区已有 `补给方案_初稿.md`。
3. 使用 @ 选择该初稿，并发送：

> 请将完善西区补给方案的工作分派给筹划席，附上这份初稿。请结合本任务相关信息完善，保留初稿，另存补给方案_v1.md，形成后提交我审阅。

核对分派确认卡确实包含初稿附件，再批准。没有附件时不要确认，保留现场供排查。

## 3. 筹划席编制第一稿

从工作待办进入所分派工作，签收、进入关联会话，发送：

> 请结合本任务的相关信息和交接初稿，编制供审阅的补给方案。写清依据、约束、建议及待确认事项；保留初稿，另存为补给方案_v1.md。

核对方案：有道路和车辆资料依据；09:40 落在 09:20–10:10 限制时段内；2 辆不足 3 辆；没有把东区任务混入，也没有编造已批准的备用路线或增援。

文件满意后要求提交并确认。总体席查看第一稿，**先不验收**。此时告知助手“第一稿已提交”，再发送恢复消息。

## 4. 恢复后修订

E4 实际接入后，总体席批准新的补充投递，再将第一稿退回：

> 有新的道路信息，请核对变化并更新方案。

筹划席回到原工作、原会话，发送：

> 请核对新的道路信息，与第一稿比较并更新方案。保留原文件，另存为补给方案_v2.md，写明变化依据和仍待确认的事项。

核对道路恢复依据来自报告修订 3、09:35 新观测；车辆仍为 2 辆，不能声称条件已全部满足。确认 v1 仍在后提交 v2，总体席审阅验收。

提交后应是筹划席跟进、总体席待验收；退回后筹划席待办理；验收后工作已办。信息是否已处理由各席单独操作，不应随方案验收自动结清。

## 5. 助手操作入口

服务器代码目录：`/home/ubuntu/axon-task-plan.XcoPwo/app`，试验数据目录：`/tmp/axon-plan-itaUFw`。使用服务器 Node 24。

```sh
npm run probe:task-plan -- send E4 --dir /tmp/axon-plan-itaUFw
npm run probe:task-plan -- evidence --dir /tmp/axon-plan-itaUFw
```

同一步发送会先查回执，重复命令不会故意创建新消息。不要 reset 当前 mock 或重新运行 `serve`：`serve` 每次新建试验，没有恢复旧试验功能。当前进程需保持运行，重启前先保存证据；原服务数据仍在旧发布目录，可按备份启动方式回退。
