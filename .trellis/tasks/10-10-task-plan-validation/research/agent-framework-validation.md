# Agent 与现有框架的端到端验证结果

日期：2026-10-13。状态：**验证已执行，发现问题，待审阅；不能宣布整体业务验收通过。**

## 1. 结论

三轮独立真实模型主流程均完成分派、查询、标注、文件保存、发布、提交、退回、修订及显式采用，共 24 次业务输入，未追加人工纠错提示。另执行指代不明和来源离线两次真实模型观察。

这证明操作链路可完成，不证明生成成果都正确。第一轮使用估算区域，第三轮写错来源时间，均未满足完整验收；第二轮核心业务目标达到，但存在判断、对象连续性和工具调用效率问题。三轮都保留原始结果，没有改提示词后重跑来替换失败。

框架机制方面，84 个不同的定向测试、12 个既有桌面浏览器用例通过，包级 typecheck、lint 通过。在已执行范围内未发现越权读写、跨会话改写草稿、固定历史覆盖或静默并发覆盖。这个结论不外推到未执行的异常变体或任意业务。

**本轮只新增验证脚本、材料、测试和记录，没有修改产品 `src/`、Pi 提示词或产品权限，没有部署线上服务。**

第一轮运行后补查了筹划席导入初稿的保全，以及工作区 v2 与提交固定副本一致性，均通过；该证据是事后只读补查，不声称首轮每个阶段已有自动断言。第二、三轮在相同材料和业务提示下加入这两项驱动断言，未改变模型指令或产品行为。各轮脚本 hash 不同据此解释。

三轮完成后，只修正驱动元数据及 README 中“其他任务未参与”的歧义说明，未重跑模型，未改写已保存的原始 baseline。最终工作区脚本 hash 因这项说明修正也会不同，实际执行版本仍以每轮证据为准。

## 4. 主要发现及下一步优先级

| 优先级 | 实际问题与证据 | 初步归类 | 后续最小改进方向（尚未实施） |
| --- | --- | --- | --- |
| P1 | 第一轮 S03 未查询已存在的区域，用估算 polygon 标注；v1/v2 均保留估算面 | Agent 依据选取 | 先完善查询和标注工具中关于来源对象、几何字段的使用说明，并以本样本验证能实际读取区域；缺位置时保留缺口，不补造坐标 |
| P1 | 第三轮将 `10:37:05.660Z` 写为 `10:37:05+08:00`；S06 同样错误，进入 `sourceRefs` 和说明文件 | Agent 证据时间改写 | 明确来源时间原值保留；区分业务生效时间、查询时间和显示时区，增加针对这类行为的验证 |
| P1 | 第二轮 S07 共 11 次参数校验错误，最后才正确携带 `payload.submissionId`；单步 17 次模型调用 | 工具使用及错误反馈可理解性 | 核对原生工具 schema/描述与错误返回，优先让当前动作的缺失字段可定位；不为此新增业务状态机 |
| P2 | 第一轮组合关键词查 0 后说“无任何情报支撑”，实际已有报告；离线专项重复 6 次失败来源查询 | 查询策略与发现性 | 明确无命中和来源不可用的含义，核对关键词匹配语义及必要回退；先用样本复测，不预设一套通用重试框架 |
| P2 | 第一轮总体席看不到筹划席后续私有授权，便断言其发布“越权”，实际 S04/S06 已明确授权 | Agent 越过可见证据作判断 | 区分“未看到授权证据”和“没有授权”；复核依据实际可见回执，不推断对方私有对话内容 |
| P2 | 第二轮把同一道路关闭→开放改成删除旧 ID、新建新 ID；又建议为“已采用”重新发布 | 对象和版本语义 | 保持对象身份，更新状态字段；发布时备注与任务 current 分开解释，减少无必要版本 |
| P2 | 错误历史缺口推断、将有效期止点当恢复事实、候选任务争用判断过于确定、地图占位链接 | Agent 表达及可用引用 | 分清事实/条件推断/待确认，使用工具实际返回的链接；按同场景核对文件及最终回复 |

第一轮估算面明确标为 estimated，并非伪称权威边界，但仍不符合本次必须使用已有几何的要求。第三轮时间字符串格式合法，框架接受它也不代表已核验其与来源证据相同；目前不能把它归为 API 返回错误。

第三轮西区转移任务是真实授权查询候选，使用同一资源引用；模型有“待确认”限定，但中间将潜在共用条件写成确定争用。应改进条件表达，不能将它误判为越权、东区污染或已证实冲突。

上述发现支持下一阶段先改善 **Agent 对现有工具和依据的可靠使用**，再用同材料复测。尚无证据要求改造成 MCP、增加标注审批、多账号共席或会话文件隔离机制。具体实现另行确认范围，本轮不顺带改产品。
