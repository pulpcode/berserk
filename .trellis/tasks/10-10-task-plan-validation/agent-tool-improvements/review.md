## 审查结果

当前未发现产品实现的阻断问题。核对的实际路径如下：

- `PiLab` 通过既有 `annotationTools` 注册新工具；委派角色和后台执行仍不获得标注写入工具。参数不包含用户、席位、任务、会话、坐标或查询时间；执行主体来自已接受请求。
- `AnnotationService.fromSource` 在查询前后检查原账号、会话、任务及来源范围。账号停用后同席位启用新账号不能替代原主体。取消、来源撤权、任务归档和查询期间草稿变化均不能继续提交。
- HTTP 查询在事务之外。查询结果要求唯一完整匹配、修订一致且有合法几何；保存复用原同步 apply、几何/容量检查、CAS 和事务，不新增表或第二份历史。
- 幂等摘要由规范化原输入生成，不包含每次变化的查询时间。同动作号同输入返回旧回执；不同输入冲突。并发同动作最终只保存一次；回执读取重新检查当前权限，Pi 回执工具还限制当前任务。
- 刷新保持标注 ID、名称、样式、说明、属性和其他来源引用；同来源引用必须唯一且类型兼容。旧固定修订、发布版本及另一会话草稿不变。说明/属性不随来源自动刷新，工具描述已明确。
- 新回执是普通原生 toolResult，`AnnotationReceipt` 只增加可选来源结果及动作类型。历史投影和聊天工具展示使用通用路径，不需要新增 custom record 解码器或数据库迁移。地图来源跳转仍来自既有查询证据，不将普通 sourceRefs 宣称为认证。
- provider schema 保持 object 根、严格字段和既有公开 Pi 工具调用机制；来源工具不要求模型传入坐标数组。未更改 Pi、工作确认或第三方校验行为。

### 第二轮仍有版本使用错误

模型在同一个输出里发出三个 add 调用，全部填 `expectedRevision:1`。Pi 按顺序执行，第一个区域保存后草稿已成为 r2，因此后两个调用正确返回 `ANNOTATION_CONFLICT`。模型随后读取 r2，再按 r2、r3 分别添加道路和车辆，最终成功。原始调用编号包括 `call_01_iPaNSWnPNeLV3PhUwREy4799` 和 `call_02_l8pSjcIU8LLVCVjcWG6n0172`。

这不是多人并行覆盖，也不是后台悄悄变化，是模型未把自己前一个写入会推进修订考虑进后续参数。CAS 起到了保护作用；“所有地图工具首次合法调用、无连续失败”不能因此判为通过。已有工具说明要求成功后使用新修订，后续改善应针对多次依赖写入的调用方式，不放宽 CAS。

### 第一轮正文地图链接有格式问题

第一轮 S01 将实际返回的 `/situation?...` 写成 `[西区](href=/situation?...)`，三个对象均如此。`src/web/situation/evidence.ts` 的 `parseMapHref` 要求以 `/situation?` 开头，因此这些链接不能被识别为有证据的地图打开动作。来源保存及查询证据正常，问题在模型正文生成；第二轮使用了正确格式。本轮不修改解析器容忍任意错误链接。
