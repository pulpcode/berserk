# Agent 工具与来源标注可靠性改进方案

日期：2026-10-14。状态：**地图范围已实现并完成固定批次验证，有剩余模型问题，待审阅结果。**

用户在审阅后明确排除工作交接工具改造，并授权先提交基线再实施。基线提交为 `ac50ba1`；本期仅改进来源查询、来源上图和标注修订。旧业务验收结论保持原样；不部署。

## 1. 目标

让 Agent 在现有框架中更稳定地查询正确对象，并准确复用来源几何及时间。复用来源时由系统复制坐标，减少用户逐个检查模型抄写结果的负担；自行设计的区域仍按用户意图审阅。

本期交付是有限场景内可靠性的改进与证据，不能承诺任意业务分析自动正确。

## 3. 本期需求与验收

| 编号 | 拟改进内容 | 可观察的验收结果 |
| --- | --- | --- |
| R1 查询可理解 | 在授权范围内说明可查对象类型、区域筛选与对象精确查询；明确组合筛选及关键词语义；区分未查询、无命中、缺几何和来源失败 | A1：同一测试资料可通过区域筛选找到实际区域对象，再精确读取；检索道路/车辆未返回区域不能被描述为区域不存在；单次关键词无命中不等于来源无报告 |
| R2 工作工具易用（本期排除） | 用户明确该问题独立于地图标绘，留待工作协同单独处理 | 本期不变更、不作为地图改进前置条件 |
| R3 来源标注 | 增加按来源对象创建或显式刷新本会话标注的能力，由宿主读取并保存几何及对应来源信息 | A3：实际保存的坐标、来源对象、版本和查询时间与该次宿主读取相符，模型不需传入坐标或查询时间；来源不完整、无权限或版本变化时不静默代填 |
| R4 意图及版本边界 | 复用来源与自定义标注分开表达；刷新同一来源对象保留标注 ID；来源变化不自动改写草稿 | A4：已有来源边界请求使用来源数据；明确自定义区域请求仍可走原绘制能力；含糊且影响含义时先询问；刷新不覆盖旧固定版本或他人草稿 |
| R5 时间及说明准确 | 原始证据时间保持原值；在工具说明中区分查询时间、来源快照时间、业务生效时间，说明文件注明其实际引用依据 | A5：最终文件及标注中没有 UTC/+08:00 原墙钟替换；新的读取时间不能冒充之前那次查询时间。来源导入只保证该操作所保存字段，不声称任意模型正文都获系统认证 |
| R6 实证复测 | 保留旧失败，分阶段验证，在相同模型和资料下完成独立重复及专项 | A6：3 次地图主场景无人工纠错完成，关键几何/时间/版本/权限准确；分别统计调用失败、恢复次数和业务语义，不以工具最终成功替代质量结论 |

权限、会话隔离、固定版本、CAS 和原工作确认规则是硬性回归项：任何越权或静默覆盖均不通过。框架必须准确拒绝输入错误；模型能否减少错误以实测为准，不用宽松校验换取“通过”。

地图工具首次合法调用率、重复错误、工具调用数和实际用量分别统计；业务语义单独评分，不把最终成功掩盖中间错误。

## 4. 范围与取舍

本期实施 R1、R3～R6，R2 排除，按 [实施顺序](implement.md) 分两段落地。技术方案见 [设计](design.md)。本次提案采用“复用现有查询和标注服务，按来源读取后保存快照”，无需新业务数据库或新审批流程。

本期保留：每会话独立草稿、跨会话授权只读引用、发布与采用独立、任务 × 席位普通文件共享、正文由模型编写、桌面浏览器三栏及窄面板适配。

本期不纳入：MCP 服务迁移、模型更换/训练、通用 GIS 空间分析、路线优化、截图多模态、长业务 Skill、模型记忆/恢复框架、来源自动同步、多人共席、手机端适配、普通文件自动版本化及新的标注审批。也不修改第三方 Pi/TypeBox 源码或放宽参数校验。

## 5. 风险与待审阅事项

- 更简单的工具可能降低错误率，但不能保证模型不再漏查或作无依据判断；必须保留人工审阅成果的入口。
- 工作交接工具保持现状，其已知错误不阻塞本期地图专项；不顺带修改确认和交接历史。
- 来源 current 接口没有任意历史几何读取能力；新操作采用“读取当前对象并比对期望修订”，不承诺直接导入已经过期且未保存的来源修订。
- 来源标注能保证它实际读取的字段；不能证明来源现实准确，也不能保证普通文件所有引用都由系统自动校验。
- 原任务“关注区域”有意图歧义。保留原三轮证据；本次复测使用明确复用/自定义的提示，不将其视作原措辞的同题重跑。
