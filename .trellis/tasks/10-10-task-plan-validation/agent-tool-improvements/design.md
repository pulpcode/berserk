# Agent 工具与来源标注改进设计

状态：待审阅。需求及事实以 [PRD](prd.md) 为准，本文不表示已实现。

## 1. 边界

继续使用 Pi 原生工具注册、调用校验、beforeToolCall/执行、原生历史及现有确认 UI。宿主沿用 ContextService、CollaborationService、AnnotationService，不增加 MCP、执行引擎、查询缓存表或授权账本。

模型决定“查谁、做什么、如何解释”；来源对象的几何与引用值由宿主确定性读取。操作仍绑定宿主已经认证的用户、席位、任务及会话。模型参数不提供 actor、权限或目标会话。

## 2. R1：让对象更容易被发现

优先补现有工具/字段描述，不自动在每轮注入全图、报告正文或坐标：

- 在授权来源目录中展示既有 objectTypes 和支持的查询方式，包括 area 对象。复用 ContextService.catalog，不新增跨来源目录库。
- 明确 task focus.areaIds 表示关注区域，可作 situation_query 的 areaIds 筛选；这与仅选择道路/车辆 objectRefs 不同。组合筛选取交集，查区域时不要无意继续带着道路/车辆对象限制。
- 用区域筛选结果中的完整 ref 精确读取，不在通用宿主中假定每个系统的 areaId 必然等于某个对象 ID，也不因有区域标签就承诺一定有边界几何。
- 明确当前模拟适配器的 query 是文本包含匹配，多词串并非自动分词搜索；无命中是本次查询结果。来源失败用实际错误表达，不包装为空列表。
- 几何和来源时间仍按需读取。只加入与实际接口有关的简短说明，不把本次西区用例答案写入系统提示。

## 3. R2：交接工具拆分，业务流程不变

建议给新模型请求提供四个用途单一的工具（名称为拟定）：

| 工具 | 模型参数概要 | 复用现有动作 |
| --- | --- | --- |
| work_item_assign | assigneeSeatId、title、goal、inputPaths | assign |
| work_item_claim | workItemId、expectedRevision | claim |
| work_item_submit | workItemId、expectedRevision、path | submit |
| work_item_review | workItemId、expectedRevision、submissionId、decision、reason? | review |

每个参数表采用严格的平铺对象，不再让模型同时面对四种 action/payload 结构。比如复核缺少 submissionId，原生校验只检查复核结构，没有其他分支占用错误列表。字段说明写明 workItemId/expectedRevision/latestSubmissionId 来自 work_item_read；不能猜测提交编号或静默替换旧提交。

宿主将已验证参数转成既有服务 DTO，保留原始工具名及参数到 Pi 历史。确认前 prepare 固定文件，确认与 toolCallId、原参数、operationId 和 grant 绑定；执行时消费同一授权并返回真实回执。后台及只读子会话仍无写工具。

本设计选择拆分而非全局增大错误数量：后者会增加其他分支噪声，不能针对验收动作定位问题。选择保留原生校验而非绕过它后自建一套解释器，符合当前 Pi 集成约定。工具数量增加带来的 schema 字节/token 与选择成本纳入复测，不先断言开销必然减少。

兼容事项：

- 新请求不同时注册旧 work_item_action 和四个新工具，避免重复入口；旧工具记录及更早 prepare/commit 记录保持可读。
- 更新确认/策略记录允许的工具名、历史重建、grant 消费及恢复检查；旧记录不能被改写为新调用或当成新授权重放。
- HTTP 页面 API、工作状态机和持久化业务 DTO 保持现状；前端需要的调整限于新工具的正常显示及已有确认卡识别。
- 发布时先排空在途调用；新工具历史写入后，不能假定旧二进制可读。保留停机备份，回退须使用经验证可读新历史的版本，或在明确数据恢复方案下操作。当前规划不执行发布。

主要影响位置：`src/contracts/collaboration.ts`、`src/pi/collaboration-tools.ts`、`src/pi/interactions.ts`、`src/pi/lab.ts` 及对应测试。确需更新浏览器 toolName 判别的位置由实现时全仓检索确定。

## 4. R3/R4：按来源生成或刷新标注

建议新增一个专用 Pi 工具 `annotation_from_source`，承接已有查询与标注服务。首次先用现有能力创建本会话草稿和图层；这个工具不隐式创建草稿或切换基线。

参数采用同一平铺结构：

```text
mode: add | refresh
sourceRef: { systemId, objectType, objectId }
expectedSourceRevision: 刚查询到的来源对象修订
expectedRevision: 已读取的本会话草稿修订
layerId: 本会话目标图层
objectId: 新标注 ID，或要刷新的现有标注 ID
```

不接受 geometry、queriedAt、用户/席位/任务/会话身份参数。名称、样式、说明等业务编辑继续使用原 annotation_action，避免把所有可选操作塞进新工具。

数据流：

1. 确认当前用户及会话、任务、草稿权限；若当前工具动作已有合法回执，按既有规则返回已提交结果，不重新查询来源后再写一次。
2. 以当前席位来源权限，对 sourceRef 做一次真实精确查询。预期修订必须匹配实际返回修订；找不到、不可用、缺几何、不支持的几何类型或修订改变，返回明确失败且无此次标注写入。
3. 从同一结果取 geometry、ref、revision、queriedAt。保持坐标与时间原值，不做估算、简化、时区文字改写；模型不负责抄写这些字段。
4. 查询完成后重新检查主体及来源权限；使用现有 AnnotationService 的 apply/CAS/容量/几何校验及事务保存。网络请求不放进 SQLite 事务。草稿已变化则拒绝，不自动改用最新修订重试。
5. 返回实际新修订、标注 ID、来源修订和本次查询时间；必要的属性及业务时间限量返回供后续解释，不默认返回整图几何。结果不确定时走现有标注回执查询。

保存策略：

- add：目标 ID 必须不存在，名称初始取来源对象名称，保存几何及其 sourceRefs；名称/样式随后可编辑。
- refresh：目标必须在指定图层，且已有匹配的来源对象引用；来源指向不同、含糊或几何类型与标注不兼容时拒绝自动改接。保留标注 ID、名称、样式、note 和 attributes；替换几何及该对象对应的来源修订/查询时间，其他来源引用保持不变。工具明确告诉模型业务说明和属性未自动改写，需按实际数据另行修订。
- refresh 表示用户要求重新采用该来源几何，即会替换该标注已被人工调整的几何；不作为后台同步，也不因地图刷新自动触发。只想更新说明时仍使用普通编辑。
- 创建与刷新均保存普通标注快照，复用现有版本/发布/采用体系。来源后续变化不回写快照；先前发布及别的会话不变。

该工具只承诺“刚读取到且修订匹配的数据”。来源在读取后再变化，不回滚已保存的正确快照，也不声称查询、外部来源和草稿构成跨系统原子事务。当前来源 API 无任意历史对象读取能力：期望旧修订已过期时返回冲突，由 Agent 重新评估，不用最新数据冒充旧版本。

复用 AnnotationService 的稳定动作 ID、所有权与回执。仅补一个异步查询到同步保存的协调函数，不增加数据库表、证据 token 仓库或通用工作流。来源访问范围及固定引用读取限制仍逐次检查，不能通过已保存引用恢复已撤销权限。

## 5. R4/R5：自定义区域与时间表达

“复用西区现有边界”走来源工具；“自行规划一个集合区域”沿用普通标绘工具。若对象或意图不清且会改变区域含义，先澄清。不得因为一次限定查询没返回边界就自行估算。自定义区域不必与来源几何相等，也不应自动标成现实边界。

sourceRefs 仍表示引用，不升级成宿主签名或可信证明。普通编辑仍可能修改几何和引用，因此不能只凭存在 sourceRefs 就宣称“全体标注已经过系统核验”；需要时核对具体操作回执和保存版本。

来源工具保存的是它自己执行的新查询时间，不能称作上一轮模型查询的时间。说明文件引用已保存标注时，应读取该固定修订的来源信息；另行查询时写清新的查询时间。保留原 UTC 字符串最直接；如需本地展示，必须正确换算且不覆盖原证据值。

本期不建设强制报告生成器或正文逐字段验证服务；通过字段说明及验收核对改善模型正文。若坐标/时间在来源工具中正确、正文仍反复错误，保留为独立未达标项，不用来源工具成功掩盖。

## 6. 暂缓的空间能力

点在面内、相交、距离、缓冲区应由确定性 GIS 工具计算，但本轮没有验证这些场景，故不提前加入。地图截图/视觉理解也不作为修复漏查和参数错误的前置条件。后续出现具体需求再规定单位、坐标系、边界规则及证据。
