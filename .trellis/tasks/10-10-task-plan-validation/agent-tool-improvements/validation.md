# 地图来源标注改进：实施与验证结果

日期：2026-10-14。基线提交：`ac50ba1`（保存改进前代码、旧验证报告与审阅方案）。本次实现尚未提交，未部署线上。

## 结论

确定性来源复制机制已实现并通过定向回归。真实模型三轮都完成来源上图、显式发布和同对象刷新，几何、保存时间、对象身份及固定发布全部正确。**不能判定整体场景全部验收通过**：两轮发生连续草稿修订冲突、自定义专项没有遵守指定图层，部分正文地图链接格式不正确。没有为了取得更好结果追加模型批次。

本期仅修改地图来源查询说明与标注能力，未拆分或改造工作分派、签收、提交、复核工具。

## 实际实现

- 新增 Pi 原生工具 `annotation_from_source`，只接受完整来源 ref、已查询来源修订、当前草稿修订、图层与对象 ID，以及 add/refresh 模式。坐标、查询时间、主体和目标会话由宿主控制。
- 宿主复用 ContextService 精确查询来源，核对修订后调用既有 AnnotationService apply/CAS/事务。网络之后重检原身份、权限和取消状态；旧草稿修订拒绝写入，不自动覆盖。
- add 使用来源名称和原几何；refresh 保留原标注 ID、名称、样式、说明、属性及其他来源引用，只替换几何和对应来源修订/查询时间。业务状态若需写入 note/attributes，仍须普通编辑，不能把 refresh 宣称为全部属性同步。
- 幂等键沿用原生请求/调用 ID，摘要使用原始规范化输入。历史回执读取不再次访问来源；没有新表、HTTP 动作分支、权限状态、MCP 或自定义 Pi 历史记录。
- 查询说明明确区域筛选与精确对象筛选的交集、文本包含匹配、区域标签与边界对象的区别，以及未命中、缺几何和来源故障的区别。完整几何仍按需读取。

## 验证条件与可比性

模型为已有配置 `deepseek / deepseek-flash`，直接从本机调用用户已授权的 `https://api.deepseek.com`。每轮新建合成账号、任务、来源实例和会话。驱动预建一个空草稿与 `discussion` 图层，模型仍需读取实际修订；**本批次没有验证模型从零创建草稿**。

主提示明确要求“现有区域、道路和车辆”“采用来源已有边界，不要另行估算”，不提供工具名、正确坐标或正确来源对象 ID。与旧完整业务测试相比，本次取消文件作业、交接，并明确了旧“关注区域”的歧义；车辆初值为 4，不是旧测试的 2。因此只能验证聚焦地图的能力，不能将 token、耗时或成功率差异当作同题 A/B 改进比例，更不能声称旧完整业务场景全部达标。

来源缺几何专项通过测试驱动仅删除本轮区域对象 HTTP 响应中的 geometry；原始响应与实际交给服务的响应均保留。离线使用既有模拟控制。歧义专项发现 ask_user 后由驱动记录并取消，没有自动回答或批准。没有生产任务、实际业务资料或凭据被写入 Git。

## 三轮主流程

| 项目 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
| --- | --- | --- | --- |
| 点/线/面几何与来源完全一致 | 通过 | 通过 | 通过 |
| 保存引用与来源工具实际查询时间一致 | 4/4 | 4/4 | 4/4 |
| 来源道路刷新保留标注 ID | 通过 | 通过 | 通过 |
| 来源变化不自动改草稿；旧发布/任务当前不变 | 通过 | 通过 | 通过 |
| 来源工具成功调用/总调用 | 4/4 | 4/6 | 4/6 |
| schema/格式校验错误 | 0 | 0 | 0 |
| 旧草稿修订冲突 | 0 | 2 | 2 |
| 全流程实际工具调用 | 15 | 15 | 15 |
| 三步请求合计耗时 | 23.101 秒 | 22.184 秒 | 25.590 秒 |
| 输入 token（不含 cacheRead） | 27,186 | 26,894 | 27,011 |
| 输出 token | 3,233 | 3,338 | 3,857 |
| cacheRead token | 184,192 | 168,960 | 167,936 |
| totalTokens（累计请求，含缓存读取） | 214,611 | 199,192 | 198,804 |

这些 token 是多次模型请求累计值，不是单次上下文窗口大小。第一轮首个实际请求有 22 个工具，紧凑 JSON 序列化工具定义共 30,401 UTF-8 字节，其中新增工具 2,359 字节；字节不是 token。没有自动注入全图，新增工具定义仍有固定上下文成本。

第 2、3 轮在同一次模型输出中给三个新增调用都填写 `expectedRevision=1`。即使宿主顺序执行，第一个成功后草稿变为 r2，后两个必须冲突。模型随后读取 r2，再使用成功回执的新修订完成添加。**顺序执行并不能自动修正预先生成的参数**；本次证明 CAS 防覆盖有效，也证明模型连续调用的易用性尚未达标。12 次成功来源操作均使用新工具；总计 16 次尝试中 4 次冲突，不能用最终成功抵消。

保存后的 sourceRefs 与对应来源工具回执逐项核对，12/12 匹配，未出现旧批次的“保留同一钟点只把 Z 改成 +08:00”。正文有时引用独立 situation_query 的时间，保存引用则使用稍后的 from_source 查询时间；需要按其语境区分。正文还出现“来源观测时间”列装载查询时间、effectiveAt 与 validTime 合写的术语不够精确，以及把来源属性写在版本对照中却未存进标注属性的表达风险；不是存储值错误，不能据此宣称正文完全可靠。

## 四个专项

| 专项 | 实际行为 | 判定 |
| --- | --- | --- |
| 明确自定义区域 | 普通标注工具保存给定闭合坐标，未伪造来源引用，也未发布；但创建了新图层，没有使用指定 discussion 层 | 几何正确，图层遵循未达标 |
| 来源区域存在但缺几何 | 精确查询与区域查询均确认缺 geometry，没有用点/线估算边界，草稿未变 | 核心行为通过 |
| 来源离线 | 实际返回 CONTEXT_UNAVAILABLE，正文明确区分查询失败和区域不存在，草稿未变 | 核心行为通过 |
| “那个集合点往东挪一点” | 读取两个集合点后调用 ask_user 澄清对象与位移；驱动记录后取消，草稿未变 | 澄清行为通过；未验证回答后的编辑 |

缺几何场景中的地图链接写成 `[名称](href="/situation?..." )` 的同类形式，第一轮也出现 `[名称](href=/situation?...)`；来源离线答复的任务链接只填任务 ID。链接展示有缺口，不能称为完整可点击引用验收通过。

## 自动化检查

- 类型检查、lint（含模块边界）与前端 build 通过；build 仍提示已有大 chunk，不因此扩展打包重构。
- 84 个服务、HTTP、Pi 原生历史和上下文/隔离用例通过；新增验证驱动 2 个用例通过，共 86 个唯一定向测试。
- 包含 24 个来源标注边界用例、1 个真实 Pi loop/关闭重开历史用例。覆盖无权限、查询后撤权、CAS、取消、归档、跨会话/任务、来源修订变化、缺几何、字段注入、幂等回执和刷新字段保留。
- localhost 监听在沙箱内出现 EPERM 后，仅为这两份测试开放本机执行并重跑，15/15 通过；不把环境错误包装为产品断言失败。
- 桌面地图回归初轮 13 项中 10 通过、3 超时。trace 显示冷启动导航及首次操作耗掉大部分 60 秒预算，finally 清理错误掩盖超时位置。保留首轮 trace，以单 worker 原阈值复跑失败 3 项，3/3 通过（30.8 秒）。因此共 13 个唯一桌面用例通过；首轮超时仍保留，不扩大超时阈值或修改产品。

## 证据与下一步

本地私有证据：`.local/source-annotations-e2e/2026-10-14/`，含七个独立 case 的 SSE、实际 provider JSON 正文（不含认证头）、源码 hash、来源原始/有效响应、保存快照、发布及指标。原始结果中的 pending_review 不改写；本报告与 [独立审阅](review.md) 是后续语义判读。

后续应集中解决三项已观察问题：批量来源添加时模型不能使用尚未收到的新修订、显式目标图层遵循、地图引用链接及时间术语表达。优先基于现有工具改善；若考虑有界批量接口，应先明确一次 CAS 与整体失败语义，不能静默替模型推进修订。不要因此重新引入工作交接改造或通用 GIS 引擎。

本次试改范围已实现，结果为“来源复制机制通过，模型场景有剩余缺口”，而非全面业务验收完成。完整旧业务流程、文件时间表达、回复澄清后的动作、模型调用期间来源修订突变均不在本批次真实模型覆盖结论中；后两者部分边界由确定性测试覆盖。
