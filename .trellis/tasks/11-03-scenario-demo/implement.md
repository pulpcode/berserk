## 1. 建议推进顺序

先冻结场景输入，再交付六个可单独验收的增量。每期都能展示实际成果；上期未通过的依赖不进入下一期。规模列只表示相对复杂度，不是日历工期承诺。

| 阶段 | 建设内容 | 可演示交付 | 依赖 | 相对规模 |
| --- | --- | --- | --- | --- |
| P0 · 场景定稿 | 确认五幕、地图选址、资源/时序、时间口径和演示角色 | 一份可核对的故事、有效期与完整输入清单 | 本计划审阅 | 小 |
| P1 · 背景世界与来源 | 将二十四车等落成数据和HTTP查询，建立隔离实例与统一场景时钟 | 在Axon查到全部资源、道路和报告，按场景时点判断并保留背景与未知 | P0 | 中 |
| P2 · 导演台与基础态势 | 按幕预览/手动推进、暂停、重演；地图呈现基础世界与时间用途 | 操作员推进一幕，时间与事实一并更新并进入现有接入链 | P1 | 中 |
| P3 · 研判、方案与批准 | 接续研判、方案版本/比较、共享方案读取、人员决定 | 看到A/B/C方向及依据，批准A；道路变化后要求复核 | P1；完整演示依赖P2 | 大 |
| P4 · 模拟执行与反馈 | 显式下达、占用与回执、逐车轨迹、受阻后修订 | 三车先到、四车绕行，保留决定与行动历史 | P2、P3 | 大 |
| P5 · 丰富任务综合页 | 在现有任务主页组合地图、事实、研判、方案和执行 | 一个任务入口可看懂当前阶段并追溯依据 | P3/P4读模型稳定 | 中 |
| P6 · 联调与演示验收 | 工程回归、固定模型批次、完整复演和操作说明 | 可重复演示的版本及真实验收记录 | P1—P5 | 中；模型问题可能增加工作 |

三个检查点：M1=P0—P2，数据可查、剧情可推进且场景时间口径一致；M2=P3，能够研判并批准固定方案；M3=P4/P5/P6，形成完整行动与反馈演示。

## 2. P0：冻结故事和数据口径

- [ ] 审阅story.md/world.md，确定二十四车、两项背景任务、十二次来源投放与主线七车需求。
- [ ] 选择地图区域，确定“真实底图承载合成业务数据”的位置、道路几何依据与署名；不沿用与故事不符的旧Orchard Road数据。
- [ ] 补齐全部资源、站点、水源、区域坐标，车型字段、路线/逐车模拟时序；对其他有据方案定义可接受分支，避免只有作者答案能运行。
- [ ] 固化已确认的导演席与四业务席分工、席位ID及独立场景授权；提案/批准/下达的业务矩阵在P3细化，导演不因控制剧情获得审批权。
- [ ] 冻结业务日期/时区、预设步骤时刻、各类事实有效期及来源状态责任；确认手动走时、暂停、重启和新轮初始时间的口径。
- [ ] 冻结场景版本、事实清单、作者侧预期和独立核对表；场景数据与模型可读内容分别列明。

验收：数量、身份、地理、时间和权限无自相矛盾；所有推断都可追到输入或明确标为假设。P0不产生产品代码。

## 3. P1：把背景世界落到可查询来源

- [ ] 将车辆、站点、道路、区域、水源及报告转换为版本化场景数据，关联真实稳定实体ID。
- [ ] 在现有模拟服务内增加新场景装载与隔离实例，不改旧场景事实；明确初始快照与后续变化。
- [ ] 在实例快照中持久化唯一businessNow、暂停状态和revision；同进程intel/situation读取同一快照，通过受配置限制的snapshotClock返回时间归属。
- [ ] 复用sourceResource/ContextService契约；补齐当前缺少的细分车型/位置/时效字段并验证兼容，不只用availableCount代替单体。
- [ ] 经真实HTTP接通报告和态势查询、分页、精确引用、资源筛选及授权；前台与后台各自使用获准范围。
- [ ] 资源有效期、关系/位置/数量依据实际按场景时点计算；补齐v4固定结果及旧历史/空间消费者兼容，跨来源/分页时间不一致明确失败，不静默回退真实时间。
- [ ] 工具正文和通知明确业务判断/投放时点、真实处理时间及旧观测时间；资源工具只校验和整理来源已声明状态，不因到期推断修复或新增调派资格。
- [ ] 区分T01临港现场关注范围和“从六站二十四车查找支援”的资源检索范围。显式提供后者的来源/区域范围；不能因用户可读某来源就自动把其中所有车辆认作任务资源。
- [ ] 为T01/T02/T03建立真实平台任务与业务编号映射，保留T02/T03已有占用，避免跨任务私有数据泄露。

验收：二十四车、六站、六路、八水源完整可查；17一般可用/5不可用/2待确认与原始事实一致；推荐之外的十七辆不会被查询接口偷偷删除。同一场景时点在不同真实日期下的资源判断一致，来源时间缺失/冲突明确失败，历史结果不随当前时钟重算。此期不下达行动。

主要代码区域：scripts/mock-context、src/contracts/context.ts/task-resources.ts/resource-results.ts、src/context、现有Pi资源/来源工具及历史/空间消费者。交付场景数据、时钟/装载配置说明和HTTP证据。

## 4. P2：导演台与基础地图

- [ ] 复用既有席位/账号及登录，补独立controlScenarios能力、指定directorSeatId和默认关闭的认证存储迁移；开通清单分别列出导演授权、来源read与任务准备所需既有公共任务管理权，不自动给旧账号授场景权。
- [ ] 在同一登录页提供导演席认证选项，登录后按权限进入独立导演页；四业务席保持原首页且无导演入口，直访显示无权，API分别处理未登录/无权。并行演示使用隔离会话，保留现有跨标签页身份变化检测。
- [ ] 新增独立“场景导演台”页面与条件导航，专门设计实例选择、下一幕预览、暂停/继续、投放与回执交互。复用useApi和现有接口基础，旧手工编辑页面仅用于旧实例，不新增独立部署的前端应用。
- [ ] 新场景定义/实例/预览/控制/操作记录均在服务端检查专用导演身份和独立能力；不沿用来源manage作为场景授权。旧模拟状态/编辑/发送及复用action路由按实例归属隔离，业务席不能旁路访问，记录实际操作者。
- [ ] 显示服务端场景时间；应用步骤时与业务事实、revision和待发通知原子提交。暂停/继续不自动走时，失败或重复操作不再次推进。
- [ ] 事实保存和通知发送继续分开，复用稳定操作ID、版本检查及接入去重；明确部分完成/结果未知如何核对。
- [ ] 十二次投放的E04按两条独立来源消息发送；显示发生/观测与接收时刻，旧消息可按设计晚到。
- [ ] “从头重演”创建新实例及任务映射，保留旧记录；批准与执行条件未达到时停在相应节点。
- [ ] 地图展示完整背景、位置、图标、来源时间、道路变化和图层筛选；复用地图引用和底图能力。
- [ ] 核验暂停、不同真实日期、重启、重演、推进中分页及旧消息晚到；捕获实际模型输入确认时间标签，不以确定性替身宣称真实模型语义通过。

验收：按幕推进确实修改来源并进入现有接收链；重复点击不重复通知或推进时间；刷新/重启不按现实经过时间推进；退出浏览器后服务状态可核对。时钟通过M1-A05/A06/A17—A20；导演席登录、入口、独立权限及旧接口隔离通过M1-A13/A21—A24，总体管理权不能越过隔离。基础地图不宣称资源已经出动。

主要代码区域：contracts/access.ts、AccessStore与认证存储/离线管理、Seats.tsx及导航/导演页面、场景配置、contracts/simulation.ts、context-routes、mock-context控制/持久化、SituationView/MapCanvas。P2可用预设人工操作验证，不依赖模型替操作员点击导演台；认证迁移、默认拒绝和现有业务权限回归列入本期检查。

## 5. P3：持续研判、候选方案与批准

- [ ] 为新场景配置既有持续分析与来源范围，验证首报、确认、资源清单和无关信息的处理；不重建Agent循环。
- [ ] 复用M1的场景时间说明，核验后台区分投放/观测/真实接收时间及固定历史；不把新接收时间当作当前业务时刻。
- [ ] 定义任务下最小方案版本/决定契约：资源、路段、时窗、有限条件、依据引用、版本/hash及状态。
- [ ] 形成方案比较与版本操作入口；前台Agent可生成候选内容，人员可编辑/提交/批准/退回，批准绑定明确版本。
- [ ] 建设“已显式共享方案”的受控只读投影；接入后台任务发现、条件研判、版本变更触发与发布时复核。
- [ ] 将R01变更关联到A方案依赖；明确条件核验与模型解释的职责，E09晚到不使旧事实覆盖新事实。
- [ ] 确定提案/批准/下达权限和变更期间的校验；继续复用HITL与回执原则，保留原工作交接用途。

验收：A/B/C方向可解释比较；批准确切版本；后台能引用读到的共享方案版本并发现A需要复核；R04等背景变化不被无依据当作T01风险。私有草稿不进入后台。此期批准不触发模拟车辆出动。

主要代码区域：新建的小型方案契约/服务/界面，AccessStore与TaskContext的必要引用，现有Pi工具、ContinuousService和任务发现。不能以“已有文件交接通过”替代本期方案实体和后台读取验收。

## 6. P4：模拟行动、轨迹与反馈

- [ ] 在模拟服务定义稳定命令ID、内容hash、当前约束核验、资源占用和查询回执接口。
- [ ] 增加Axon侧受控执行适配和必要的发送/核对记录，人员显式下达前核验已批准版本、有效条件及权限。
- [ ] 逐车生成有依据的接受、出发、途中、到场和受阻回报；回到来源查询/通知/研判链，不直接改写模型结论。
- [ ] 用执行记录驱动来源位置、历史轨迹、航向/更新时间及受阻显示；计划轨迹与实际模拟记录分开。
- [ ] 实现未完成安排的修订：原三车到场事实保留，跨站四车经新决定绕行，同一批车辆不重复占用。
- [ ] 覆盖拒绝/取消、占用冲突、版本过期、响应丢失、重启及重复请求；核对回执后再决定补发，不自动重放。

验收：先批准再显式下达才出动；不征用T02/T03车辆；A→B推荐路径时限可核对，已发生事实不回滚；09:40趋稳报告不自动等同事件结束。无批准或未支持分支时停在真实进度。

主要代码区域：模拟执行端及持久化、新业务命令适配、受控工具/人工入口、地图动态数据消费。内部决定与外部效果分别验证，不承诺跨HTTP分布式事务。

## 7. P5：在现有任务主页集中展示

- [ ] 扩展TaskHome入口，按任务汇集当前阶段/目标、地图、最新事实和研判、方案决定、执行反馈。
- [ ] 提供到原来报、固定研判、方案版本、审批记录、逐车回执及历史的入口，复用现有组件和权限查询。
- [ ] 阶段来自真实业务记录和显式演示节点；尚未建方案/尚未下达/来源离线时显示实际状态。
- [ ] 验证桌面宽窗、缩放、三栏和窄地图面板；刷新、切任务、返回和有新信息时保留草稿/焦点。

验收：观众从一个任务入口能回答“发生了什么、当前依据、为什么选这个方案、谁批准、执行到哪里、变化后改了什么”。页面浏览不发模型请求或业务动作，状态不另复制存储。

主要代码区域：TaskHome、共用地图、ContinuousAssessments、方案/执行展示及工作入口。P5可在P3/P4读接口冻结后并行准备，不提前编码尚未稳定的数据契约。

## 8. P6：联调、质量与交付

- [ ] 固定工程验证清单：真实HTTP取数、SQLite迁移与重开、native Pi工具链、HITL、来源权限、幂等和执行回执，以及受影响旧功能。
- [ ] 固定桌面流程：五幕主线、拒绝批准、重复发送、旧消息晚到、资源冲突、刷新/重启/重演；保留实际截图和回执。
- [ ] 在付费调用前提交固定模型/参数、数据hash、运行次数与费用/请求上限供审阅。建议3次完整主线、2次变化场景；失败不自动换模型/改答案/追加重跑。
- [ ] 独立核对关键语义：车辆/车型/数量与状态、来源时间、R01影响、背景无关性、批准版本、实际执行及完成边界。工程成功不代替解释正确。
- [ ] 产出演示操作说明、实例准备/重演方法、限制清单和验收报告；分别记录程序结果、真实模型结果与人工介入。

验收：批准批次中的主线与变化路径完成且关键事实/权限/执行无错误，支持回看来源；任一关键错误保留并阻止“演示已验收”结论，另开有界诊断。此批只证明场景演示准备程度，不宣称生产正确率或长期运行通过。

交付代码检查从包目录运行：npm run typecheck、npm run lint、npm test、npm run build；Playwright按受影响桌面套件运行，关键持久化/授权变更后补完整回归。具体新增测试与命令在所属子任务列明，不在本规划阶段运行空测试。

## 9. 依赖、任务与审阅安排

P1是数据依赖；P2与P3可在P1契约稳定后分别推进，完整联调时汇合；P4依赖P2/P3；P5依赖P3/P4读模型；P6汇总验收。

本task作为父规划记录。计划批准后，按P1—P6建立可独立验收的子任务，每个子任务记录所属需求/验收映射、实际依赖、精确接口/权限/迁移及验证命令，再进入实现。P0只做内容和数据口径定稿。无需一次创建六个未收敛实施任务。

当前可审阅：story.md、world.md、issues.md、prd.md、design.md与本文件。当前未授权内容：整套计划实施、付费模型批次、部署、合并；本轮只形成规划。

完整服务按管理域拆分、真实业务系统接入、复杂调度/火势模型另期安排。各阶段工作量在子任务拆解后估算，先用P1实际完成情况校准，不以本表相对规模承诺日期。
