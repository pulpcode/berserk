# 场景建设总体边界提案

版本：v0.7；2026-11-05；供阶段规划审阅。本文确定建议的组件责任与数据流，精确接口/表结构由对应实施子任务审阅，不表示已具备实现条件。

P0—P2的详细设计入口为milestone-1-design.md（2026-11-04，待审阅）。本文保留完整场景后续边界；第一里程碑不据此提前生成批准或车辆执行事实。

车辆执行过程、车辆移动、结构化方案卡和任务综合展示的已有能力、具体缺口与阶段归属，统一见[第一里程碑设计的现状表](milestone-1-design.md#当前实现与后续建设差距)。现有任务首页、地图、资源字段及工作交接是复用基础；后续阶段不将它们误写为全部缺失。

## 0. 本期范围收敛（2026-11-05）

[双系统来源与业务来报调整方案](external-systems-design.md) 为本期来源修正入口：沿用 intel / situation 及已有查询/隔离机制，只修正来源身份/显示名称和新版本来报中的控制信息。当前固定接入映射已经跨轮复用，不因来源名称不当重写注册机制。

用户明确将七类系统设计列为后续 SIM-DOMAIN-001，资料见 [后续候选设计](research/external-systems-domain-proposal.md)。本期不做七系统逻辑建设、管理域拆分、来源能力框架或对应提示词/Skill 改造。

本期双系统名称和新版本业务来报已按后续授权实施并通过本地回归；七类系统、接口/工具改造与线上配置未变。较早阶段的“本期”描述保留为规划背景，当前已实现的导演台及轮次隔离状态见 run-isolation-design.md 和发布记录。

## 1. 两侧系统与数据责任

| 组件 | 本期责任 | 复用基础/新增原因 |
| --- | --- | --- |
| 场景导演台（控制台） | 专用导演席在独立页面选择实例，预览变化，推进/暂停/继续，查询投放与执行情况 | 复用现有登录认证，新增独立场景控制能力与条件导航；四业务席不开放，旧模拟接口仅用于旧实例 |
| 模拟业务服务 | 统一维护实例场景时间、基础世界、来源报告、车辆动态、道路变化，以及P4增加的调派占用和执行回报 | 复用mock-context独立HTTP服务与持久化；本期各来源共享实例快照，后续按issue拆域 |
| Axon查询与后台 | 按授权读取实际接口返回及时间归属，按场景时点核对资源依据，接续研判并保存证据 | 复用ContextService、TaskResourceService、ContinuousService及Pi；不维护另一份时钟或来源业务状态 |
| 方案与决定模块 | 任务内候选版本、比较、人员决定、明确条件及受影响状态 | 聊天文件/WorkItem当前没有方案实体和可供后台读取的共享版本 |
| 模拟执行适配 | 核验已批准版本，显式发送指令，核对远端回执与执行事实 | 当前工作交接不产生车辆调派；需最小业务命令与回执能力 |
| 任务综合展示 | 按任务读取上述状态，提供既有业务操作入口 | 扩展TaskHome及共用地图/研判/待办，展示层不拥有另一个状态机 |

模拟服务经HTTP向Axon提供事实与通知，Axon经受控适配器向模拟服务发送人员已确认的执行请求。场景控制台只能调节合成来源和推进演示，不替Agent生成判断、不替人员批准。

### 登录、页面与席位隔离

用户已确认：在同一Axon登录页增加专用导演席账号（拟用seat-director），导演登录后进入/scenario-director并有导航入口；总体、情报、筹划、态势四个业务席保留原业务首页且不开放导演台。未登录进入既有认证流程；业务账号直访页面或控制API均无权，不能仅靠隐藏按钮。

拟新增独立席位能力controlScenarios，默认false，服务端同时校验当前账号属于配置指定的导演席。来源manage、任务管理、模型管理或旧simulationEnabled都不隐式授予该能力；新场景控制不要求把通用来源manage授给导演。导演核对数据所需来源read与任务准备所需既有公共任务管理权另行配置，后者仍为全部公共任务元数据范围，不能称为仅本轮授权。

新场景的列表/预览/控制/回执均限制导演访问；复用旧操作路由时按服务器确认的实例归属鉴权，旧编辑/状态接口不能旁路控制新场景。公共来源仍供业务席读取已生效事实，未来步骤/作者材料不进入公开前端包或业务上下文。控制记录保存实际操作者身份。

同一浏览器配置的标签页共享登录会话，导演与业务席同时演示使用独立浏览器配置或会话窗口；复用现有身份变化检测，不建设标签页多账号。完整登录流程与权限矩阵见[milestone-1-design.md第10节](milestone-1-design.md#10-权限与数据边界)。本轮仅补设计，不创建账号或执行授权。

## 2. 数据如何组织

### 来源侧

- 场景清单：版本、实例、业务时钟、区域、站点、车辆、道路、水源、报告和步骤。
- 车辆：复用现有resourceData的单体、身份、状态依据和位置含义；细分车型、来源更新时间及轨迹最小字段需在P1定稿。库存或列表数量不能替代单车身份。
- 事件：区分事实生效、观测、发布、模拟投放、真实接收及查询时间。既有接口字段保持原语义；需要模拟时间时单列，而非覆盖receivedAt/queriedAt。
- 本期仍可共用一个模拟服务/数据库；各事实注明所属业务责任，细分服务后续按SIM-DOMAIN-001演进。不把“综合态势”设为所有原始事实的唯一维护者。
- 明确可见来源身份、接口能力、通知入站来源及认证配置；浏览器和模型不能选择凭证或自行扩大范围。
- 现场关注区域与支援资源检索范围分开；六站车辆查询使用显式授权来源/范围，不为扩大统计而把所有可读对象自动关联到T01。后台继续使用其获准来源查询，不默认获得前台task_resource_query或私有标绘权限。

资源查询服务校验来源已声明状态的有效期、条件与冲突并整理结果，Agent工具只是其调用入口。检修、占用和执行事实由对应模拟业务责任维护；M1不新增综合出动资格规则引擎，不能由检修记录到期推断已修复，也不能把车况正常与未被占用合并成无依据的可调派结论。

### Axon侧

最小新增记录的需求是让决定和现实效果可定位，不增加第二套聊天/工具证据存储：

| 记录 | 最少需要的信息 | 必须新增的原因 |
| --- | --- | --- |
| 方案版本 | 所属任务、资源/路段身份、目标与时窗、条件、输入版本引用、内容hash、创建主体 | 需要固定比较/批准对象，文件名和聊天段落不足以表达依赖 |
| 人员决定 | 方案确切版本/hash、决定人/时间、同意或退回及理由 | 方案更新不能自动继承此前批准 |
| 执行请求与回执 | 任务/批准/方案版本、稳定命令ID、远端接受与否、当前核对状态 | 请求超时或重复提交时必须确认有没有产生占用与出动 |

实际SQLite表、迁移版本和API命名在P3/P4子任务定稿；保留既有业务库、Pi原生历史、文件归属及旧数据读取。新增记录不复制原生完整工具结果或私有对话。

## 3. 场景推进与时间

场景时钟纳入本期M1（P0—P2），由模拟服务中的场景控制后台维护并持久化，导演台仅提交操作。初始实例带稳定场景版本与输入清单；businessNow只随手动应用预设步骤前进，暂停/继续不会让它按真实秒数走时。再次从头演示创建新实例/新任务映射，恢复初始时间并保留旧轮记录，满足现有持久地图实例不允许原地reset的契约。

本期intel/situation读取同一实例时间与事实快照，经HTTP返回受配置限制的snapshotClock；时间和本步事实在同一事务提交。Axon固定本次资源查询的场景时点，各分页/来源不一致则明确失败，不用真实时间兜底。来源状态的有效期、数量与位置依据按该时点校验，场景资源结果用v4保留时间口径；历史v1—v3和普通来源维持原义。

Agent可见工具正文与页面分别标明“业务判断时点”和“实际查询/结果生成时间”，通知保留投放场景时间及原观测/发生时间。receivedAt、queriedAt、Axon结果createdAt、日志、登录和超时仍使用真实时钟，不修改全局Date.now或Pi历史；旧通知和固定查询不冒充当前时刻。详细责任、兼容与验收见[milestone-1-design.md第4节](milestone-1-design.md#4-业务时间与资源有效期)。

本期不部署独立时间服务或新增Agent时间工具。未来多个模拟服务的同步随SIM-DOMAIN-001细化；真实外部系统继续使用真实时间，不在本期混入场景统计。

一幕有“前置状态→将改变的事实→待发通知→回执核对”四部分。保存事实不会等同通知已接收或Agent已研判；同一实例/步骤保持稳定消息ID，遇到响应不明先查回执。恢复只接续未确认部分，不自动重复模型运行或业务动作。

故事09:18批准、09:22到场等是推荐路径下的模拟时刻；导演台在缺少人员决定或执行回执时停在该节点。操作员用多少真实分钟思考，不应让合成事件自行跳到成功。

E04定义为一次“报告组到达”的场景步骤，分别发送园区与无人机两份独立报告，各有消息ID。十二次导演投放至少产生十三条入站消息/来源记录，不能以一个ID装成同一份报告。逐车回执另计，不混入该十二次投放。

## 4. 方案、研判和审批

- 方案可以是前台私有草稿，也可以由人员显式提交为任务内共享版本。公共任务可见不自动公开私有草稿、文件或会话。
- 共享版本暴露必要的结构化摘要和依赖引用；后台服务按当前任务/来源/受众授权只读此版本，并记录读到的确切方案版本。
- 当前后台仅支持任务元数据与获准来源。因此P3必须补齐共享方案读取、版本变化触发、研判发布时版本复核；优先复用task_revision输入和既有批次机制，不增加后台循环。不通过复制全部方案进AGENTS.md或扩大私有标绘权限解决。
- 方案版本状态、有效性和执行状态分别表达。批准记录永远保留；依赖变化可使当前版本“需要复核/条件不成立”，不会改写原批准。
- 关键条件采用有限的结构化声明，例如路段开放、明确车型数量、资源占用与业务时窗，核验用确定性服务；AI的解释、风险和建议单独展示，不将模型自报置信度当作批准依据。
- E08导致R01依赖变更；E09只是一条更早观测，不能把R01当前状态改回开放。不同来源矛盾需保留，不按最新接收时间简单覆盖。
- 提案/批准/下达权限在四个业务席位内按业务职责细化，精确矩阵在P3审阅；专用导演席的场景控制权不授予这些业务权限。服务器核验，现有任务管理权也不自动等同模拟调派权。

## 5. 模拟执行与资源占用

人员批准方案只形成决定，不立即占用车辆。人员显式下达时重查权限、方案版本、时效和资源约束；模拟服务接收命令后，在自身事务内检查/记录该批车辆占用并返回稳定回执。

同一命令ID相同内容返回原回执，不同内容冲突；同车被其他行动占用时返回可解释冲突。Axon保存发送意图和核对信息，远端维护实际占用/出动事实，不宣称本地SQLite和HTTP外部效果属于可回滚的单一事务。超时、刷新和重启均不得直接重放下达请求。

整体进展可表达为“待下达→待核对回执→执行中”，并进入受阻、阶段完成、失败或取消；逐车保留出发、途中、到场事实及时间。状态名和合法转换在P4定稿，Agent运行完成、WorkItem验收和车辆到场不能互相代替。

主线修订时，V01/V03/V06已到场，继续保留；V07/V08/V11/V13的未完成安排由新批准版本替换，不重复占用七车。取消/修订针对尚未发生的动作，已发生的物理效果保留。场景只完成“支援到齐”这一阶段目标，火势趋稳仍作为后续报告。

## 6. 地图与综合页

复用现有一张地图、底图、图层树和专业标号。P2先呈现全部基础对象、来源时间与变化；P4再以执行回报驱动车辆位置、历史轨迹和朝向。平滑移动只插值已提供的模拟轨迹，不编造定位事实或真实路线计算。

任务总览聚合目标/当前阶段、最新事实、当前研判、方案/审批、执行与反馈，并提供地图及原记录入口。阶段从实际业务记录和显式演示节点计算，不从AI自然语言推断完成。P5只在数据契约稳定后接入展示，不另存一份流程状态。

## 7. 兼容、验证与回退

新增场景使用独立配置、账号范围和数据目录；旧场景协议保持可读，新增字段采用明确版本/兼容规则。需要变更主应用数据库时，停止备份与迁移重开验证纳入对应子任务。不得用旧版直接打开新schema作为回退。

复用现有源码测试和真实HTTP/Pi测试边界，分别验证工程契约、桌面流程和真实模型解释。现有模型语义不足作为风险保留，不能靠写死推荐方案或伪造后台判断达到演示成功。
