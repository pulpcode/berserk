# 地图工具契约与回答边界：收窄后的最小改进

2026-10-15修订。**待用户审阅，未批准实施。** 基线为 `d79a561`；本轮仅更新规划，不修改产品、运行模型、提交Git或部署。

## 目标与价值

补齐工具使用所需的通用契约，让回答既准确又完整；把新增范围标签视为待验证假设，避免为少量错误持续扩大接口。验证同时区分业务完成、解释正确、读取效率和边界覆盖。

## 已确认事实

- 上轮原45请求明确错误由4条降至2条，新增G02另有1条明确错误；操作保存、发布、采用和隔离正确。
- 范围错误发生时模型已收到实际query及计数说明；历史备注错配发生时正确历史仍在上下文。不能据此认定缺一个字段或一句prompt就是根因。
- G01/G03回答内容正确但采用了其他合法读取路径；原测试把业务目标和指定工具路径联系得过紧。G02的数据排列让错误全图分页碰巧返回正确页面对象。
- 现有结果投影、Pi content/details及固定地图入口已经可用，不需要新建解释状态或回执系统。证据见 [research.md](research.md)。

## 范围分级

| 级别 | 内容 | 承诺边界 |
| --- | --- | --- |
| 必做 M1 | 澄清基础摘要、可选fields、图层ID定位及版本元信息的含义 | 就近整理现有工具说明，不依赖Skill，不增加案例禁令 |
| 必做 M2 | 用一条通用规则要求事实有依据，同时保留必要分析、建议和不确定性 | 不以少答、拒答或漏答换取表面准确；不强制每次读回 |
| 必做 M3 | 修正评分方式，保留回归并加入新自然业务题、固定重复和完整性检查 | 业务路径合理即可；原场景、预留新题、受控诊断分开计分 |
| 候选 E1 | 模型读取结果增加query.scope | 只在隔离B构建做对照；默认产品A不增加scope，不预先承诺采用 |
| 暂缓 D1 | counts改名为changeCounts | 服务、模型、HTTP、取证消费者均继续使用counts；不建设双名称兼容分支 |

## 需求与验收

| ID | 需求 | 可观察验收标准 |
| --- | --- | --- |
| R1 | 工具契约清楚且通用 | 名称/类型等基础字段、fields缺省、图层筛选和分页含义准确；实际provider可见说明，无测试名称或答案注入 |
| R2 | 回答准确且完成用户目标 | 原范围扩大及历史备注错配如实复测；新增完整数量、版本差异、空字段和建议类问题不能漏答或无依据拒答 |
| R3 | 保持业务保护与接口稳定 | 服务/HTTP/原始回执、counts、固定入口、权限/隔离/CAS/幂等、来源复制及baseRef/current无回归 |
| R4 | 公平区分业务与诊断 | 原57请求保留首轮直接对照；关键只读、新题固定重复3次，受控解释单列；失败不替换，合法替代路径不误判 |
| R5 | scope必须有独立收益证据 | A/B仅scope有差异，在固定回归变体与预留新题中对照；无清楚收益或有完整性回归则不建议默认采用 |
| R6 | 防止对已知案例过度适配 | 新题及评分冻结后不用于修改产品提示/接口；重复次数预先确定，全量保留结果，不挑最好一次 |

## 不在范围内

不增加答案审核器、第二个模型、历史事实账本、强制全图读取/逐次读回、新工具/审批/MCP、UI卡片、运行时实验开关或持久迁移。不改手机端、业务权限或三栏布局。历史答复不重写。

## 关键取舍

- 必做A组完成后，即使scope没有收益也可以交付A组的独立结论；候选失败不自动扩大修复。
- 后续若用户批准完整方案，包含预定隔离A/B验证；不包含将scope默认启用或上线。实验后提供采用/不采用建议，等待审阅。
- 新H01–H03未参与此前修复，但本次题目公开供审阅，不宣称严格盲测。冻结后只用于验收；若后续按其失败调优，该批题转为回归，不再称未参与调优的新题。
- 原“每例一次”改为关键案例固定3次，目的是观察波动，不是失败后补跑。3次仍不足以证明普遍稳定或统计显著性。
- 详情见 [design.md](design.md)、[implement.md](implement.md)、[validation-cases.md](validation-cases.md)。当前没有阻塞规划的产品问题，下一阶段需用户明确批准。
