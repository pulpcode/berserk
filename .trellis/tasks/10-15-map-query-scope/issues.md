# 地图查询范围与回答一致性问题报告

2026-10-15 · **未解决，待审阅。** 本报告记录已观察到的问题，不批准新修复、追加模型实验或上线。

## 结论

工具成功返回并不保证 Agent 正确解释查询范围：它有时把局部结果扩大为整个版本的结论，也会把用户想要的筛选当成工具已经执行的筛选。更换为 deepseek-v4-pro 后，固定同输入对照仍复现这些实质错误，不能仅归因为 Flash 能力不足；也不能从两模型同错直接推导工具设计有错。

本轮对照是四份冻结输入 × 两模型 × 三次，共 24 次单步调用。除 model 外实际 provider 请求完全相同，均为 thinking disabled；无重试、无传输失败、无生成或执行工具调用。先匿名评阅并冻结，再解盲。两模型各有 5/12 次明确错误；Pro 的附加表述歧义较少，但未达到预设改善门槛。详情见 [模型对照报告](model-comparison/validation.md) 与 [逐项评分](model-comparison/results.json)。

## MAP-Q01：由局部读取推断整个版本不存在某对象

**状态：可重复复现；影响回答准确性，尚无本案例错误写入证据。**

- 用户目标：比较引用版本与本会话中“集合点甲”的备注。
- 模型证据：引用读取按 `objectIds: ["point-a"]` 选择甲，备注为“A 现场讨论”；本会话甲备注为“基线备注”。引用结果没有提供整版对象清单。
- 实际表现：六份回答都正确比较甲的备注，但 Flash 两次、Pro 两次额外断言引用版本不存在乙或只有甲。Pro run 18 原句：“引用版本中只有 point-a 这一个对象”。
- 预期表现：回答甲的备注差异；若说明乙，只能说乙不在此次引用读取范围内，不能声称不存在。用户未要求比较乙，不需要为额外扩展结论强行补查。
- 影响：用户可能据此误判版本内容或遗漏对象，即使主要比较表正确也不能判整段答案正确。
- 归因边界：实际选择条件及范围说明已在输入中，不能说完全缺少范围信息。观察到的是模型在附加解释中越过证据边界；表达显著性、历史干扰与模型推理弱点各占多少，尚未隔离证明。
- 证据：C1；Flash runs 01/10，Pro runs 09/18。Flash run 17 的“引用版本对象清单中无同名对象”另记歧义，没有算成确定错误。

## MAP-Q02：未执行图层筛选，却按图层范围解释分页

**状态：本轮两模型各 3/3 次复现；直接答错用户所问对象与数量。**

- 用户目标：查看“仓储设施”图层按保存顺序第 4～5 项。
- 已有历史调用：`annotation_read({mode:"draft",offset:3,limit:2})`，没有 `layerIds`。前一条助手文字却称准备读取仓储层对象。
- 实际回执：`query: {}`，返回全图第 4～5 项南仓、河畔仓；`total: 7` 属于全图，层列表包含维修、仓储两层。
- 实际表现：六次均把南仓、河畔仓当成仓储层第 4～5 项，并把全图 7 个对象说成仓储层数量；没有选择补查。
- 预期表现：发现请求范围与实际调用不符，利用已返回的 storage 图层 ID 补查该层 `offset:3,limit:2`，或用完整摘要正确筛选。当前输入尚未给出所需页，不能凭隐藏测试答案直接回答东仓、山脚仓。
- 影响：错误不是单纯转述冗余，而是核心查询目标未完成。返回对象恰好都属于仓储，也不能使全图序号变成层内序号。
- 归因边界：本轮从错误调用之后重放，测的是发现错误并恢复的能力，不能把原调用错误算作 Pro 自主生成。历史文字、返回对象层归属与隐含缺省范围可能共同诱导错误，但没有独立消融，不能认定单一根因。工具数据本身与实际参数一致，未观察到服务返回错误范围。
- 证据：C2；Flash runs 03/12/19，Pro runs 04/11/20。

## MAP-Q03：不必要的状态补充产生歧义

**状态：本批 Flash 有三处实质歧义，Pro 未观察到；不混入明确错误计数。**

| 样本 | 表述 | 风险 |
| --- | --- | --- |
| C1 / run 17 | 引用版本对象清单中无同名对象 | 可指已返回清单，也容易被理解为整版不存在 |
| C3 / run 05 | 这不是固定版本 | 可指 draft 与指定 ref 的读取方式区别，但读取结果仍对应固定修订 |
| C4 / run 23 | 非任务当前采用版本 | 可指数据入口区别；若解读为已核实未采用，则没有 current 查询证据 |

保留揭盲前的宽严两种解读，不因知道模型身份而改分。按排除上述歧义的严格口径，Flash 4/12、Pro 7/12 份回答符合；这不改变 MAP-Q02 全错、MAP-Q01 反复出现的结论。无需为减少歧义而要求每次额外查询任务当前状态。

## 已验证边界与尚未验证事项

- C3 受控诊断与 C4 正确查询后的主要问题，两模型均 3/3 答对；不能说它们完全不理解范围，也不能用受控诊断通过代替自主查询可靠性。
- 本批没有写入、发布、采用或权限操作；不用于证明这些机制正确或错误。上一阶段操作与隔离结果见 [原场景验收报告](validation.md)。
- 上一批时区有效期解释、当前状态附加误述、无必要澄清，以及 H01 任务/数据归属歧义，仍按原 [语义审阅](semantic-review.md) 保留；这四份重放没有覆盖它们，不能标记已修复。
- 既有 query.scope 候选未达到此前采用门槛，仍未进入默认产品。本轮换模型对照不能重新证明 scope 有效或无效。
- 本批是已知案例、每格三次、保留既有历史、非思考模式的单步诊断，不能给出总体可靠率或完整 Agent 性能排名。

## 后续处理边界与关闭标准

当前只记录，不继续加 prompt、不自动换模型、不新增宿主拒绝或答案审核器。若继续，应先审阅一个固定模型、固定案例的表达对照，检验呈现实际查询范围的变化是否有独立收益；不能按本次失败直接写案例禁令。

问题关闭至少需要同时证明：

1. 局部读取不再产生整版存在性/数量断言；分页范围不符时能正确补查，并完成用户所问内容。
2. 没有用漏答、无必要拒答或大量冗余读取换取表面准确。
3. 原失败案例作为回归保留，再用未参与调优的新场景检验迁移；次数、条件及评分在调用前固定，失败不替换。
4. 事实错误、表述歧义、有效补查、完整性与操作副作用分别评分；在批准的验收门槛满足前保持未解决。
