# 实施与验证计划

1. 确定镜像仓库、读写权限与部署网络。测量目标服务器拉取时间，确认首版平台与磁盘需求。
2. 增加发布流水线，构建一次并以同一镜像完成真实执行探针和发布。形成摘要与应用标签绑定，避免浮动标签进入正式部署。
3. 将部署预检改为按摘要检查、拉取和试运行。核对应用运行时所用摘要及已有 systemd 单元的升级路径。
4. 更新部署手册，覆盖凭据准备、版本检出、自动拉取、错误排查和回退。
5. 自动化覆盖缓存命中、首次拉取、拉取失败及关闭沙盒。使用独立 Ubuntu 实例验证真实分发、运行、切换和回退，完成后清理验收资源。

## 实施进度

- 已增加手动触发的 GHCR 发布工作流，以及正式部署和服务启动共用的摘要绑定读取。旧 systemd 单元格式继续适用。
- 已更新部署人员操作和发布方首发步骤。实际发布摘要由首次工作流运行提供，并随应用发布提交一起入库。
- Node 24 类型检查、lint、工作流 YAML 与 Bash 语法检查通过。席位、登录和镜像预检相关 14 项测试通过。首次公开发布、腾讯云匿名冷拉取和真实端到端回退待验收。
