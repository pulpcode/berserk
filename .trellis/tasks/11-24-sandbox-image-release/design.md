# 沙盒镜像发布与部署方案

## 镜像存放

采用公开 GitHub Container Registry 包 `ghcr.io/pulpcode/berserk-file-runtime`，关联应用仓库。GitHub Actions 构建作业持有包写权限，包首次发布后由管理员设置为公开，部署主机匿名拉取。镜像仓库地址、应用发布标签和 SHA256 摘要可进入 Git，镜像层与凭据分别留在镜像仓库和各部署环境。仓库地址选定前，从真实部署网络验证匿名整镜像拉取及重复拉取。

## 与应用版本绑定

在仓库根目录增加 `release/sandbox-image.json`，作为拟议的版本绑定文件。每个应用发布 Git 标签指向含该文件的应用提交。文件记录完整的镜像地址、不可变摘要和目标平台。示例值如下。

```json
{
  "image": "ghcr.io/pulpcode/berserk-file-runtime@sha256:<真实摘要>",
  "platform": "linux/amd64"
}
```

发布方先对候选提交构建并运行真实执行探针，将同一验证产物推送镜像仓库，取仓库返回的摘要。将摘要写入绑定文件后，验证最终发布提交的沙盒相关输入与被验收候选一致，再打应用发布标签。同一镜像可由多个应用版本引用，沙盒镜像变更时更新至新摘要。镜像仓库保留现役和回退版本引用的摘要，便于重启及回退。

## 部署人员操作

以下命令适用于方案上线后的正式发布，继续使用现有的实例目录和来源配置。部署人员以 Axon 运行账号执行。

1. 按现有操作手册安装 Docker、Node.js 24，准备目标实例的私有配置和演练来源。公开镜像可直接拉取。私有源码仓库的 Git 访问方式照旧。
2. 从 GitHub 克隆仓库并检出批准部署的应用标签，再执行一键部署。

```bash
git clone git@github.com:pulpcode/berserk.git
cd berserk
# vX.Y.Z 替换为批准部署的实际 Git 标签
git checkout --detach vX.Y.Z
./deploy.sh --preset scenario \
  --data-dir /home/ubuntu/axon/4316/data \
  --config-dir /etc/axon/4316 \
  --service axon-4316.service
```

3. 脚本从本次发布提交读取绑定文件，检查宿主平台和 Docker。按完整摘要查找本地镜像，缺失则自动拉取，随后试运行。失败时显示镜像地址和具体失败阶段，在写库、停服或切换前退出。正式路径中的显式关闭开关继续生效。
4. 预检和运行时共用同一镜像引用。预检与服务入口读取已检出发布目录中的同一绑定文件。systemd 跟随 `current` 选择对应发布版本，沿用原有单元。正式预设由发布绑定文件控制镜像，若实例 `LAB_EXECUTION_IMAGE` 与之冲突，报出配置项并停止，开发构建继续使用当前配置方式。
5. 验收健康接口、登录入口及一次沙盒文件读写。升级检出新的应用标签再部署。回退时切回原发布目录，让应用与沙盒摘要一同回退，数据库处理仍按现行部署规范。

首台主机会下载镜像层。本地已有同一摘要时直接复用，部署主机可省去基础镜像构建、apt 和 pip 安装。
