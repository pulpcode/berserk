## 2. 三项产品侧修复

### A. 明确目标后操作，必要时简短澄清

**问题**：C02两次将泛称“消防车”直接画成水罐车，并附加“默认/最通用”的无依据说明。只写“消防车先问车型”容易局限于这道题；只写“业务含义不明确时消歧”又缺少可执行的判断。本项覆盖对象、类型和目标图层的选择，车型作为已发现问题的回归案例。

**拟写入 Skill 的判断步骤**（待审文字，尚未修改 Skill）：

1. **先找明确依据。** 使用当前请求中的对象引用、具体名称和前文已确认且仍适用的选择；目录中能唯一匹配的明确别名也可使用。名称若对应多个对象，不能据此任取一个。已有依据足以确定目标时直接继续，不重复询问。
2. **对象、类型或目标图层仍不明确时，先核对，再简短询问。** 能通过读取数据确定，就只读必要内容；读取后仍有多个合理候选，就用候选名称问一个必要问题。缺少选择依据时，不凭“默认”“最通用”补出具体类型，不先写入占位对象。读取没有匹配时如实说明，不编造候选。用户明确允许任选时，可以在授权范围内选择并说明，不再要求用户选一次。
3. **仅缺显示细节时，按已有规则处理。** 新增对象可用规定的默认尺寸；编辑已有对象保留未要求修改的值。显示默认值不能替代对象类型、业务属性或信息角色的选择，也不能补写未确认的现实事实。

上述步骤只解决选择依据；已有固定引用、当前草稿读取、权限及CAS要求仍照常执行，不因确定了目标而跳过写入依据。

**行为例子**：

| 请求与上下文 | 预期行为 |
| --- | --- |
| “放一辆消防车”，此前未确认类型 | 询问“水罐车、泡沫车，还是其他车型？”；用户明确后创建一个对象 |
| 前文已确认水罐车，紧接着说“同样的再放一辆消防车” | 沿用已确认类型，不重复询问 |
| “把这艘船转向东”，附带唯一对象引用 | 核对当前可写对象后修改，不因地图上还有其他船就询问；没有引用且存在多个候选时才需消歧 |
| “放一辆水罐车”，未指定尺寸；或“任意选一种消防车做示意” | 前者使用默认尺寸；后者在允许的类型中选择并说明，不擅自扩大“任选”的范围 |
| “放到部署图层”，读取后发现两个同名图层，前文未指定 | 用可区分的图层信息询问目标，不默认选择第一个；已有明确layerId则直接使用 |

**工具说明与 Skill 的分工**：工具说明放简短、与该工具有关的选择约束；Skill 放以上步骤及正反例。继续使用唯一共享目录，不维护第二套车型映射，不增加宿主侧意图判定流程。标准/扩展说明限定为本系统目录和已核实条款，不能由“应用扩展”推导“所有标准中都不存在该符号”。

**验收重点**：同时检查“该问时是否问”和“已有明确依据时是否多问”。不把询问次数增加当作修复成功，也不要求所有操作都先澄清。

### B. 逐项完成用户明确要求的修改

**问题**：C10-1保存了指定范围，却漏掉明确要求的 `informationRole=plan`，还要求用户再次确认。要修复的是“只完成部分要求便停止，并对已明确的剩余要求重复询问”，不将某个属性值单独写成通用操作规则。

**拟写入 Skill 的通用规则**（待审文字，尚未修改 Skill）：

> 逐项完成用户明确要求的修改。一次保存成功，不代表所有要求都已完成；对已经明确提出、且现有工具能够完成的要求，应继续执行，不再重复询问。

这条规则在现有权限、读取依据和异常恢复机制内执行。遇到新的歧义、冲突、权限不足或保存结果不确定，仍按既有规则处理，不能以“完成全部要求”为由跳过核对、重发不确定操作或扩大用户授权。

**已核实的能力边界**：`annotation_from_analysis` 接收固定结果引用、目标图层、新对象ID和名称，不接收信息性质、样式或备注；`annotation_action` 的 `update_object` 可以修改这些字段。C10-2已用“保存范围＋修改同一对象属性”完成这部分要求，证明现有能力可组合使用，不证明补充提示后能稳定改善。人工新建表单默认选择拟定方案，而Agent保存分析几何不自动填写；这属于入口差异，不能据此把全部新对象默认设为plan。

**拟改动**：

- **工具说明交代能力边界与衔接方式。** 明确当前保存工具实际携带哪些字段；用户要求的其他属性可由现有编辑工具继续完成，不以“拟定方案”作为专门触发条件。
- **Skill 按请求核对完成情况。** 将用户明确要求的名称、图层、备注、信息性质等，与实际成功提交的内容逐项核对；这些只是字段例子，未要求的字段不擅自补齐。不新增持久清单或宿主调度流程。
- **同一对象继续修改。** 需要后续编辑时使用本次真实保存的对象身份，保留其他字段；改样式等整体替换字段时遵守完整读取和保留要求，不为补一个属性重新创建对象或重算几何。
- **据实报告结果。** 回执和提交内容足够时不机械重读；不足时只补读相关字段。剩余步骤无法完成时说明已完成和未完成部分，不把“保存成功”说成“所有要求均已完成”。

**行为例子**：

| 明确请求 | 预期行为 |
| --- | --- |
| 保存刚才范围到派生层，命名“临时范围”，标为拟定方案 | 沿用固定几何创建一个对象，设置正确名称、图层及信息性质；必要时用已有工具分两步完成，不再询问是否需要方案属性 |
| 保存刚才范围到派生层，并添加备注“待现场核实” | 保存后在同一对象上落实备注，不遗漏、不重复创建；不能只对plan属性检查完整性 |
| 将引用对象改名，并把图标尺寸调为56 | 两项明确修改都落实，保留其他样式和属性；不因改名成功就停止 |
| 只要求保存范围，未指定其他属性 | 按明确要求保存，不为“完整”而擅自补plan、备注或其他业务内容 |

**回归例子中的概念**：草稿是当前会话中可继续编辑的标绘工作版本，保存成功后已写入系统；“拟定方案”是对象的信息性质，表达计划如何部署或处置。C10-1的问题是已保存对象遗漏一个明确属性，不是整个范围未保存，也不是所有草稿都必须属于方案。

**待验证的假设**：明确工具能力边界并加入通用完成检查，可能减少遗漏和重复询问。效果必须通过真实复测确认；不能因提示文字已修改或原题一次通过，就认定修复有效。

### C. 证据表述：回答前核对每项结论的依据

**问题**：核心操作或计算正确后，额外说明仍可能扩大查询范围、补出不准确数值，或把名称、某个属性当成另一项结论的证明。现有工具说明和 Skill 已包含范围、数值及事实依据要求，不能直接归因于“少了一句提示词”。本项精简并明确核对步骤，不逐题追加禁令；具体失败案例及相邻反例放在第5节回归测试设计中。

**拟写入 Skill 的通用规则**（待审文字，尚未修改 Skill）：

> 回答前，核对每项结论是否有依据。查了哪些对象，就在这个范围内回答；数值和状态按实际取得的信息说明。
> 工具没有给出的结论，只有在已有信息足够、推导正确时才能补充；不能因为对象名称、图标或某个属性，就认定另一件事。
> 用户需要的结论缺少依据时，补充必要查询或计算；暂时无法确定就说明。与问题无关的细节不必添加。

**工具说明保留的规则**：

- **数量与分页范围。** `objects.total` 是本次筛选后、分页前的对象数量；`hasMore` 只反映同一筛选范围的后续页。读完一个过滤范围不等于读完整图，读到末页也不证明此前各页已读。对象、图层和全图的数量陈述须对应实际范围。
- **字段与版本。** 未请求字段不等于字段为空；固定结果对应原读取或计算版本，不自动代表最新状态。沿用现有字段选择和固定结果规则，不为回答简单问题强制读取整图或全部字段。
- **空间关系与计算含义。** 本工具的 `contains` 包含边界；对点的命中结果不能单独区分内部与边界，`classify_points` 才直接返回这类分类。保留各计算方法的输入条件、单位、精度及结果字段含义，不把某次失败题中的错误推理写成新增工具能力约束。

**Skill 的执行边界**：

- 复用仍适用的用户明确提供的信息、实际读取、计算和操作回执；回答保留其来源、范围和时间含义，不能把用户描述、旧结果或模型推断说成本次查询已核实的事实。
- 需要补充数值或判断时，先核对已有输入和方法是否足够。允许正确的单位换算、汇总或可复核推导，数值精度须与方法相符；不要求每句话都调用工具，也不把“未调用测距”本身判为错误。缺少必要依据时只补查相关对象、字段或计算。
- 同时核对结论和解释是否成立；结果正确不代表附加的因果说明正确。必要推断应明确依据和限制，不能仅加“可能”“大概”就替代依据。用户明确要求的结论仍须完成或说明缺口，不能靠少回答回避错误。

**待验证的假设**：精简现有说明并明确核对步骤，可能减少无依据的附加表述，但效果需由真实复测确认。工具说明负责解释实际能力与返回值，Skill 负责如何据此回答；不新增宿主事实判定流程或固定答复模板，也不把原题一次通过当作具备跨场景能力。

3. **保留历史**：不修改已冻结的 `evaluation/` 与本次原始轨迹来重写旧成绩；获准实施后建立有明确版本的新测评驱动，冻结旧依赖或保存完整历史快照，核对旧冻结证据可追溯。
4. **保护边界不变**：预算、一次性批次、模型漂移、关键效果错误停止和证据保存机制继续生效；不借修结束语放宽权限、删除失败样本或自动补跑。

以下仅为待批准的测试设计，尚未修改测试代码或发起模型调用。具体案例用于检查通用规则，不将题目名称、固定数值或专门纠错句写入产品提示。

| 已发现的案例 | 回归检查与相邻反例 |
