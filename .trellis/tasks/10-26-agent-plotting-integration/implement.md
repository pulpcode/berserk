## 2. 实现拆分与检查

1. **共享契约说明：**生成 symbolId 的受控描述；补充 style/attributes 整体替换语义及操作 Skill。确认当前目录全部 22 项仍唯一、标准/扩展标记正确，没有新增工具种类或复制目录。
2. **编辑与引用：**读取到的版本与对象成对；生成最小字段变化；保留缺省值；未保存时提示和引用离页保护。
3. **冲突核对：**实现有限字段比较及按需展开的核对区；不同字段确认合并、同字段逐项选择、删除/只读停止、二次冲突重新核对；未知回执使用原路径。
4. **确定性回归：**使用真实服务、真实工具及受控模型流验证状态变化；浏览器使用本地瓦片、独立测试数据和端口，不写现有试用数据。
5. **冻结与真实验收：**离线检查通过后记录源代码、Skill、参数、题干、夹具和评分规则的哈希，再执行已批准的批次。

实现和质量复核按项目 Trellis 流程分别执行；本轮已按批准方案派发实施及独立复核。预期生产改动文件见 design.md 第6节，新增纯差异模块与冲突视图以最小必要范围为准。

## 3. 必须覆盖的工程行为

| 领域 | 必须验证的结果 |
| --- | --- |
| 标号和字段 | 全目录受控；方向/直立规则；仅改方向、尺寸、标签、名称、角色、一个业务键时其他字段及缺省状态完全保留；清除 heading 和删除属性不被忽略 |
| 引用和身份 | 固定引用不能冒充已读；同名/同 ID 跨 set 不误改；未保存预览不能成为有效固定引用；全屏引用不丢本地输入 |
| 版本与比较 | binding/内容乱序和失败不产生混合编辑依据；目标未变、不同字段、同字段同值、同字段异值、不同 attribute 键、geometry 整体变化、二次冲突各有真实断言 |
| 异常和恢复 | 删除对象/图层、只读变化、保存响应丢失、原回执回查、未找到回执、普通校验失败，均不自动重发、不静默清空或覆盖输入 |
| UI 连续性 | 地图实例/相机保持；浮动面板高度受限、核对内容可滚动、保存取消可见；宽、窄、矮桌面窗口；旋转和普通点线面编辑回归 |

验证 HTTP 持久状态和实际回执，不能只看按钮提示。保存冲突用第二个真实 service/API 操作产生新修订；网络/刷新失败按既有浏览器机制注入并保留证据。无网络模型的受控 Pi 测试只证明程序边界，不计真实模型正确率。

## 4. 真实模型测评建议

### 4.1 配置和样本

建议使用 R13 E0 的模型配置：请求 `deepseek-v4.1-flash`，响应版本核对 `deepseek-v4-1-flash-261017`，关闭推理、无 reasoning_effort，max_tokens=32768、top_p=1、不传 temperature。只在隔离验收实例固定配置，不改本地产品设置，不与 R14 比较组混用。若执行时版本不再可用，先审阅替代配置，不能悄悄换模型。

保留原生按需 Skill 加载，不预加载或强迫指定工具序列。每次记录实际送达的工具 schema、Skill 正文读取与实际参数；Skill 读取率不是通过标准。

**10 道新整合任务＋5 道既有空间回归，每题独立执行 2 次，共 30 个完整任务槽位。** 重复不是新增独立题目。每项使用全新合成账号/会话/数据，固定同一业务日期；几何、字段与权限可复核，正确答案单独存放，不进入模型上下文。

新任务建议如下，正式用户文本与初态在驱动实施后按本表冻结，不增加要求或暗含答案：

| ID | 初态与用户任务 | 主要判定 |
| --- | --- | --- |
| C01 | 空的既定部署层；要求在明确给定的三个坐标分别放置救护车、冲锋舟、消防艇，均为方案 | 正确区分三个目录项和标准/扩展，坐标与信息性质正确，仅写指定层 |
| C02 | 有明确位置和图层；要求放一个“消防车”图标；对合理车型澄清预定回答“水罐消防车” | 不猜具体车型；澄清后正确创建一个对象；澄清前不先建错对象 |
| C03 | 引用已保存的冲锋舟，heading=45、iconSize=48，含标签、颜色、备注、属性和来源引用；要求“朝东，其他不变” | heading=90，其他字段及身份完全保留；图标和地图显示一致 |
| C04 | 引用一个历史普通点，原来缺少 role/heading/style 的可选字段；只要求改名 | 只改名，不补角色、方向或默认样式 |
| C05 | 引用固定直立的消防无人机标号；要求旋转到90° | 说明该符号不支持旋转，不写非法 heading、不自动换成别的图标 |
| C06 | 已保存资源点含 unit、count、confirmed、unknown:null 等属性；只要求添加 contact | 只增加明确值，原属性、style、角色、几何和来源不丢失；不把 null 变成缺失或零 |
| C07 | 当前草稿与其他参考版有同名对象或相同短 ID；引用当前草稿中的一个对象，要求修改尺寸 | 根据完整引用命中正确对象，其他 set/对象不变；固定引用后仍取得当前写入依据 |
| C08 | Agent 读完目标后，驱动用实际服务把其方向和备注改为新值；用户原要求改方向 | 原写入被 CAS 拒绝；重读后核对同字段变化；若询问，按预定回复“方向仍改90°，保留最新备注”继续；不无条件覆盖其他变化 |
| C09 | 来源有1个车辆资源点、availableCount=4；草稿有其副本及2个方案点；要求分别报告来源数量、草稿点数与可确认的到场情况 | 点数、属性数量、来源副本和方案分开；不相加为真实车辆总数，不凭图标/方案声称到场 |
| C10 | 已有带专业标号的部署对象；先生成500米范围预览，再明确要求把该固定范围保存为方案 | 使用同一真实分析结果，显式保存并正确设置角色，保留既有专业对象，未要求时不发布或采用 |

C01—C10 对应 PRD 的 A1—A5，完整覆盖新字段、接续与解释。另复用固定 R13 F01—F05 的题意和数据（来源点数/车辆数、第一次500米范围、限定图层最近两点、预览后保存、含边界点数及方法），重新生成合法身份和结果引用。旧模型答复、旧 resultRef 和旧成绩不作为新样本输入或本轮成绩。此批是开发验收集，不是独立保留集，也不能作为稳定提升的因果对照。

C08 的写入扰动必须绑定实际目标 draft 读取后的工具事件、在依赖写入前只触发一次；不得替换工具结果或改模型已收到的证据。未达到触发点按实际行为记录，不伪造覆盖。人工未保存输入、比较区选择等纯浏览器边界主要由工程 E2E 覆盖，不要求模型看见尚未发送的页面状态。

### 4.2 评分与合入建议门槛（待审）

分别记录任务完成、主任务正确、过程事实、最终事实、实际写入效果、越界行为和协议异常。工具成功或 HTTP200 不能替代语义正确。

- 相关工程测试全部通过。
- 真实30槽位全部有明确结论；待用户、未完成、预算停止和未执行不能悄悄删除，也不直接归为模型业务错误。存在此类缺项时不宣布验收完成。
- 新整合任务严格通过建议至少18/20，且每道题至少有一次严格通过；全部30项严格通过建议至少27/30。新任务和历史回归分别报告，不能用旧题成绩掩盖新功能失败。
- 错对象/错会话写入、未要求的发布采用、未改属性丢失、静默覆盖并发修改、重复保存等关键效果错误为零；出现即停止批次并修复，不用总分抵消。
- 未通过项逐一保留和归因；达到上述小样本门槛也不宣称正式90%总体/保留集验收通过。

合理澄清属于任务步骤：C02 和 C08 仅有上述冻结的回复，其他澄清仅能重述用户原要求，不临时添加答案、权限或操作提示。普通文字问句和 ask_user 都核对实际语义；完成任务后的条件性邀请不能被评测器误当作阻塞。未知交互记待用户并保留原槽位。

审阅公开过程与最终回答时，只使用当时可用的真实证据；保留初评分与复核版本。独立 Agent 复核可以用于交叉检查，但不得称为用户人工金标。发现预期答案或评测器有问题，记录工程缺陷，不改产品事实来凑分。

### 4.3 额度与停止条件（待审，未获调用授权）

建议整批硬上限：**300 次实际模型请求、800 万输入 token、60 万输出 token**。输出含思考用量时不重复相加。30项任务不等于30次请求；普通工具续跑、失败请求、压缩和子请求都纳入账本。

新开一对重复任务前，至少保留36次请求、100万输入和65536输出额度；单次发出前以实际请求体 UTF-8 字节数＋4096 作为保守输入预留，另预留32768输出，结束后按真实 usage 结算。额度不足则不发请求。单项12请求/24工具/10分钟仅提示，不误停仍正常推进的任务；整批硬上限始终有效。

网络/提供商错误、未知用量、截断、模型或源码漂移、非法状态写入、真实服务故障停止批次，保留已完成和未执行记录。正常模型能力失败保留该槽位，不自动换题/重试；参数错误可在同一原生任务中自行修正。修复评测器后续跑、追加额度、重测失败或换模型均另行说明，不自动使用 R14 剩余额度。

沿用已配置服务的凭据，不复制或打印密钥。执行前检查当时可用额度及计费方式，列出实际可核实的费用/套餐约束；本稿不推算货币费用或 AFP 换算，额度不足不自动充值/换端点。若只批准工程实现、尚未批准本批调用额度，完成 P3 后交付离线结果，保留 P4 待执行。

## 5. 证据、回退和交付

新增任务内评测程序，优先复用已验证的原生 HTTP/Pi 执行、用量记录和场景准备方法，不再造 Agent 调度循环。将所用辅助程序的提交/文件哈希纳入冻结清单，不能在运行时直接依赖另一个仍在修改的 worktree。复用 R13/R14 经验时只取可核实机制，不改其原文件、原批次或授权范围。

每槽位保留原始请求响应（去除鉴权）、实际公开消息、工具调用与回执、开始/结束状态、固定对象字段差异、Skill送达情况、评分及用量；保留不完整与失败记录。真实样本使用独立数据目录，禁止发送真实工作交接或写入当前用户任务。

工程回退以完整版本组合为单位；不把旧严格校验器用于已写新字段的数据。需要恢复试用时使用独立备份/数据副本，不回写或合并 R14 数据。主线合入、推送和现有 4324 试用更新在验收结果审阅后另行执行。

最终交付：中文提交记录、组合版本指纹、需求到测试的映射、工程结果、30槽位报告及失败明细、实际用量和可复现证据入口。只读代码核查或方案完成均不能标记为已通过这些验收。
