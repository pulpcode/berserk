# 优化聊天文件展示视觉

版本：实现与验收已完成，待提交，2026-11-10。

## Goal

改善聊天内固定交付文件卡的视觉层级、交互反馈与多文件秩序，缩小与 DeepSeek Harness Web（DSH）的美观度差距，同时保留现有固定副本、请求归属、历史顺序和完整文件名可读性。

## Background

- A 轮提交 `fa3c061` 对 `FileOutputCard` 仅删除“本次交付的内容”副文案；当前基础卡片样式主要来自较早的 `2188aaf`，尚未进行组件级视觉改造。
- 当前 `experiments/harness-lab/src/web/Files.tsx:30-32` 使用裸的 22px 通用文件图标、文件名、大小和文字下载链接；`styles.css:472-477` 使用内容自适应宽度、15px padding、白底和 1px 边框，没有整组多文件布局。
- 当前 `processGroups.ts:28-58` 按原生消息位置插入文件，既有约束要求不重排消息、交互、异常与文件归属。
- `.trellis/spec/frontend/harness-lab.md:100-102` 要求固定下载语义、正文对齐、长文件名完整可读且不溢出，并记录文件卡随内容收拢、最大 480px 的既有视觉约定。
- DSH 参考固定为 `deepseek-ai/deepseek-harness@fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。其交付卡使用 40px 图标块、明确文字层级、hover/focus、多文件网格与超过 4 项折叠；预览、侧边栏与原生打开属于额外交互能力，不在本任务自动引入。

## Requirements

### R01：单文件卡视觉层级

- 建立明确的文件图标块、文件名、元数据与下载操作层次，避免所有内容权重接近。
- 统一卡片最小高度、内外间距、圆角、表面、边框和文字行高；短内容不应显得松散，长文件名必须完整换行。
- 提供克制的 hover、focus-visible/focus-within 与 reduced-motion 适配，不通过整卡点击隐式下载。
- 2026-11-10 用户确认：保留随内容收拢与 480px 上限，并设置约 320px 的合理最小宽度（容器不足时收缩）；不采用 DSH 单文件占满整行的宽度规则。
- 下载继续使用原 `downloadId` 对应固定字节，不能改成当前同名路径。

### R02：相邻多文件组织

- 相邻且属于同一请求的文件可组成一个视觉网格；单文件与多文件均保持正文左缘对齐。
- 宽聊天区域使用两列，实际容器不足时切为单列；同一网格行的卡片高度协调。
- 超过 4 个文件时默认展示前 4 个，并提供可访问的展开/收起控件；展开状态在后续流式更新中不被无故重置。
- 不跨普通消息、交互、错误或请求边界合并文件，不改变文件与 `requestId`、`toolCallId`、`downloadId` 的绑定。

### R03：兼容与验证

- 保留上传、历史引用、固定下载、旧快照去重和错误可见性；本任务不改变权限、文件复制或执行语义。
- 桌面宽窗口、960px 窗口及桌面窄窗口或分屏形成的窄聊天面板均无页面级横向溢出。
- 以代表性单文件、多文件、长中英文名及展开状态截图审阅视觉结果。

## Acceptance Criteria

- [x] AC01（R01）：单文件卡具有统一图标块、清晰的文件名/元数据/下载层级；容器允许时宽度不小于 320px 且不超过 480px，容器不足时不超过可用宽度；短文件名与长文件名均无异常留白、裁切或重叠。
- [x] AC02（R01）：下载链接仍指向原固定 `downloadId`；点击下载之外区域不会触发下载、预览、消息发送或文件写入。
- [x] AC03（R01）：hover、键盘焦点和 reduced-motion 状态清晰且稳定，不改变卡片布局尺寸。
- [x] AC04（R02）：2–4 个相邻同请求文件按容器宽度形成两列或单列；超过 4 个默认显示 4 个，展开后全部可见并可收起。
- [x] AC05（R02）：不同请求或被普通消息、交互、异常分隔的文件不被跨边界合并；重复 `downloadId` 仍只出现一次。
- [x] AC06（R03）：既有文件、聊天与过程分组回归通过，固定下载、历史引用和错误语义无回退。
- [x] AC07（R03）：1440px、960px 与桌面窄窗口形成的窄聊天容器截图完成审阅，无页面级横向溢出，长文件名完整可读。

## Out of Scope

- 文件内容预览、右侧边栏、原生应用打开、右键菜单和变更 diff 视图。
- 上传附件、历史引用和项目文件面板的样式或结构改造。
- 新后端字段、文件复制、权限变化、消息重排或持久化显示偏好。
- 手机端专项设计或验收。
