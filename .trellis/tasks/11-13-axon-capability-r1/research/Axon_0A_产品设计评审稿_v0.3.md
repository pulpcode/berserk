# Axon 能力中心与专家协作
## 第 0 轮 · 0A 产品设计评审稿

版本：0A v0.3  ｜  日期：2026-11-13  ｜  状态：补充交互与内置专家规则；产品基线

产品方向已获大体认可。本版在 v0.2 基础上落实“与专家协作”操作名称和系统内置通用助手的界面定位，其余产品范围与轮次不变；0B 技术设计已通过评审，R1 尚未实施。

## 一、阶段目标与已确认边界

建设统一能力中心，让用户能选择专家、使用技能与外部连接，按需组织专家协作；让管理员能配置、发布和维护这些能力。实际工作仍在现有工作台完成。

| 已确认事项 | 本阶段处理 |
| --- | --- |
| 企业智能体 | 暂不纳入。独立部署、托管和对外服务另行调研。 |
| 个人创建专家与技能 | 不纳入，留待下一阶段；普通用户本阶段只使用获准能力。 |
| 外部系统集成 | 保留已有业务功能，进行连接器规范化改造，并增加 MCP 接入。 |
| 后台与专家团顺序 | 先改造后台持续分析 Agent，再建设专家团与协作编排。 |

## 二、产品入口与核心对象

全局导航新增“能力中心”，包含专家、专家团、技能、连接器四类。按建设轮次开放功能，不提供尚不可执行的操作入口。专家列表专门展示可选的专业专家；“Axon 通用助手”属于统一专家技术体系中的系统内置基础助手，但不在该列表展示。

| 对象 | 用户理解 |
| --- | --- |
| 专家 | 可复用的专业助手，如筹划专家。独立于用户和席位，可作为主助手或接受委派。 |
| 专家团 | 由主理专家和成员组成的协作配置，明确分工、执行关系和汇总要求。 |
| 技能 | 专家可采用的工作方法，可包含参考资料、模板和脚本。 |
| 连接器 | 可使用的外部系统能力，以及实际连接和授权状态。 |

## 三、管理分工

普通用户：查看已发布且获准的专业专家，通过“与专家协作”开始工作；使用获准的其他能力，设置个人默认和收藏；不能创建、导入或修改共享专家、技能。

管理员：系统统一的管理角色，本阶段负责组织级能力的创建、导入、试用、发布、更新、停用及连接管理，后续可扩展其他系统管理职责。可设专用账号；管理权不按席位名称推导，也不自动授予业务数据读取或指令下达权限。

## 四、核心使用流程（建议）

### 4.1 与专家协作

专业专家详情 → 点击“与专家协作” → 确认任务空间或个人空间 → 创建专家会话 → 用户输入目标后开始执行。

从任务空间进入时沿用当前空间；从全局进入时先选择空间，取消不创建会话。“与专家协作”仅创建空会话，不自动发送消息、不修改个人默认，也不启动后台任务。

会话显示当前专家，并保存实际专家版本。后续多轮继续使用该专家；切换主专家优先新建会话。修改个人默认不影响已有会话。

“与专家协作”与“专家委派”分开：前者为用户选定主专家并创建会话；后者由主 Agent 发起独立子任务，结果返回主会话。

### 4.2 默认专家与权限

先校验使用权限，再按以下顺序确定新会话的专家：

会话显式选择 → 任务明确默认 → 个人默认 → 席位默认 → Axon 通用助手

任务可不配置默认；仅“推荐”的专家不覆盖个人偏好。本阶段不普遍设置强制专家锁定。现有“新建对话”入口始终保留，按上述规则创建会话；在尚未设置其他默认专家时使用 Axon 通用助手，而不是进入专业专家列表选择。通用助手可以在会话头部显示其名称。

| 场景 | 建议行为 |
| --- | --- |
| 筹划席位用户未设置个人默认 | 使用席位默认的筹划专家。 |
| 个人改为获准的态势专家 | 新建普通会话使用态势专家；原会话不变。 |
| 选择无权使用或已停用的专家 | 明确提示不可用并重新选择，不因个人设置扩大权限。 |

### 4.3 管理员发布能力

管理员创建专家；技能可创建或从技能包导入。流程为：保存草稿 → 自动校验 → 隔离试用与人工确认 → 发布为不可变版本 → 获准用户可使用。修改内容后，重新取得与当前草稿匹配的校验及试用记录。

详情展示职责、适用场景、示例、版本、技能和连接依赖。缺少授权或依赖时明确提示；已开始的执行不因发布新版本而悄悄变化。

本阶段不建设私人专家库、私人技能库、普通用户上传安装及个人发布审批流程。

### 4.4 外部能力的使用

组织预配置核心业务连接，用户无需每次重新添加。专家按任务需要调用获准能力；个人授权仅在所接服务确有需要时引导完成。

“已连接”不等于允许写入，“已授权”不等于批准某次操作。需要业务确认的提交、发送或下发，仍走现有确认与回执流程。

## 五、各模块建设内容

### 5.1 专家管理

将 Axon 通用助手作为系统内置基础专家纳入统一专家定义，但不在能力中心的专业专家列表中展示；现有“新建对话”沿用其默认能力。通用助手不可通过普通专家管理界面直接编辑或删除，核心配置由受控系统升级维护。现有 analyst/reviewer 子角色亦统一纳管，但不作为可选主专家卡片。专业专家支持名称、职责、专业指令、技能与连接依赖、工具范围、适用运行方式，以及创建、试用、发布和版本管理。

主会话使用平台已配置的模型，子任务默认继承父请求模型。复杂模型路由不作为本阶段前提。专家配置不能覆盖平台权限规则。

### 5.2 技能管理与导入

将固定技能列表改为可管理的技能目录，支持管理员创建、导入、发布、启停和更新；专家绑定与用户显式选择遵守同一套可用范围。

导入内容可包含 SKILL.md、参考资料、模板和脚本。导入只生成草稿，不自动执行脚本或安装依赖；使用时仍经获准工具和受控沙盒执行。

校验采用程序规则及适用的静态、依赖扫描；LLM 仅作可选辅助，不能批准放行。试用在独立测试工作区执行代表性任务，默认不含生产凭证；管理员核对工具调用及成果后发布。检查未完成不得标为通过，通过准入也不代表绝对安全。具体规则由技术稿细化。

普通用户上传的 SKILL.md 或技能压缩包只作为普通文件，不自动安装、发布，也不改变工具权限。

### 5.3 连接器规范化与 MCP

统一已有适配器的能力说明、连接配置、凭证引用、授权范围、状态和调用记录；保留来源、版本、业务时间、任务范围及回执等业务校验。增加远程 MCP 接入，并选一个真实目标服务完成验证。

建议支持同类适配器登记多个独立连接，例如不同服务地址或账号；每条连接独立授权、标识来源。可同时登记不等于自动合并查询。此处“实例”指实际连接，不指某一轮演练场景。

一期用不同名称添加连接即可，不做自动负载均衡、主备切换或跨实例自动聚合。

### 5.4 后台持续分析 Agent 改造

将现有后台处理方案（Profile）中的专业指令、技能和工具配置整合到专家定义；来源、触发、处理范围、执行身份和投递仍由后台规则管理。

保留并验证现有持续研判、暂停、恢复和结果记录。共享专家定义不共享个人聊天、私有文件或个人凭证；不扩展成企业智能体部署产品。

### 5.5 专家团与协作编排

支持主理专家、成员、分工与交付要求，先实现顺序协作和有界并行，再实现受控嵌套委派。统一停止、部分失败、资源约束与成果汇总，展示真实成员执行，不开放无限递归。

### 5.6 明确不做

除已确认排除项外，本阶段不建设公开商业市场、通用工作流编辑器、任意宿主命令执行、完整长期记忆系统；不以替换 Pi 或重写现有业务流程为前提。

## 六、建设轮次与每轮交付

| 轮次 | 建设重点 | 可审阅结果 |
| --- | --- | --- |
| 0A | 产品设计评审（本稿） | 确认产品流程、范围与顺序，不做正式编码。 |
| 0B | 技术设计与实施准备 | 明确共同契约、兼容迁移及第 1 轮任务与验收。 |
| 第 1 轮 | 统一定义与最小闭环 | 正式编码：通用助手及角色技术纳管、专业专家目录与“与专家协作”、会话绑定；一个专业专家真实可用。 |
| 第 2 轮 | 专家管理与使用配置 | 管理员创建发布、版本管理、席位默认及个人偏好。 |
| 第 3 轮 | 技能管理与技能包 | 动态登记、管理员创建与导入、试用、发布及启停。 |
| 第 4 轮 | 连接器规范化与 MCP | 现有集成规范化、连接管理与授权、真实 MCP 服务验证。 |
| 第 5 轮 | 后台 Agent 统一化改造 | 后台方案引用统一专家；持续分析与原流程不退化。 |
| 第 6 轮 | 专家团与协作编排 | 顺序、有界并行、受控嵌套和结果汇总；阶段总验收。 |

第 1 轮先使用内置示范配置和已有技能，不要求同时完成网页创建、技能包导入或 MCP；后台的共同配置需求在 0B 就纳入设计，第 5 轮再迁移。

## 七、阶段验收

用户闭环：选择专业专家并点击“与专家协作” → 使用获准技能与连接 → 按需委派或组织协作 → 在现有工作台交付成果。原“新建对话”入口与通用助手继续可用，通用助手不出现在专业专家列表。

管理闭环：管理员不修改业务主体代码，即可发布新专业专家或方法型技能；发布、停用、依赖与授权状态真实生效。

安全与兼容：选择能力不扩大权限；实际版本和执行结果可查；旧会话、文件作业、人工确认、工作交接及后台处理不退化。
