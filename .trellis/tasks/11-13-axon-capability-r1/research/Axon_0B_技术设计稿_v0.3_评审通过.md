## 一、总体方案与边界

**已确认：在现有应用内增加统一能力管理与装配层，继续使用 Pi 执行；不另建聊天系统，不重写现有业务服务。**

产品约束保持不变：使用系统统一“管理员”；普通用户不创建专家或技能；现有集成要规范化改造；第 5 轮先整合后台，第 6 轮再建设专家团；企业智能体部署与托管不纳入。

### 1.1 逻辑结构

能力中心／管理页面 → 能力目录与发布服务 → 能力解析器 → 现有 Pi 会话与工具执行。

权限服务贯穿目录、创建会话及每次调用；原业务服务继续处理任务范围、来源时间、操作确认和回执。前台、子任务、后台共用解析器，但传入不同的执行身份与运行约束。

### 1.2 代码现状与接入点

| 现有位置 | 已有基础 | 本阶段处理 |
| --- | --- | --- |
| pi/lab.ts、pi/roles.ts | 会话创建、固定通用助手、受控子角色 | 抽出专家解析与装配，保留 Pi 工具循环。[S1] |
| resources/service.ts | 固定技能及资源快照 | 先做兼容提供器，第 3 轮改为动态目录。[S1] |
| access/*、server/app.ts | 登录、席位检查、会话 API | 增加账号级管理员身份和新接口鉴权。[S3] |
| context/*、commands/* | 专用业务接入与回执 | 封装为连接器适配器，保留业务校验。[S4] |
| background/* | 处理方案、作业与持续研判 | 第 5 轮改用统一专家；不重建调度。[S5] |

### 1.3 架构约束

新建 capabilities/ 管理资产、版本、授权与解析；connectors/ 管理外部接入；Pi 相关转换仍放在 src/pi。新模块不依赖 Pi 的原生类型。继续单服务进程，不新增微服务、消息中间件或第二份聊天数据库。

本稿确定共同契约和第 1 轮实施边界。后续各轮再细化接口字段、扫描阈值与性能参数，不能以此提前实现全部功能。

## 二、统一模型、存储与版本

### 2.1 核心对象（字段为建议，不是最终数据库表）

| 对象 | 关键内容与用途 |
| --- | --- |
| ExpertRevision | 稳定 expertId、不可变 revisionId、发布版本号 releaseVersion、内容摘要 digest、专业指令、模式、依赖与委派策略。 |
| SkillRevision | skillId、不可变修订、发布版本号 releaseVersion、SKILL.md、文件摘要、声明依赖、校验和试用证据。 |
| TeamRevision | 主理专家、成员版本、分工、依赖关系、并行及委派限制。 |
| ConnectorDefinition | 适配器类型与版本、认证方式、可开放动作及参数契约。 |
| Connection | 独立 connectionId、定义引用、地址、凭证引用、归属身份、开放动作与状态。 |
| CapabilityBinding | 席位使用范围；账号个人默认；任务默认与连接绑定。偏好和授权分字段保存。 |
| ExecutionManifest | 本次专家／技能修订及摘要、连接配置修订、身份、模式、工具集合、模型配置版本和策略摘要；不含密钥。 |

专家声明“需要什么”，不声明“授予自己什么权限”。技能是方法资产；后台规则和专家团分别引用专家，不复制专业定义。所有对象使用稳定 ID，显示名称可修改。Axon 通用助手按系统内置专家定义统一解析、版本绑定与审计，但不进入面向用户的专业专家列表；现有只读子角色同样不作为可选主专家卡片。

### 2.2 建议存储

新增 LAB_DATA_DIR/capabilities/capabilities.sqlite，保存资产元数据、草稿、版本引用、绑定、检查记录和管理审计。技能包按内容摘要存入只读 blobs 目录；先完成文件落盘，再事务提交发布引用，未提交文件不可发现。

管理员身份复用现有认证库，新增账号级角色记录并走受控迁移；不由席位名称或已有模型管理权限自动推导。凭证只以 secretRef 关联，实际内容由服务端 SecretStore 管理，禁止写进包、会话和审计正文。

**聊天与工具证据仍以 Pi JSONL 为准。** 专家绑定和执行清单新增版本化 custom entry；目录库可建查询索引，但不成为第二份历史真相。现有严格解码须同步扩展。[S2]

### 2.3 版本与状态

**配置修订与发布版本号分离。** 每次正式发布生成不可变 revisionId，重试不重复生成；releaseVersion 是用户可见的正式发布版本号，不用于内容寻址。R2 的正式发布流程按版本规则生成新 releaseVersion；R1 的受控内置登记及兼容测试即使使用相同 releaseVersion，只要内容改变仍必须形成新 revisionId。digest 校验规范化配置和锁定依赖。

新会话绑定 expertId＋revisionId＋digest；新发布仅改变新会话默认，旧会话刷新／重启仍用原修订，但须保持当前授权。一期不做旧会话原地升级、多版本切换或灰度发布。

专家修订锁定声明的技能修订，团队锁定成员修订；显式额外选择的技能按请求固定，不得覆盖同名的固定依赖。工作区指令、用户输入和实时授权仍按请求读取，不冻结整个工作环境，也不保证模型输出完全相同。

普通停用阻止新会话和新请求；已接受请求仅在原快照和授权内收尾，不能继续接收追加输入扩展任务。紧急封禁或撤权后，服务端提交点起阻止受影响的新调用，并向在途执行传播取消；已发出的外部操作可能无法撤回，须查询回执，不承诺回滚。

可用状态独立保存；受引用修订及依赖不删除，缺失则阻断续跑，不用最新内容替代。历史仍受原权限约束。WorkBuddy 实测仅是行为参考。[S11]

## 三、身份、授权与专家协作

### 3.1 三种身份，统一校验

用户请求从登录会话取得 userId、seatId；席位后台保留其获准身份，来源预处理与持续研判使用服务身份；子任务仅继承父任务授予范围。后台领取时复核原主体仍有效，客户端不能指定别人的身份。

管理员可维护组织级资产和连接配置，但管理权限不自动授予业务查询、下发或他人私有文件读取权。仅管理账号需要试用时，使用独立试用空间，不借用业务席位。普通用户的创建、导入、发布请求在服务端拒绝。

**有效能力取交集：执行主体授权 ∩ 运行模式约束 ∩ 专家允许范围 ∩ 任务明确限制 ∩ 连接授权 ∩ 工具自身规则。** 未配置任务限制表示沿用已有授权，不等于开放全部；必需依赖缺失明确报错，可选依赖缺失可降级并说明。

### 3.2 默认与会话绑定

会话显式选择 → 任务明确默认 → 个人默认 → 席位默认 → Axon 通用助手。任务推荐不覆盖个人偏好。被选中的默认已停用或无权使用时，提示重新选择，不静默换成另一专家。普通“新建对话”入口继续适用这一解析规则；通用助手无需在专家列表中提供选择卡片。

个人默认按账号保存，席位默认由管理员配置；修改默认只影响以后创建的会话。已有会话不允许原地切换主专家，界面提供“用另一专家新建会话”。首次创建时解析并固定具体 revisionId 与 digest，而非仅记录显示版本。

### 3.3 “与专家协作”流程

| 步骤 | 服务端与界面行为 |
| --- | --- |
| 选择专业专家及空间 | 仅对可选的专业专家展示“与专家协作”；任务内沿用当前空间，全局入口先选空间，取消不创建。 |
| 校验并创建 | 检查已发布版本、空间访问权及使用资格；保存会话专家绑定后再返回成功。 |
| 展示依赖 | 区分未配置连接、需个人授权、依赖不存在与服务暂不可用；允许先进入空会话补齐授权。 |
| 用户发送 | 再校验必要依赖及当前权限，保存执行清单，之后才调用模型。 |
| 执行与续聊 | 每次工具调用复核当前授权；保留专家版本，工作区指令仍按新请求读取。 |

点击“与专家协作”只创建空会话，不发送消息、不调用模型、不自动运行后台。专业专家列表不展示 Axon 通用助手；它仍可通过“新建对话”作为默认能力使用，并在会话摘要中显示身份。列表可见不等于可调用，界面隐藏不能替代鉴权。管理写入使用 expectedRevision 防止覆盖，冲突返回 409 并保留草稿。

## 四、能力装配、接口与第 1 轮边界

### 4.1 统一装配流程

CapabilityResolver 接收身份、空间、专家修订、运行方式和本条选择，返回 ExecutionManifest 与可注册工具。业务层负责策略，Pi 适配层只负责转换成提示、资源和工具。首轮模式保留 interactive、delegated；background 与 trial 预留类型，分别后续接入。

平台规则由代码维护，专家专业指令与项目指令分区装配；文件、连接器结果均按资料处理，不获得系统权限。技能目录先提供摘要，正文按需读取；显式选择时加载同版本正文。继续 noSkills: true，不开放未经平台批准的自动发现。[S1]

主会话沿用已有模型选择，子任务继承父请求模型配置快照，后台沿用其明确模型配置。继承模型不复制父会话全文。第 1 轮不增加独立专家模型路由、并行或递归。

### 4.2 建议 API（路径与字段待实现时校核）

| 接口 | 本轮契约 |
| --- | --- |
| GET /api/capabilities/experts | 第 1 轮。只返回面向用户可选的专业专家；排除系统内置通用助手和仅供委派的子角色；提供模式、可用性和依赖摘要，不泄露密钥或内部路径。 |
| GET /api/capabilities/experts/:id | 第 1 轮。读取获准的可选专业专家修订详情、releaseVersion 与内容摘要；通用助手身份通过会话 API 展示。 |
| POST /api/sessions | 第 1 轮。在原接口增加 expertRef（含 revisionId）、expectedDigest、clientActionId；沿用空间、模型与鉴权。 |
| GET /api/sessions/:id | 第 1 轮。增加当前专家身份（含 Axon 通用助手）、releaseVersion、修订与可用性摘要；复用原历史、状态和 SSE。 |
| /api/admin/capabilities/* | 第 2、3 轮。草稿、检查、试用、发布、停用；管理员鉴权。 |
| /api/admin/connections/* | 第 4 轮。实例、凭证写入、测试和授权管理；用户只管理获准的个人授权。 |

所有前台会话创建入口复用同一绑定函数；第 1 轮“新建对话”未指定专家则使用系统内置的 Axon 通用助手，即使它不在专业专家列表中；第 2 轮接入默认优先级解析。原有输入框“选择子 Agent”仍为本条委派意图，不能变成切换主专家。[S1、S3]

### 4.3 创建的一致性

按“账号＋clientActionId”保存创建意图及参数摘要。同键同参数返回原会话，同键异参数返回 409。先持久化专家绑定，再发布工作区关联；跨文件／数据库无原子事务，用准备记录核对完成情况。中断不自动重发用户消息，无法确认时显示待核对而非再建空会话。

第 1 轮从受控内置配置登记不可变修订，固化主专家所需的内置技能内容；保留旧角色别名、工具边界和按父请求加载语义。登记是内容快照保存，不开放网页发布。第 2 轮转入正式编辑发布流程，逐资产确定唯一配置来源，不双写。

### 4.4 服务端装载与观察

专家和技能集中存储，不下载到浏览器安装。R1 使用按 revisionId＋digest 寻址的有界内存缓存，内容可共享，私有上下文和授权不可共享。先给技能摘要，再按需载入正文。分别记录冷／热装载、上下文组装、模型首段输出和工具耗时；先测量，不预设无依据的性能承诺。

## 五、技能导入、安全校验与发布

### 5.1 建议支持范围

仅管理员创建／导入。首期支持 SKILL.md 与 ZIP 包，单一技能根目录，可含 references、templates、scripts；支持方法型及受控 Python／JavaScript 脚本。未知二进制、宿主安装钩子和无法检查的执行格式不开放。来源格式映射在导入时完成，不承诺任意生态包直接兼容。

普通聊天上传 SKILL.md 只是资料。导入产生草稿，不执行包内程序、不自动安装依赖。依赖缺失由管理员维护受控镜像；检测依赖不得 import 或运行不可信模块。

### 5.2 准入检查与责任

| 层次 | 具体方式 | 结果处理 |
| --- | --- | --- |
| 文件与格式 | 程序检查路径、文件数量、大小及实际解压量；拒绝越界路径、符号／硬链接、重复归一化路径和嵌套归档；核对引用。 | 违反硬规则直接阻断。阈值配置化，第 3 轮测试后确定。 |
| 脚本静态扫描 | 建议本地 Semgrep CE，固定工具与规则版本；扫描器也在无秘密的受限环境运行。 | 规则命中分类复核；扫描失败或漏扫不标为通过。[S8] |
| 依赖检查 | 声明依赖、锁文件与执行镜像清单交叉核对；适用时用 OSV-Scanner 离线库检查已知漏洞。 | 不适用单列；未知版本、库过期或不可用明确显示，不冒充无漏洞。[S9] |
| LLM 辅助审查 | 可选；只读分析指令和代码风险，不挂工具、不传凭证。 | 只提供意见，不决定放行；关闭不降低其他检查要求。 |

扫描默认不向外部服务上传技能和业务资料；规则与漏洞库通过独立受控流程更新。扫描不能证明语义正确或绝对安全，不以“零告警”自动批准发布。

### 5.3 试用与发布条件

为草稿生成固定内容摘要；在独立临时工作区、现有 Docker 边界下，用脱敏样例执行代表性任务。第 3 轮增加技能包只读挂载及配套路径校验，工作输出单独可写；不挂生产凭证，外部写入只对测试目标开放且仍需确认。[S6]

记录内容摘要、工具／规则版本、镜像摘要、测试输入、调用及成果、管理员结论。发布事务重新核对摘要一致、必需检查完成、硬阻断项清零、可复核项有处置、至少一次代表性试用被确认。内容或依赖变化使旧检查／试用失效。不能把管理员点击确认当作覆盖硬规则的后门。

## 六、连接器规范化与 MCP

### 6.1 改造方式

**统一接入契约，不抹平业务语义。** 提取适配器的能力描述、输入校验、调用、健康检查和错误映射；可选提供事件接收与回执查询。现有 ContextService、入站处理和 CommandService 继续承担领域校验与业务状态。[S4]

专家声明逻辑能力需求，任务或席位绑定具体 connectionId；个人连接只能由其归属账号授权使用。存在多个匹配连接时明确选择，不自行混用。实例区分地址／账号；scenarioInstanceId 仍是业务场景范围，不能互相替代。

| 统一项 | 设计要求 |
| --- | --- |
| 调用与来源 | 记录 connectionId、稳定动作 ID、请求关联、来源版本和业务时间；工具名按实例消歧。 |
| 身份与秘密 | 机构连接与个人连接分开；服务端保存 secretRef；新保存的秘密加密，主密钥外置，不进入浏览器、模型或沙盒。 |
| 状态 | 启停、授权状态与健康状态分开；查询、事件接收、写入可分别异常。 |
| 错误与重试 | 区分未授权、权限不足、超时、数据无效及结果不明。只对安全读取有限重试；写入先核对幂等键和回执。 |

第 4 轮保留原 systemId 与业务对象引用，建立旧配置到连接实例的映射，不通过改显示名称重建来源身份。请求固定连接配置修订及工具描述摘要；换地址或账号须重新确认绑定，不让在途请求漂移。凭证值不入快照，撤权即时生效。规范化前后用同一输入核对结果和权限。

### 6.2 MCP 的接入边界

Axon 作为客户端，建议采用官方 TypeScript SDK 的受控远程 HTTP 接入；首期以工具发现和调用为主。不开放任意 stdio／CLI，不自动启用服务器发起的采样、文件根目录或其他额外能力。SDK 和协议版本在第 4 轮锁定并记录兼容矩阵。

本稿参考 MCP 2026-07-28。该版传输行为与 2025 版本存在差异，因此不能手写一套“通用握手”就声明兼容；按选定 SDK 与目标服务实测。MCP 的连接状态不替代 Axon 的会话或业务任务。[S7]

先发现工具，再校验参数结构、审核开放动作并锁定描述摘要；工具变更重新确认。不信任上游“只读”等声明来跳过权限。已有来源数据不能未经批准作为参数外传到另一连接。

### 6.3 网络与认证

出站地址由管理员配置；校验域名／IP、重定向、TLS、超时及响应大小，阻断云元数据等禁用目标；内网业务地址须显式允许。凭证按连接和主体隔离。个人 OAuth 按协议处理状态校验、PKCE、刷新与撤销，仅在目标服务需要时实现并验收。真实目标服务在第 4 轮开工前选定。

## 七、后台先整合，专家团后扩展

### 7.1 第 5 轮：后台处理方案改造

当前既有使用服务 Profile 的预处理／持续研判，也有沿席位会话执行的 seat_analysis，不能把所有后台作业强行改成服务身份。持续研判还保留只读工具子集及专用完成检查。[S5]

| 原有配置 | 新归属 |
| --- | --- |
| 名称、专业目标、instructions、skillIds、agentIds、tools | 专家定义与不可变修订；一次作业的具体目标仍作为任务输入。 |
| 来源、触发、合并等待、接收席位、启停 | 现有后台规则／持续研判配置，增加 expertRef。 |
| contextScopeId、执行身份、运行模式限制 | 后台运行绑定，不能被专家 Prompt 覆盖。 |
| requireTaskAssessment 等业务完成条件 | 原业务校验器；不能随专家指令删除。 |

迁移采用“暂停领取 → 处理或人工停止在途作业 → 固定版本映射 → 原子切换配置 → 核对未消费输入 → 恢复”。队列和历史作业保留原快照，绝不批量换成最新专家后重跑。

持续研判更换专家时创建新的配置代际；既有发布结论作为可核验基线，不混用新旧专业指令。来源游标、未消费事件、批次与回执不丢失、不重复发布。复用配置不共享个人聊天、私有文件或凭证；不新增企业智能体部署功能。

### 7.2 第 6 轮：专家团与委派

团队引用不可变专家修订，声明主理人、成员及交付要求。先做单层顺序与有界并行，再做有界嵌套；不仅删除当前单活跃子任务检查。[S10]

执行节点记录 rootRunId、parentNodeId、expertRevision、子会话及状态，复用版本化父子历史记录；状态由真实调用投影。限制并行数、深度、节点数与可选总预算；成员权限不得大于父任务授权。

全局模型额度只覆盖实际模型调用，父节点等待子结果时不能长期占用额度导致死锁。父取消传播到整棵树；部分失败由主理人说明缺口，不能当作全员成功。服务重启后在途节点标为中断，不自动重放写操作。

并行成员默认只读共享输入，输出写入各自隔离目录，通过明确交付汇入主任务。需要交互审批的动作回到主会话确认；后台模式不允许靠嵌套委派绕过限制。并发与预算的默认阈值在该轮压力测试后确认。

## 八、兼容、迁移与回退

### 8.1 必须保留的旧契约

当前 workspace-index 校验固定 skillIds，资源与会话历史也检查技能 ID 和记录格式；旧输入文本还存在逐版本解码规则。不能直接换掉全局列表后让旧校验器读取新语义。[S2]

| 范围 | 兼容处理 |
| --- | --- |
| 旧主会话 | 按迁移清单识别旧格式，显示“通用助手（历史兼容）”；不伪造历史版本，首次新请求才追加绑定。新格式缺绑定按损坏处理，不降级为通用助手。 |
| 旧子角色 | 保留 analyst/reviewer 别名、角色哈希、原工具集合与旧历史解码；新专家定义通过兼容层接入。 |
| 旧技能和工作区 | 历史解码固定旧版常量；动态技能绑定放入新能力库，不把任意新 ID 写回严格的旧索引。 |
| 新历史记录 | 新增明确 schemaVersion 的 expert-binding、execution-manifest 和后续资源记录；旧格式继续只读解码。 |
| 旧连接与后台 | 显式登记配置映射；每一项确定唯一生效来源，避免文件和界面双写，旧作业仍用原快照。 |

旧会话继续保留新请求读取最新工作区指令的规则，不把历史空指令或旧承诺重新当作当前授权。发现缺失快照、哈希不一致或非法引用时，保留历史供核查并禁止继续执行，不静默修复为默认专家。

### 8.2 迁移与发布流程

先 dry-run 输出资产、角色、连接和后台规则的映射及冲突；停服后备份完整数据目录，再执行可重复、带阶段标记的迁移。资产库与认证库分别记录迁移，不靠覆盖旧 schema 版本绕过检查。

R1 保留现有运行路径作兼容入口；R3、R4、R5 分别切换技能、连接和后台。没有真实服务或运行环境时，只报告替身测试结果，不能宣称完成真实集成验收。

### 8.3 回退与观察

新格式写入后，不允许旧程序直接打开升级后的活动数据。回退采用匹配旧程序与完整备份，并保留升级后新增数据供核对；关闭功能开关不等于数据已降级。

审计至少记录操作者、动作、资产／连接 ID、前后版本、结果和关联请求；不记录明文凭证。保留失败原因、工具调用及必要结果证据；历史访问继续按原空间和席位控制。

## 九、实施轮次与第 1 轮验收

### 9.1 轮次不变

第 1 轮统一定义与专家协作闭环 → 第 2 轮专家管理及默认 → 第 3 轮技能管理 → 第 4 轮连接器规范化与 MCP → 第 5 轮后台整合 → 第 6 轮专家团。每轮均含测试、迁移检查和独立产品验收。

### 9.2 第 1 轮编码任务

| 编号 | 工作包 | 交付结果 |
| --- | --- | --- |
| R1-1 | 契约与提供器 | ExpertRevision、ExecutionManifest；通用助手、旧角色与示范主专家读取；固定内容摘要。 |
| R1-2 | 存储及权限基础 | 能力库初始化与迁移登记；账号级管理员入口；无自动提权；原权限不回归。 |
| R1-3 | 会话及执行接入 | 专家绑定、幂等创建、统一能力解析、Pi 装配、新旧历史解码及状态投影。 |
| R1-4 | 前端闭环 | 仅专业专家目录、详情、“与专家协作”、空间选择、会话专家标签（含通用助手）、依赖提示及刷新恢复。 |
| R1-5 | 验收与回退 | 单元／集成／浏览器回归，独立数据目录真实模型验证，升级和中断测试，形成记录。 |

首轮不做网页创建发布、个人默认设置、技能包导入、MCP、后台迁移或并行递归。管理员身份仅接入本轮需要的管理访问；其他系统管理模块以后逐项对接，不自动替换已有权限。

### 9.3 第 1 轮通过标准

| 编号 | 必须证明的行为 |
| --- | --- |
| A01 与专家协作 | 通用助手不出现在专业专家列表；“新建对话”仍可正常创建通用会话；与专业专家协作取消不创建、重复点击不重复创建、未发消息不调用模型。 |
| A02 专家生效 | 一个专业主专家完成多轮任务；实际模型输入、技能与工具集合来自正确版本。 |
| A03 隔离 | 切换用户、席位、任务不能越权；普通用户伪造管理请求被拒绝。 |
| A04 持久化 | 刷新、重启后专家绑定不变；保存中断可核对；未完成用户工作不自动重做。 |
| A05 兼容 | 旧主会话、旧子角色、技能标签、文件交付、人工确认、工作交接及后台流程不退化。 |
| A06 修订与状态 | R1 同 releaseVersion 的内置配置改变仍产生新 revisionId；旧会话经刷新／重启仍用旧内容；停用与撤权按策略生效。 |

检查包括 typecheck、lint、单元／集成及浏览器测试；真实模型和 Docker 验证单列环境与证据。数量和性能结果以实际执行为准，本稿不预填“已通过”。

## 十、评审结论与依据

### 10.1 评审结果（2026-11-13）

| 编号 | 通过的方案 | 主要取舍 |
| --- | --- | --- |
| T1 结构与存储 | 单体内新增能力模块；元数据用独立 SQLite，包按摘要保存；会话仍用 Pi JSONL。 | 隔离改造影响，但跨文件提交需准备记录与核对机制。 |
| T2 管理员身份 | 账号级 administrator；首个管理员由离线管理命令显式授予。 | 不绑定业务席位；本轮不全面改写既有管理权限。 |
| T3 修订策略 | 内部 revisionId 与正式发布版本号 releaseVersion 分离；会话固定专家及声明依赖；实时鉴权，停用与封禁分开。 | 新旧会话隔离；不复制 WorkBuddy 原地覆盖，不做原地升级或灰度。 |
| T4 技能准入 | 本地规则与适用扫描为基础；独立试用；LLM 可选；内容变更需重新检查。 | 不承诺绝对安全，不建设复杂审批或自研扫描引擎。 |
| T5 接入与迁移 | 原生与 MCP 共存；先后台、后专家团；逐模块切换，不整体重写。 | 保留旧业务契约；后续轮次仍需专项设计和实测。 |

根据用户“采用建议，修订并通过评审”的确认，0B 设计通过，T3 沿用不可变发布修订方案；T1、T2、T4、T5 不变。后续确认的“与专家协作”、releaseVersion 和通用助手不进入专业专家列表属术语及入口设计修订，不改变总体架构。0A v0.3 产品范围不变，进入 R1 实施准备。方案通过不等于已创建分支、迁移数据或完成编码。

本次同步修改核心对象、专家协作流程、目录/API 可见性、R1-4 和 A01/A06 验收，保留前版已通过的服务端缓存与耗时观察要求。MCP 目标服务、扫描规则及并发阈值仍在对应轮次锁定，不阻塞 R1。
