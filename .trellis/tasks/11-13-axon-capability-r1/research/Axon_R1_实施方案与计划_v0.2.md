## 一、本轮目标与范围

**交付目标：用户从能力中心选择专业专家，点击“与专家协作”，在原工作台连续完成任务；会话固定实际配置修订，刷新、重启或配置更新都不会静默换用其他内容。**

本稿是编码方案，不是再次讨论产品方向；不表示已建分支、修改代码、迁移数据或运行测试。0B 已通过，R1 的实现和验收尚未开始。

### 1.1 首批纳管对象

| 对象 | R1 处理 | 权限边界 |
| --- | --- | --- |
| Axon 通用助手 | 系统内置基础专家，技术纳管但不在专业专家列表展示；“新建对话”未指定专家时沿用 | 保留现有获准工具，不额外放权；核心配置不通过普通专家管理界面直接编辑 |
| 资料综合专家（示范） | 新增受控、可在专业专家列表选择的主专家，用测试资料验证多轮综合与复核 | 以资料读取、synthesis / review 为主，不提供业务下发 |
| analyst / reviewer | 通过兼容提供器纳管，保留原名和委派入口；不作为可选主专家展示 | 仍为只读、单层、顺序委派，不自动升级为主专家 |

示范专家是本轮验收配置，不作为最终业务专家目录。验收资料使用现有通用样例或合成数据，不依赖生产连接器。

### 1.2 本轮做与不做

| 本轮必须完成 | 后续轮次再做 |
| --- | --- |
| 专家修订、内置依赖快照、最小能力库 | 网页创建／编辑／发布专家，个人及席位默认（R2） |
| 账号级管理员基础、最小管理只读入口 | 技能包导入、扫描、试用与动态技能管理（R3） |
| 会话绑定、统一解析、服务端内容缓存 | 连接器规范化、MCP 和多实例管理（R4） |
| 专业专家目录、详情、“与专家协作”及状态提示；原“新建对话”保持 | 后台 Profile 迁移（R5）；专家团、并行、嵌套（R6） |
| 兼容、状态控制测试、迁移及回退演练 | 普通用户个人创作、企业智能体部署：不在本阶段 |

**演示闭环：** 查看专业专家 → 点击“与专家协作” → 选择任务／个人空间 → 创建空会话 → 输入目标 → 按专家与技能工作 → 多轮续聊 → 刷新／重启仍使用原修订。该操作本身不调用模型。另验收“新建对话”无需从专业专家列表查找通用助手。

## 二、核心契约：修订、依赖与权限

### 2.1 修订是技术身份，releaseVersion 是正式发布版本号

| 字段／对象 | R1 约定 |
| --- | --- |
| expertId | 稳定资产标识；不使用名称作为唯一键 |
| revisionId | 不可变配置标识；会话绑定的主键依据 |
| releaseVersion | 面向用户的正式发布版本号；不作修订寻址键。R2 正式发布时按明确规则递增 |
| digest | 规范化专家定义及锁定依赖的 SHA-256；序列化规则固定 |
| ExpertRef | expertId + revisionId；配合 expectedDigest 校验选择未变化 |
| ExecutionManifest | 本次专家／技能修订、身份、模式、工具集合、模型配置与运行程序标识；不含秘密 |

R1 受控配置登记及兼容测试中，即使 releaseVersion 相同，不同内容仍必须生成不同 revisionId；R2 正式发布按规则生成新的 releaseVersion。内容哈希只证明一致性，不证明可信或安全。配置与权限分开存储；修改可用状态不改写发布内容。

### 2.2 没有网页发布，如何验证新旧修订？

R1 从受控内置定义登记修订，提供幂等的初始化／同步命令：相同来源与内容重复登记不产生重复记录；内容变化新增修订并更新“当前修订”指针。已有会话不改绑。

这是部署维护入口，不是普通用户上传入口，也不提前实现 R2 的网页发布流程。测试以受控提供器切换 r1/r2，验证 releaseVersion 相同时仍能正确隔离；正式发布版本生成规则在 R2 实现。

主专家声明的内置技能，登记时保存正文、元数据和摘要的不可变快照。修改 fixtures 中的技能文件不能影响已绑定会话；这只是固定技能兼容层，不扩展技能目录。用户另选同 ID 不同修订的技能时返回冲突，不静默覆盖专家依赖。

### 2.3 授权和状态

账号级 administrator 由离线管理命令显式授予／撤销，不由席位名或模型管理权推导。管理员只读入口展示登记与运行可用状态，不提供尚未建设的编辑按钮；普通用户访问管理接口返回 403。

能力准入复用原账号、席位、任务和工具检查，再与专家工具范围取交集。R1 仅提供最小受控使用范围，不建设完整可视化授权平台；独立后台服务仍走旧路径，不借机改变其权限。

## 三、运行装配与 T3 生效规则

### 3.1 每次请求的处理顺序

读取会话绑定 → 核对主体与空间 → 读取固定专家修订 → 组合锁定技能及本条选择 → 读取本轮工作区指令／资料 → 计算有效工具 → 保存执行清单 → 创建 Pi AgentSession → 执行与记录。

专家固定的是专业配置，不是用户历史、项目资料或整个运行环境。工作区指令继续每请求读取；主会话沿用模型选择，子任务继承父请求的模型快照。固定配置不保证模型输出逐字相同。

平台规则由代码维护，专家指令与工作区指令分区装配；不重复注入专业指令。保留 noSkills: true，skill_read 和显式技能选择都从本次正确快照读取。文件／来源内容不能增加工具权限。

### 3.2 更新、停用与撤权

| 操作 | 新会话／新请求 | 已接受请求 |
| --- | --- | --- |
| 登记新的当前修订 | 新会话默认新修订；旧会话继续原修订 | 内容不变 |
| 普通停用某资产或修订 | 拒绝受影响的“与专家协作”会话创建和新请求；历史仍可看 | 允许在原快照内收尾；不再接收追加输入 |
| 紧急封禁或撤销权限 | 拒绝受影响的新工作 | 先关闭调用准入，再传播取消；已产生效果不回滚 |

R1 实现状态服务方法、请求准入与调用守卫，并通过集成测试触发状态变更；正式网页停用／封禁操作在 R2 开放。普通停用的在途例外由服务端已登记请求识别，不凭客户端声明。

准入检查与活动请求登记在单进程内协调；每次工具真正执行前及等待确认后重新校验，紧急撤权后不能凭旧确认继续提交。已发送的外部调用可能不能撤销，保留结果并提示核对，不宣称“零副作用”。

### 3.3 内容缓存与观测

服务端按 revisionId + digest 缓存已校验的不可变内容，限制总量并淘汰闲置项；不把私有历史、工作区正文或某用户授权存入共享缓存。可用状态每次准入及调用时读取当前值，不被内容缓存延迟。

分别记录能力冷／热装载、上下文组装、模型首段输出与工具耗时；若适配层仅提供文本片段，不冒称精确首 Token。报告实测分位值、样本量和缓存命中率，不预填延迟指标。无需浏览器下载专家包或新增 Redis。

## 四、存储、接口与用户交互

### 4.1 最小存储与唯一真相

| 存储位置 | R1 保存内容 |
| --- | --- |
| capabilities.sqlite | 专家目录、不可变修订、内置技能快照引用、可用状态、创建意图及迁移登记；不预建后续所有表 |
| 只读内容存储 | 按摘要保存配套内容；先写完并校验，再提交数据库引用；未引用文件不得对用户开放 |
| 现有认证库 | 新增账号角色记录；保留原席位权限和全部既有 schema 兼容 |
| Pi 原生历史 | expert-binding 与 execution-manifest 等带 schemaVersion 的记录；聊天与工具证据仍只存一份 |

Pi 记录解释仅放在 src/pi。expert-binding 是会话级记录，不能被旧校验器当成必须带 requestId 的请求记录。资源记录、压缩与父子历史的解码均需回归。[B1、B2]

### 4.2 接口与创建一致性

| 接口 | R1 变更 |
| --- | --- |
| GET /api/capabilities/experts；GET /:id | 面向用户仅返回可选专业专家及详情，不包括系统内置的 Axon 通用助手和仅供委派的子角色；含模式、revisionId、releaseVersion、digest、依赖和可用原因 |
| POST /api/sessions | 沿用原参数，增加 expertRef、expectedDigest、clientActionId；前端所有创建入口接入 |
| GET /api/sessions/:id | 返回当前专家名称（含 Axon 通用助手）、releaseVersion、绑定修订及当前可用性；复用既有历史和 SSE |
| GET /api/admin/capabilities/summary（拟） | 管理员只读查看登记情况；不能据此读取他人会话或文件 |

服务端以“认证主体 + clientActionId”保存输入摘要和预分配会话 ID。同键同参数返回同一结果，同键异参数返回 409；重试先查原意图，不重新解析到最新修订；重新鉴权后才返回会话。新建时详情所选修订已被更新则返回 409 并提示刷新，不静默换版。R1 原“新建对话”未指定专家时仍绑定 Axon 通用助手，不要求出现在专业专家目录；R2 再接入默认专家优先级。旧入口可兼容缺少动作 ID，但不得宣称其具有幂等保障。

先登记创建意图，再持久化专家修订与原生会话绑定，最后发布工作区关联和完成回执。中断通过原意图核对；无法证明完整时保留现场并阻止续跑，不自动重发用户消息。

### 4.3 界面规则

只开放已实现的专业专家目录、详情和“与专家协作”；不展示 Axon 通用助手或只读子角色卡片，不显示未实现的创建／导入／专家团按钮。能力中心发起协作先选空间；任务内沿用当前空间，取消不建会话。原“新建对话”入口保持可用，且不经专家目录选择。重试沿用动作 ID，草稿和附件不自动发送。

会话头部显示当前专家名称（包括通用助手）、发布版本号及简短修订标识；提供新修订提示和“使用当前修订新建会话”，不迁移原历史。旧修订不可用时保留历史，阻止发送并说明原因。子 Agent 标签仍仅表示本条委派，不切换主专家。

## 七、旧数据兼容、迁移与回退

### 7.1 先确认旧数据，再写新格式

旧 workspace-index 对 skillIds 和字段结构有严格限制；本轮不把新专家或动态技能字段塞进旧索引。新绑定使用能力库及原生版本化记录，旧格式校验常量保留。[B2]

迁移清单明确列出合法旧会话。读取旧历史不写入、不伪造过去使用的专家修订；仅在用户明确发起后续请求时，为未来工作追加“通用助手（历史兼容）”绑定。新会话绑定丢失不能走这条兼容路径。

原 analyst/reviewer 继续按父请求固定角色内容，不增加并发、写权限或递归。现有 preprocess / continuous_analysis 与 seat_analysis 路径保持原身份和业务完成检查；R1 只做调用兼容，实际后台迁移留到 R5。[B4]

### 7.2 迁移与启动顺序

| 步骤 | 要求 |
| --- | --- |
| 检查 | dry-run 清点会话、角色、内置技能与数据模式，输出冲突；不调用模型 |
| 备份 | 停止服务后备份完整 LAB_DATA_DIR；记录基线程序和备份校验值 |
| 应用 | 分别迁移认证库与能力库，记录 prepared／completed；中断可用同一参数继续 |
| 初始化 | 幂等登记内置内容，保存旧会话清单；管理员仅显式授予，不能自动提权 |
| 启动与核对 | 存储完整后开放接口；未完成迁移阻断启动；检查旧历史、专业专家协作及通用“新建对话” |

单进程独占数据目录，测试与生产不得共用；不能在正在变化的数据目录上假定复制得到一致备份。只凭孤立原生文件不得猜测其工作区归属。[B1]

### 7.3 回退与失败恢复

回退使用升级前程序和匹配的完整备份；保留升级后新数据供核对，不直接用旧程序打开新格式。关闭功能入口不等于数据降级。

创建跨数据库与文件提交时，准备记录保存原绑定及会话 ID。可证明未提交或完整提交时按原 ID 恢复；其余状态显示待核对并保留证据，不自动另建会话。正文保存、工具写入或外部操作结果不明时，不用重跑来“修复”。
