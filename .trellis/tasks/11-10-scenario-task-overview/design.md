# P5 简洁方案：任务首页进展整合

v0.1 · 2026-11-10拟定；2026-11-11用户批准实施，原设计范围保留

## 1. 页面怎么调整

沿用点击侧边栏任务后进入的首页，保留“任务说明、相关信息、态势”三个页签。

首页从上到下为：**目标 → 当前研判／来报分析 → 工作进展 → 执行进展 → 新建对话**。有对应资料和权限才展示；没有执行能力的普通任务不出现空的执行大卡片。不增加总进度百分比、强制阶段、重复任务标题或常驻操作说明。

“相关信息”继续看原文、分析和关联依据；“态势”继续看地图、车辆和轨迹。首页只给必要入口，不复制两套列表或地图。

## 2. 各部分的信息从哪里来

| 部分 | 真实来源 | 如何呈现 | 本期需要新增什么 |
| --- | --- | --- | --- |
| 目标与说明 | 现有任务的 `goal / context / revision` | 保留原文预览、展开、编辑；首页短文只截取原文，不由AI重新概括，不把自由文本推断成结构化期限 | 调整现有布局与默认展示；不增加任务字段 |
| 当前研判／来报分析 | 优先读取现有“本任务已发布持续研判”；没有时，读取本席可见的最近关联来报及其已保存分析 | 持续研判保留版本和资料截至时间；后者明确标为“最近来报分析”，显示来报标题、接收/分析时间及详情入口，不能冒充整个任务最新结论 | 精简现有研判展示，并补关联分析入口；不新增模型调用、摘要存储或自动启用持续研判 |
| 工作进展 | 现有 WorkItem、工作台和已授权的工作总览 | 本席可办理/跟进工作优先；有工作总览权限时补跨席摘要，按工作ID去重。默认最多3条，其余进入原列表 | 任务内工作摘要与原详情跳转 |
| 文档与审核 | 工作附件、Submission、对应的验收/退回记录及文件hash | 文档作为所属工作的附件行显示；明确是哪次提交、是否验收。不是另建“最新批准方案”卡片 | 把获准附件和固定版本入口嵌入工作行；不建立任务共享文档库 |
| 执行进展 | Axon已接收指令的可信任务归属，以及外部模拟系统返回的逐车执行事实 | 展示待出发、途中、受阻、到场、取消等实际状态及业务时点；明细展开；有原指令核查权才出现完整指令详情入口 | **新增按任务、按来源权限过滤的只读执行摘要**，见下一节 |
| 新建对话 | 现有任务对话、模型选择和草稿机制 | 简化标题说明与输入框，继续创建本席私有对话 | 展示调整；保留模型选择、草稿和错误反馈 |

分析正文过长时使用原文预览和展开，不调用LLM生成“首页摘要”。多个持续研判配置各自保留出处，不拼成一条新的综合结论。关联来报按现有接收顺序呈现，旧观测晚到不因此覆盖持续研判或当前来源事实。

## 3. 两个需要特别说明的边界

### 工作与文档：沿用已有权限

- 参与者可以进入原工作详情，按既有权限查看附件、提交和审核意见。
- 有“工作总览”权限但不是参与者，只显示现有获准摘要：标题、双方席位、状态、更新时间等；不返回附件名称/正文、审核意见或私有会话。
- 没有工作总览权限，只显示本席可读工作。公共任务不意味着其内部工作和文档自动公开，也不为P5默认授予全席总览权限。
- 不能凭文件名、时间先后或聊天文字认定“总体席已认可”“已经交给控制席”；只能引用真实提交、审核和分派记录。无法证明跨工作文件关系时分别显示，不拼接出完整流程。

因此，示意图中的文档行和跨席状态需要按访问者权限收敛，不能给所有席位显示同样的详情。

### 执行摘要：新增只读视图，不放开指令权限

当前完整指令记录仅允许获授权的原下达席核查，其他业务席不能直接复用该接口读取。为了让任务参与席了解车辆进展，本期拟新增有限的只读摘要：

1. 宿主从实际任务及已接收指令确定归属，不凭来报正文、车辆名称、目标区域猜关联。只纳入已有外部执行事实的派遣，准备、接收不明和拒绝不等于已经发车。
2. 访问者必须有该任务的读取权及对应态势来源的现行读取权限；服务端逐项过滤，不能通过首页扩大来源范围。只允许观察的账号也不因此获得业务办理权。
3. 返回获准车辆名称/引用、状态、目的地、来源业务时点及必要的执行原因；不返回控制席草稿、内部确认内容、文件附件、私有会话或账号审计字段。不显示轮次术语。
4. 当前状态从外部模拟系统读取，Axon只整理展示。复用现有执行查询、来源身份与数据契约，不新增推演规则、执行数据库或结果状态机。
5. 按原派遣归并改道/取消记录，同一车辆不因多个操作重复计数。不同派遣中的同一车辆取可证明的现行归属；归属不清时列为待核实。到场仍是占用，取消不等于归队或火情结束。
6. 多车组分别保留查询业务时点。只有完整、同一业务时点且已去重的结果才能汇总总数；缺失、超限或查询失败显示未查全，不能显示“全部到场”。读取按现有上限分批，不截断后报总数。
7. 普通席只能看获准摘要及来源信息/态势入口；原下达控制席继续进入现有指令详情办理。新增摘要不向Agent自动注入资料，不开放下达工具。

该摘要的跨席读取是用户本次批准的新增范围；原指令和来源查询权限仍分别校验。

## 4. 刷新和异常

- 只在首页可见时读取；进入、恢复可见及本页办理成功后刷新。默认复用现有低频查询方式，首页执行摘要约每10个现实秒更新；需要观察车辆移动时进入已有态势页，保留其演示地图每秒读取机制。
- 各区独立读取和报错，显示自己的时间；不宣称目标、分析、工作及执行来自同一个全局快照。
- 加载采用现有加载组件。失败保留上次内容并标明更新失败；撤权后移除原内容并禁用相关入口，不能继续显示缓存中的敏感数据。
- 新任务、无分析、无工作、无执行分别按真实情况呈现，使用一行必要空态。读取失败不写成“暂无”。归档/旧演示只读；无历史执行查询能力时仅呈现明确标注的已保存记录，不以当前世界补写历史。
- 详情复用现有侧栏/面板，支持关闭按钮、空白处关闭和Escape；关闭回到原任务与阅读位置。

## 5. 新增工作量与明确后置

**新增主要有两块：任务内工作/附件摘要，以及服务端只读执行摘要。** 其余为现有说明、研判、相关信息、对话和导航的布局与交互整合。后端拟只补一个任务执行摘要读取入口，复用原数据，不建设通用聚合平台。

不新增方案实体、硬审批门禁、自动业务阶段、自动再研判或自动改派。地图关注范围问题SIM-MAP-001、无来源任务归属SIM-TASK-002、分步再研判SIM-COMMAND-001继续后置；不借P5顺带实施。

不修改存量任务、工作、文件、指令和场景数据，不为新页面回填历史；不新增数据库表及业务写接口。

## 6. 怎么验收

- 从首页看清真实目标、获准分析、工作和执行现状；任一摘要都能追溯其原记录。
- 总体席、控制席、普通业务席及只读观察者按现有权限看到不同入口，不能通过新摘要越权查文件或操作指令。
- 验证正常到场、受阻、改道、取消及中途重演；核对重复车辆、多指令、部分查询失败和旧分析不冒充新事实。
- 页面不调用模型、不发送指令、不推进场景，业务办理仍在原入口显式确认。
- 用户批准后在服务器执行工程与桌面交互验证并保留结果；P5通过不等于模型语义已零错误，也不代替P6最终业务验收。
