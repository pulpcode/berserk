## 3. 实现时的关键检查

- 在 prompt 前订阅 compaction_start／compaction_end，以每会话独立标记区分摘要调用；标记不依赖网页是否在线或当前 UI 阶段。
- 默认摘要经 agent.streamFunction 调用。摘要不注入完整 AGENTS 提醒或新增提示，正常回答仍使用本次固定快照；两类调用都经过取消、用量记录与错误清洗，摘要的原生输出额度不被回复包装覆盖。
- src/server/config.ts、model-settings.ts、src/pi/lab.ts 和配置模板同步改造：C/M 与运行控制分别解析，旧实验环境键只提示迁移；公开 limits 与页面同步，保留用户配置文件。
- 默认没有整轮调用次数和总时长上限；可选总时限覆盖全部阶段。模型空闲／单次请求超时接入 Pi 对应配置，工具可选超时由宿主定义；超时错误返回模型，写效果未知则停止核对。
- 使用 Pi 原生瞬时重试默认值，最多额外 3 次，适用于回答和摘要；provider 重试为 0。错误清洗保留安全分类，使重试和溢出识别可用。
- 最终失败先关闭模型／工具准入，再取消；外层等待完整 session.abort()，事件回调不等待自身 idle。
- 原生溢出恢复期间的临时错误不能提前结束整个请求；不重新 prompt 原输入，最终只有一个请求终态。
- 同请求多次压缩、长单轮双摘要、重试和恢复全部记录次数及用量，不以计数阻断正常工作；usage 缺失标未知，不重复累计成功摘要。
- 摘要由 Pi 保存；项目只关联新条目 ID，不能按摘要文字匹配或再次 append。失败写盘后停用污染 manager，finally 不向其写终态。
- 历史从原始 branch 展示；已有指令编辑、资料工具和工作区隔离按原契约回归。
