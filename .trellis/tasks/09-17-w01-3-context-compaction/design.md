# W01-3 设计：Pi 默认上下文压缩

日期：2026-09-17。状态：**已实现并通过验收，待提交**。范围见 [PRD](prd.md)，技术依据见 [Pi 研究](research/pi-compaction.md) 与 [模型及运行控制研究](research/model-budget.md)。

## 1. 压缩如何发生

用户正常发送消息。服务端固定本次工作区、模型配置和完整 AGENTS.md 指令，交给 Pi 处理。Pi 判断需要压缩时，生成旧历史摘要，再使用摘要和近期消息继续回答或工具循环。网页显示“正在压缩上下文”，原始聊天记录保持原样。

### 检查时机

指程序在什么位置判断是否需要压缩：新用户请求进入前、工具返回且准备下一次回答时，以及原生 Agent 运行结束后。检查不等于一定压缩，达到原生阈值才执行。这不是 checkpoint；压缩成功后保存的摘要及保留边界，才是后续重建上下文的记录。

### 摘要范围与原文保留起点

Pi 按近期内容量选择分界位置。例如消息 1～80 生成摘要、81～100 保留原文，81 就是原文保留起点（原生字段 firstKeptEntryId，也称切点）。本次保留区不参与本次摘要，后续变旧时可以进入下一次摘要范围。

正常按回合边界划分；特别长的一轮可以压缩前半段、保留后半段，不拆散工具调用与结果。因此近期保留量不等于固定保留几轮。

### 一次溢出恢复

模型出现 Pi 可识别的上下文超限等可恢复情况时，Pi 可以先压缩，再继续原来的处理一次；恢复仍失败则结束。限制的是这次错误的恢复尝试，整个会话可以多次正常压缩。恢复不重新发送整条用户消息，也不从头重跑工具链。

## 2. 摘要、指令与原文

| 内容 | 本期处理 |
| --- | --- |
| 历史摘要 | 使用 Pi 默认提示词、文本格式和序列化；不增加项目压缩要求 |
| 近期保留消息 | 原文进入后续上下文，由 Pi 维护摘要范围与保留起点 |
| 当前 AGENTS.md | 沿用现有工作区加载及每请求快照，独立参与正常模型调用，不由摘要替代 |
| 原始历史 | 保存在原生 JSONL，网页继续展示完整消息和工具结果 |

Pi 默认摘要保留目标、约束、进展、决策、下一步和必要背景；再次压缩会综合上一摘要与新增历史，不把全部旧摘要一起发送。长单轮可能生成两个摘要调用，但最终保存一条压缩记录。

当前 AGENTS.md 全文不作为摘要对象，也不向摘要模型注入完整回答提醒。旧历史中曾出现的指令正文仍属于历史材料，不能恢复已经删除的规则。正常回答与压缩后的接续都使用本请求固定快照，下一请求才加载文件更新。

Pi 序列化摘要输入时，每条工具结果最多保留前 2,000 个 JavaScript 字符并附截短标记；磁盘和网页上的原始结果不因此截短。摘要不能代替已保存文件和工具执行记录，实际续作质量通过验收确认。

关键项目数据的专门保存与按需加载后置。未来可让已经独立保存的数据直接参与上下文组装，不依赖摘要保留；数据范围、版本和加载规则随具体需求设计，本期不实现自动提取或固定数据区。

## 3. Pi 接入与调用控制

保持 Pi 0.85.1，直接开启 AgentSession 的默认自动压缩。AgentSession 是 Pi 的会话运行对象，负责模型／工具循环、上下文和压缩；本项目每次用户请求创建该对象并连接已有历史，请求结束后释放，网页会话与历史继续保留。目录扩展发现保持关闭，本期不注册自定义摘要扩展，不修改内核、不直接调用内部压缩函数。

1. 沿用同会话活动占位和资源快照，在调用 prompt 前订阅 Pi 事件；用户输入只 prompt 一次。
2. 在 compaction_start 同步设置本会话独立的摘要调用标记，在 compaction_end 清除。该标记与网页是否在线、当前查看哪个项目无关；每次流调用开始时固定其用途，清理时重置。
3. Pi 默认摘要使用 agent.streamFunction。现有受控流据用途分为 reply／compaction：回答注入当前 AGENTS 提醒；摘要保留 Pi 原生 Context，不加提示词、指令小节或工具 schema。
4. 两类调用共用认证、提供方选项、错误清洗、取消和用量记录；分别采用正常回答与原生摘要的输出额度，不设置累计调用次数上限。摘要返回须为完整、非空文本且无 toolCall；保留 Pi 对 error／length 的处理，不要求固定 JSON 字段。
5. Pi 负责追加摘要与重建当前上下文。项目只关联新保存的条目 ID、映射状态，不再次 append 或重新创建会话来模拟接续。

Pi 的压缩失败事件不保证宿主请求已经终止。最终失败时先记录原因、禁止新模型和工具调用，再传播取消；模型入口与 beforeToolCall 均检查终止标记。事件回调只发出停止信号，外层等待完整 session.abort()，避免等待自身结束。

## 4. 模型参数与运行限制

### 模型设置

复用当前模型设置窗口和 `/api/settings/model`，增加以下字段：

| 字段 | 含义与缺省 |
| --- | --- |
| contextWindow（C） | 模型输入与输出合计容量；官方 deepseek-flash 按已核对 1M 规格配置为 1,000,000，其他模型需可信映射或用户填写 |
| maxOutputTokens（M） | 当前模型部署支持的最大输出量；来自相同提供方／模型／端点的可信映射或用户填写，不使用实验输出额度冒充模型能力 |
| compactionReserveTokens（R） | Pi 判断接近容量时的预留量；当前默认 DeepSeek 使用 16,384 |
| compactionKeepRecentTokens（K） | 近期保留原文的近似 token 数；当前默认 DeepSeek 使用 20,000 |

R/K 放在可展开的高级参数中。原生触发规则是 `contextTokens > C - R`。Pi 使用最近一次模型响应的 token 用量统计，并估算随后新增的内容，判断是否需要压缩；估算可能与实际输入不同，超限时再按原生机制尝试恢复。完整指令、工具定义、提醒和输出仍消耗实际容量。

容量支持 8,192～2,000,000；M/R/K 为正整数，要求 M≤C 且 R+K<C。M 是输出能力上限，R 是压缩触发预留量，不要求 M≤R；实际生成额度还须适配剩余上下文。缺省的小窗口参数取 `R=min(16384,floor(C/4))`、`K=min(20000,floor((C-R)/2))`。不满足条件时提示调整。这些校验与小窗口缺省值属于项目配置规则，压缩触发和摘要范围仍由 Pi 决定。

### 配置兼容

- GET 返回解析后的数字，C/M 及不能派生的参数未知时为 null；contextSource 和 outputSource 各为 preset／explicit／unknown。contextReady 表示 C/M/R/K 完整且合法，与密钥是否配置分开。
- PUT 字段可省略、显式值须为整数；同模型身份保留省略项，换 provider／model／规范化端点时重新解析，不继承旧模型的容量与输出能力。拒绝 null。
- 持久配置读取 v1、显式保存时升级 v2。新增可选 LLM_CONTEXT_WINDOW 和 LLM_MAX_OUTPUT_TOKENS；已有 v2 优先，v1 仅在环境模型身份一致时用环境值补缺，其余按映射或 unknown 处理。
- C/M 未知时可查看历史，发送前同步提示补填，不占位、不写消息、保留草稿；配置后用户自行发送。原有版本冲突、空闲保存、密钥保留和文件权限不变，不改写 .env.local。

### 持续执行与超时

一次用户请求包含本轮全部模型、工具、摘要和恢复工作。默认不设整轮工具次数、模型调用次数或总时长上限；有正常工作时继续执行，完成、用户停止或最终失败时结束。当前串行工具策略不变，调用次数仅用于观测。

| 范围 | 配置及行为 |
| --- | --- |
| 模型连接／流空闲 | LLM_HTTP_IDLE_TIMEOUT_MS 默认 300,000 毫秒，0 关闭；宿主按HTTP 响应数据进展重置空闲计时（包括 SSE 心跳）。Pi 0.85.1 的 httpIdleTimeoutMs 在默认流中转为调用时限，本项目覆盖 streamFunction 后单独保证空闲语义；持续产生数据不会因超过该时长而停止 |
| 单次模型调用 | 可选 LLM_REQUEST_TIMEOUT_MS 映射 Pi retry.provider.timeoutMs；未设置沿用提供方 SDK 默认，设置时为正整数。只约束当前模型调用，不作为整轮任务总时限 |
| 单次工具调用 | 由宿主工具定义可选 timeoutMs，模型不可改写。现有本地资料／指令／Skill 工具默认不增加统一计时器，未来远程工具按自身操作设置；仍响应用户停止 |
| 整轮任务 | AGENT_RUN_TIMEOUT_MS 默认 0，不启动总时限计时器；显式正值从接受本次用户请求开始计时，涵盖准备、模型、工具、摘要、重试和恢复，不因进展重置 |

以上时长均以毫秒计，显式值须是计时器可表达的安全整数；负数、非法数值或溢出值拒绝启动，不静默截断。环境配置只控制服务端，本期不增加运行控制设置页面。

工具超时先取消该调用，待工具收敛后返回明确错误；没有未决写效果时，模型可以据此调整下一步，不直接终止整轮任务。写入结果未知时先停止并核对效果，不自动重做。工具不响应取消时不能虚报已停止或释放仍在工作的执行上下文。

### 输出、重试与用量

注册 Pi 模型时使用真实 C 和 M。正常回答采用 Pi 按模型能力和剩余上下文计算的输出额度；摘要保留 Pi 传入的 maxTokens，不再被统一实验输出值覆盖。Pi 主摘要采用 `min(floor(0.8*R),M)`，长单轮前缀摘要采用 `min(floor(0.5*R),M)`，提供方适配层仍可按剩余上下文收缩额度。达到输出上限不等于回答完整，摘要截断须明确失败。

启用 Pi 原生瞬时错误重试，沿用默认最多额外 3 次、基础等待 2 秒；provider 层重试为 0。该次数针对一次失败调用的重试，不扣减正常工具循环额度。认证、额度、用户取消、输出截断和非法摘要不额外添加宿主重试；上下文溢出按原生机制尝试压缩恢复一次。安全错误分类保留，最终失败关闭后续调用；若配置整轮时限，所有重试和恢复都受该截止时间约束。

回答、双摘要、重试和恢复均记录模型尝试与用量。usage 有响应才按实际记录，缺失标未知；请求汇总和成功摘要用量是同一批调用的不同视图，不重复相加。计数用于观测，本期不增加费用额度、累计调用次数上限或重复循环检测插件。

### 旧实验配置与测试

REQUEST_TIMEOUT_MS、MAX_TOOL_CALLS 和 MAX_OUTPUT_TOKENS 退出运行配置；不新增 MAX_MODEL_CALLS_PER_REQUEST。启动时如发现这些旧键，仅列键名并说明迁移方式，不继续执行旧限额，也不自动改写用户文件。需要整轮时限时显式设置 AGENT_RUN_TIMEOUT_MS；模型输出能力通过模型设置或 LLM_MAX_OUTPUT_TOKENS 配置，不将旧实验输出值自动迁移为模型能力。

实施时同步配置模板、README、公开 limits 投影和页面消费；无总时限显示为未设置，不以 0 次调用或 0 token 冒充无限。旧数值测试改为新语义，另用确定性任务验证跨过原有次数和时长边界仍能完成。

压缩测试用独立配置增大 R、缩小 K 提前触发，C/M 保持真实。真实探针可独立配置总时限控制实验结束，不将探针设置写回产品默认，也不增加 10 条验收总量限制。

## 5. 停止与失败

| 情况 | 处理 |
| --- | --- |
| 压缩成功 | 保存摘要，继续本次回答或工具循环 |
| 瞬时模型错误／模型调用超时 | 由 Pi 原生分类决定是否重试，瞬时错误最多额外 3 次；最终失败明确结束，停止可取消等待 |
| 可恢复上下文超限 | 压缩后继续一次；仍失败或无法压缩则明确结束 |
| 摘要最终失败／为空／截断 | 显示原因，保留原历史和已有摘要，停止后续调用 |
| 工具超时 | 取消并等待该调用收敛，返回错误供模型处理；写效果未知时停止并核对 |
| 用户停止／显式整轮时限到期 | 先关闭调用准入，传播请求信号并调用完整 session.abort()，收敛后释放会话 |
| 摘要写盘失败 | 停用当前不可信 manager，禁止 finally 继续写入，严格重读并保留证据 |

取消在原生追加前被观察到就不提交；追加成功后再取消则保留完整摘要。已经保存的文件不回滚，未决写效果沿用现有核对规则。

普通取消或压缩失败后，新用户输入重新检查上下文，不自动补发上条消息。若原文损坏、上次请求异常中断或效果不确定，沿用 recoveryWarning 提示，不承诺自动恢复。权限、expectedHash 和 unchanged 检查继续约束工具，摘要不能代替实际效果核对。

## 6. 保存、页面与兼容

### 原生保存

原始消息保存在 LAB_DATA_DIR/sessions/下的 Pi JSONL。Pi 追加 CompactionEntry，保存 summary、firstKeptEntryId、tokensBefore、原生 details 和可获得 usage；项目不改写这些字段的语义。

现有请求结果增加可选 compactionIds、压缩事件元信息和 usageSummary，用于关联本次多条摘要、模型／配置版本及触发原因。ID 取本次新增条目，不能按摘要文字相等匹配。异常退出没有完整请求结果时，缺失元信息标为未知，不能编造归属或成功终态。

网页从 getBranch 展示原始记录；模型由 Pi 使用最近摘要和保留消息重建。打开文件前沿用逐行严格校验，同时检查原文中的未完成请求，不能让摘要遮蔽中断。无压缩旧会话与合法原生压缩记录均可读取；损坏的摘要或保留边界拒绝续跑。

### 页面与接口

- RequestState.phase 增加 compacting，当前回复区及跨项目活动列表显示压缩状态，stopping 优先；恢复后回到 generating／tool。
- SSE 增加 context.compaction_started／completed；失败使用已有请求终态。恢复中的临时模型错误不能提前结束整个请求，最终只产生一个终态。
- SessionSnapshot 返回最近压缩概要；`GET /api/sessions/:id/compactions/:compactionId`只读返回本会话摘要及边界，拒绝其他会话的 ID，不触发模型调用。
- 会话提供“查看最近压缩摘要”入口，原文仍在聊天中查看；每请求的指令、Skill 与用量记录保留在后台用于排查，不提供面向用户的逐轮资料面板。前后估算与实际 usage 分开标注，缺失显示未知，不提供压缩要求编辑或逐项原文检索。
- 沿用 requestId／revision 处理刷新、切换和迟到事件；未入库输入保留草稿，已入库消息不补发。单纯摘要成功不产生未读蓝点。

### 重启与回退

正常完成并保存后可重启续聊。处理中异常退出，包括摘要已写但请求尚未完整结束，保留记录并按现有 recoveryWarning 提示；正式崩溃恢复在 S3。

Pi 同步追加不是数据库事务或断电安全保证。开发测试用独立目录；接入活动目录前停服备份整个 LAB_DATA_DIR。代码回退只使用升级前备份目录，保留新历史，不让旧版写已升级配置或记录。

具体开发位置与检查见 [实施方案](implement.md)。可配置摘要要求、手动压缩、关键项目数据管理和历史检索后续单独设计。
