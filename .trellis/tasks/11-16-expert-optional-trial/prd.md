# 专家试用改为可选

## Goal
让组织专家在满足配置与发布条件后直接发布，试用作为可选的效果验证步骤，与 Skill 保持一致。

## Background and approval
- 用户先要求方案审阅，随后明确选择“专家试用改为可选，与 Skill 保持一致”，并在完整方案呈现后回复“开始执行”。该回复授权创建独立 worktree、任务及按方案实现；不包含部署或推送授权。
- 固定基线：codex/axon-r3a @ 1e99845e91b62f30c966baa25d9bf9de3756808b。本分支 codex/expert-optional-trial，隔离原 R3A worktree 的未提交改动。
- 已只读核对 4316 健康、监听进程和发布相关三份源码 hash 与基线一致；本次只做本地实现。

## Requirements
R1. 未试用、失败、取消、中断、运行中或成功待确认，都不单独阻止发布。保留真实试用结果，不伪造通过。
R2. 保存的当前草稿有效校验、依赖有效性、配置风险逐项确认、有效使用范围、发布说明及页面管理员发布确认仍必需。权限、CAS、原子提交、幂等和会话固定版本保持原约束。
R3. 文件工具取消发布前必须成功验证文件执行环境的条件；保留工具风险确认及运行时的执行环境和权限检查。
R4. 试用仍需管理员显式启动并实际调用原隔离 Pi 运行器；结果确认及历史查询继续可用。
R5. 请求中的 trialId 和新发布记录中的 trialId 可选；有引用时仍核对归属、当前草稿/校验、成功及管理员确认。无合格引用的发布不得生成假试用证据。
R6. 页面明确“隔离试用（可选）”，发布确认改为“我已核对配置和使用范围，确认发布。”，不再因无合格试用禁用发布。同步相关强制试用文案。
R7. 保留历史发布/试用数据和旧请求兼容性，不做表结构迁移；Skill 规则不变。

## Acceptance criteria
AC1 (R1/R3/R6): 全新无试用专家及含文件工具专家可从 API/桌面页面发布；发布本身不调用模型。
AC2 (R1/R4): 当前草稿存在失败/取消/中断/运行中/未确认试用时仍可不携带引用发布；记录保持真实。可选试用及确认流程正常。
AC3 (R2): 无权限、校验缺失/过期、依赖不可用、风险未确认、使用范围未开放、说明为空等仍被阻止；并发和重试不产生重复版本。
AC4 (R5/R7): 合格旧格式 trialId 可关联发布；伪造/跨专家/其他用户/旧草稿/不成功/不确认的显式引用被拒绝；新旧发布记录重启后可读。
AC5 (R2/R7): 已有会话固定原配置，新会话选择新版本；Skill 发布和历史读取回归通过。
AC6: typecheck、lint/boundaries、build、相关服务/API/试用/历史测试及桌面浏览器验证通过。实模和 Docker 物理验证不由 mock 结果替代。

## Out of scope
不改 Skill 发布规则、Pi 执行内核、试用隔离/确认机制、模型、业务权限、默认专家或移动端；不新增配置开关、跳过审批流、试用状态表或恢复机制；不合入原 R3A 未提交修改，不更新线上服务。
