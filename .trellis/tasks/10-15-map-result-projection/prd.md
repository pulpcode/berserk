# 地图工具模型结果与界面回执分离

2026-10-15 · 用户已批准修订方案，实施及复测完成，整体说明/泛化验收未通过，待审阅结果。产品基线：`efe2fb6`。

## 目标

保留现有程序生成地图入口的机制，分开模型所需结果与界面原始回执，减少正文无必要的 hash 转述；通过现有查询参数和计数语义帮助 Agent 理解读取范围。保留现有桌面对话与地图布局，回答改善以实际复测为准。

## 设计时已确认事实（基线状态）

- 上轮原场景 7 个环境、45 个请求，操作通过，三条协同链未再混淆草稿基线与任务当前；但有 4 条最终回答错误：一次将对象筛选结果说成整个版本，两次错误 hash 缩写，一次添加回执并不存在的 `committed=true`。见 [原验证报告](../10-14-map-result-reporting/base-current-validation.md)。不改写该结论。
- `experiments/harness-lab/src/pi/annotation-tools.ts:74` 将整个服务结果写入模型 `content`，`details` 为空；同包 `src/web/situation/evidence.ts:67` 又从这段文本提取界面入口。因此模型与界面当前消费同一份 JSON。
- 同包 `src/annotations/service.ts:172` 先筛选对象再分页，`objects.total` 表示筛选范围内总数；返回值没有回显对象/字段筛选条件，但模型已可看到自己的调用参数。原 B02 两个版本实际均含甲乙，模型分别只读甲、读取甲乙后，额外得出了错误的全版对象集合结论；不能直接把该错误归因于缺少参数回显。
- Pi 0.85.1 原生支持给模型的 `content` 与用于日志/界面的 `details` 分开。当前地图入口已由程序生成，无须要求模型再输出 URL 或另调一个“生成引用”工具。

## 需求与验收映射

| ID | 需求 | 可观察验收标准 |
| --- | --- | --- |
| R1 | 同一次真实执行产生模型结果和界面回执两份表达 | 现有地图入口改从原生结果的结构化回执取值，保持原行为；前后均不依赖助手输出链接，不能靠助手编造 ref/URL 生成成功入口 |
| R2 | 减少无业务需要的精确数据转述 | 新标注工具结果及新显式标注引用默认不向模型提供内容校验 hash；服务、宿主校验和原始回执保留 hash。模型保留继续操作所需固定引用、业务字段及恢复信息 |
| R3 | 澄清通用查询语义 | 成功读取的 draft/read 结果用 query 回显原 objectIds/layerIds/fields，保留 total 与分页字段；原用例及不同图层/分页/字段案例分别检查返回契约和模型解释，未查部分不能断言不存在或为空 |
| R4 | 保持现有语义与保护机制 | baseRef 与任务当前继续区分；创建/编辑/来源复制/发布/采用、权限、CAS、幂等及不确定结果恢复行为不变；未读或被替换的工具结果不能制造可写依据 |
| R5 | 新旧历史与实时显示一致 | 实时完成、刷新、重开、续聊的入口指向相同固定版本；旧回执仍可查看，新格式缺失/损坏时不伪造成功；重放/查旧回执标为原动作结果 |
| R6 | 用原场景判断改善并检查泛化 | 按 [验收安排](implement.md#原场景复测) 固定运行原场景和独立只读泛化案例，保留全部失败；分别报告操作、界面入口、回答准确性和效率。不能用按钮正确代替正文正确 |

## 范围

仅改标注工具的结果表达、相应 Pi/Web 传递与历史兼容、新显式标注引用的模型表达，以及查询范围说明。复用已有地图按钮、服务回执、权限与原生会话记录。

不增加结果卡片、对比面板、姓名解析服务、自动答案审核或第二个解释模型；不改来源系统、MCP、模型配置、业务工具操作分支和三栏布局；不为每次保存追加全局查询或读回；不扩展手机端。本轮已获准实施及隔离真实模型验收，不包含部署或推送。

## 已确定的取舍

- 精确 `ref` 仍可在工具结果中交给模型作为后续调用参数，但不要求模型在正文再抄一遍；“减少转述”不等于删除全部 ID。
- 界面入口证明一次实际操作及其固定版本，不自动证明助手每句话。备注比较等业务解释仍由模型完成，本期不建设通用字段对比 UI。
- 查询范围关键语义直接放在结果与工具说明中，不依赖可选 Skill。旧版 baseRef/current 关键说明继续自动投放。
- 模型接收数据裁剪和参数回显，仍自行理解并组织语言；程序不硬性禁止错误解释或编造。保留 total 的现有名称，不增加专用范围分类，不将甲乙案例变成提示词补丁。
- 旧历史不重写，旧回答中已有的错误不会被此次改造自动纠正；复测使用全新隔离会话，并另验旧历史兼容。

用户已批准上述范围。详细接口选择见 [design.md](design.md)，实际完成情况另记 implementation.md、validation.md 与 semantic-review.md。
