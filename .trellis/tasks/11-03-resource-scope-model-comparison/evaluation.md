## 2. 数据准备方式

复用上一轮[题包](../11-03-resource-independent-acceptance/cases.md)及真实fixtures：来源放在隔离HTTP来源服务，标绘通过现有服务创建，副本真实受控导入，显式引用由桌面浏览器正常发送。模型收到正常目录、引用摘要和实际查询结果。

不把完整事实表、预期、评分或隐藏用户偏好注入模型上下文。地名和坐标均为合成测试材料。D01—D05保留原题事实和必要问题，只允许隔离ID、实际版本和业务时间按旧公式重建并留映射；D03仅增加评测侧边界确认，不提前注入。查询时间和版本时间取实际响应。

## 3. 四项公开流程检查

| 流程 | 用户任务与实际数据 | 验证内容 |
| --- | --- | --- |
| P01，A/B各一次 | 引用测试图层：层内两点、另层一点；询问引用层名称坐标，再问“沿用刚才的固定图层再列一次” | 真实引用发送、按引用或等价正确读取、固定范围续用、结果展示；不带入另一层 |
| P02，A/B各一次 | 两个同名区域，要求一个区域内资源、边界单列；冻结选择东侧，也预备“边界就是边界线”的确认 | 真实追问后接续完成，兼容文本/API；一次问多件事时逐问回复 |

两种接续渠道、多问及错误questionId等分支先用确定性离线脚本覆盖，不要求模型恰好问出两问。P01没用新入口时另记覆盖不足，不能凭答对宣称入口经模型验证。

流程通过指发送、接续、取数、记录和评分链路有效，不要求业务全对。业务失败照实记录，可继续计划内诊断；接口、接续、用量或证据失真则暂停。若须修改冻结材料，保留原尝试并另行审阅恢复，不自动补跑公开题。

## 4. 六道诊断题

### D01：五辆车与一个标绘副本（沿用N02）

**用户问题：**把“鹭桥车籍”的“晨组车辆汇总”和“暮组车辆汇总”去重，给我车辆名称名单和数量。图层里引用的“沄桥运输车副本”也要核对，别重复算同一辆。

**实际数据：**同来源、同时间、同数量含义及范围。晨组 `{e17,e26,e39}`，暮组 `{e26,e39,e48,e56}`，成员完整；5个单体提供身份与名称映射。副本由e17单体真实导入。来源共7条对象记录，标绘只有1个副本；实际ID沿用旧N02前缀。

**预期：**沄桥、澄砾、榆汀、荻石、岚湾运输车，共5辆；说明两个重叠成员和副本身份。不是7辆、8个实体或6个标绘对象。

**评分：**主任务检查名称、数量和副本不重复；解释检查对象类型与依据，包括附加建议中的事实。允许等价查询完成，未调用资源统计工具不扣业务分；工具覆盖另记。

### D02：实际位置与时间，不能多说错或漏答（沿用N05）

**用户问题：**按实际位置统计我引用的“鹤砾矩形”内车辆和舟艇，边界及没有可判定实际位置的资源分别列出；同时说明每项的数据时间、读取时间和统计范围。站址、计划位置不能当成员实际位置。

**实际数据：**矩形 `R(121.00,31.00,121.04,31.04)`；沿用N05全表：车辆聚合4辆及4个单体，另1计划位；舟艇聚合4艘、3个单体，第四个只有成员ID。聚合点是站址，浦灯只有估计位置。两来源各有不同scope、快照和业务时间，queriedAt取真实查询。

**预期：**车辆内部青芒1、边界银菰1、外部赭砂1、无实际位置紫苇1；舟艇内部鹭纹1、边界荻帆1、无实际位置浦灯及lt-e81共2。站址不代表成员位置，计划位不算实际资源。未知位置项也需时间或明确共用时间映射；lt-e81沿用成员依据时间，不造单体时间。

**评分：**主任务检查必要集合、各组数量、时间和范围是否答全；解释检查asOf、业务时间、queriedAt、标绘版本时间未混用。若说明处理数量，须区分车辆来源6条原记录与工具剔除计划后的5条，不能再次扣计划。漏掉用户要求的时间不能换取解释高分。

### D03：范围真的不明确，先问再算（沿用N06）

**用户问题：**查北区内本任务可用资源，边界单列。

**实际数据：**引用层有两个同名北区。西区 `R(121.00,31.00,121.04,31.04)`，东区 `R(121.06,31.00,121.10,31.04)`，注记可区分。沿用N06资源：东内部檀浦、雀榆，边界萤湾；西内部榕荫、边界池杉，另有故障苍苔；均有任务分配证据。

**冻结回复，仅被问到时发送：**

| 实际问题 | 可用回复 |
| --- | --- |
| 选哪个北区 | 选东侧北区，经度121.06到121.10、纬度31.00到31.04的那个。 |
| 确认“边界单列”的含义 | 是，指区域边界线上的资源，与严格内部的资源分开列出。 |

**预期：**先帮助区分并等待选择，收到东侧回复后完成内部2辆、边界1辆。若先只问边界，回复边界后仍需澄清区域，不能提前补发东侧偏好。

**评分：**主任务要求澄清、实际收到回复并完成；关键约束禁止先完成双区业务统计再问。读取候选区域本身不违规。边界确认不算新业务任务或默认失败，另记是否多余；未收到答复与收到后答错分开归因。

### D04：明确比较，不能强迫单选（沿用N07）

**用户问题：**两个北区分别有哪些可用资源？请比较，内部和边界分开说明，不需要把两区合成一个总数。

**实际数据：**西区 `R(121.00,31.00,121.04,31.04)`，东区 `R(121.02,31.00,121.06,31.04)`；沿用N07的7个单体。青菱 `[121.02,31.03]` 对西区是内部、对东区是边界。全部可用，任务关系未确认，题目不要求已分配。

**预期：**西内部石芽、鹭羽、青菱3辆，边界苇穗1辆；东内部鹭羽、砂汀2辆，边界青菱、霜菊2辆。说明共享成员及分类差异，不强迫单选，不以合计代替比较。

**评分：**名单、数量和比较关系均为主任务；前表正确、后文又说青菱“两区都边界”，仍判事实错误和主任务失败。不能因任务关系未知而排除用户要比较的资源。

### D05：固定图层两轮问答，不扩大到别处（沿用N08）

**首问：**只看我引用的“沚灯现场图层”中的实际资源，告诉我有哪些、分别在哪里。

**次问：**同一图层全部点分别在哪里？

**实际数据：**目标层4点：白砾观察点 `[121.011,31.013]`、芦影计划泊位 `[121.019,31.021]`、沚灯运输车 `[121.027,31.029]`、菰湾救生艇 `[121.035,31.037]`。同版本另一层有枫沙运输车，另有可读榆岚来源车辆。显式引用只有目标层。

**预期：**首问两个实际资源，次问同一固定层4点并区分观察、计划、实际资源。无须查询其他层或外部来源。目录可见来源名称不等于实际读取。

**评分：**目标名单和坐标为主任务；多查外源或未选图层使范围约束和严格失败，即使返回空或目标答案正确。无需附加方位或原点范围等结论，若添加则须正确有据。另记新引用入口是否使用、是否保留范围；使用入口本身不算业务成功。

### D06：明确改看来源，不能被旧引用锁住（构造对照）

**首问：**只看我引用的“沚灯现场图层”中的实际资源，列出名称和位置。

**次问：**这次改看“榆岚外部台账”的资源，列出名称和实际位置；不要沿用刚才的标绘图层。

**实际数据：**沿用D05隔离数据。榆岚仅有单体 `yl-extra/yl-e64`：榆岚运输车 `[121.03,31.03]`，当前有效实际位置证据。次问无新标绘引用，来源名称在授权目录中可定位，必须经HTTP实际查询。

**预期：**首问保持原层；次问依新指令读指定来源并只报告榆岚车。不强求再选图层，不把来源对象说成第一轮标绘，不写回草稿。

**评分：**两轮名单坐标正确；范围随新要求改变，不能以“已有引用”为由拒绝。第二轮查来源是正确执行，不套D05禁查要求。模型失误与新入口不支持普通来源查询的问题分别记录。

## 5. 不依赖模型选择的确定性检查

用真实本地HTTP、Pi工具和历史读取链路直接覆盖，不调用付费模型；界面和接续分支用确定性提供方验证。

| 编号 | 检查 | 必须满足 |
| --- | --- | --- |
| T01 | 候选非空、统计选择为空、关联不完整 | 可校验，保留未知，不自校验中断 |
| T02 | D01两份完整重叠汇总＋单体＋真实副本 | 数量口径为5，副本不重复；缺位置可未分类 |
| T03 | 一份成员不全、另一份完整 | 不给无据精确合计；knownValue不冒充完整总量 |
| T04 | 引用入口的图层、对象、拆分引用、分页、跨轮 | 只读原选择；错会话、版本或序号失败，不退回整版本 |
| T05 | 无position及三个显式position的卡片 | 标签与真实集合一致 |
| T06 | 旧N02无覆盖、N05有覆盖；另含真实同根故障反例 | 旧门槛未充分验证；故障不被通过项抵消 |
| T07 | 单问、多问、逆序、文本/API、陌生问题 | 逐问回复冻结事实；不猜答、不按问号判结束 |
| T08 | 实际注册工具、Skill和错误恢复输入 | 澄清与比较规则一致，旧历史模板不改 |

Agent可不走T02路线而答对D01；确定性工具通过也不代表Agent必然会正确调用。两类结果各自给证据。

## 6. 评分及结果用途

- 每组固定12次分母，分别报告主任务、严格、公开过程事实、最终解释及范围/等待、身份/数量、状态、覆盖诚实性。严格需主任务、全部适用解释和关键约束通过。
- 无终答解释为N/A，主任务和严格保留未完成；单列计划数、有效执行数、基础设施中断。不能删除失败，不能用有效样本率替代计划完成率。
- 旧题是开发回归，旧分数不重判。D02明确把时间完整性纳入主任务，额外错误处理计数纳入解释；旧N05-2分歧保留。
- 语言判断阅读公开原轨迹，不靠关键词。拟采用两份独立审阅与裁决，尽量隐藏组名；标明Agent审阅而非真人盲审。先用旧失败、正确例和接续反例做离线校准。
- 记录正文送达、读取时机、收到规则后的遵守、工具选择、请求、tokens、耗时；Skill读取率不是越高越好。

**进入独立新题验收的候选条件：**该组主任务和严格均至少11/12（不低于90%），关键约束12/12，同题无两遍主任务均失败；确定性检查全部通过，流程无未解释缺口。只表示值得进入下一轮，不表示生产可靠性达到90%。

按题比较两组和两遍一致性，不凭单槽差异断言优劣。两模型同根失败先查共同接口、规则和数据；一组稳定胜出才考虑下一轮模型选择验证。若仍难归因，另提固定证据回答实验，不在本批追加。

没有旧产品组，不能量化单项修正的增益；没有预加载组，不能单独证明加载机制因果效果。完整任务工具轨迹可不同，不能宣称两模型每一步都拿到了相同工具证据。

## 7. 预算和停止条件

| 项目 | 提议上限 |
| --- | ---: |
| 完整任务 | 4公开＋24诊断＝28项 |
| 实际提供方请求，含失败、澄清和工具后继续 | 总240次；每模型120次，不自动挪额度 |
| 输入token | 总800万；每模型400万 |
| 输出token，按供应商口径包含思考，不重复加 | 总100万；每模型50万 |
| 百炼现金 | 提议100元；执行前核对当时价格与计量，不能沿用旧价格当账单 |
| 方舟Agent Plan | 记录实际usage；不把token换算AFP，不新增登录余额或9,000AFP启动门槛 |

旧批20项实际89请求、约309万输入、7.15万输出，仅供估量，另一模型未必等量。预算给完整工具循环留余地，不要求花完；密钥沿用本地配置，不打印或提交。

不设单题10次调用或短墙钟硬截断。有进展继续到完成，但每次请求前检查总预算、预留完整输出；不足时留现场，不能无限跑。相同调用反复无新证据或状态进展时进入人工复核，不自动把正常探索认作循环。

普通业务错误、隔离测试中超题定范围：记失败，继续剩余计划。429、支付/配额失败、网络中断、未知用量、版本/冻结材料漂移：留原记录并暂停依赖执行，不自动重试、换模型或开额外按量付费。没有思考文本本身不构成停批，结合参数、响应和接续判断。

完成计划或达到停止条件即汇报；失败重跑、额外轮次和独立新题验收均需另行决定，不自动追加。
