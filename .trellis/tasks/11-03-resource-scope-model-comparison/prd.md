# 本轮方案：统一规则与引用范围，再比较模型表现

## 1. 为什么需要这一轮

上一轮主任务12/16、严格正确8/16，有终答解释10/15。剩余问题不能全部归为模型能力：

- Skill要求单一范围有真实歧义时先问，实际空间工具描述却仍允许直接分列条件答案。
- 用户已明确引用图层，模型调用读取工具时仍需重新拼版本和图层；漏掉图层条件就会读整个版本。
- 评测接续只支持单问，导致一次区域追问伴随额外边界确认时无法继续。
- 指定工具组合未覆盖，聚合器却用另一题的覆盖判通过。
- 正确工具结果仍可能被转述错误，或遗漏用户要求的时间；卡片另有一处范围标签错误。

上述均有[本地依据](research/verified-findings.md)。目标是先补齐确定的规则、接口和评测缺口，再判断不同模型在范围选择、澄清和事实解释上的差异。

## 2. 本轮改什么

| 编号 | 建设内容 | 用户能观察到的结果 |
| --- | --- | --- |
| R1 规则一致 | 统一实际工具描述、Skill、宿主指导和评分的澄清规则 | 要单一范围却不明确时先询问；明确比较时直接完成，不被迫单选 |
| R2 引用读取 | 现有annotation_read新增按完整用户引用读取入口 | 不再必须让模型重新抄版本和图层，减少漏参造成的范围扩大 |
| R3 忠实说明 | 保留必要名单、数量、状态和时间；纠正对象类型、筛选前后数量、跨区域分类的说明规则 | 不把来源对象说成标绘对象，不重复扣除计划记录，不漏答时间 |
| R4 卡片标签 | 无position时按实际空间结果集合描述 | 卡片不再把可能包含边界/外部的集合统称为内部 |
| R5 评测可信 | 修指定工具覆盖、多问题接续及Skill读取记录；旧轮单独出勘误 | 分清业务失败、工具缺陷、覆盖不足和评测接续不足 |
| R6 模型对照 | 同一修正版上比较Flash与Qwen的完整任务 | 观察规则统一后两组是否仍出现相同错误，不预设换模型有效 |

## 3. 保留的边界

保留Pi原生循环、现有后端、权限、固定快照和按需Skill加载。引用入口只复用已有选择，不建设“模型理解已被证明”的通用凭证，也不限制所有工具只能接收这种引用。

不改用户显式引用交互，不把地图单击变成聊天引用；不新增答案拦截器或自动裁判运行时；不调整资源统计算法、路网计算或专业作业决策；不部署或替换线上默认模型。

按引用读取只能减少漏传范围，不能保证模型不主动查其他来源。规则修改也不能保证自由解释不再出错，这两项仍须测评。已知 `hasDraft()` 和用户消息无差别影响可用性的问题继续列为独立待办。

## 4. 先离线，再做小范围对照

拟定顺序：确定性修正与离线检查 → 冻结完整输入及评分 → **4项公开流程检查＋24次诊断对照** → 报告后停止。

24次为6道题 × Flash/Qwen两组 × 每组两遍：

1. 五辆车与一个导入副本：数量、身份和对象类型是否说对。
2. 实际位置与各项时间：不能把站址当实际位置，也不能漏掉时间。
3. 单一区域有歧义：先问、收到真实回复再完成，支持多问题。
4. 用户明确比较两个区域：直接比较，保留同一对象的不同分类。
5. 固定图层两轮续问：业务筛选可变化，引用图层不能擅自扩大。
6. 用户下一轮明确改看来源系统：正确切换范围，不能被旧引用锁住。

详细问题、真实数据准备、预期与评分见[逐题清单](evaluation.md)。旧案例用作开发诊断，不冒充未见过的新题验收。

拟议总上限：240次提供方请求、800万输入/100万输出token；两模型各一半。百炼现金上限提议100元；方舟记录套餐用量，不新增余额核查启动门槛。完整任务次数不等于模型调用次数；不按单题10次请求强制打断，但仍受总预算约束。预算随用户“提交并开始实施”获批，须按离线检查和流程检查顺序执行。

## 5. 如何验收本轮工作

| 对应要求 | 完成标准 |
| --- | --- |
| R1、R3 | 实际提供方输入、读取到的Skill和评分无冲突；离线正反例齐全，不靠少答提高解释分 |
| R2 | 完整引用范围、分页、跨轮与历史读取通过；无效引用明确失败，旧入口兼容；按引用读取不扩大集合 |
| R4 | 四种有/无位置条件的卡片标签与后端实际集合一致 |
| R5 | 指定路径缺失判未充分验证；已有工具回归不可被整体分数抵消；单问、多问及普通文本/API接续可离线复现 |
| R6 | 按冻结计划报告所有执行及未完成项、各组分数、两遍差异、Skill送达、失败原因、实际用量；不自动重试或追加 |

**90%目标保留。** 本轮每模型12次，主任务和严格均至少11/12、关键约束12/12且无同题两遍主任务均失败，才建议进入独立新题验收；确定性工具检查也须全部通过。这只是进入下一阶段的条件，不是宣布生产正确率达到90%。

这次不安排旧产品对照或预加载组，因此不宣称某个改动提高了多少百分点，也不单独判断Skill加载机制的因果效果。若新题验收值得开展，再单独拟定和审阅，不自动扩测。
