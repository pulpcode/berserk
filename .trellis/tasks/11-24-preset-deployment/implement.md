# 实施与验证草案

1. 用演练席位清单构造预设，逐项核对 directorSeatId、commands.seatIds、来源范围及权限。
2. 实现离线初始化命令，复用现有初始化、管理员角色、账号存储和预检。验证目标数据目录解析及凭据安全交付。
3. 接入现有 systemd 发布布局，启用沙盒时先以服务身份校验 Docker、镜像和容器执行，初始化完成后切换并启动。补充部署说明和调用示例。
4. 以新临时数据根验证首次部署及登录选项。针对同一数据根重复执行、模拟中断后继续、已有记录冲突及配置缺失进行验证。
5. 运行定向席位部署与管理员登录测试。用隔离实例确认健康、角色权限以及原有会话连续性。覆盖启用沙盒时的真实执行、Docker 不可用时停止切换、关闭沙盒时无 Docker 部署。

首版采用演练六席和独立管理员。沙盒默认开启。

## 本地验证

- Node 24 类型检查、lint、前端构建与 Bash 语法检查通过。lint 保留 InteractionCard 的两条既有警告。
- 席位初始化、预检和登录相关 14 个定向测试通过。覆盖初始凭据、六席与管理员入口、控制权限、重跑保留会话、冲突处理及 Docker 默认开启与显式关闭。
- 允许本机环回后，全量 Vitest 2066 通过、1 失败。唯一失败是 Pi 的 HTTP 心跳空闲超时测试。对未修改的 main 使用同一 Node 24 单独复测，复现预期 1 次请求、实际 2 次请求的断言失败。

## Ubuntu 隔离验收

- 在腾讯云服务器以独立 systemd 单元、端口和空数据根运行实际 deploy.sh。复用宿主已有执行镜像，使用独立模拟业务来源和测试凭据。
- 模拟 Docker 守护进程不可达时，默认开启沙盒的部署被拦截，未初始化数据或创建、切换服务。恢复真实 Docker 后，依赖安装、前端构建、预设开通、预检、systemd 启动与健康检查通过。
- 六席和独立管理员均通过真实 HTTP 登录，导演与控制权限符合预设。真实 Docker 执行探针通过九项检查，包括文件读写、席位隔离、无网络和容器清理。
- 考虑宿主剩余磁盘空间，重跑验收复用已构建发布目录，执行离线初始化及 systemd 重启。初始密码文件与签名保持原值，已有登录会话仍生效。
- 两轮验收的临时目录、凭据、systemd 单元和启用链接均已删除，测试端口已释放，未检测到挂载验收目录的容器。主线服务复查为 active，健康接口返回 ok。
