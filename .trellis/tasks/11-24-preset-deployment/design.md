# 技术方案草案

## 预设与运行时边界

沿用席位样例中的 ID、名称、职责和类型。预设引用席位清单，补充稳定用户名、必要的现有授权以及配套 context/background 配置。导演使用 seat-director，控制使用 seat-control。管理员不绑定业务席位。实例私有配置提供实际来源地址和凭据。纯业务预设可按同一契约后续补充。

## 执行流程

1. 发布脚本准备代码、依赖、前端构建结果和实例配置，解析实际数据根和服务名。
2. 停服阶段校验预设及现有席位、账号、权限和来源配置。复用数据库初始化及管理员迁移。批量开通复用 AccessStore，沿用现有密码哈希和职责更新。
3. 创建前查找已存在记录。相符记录跳过账号写入，避免清除已有会话。遇到 ID、用户名绑定或权限冲突时停止并报告。首次凭据在写库前生成并保存在权限 0600 的实例私有文件中。重试复用未交付凭据，终端日志只输出文件位置。
4. 仅在停服时写入。用同一实例的互斥执行保护检查与写入。初始化各阶段须支持重复执行，预检通过后才切换并启动 systemd 服务。
5. 沿用 seats:check，启动后核对健康接口及未登录的 loginSeats 和 loginUsers。初始化完成以前保留原发布入口。旧实例数据升级沿用独立备份和迁移流程。

## 边界

初始化命令负责实例数据及预检。仓库根目录 deploy.sh 串联构建发布、离线初始化、首次安装 systemd 单元、版本切换和健康检查。应用沿用当前启动和鉴权逻辑。

## Docker 执行沙盒

容器执行默认开启，实例配置可以显式关闭。启用时，由运维准备并启动 Docker，发布入口以 Axon 服务身份检查 daemon、准备实例选定的镜像并验证容器可运行。检查在版本切换前完成，失败则停止发布。关闭时跳过 Docker 检查与镜像准备。Axon 服务继续由 systemd 启动，运行时按请求启动执行容器。
