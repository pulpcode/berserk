# W01-6 设计：Web 人工交互

日期：2026-09-18。状态：**已实现并通过开发验收，待用户浏览器验收**。范围见 [需求](prd.md)，依据见 [Pi 能力核对](research/pi-hitl.md) 与 [命令策略参考及验收样例](research/command-policy.md)。

## 1. Pi 与宿主分工

沿用 Pi 0.85.1 SDK、原 AgentSession、默认压缩和工具循环。本期增加两种交互：

| 交互 | Pi 接入点 | Axon 补齐 |
| --- | --- | --- |
| AskUser | 固定扩展通过 pi.registerTool 注册 ask_user，异步 execute 等待回答并返回工具结果 | 问题卡片、回答回传和会话关联 |
| 操作确认 | 公开 beforeToolCall 执行服务端规则；允许返回、询问等待、禁止或拒绝返回阻止结果 | 命令判断、操作卡片、决定校验与记录 |

AskUser 参考官方 question／questionnaire 的工具参数与结果流程，使用受控 `extensionFactories` 注入，保持 `noExtensions: true` 关闭自动发现，并将 ask_user 加入主 Agent 工具列表。扩展通过注入的网页交互桥接函数等待回答，替换示例中的终端 `ctx.ui.custom`；不复制 TUI 组件，也不伪称已实现完整 ExtensionUIContext。扩展装载失败明确结束准备，不静默缺失工具。

本期固定加载受信任代码；扩展在宿主进程运行，上传的脚本仍在容器执行，不自动成为插件。插件安装和热重载管理后置。SDK 已支持扩展加载，无需转用 CLI/RPC 或另写 Agent 循环。

保留工具串行执行。组合 Pi 原有 beforeToolCall 和当前停止检查；确认位于参数最终处理之后，批准后再检查停止与参数一致性。等待期间同批后续工具不执行。Pi 的 tool_execution_start 早于拦截，不据此声称实际操作已经执行。

## 2. AskUser 的行为

模型可调用 `ask_user({questions})`：一批 1～4 题，通常优先一题；每题包括稳定 id、问题正文、可选选项（id、标签、说明）及可选 multiSelect。无选项时直接填写文字，有选项时始终允许自定义文字。1～4 是本项目界面约束，不是 Pi 内核限制。

用户填写后统一“提交回答”；选择选项不自动提交。答案按题目 id 返回选择 id 或自定义正文，保持顺序；每题答案互斥，不同时提交选择和另一套正文。多选仅针对该题。全部作答后提交，或通过“跳过提问”返回明确的 skipped，不补齐默认答案。停止则结束整次请求。

回答作为 ask_user 的普通工具结果交回 Pi，进入后续模型上下文及原生历史。问题卡片记录用于展示，不重复注入上下文。跳过后 Agent 可在信息足够时继续；关键条件缺失则说明无法继续的原因，不能假称用户已选择或用跳过授予权限。

普通自然语言问句仍可作为一次回复结束，不强制转换成 AskUser。AskUser 用于处理中需要明确输入并继续的场景，不用于替代操作确认；即使问题选项写着“同意上报”，回答也不会建立操作授权。

## 3. 操作规则与 bash

是否需要确认由服务端的工具规则决定；工具描述帮助模型选择工具，不是权限配置。AGENTS.md、模型输出和上传内容不能覆盖规则，用户通过网页批准具体调用。规则为随代码部署的受控配置，当前请求固定其版本；不提供网页规则编辑或“始终允许”。

规则输入是工具名、校验后的实际参数、固定工作区与执行环境，输出 `allow / ask / deny`、规则 ID 和理由。优先级为 deny > ask > allow。规则抛错或解析器不可用时结束请求，不降级为直接执行。尚无规则的现有非 bash 工具沿用原访问范围；AskUser 本身无需先申请操作批准。

### bash 的首期范围

使用成熟的 tree-sitter Bash 语法解析器，不用空格拆分或几条字符串正则充当 Shell 解析。Node.js 绑定与 grammar 的兼容版本在 P1 锁定并验证；解析器提供语法树，下面的产品规则由 Axon 实现。

| 情形 | 决定 |
| --- | --- |
| 已识别的 sudo、su、doas、mount、umount、nsenter、chroot 调用 | deny；本期不开放提权或切换执行环境 |
| 已识别的 rm、rmdir、unlink、shred、truncate、chmod、chown、chgrp | ask；展示完整命令与参数，不按模型给出的“安全”描述放行 |
| git clean、git reset --hard、git restore | ask；包括 reset 的选项顺序变化；git 的常见 -C／-c 参数须解析后判断子命令 |
| 简单字面量命令及由换行、&&、\|\|、;、\| 组成的可分析命令链 | 逐项判断，整条取最严格结果；决定前整条均不执行 |
| 变量／命令替换、循环、函数、后台执行、here-doc、动态命令名、内联解释器代码或未支持的语法／包装 | ask；显示“该命令需人工检查”，不声称检测到确定危险 |
| 支持范围内未命中 ask／deny 的普通命令 | allow，但仍在原 Docker 沙盒内执行 |

识别时处理静态引号、命令绝对路径的 basename、字面量环境赋值和简单 env／command 包装；不执行展开、source 文件或任何试运行。复杂包装无法可靠还原时询问，不凭安全前缀放行。实际执行保留原命令，不执行拆分后的重组命令。

简单重定向需识别目标：仅静态、无 ../ 穿越的工作区路径、/tmp 路径及 /dev/null 可沿用命令决定，其他或动态目标询问；文件描述符间重定向不授予额外路径权限。前面的 cd、目录变化或路径含义不确定时询问，不用初始 cwd 错判目标。

普通 `python /workspace/process.py`、`node /workspace/process.js` 在没有其他命中项时允许，脚本正文不在本期自动审计。内联代码（如 python -c、node -e）、Shell 脚本／bash -c 等委托执行入口询问。这个取舍保留文件处理能力，但不保证拦住以其他程序形式完成的相同删除行为。

确认始终只批准当前原始命令与固定参数，包含工作目录，不更改容器网络、挂载、用户或宿主权限。ask 卡片展示命中的规则与影响；deny 直接返回原因及可行替代方向，没有批准按钮。示例集见 [命令策略样例](research/command-policy.md)。

### 通用操作与后续业务

保留 `confirmation_demo({content})`，仅通过默认关闭的 LAB_HITL_DEMO_ENABLED 启用，主 Agent 可用。它固定返回 ask；批准后仅生成本地验证回执，不发送消息或改动用户文件，供通用确认故障测试。

将来的上报／下发工具可以登记独立规则；其主体权限、接收对象、文件版本／快照和外部幂等由业务工具负责。AskUser 补齐接收对象不等于批准上报。共享文件不能仅凭一个可能变化的路径取得版本授权，本期不建设成果冻结或业务状态。

## 4. 网页交互

在对应工具位置展示两种卡片，复用现有样式，不开全局模态框或审批中心。

| 提问卡片 | 操作确认卡片 |
| --- | --- |
| 问题正文、选项／文字输入；提交回答／跳过提问 | 具体动作与影响；bash 展示工作目录和完整命令；拒绝／确认执行 |
| 导航显示“待回答” | 导航显示“待确认” |
| 已回答／已跳过 | 已确认／已拒绝，实际执行结果另显示 |

卡片提交期间禁用重复操作。批准只显示“已确认，继续处理”，不能提前显示成功；实际工具错误照常显示。拒绝通过关联交互记录解释，不通过匹配错误文字猜测。问题与命令按纯文本展示，不执行模型提供的 HTML。

等待时普通输入框仍保留草稿，发送禁用，保留“停止本次处理”；不显示模型仍在生成的动画。两种等待都计入“需关注”，均不产生新回复蓝点。切换不抢焦点，不默认批准或提交默认选项；中文输入法确认键不提交。窄屏可读，命令可展开完整查看。

问题草稿按 sessionId／requestId／interactionId 存入本标签页 sessionStorage；切换、刷新、网络失败保留。关闭标签页后的未提交答案不保证恢复，重新打开仍可查询服务端待回答项。服务端已回答、跳过、取消或失效时清除可提交草稿，不能用旧草稿覆盖已接收答案。多标签页以服务端首次有效提交为准。错误在卡片附近说明并提供查询／重试入口；先 GET 核对结果，不自动重发消息或交互提交。

## 5. 共用契约与通信

使用带 `kind: question | confirmation` 的 Interaction，而不是让一个无类型的“同意”字段同时处理回答与授权。公共字段：schemaVersion=1、interactionId、workspaceId、sessionId、requestId、toolCallId、toolName、createdAt。问题分支保存题目与答案，确认分支保存固定操作说明、待执行参数快照、规则 ID／版本；保留与原生工具调用的关联。

问题状态：pending → answered／skipped／cancelled／expired。确认状态：pending → approved／rejected／cancelled／expired。这些是交互记录状态，不是成果状态机或完整 Run。状态终结后不可重新打开；同请求可先后交互，同一时刻最多一个待处理项。

| 入口 | 约定 |
| --- | --- |
| GET /api/sessions/:id | 新增 interactions，包括当前和历史记录；旧会话返回空数组 |
| RequestState / GET /api/activity | 新增 waiting_answer、waiting_confirmation phase；活动摘要不含正文，当前请求仍为 responding |
| 原消息 SSE | 新增 interaction.updated，携带完整记录及 sessionId／requestId |
| POST /api/sessions/:id/interactions/:interactionId/response | 问题只接受 `{requestId, kind: question, action: answer, answers}` 或 action=skip；确认只接受 `{requestId, kind: confirmation, decision: approve或reject}`，不接受替换参数 |
| 原取消接口 | 仍按 sessionId／requestId 停止，待处理交互同步失效 |

响应接口返回权威交互记录，不等待后续工具或模型结束。按 kind 严格校验载荷，跳过不得夹带答案、确认不得夹带问题答案；核对题目／选项 ID、答案完整性及会话／固定席位归属；未知 ID 为 404，过期或冲突为 409，格式错误为 400。相同答案／决定重复提交返回原记录，不同内容冲突；终态重试只确认收到，不重新执行。

前端合并时坚持所属会话／请求，忽略已终结记录的旧 pending 快照。交互解决后退出等待 phase：问题／拒绝转后续处理，批准转工具处理；最后按请求终态快照收敛。

## 6. 等待、停止、历史与重启

共用请求内等待对象，只保留一个 Promise 和取消监听。首次有效响应按同一 Active 同步占定、保存后解开等待；停止先被接受时不接收迟到响应，响应先接受后仍要检查停止再进行新工作。不能两个请求都读到 pending 后分别推进。

使用已有 Active.controller 的 abort 信号，包括 AskUser 工具传入的信号。等待必须结束并清理监听，不能在 Pi 回调内等待 session.abort 自身管线。保存交互或响应失败则结束请求，不放行、不制造空答案。网页断开不等于取消；同请求等待时不发新模型／工具调用，其他会话可继续。

默认不新增次数或等待时限；若已有 AGENT_RUN_TIMEOUT_MS，等待计入整轮墙钟时间，到期走原停止路径。AgentSession 和已创建容器保持到请求结束，不为提问或确认新建容器，不声称释放 Worker 后持久化续接。

沿用原生 Pi JSONL，追加 `berserk.interaction.requested.v1` 和 `berserk.interaction.resolved.v1`，分别保存问题／确认及答案／决定／结束原因。记录固定测试席位，沿用持久化失败守卫。严格解析校验工具调用、归属、类型与唯一终态；bash 的规则结果／版本通过公开 appendCustomEntry 保存为 `berserk.command-policy.v1`，关联实际工具调用与固定参数；实际执行后的工具 details 同时带规则信息，不另建操作账本。Pi 对被阻止的调用不会执行 afterToolCall，因此不能只依赖该钩子保存禁止／拒绝的证据，也不修改事件对象充当结果扩展。

AskUser 的回答通过普通工具结果进入上下文；拒绝通过 Pi 阻止结果进入上下文。网页交互记录不重复注入，原文和卡片不因默认压缩消失。批准与实际工具结果分开，原生记录仍是效果来源；批准后停止且工具尚未启动时显示“未执行”，不误记为执行失败。

刷新可恢复仍在进程中的等待。服务重启时旧 pending 投影为“已失效：服务重启”，不重建 Promise 或工具调用；批准后缺结果显示“执行结果未确认”。沿用原有未完整请求的恢复提示，需新建会话核对后继续；不自动重放。旧已实现会话无需迁移；回退代码时保留新记录，不能删除以绕过校验。
