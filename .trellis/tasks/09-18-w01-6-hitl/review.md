# W01-6 审阅入口：Web 人工交互

日期：2026-09-18。状态：**已实现并通过开发验收，待用户浏览器验收**。

本期实现两类交互：Agent 缺少信息时通过 AskUser 向用户提问；准备执行受控操作时，请用户确认或拒绝。前者补齐任务信息，后者授予一次操作权限，为后续上报、下发准备。

实现与测试证据见 [验收记录](research/validation-results.md)。

## 请重点验收

| 事项 | 方案安排 |
| --- | --- |
| Pi 复用 | AskUser 采用固定扩展注册工具；操作确认采用公开 beforeToolCall；循环、工具执行和上下文仍由 Pi 管理 |
| 网页体验 | 会话内分别显示问题卡片和操作卡片，支持回答／跳过、确认／拒绝，以及停止；可切换、刷新后继续 |
| bash 判断 | 服务端检查实际命令与参数，返回允许／询问／禁止；解析复合命令，无法可靠分析时询问，规则故障不执行 |
| 首期规则 | 直接删除、截断、权限修改及指定 Git 清理／覆盖命令询问；识别到提权、切换执行环境的命令禁止；具体样例见下方链接 |
| 脚本边界 | 普通 Python／Node 文件脚本继续可执行，正文不做语义审计；内联代码、Shell 脚本和复杂语法询问。这无法保证拦住脚本内部的所有删除或覆盖 |
| 沙盒 | 沿用现有 Docker 隔离；批准命令不开放网络、宿主文件、提权或凭证 |
| 等待与重启 | 保留进程内请求及已有容器，其他会话可继续；重启后待处理项失效，记录保留，不自动重放 |
| 验收 | 真实提问后生成文件、测试目录内命令批准／拒绝续作；确定性测试覆盖规则、重复提交、停止、刷新和重启 |

AskUser 回答不能代替操作批准。规则不是任意程序行为的完整安全审计，也不让所有普通文件读写都弹确认。上述范围为当前实现边界。

真实上报／下发、跨席位业务审批、成果状态、持久化 Run、等待资源调度和插件安装／热重载管理后置。不提前宣告 W01 的 T04 或 MVP 的 FG02 通过。
