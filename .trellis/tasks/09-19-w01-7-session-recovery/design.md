# W01-7 设计：中断后原会话续聊

日期：2026-09-19。状态：**已实现，自动验收通过，待用户验收**。基线：当前 Axon、Pi SDK 0.85.1；依据见 [验证报告](../09-16-w01-harness-validation/research/pi-recovery-validation.md)。

## 1. 实现原则

优先沿用 Pi 的原生设计、默认行为和公开 SDK。Axon 只适配已有 Web、工作区、操作确认和 Docker 边界；新增机制必须有明确需求或验证发现的能力缺口。

本期不新增中断记录、恢复摘要、恢复专用提示词、操作账本或恢复接口，不修改 Pi 源码。AGENTS.md、工具权限和命令确认规则保持现状。

## 2. 原会话继续处理

1. 服务启动，沿用现有流程初始化执行环境、严格加载原生会话及归属信息。
2. 根据已有请求记录和当前活动状态识别未正常结束的请求。仅因普通请求未完成而设置的禁止续聊限制解除；独立异常继续保留保护。
3. 用户显式发送新消息后，沿用现有方式创建新 requestId、资源快照和 AgentSession，复用原 SessionManager 与工作区。
4. Pi 负责历史上下文、模型调用、工具循环及压缩；新消息和新结果正常追加保存。

重启、打开会话和 GET 均不改写会话历史，不调用模型或执行旧工具。继续处理不恢复旧 Promise、容器程序或子 Agent 进程。

## 3. 从已有记录识别状态

沿用 `berserk.request-resources.v1` 中的 requestId 及已有 `berserk.request-result.v1`，在读取时按请求归组。

| 已有记录与执行状态 | 页面状态 |
| --- | --- |
| 有正常结束记录 | 使用真实 succeeded／failed／cancelled |
| 没有结束记录，且属于当前活动请求 | 使用当前运行／等待状态 |
| 没有结束记录，重启后没有执行者，历史校验通过 | 显示“已中断” |
| 空会话或尚无合法请求记录 | 不编造请求状态 |
| 记录损坏、归属或关联不合法 | 保留现有拒绝加载／禁止处理行为 |

现阶段以单服务进程拥有一个 LAB_DATA_DIR 为前提。缺少结束记录只说明未正常结束，不能推断准确退出时间、退出原因或工具执行效果。

新请求的资源记录界定下一请求的开始。因此，A 请求未结束、B 请求后来正常完成时，仍能从原记录分别识别 A 与 B，无须补写 A 的终态。再次重启也使用同一规则。无法确定请求归属的旧格式或异常记录不猜测、不修补。

历史校验、交互和页面投影共用该请求边界。缺少 toolResult 本身不再一律阻止原会话续聊；保留格式、权限、文件归属和持久化故障检查。当前进程内的持久化失败不能借此直接解除保护。

`interrupted` 只作为对外读取结果的状态，可复用 `lastResult` 展示；不追加对应的 JSONL 条目，原结束记录格式保持不变，也不增加发现时间或独立中断记录列表。

## 4. 工具、提问与确认

Pi 处理缺失工具结果的协议配对；当前验证中，适配层仅在发送载荷补 `No result provided`，不回写原文件。Axon 不自行伪造工具结果。

- 有真实工具结果时，保留原结果；缺失时在网页投影中用 `resultMissing` 标记说明“未收到执行结果”，不能据此判断没执行、成功或回滚。此标记不写入 JSONL，也不发送给模型。
- 旧待回答／待确认卡片按已有语义显示失效；保存过的答案、批准和拒绝继续保留。批准但缺少执行结果仍为 unknown。
- 历史解析遇到下一请求边界时，使旧 pending 失效，避免阻挡新 AskUser。它是读取时的状态判断，不补写交互结果。
- 对旧卡片的提交仍返回失效冲突；新调用需要确认时按现有规则生成新卡片，旧批准不跨请求使用。

保留现有工具集合，不新增统一只读恢复模式或去重拦截。模型在新请求中可能重新提出相同操作，本期不保证恰好执行一次。

## 5. 上下文与执行环境

直接使用 Pi 从原始历史和最近有效摘要构建的上下文；当前 AGENTS.md 与工具按现有方式加载。不为中断另加系统提醒、恢复摘要或自定义压缩要求。

压缩期间退出时，仅使用已完整保存且通过校验的 CompactionEntry，未保存的摘要不补造。新请求是否需要再次压缩仍由 Pi 决定。

Docker 沿用按实例标签清理旧容器的初始化流程，文件保留在原工作区。中断请求涉及沙盒执行时，沿用初始化成功结果作为放行条件；初始化失败则保持保护，本期不增加容器接管或细分恢复状态。纯对话不额外依赖镜像可用性，文件工具不可用时不回退到宿主执行。

未结束子任务、子文件缺失或父子结果不一致暂保留原有保护；完整子任务历史不妨碍父请求续聊。不新增子任务恢复或自动重跑。

## 6. 网页适配

复用消息发送、GET 快照及活动列表。可继续的中断不设置禁止发送的 `recoveryWarning`；硬异常仍使用该字段，页面不靠中文文案判断权限。

- 最近请求中断时，显示“上次处理已中断，已保存内容保留，可继续发送消息”，必要时附缺少工具结果说明。
- 用户发送后按新请求显示活动和结果；旧历史、文件、失效卡片和未知效果仍保留。不新增请求状态时间线或恢复中心。
- 刷新以持久历史为准，清除失效的运行动画及未落盘片段；普通浏览器断线不算服务中断。
- 草稿、附件、焦点与会话切换沿用现有行为；已落盘用户消息不自动填回或重发。未落盘输入仅按现有本地备份机制恢复，不覆盖正在编辑的内容。
- 导航可显示最近请求“已中断”，蓝点仍只表示新回复未读。

## 7. 验证与兼容

按 [验收清单](acceptance.md) 验证原会话续聊、无自动重放、旧交互失效和真实文件效果。首次请求、压缩期间退出和 Axon 交互桥接是已有 Pi 探针尚未覆盖的重点。

本期不新增历史格式或迁移。部署前备份数据，先使用隔离副本验证；旧程序仍可能阻止未正常结束的请求，回退不靠删除历史实现。服务已按用户授权更新，部署无需历史格式迁移。
