旧问题和确认失效，已保存决定保留；旧批准缺少执行结果时仍为未知。历史损坏、归属异常、持久化故障、未完成或不一致的子任务，以及相关沙盒初始化失败仍保留保护。

脚本：[probe-session-recovery.ts](../../../../experiments/harness-lab/scripts/probe-session-recovery.ts)。统计：[recovery-evidence.json](recovery-evidence.json)。

| 证据 | 结果 |

| Ubuntu 独立目录 + 真实 Docker／DeepSeek | 4 个 SIGKILL 后续聊场景通过；新用户请求 4 次，模型调用 10 次，工具调用 7 次 |
| 重载与查询 | 每场景重载并连续 GET；JSONL 字节不变，不重放旧工作；续聊追加新 requestId，原字节前缀保留；再次重启可读取新终态 |
| 文件效果 | 指令工具执行前为空，执行后为目标内容，重载不增加修改；Docker 已追加的一行仍为一行，后续生成 recovered.md |
| 容器 | 根据各测试实例标签查询，残留容器均为 0；最终后端源码重新读取全部 4 组 Ubuntu 历史通过 |

Ubuntu 的 4 个场景：

1. Bash 已写文件、命令尚未结束时杀死宿主；初始化清理旧容器，新请求读取已有文件并写出新文稿，没有再次追加旧效果。
2. 删除命令等待批准时退出；旧确认失效，新请求重新确认。测试拒绝后，文件仍存在。
3. 删除已经执行、结果尚未保存时退出；旧批准显示未知。新请求对另一份测试文件重新确认，拒绝后保留该文件；旧未知状态不被新请求成功覆盖。
4. AskUser 等待回答时退出；旧问题失效，新请求重新提问，回答 Markdown 后正常完成。

故障点由真实 Axon／Pi 写入和事件触发，再对测试子进程发送 SIGKILL。故障前模型传输是确定性的；Ubuntu 的续聊使用真实模型。两类证据不混作“全程真实模型”。网页测试使用确定性 HTTP 服务，与后端及真实模型证据组合验收。

本次修正了两个测试数据问题：指令写入使用实际初始 hash，避免将保存冲突误当作成功写入；已删除文件不再用于验证新确认，改用另一份存在的文件。最终报告仅采用修正后的完整通过结果。
