# W01-7 中断后原会话续聊

日期：2026-09-19。阶段：S3c。状态：**已实现，自动验收通过，待用户验收**。

## 目标与原则

服务异常退出后，用户能在历史可校验的原会话中发新消息，利用已有对话和文件继续工作。尽量沿用 Pi 的原生机制，仅补齐 Web 接入所需的处理；不为尚未出现的需求增加运行管理机制。

例如：Agent 已写好部分方案，服务退出。重启后，用户看到已保存内容和中断提示，输入“先检查现有文件，再继续完善方案”，开始一次新处理。

## 需求

| 编号 | 用户可观察的要求 |
| --- | --- |
| J01 | 已完成会话照常继续；普通中断会话保留原历史、文件及归属，允许用户发新消息，无须新建会话 |
| J02 | 最近请求中断时显示“已中断”，不显示运行中或用户取消；未保存的流式文本不承诺恢复 |
| J03 | 保留真实工具结果；缺失结果时如实说明，不能宣称未执行、已回滚或已成功；旧未知效果不被新请求成功覆盖 |
| J04 | 重启、打开页面、刷新和查询状态不改写会话历史、不自动调用模型、不重发消息或执行旧工具；继续由用户发送新消息触发 |
| J05 | 旧待回答／待确认卡片失效，已保存答案和决定保留；需要时重新提问、确认，旧批准不授权新操作 |
| J06 | 续聊保持当前工作区指令、工具权限、命令规则、压缩、停止和会话隔离；上下文沿用 Pi 现有处理 |
| J07 | 历史损坏、持久化失败、归属错误、子任务记录不一致或相关沙盒未确认停止时，保留已有保护 |
| J08 | 保留现有草稿、附件和切换体验；已落盘的用户消息不重新塞入输入框或自动发送 |

普通中断包括等待模型、回复输出中、工具调用前后及等待用户回答／确认，前提是历史及归属可校验、没有独立异常。

## 范围之外

- 不新增持久中断记录、恢复提示词／摘要、恢复接口或请求状态时间线。
- 不恢复旧执行进程、等待对象、容器程序或子 Agent；不自动重试旧请求。
- 不建设 Run 数据库、操作账本、持久队列、租约、多实例接管或任意操作去重。相同的新调用可能重复产生效果。
- 不改变现有工具与确认规则，不新增恢复专用只读模式或默认执行上限。
- 未结束或不一致的子任务暂保留保护；真实业务上报／下发、成果状态和跨席位审批继续后置。
