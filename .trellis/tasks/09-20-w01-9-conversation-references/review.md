# W01-9 审阅入口：文件引用与 Skill、子 Agent 选择

日期：2026-09-20。状态：**已实现并通过组合验收，待用户查看；尚未部署**。

目标：在现有对话输入框中，方便地指定要处理的文件、采用的方法和参与工作的子 Agent。

## 交互方案

| 入口 | 用户选择什么 | 发送后如何处理 |
| --- | --- | --- |
| `@` → 文件 | 当前工作区中的文件，可多选 | 提供文件引用，Agent 按需读取或解析 |
| `/` → Skill | 本条请求采用的方法 | 服务端加载所选 Skill 正文，随本条请求交给 Pi |
| `@` → 子 Agent | 希望委派的角色 | 主 Agent 接到明确委派要求，通过现有 `subagent` 工具执行，结果返回主会话 |

选择后显示可移除标签；点击发送才开始处理。输入框旁的添加菜单也提供相同入口，不要求记住快捷符号。

## 本期行为

1. **选择结果如何显示**：本方案保留现有文本输入框，在正文上方显示文件、Skill 和子 Agent 标签；不把标签嵌入正文。文件显示相对路径，避免同名混淆。
2. **组合范围**：一条消息可选多个文件、一个 Skill 和一个子 Agent。更换 Skill 或角色时替换原选择；只作用于本条请求。该数量是本期选择器的产品范围，不是 Pi 的能力上限。
3. **Skill 如何生效**：显式选择后直接加载正文；未选择时，Agent 仍可按任务需要调用 `skill_read`。同时指定子 Agent 时，将这份方法和所选文件引用一并提供给它。
4. **委派的含义**：选择的是子 Agent，主会话保持原角色。主 Agent 仍负责澄清和拆分，通过工具委派；选择标签表示用户要求，实际调用以子任务卡片为准。本期不增加绕过 Pi 循环的强制调度器。
5. **文件查找范围**：先复用当前工作区的目录浏览、文件名筛选和相对路径输入；不新增全盘索引或文件内容搜索。

既有只读子 Agent 权限、上下文隔离、停止、压缩和 HITL 继续适用。选择文件不代表提交该文件，选择角色也不是向其他席位分派工作；上报、下发仍走现有业务工具和确认流程。
