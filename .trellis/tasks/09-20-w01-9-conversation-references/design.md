# W01-9 设计：对话中的文件、Skill 与子 Agent 选择

日期：2026-09-20。状态：已实现并通过组合验收，待用户查看；尚未部署。

## 1. 输入框交互

保留当前 textarea、上传入口和附件标签。增加一个候选浮层和两类选择标签，不引入富文本编辑器。

```text
┌────────────────────────────────────────────┐
│ 文件：plans/方案.md ×                       │
│ Skill：review ×     子 Agent：reviewer ×    │
│                                            │
│ 请检查方案中的依据、矛盾和遗漏。             │
│                                            │
│ ＋                                  发送   │
└────────────────────────────────────────────┘
```

- 输入 `@` 打开候选浮层，按“文件”“子 Agent”分组；输入 `/` 打开 Skill 列表。角色和 Skill 显示名称与简短职责／说明，角色明确标为只读。
- 文件组默认浏览工作区根目录，可进入子目录、返回上级，按当前目录的文件名筛选；输入 `plans/方案` 表示在 `plans` 下查找文件。目录用于导航，不能选为附件。同名文件显示相对路径。
- 选择候选后只删除当前触发片段，例如 `@方案`，保留其他正文并添加标签；焦点回到原光标位置。重复选同一文件不增加标签，选择另一个 Skill／角色会替换原项。
- 添加菜单提供“上传文件、引用文件、使用 Skill、委派子 Agent”，均进入相同选择逻辑。既有文件面板“引用”也共用文件标签。
- 输入目标后点击发送才工作；仅有标签、没有正文时提示补充目标。选择项只绑定当前草稿，不自动带入下一条消息。

触发识别限于光标处正在输入的独立片段，位于正文起点或空白之后；粘贴普通文本不自动创建引用。邮箱、已粘贴的路径、代码中的符号都不能生成结构化选择。关闭浮层或未选中候选时，原字符按普通文本处理，不在发送时暗中解析。

浮层打开时，上下键选择、Enter 确认候选、Escape 关闭，Tab 正常移动焦点且不发送。中文输入法组合期间不选择、不发送。点击外部关闭时保留已输入文字。列表支持鼠标和触屏；窄屏不超出输入区域，长路径可换行，焦点可见，加载／无结果／失败各有明确反馈。

## 2. 选择项和接口

接口继续使用现有席位作用域；双席位模式下前缀为 `/api/test-seats/:seatId`。服务端以已验证的席位和会话绑定确定工作区，浏览器不能提交宿主路径或工具权限。

| 接口 | 本期处理 |
| --- | --- |
| `GET /workspaces/:id/files` | 复用 `path/search/offset/limit` 的目录列表；不新增递归扫描或索引 |
| `GET /workspaces/:id/resources` | 复用当前可用 Skill 元数据 |
| `GET /workspaces/:id/skills/:skillId` | 复用查看 Skill 正文；查看不等于选用 |
| `GET /workspaces/:id/agents` | 新增只读角色目录，返回 `name/description/hash`；角色来自现有受控配置，不返回宿主路径 |
| `POST /sessions/:id/messages` | 保留 `text/uploadIds/fileRefs`，增加可选 `skill: {id,hash}`、`agent: {name,hash}` |

hash 用于确认 Skill／角色仍是用户刚才选中的版本；不由浏览器提供正文、系统提示或工具声明。文件引用沿用 `{path}`，发送时从实际文件取得名称、大小和 hash；与文件版本提交是两种行为。

前端把选择项放入现有按席位、会话／新会话工作区区分的草稿中。异步目录查询固定作用域和查询代次；切换后迟到结果不能更新新页面。新会话创建期间，正文、上传和选择项一起迁移到已创建会话；发送期间继续编辑的新草稿不能被完成事件清空。

## 3. 发起请求与上下文

沿用 `PiLab.start` 同步占用本会话的活动请求，再在准备阶段处理选择项：

1. 在会话固定工作区中取得资源快照和角色配置，解析文件引用。
2. 校验 Skill／角色存在且 hash 一致；无效或版本已变化时在调用模型之前结束，提示重新选择，保留用户输入。
3. 用服务端取得的内容构造本条输入；先保存原生输入记录，再调用公开 `AgentSession.prompt` 处理用户正文。

| 选择类型 | 交给模型的内容 | 不代表什么 |
| --- | --- | --- |
| 文件 | 现有文件引用消息：相对路径、名称、大小、hash | 不包含完整正文；不代表已经读取 |
| Skill | 所选 Skill 的方法正文及名称，来自本轮受控快照 | 不增加工具、不授权写入、不替换 AGENTS.md |
| 子 Agent | 明确的角色委派要求及角色名称 | 不切换主 Agent，不直接启动脱离主请求的后台任务 |

**Skill 采用显式加载。** Pi 的原生 `/skill:name` 会展开 Skill 正文。Axon 当前关闭目录自动发现和命令展开，并从受控快照读取 Skill；因此本期在 Web 适配层把所选正文作为输入交给 Pi，保持“显式选用即加载”的语义。复用公开 SDK，不调用私有 `_expandSkillCommand`，不为展开命令生成临时 Skill 文件。未选择时仍提供原有目录和 `skill_read` 工具。

方法正文作为本条任务的用户级资料，采用明确边界包裹；不得把整份 Skill 当成高于宿主权限的 system 指令。AGENTS.md 继续按现有机制独立加载。Skill 可参与 Pi 后续的正常压缩，本期不增加特殊保留规则。

## 4. 子 Agent 委派

主 Agent 读取用户目标、所选角色及必要材料，通过原有 `subagent({agent,task})` 工具委派。目标缺少必要信息时可以先询问；只有实际工具调用才创建子任务卡片。选择标签只表示用户要求，不能提前显示“已委派”或“检查完成”。

本期不在宿主另建强制调度流程，也不在模型未委派时自动追加一轮纠正请求；模型执行要求的可靠性通过真实委派场景验收。若后续要求“选择角色后必须由服务端直接启动”，需单独讨论执行语义。

同时选择 Skill 和角色时，宿主在这次匹配角色的委派输入中补入已选 Skill 正文和文件引用，主 Agent 补充明确子任务及必要背景。委派说明要求保留所选方法的步骤与输出要求，不另定冲突格式；不依赖模型重新抄写方法，也不复制父会话全文。之后由主 Agent 汇总或继续处理文件。没有显式选择角色时，主 Agent 仍可按需要自主委派。

所选 Skill 是输入材料，子 Agent 不必拥有 `skill_read` 才能使用已经提供的正文。例如 analyst 当前没有该工具，仍可接收所选方法；这不改变它的工具白名单。方法要求写文件或执行脚本时，只读子 Agent 可提出建议，实际操作由主 Agent 在现有权限下完成。

子 Agent 保留既有独立 JSONL、只读工具、停止信号和结果返回机制。子会话原文不进入父会话压缩；父会话只接收现有最终结果或失败信息。

## 5. 历史记录

文件引用继续使用已有 `berserk.files-input.v1`。为在刷新后还原 Skill／角色选择，并保存真正交给模型的方法正文，使用 Pi 公开 `sendCustomMessage` 在同一 JSONL 中追加一种输入消息：`berserk.composer-input.v1`，不新建数据库或运行状态。

- 仅存在 Skill／角色选择时写入，`display: false`；正文包含本条选用的方法及委派要求。
- `details` 保存 `workspaceId/sessionId/requestId`，以及可选的服务端解析后 `skill: {id,name,description,version,hash,content}`、`agent: {name,description,hash}`。
- 用户正文仍由 `prompt(text)` 保存为普通用户消息，标题和聊天气泡不显示展开后的方法大段文本；前端按 requestId 投影选择标签。
- 标签表示本条请求的选择，Skill 成功加载后可以查看当时正文；不伪造 `skill_read` 的工具调用记录。子任务卡片继续表示实际执行结果。
- 读取时校验归属、字段和重复记录，沿用当前合法历史／中断处理原则。旧会话没有这种消息也正常读取。压缩只改变模型上下文，原始输入记录继续保留。

这条消息补齐的是“结构化选择不能仅靠用户正文恢复”的实际缺口。它不记录新的任务状态，也不承担业务审批、文件版本或自动恢复职责。

## 6. 错误与兼容

- 列表加载失败可以重试查询，不清空正文和已选项；没有候选时说明当前目录／工作区没有可选项。
- 文件被删除、Skill／角色失效或配置变化时，标明有问题的选择，用户可移除或重新选择后发送。请求开始后固定本轮 Skill／角色；文件按现有规则读取当时实际内容。
- 准备失败走当前请求结束及草稿恢复流程，不留下活动会话锁。传输断开先按现有机制查询会话；不因缺少响应自动重发。
- 停止、中断、确认与席位隔离沿用既有行为。`@文件` 加“上报”仍必须通过业务工具和确认，不从标签直接触发提交。
- 不修改 Pi 内核，不升级依赖，不建设全局命令注册器。前端保留普通文本输入和已有添加文件入口。
