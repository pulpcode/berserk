# R1.2 实施计划

按已审阅的 [技术方案](./design.md) 分阶段实施，每阶段以实际数据和会话回放验证。

## 一、验证结果保存和模型引用

- 用最小工单 CSV 样例通过现有 Pi 工具读取并计算。验证原生工具回执的输出体积、截断、会话归属和重启恢复。
- 用两种现行模型协议的可控供应端确认模型拿到可信的结果引用，原生回执及历史解析保持兼容。
- 按当前会话和授权读取结果。覆盖同工作区不同会话、跨席位、撤权和结果缺失，验证拒绝被截断或不完整的结果。

## 二、建立表格和通用柱状图

- 确定 `ResultDatasetV1` 严格解码、共享字段约束和返回错误，接入 `dataset-v1` 目录。用指标清楚的固定样例验证原生消息流和聊天渲染。
- 用普通 React 表格和通用柱状图完成一条从输入文件到展示的闭环。检查在回复生成中出现的实际绘制内容，以及多个组件共用一次授权读取。
- 保留 R1.1 资源展示的流式和历史回归。验证改变工作区同名文件、刷新、重进和服务重启，旧图表仍绑定原结果版本。验证只看图时无须文件交付，单独请求文件时仍可下载。

## 三、补齐四类图表与样例

- 接入饼、折线、雷达和散点图的字段映射、校验及错误状态，每类制作正常和关键边界固定样例。
- 对照数据行、计量单位和计算说明核对显示值，覆盖缺失值、重复或无序时间、非正分母、雷达量程、散点行对齐及点数超限。
- 验证桌面三栏、窄聊天栏、图表尺寸更新、键盘值列表和表格横向滚动。

## 验证与发布

- 在 `experiments/harness-lab` 运行受影响的 Vitest、`npm run typecheck`、`npm run lint`、`npm run build` 和桌面 Playwright。
- 验收记录分别标注固定样例、实际 Pi 文件计算、真实模型和用户体验结果。记录一个文件计算样例与五类图表样例的入口。
- 限量部署时使用现有展示开关控制生成。验证 R1.1 和 R1.2 历史兼容后再开放测试。
