# R1.2 通用计算结果与五类图表技术方案

实施方案。基线为 R1.1 提交 `9f23412`。阶段交付与验收见 [PRD](./prd.md)，执行顺序见 [实施计划](./implement.md)。

## 1. 图表展示与文件下载

只要求看图时，Agent 计算后在聊天内展示图表或表格。刷新和重启后，应用仍可读取当次计算的结果。用户明确要求一份文件时，文件交付可单独执行。两项都要求时，同一次计算可以供两项使用。

例如，Agent 读取一份 Excel 工单明细，汇总得到甲班 12 件、乙班 8 件。保存的是绘图和表格所需的两行汇总数据。输入 Excel 保留原格式，旧图始终引用当次汇总结果。

## 2. 计算结果随 Pi 工具回执保存

首选沿用现有 `bash`。需要展示时，脚本将带有 `format: "result-dataset.v1"` 的单个 JSON 对象输出到命令结果。宿主只识别成功执行后的显式结果，校验完整性、体积和数据结构，随后把数据和归属写入 Pi 原生工具回执详情。普通命令输出继续按现有行为处理。数据超过现有命令回执能力时，请 Agent 缩小展示范围或先汇总。现有执行权限、日志和下载才使用的 `file_output` 沿用各自路径。

宿主向后续模型调用提供固定 `resultRef` 及精简字段信息，向浏览器从现有工具完成事件投影受控数据。会话历史由同一条原生回执恢复数据。Agent 继续在普通回复流中生成 `berserk-ui-v1` 展示块，由前端用 json-render 编译并将数据交给 React 图表与表格。

第一步用真实 CSV 计算验证已选路径，包括实际工具输出边界、历史保存与浏览器恢复。当前方案无需专用 UI 工具、新的结果提交工具或下载。如果发现现有工具回执无法满足已确认的场景，再复核结果交接方式。

## 3. 数据契约草案

采用稳定列 ID 和行 ID。下方 JSON 用于说明展示数据的结构。首版限制为 48 KiB、32 列和 1,000 行，预留 Pi 的 50 KiB 命令输出边界。接收和恢复均校验版本、大小、业务结构与归属。表格分页渲染，图表点数另行限制。数值采用有限 JSON 数值。整数限于 JavaScript 安全整数范围，需精确表示的更大数值由计算步骤先确定可用刻度。缺失统一写 `null`。

```json
{
  "format": "result-dataset.v1",
  "columns": [
    { "id": "team", "label": "班组", "type": "string" },
    { "id": "orders", "label": "工单数", "type": "number", "unit": "件" },
    { "id": "avgHours", "label": "平均耗时", "type": "number", "unit": "小时" }
  ],
  "rows": [
    { "id": "team-a", "values": { "team": "甲班", "orders": 12, "avgHours": 3.2 } },
    { "id": "team-b", "values": { "team": "乙班", "orders": 8, "avgHours": null } }
  ],
  "provenance": {
    "source": "工单明细 CSV",
    "scope": "本批输入中可识别班组的工单",
    "method": "按班组计数，耗时仅纳入已填报记录"
  }
}
```

- 列类型建议为 `string`、`number`、`boolean` 和 `datetime`。时间列采用带时区的 ISO 8601 时间，主机按实际时序排序。列和行 ID 唯一，每行的字段与声明的列一一对应。校验重复 JSON 键、未知属性、错误类型和非有限数值。
- 数值列可提供单位。未声明单位的字段用未标注的尺度展示。仅在单位和计算口径可核对时共享数轴。需作为业务指标展示的加总、百分比和单位换算由脚本给出。饼图根据所选非负原值计算构成比例，并展示对应的分母。
- 雷达图选中的数值列还需提供 `radarScale`，包含 `min`、`max`、`direction` 及量程来源说明。范围外值产生可读的校验反馈。
- `provenance` 保留输入、统计范围和运算方法，展示时注明其为本次计算的说明。图表值通过列和行 ID 对应到固定数据。聚合值通过数据行及所声明的计算方法核对。

## 4. 结果引用、授权与恢复

图表和表格使用经校验的计算结果引用。同一回复中的组件可以共用一次授权读取。结果引用应绑定当前会话、产生结果的工具记录及固定版本。模型提供图型、列 ID 和受限的展示选项，React 根据结构化结果构造图表和表格。

首个组件可渲染时即可显示数据。重新进入会话、刷新或重启后，应用重新按会话权限读取原结果版本。结果缺失、权限不足、版本不支持和完整性异常应有可读反馈。已有 `resource-v1` 用原路径回放。关闭生成后继续支持兼容的历史展示。

## 5. 图表与表格约束

| 图型 | 首版配置 | 值校验与反馈 |
| --- | --- | --- |
| 柱状图 | 分类列，单个或多个并列的同单位数值列，可横向排列 | 分类需能区分数据行，重复分类由计算步骤产生汇总行。未知数值保留缺口和说明。柱形与展示单位可从表格核对 |
| 饼图或环形图 | 一个分类列加一个可相加的数值列 | 同一统计总体，显示分母。数值须非负且总和大于零。缺失部分提示无法确认构成比例 |
| 折线图 | 时间列或数值顺序列，同单位的一个或多个数值系列 | 按 X 排序。重复时点要求先汇总或明确分列。有效 X 上的空 Y 保持断点，缺 X 的条目单独报告 |
| 雷达图 | 对象标识与多个具备独立量程及方向的数值列 | 用固定量程归一后绘制。工具提示和表格保留原值和单位。缺失维度或越界值提示数据不足，拒绝推导排名 |
| 散点图 | 同一数据行的两个数值列 | 两轴各自显示单位。缺失任一轴的行退出绘图并报告遗漏量，通过行 ID 核对原表 |

图表提供对照数据或可键盘展开的值列表。表格支持按固定列顺序回看、分页和桌面窄栏的可聚焦横向滚动。首版图表建议最多绘制 1,000 个有效点，超限时返回明确反馈，表格继续支持读取完整数据。大数据可在计算步骤中明确分组或汇总。

## 6. 验收与风险

1. 用一份已知答案的工单 CSV 跑通上传、实际计算、保存结果与原聊天展示。核对只请求看图时没有 `file_output` 调用或下载卡。让模型继续输出解释，在回复结束前分别观察图表和表格真实内容。用独立期望值核对 12 件、8 件等数值以及耗时未知值。
2. 五类图表均提供一份正常数据和一份关键边界样例，并验证与表格对应。覆盖窄桌面栏、图表下钻数值、表格横向滚动及较长标签。
3. 验证同会话刷新、重新进入、服务重启和修改工作区同名文件后，历史仍读取原固定版本。覆盖同工作区不同会话、不同席位、撤权及结果缺失。加入截断或非法回执样例。
4. 重放 R1.1 资源围栏和旧 `file_output` 历史，验证单独请求文件时仍可独立完成文件交付。用可控供应端核对两种现有协议的出站引用，在选定模型上观察一轮真实流式体验。记录确定性验证、真实模型验证和用户验收各自的结果。

先完成一条真实计算、流式展示和历史恢复的纵向链路，再接入其余四种图表及边界样例。自由制图、可编辑结果和对复杂图表的临时聚合沿用阶段总规划。
