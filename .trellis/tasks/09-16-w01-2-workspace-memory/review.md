# W01-2 审阅入口

日期：2026-09-16。状态：**已按获准设计完成实现和 A01～A12 组合验收（2026-09-17）。** 本任务是 W01 的子任务，对应 S2a。W01-1 的实现与验收保持有效。

## 1. 本次交付什么

在现有多轮对话页面上增加工作区。每个会话固定属于一个工作区；同工作区会话可以使用相同资料和 AGENTS.md 约定，聊天历史仍然独立。用户可以直接编辑工作区指令，也可以在对话中明确要求 Agent 记住或修改约定。Agent 可以按目标读取固定 Skill，组合受控工具形成或检查回答。

文档统一称为“Agent 指令文件（AGENTS.md）”；页面使用“通用指令”和“工作区指令”。

建议将 S2 分为三个增量：**S2a 工作区、Memory、Skill → S2b 上下文压缩 → S2c 只读 Subagent 与累计预算**。本次只实施 S2a，不把 S2b／S2c 视为已完成详细设计。

用户已明确：跨会话检索／引用后置，是否引入及规则尚未决定，不纳入本期或自动排入后续阶段。本期同区共享指令与资料，会话不检索其他会话，也不读取其他工作区的 AGENTS.md。

用户已确认页面编辑冲突的处理方式：保留正在编辑的草稿，“查看最新内容”只在单独区域显示服务端文件；用户对照合并后再保存，或主动选择“放弃草稿，使用最新内容”。查看本身不能丢弃草稿。具体场景、按钮行为和分工见 [页面冲突设计](design.md#31-页面编辑指令时发生冲突)。用户随后已明确要求按本阶段设计开始开发。

## 2. 优先审阅的决定

以下为本轮已获准实施的方案范围：

| 审阅项 | 本方案建议 | 对使用体验的影响 |
| --- | --- | --- |
| 工作区与业务任务 | 本期支持创建／切换工作区、在其中建立多个会话；不增加业务任务状态和分派 | 先有明确的资料与约定归属，仍以对话为主体 |
| 历史会话 | 现有全部会话归入“默认工作区”，保留 ID、历史与草稿；会话创建后不跨工作区移动 | 旧对话可继续使用，避免携带旧历史进入另一范围 |
| Memory 共享范围 | 一份只读通用指令 + 每工作区一份可编辑 AGENTS.md | 修改影响该工作区后续请求；不同会话不互读聊天 |
| 生效时点 | 保存后下一次请求加载新内容；正在回复的请求继续使用开始时的版本 | 可以在回复期间编辑，页面明确提示“下次发送时生效” |
| Agent 修改方式 | 用户在对话中要求“记住／修改约定”，Agent 使用当前工作区的受控编辑工具 | 沿用自然对话，不增加每轮许可开关或确认卡；宿主限制可写文件，模型不得自选权限 |
| Skill 范围 | 两个固定、只读 Skill：资料综合写作、结果检查；Agent 按需读取 | 本期不做 Skill 编辑、安装市场、脚本执行或专门选择器 |
| 文件和资料入口 | 受控工作区目录；预置通用测试资料；页面通过 ID 查看 | 本期没有任意本地目录挂载、文件上传或完整文件管理器 |

业务任务将来可以关联工作区，承载目标、负责人和交付状态；本期不预设一个业务任务必然等于一个工作区。MVP 正式任务工作区的关系在 S3／M1 明确。

## 3. 可以怎样验收

1. 创建两个工作区，分别写入不同约定；每个工作区建立两个会话，检查约定共享与聊天隔离。
2. 修改／删除约定后，在当前会话追问、另一会话追问，以及重启后追问，验证加载的是当前内容。
3. 要求 Agent 记住一项约定，再要求更正或删除；核对工具结果与文件内容，同时验证只读通用文件和别区文件无法写入。
4. 用相同工具集合完成概括、综合写作、检查修订三种目标；实际读取 Skill 和资料，普通问题允许直接回答。
5. 打开指令面板增加“先给结论”但不保存，再通过对话让 Agent 保存“注明来源”。回到面板保存，应提示冲突且保留草稿；查看最新内容不覆盖草稿，手动整理后可保存两项约定。另验主动放弃草稿、读取失败及合并保存前再次更新，确保不丢未保存修改、不自动写文件。
6. 验证取消与写入竞争、刷新和切换工作区、旧会话过渡及配置损坏。检查原文件、实际模型输入和页面结果。

详细通过条件为 [A01～A12](prd.md#验收标准)，与父任务 T06／T07 部分能力对应。通过本期不等于完整 T06／T07、S2 或业务 MVP 已通过。

## 5. 实施准备与限制

继续使用现有 TypeScript／Node、React、Fastify、Pi 0.85.1 和已配置的 DeepSeek Flash。无需新增 API Key 或 Ubuntu 凭证。真实验收使用独立目录；已有会话升级前先停服并备份。

本期继续单一本地主体、单服务进程和原生会话历史。新增小型工作区目录索引，不引入 SQLite、完整 Run、确认流程、操作账本或成果版本。用户指令是可编辑文件，不承诺不可篡改审计或运行中崩溃恢复。

用户已批准上面的范围及使用行为。技术验证点已有明确验证步骤；如实际 Pi 接口不能满足“新规则生效且历史不重放”，先修订接法，不降低验收条件。
