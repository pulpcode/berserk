## 4. 风险、停止条件和回退点

| 风险 | 必须检查／处理 |
| --- | --- |
| 重建实例丢失或重复历史 | P0 先用真实 Pi 原生会话验证，再增加功能；禁止业务代码拼接重放消息 |
| 指令改动影响错误范围 | 读取、写入、UI 草稿及异步响应均绑定 workspaceId，测试同区／跨区并发 |
| 更新规则仍受旧历史影响 | 同时检查当前系统输入和真实追问；失败时改进装配及优先说明，再复测 |
| 文件写与原生工具记录不原子 | 以文件状态核对，明确结果未知；不自动重放写操作，不冒充 S3 恢复 |
| 旧数据归属错误／索引损坏 | 备份、初始化标记、迁移报告与故障注入；损坏停止写入，禁止猜测重建 |
| 范围逐步膨胀 | 不加入 SQLite／Run／任务分派／上传／任意 Shell，压缩和 Subagent 独立审阅 |

开发和测试先使用副本。用户现有数据在 P1 检查通过后、实际升级前才按 [设计第 9 节](design.md#9-旧数据过渡与回退) 操作。任何失败保留原目录和备份；不把用户 `.local` 当测试清理目录。
