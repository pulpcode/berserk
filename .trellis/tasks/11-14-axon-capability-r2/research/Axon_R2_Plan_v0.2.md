### 2.1 必须尊重的现有契约

R1 修订 ID 为 rev-<digest>，内容摘要包括 releaseVersion 和锁定技能正文；SkillRevision 暂保留 legacy version 字段。R2 不原地改写这些对象，不批量改号，也不借本轮将技能存储提前升级成 R3。[S2、S6]

R1 访问规则目前是账号维度的最小拒绝机制，不是完整席位白名单。R2 需显式增加席位授权并兼容原账号拒绝，不能把“没有拒绝记录”理解为新专家对所有人开放。[S2]

## 三、页面与专家配置

### 3.1 页面分工

| 入口 | 操作与边界 |
| --- | --- |
| 能力中心 → 专家 | 普通用户查看获准专业专家，查看依赖和版本，点击“与专家协作”；不显示通用助手及仅委派角色。 |
| 能力中心 → 专家管理 | 仅管理员可见。列表区分草稿、已发布、停用、归档；详情包含编辑、检查／试用、发布历史、操作记录及使用范围。不提供紧急停止入口。 |
| 设置 → 个人偏好 | 设置默认专家、恢复继承；可明确选择通用助手。只改个人偏好，不改共享专家或席位授权。 |
| 管理 → 席位使用配置 | 管理员设置席位可用专家与默认专家；不改原业务权限。 |
| 任务设置 → 默认专家 | 沿用现有任务管理权限。公共任务管理者、个人空间所有者各管其范围；管理员身份本身不额外授予任务修改权。 |

### 3.2 管理员编辑哪些内容

| 内容 | 本轮规则 |
| --- | --- |
| 名称、简介、专业指令 | 稳定 expertId 由服务端生成；名称可调整。专业指令包含职责、工作步骤、输入与交付要求，不替代平台规则。 |
| 技能依赖 | 只从已纳管的受控技能中选择；校验／试用固定正文、revisionId 与 digest，发布沿用同一快照。无新增技能或上传入口。 |
| 工具范围 | 从服务端工具目录勾选，按读取、文件作业、业务动作分组；必须显式列出。allowedTools:null 仅保留系统内置兼容用途。 |
| 发布说明 | 记录本次变更及影响；releaseVersion 自动生成，revisionId 与 digest 不可手填。 |
| 使用范围 | 选择全部获准业务席位或指定席位；新专家默认未开放，发布前必须明确范围。与内容修订分开管理。 |

本稿建议 R2 网页编辑聚焦交互主专家。可使用现有单层、顺序、只读委派，但不新增自定义子角色管理或开放写入／递归委派。原 analyst/reviewer 保持原行为；该范围取舍列入 Q1 审阅。

通用助手、内置示范及兼容角色在管理员列表可只读查看。示范专家可复制为新组织专家；新 ID、独立草稿，权限不会随复制自动授予，试用证据也不继承。通用助手核心配置不开放编辑或删除。

## 四、草稿、校验与隔离试用

> 创建／复制 → 保存草稿 → 自动校验 → 隔离试用 → 管理员确认 → 发布。R2 检查的是专家配置；技能包解析、代码扫描和依赖安装不提前纳入。

### 4.1 草稿与校验

每个组织专家先维护一份共享工作草稿，以 draftRevision 做乐观锁。管理员并发保存冲突返回 409，保留本地输入；草稿变化不影响已发布会话。校验和试用绑定 draftDigest，修改可发布内容或依赖后，旧证据失效。

| 检查项 | 检查方式及结果 |
| --- | --- |
| 格式与字段 | 服务端检查必填项、长度、允许字段、模式和标识；拒绝伪造 system、身份、路径、revisionId 等字段。 |
| 依赖与能力 | 核对技能快照、工具目录与适用模式；不把 Skill 中的文字当作授权。未知工具、缺失必需依赖明确阻断。 |
| 使用范围 | 检查目标席位有效且有业务资格；能发布配置不代表这些席位一定拥有全部业务能力，界面分别展示。 |
| 配置风险 | 提示业务写动作、文件写入等需要注意的能力；管理员逐项确认。自然语言风险分析可辅助，不作安全证明或放行依据。 |

### 4.2 试用不是先把草稿发布出去

新增管理员专用“试用专家”入口，试用固定草稿快照，不创建普通已发布修订，不出现在用户目录。由现有 Pi 装配／执行逻辑承载，新增 trial 运行入口与鉴权，不另写模型循环。

使用独立试用目录和测试会话，只放管理员明确提供的合成／脱敏文件。输入、输出、日志和历史独立于正式任务；不挂生产凭证、不借用其他席位，不允许正式指令下发、成果提交或修改真实任务。需 Docker 时沿用受控镜像和无网络边界。

只读业务查询采用明确的测试来源或替身，并在报告中标明；不能用替身结果宣称真实外部集成已验证。必需依赖不可用则试用不能判为通过。非必需、未覆盖能力明确列为未验证，不补造调用。

试用记录至少包括草稿摘要、技能快照、目标运行模式、实际工具集合、模型／运行环境、输入、工具调用、成果、异常及管理员结论。模型调用可能产生费用；不自动重试或批量重复运行。

至少一次代表性任务通过且管理员确认，才可发布。纯文本专家不强制要求 Docker；涉及文件脚本的专家必须完成相应环境验证。修改草稿、关闭必需依赖或显著改变试用策略后需重新校验。

## 五、发布修订与生命周期

### 5.1 发布的一致性

发布请求携带 clientActionId、expectedDraftRevision、expectedCurrentRevisionId 及检查／试用引用。服务端先查询同一动作回执，再校验当前管理员身份、草稿摘要、依赖与证据；同键同参数返回原结果，异参数返回 409。

新专家首次 releaseVersion 为 1.0.0，普通更新自动递增 PATCH（建议规则，见 Q2）。版本分配在发布锁／事务内完成，同一专家不产生重复发布号；不根据自然语言自动猜测 MAJOR/MINOR。相同内容再次提交提示“无变更”，不制造空版本。

继续使用 R1 的不可变修订和只读内容存储：先持久化并校验内容，再事务提交修订、当前指针、发布记录和动作回执。发布失败不得留下可见半成品；启动及重试不得重复分配版本。

已有 R1 修订可能同 releaseVersion 而内容不同，保留其原始数据。R2 新发布规则仅约束后续正式发布，不能为加唯一索引而改写旧修订或会话。新版本不改绑旧会话；普通用户只对当前修订新建专业会话。

### 5.2 操作语义

| 操作 | 对新工作与在途执行的影响 |
| --- | --- |
| 发布新修订 | 只更新当前发布指针；新会话使用新修订，旧会话继续原修订和锁定依赖。 |
| 普通停用 | 按专家整体或指定修订阻止新会话、新请求及追加输入；已接受请求在原范围内收尾。 |
| 恢复启用 | 仅恢复普通停用（disabled）；不得解除 banned 或覆盖其他授权限制。不自动重放已完成或中断的请求。 |
| 归档 | 用于不再维护的组织专家：先按停用规则收尾，再从普通目录移除；保留内容、绑定和管理记录，不物理删除被引用修订。 |

操作前展示影响：当前默认引用、依赖与活跃请求数量；若无法完整统计就标注未知。普通停用不主动取消已接受请求。记录管理员、对象／修订、原因、前后状态与回执。普通恢复只允许处理 disabled；对 R1 已有的 banned 状态和撤权限制必须拒绝越权解除。紧急停止、封禁处置及跨后台／连接器协调在独立安全治理专题评审，R2 不新增相关管理入口或中断架构。

本轮提供历史查看与差异；历史内容可复制为新草稿，重新校验试用并发布为更高版本。它是前向恢复，不倒退当前指针，也不修改旧会话。

## 六、默认专家与使用授权

### 6.1 默认只决定新会话，不授予权限

> 会话显式选择 → 任务明确默认 → 个人默认 → 席位默认 → Axon 通用助手。只有“未配置／继承”才继续向下查找；命中的配置失效时明确报错，不静默跳过。

个人与任务设置采用三种语义：继承、明确使用通用助手、使用指定专业专家。通用助手只作为设置中的基础选项，不在专业专家列表增加卡片。个人默认是账号级偏好，任务默认仍可优先；界面展示最终生效来源。

| 情形 | 结果 |
| --- | --- |
| 无任务默认；个人继承；席位默认筹划专家 | 新建对话选择筹划专家。 |
| 个人改为获准的态势专家 | 无更高优先级配置时，新会话用态势专家；旧会话不变。 |
| 任务明确默认 A；个人默认 B | 任务中新建会话默认 A；用户可显式选择其他获准专家。 |
| 命中的默认已停用、无权使用或依赖缺失 | 提示是哪一级设置失效，提供修改／选择入口；不偷偷切换通用助手。 |
| 同一创建操作重试时，默认或当前修订已改变 | 恢复原创建意图的修订与会话 ID，重新鉴权；不创建第二个会话。 |

默认配置保存 expertId 与“跟随当前已发布修订”语义；创建意图首次接受时才解析具体 revisionId 并持久化。已有会话始终绑定原修订。已完成创建在随后撤权时可按原会话权限显示历史，但禁止新执行；未完成创建不得越过当前授权。

### 6.2 席位与账号授权

新增组织专家使用范围可选“全部业务席位”或明确席位集合，默认空范围；管理员发布前明确选择。沿用 R1 既有资产的使用行为，不在迁移中突然锁死通用会话。

最终可执行能力取现有业务权限、席位使用范围、账号限制、专家工具范围、任务限制与运行模式的交集。设置默认不产生 grant；账号明确拒绝不能被席位允许覆盖。管理员试用也不能借管理员身份获得正式业务权限。

身份从服务端登录会话取得。R1 principalId-only 的检查扩展为同时识别 userId、seatId；目录、详情、默认保存、创建、续聊及工具调用均复核。账号及席位授权调整必须保留 R1 已有实时鉴权和撤权安全守卫，并复核等待审批后的执行；这属于原有安全约束，不构成 R2 新增“紧急停止专家”功能。

R2 个人偏好以默认专家为必做；收藏仅作为可选轻量项，不引入私人能力资产或分享发布流程。

## 七、技术落点与接口

### 7.1 在既有服务上增加管理层

保留 CapabilityService 的不可变内容解析、缓存、请求守卫及创建意图；将 R2 管理流程分离到草稿、发布、试用、默认／授权服务。新增文件名和接口为建议，开工时按仓库规范校核，不把所有逻辑继续堆入 lab.ts。

| 对象／存储增量 | 职责 |
| --- | --- |
| ExpertDraft、ValidationRecord | 可编辑内容、draftRevision/digest、基线发布修订与结构化检查结果。 |
| ExpertTrial | 固定草稿快照、试用拥有者、受控目录、实际运行记录与确认结论；草稿试用不污染正式会话索引。 |
| Publication、ManagementAction、Audit | 发布号、修订映射、幂等回执、状态变更及操作者；与能力库事务协调。 |
| ExpertUsePolicy、ExpertDefault | 席位使用范围和账号限制；账号／席位／任务的继承、通用或专家选择，带并发修订。 |
| 内置／组织来源 | 服务端维护配置归属。内置登记只处理自身资产；网页发布不能占用内置 ID，也不能把 system 伪造为 false。 |

上述为概念对象，表结构可合并，但必须扩展 capabilities.sqlite 的版本化迁移。未发布新专家只进入草稿存储，不向 R1 的 current_revision 写空值或伪发布修订。旧 ExpertRevision／ExpertBinding 保持可解码；新增不可变字段或 Pi 记录时显式升级 schemaVersion，不修改旧摘要算法。

### 7.2 建议 API 分组

| 接口族 | 主要能力 |
| --- | --- |
| /api/admin/capabilities/experts/* | 组织专家列表与草稿；validate、trials、publish；release history、普通停用／恢复启用、archive；使用范围。不提供封禁写接口。 |
| /api/me/preferences/expert | 读取／更新个人默认；目标账号来自登录身份，不接受客户端冒充 userId。 |
| /api/admin/seats/:id/expert-default | 席位默认与作用范围；管理员鉴权，不扩大原业务授权。 |
| /api/tasks/:id/expert-default | 任务默认，沿用任务原管理／个人空间归属权限。 |
| 原 /api/sessions 与能力目录 | 保留 R1 接口兼容；加入服务端默认解析及选择来源；与专家协作仍只创建空会话。 |

所有管理写入使用乐观锁；有副作用的操作加持久化 clientActionId。发布、停用、权限变更提交前重新鉴权。管理控制不依赖前端隐藏按钮；页面首次加载不调用模型。

## 八、实施顺序、迁移与回退

R2 编码建议分为以下工作包，每包同步增加测试。方案通过不代表已创建分支或已获准发布服务。

| 工作包 | 交付与退出条件 |
| --- | --- |
| R2-0 基线与收口 | 完成 R1 最终验收核对、最新 SHA 差异清单、锁定依赖与测试基线；建立独立工作分支和 Trellis 任务。 |
| R2-1 存储与管理契约 | 草稿／检查／试用／发布／默认的 DTO 与迁移；内置来源保护、管理员鉴权及审计；迁移重入和并发单测。 |
| R2-2 专家编辑与校验 | 创建、复制、草稿编辑、依赖和工具选择、CAS 冲突；管理员真实 API 下可保存校验，普通用户拒绝。 |
| R2-3 隔离试用 | 新增 trial 入口，复用 Pi 执行与受控样例空间；记录工具、成果、取消、重开和撤权；草稿不得绕过发布进入普通会话。 |
| R2-4 发布与生命周期 | 正式发布、自动版本、幂等回执、差异与历史、普通停用／恢复启用／归档和使用范围；不暴露 banned 管理操作；重启不被内置登记覆盖。 |
| R2-5 默认与使用配置 | 个人、席位、任务默认及来源提示；所有用户发起会话入口共用解析；重试固定首次结果。 |
| R2-6 验证与交付 | 全量与定向回归、浏览器、真实模型／Docker、迁移回退、性能对照、用户验收；区分每类证据。 |

### 8.1 必须覆盖的兼容路径

普通新建、专家协作、工作交接签收、信息接手等“用户发起新会话”入口都要逐一盘点。现有服务预处理／持续研判及 seat_analysis 保留 R1 行为，不因新增个人默认被悄悄改用另一专家；其统一化仍在 R5。

旧会话绑定、旧角色、旧技能正文和当前已保存历史按原语义读取。测试应覆盖本分支合并后的 assistant.updated、可见思考／工具过程与侧栏状态，不能只回归 R1 合并前版本。[S1、S3]

### 8.2 迁移及回退

先在数据副本 dry-run，列出内置来源、历史版本重复号、现有拒绝规则及未完成创建意图；停服完整备份后 apply。保留所有原 revisionId/digest 与字节，不覆盖旧认证库的可选模块版本。

回退必须配对 R1 程序和 R2 前完整备份，同时保留 R2 新数据供核对；不允许旧程序直接打开 R2 活动库。试用失败、发布响应丢失或升级中断均不得自动重放用户任务。

## 九、验收清单与交付门槛

以下是 R2 待执行标准，不是本次测试结论。专家生效主要核对服务端实际指令、依赖快照、工具集合和记录，不只观察模型末尾关键词。

| 编号 | 必须证明的行为 |
| --- | --- |
| B01 权限与内置 | 管理员可管理组织专家；普通账号写接口 403；内置资产不可冒名覆盖；通用助手不在专业列表。 |
| B02 草稿一致性 | 多人编辑冲突保留草稿；草稿变化使旧校验／试用失效；已发布会话不受草稿影响。 |
| B03 配置校验 | 未知工具、非法模式、伪造 system、损坏依赖明确拒绝；空工具集合合法，绝不回退全量工具。 |
| B04 隔离试用 | 纯文本及文件样例真实执行；无生产秘密和跨席位数据；试用不进入普通目录或默认项。 |
| B05 试用收敛 | 停止、服务重启、管理员撤权不继续新调用；未验证与失败如实显示，不自动重新运行。 |
| B06 发布原子性 | 同键并发或响应丢失仅一次发布；旧草稿／基线冲突 409；半成品不可见，无变更不重复发版。 |
| B07 修订与重启 | 新会话用新修订，旧会话刷新／重启仍用旧内容；启动不覆盖组织专家；历史 R1 重复版本号仍可读。 |
| B08 状态与影响 | 普通停用阻止新会话、新请求和追加输入，已接受请求按原快照收尾；恢复仅解除 disabled；归档保留历史；R1 既有封禁／撤权守卫不得回归。 |
| B09 默认规则 | 五级优先级、继承／通用／指定专家均正确；失效配置不静默降级；个人不修改席位公共默认。 |
| B10 默认幂等 | 创建中途更改默认／发布新修订，同一 clientActionId 仍返回原绑定；新动作才能解析新默认。 |
| B11 全入口授权 | 席位与账号限制贯穿目录、默认、创建、续聊、委派和工具；管理权不扩大业务访问，授权撤销沿用既有安全守卫，不额外开发统一紧急停止。 |
| B12 兼容与运维 | R1 A01–A12、聊天合并回归、旧角色／技能／交接／后台均不退化；完整备份回退通过。 |

### 9.1 检查与交付证据

执行仓库锁定的 typecheck、lint／边界、build、单元／集成和浏览器回归；记录最终提交、命令、环境与失败修复重跑范围。全量首次失败后仅定向重跑，不能称为“最终全量全部通过”。

真实模型与 Docker 单列：至少完成一个组织专家的编辑→试用→发布→默认新建→多轮→更新→旧会话续聊流程。提供冷／热加载及发布并发下的测量，与 R1 同环境比较，不把替身首文本耗时当真实模型性能。

退出条件：阻断项清零、数据迁移回退可证明、用户完成实际交互验收。环境缺失和未测试项必须保留为待验证，不用截图或页面可打开替代完整链路。
