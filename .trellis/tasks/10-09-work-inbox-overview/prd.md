# 统一席位待办与工作总览

日期：2026-10-09。状态：**待审设计，planning；产品实施未批准。**

## 1. 目标

让各席位从一个入口找到自己需要处理的外部信息、交接工作和对话回应，让总体席在获授权范围内查看整体推进情况。消除“工作待办／收到的信息／信息处理中心／全部动态”之间的职责混淆，同时继续在具体任务中开展分析与成果工作。

## 2. 已确认背景

- 用户已确认：工作待办原指席位间工作交接，收到的信息原指外部系统来信；两者应探索统一办理入口，全部动态不再保持独立一级入口。
- 用户已要求参考 main 在途的总体席、情报席、筹划席、态势席定义；本次只交付独立 worktree 中的设计文件，供审阅。
- 现有交接只允许发起者和承办者读取；收件没有人员阅处状态；全部动态仅汇总本席位对话；信息中心尚不包含跨席位完整工作交接总览。证据见 [现状依据](research/current-state.md)。
- 补充投递审批为可选兼容能力，基础改造不依赖它完成或启用。

## 4. 本版业务规则（待整体审阅）

统一的是办理入口，不替换各类业务责任。信息阅处表示本席位已经处理这份来信的当前需要；后续工作可以继续。工作验收表示发起方接受该次交付。补充投递批准只决定接收范围。三者不能相互推导。

新投递各自登记阅处，重试原投递不新增；重新分析形成的新投递拥有独立阅处状态。总体只读摘要中可看到各席位阅处进度，但不能替其他席位标记阅处。

总体对公共工作查看的范围为标题、任务、分派双方、业务状态、时间及交付版本摘要。已授权参加该工作的人员继续通过原详情读取文件；只读总览权限本身不授予文件、正文和私有会话访问。

历史记录没有可证明的人员阅处事实，升级时归为“历史未登记”；进入全部列表仍可查看，人员可主动列入待阅处或标记已阅处。旧交接状态保持原样。

## 5. 范围

包括导航重组、统一待办、最小信息阅处能力、跨席位只读工作摘要、现有信息中心承接、权限与历史兼容、对话提醒归位和可选审批适配。

不包括自动判断人员是否完成工作、强制信息签收或逐条验收、批量自动结清、逾期与催办、代理审批／代办、多级组织权限、跨席位全文会话监控、任意成果共享、通用事件总线或流程引擎。

本版为完整待审建议，用户尚未批准细节及实施。审阅重点为信息阅处方式、历史记录默认处理、总览只读边界，见 [审阅入口](review.md)。技术落点与验证计划已列明；启动产品实现前须取得对本版的明确批准，并核对 main 最新已提交接口与迁移版本。
