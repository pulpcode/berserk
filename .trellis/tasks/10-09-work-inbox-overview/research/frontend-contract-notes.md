# 本次入口调整需要保留的前端契约

这是从 [现有前端规格](../../../spec/frontend/harness-lab.md) 提取的任务相关阅读索引与约束摘要，基于 `4fd9565`；不修改也不替代原规格。原文件超过上下文注入单文件上限，因此清单优先注入本摘要，实施时按下列主题读取原文。

## 1. activity、导航和未读

- useChat 继续拥有选中会话、草稿、流、快照、请求修订和全局 activity 轮询。activity 更新不能覆盖本地当前流拥有的状态，也不能因为删除动态页面而被删除。
- 轮询保持同一请求最多一个在途；失败保留旧数据并提示过期，回焦刷新，重试只读取，不自动重放 POST／PUT。
- 原结果已读须满足当前前台对话、快照和摘要的成功 requestId 一致、没有活动请求或遮挡、滚动到末尾。查看待办或工作总览不标记回复已读。
- 切换视图和任务需使旧异步创建／准备的自动跳转失效；迟到结果仍可在原归属下显式打开。不能抢走用户后续选中的任务。
- 新建对话、详情抽屉、设置和窄屏菜单的焦点与返回状态继续保留。列表更新不能把阅读位置推回末尾。

## 2. 信息接续与交接

- 信息接续绑定固定 task/event/job 或 delivery，不随筛选切换把结果写进另一条信息。
- 信息详情自己的选择世代和父导航世代都需有效，才能写入草稿／进入准备好的会话；仅 URL 归一化不误判同一原点。
- 只有明确“发送并进入对话”才发送一次；准备、查询回执、刷新、重新打开都不自动发送。
- WorkInbox 未完成 prepare/commit 必须保留查询结果入口、原参数、固定文件与确认状态；抽组件不能丢失这些状态。
- 权限冲突或业务冲突保持用户编辑内容，重读最新服务状态，不伪造成功。

## 3. 身份与任务范围

- API client 绑定本次登录 viewId／席位，换身份后旧 client 中止；迟到回调不读取全局可变席位。
- public 任务的会话与文件仍按任务 × 席位隔离；任务目录可见不等于其他席位历史可见。
- 浏览详情、相关信息和能力选项不能创建工作区、复制文件或启动模型。
- 禁止把后台作业、回复成功、阅处完成和工作验收的不同状态相互推导。

实施者需重点阅读原文的 workspace/activity/read markers、conversation creation/navigation、information continuation 和 async origin reconciliation 相关段落，并以实施基线版本为准。
