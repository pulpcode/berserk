# 验收清单

状态：计划用例，**尚未执行产品验收**。编号供 PRD 与实施计划引用。

## 1. 测试准备

使用隔离数据创建总体、情报、筹划、态势四席位；总体显式授予工作总览，来源查看／管理和资料权限另配。准备两个公共任务和一个私有空间、两种来源，其中一种仅部分席位可读。审批启用与未启用各运行一组。

准备工作交接各原状态、新投递、升级前 delivered、升级前仍 pending／failed 的投递、同一事件重新分析版本、关联多个任务的信息，以及待回答、待确认、失败、未读回复的本席位会话。不使用真实账号或生产资料。

## 2. 验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AT01 | 普通席位进入应用，分别收到工作和外部信息 | 统一工作待办入口；列表清晰区分来源、类型、责任与动作；无独立收到的信息／全部动态入口 |
| AT02 | 分类型、任务和关键词查询超过一页数据 | 权限过滤后统一排序分页；非首屏记录可找到，数量与对应筛选一致，不拼接各源第一页 |
| AT03 | A 分派、B 签收、提交、A 退回、B 重交、A 验收 | 业务状态沿用原流程；提交后 B 为跟进中、A 为待验收；双方已完成视图一致；只有发起者验收 |
| AT04 | 打开信息、阅读分析、继续对话、后台分析完成 | 不自动变为已处理；人员点击后只改变本席位处理状态；不强制交付文件，不停止后续对话 |
| AT05 | 标记已处理、重新列入、多浏览器并发及断网后查询 | revision 防覆盖；同 action 回执不重复；状态与操作者可重读，不盲目新建 action；其他席位不受影响 |
| AT06 | 投递重试、同事件重新分析、关联两个任务、固定与补充给同席 | 原投递不重置或重复；新分析投递独立待处理并标版本；多任务只一项收件；同 job/seat 唯一 |
| AT07 | 迁移前已 delivered，以及迁移时尚未送达的记录 | 前者为历史未登记，仅全部可查，可人工纳入或结清；后者今后首次送达成为待处理；不虚构已读事实 |
| AT08 | 未打开的任务对话等待回答／确认，随后解决或取消 | 待办有可直达提醒；进入原交互卡处理，无列表代批准；解决后消失；重启失效不重放授权 |
| AT09 | 对话运行、新回复、失败；侧栏任务折叠 | 转圈表示处理中，蓝点表示新回复，橙黄色点表示待确认，红色用于异常；对话行无重复状态文字，保留悬停说明及无障碍标签；新回复与待确认并存时优先待确认；任务折叠后仍可发现提醒；待办提醒保留操作文字；新回复不计为待办理，阅读仍需原未读条件 |
| AT10 | 保存草稿／文件选择／未完成交接准备后切换待办、总览、任务 | 草稿和查询结果恢复入口可用，滚动与返回位置正确；切换不取消执行、不自动提交或发送 |
| AT11 | 未参与某工作且获只读总览的总体查看公共工作 | 可见授权摘要和当前责任方；无资料／私有对话字段；原详情、文件、验收权限仍严格限双方 |
| AT12 | 同一项工作在双方待办和总体摘要中推进；信息多次分析 | 同一原记录状态收敛；区分送达、处理、交付；旧作业版本不覆盖新投递含义，不产生伪整体百分比 |
| AT13 | 仅有来源查看权，或只有公共任务管理权，或席位改名为总体席 | 不自动取得跨席位工作摘要权；规则修改／审批／队列权限分别判断；仅来源权限者仍有信息总览 |
| AT14 | 撤销权限后刷新、搜索、翻页及访问旧详情 | 标题、数量与内容都不能泄露；所选旧详情清除并提示；私有任务不进入总体摘要 |
| AT15 | 可选审批存在：从待办批准／拒绝，再从总览查看 | 操作同一 review；原决定、候选与回执复用；批准不创建工作或标记处理，固定投递不等审批；发送失败不重开审批 |
| AT16 | 无审批、审批未启用、无审批权、审批服务失败 | 前三种按能力省略且基础功能完整；最后一种显式故障、未知数量，不伪装成无待办 |
| AT17 | 旧 inbox、information 各栏目链接，新 work／overview／会话直达，刷新返回 | 落到正确对象和筛选；别名无额外返回层；组件不写回旧路径；越权直达有明确反馈 |
| AT18 | 登出换席位、迟到响应、服务重启、处理事务中断 | 旧身份数据不进入新页面，动作不串席位；已提交回执可查；未提交事务无半条数据；刷新不触发模型 |
| AT19 | 交接、信息或审批某一读取失败；activity 轮询失败 | 保留可用列表与上次状态，明确哪个模块过期／不可用；不完整计数不报零或完整总量；有只读重试 |
| AT20 | 传统单席位、测试双席位、无外部来源；桌面与窄屏键盘操作 | 保留既有模式能力；不调用缺失正式 API；无错误空栏目；焦点、返回、状态文字和布局可用 |

## 3. 计数与边界补充

- 持久待办按带类型的原对象 ID 唯一；同一审批在两个页面仅是一条记录。
- 一项工作对应一个待回应对话时，页面分别标“项”和“个对话”并展示关联，不合计为两项业务工作。
- 全部中的历史信息不混入待处理角标。只读总览人数／条数不包括当前无权看到的来源、任务或分析版本。
- 本席位已处理不保证其他席位已处理；AI 执行成功不保证人工工作完成。

## 4. 实施时的结果记录

每项记录通过／失败／未适用、相关测试或人工操作证据。审批模块不存在时 AT15 可记未适用，AT16 的无审批路径仍必须通过；不得据此把基础交付标为受阻。
