# 文稿修订与双席位交接测试

目标：带初稿的修改需求 → 后台预处理 → 席位 A 收到信息 → A 分派给 B → B 修订并提交 → A 验收。

本次使用 Markdown 文件，集中验证资料传递、办理和成果交接。当前系统已支持这条流程；信息归属任务、附件导入、正式交接由用户明确操作。

[使用席位 A 打开本次信息](http://127.0.0.1:4315/inbox?id=878be739-9e15-4553-94a8-805deefe4228)。服务运行在腾讯云，本机 4315 通过 SSH 转发访问。

## 已准备的内容

- 公共任务：`值班交接说明修订测试`。
- 来信：`【流程测试】请修订值班交接说明（附初稿）`。
- 原始附件：`值班交接说明_初稿.md`、`修订要求.md`。
- 预处理后只投递给席位 A。席位 B 从 A 分派的工作中接收材料。
- A 分派、B 办理及提交、A 验收均留给测试人员操作。

系统准备结果和记录编号见同目录的 `准备结果.json`。测试资料接入来源的规则已改为只投递 A，原规则保存于 `原投递规则.json`，旧信息及既有待办不受影响。

## 1. A 收到信息并分派

1. 使用账号 `a` 登录，打开 **收到的信息**，选择上述来信。
2. 展开 **查看原文与附件**，确认两个附件都存在。
3. 在 **开始分析** 中选择公共任务 **值班交接说明修订测试**。在“使用的资料”中保留预处理文字结果，并手动勾选上述两个原始附件。
4. 将以下文字填入“分析目标”，点击 **进入对话分析**，进入会话后发送。

```text
请将本次《值班交接说明》修订工作分派给席位 B（seat-b），工作标题为“修订值班交接说明”。请先读取本次导入的“值班交接说明_初稿.md”和“修订要求.md”，将四项修订要求写入工作目标，并把这两个实际文件作为输入资料一起交给 B。最终在工作区根目录交付一个“值班交接说明_修订稿.md”，保留初稿。这是流程测试，未规定的班次名称、示例时间和章节安排等编辑细节由 B 合理拟制，标注为测试示例，无需逐项询问。请准备正式分派，等待我确认，不要在 A 这里代为完成修订。
```

5. 在确认卡片上检查：接收方是 B，附件有初稿和修订要求，目标完整。确认分派。

预期：新增一项“待签收”工作；B 可以在 **工作待办 → 待我办理** 看到它。导入时文件名可能增加编号前缀，核对原始名称即可。

## 2. B 办理并提交

为方便对照，建议使用另一个浏览器或独立无痕窗口登录账号 `b`。同一浏览器普通标签页共用登录身份。

1. 打开 **工作待办 → 待我办理 → 修订值班交接说明**，核对两份输入资料。
2. 点击 **开始办理**，确认交接；随后点击 **新建对话办理**。
3. 发送以下内容：

```text
请办理当前关联工作。先将该工作的初稿和修订要求导入当前工作区并读取，按全部四项要求修改。把成稿保存为工作区中的“值班交接说明_修订稿.md”，保留初稿。完成后先自查四项要求，再将这一个修订稿正式提交给分派方席位 A，等待我在确认卡片批准。
```

4. 检查文件内容，确认提交卡片中的文件是修订稿，再批准提交。

预期：工作变为“待验收”。生成文件或提供聊天下载按钮本身不等于正式提交。如 Agent 仅生成了文件，可在工作详情点击 **提交文件**，选择修订稿并确认。

## 3. A 验收

1. 回到 A，打开 **工作待办 → 待我验收**，必要时点击 **刷新待办**。
2. 在提交记录中查看或下载修订稿，检查四点：日期格式统一；必填项完整；书面交接与双方核对；填写示例及修改说明齐全。
3. 点击 **验收通过** 并确认。若需体验返工，也可填写具体意见后 **退回修改**。

完成标准：B 接收到两份资料，提交的是修订稿，A 能读取该提交版本并将工作验收为“已完成”。

本次不需要再手动上传同一初稿。B 通过 Agent 生成的文件已经在自己的工作区；“提交文件”负责把成果交回 A。
