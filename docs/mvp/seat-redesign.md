# Axon 席位重设计方案

审阅稿 v0.3 · 实施目标分支 `main`

本期产品以部署配置中的 N 个席位为入口。每个席位有稳定的 ID、名称、类型和职责。导演席负责演练、控制席负责业务指令下达、管理员席负责平台设置。导演席和管理员席没有业务任务工作区。总体、情报、筹划、态势等席位沿用现有分工。账号管理、人员与席位绑定、通用权限和鉴权体系留待后续。现有登录与服务端检查用于兼容旧服务。

## 1. 当前模型和部署问题

以本地 `main` 的 `f71996c` 为基线。导演台要求数据库中的 `control_scenarios` 与外置配置中的 `simulation.directorSeatId` 同时匹配，并核对情报、态势来源的读取权限。控制席的指令下达资格来自 `commands.seatIds`。管理员由独立账号角色识别，能力中心已接入这套授权，模型设置仍使用席位的 `manage_model`。旧总体席职责样例也包含「承担系统管理职责」。安装新实例时，分别开好账号、准备配置和配置来源后，仍需要逐项核对这些约定是否一致。

基线查证位置为 `experiments/harness-lab/src/access/store.ts` 的 `AccessStore`、`src/access/system-roles.ts` 的 `SystemRoles`、`src/server/scenario-routes.ts` 的 `scenarioDirector`、`src/server/app.ts` 的 `commandSeatIds` 与 `requireModelSettings`，以及 `fixtures/seat-responsibilities/overall.md`。演练入口沿用 `main` 已有的场景演练和自由调试，管理员个人空间沿用 R2 的账号私有范围。

## 2. 席位职责与权限

| 席位 | 职责和入口 | 业务任务工作区 | 专属权限与授权范围 |
| --- | --- | --- | --- |
| 导演席 | 在导演台准备演练、选择场景演练或自由调试、控制轮次和演练时间、投放演练事件、核对运行结果 | 无。通过导演台和获准的只读视图核对本演练任务、地图、来源和回执 | 独有导演台及演练控制权限。可通过导演台初始化本轮预置任务，并按现有约束归档相应演练任务 |
| 管理员席 | 使用现有管理入口维护平台配置、共享模型、专家、技能与连接器，暂停或恢复全局后台作业领取 | 无。已有管理员个人空间、对话和文件沿用原入口与归属 | 平台设置由管理员席承担。保留现有管理校验和业务数据隔离 |
| 控制席 | 接收交接、核对资料、办理任务、确认下达并查看执行回执 | 有。沿用公共任务、席位私有任务和任务内工作区的现有访问规则 | 独有正式下达权限。下达还须通过现有任务、演练轮次、来源访问和人员确认检查 |
| 总体席 | 管理公共任务、跨席位协调、工作分派与验收，按配置审批补充投递 | 有 | 保留原公共任务管理、来源业务权限及获准的工作总览。共享模型设置调整至管理员入口，使用已有管理校验 |
| 情报席 | 核实来源与事实、判断可信性、辨别矛盾和缺项、分析情报变化 | 有 | 保留获准的情报来源、收件和协作权限 |
| 筹划席 | 综合任务、情报与态势，编制和修订方案、提出建议、提交交接成果 | 有 | 保留获准的来源、任务和协作权限 |
| 态势席 | 核对区域、对象、资源和行动状态，分析变化与约束 | 有 | 保留获准的态势、地图、任务和协作权限 |
| 其他既有业务席位 | 按实例配置保留原席位名称、职责及分工 | 有 | 保留原有业务授权及资源范围 |

共享模型设置归管理员席。业务席位继续在自己的会话中选择已开放的模型。原处理与投递规则、来报核对、重处理和补充投递审批继续使用现有业务授权。单个来源的接收开关沿用现有入口与授权。全局后台作业领取开关归管理员席。

「管理员席 → 设置 → 后台作业」可暂停或恢复整个实例领取新作业。已在运行的作业继续执行。总体席可从「工作总览 → 信息流转／处理运行」查看队列状态。单个来源的接收开关继续由获准的来源管理席在工作总览操作，管理员也可在连接器详情操作同一来源的接收状态。业务路由规则在「工作总览 → 处理与投递规则」按来源编辑。情报和态势各有一条可启用的规则，场景演练和自由调试共用。编辑仍要求有效来源的管理权限。

### 任务空间与个人空间

- 公共任务是原有共享任务记录。控制席和其他业务席位按现有可见性和状态规则查看，进入后使用各自的「任务 × 席位」工作区。私有业务任务由所属业务席位使用。跨席位交付继续经现有工作交接。
- 导演席无任务工作区、业务会话或业务待办，也不参与分派、接收、办理、提交或验收。导演台创建并归档的是指定演练轮次的任务记录。普通公共任务创建、编辑、重开和归档仍按业务授权执行。导演的只读核对也须经过轮次、任务和来源检查。
- 管理员席同样无任务工作区、业务会话或业务待办。已有管理员个人空间沿用原有私有标识及隔离，保留个人对话、文件和获准的能力试用。新席位配置与个人空间归属分开，两者均不产生业务工作区。
- 业务席位目录、固定及补充投递候选、工作分派和成果交接仅接受有业务资格的席位。后台作业和外部来源继续使用服务身份及自己的作用范围。

## 3. 席位和部署配置

部署者通过一份席位清单声明本实例使用的席位 ID、名称、类型与职责。类型表达固定工作分工。总体、情报、筹划、态势使用普通业务类型，细分由名称和职责表达。席位入口分别通往导演台、能力中心或业务工作台，导演席和管理员席均从业务协作目录排除。

现有账号、会话和服务端校验继续作为运行兼容层。已有管理员入口可显示为「管理员席」，现有管理校验和个人数据隔离照旧，无需给每个管理员创建新席位或改变登录记录。页面入口和服务端行为须一致，复用现有导演、下达、管理员及工作区检查。配置中的职责描述或席位名称改动本身不会改变既有授权。

| 配置项 | 归属及用途 |
| --- | --- |
| 本实例有哪些席位 | 在一份席位清单声明。部署时核对现有功能配置与清单是否匹配 |
| 谁可以管理公共任务、查看业务总览 | 保留现有显式业务授权，仅对可参与业务的席位生效 |
| 谁能查外部系统、读某个来源或维护该来源的业务规则 | 保留现有系统读取范围及来源授权。导演仅使用核对所需的读取范围。管理员席无隐式业务范围 |
| 服务启用哪些集成、连接到哪里、使用哪个凭证 | 沿用每个实例的集成及私有配置。现有功能的配置缺项由部署检查指出 |
| 哪个业务席接收某条规则的投递或审批 | 保留既有规则、候选集和审批名单。平台权限、场景权限不改变投递资格 |

席位总数由部署决定。每套启用演练的 Axon 服务只设一个导演席，由现有的 `simulation.directorSeatId` 指向。未启用演练的服务可省略导演席。启用下达的服务可配置多个控制席，继续使用 `commands.seatIds` 列表。部署检查在席位清单与现有配置不一致时列出差异。

## 4. 现有服务迁移

### 离线预检与映射

先按 systemd 实例核对实际发布提交、数据根、外置配置目录、SQLite 版本、模拟来源及依赖。当前部署规范中主线 `axon-4316.service` 和 `axon-jc.service` 有各自的数据与私有配置。每个实例独立产生映射与备份。服务端实际内容以发布时只读核查为准。

| 旧身份或授权 | 迁移规则 |
| --- | --- |
| 导演席 | 按现有演练配置和导演校验核对入口，沿用原 `seatId`、轮次绑定、核对范围和历史记录 |
| 控制席 | 对照现有下达名单核对控制席，可保留多条有效记录。沿用原 `seatId`、任务和回执 |
| 管理员入口 | 复用当前管理入口和管理身份，保留登录记录和个人空间的原有归属，报告没有可用管理入口的实例。席位清单登记产品上的管理员入口，旧账号无需重新绑定 |
| 普通业务席 | 保留席位 ID、名称、原业务职责、公共任务与总览等授权，以及来源范围。共享模型设置随管理员入口接通后再撤下旧入口。总体席职责样例同步去掉平台管理描述 |

预检默认只读，列出席位、对应功能、现有入口、来源范围和配置差异。重点核对导演来源读取、控制席的任务与态势依赖、管理员入口可用性和投递候选中的非业务席。未完成引用按既有流程处置，历史快照保留。输出仅显示凭证是否配置。

### 执行、验证与回退

1. 先用脱敏数据或停服备份副本演练。生产切换前确认目标实例、基线提交、活动轮次和在途请求。阻止新增写入，暂停相关入口，确认运行中或待确认的下达、交接和作业如何收尾。若共享依赖仍有写入，先确定可获得一致快照的停写范围。
2. 停服后备份旧程序、完整宿主数据根、相关独立来源数据、外置配置和凭证，SQLite 的附属文件随数据根一并备份。记录对应关系与校验值。按已审核的清单配置席位入口，复核其与现有登录、管理及工作区检查一致。
3. 切换匹配的新程序和配置，待关键校验通过后恢复接入和队列。比较任务、工作区、Pi 会话、文件、收件、工作项、指令和回执的 ID、数量及必要校验和，再核对已有个人空间和管理入口。使用只读检查确认旧记录，新增动作验收在隔离数据上完成。
4. 重试复用原席位清单和备份。若迁移失败，先停新服务并保留失败现场，恢复配对的旧程序、数据、配置及凭证。已对外发送的业务动作按实际回执核对，再决定如何恢复接入。

## 5. 新服务配置

新服务沿用每实例独立的数据、systemd 和私有配置目录。部署时准备实际席位清单。下表为一套启用演练及下达的样例，实例按需取用。

| 示例席位 ID | 类型 | 开通时核对 |
| --- | --- | --- |
| `seat-admin` | 管理员 | 使用现有方式准备管理入口及其运行所需的凭证 |
| `seat-director` | 导演 | 演练控制。按导演台需要配置情报和态势的查询及来源只读范围 |
| `seat-control` | 控制 | 业务参与和下达资格。配置所需的态势查询范围及现有业务授权 |
| `seat-overall` | 普通业务 | 总体席职责，按需显式开通公共任务管理、来源业务权限、总览与补充投递审批 |
| `seat-intelligence`、`seat-planning`、`seat-situation` | 普通业务 | 分别沿用情报、筹划、态势职责及各自所需的业务范围 |

1. 初始化实例数据根，录入审核过的席位清单，沿用现有离线方式准备席位入口运行所需的登录记录和凭证。部署者只维护实际使用的席位，签名密钥和外部服务凭证保存在实例私有配置。
2. 配置实际启用的模块。若启用演练，核对席位清单中唯一的导演席与演练配置指向一致，再核对演练服务、凭证引用和来源映射。若启用下达，核对控制席列表、演练集成和控制席所需的态势查询范围。任务、来源范围和投递规则继续引用实际席位 ID。
3. 启动前逐席核对入口、现有校验、业务任务空间边界及功能缺项。启动后核对健康接口和各席落地页，演练和下达用隔离测试数据验收。

## 6. 实施顺序与验收

1. 在 `main` 上补齐席位清单、与现有实例配置的只读核对，以及对应的部署样例。以空数据根和旧实例副本验证入口兼容、缺项提示和回退。
2. 按席位职责整理导演台、指令下达和管理员入口，复用现有校验。验证共享模型设置、管理员个人空间、导演任务准备、业务任务空间及 Agent 行为。保留现有 Pi 会话、工具确认与工作区机制。
3. 补齐部署手册和配置样例，用一份旧实例副本和一套全新实例跑完各自操作手册，再按服务单独安排发布。按当前项目命令执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 和相关桌面浏览器测试。重点复用 access、administrator、director、commands、handoff、workbench 和 background 的回归覆盖。

| 验收项 | 通过条件 |
| --- | --- |
| 三项专属权限 | 仅导演席通过导演台及控场鉴权，仅控制席可准备和确认下达，仅管理员席能修改平台配置。其他席位即使直访 API、继续使用旧页面或调用 Agent 工具也被服务端拒绝 |
| 任务和个人空间边界 | 导演在获准范围可准备、核对演练。导演和管理员无法打开业务会话、读写业务工作区、办理业务或成为接收方。管理员仍能使用自己的个人空间。控制席及其他业务席原有业务流程通过 |
| 配置核对 | 启用演练时，缺少导演席、配置多于一个导演席或演练配置指向不一致均报告错误。改显示名不会改变授权。现有控制席列表中的多个有效席位能够保留。关闭集成、缺少凭证或来源访问时，明确显示原因 |
| 旧服务迁移 | 既有登录、业务与个人历史、数据归属及普通业务授权继续有效。共享模型管理通过管理员入口，单来源接收沿用原规则，全局队列沿用原状态并改由管理员席操作。副本上验证重试和备份恢复 |
| 新服务配置 | 根据一份席位清单配置最小实例和完整演练实例，逐席核对落地页、任务空间边界和集成缺项 |

后续独立设计账号生命周期、人员与席位的关系、可配置权限、认证授权体系以及跨席位换岗。
