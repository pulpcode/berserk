## 目标与建议规模

用一类模拟场景，验证三件事：Agent 能否综合特情、态势等信息形成有依据的方案，能否在多轮对话中补充和修订成果，席位之间能否完成任务交接、审核和归档。

建议规模为 **3 个预置席位、2 个并行验证任务、每任务多会话、1 套统一 Harness 引擎、1～2 个固定 SubAgent、1 个后台特情 Agent、4～6 个 Skill、2 类成果、1 个地图适配、Ubuntu 单机部署**。引擎实现复用，会话与 Run 的上下文和状态独立。成果收敛为特情／态势简报与筹划方案；其余数量沿用讨论建议，属于规划口径。

样板闭环：多源模拟信息接入 → 后台分析与提醒 → 建立任务 → 分派与签收 → 综合研判与多轮筹划 → 成果退回修改及审核 → 方案归档。信息输入至少覆盖特情与态势；资源概况、环境等可按样板需要作为只读参考。

调度单、调度指令、资源锁定／占用、执行回执和调度状态推进均不进入 MVP 实现和验收。后续接入设计集中记录在 [design.md](design.md) 的“后续调度系统接入”一节，不要求本阶段编写占位接口或模拟执行能力。
