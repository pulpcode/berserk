# MVP 验收场景

版本：v0.3；状态：测试设计，所有用例尚未执行。需求见 [PRD](prd.md)，工作包见 [implement.md](implement.md)。先以 FG01～FG07 验证通用框架，业务接入后按 AC01～AC20 验收多源研判、方案形成、审核和归档；调度实现继续后延。

## 0. 通用框架阶段验收（M0／M1）

前期只需两个测试任务、固定测试身份、少量文本／JSON 资料、一个测试成果类型、固定工具／Skill 配置和合成事件。无需样板灾种、特情服务、态势数据、地图、领域知识库或业务席位矩阵。至少一条主 Agent 与子 Agent 路径使用真实模型和宿主工具执行，故障路径可用确定性测试替身。

| 门槛 | 操作与通过条件 | 工作包 | 为后续验收提供的基础 |
| --- | --- | --- | --- |
| FG01 通用连续作业 | 读取固定资料、生成结构化草稿，再以补充要求修改；保存真实工具结果与跨轮引用；每次 Run 正确结束，Session 可等待新输入 | W04、W05、W07-A | AC02 |
| FG02 运行与确认控制 | 刷新／关闭页面、取消、超时、预算耗尽、同会话并发及确认接续；状态持久化，刷新不重启作业，受控操作在确认后执行，普通对话不挂起待确认 | W02、W05 | AC06、AC13 |
| FG03 隔离与文件边界 | 两个任务、多个测试身份和同任务下不同会话并行；用不同输入标记核对各 Run 的上下文、工具结果及控制状态不串用，其他会话聊天不默认注入；尝试替换对象编号、角色和文件路径，越界被服务端拒绝，凭证不进入浏览器或成果 | W02、W04、W05、W07-A | AC01、AC03、AC18 |
| FG04 成果与协作 | 测试身份分派、签收、提交测试成果、退回、修改成新版本并再确认；版本与操作关联，旧确认不批准新版本，接收方无需完整聊天即可继续 | W04、W07-A、W08-A | AC04～AC06 |
| FG05 持久化与中断恢复 | 停止 Worker，制造成果写入成功但响应丢失，再恢复并查询／重试；中断可识别，结果保留，不重复写入或投递，同操作标识异参数拒绝 | W02、W05、W07-A、W08-A、W09-A | AC14、AC19 |
| FG06 通用后台作业 | 无页面在线时注入合成事件，验证去重、同对象版本更新、失败重跑、触发启停与离线待办；旧输出不覆盖新输入结果，输出不循环触发自身，通知失败只重试通知 | W08-A、W09-A | AC08～AC11、AC19 |
| FG07 单层委派 | 用固定资料执行一次摘要／格式检查子运行；独立上下文、父子关联、结构化回传可查；子运行失败可见，递归和提权被拒绝 | W05、W10-A | AC07 |

M1 完成条件：FG01～FG07 均有步骤、环境、输入／配置版本、Run／成果／操作编号及实际结果。此时可演示通用作业台，随后再开展 W00 与 W03。框架检查不评价消防专业质量，也不能将对应 AC 提前标为通过；M4 在领域接入后复验框架并执行全部 AC。

## 1. 完整领域 MVP 的固定测试条件（M2～M4）

- 三个预置席位、两个同类场景任务 A／B；至少各一个会话，并增加同任务第二会话用于并发检查。
- 同一事件的特情消息与态势快照，至少两类输入；样板需要时增加资源／环境只读概况；各来源有标识、时间及版本。
- 初始与补充特情、重复及矛盾消息、过期态势、会改变方案约束的新输入和标注好的参考材料。
- 简报与筹划方案两类成果样例、版本与确认规则、已选模型／配置／Skill 版本、固定场景种子。
- 支持关闭浏览器、刷新页面、停止 Worker、模拟工具超时和通知投递失败。

每次测试记录环境版本、数据／场景版本、输入与预期、实际结果、相关编号和通过／失败。测试真值不提供给 Agent；固定输入可复现不代表模型输出逐字相同。

## 2. 身份、作业与协同

| 用例 | 操作 | 通过条件 | 关联 |
| --- | --- | --- | --- |
| AC01 三席位进入 | 不同浏览器会话分别进入三个预置席位，查询身份及可用工具 | 角色与工具清单正确且会话间不串身份；服务端拒绝伪造角色参数 | R01；W02、W08-B |
| AC02 真实多轮作业 | 连续要求整理特情、查询态势及资料、综合形成方案、修改指定段落并保存新版本，再准备提交 | 真实工具调用与结果可查，方案使用特情与态势依据；后续轮正确引用已有成果，无需重述全部背景；每轮结束可等待新输入，不保持无意义的执行或待确认状态；不同会话上下文独立 | R03、R04、R06；W04～W06 |
| AC03 双任务隔离 | A／B 同时作业；在 A 中尝试读取仅 B 可访问的会话、成果和文件，并测试更换对象编号 | 合法访问成功；越界请求被服务端拒绝且无内容泄露；不因前端传入标识或子 Agent 调用绕过范围检查 | R01、R03、R07；W02、W04、W07 |
| AC04 工作交接 | 信息席分派，筹划席签收并依据输入继续作业；随后向审核席上报 | 工作项状态、责任和成果明确；接收方不依赖发起席位完整聊天历史；模型停用时仍能用页面执行标准业务操作 | R02、R08；W04、W08 |
| AC05 版本退回与冲突 | 提交 v1、退回、修改为 v2、再次提交确认；之后创建 v3；另用旧编辑版本尝试覆盖最新成果 | 审核绑定具体版本，v1／v2 历史保留，v3 不继承 v2 确认；并发修改被明确拒绝或要求处理冲突，不静默覆盖 | R07、R08；W07、W08 |
| AC06 操作确认 | Agent 尝试未经确认正式提交成果或发布共享态势、非审核席尝试审核；用过期版本或变更参数重用确认，再执行有效确认操作 | 无效操作被拒绝，有效操作可执行；确认绑定主体、版本和具体动作；工具白名单不能替代业务确认；普通查询和草稿修改按已授权范围执行 | R01、R04、R08；W05、W08、W12 |
| AC07 专业委派 | 主 Agent 调用预置子 Agent，再让子 Agent 尝试分派／审核及递归委派 | 独立子 Run、目标、输入、工具结果和结构化回传可查；主 Agent 能使用候选分析；越权与递归被拒绝 | R05；W10 |

建议证据：身份响应、工作项时间线、成果及版本编号、确认记录、工具调用与父子 Run 关联、越权失败记录。

## 3. 后台智能作业

| 用例 | 操作 | 通过条件 | 关联 |
| --- | --- | --- | --- |
| AC08 无人在线处理 | 关闭全部席位页面后注入特情，待处理结束再登录 | 原文、后台 Run、候选分析和信息席待办均存在；后台使用固定服务身份，无需借用登录用户 | R09；W09 |
| AC09 重复与补充消息 | 重发相同来源消息标识，再发送同事件的全新补充消息 | 重复消息不产生重复逻辑处理及业务效果；新消息仍保存和处理；消息去重不等于事件去重 | R09、R10；W03、W09 |
| AC10 通知失败 | 分析成功后故障注入使通知投递失败，再恢复投递 | 分析只生成一次；通知记录可查，只重试投递；离线后登录能见结果；已读不等于工作项签收 | R08、R09、R12；W08、W09、W13 |
| AC11 更新与自触发 | 同一事件连续注入两个版本，制造旧分析晚完成；观察分析完成事件 | 同事件按约定串行／合并，旧结果保留但不覆盖新输入对应状态；系统明确标记过期；自身输出不会无限触发分析 | R09、R12；W09 |

建议证据：来源消息标识与事件编号、输入版本、作业与 Run 关联、分析记录数量、通知重试记录和触发来源。

## 4. 一致性与恢复

| 用例 | 操作 | 通过条件 | 关联 |
| --- | --- | --- | --- |
| AC12 多源综合与输入更新 | 提供特情、态势及相关知识，要求形成方案；加入矛盾、缺失或旧来源；再更新一项关键态势约束并要求修订 | 方案实质使用至少特情与态势两类输入，关键判断／建议可定位来源及版本；矛盾和缺失显式标记；更新后说明影响并形成新版本，旧依据和审核历史保留，新版本不继承旧确认；未把读取到的资源概况改成执行结果 | R06、R07、R10、R12；W03、W06、W07、W12 |
| AC13 页面与运行控制 | Run 执行时刷新／关闭再进入；同会话提交第二个请求；取消一次运行并测试预算耗尽与待确认 | 刷新不新增 Run；同会话无重叠活动执行；可看到工具、失败和确认状态；取消停止后续动作但不宣称回滚已完成操作；预算有界，确认后可安全接续 | R03、R04、R12；W05、W13 |
| AC14 中断、幂等和结果不明 | 停止 Worker；模拟信息查询超时，以及成果保存／提交成功但响应丢失；重启后查询结果并以相同操作标识重试，再尝试同标识不同参数 | 中断被识别而非永久运行中；原消息、工具结果和成果保留；纯分析可按策略重试；已完成写操作返回原结果，不重复创建版本、提交或通知；同标识不同参数明确拒绝 | R04、R09、R12；W05、W07～W09、W12、W13 |

建议证据：输入来源与版本、方案依据和修订说明、操作编号与幂等键、成果／提交记录数量、刷新前后 Run 编号、重启前后状态及恢复日志。

## 6. 验收报告口径

最终报告至少包含：

- AC01～AC20 的执行结果、失败原因、复现步骤与相关记录编号。
- 正常路径以及多源矛盾、缺失／过期信息、重复、越权、并发修改、通知失败、工具超时和 Worker 中断的覆盖情况。
- 从多源输入到方案审核归档的完成耗时、关键操作耗时、模型／工具用量、人工修改量与审核问题记录。
- 知识／成果样本的评估方法、样本量、业务评审人及预先确定的通过阈值。
- 部署和恢复验证、已知限制以及未纳入 MVP 的范围。

W01／W02 先确定开发模型与机器环境、框架运行预算和测量方式；不以业务场景和业务质量阈值作为 FG 的前置条件。W00 后续确定业务负载、专业评估样本及通过标准，M4 按确认口径验收。在这些口径确定前，不以任意“秒级响应”或“95% 准确率”作为承诺。
