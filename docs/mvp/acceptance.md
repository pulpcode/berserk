# MVP 验收场景

版本：v0.7；状态：测试设计，所有用例尚未执行。需求见 [PRD](prd.md)，工作包见 [implement.md](implement.md)。先以 FG01～FG11 验证成熟 Harness 基础能力与作业框架，业务接入后按 AC01～AC24 验收完整能力及多源方案闭环；调度实现继续后延。

## 0. 通用框架阶段验收（M0／M1）

W01-1 先按 [C01～C06](../../.trellis/tasks/09-16-w01-harness-validation/prd.md#首增量验收c01c06) 独立交付 Pi 多轮对话、最小工具、基本停止与原生历史。下列 FG 是完整框架门槛，不要求首步完成 Run 状态机、确认恢复、成果版本或 FG11 导出检查。完整 W01 的 T01～T13 按 S2～S5 分阶段验证，不能反向阻塞首增量。

前期只需两个测试任务、固定测试身份、少量文本／JSON 资料、一个测试成果类型、固定工具／Skill 配置和合成事件。无需样板灾种、特情服务、态势数据、地图、领域知识库或业务席位矩阵。至少一条主 Agent 与子 Agent 路径使用真实模型和宿主工具执行，故障路径可用确定性测试替身。

另准备不同任务的 AGENTS.md 式指引文件、修改／删除规则与越界样本、可触发压缩的长对话，以及需要不同工具组合的目标。固定输入服务于复现，不固定模型的唯一调用序列；真实正常路径须保留模型、工具、指引文件加载及压缩证据。预算可以调小以触发压缩，测试真值不注入 Agent。

M1 完成条件：FG01～FG11 均有步骤、环境、输入／配置／Skill 版本、Run／成果／操作编号及实际结果；指引文件标识／内容摘要、压缩范围／摘要与前后上下文证据可定位。此时可演示以多轮对话为主的作业台，再开展 W00/W03。框架通过不代表专业质量或 AC 通过；M4 复验框架并执行全部 AC。

## 1. 完整领域 MVP 的固定测试条件（M2～M4）

- 三个预置席位、两个同类场景任务 A／B；至少各一个会话，并增加同任务第二会话用于并发检查。
- 同一事件的特情消息与态势快照，至少两类输入；样板需要时增加资源／环境只读概况；各来源有标识、时间及版本。
- 初始与补充特情、重复及矛盾消息、过期态势、会改变方案约束的新输入和标注好的参考材料。
- 简报与筹划方案两类成果样例、版本与确认规则、已选模型／配置／Skill 版本、固定场景种子。
- 支持关闭浏览器、刷新页面、停止 Worker、模拟工具超时和通知投递失败。
- 增加按任务／工作区区分的业务指引文件及修改／删除样本、可触发压缩的长程筹划对话，以及改变工具选择的补充目标；明确各文件允许与禁止的读取／编辑身份。

每次测试记录环境版本、数据／场景版本、输入与预期、实际结果、相关编号和通过／失败。测试真值不提供给 Agent；固定输入可复现不代表模型输出逐字相同。

## 6. 验收报告口径

最终报告至少包含：

- FG01～FG11 的框架复验及 AC01～AC24 的执行结果、失败原因、复现步骤与相关记录编号。
- 正常路径以及多源矛盾、缺失／过期信息、重复、越权、并发修改、通知失败、工具超时、Worker 中断、指引文件过期缓存／读取失败、压缩失败和关键输入超预算的覆盖情况。
- 从多源输入到方案审核归档的完成耗时、关键操作耗时、模型／工具用量、人工修改量与审核问题记录。
- 知识／成果样本的评估方法、样本量、业务评审人及预先确定的通过阈值。
- 部署和恢复验证、已知限制以及未纳入 MVP 的范围。
- 内核依赖检查、工作记录导出与关联校验、快照版本拒绝案例；明确尚未实施自研内核或跨内核迁移。

W01／W02 先确定开发模型与机器环境、框架运行预算和测量方式；不以业务场景和业务质量阈值作为 FG 的前置条件。W00 后续确定业务负载、专业评估样本及通过标准，M4 按确认口径验收。在这些口径确定前，不以任意“秒级响应”或“95% 准确率”作为承诺。
