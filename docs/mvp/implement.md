# MVP 阶段工作清单

版本：v0.8；状态：W01-1 已通过 C01～C06；W01-2（S2a）已完成 A01～A12 组合验收，W01-3/S2b 与 W01-4/S2c 已实现，其余工作包待开始。范围见 [PRD](prd.md)，通过条件见 [验收场景](acceptance.md)。顺序保持：**先具备 Tool、Memory、Skill、Subagent、上下文管理与压缩能力的 Harness 和作业框架，后样板业务与模拟服务，再完成领域集成与验收**。多轮对话为主要入口，MVP 业务闭环仍为多源研判、方案形成及审核归档；调度实现后延。

建议责任方向：Agent／后端，前端负责事件展示。

- [ ] 落实统一内核接口与单一适配器，限制 SDK 类型及 hook 的依赖范围；用最小契约替身验证接口，以 FG11 检查工作记录、版本绑定和数据导出边界。

- [ ] 复用内核的 Context Files／资源加载机制实现文件式 Memory：按工作区选择文件，加载 AGENTS.md 式规则／偏好，受控编辑后下一 Run 重载；保存加载内容摘要并检查范围，不实现记忆抽取／检索服务。

- [ ] 识别 Worker 失联与中断，保存错误和已有结果；人工确认时释放执行资源。

A 完成条件：无浏览器在线时，固定测试事件仍能生成持久化结果与待办；重复事件、重启和投递失败不会重复产生效果。

**W09-B（M3）：特情业务接入。** 接入 W03 的特情消息及关联态势，加载 W06 Skill、W07-B 模板和 W08-B 席位路由；保存原始特情并形成候选分析，缺失来源显式标记。

B 完成条件：无人在线特情处理、更新、通知及恢复通过领域验收；不再实现另一套工具循环或后台运行机制。

### W10 子 Agent 委派与专业配置

建议责任方向：Agent 工程。

**W10-A（M1）：单层委派机制。**

- [ ] 用固定“资料摘要”或“格式检查”测试子 Agent，验证独立上下文、父子 Run、工具子集、预算与并发控制。
- [ ] 主 Agent 接收结构化回传并引用结果，正确处理子运行失败和取消。
- [ ] 按目标选择子 Agent 并综合来源与回传，不固定为每次都委派；子运行只加载获准指令文件，不编辑共享指令，上下文预算独立，总消耗受父作业约束。
- [ ] 禁止递归委派和权限扩大，测试子 Agent 只查询和返回候选结果。

A 完成条件：至少一次真实子运行可追踪，输入隔离和权限限制有效；不依赖消防知识或 W06。

**W10-B（M3）：专业配置。** 加载 1～2 类态势摘要或方案检查配置，复用 W10-A 的委派机制。

B 完成条件：专业结果可被主 Agent 用于方案作业，并通过 AC07。

## 4. M2：样板业务与信息模拟

### W00 样板业务与领域契约

建议责任方向：业务负责人、产品、技术负责人共同完成。

- [ ] 基于已可演示的框架选定一类场景，准备特情、态势、补充／矛盾信息和测试真值，明确各来源如何影响方案。
- [ ] 确认信息态势席、筹划席、综合审核席，制定业务动作与可见范围矩阵。
- [ ] 定义工作项完成条件，准备简报和方案样例，以及必填字段、依据、约束和待核实项。
- [ ] 明确成果审核、共享态势发布、输入更新和旧版本重新审核的业务规则。
- [ ] 将业务对象、时间、坐标、来源及查询契约映射到通用协议，确认领域指令文件内容、共享范围与编辑权限，以及地图、知识和文件格式。
- [ ] 补齐业务输入规模、领域评估样本和通过阈值，更新相关待决策项。

完成条件：样板每一步都有责任、输入、输出和通过条件，业务配置可接入框架。W00 是 M2 的开始，不再阻塞 M0／M1；未确定的专业规则由业务人员确认。

### W03 多源信息模拟与只读查询

建议责任方向：模拟／后端。

- [ ] 提供特情注入、态势快照及变化查询，按需要提供资源／环境只读概况，保存来源、对象、时间和版本。
- [ ] 区分消息去重、事件关联和多源报告，显式表示矛盾、缺失和延迟。
- [ ] 实现固定业务场景启动、重置、种子、受约束扰动、重复及补充信息注入。
- [ ] 提供查询超时、来源不可用和旧快照等异常，适配 W05 的工具接口及 W09-A 的事件入口。

完成条件：多源查询、版本更新与固定业务场景可复现，接口符合框架契约；不存在资源分配或占用接口。早期测试数据不直接冒充该服务的交付。

### W06 多源研判、领域知识与 Skill

建议责任方向：业务专家与知识／Agent 工程。

- [ ] 整理经确认的小型知识样本，保留来源、版本、片段定位和适用范围。
- [ ] 接入知识检索、特情／态势工具和来源引用；场景当前信息从 W03 查询。
- [ ] 编写 4～6 个领域 Skill，覆盖特情整理、态势归纳、多源研判、方案草拟、方案检查和成果上报。
- [ ] 区分事实、推断、矛盾与缺失，方案附依据，输入更新后支持补充分析与新版本。
- [ ] 每个 Skill 明确输入、职责、工具、模板、成功条件、失败处理和人工确认点，使用 W05 的加载机制。

完成条件：产出的方案实质使用特情与态势输入，建议可定位依据；以业务样本验证，通用测试 Skill 不替代此交付。

W07-B 和 W08-B 在本阶段完成，具体交付见各工作包的 B 部分。

## 5. M3：领域接入与方案闭环

先完成 W09-B、W10-B，将后台特情处理和专业委派接入已有框架。

### W11 地图／态势双向适配

建议责任方向：前端／GIS 与工具适配。

- [ ] 接入一个选定地图组件或既有框架，显示模拟事件、态势及样板纳入的只读资源信息。
- [ ] 将对象／区域选择转为带标识、时间、版本和坐标口径的上下文输入。
- [ ] 校验 Agent 候选标绘，人员确认后发布到任务共享态势。

完成条件：完成“地图选择 → Agent 读取 → 候选标绘 → 人工确认 → 共享显示”，不改变通用 Run 生命周期。

### W12 多源方案形成与闭环集成

建议责任方向：业务后端、Agent、前端与模拟服务联合集成。

- [ ] 串联多源输入，形成包含目标、态势判断、约束、建议安排和待核实事项的方案。
- [ ] 注入关键输入更新，验证有依据的修订及新版本，保留旧结论和审核历史。
- [ ] 检查矛盾、缺失、过期来源及任务隔离，复验成果写入与提交的结果查询和幂等。
- [ ] 串联后台特情、三席位多轮作业、专业委派、地图、退回修改、审核与归档。
- [ ] 验证任务指令文件在获准会话中的加载、修改与重启生效，长程对话压缩后续作、目标变化下的工具组合与子运行综合，完成 AC21～AC23。

完成条件：至少使用特情和态势两类输入，更新能推动可解释的修订；双任务并行不串资料，归档可查全链路证据。

## 7. 验证与落地记录

FG01～FG11 是 M1 框架退出门槛，定义在 [acceptance.md](acceptance.md)；AC01～AC24 为完整 MVP 验收。工作包中的 AC 在业务未接入前仅表示后续目标，不能以固定测试数据提前勾选通过；记忆、压缩和工具组合的真实记录与异常证据须单独保存。

W01-1 工程和检查命令已建立，见 [实验工程说明](../../experiments/harness-lab/README.md)。各检查的实际结果单独记录，命令存在不代表验收已通过。

后续创建开发任务时，按表中依赖和 A／B 部分拆分；通用部分完成即可进入后续框架工作，不等待整个父工作包的业务部分。所有排期和任务状态仍按 Trellis 流程管理，本清单不启动实施。

首增量实施前，从 [W01 开工审阅清单](../../.trellis/tasks/09-16-w01-harness-validation/review.md) 审阅 Pi 多轮对话范围、基本交互、历史保存限制及 C01～C06。完整 Run 和迁移设计进入对应阶段再审阅；M1 正式选型仍依据完整 W01 证据收敛。

未来完全自研另立任务：实现核心能力 → 同一能力验收 → 新会话试用 → 旧数据转换与专项验证 → 移除原依赖。切换与回退约束见 [设计第 8 节](design.md#8-技术选择与运行记录)，不将此路线加入 MVP 必建工作量。

## 8. 后续阶段：调度实现后延

以下仅登记延后范围，不属于当前工作包或前置依赖：

- 接入模拟或真实调度系统，增加受控工具、专门操作确认及适配。
- 增加调度请求／回执对象、资源占用与冲突处理、执行状态和结果对账。

接入原则见 [design.md](design.md) 第 9 节。通用框架通过成果版本、审核记录与领域工具边界保留扩展可能性，不建设调度占位服务，也不扩展为插件市场、通用工作流设计器或多 Harness 平台。
