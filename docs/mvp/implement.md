# MVP 阶段工作清单

版本：v0.4；状态：规划，所有开发工作包待开始。范围见 [PRD](prd.md)，通过条件见 [验收场景](acceptance.md)。顺序保持：**先具备 Tool、Memory、Skill、Subagent、上下文管理与压缩能力的 Harness 和作业框架，后样板业务与模拟服务，再完成领域集成与验收**。多轮对话为主要入口，MVP 业务闭环仍为多源研判、方案形成及审核归档；调度实现后延。

优先级含义：**P0** 为框架或业务闭环的核心依赖；**P1** 为随后集成但仍需交付的领域能力；**P2** 为 [PRD 暂缓范围](prd.md)。阶段及前置依赖决定执行顺序，P0 不表示所有工作包同时开展。

## 2. M0：通用协议与技术验证

### W01 通用 Harness 协议与技术路线验证

建议责任方向：Agent／后端技术负责人。

- [ ] 基于已有 DeepSeek、Kimi 等 API 明确首个验证模型、协议、网络限制与预算；用户建设后配置本地凭证，不要求现在提交密钥。样板、席位和地图不是前置条件。
- [ ] 定义 Session、Run、事件、工具、身份与范围、确认、成果及父子协议，补充记忆版本、上下文快照与压缩记录的最小语义。
- [ ] 优先验证 TypeScript 路线及成熟嵌入内核，必要时对照运行时包装；分别记录 Tool、Memory、Skill、Subagent、压缩、事件与控制的原生能力、宿主补齐项和限制。
- [ ] 使用固定测试工具验证“读取资料 → 提取结构化内容 → 生成草稿 → 按补充要求修改”；至少一条路径实际调用模型并由宿主执行工具。
- [ ] 验证历史保存后继续多轮作业、Web 事件展示、停止、失败、确认接续、工具范围和父子运行接入，记录需由宿主补齐的能力。
- [ ] 增加记忆保存／检索／纠正及小预算触发压缩后续作的探针；验证原文可回查、关键约束与引用保留，记录失败路径与调用开销。
- [ ] 使用不同目标和中途补充要求检查工具选择与组合，区分 Agent 组织步骤、Skill 指导和宿主授权规则，不以单条固定脚本代表能力完成。
- [ ] 检查依赖的部署约束、许可与版本固定方式，选定语言、一个内核、数据库及主要框架，形成实测选型记录。

完成条件：工具循环、跨轮接续、记忆、压缩、Skill、子运行、事件／确认及工具范围均有证据与缺口结论，形成无业务专属字段的协议及选型依据。原型不替代 M1 验收；正式持久化由 W02 落地，不依赖 W00/W03。

## 3. M1：通用 Harness 与作业框架

### W02 工程与持久化基础

建议责任方向：后端与部署。

- [ ] 建立启动、配置、检查和测试入口，分开 API 与 Worker；信息模拟服务在 W03 才加入。
- [ ] 建立迁移、测试身份、静态策略、数据库和文件持久化；先用固定测试角色，业务席位规则后接入。
- [ ] 实现作业、事件、Run、工具结果、记忆及修订、上下文／压缩记录、通知与审计的保存查询；保留原消息和来源版本，范围不依赖特情对象。
- [ ] 保持模型与服务凭证在服务端，定义文件访问范围和运行预算配置。
- [ ] 提供健康检查、日志、启停和重启能力，以及实际可执行的开发说明。

完成条件：重启后基础记录可查，不同测试身份和数据范围可区分，静态策略能拒绝越权请求；不需要业务数据种子。

### W04 通用任务、工作项与会话

建议责任方向：业务后端与前端。

- [ ] 实现任务创建／查看／归档，关联资料、成果、会话和处理记录；外部业务对象通过引用关联，特情接入后再配置。
- [ ] 建立一层 WorkItem，保存目标、接收身份／席位、输入引用、交付要求和状态，先用测试工作项验证。
- [ ] 建立固定任务与身份绑定的会话、消息保存、历史读取及多会话入口。
- [ ] 提供以多轮对话为主的作业台、资料／成果引用、处理步骤与工具／子运行视图，以及任务列表、到期／阻塞提示；标准动作保留结构化入口。
- [ ] 提供获准记忆的来源与有效状态查询、纠正／失效入口，复用 W05 的服务契约；不得展示其他会话未共享的信息。

完成条件：两个通用任务、多个测试身份和会话可独立使用；任务及工作项状态不由 Run 结束自动替代。运行、记忆和子运行面板先按 W01 契约组织入口，分别在 W05/W10-A 接入后完成对应验收，不让后续能力反向阻塞任务／会话基础。

### W05 统一 Harness 引擎与独立运行控制

建议责任方向：Agent／后端，前端负责事件展示。

- [ ] 实现模型适配、固定角色配置、版本化 Skill 加载、工具注册与参数校验，不依赖 W06 的领域 Skill。
- [ ] 按任务和身份装配目标、资料引用、成果、会话、有效记忆与摘要；业务输入通过上下文提供接口接入，不硬编码特情或态势字段。
- [ ] 实现会话级／任务级 Memory 的持久保存、范围检索、来源与版本、纠正及失效；跨会话共享受控，候选推断不升级为确认事实。
- [ ] 实现模型相关的输入预算、输出预留与压缩阈值；在安全边界压缩历史，保存覆盖范围、摘要及原文引用，保留目标／纠正／工具效果／未完成事项。
- [ ] 验证压缩后可回查并继续任务，失败或关键输入超限时有界重试、降级或明确停止；压缩用量纳入总预算。
- [ ] 复用引擎实现，为各会话和 Run 分别保存上下文、工具结果及控制状态；每次调用校验身份与任务范围，同任务的不同会话不默认注入彼此聊天历史。
- [ ] 完成目标驱动的模型—工具—结果循环及步骤调整；可组合工具和 Skill，实际结果回到循环；输出、工具范围和人工确认由宿主校验。
- [ ] 保存 Run 和执行事件，展示流式回复、工具调用、产物、待确认、失败与中断状态。
- [ ] 实现单会话活动 Run 约束、跨会话并行、取消、预算限制及失败后接续；普通多轮回复结束后 Session 等待输入。
- [ ] 验证关闭页面后执行仍由服务端管理，中断后保留的结果可继续使用。

完成条件：完成真实多轮工具作业、产物与控制，刷新不重复启动；记忆、压缩后续作及目标驱动工具组合分别通过 FG08～FG10。FG10 的子运行组合在 W10-A 接入后验证；W05 自身先验证记忆、压缩和普通工具组合，不形成反向依赖。无需业务模拟接口。

### W07 工作区与成果版本

建议责任方向：业务后端与前端。

**W07-A（M1）：通用成果机制。**

- [ ] 实现任务资料目录、运行临时区域、成果登记和受控文件访问。
- [ ] 保存成果类型、结构化内容、Markdown 展示、来源引用及版本，用一个测试成果类型验证格式校验。
- [ ] 关联输入版本、生成 Run 和文件，提供预览与版本查询；通过版本检查拒绝静默覆盖。
- [ ] 保存／提交结果可按操作标识查询，避免重试重复创建成果版本。

A 完成条件：通用成果独立于聊天持久化，旧版本及依据可定位；不要求先定义业务简报或方案字段。

**W07-B（M2）：业务模板。** W00 确认后注册简报与筹划方案两类模板、必填项和引用规则，使用 W07-A 的同一套保存、校验与展示机制。

B 完成条件：两类业务成果可预览、保存新版本并定位特情、态势和知识依据。

### W08 分派、上报与人工确认

建议责任方向：业务后端与前端。

**W08-A（M1）：通用协作机制。**

- [ ] 使用测试身份实现固定的分派、签收、提交、接收、退回、再提交和确认动作。
- [ ] 确认绑定主体、具体成果版本和动作，校验重复请求及不匹配的版本或参数。
- [ ] 持久化通知和待办，支持离线查看、已读和投递重试；签收与通知阅读分开。
- [ ] 页面与 Agent 共用服务端校验，接收方依据工作项和成果继续会话。

A 完成条件：测试身份完成一次“提交—退回—新版本—再提交—确认”，无需业务席位矩阵和全部聊天共享。

**W08-B（M2）：业务席位配置。** W00 确认后配置三个席位、任务可见范围、成果审核与共享态势发布规则。

B 完成条件：专业席位使用已有协作机制，业务确认语义明确；不新增通用审批设计器。

### W09 后台作业与特情接入

建议责任方向：Agent／后端，前端提供最小作业视图。

**W09-A（M1）：通用后台作业。**

- [ ] 建立固定服务身份、合成事件触发、人工重跑、可靠入队与 Worker 消费，复用 W05 的 Harness。
- [ ] 通过来源消息键去重，通过工作对象引用约束并发；保存输入版本，识别过期结果及产物自触发。
- [ ] 分开保存运行结果和通知投递；通知失败只重试通知，扫描仅补偿待处理和到期重试。
- [ ] 提供触发启停、作业查询、取消和重跑，明确停用期间输入的保留及恢复策略。
- [ ] 识别 Worker 失联与中断，保存错误和已有结果；人工确认时释放执行资源。

A 完成条件：无浏览器在线时，固定测试事件仍能生成持久化结果与待办；重复事件、重启和投递失败不会重复产生效果。

**W09-B（M3）：特情业务接入。** 接入 W03 的特情消息及关联态势，加载 W06 Skill、W07-B 模板和 W08-B 席位路由；保存原始特情并形成候选分析，缺失来源显式标记。

B 完成条件：无人在线特情处理、更新、通知及恢复通过领域验收；不再实现另一套工具循环或后台运行机制。

### W10 子 Agent 委派与专业配置

建议责任方向：Agent 工程。

**W10-A（M1）：单层委派机制。**

- [ ] 用固定“资料摘要”或“格式检查”测试子 Agent，验证独立上下文、父子 Run、工具子集、预算与并发控制。
- [ ] 主 Agent 接收结构化回传并引用结果，正确处理子运行失败和取消。
- [ ] 按目标选择子 Agent 并综合来源与回传，不固定为每次都委派；子运行记忆读取须授权，不直接修改共享记忆，上下文预算独立，总消耗受父作业约束。
- [ ] 禁止递归委派和权限扩大，测试子 Agent 只查询和返回候选结果。

A 完成条件：至少一次真实子运行可追踪，输入隔离和权限限制有效；不依赖消防知识或 W06。

**W10-B（M3）：专业配置。** 加载 1～2 类态势摘要或方案检查配置，复用 W10-A 的委派机制。

B 完成条件：专业结果可被主 Agent 用于方案作业，并通过 AC07。

## 4. M2：样板业务与信息模拟

### W00 样板业务与领域契约

建议责任方向：业务负责人、产品、技术负责人共同完成。

- [ ] 基于已可演示的框架选定一类场景，准备特情、态势、补充／矛盾信息和测试真值，明确各来源如何影响方案。
- [ ] 确认信息态势席、筹划席、综合审核席，制定业务动作与可见范围矩阵。
- [ ] 定义工作项完成条件，准备简报和方案样例，以及必填字段、依据、约束和待核实项。
- [ ] 明确成果审核、共享态势发布、输入更新和旧版本重新审核的业务规则。
- [ ] 将业务对象、时间、坐标、来源及查询契约映射到通用协议，确认领域记忆的来源、共享与纠正规则，以及地图、知识和文件格式。
- [ ] 补齐业务输入规模、领域评估样本和通过阈值，更新相关待决策项。

完成条件：样板每一步都有责任、输入、输出和通过条件，业务配置可接入框架。W00 是 M2 的开始，不再阻塞 M0／M1；未确定的专业规则由业务人员确认。

### W03 多源信息模拟与只读查询

建议责任方向：模拟／后端。

- [ ] 提供特情注入、态势快照及变化查询，按需要提供资源／环境只读概况，保存来源、对象、时间和版本。
- [ ] 区分消息去重、事件关联和多源报告，显式表示矛盾、缺失和延迟。
- [ ] 实现固定业务场景启动、重置、种子、受约束扰动、重复及补充信息注入。
- [ ] 提供查询超时、来源不可用和旧快照等异常，适配 W05 的工具接口及 W09-A 的事件入口。
